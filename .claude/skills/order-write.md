## 지시서 발행 절차

### 1단계 — 역할 선언 블록 삽입

1. 지시서 초문에 아래 역할 선언을 반드시 삽입한다:
   ```markdown
   ## 역할 선언
   > **너는 "막내N호"다. 쌍아가 아니다.**
   > - 쌍아 = VSCode 전략실 (이 지시서를 작성한 에이전트)
   > - 막내 = iTerm 터미널 (이 지시서를 실행하는 너)
   > - 완료 보고: `{디바이스}/막내N → {수신자}` 형식
   ```
2. N호 번호: 작가님이 배정하거나, `막내(any)`으로 미지정 가능.

### 2단계 — YAML frontmatter 작성

1. 지시서 파일에 YAML frontmatter를 작성한다:
   ```yaml
   ---
   type: ORDER
   date: YYYY-MM-DD
   from: {디바이스}/{에이전트}
   to: 막내N
   subject: {지시 제목}
   priority: {P0~P3 또는 최고/높음/보통/낮음}
   ---
   ```

### 3단계 — 본문 작성

1. 배경, 실행 내용, 검증 항목을 명확하게 기술한다.
2. 번호를 매겨 막내가 순서대로 실행할 수 있게 작성한다.

### 4단계 — 엔드라인 테이블 삽입

1. 모든 지시서에 아래 엔드라인 테이블을 포함한다:
   ```markdown
   ## 엔드라인
   | 항목 | 내용 |
   |------|------|
   | 마무리 | `커밋+push` / `배포` / `보고 대기` |
   | 산출물 | `{적립 경로}/{파일명}` (ch4 3조 네이밍 준수) |
   | 문서 유형 | `REPORT` / `TASK` / `SPEC` / `INCIDENT` / `DESIGN` / 해당 없음 |
   | 세션 로그 | `[log] 태그 커밋` / `해당 없음` |
   ```

### 5단계 — 준수 조항 선별

1. 위반 가능성이 높은 조항만 선별하여 `⚠️ 준수 조항` 섹션에 워닝한다.
2. 필수 포함 항목:
   - 헌법 4조 1항: API 키/비밀정보 절대 생성 금지
   - 헌법 1조 1항: 타임스탬프 `date` 명령 취득
   - 헌법 1조 2항: 완료 보고 필수

### 6단계 — 마크다운 링크로 제시

1. 지시서 파일을 `monkos-ops/ops/orders/YYYY-MM/` 에 저장한다.
2. 작가님에게 마크다운 링크로 제시한다: `[파일명](상대경로)`
3. 작가님이 링크를 드래그하여 터미널에 투입하는 방식이다.
4. `pbcopy` 클립보드 사용 금지 (VSCode 환경에서 불안정).
