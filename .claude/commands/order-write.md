## 파일명 규칙

`ORDER_{YYYYMMDD}_{발신}_{수신}_{내용}.md`

## YAML frontmatter 필수

```yaml
---
type: order
date: YYYY-MM-DD
from: {디바이스}/{에이전트}
to: {디바이스}/{수신자}
subject: {한 줄 요약}
status: 대기
portfolio: PF_{코드네임}
---
```

## 지시서 구조

1. 배경/목적 — 왜 이 작업이 필요한지
2. 산출물 — 파일 목록과 역할
3. 상세 설계 — 수정 내용, 코드 위치, 참조 파일
4. ⚠️ 준수 조항 — 위반 가능성 높은 조항만 선별
5. 완료 기준 — 체크리스트
6. 커밋 메시지 — `[카테고리] 요약` 형식

## 준수 조항 필수 포함

- 헌법 4조 1항: API 키/비밀정보 절대 생성 금지
- 헌법 3조 1항: 타임스탬프 `date` 명령 취득
- 헌법 3조 2항: 완료 보고 필수

## 제시 방식

- 파일 작성 후 **마크다운 링크**로 제시: `[파일명](상대경로)`
- 작가님이 드래그하여 터미널 투입하는 방식
- `pbcopy` 클립보드 사용 금지 (VSCode 환경 불안정)

## 수신 게이트 (2026-08-13 신설 — PETITION_20260806 #8)

- 지시서는 **수신 에이전트의 첫 응답(수신 확인)까지 발행 미완**으로 취급한다. 발행자는 수신 확인 여부를 자기 세션 로그에 기록한다.
- **만료**: 발행자의 다음 세션 시작 시점까지 수신 확인이 없으면 만료로 판정한다.
- **만료 시 조치**: 작가님 보고 후 재토스 또는 타 막내 재배정. 상태 방치 금지 (근거: 2026-08-06 심사 지시서 7일 방치 실사고 — 확인 부재가 아니라 감지 후 조치 부재가 손실 구간).
- **긴급 예외**: 핫픽스·장애 대응 지시서는 구두 토스 즉시 착수 + 사후 기록으로 게이트를 우회할 수 있다 (헌법 3조 3항 INCIDENT 최소 필드 예외 준용).
