> 원천: ch3 3조 (세션 마감 절차) + ch3 1조 (기본 규칙 — 보고 파일 수거)

## 세션 마감 절차

### 1단계 — 세션 로그 완료 사항 작성 (ch3 3조)

1. 세션 로그에 완료 사항을 기입한다:
   ```markdown
   ## 완료 사항
   - [x] 작업 1
   - [x] 작업 2

   ## TODO
   - [ ] 다음 작업

   ---
   **세션 종료: HH:MM KST**
   ```
2. 종료 시각은 `date` 명령으로 취득한다 (헌법 제3조 1항).

### 2단계 — 보고 파일 수거 (ch3 1조, 쌍아 전용)

1. `monkos-ops/ops/reports/` 내 COMPLETION 파일을 확인한다.
2. 수거 시 민감 정보 유무를 확인한다. 발견 시 해당 커밋의 보정을 지시한다.
3. 수거 내용을 자기 세션 로그에 통합 기록한다.
4. 통합 후 보고 파일은 삭제하지 않는다 (원본 보존 원칙).

### 3단계 — PF 히스토리 갱신 체크 (ch3 3조 + ch4 9조)

1. 이번 세션에서 활성 PF 대상 작업이 있었는지 확인한다.
2. 있었다면 해당 PF 히스토리에 1행 어펜드한다 (`| 날짜 | 주체 | 내용 | 산출물 | 상태 |`).
3. PF 대상 작업이 없었다면 스킵.
4. **이 단계를 건너뛰지 않는다** — 세션 마감의 핵심 의무.
5. 처리한 일이 브리핑 승계 번호와 관련 있으면 `scripts/brief_ledger.sh resolve --id N --evidence "{SHA·2회 히트·대조군·HH:MM 중 1}" --by {디바이스}/{에이전트}` 1행.

### 4단계 — 월별 폴더 검증

1. 이번 세션에서 생성한 파일(세션로그, 보고서, 지시서)이 **월별 폴더 안에** 있는지 확인한다.
2. 루트에 생성된 파일 발견 시 즉시 해당 월 폴더로 이동.

### 5단계 — 커밋 (ch3 3조)

1. 보고서·로그 파일을 커밋한다.
2. 커밋 메시지에 `[log]` 태그를 포함한다.

### 6단계 — push (ch3 3조)

1. `scripts/mk-push.sh`를 실행한다 (main push — works 스텝은 2026-08-13 채널 폐지로 소멸).
2. push가 완료되어야 세션 마감으로 인정한다.
3. push 미완료 시 **세션 미마감**으로 간주한다.
4. **푸시 게이트 (2026-08-13 신설 — PETITION_20260806 #7)**: push 직후 `git status -sb`로 `ahead`를 **실측**한다.
   `ahead` 표기가 남아 있으면(=미푸시 커밋 존재) 마감 보고에 미푸시 커밋 수와 원인을 명기한다. 무음 마감 금지.
   mk-push.sh가 행·중단된 경우에도 이 실측은 독립적으로 수행한다 (게이트는 스크립트 밖에 둔다).

### 7단계 — CHANGELOG 갱신

1. `monkos-ops/ops/MEMORY_CHANGELOG_{디바이스}.md`를 갱신한다.
2. MEMORY.md 변경사항이 있었다면 변경 내용을 기록한다.

### 8단계 — push 최종 확인

1. push 성공 여부를 `git status -sb`(ahead 부재)로 실측 확인한다 (6단계-4 게이트와 동일 기준).
2. 에이전트는 보고와 push를 하나의 연속 동작으로 처리한다 (승인 대기 누락 방지).
