## 막내 마무리 절차

### 1단계 — 완료 보고 파일 생성

1. 아래 경로에 보고 파일을 생성한다:
   - `monkos-ops/ops/reports/YYYY-MM/COMPLETION_YYYYMMDD_막내N_{HHMMSS}.md`
2. YAML frontmatter 필수 필드:
   ```yaml
   ---
   type: completion
   date: YYYY-MM-DD
   time: HH:MM KST
   from: {디바이스}/막내N
   to: {지시서 from 또는 작가님(직접지시 시)}
   order: {지시서 파일명 또는 "[직접지시]"}
   commit: {커밋 해시 7자리}
   branch: main
   ---
   ```
3. 본문은 헌법 제3조 2항 형식(`✅❌💡⏳📁🔀`) 준수.
4. 변경 파일 목록, 커밋 해시, push 상태를 포함한다.

### 2단계 — 보안 수칙 점검

1. 보고 파일에 아래 항목이 포함되어 있지 않은지 확인한다:
   - API 키, 토큰, 비밀번호 (헌법 4조)
   - 사용자 개인정보 (이메일, 전화번호, 결제 정보, OAuth 계정 ID)
   - 서버 URL, 내부 IP
2. 에러 로그 인용 시 민감 정보를 마스킹한다.
3. 보고 파일은 Git 이력에 영구 기록된다 — 민감 정보 커밋 시 복구 비용 극히 높음.

### 3단계 — PF 히스토리 어펜드

1. 지시서의 `portfolio:` 필드를 확인한다.
2. 해당 PF가 있으면 히스토리에 1행 어펜드한다:
   - `| MM/DD | {에이전트} | {작업 요약} | {산출물 링크 또는 커밋 해시} | ✅ |`
3. `portfolio:` 필드가 없거나 PF 무관 작업이면 스킵.
4. 처리한 일이 브리핑 승계 번호와 관련 있으면 `scripts/brief_ledger.sh resolve --id N --evidence "{SHA·2회 히트·대조군·HH:MM 중 1}" --by {디바이스}/{에이전트}` 1행.

### 4단계 — 월별 폴더 배치 확인

1. 생성한 COMPLETION 파일이 `reports/2026-MM/` 안에 있는지 확인한다.
2. 세션 로그도 `sessions/2026-MM/` 안에 있는지 확인한다.
3. 루트에 있으면 즉시 이동.

### 5단계 — 커밋

1. 작업 파일 + 보고 파일을 함께 `main` 브랜치에 커밋한다.
2. 세션 로그 포함 시 커밋 메시지에 `[log]` 태그를 추가한다.

### 6단계 — push

1. `git push origin main` 을 실행한다.

### 7단계 — 엔드라인 추가 작업 (조건부)

1. 지시서 엔드라인에 따른 추가 작업을 수행한다 (ch1 3조 참조):
   - `커밋+push`: 3~4단계로 완료.
   - `배포`: 3~4단계 + 배포 실행 (deploy-cf 또는 deploy-cr 절차).
   - `보고 대기`: 3~4단계 + 배포 대기 명시.
2. `main` 머지 + prod 배포는 **금지** — 작가님 별도 지시 시에만.

### 8단계 — 터미널 완료 보고 출력

1. 터미널에 헌법 제3조 2항 형식으로 완료 보고를 출력한다.
2. 보고가 세션 마지막 출력이다 (보고 후 잡담 금지).

### 파일 충돌 방지

- 파일명에 `HHMMSS` 포함 → 동시 보고 시에도 충돌 없음.
- 다른 막내의 보고 파일을 수정/삭제하지 않는다.
- 다른 에이전트의 세션 로그 파일을 편집하지 않는다 (분산 기록 원칙).
