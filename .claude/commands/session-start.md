## 디바이스 판별

> 정본은 SessionStart 훅(`scripts/hooks/session_start.sh`)의 `디바이스=` 값과 `판별` 출처다. 11-03 정본화(ORDER_20261103 막내8 — M1·4060이 `웹(원격)/민아`로 오판되던 결함 교정). 위에서부터 먼저 맞는 것이 이긴다.

| 순위 | 신호 | 디바이스 |
|------|------|---------|
| 1 | 환경변수 `MONK_DEVICE` (`iMac`·`M1`·`M2`·`4060`·`웹`) | 그 값 |
| 2 | 기기 로컬 파일 `~/.claude/monk-device` 1행 (같은 허용값, Windows=`%USERPROFILE%\.claude\monk-device`, BOM·CRLF 허용) | 그 값 |
| 3 | hostname `iMac` | iMac |
| 3 | hostname `Macminiui-Macmini` / `macmini-macmini` / `MacBook` / `M1` | M1 |
| 3 | hostname `MONK-4060` / `monk-4060`, `uname -s`=`MINGW*`·`MSYS*`·`CYGWIN*`, WSL | 4060 |
| 3 | hostname `mac-mini` / `Mac-mini` / `M2` | M2 |
| 4 | `CLAUDE_CODE_REMOTE=true` (클라우드 세션 양성 신호, 공식 문서 env-vars) | 웹(원격) → 역할 웹 민아 |
| 5 | 그 외 | **미확인** + `[HOOK-ERR] 기기 미확인` — 역할은 덮지 않는다. 해당 기기에 `~/.claude/monk-device`를 만든다 |

- 허용값 밖 `MONK_DEVICE`·파일 값은 `[HOOK-ERR]`로 알리고 다음 순위로 넘어간다.
- 훅이 `디바이스=미확인`을 내면 헤더에 기기를 추정해 쓰지 말고 첫 보고에 1줄로 알린다.

## 절차

1. 위 동적 주입 결과에서 타임스탬프, 디바이스, 역할을 확정한다.
2. origin/main에 신규 커밋이 있으면 머지한다.
3. MEMORY.md를 읽는다.
4. **옛 인스턴스 확인 (10-02 신설)**: `ListAgents`로 피어 목록을 조회해, 같은 디바이스·역할의 **다른 살아 있는 세션**(예: 이름 `iMac-쌍아-*`, 구 이름 `iMac-쌍아` 등)이 있으면, 그리고 훅 도입(10-02) 전에 열려 자동 이름이 없는 같은 표면 세션(VSCode는 `monk-project-xx`, 앱은 `Claude Desktop session` 표기)이 있으면 시작 시각과 함께 첫 보고에 1줄로 알린다 — `⚠️ 옛 세션 살아 있음: {이름} — 세션 간 메시지가 그쪽으로 갈 수 있음`. 닫는 것은 작가님 손이다. 세션 이름은 훅이 `{디바이스}-{역할}-{MMDD}-{HHMM}`으로 자동 지정한다(기존 이름은 유지).
   - **이름 자가 교정 (10-02 신설 — 작가님 12:57 지시, 민아 실증)**: `ListAgents`의 `This session is` 값이 훅이 낸 `세션 이름:` 값과 다르면 **묻지 않고 이 절차 안에서 바로 고친다**. 데스크톱 앱(민아)은 첫 발화로 제목을 사용자 출처로 지정해 훅 이름을 덮는다 → `mcp__ccd_session_mgmt__set_session_title`(`session_id="self"`, `title`=훅 이름)을 호출하고 `ListAgents`를 다시 읽어 반영을 확인한다(지연 도구면 ToolSearch로 먼저 로드). 같은 기기 피어 목록에도 반영된다(12:57 실측). 이 도구가 없는 표면(VSCode 확장·CLI)은 교정 수단이 없으므로 아래 시작 알림 1줄로 대신한다. 교정에 실패하면 무음으로 넘기지 않고 첫 보고에 `⚠️ 세션 이름 교정 실패: {현재 이름}` 1줄을 쓴다. 작가님이 직접 붙인 이름(규칙 형식이 아닌데 첫 발화 문구도 아닌 이름)은 건드리지 않는다.
   - 보내는 쪽 규칙: 같은 기기·역할이 여럿이면 이름의 날짜·시각이 가장 늦은 세션으로 보낸다. 회신은 받은 메시지의 `from` 주소로.
   - **옛 세션 비활성화 (10-03 신설 — 작가님 12:41 A안 승인, 민아 실증)**: 같은 기기·역할의 옛 세션은 새 세션이 **Remote Control off → 아카이브** 순으로 비활성화한다. 죽이는 것이 아니라 숨기는 것이다 — 아카이브는 프로세스를 멈추고 사이드바에서 내리되 대화 기록은 보존되며, Archived 목록에서 일부러 열어야 보인다. 통신 인계는 이것으로 성립한다(피어 목록에서 사라져 세션 간 메시지가 새 세션으로만 간다).
     - 데스크톱 앱(민아): `mcp__ccd_session_mgmt__list_sessions`로 같은 작업 폴더·역할의 옛 세션을 찾아 `set_remote_control(enabled=false)` → `archive_session`(사유에 승인 출처 기재). 작가님 범위 승인(10-03 12:41)으로 세션별 재승인은 불요. 상대가 작업 중(busy)이면 아카이브가 거부되므로 건너뛰고 첫 보고에 1줄. 다른 기기에서 연 세션은 도구가 거부한다 → 그 기기 몫. 아카이브 후 `ListAgents` 재조회로 소멸을 확인한다.
     - VSCode 확장(쌍아)·CLI(막내): 세션 관리 도구가 없다 → 첫 보고에 옛 세션 목록(이름·시작 시각) + `닫아 주세요` 1줄. 닫기는 사람(iMac=작가님, M2=꾸)이 그 창에서 한다. 프로세스 kill로 대체하지 않는다(작가님 10-03 "억지로 죽인다기보다"). 옛 VSCode 세션의 Remote Control은 자동 연결 설정 때문에 켜진 채 남으므로 닫기 전까지 기기 간 메시지가 그쪽으로 갈 수 있다. M2 쌍아에도 동일 적용(작가님 12:41).
     - 실증 10-03 12:42(iMac/민아): 옛 민아 3건 Remote Control off → 아카이브 → 피어 목록 53→47, 민아 옛 세션 0건. iMac VSCode 쌍아 옛 세션 3건(10-01 12:41·10-02 10:47·10-02 12:19 시작)은 도구 밖 — 보고로 대체.
   - **시작 알림 1줄 (10-02 실증 보완)**: 훅 이름은 **기기 간(Remote Control)에만 반영되고, 같은 기기 피어 목록에는 기본 이름(`monk-project-xx`)으로 남는다**(원인 미확정, 민아 12:22 실측). 그래서 새 세션은 같은 기기의 살아 있는 부서장 세션(쌍아·민아)에 `[세션 시작] {훅 이름} · 로컬 주소 {ListAgents 'This session is' 값}` 1줄을 먼저 보낸다. 받는 쪽은 `from` 주소로 답한다. 알림이며 지시·승인이 아니다. 상대가 없으면 보내지 않는다. 예비 수단은 수동 `/rename`(로컬 반영 전례 있음).
5. 첫 인사를 출력한다:
   - 쌍아: `[YYYY-MM-DD HH:MM KST] {디바이스}/쌍아입니다. 지시 대기합니다.`
   - 막내: `[YYYY-MM-DD HH:MM KST] {디바이스}/막내입니다. 지시서 수신 대기합니다.`
   - 소소: `[YYYY-MM-DD HH:MM KST] {디바이스}/소소입니다. 브리프 대기합니다.`
6. 동기화 결과를 보고한다. 이 절차를 완료하기 전까지 신규 작업에 착수하지 않는다.
