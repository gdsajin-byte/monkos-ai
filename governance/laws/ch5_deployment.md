### 1조: monk.kr 배포 (CF Pages)

1. **자동빌드 OFF.** Git push = 코드 저장만. **배포 ≠ push.** 배포 워크플로에 `push`·`schedule`·`repository_dispatch` 트리거를 두지 않는다.
2. **배포 = 승인자 트리거 2경로.**
   - ① **[기본] 버튼 배포** — `.github/workflows/deploy-monk-kr.yml` `workflow_dispatch`
   - ② **[예비]** `wrangler pages deploy` 수동 실행 — ①이 불능일 때만. 사용 시 세션 로그에 `[1조 예비경로: 사유]`를 기재한다.
3. **트리거 권한: 작가님.** 에이전트는 ch1 7조 2항에 따라 **새 사용자 턴으로 도착한 작가님 승인을 수신한 뒤에만** 트리거한다. 같은 응답 블록 안에서 생성한 승인은 승인이 아니다. **1회 승인 = 1회 트리거(당일 한정).** 동일 사유·동일 커밋의 즉시 재시도는 1승인 내로 본다. **무인 맥락(데몬·크론·Routines) 트리거 금지.**
   - **한계**: 에이전트 자격증명은 작가님 계정을 공유하므로 본 항은 트리거 주체를 기계적으로 검증하지 못한다(ch1 7조 4항 준용). 주체 식별은 4항의 흔적에 의존한다.
4. **흔적 의무.**
   - 사유 입력은 `{주체} | {승인 수신 시각} | {사유}` 서식을 따른다. 워크플로가 서식을 검증하고 불일치 시 배포하지 않는다. 작가님 직접 실행은 승인 시각에 `직접`.
   - 에이전트가 트리거한 경우 세션 로그에 **run ID · 배포 커밋 SHA · 승인 수신 시각**을 기재한다. 미기재 트리거는 무승인 배포로 간주한다.
5. **배포 대상.**
   - 버튼: 기본은 main HEAD. 선택 입력 `sha` 지정 시 해당 커밋을 배포한다.
   - 예비 경로: 배포 전 `git status --porcelain MONK_kr/ functions/`가 비어 있어야 한다. 미커밋 상태 배포는 장애 대응에 한하며 세션 로그에 사유를 기재한다.
   - 배포 페이로드 규율(미추적 입력 자산)은 **6조 게이트 6**을 따른다.
6. **표준 명령(예비 경로)**: `npx wrangler pages deploy MONK_kr/ --project-name monk-kr --branch main --commit-dirty=true`
   - CWD = 프로젝트 루트 (wrangler가 CWD의 `functions/`를 참조). 정본: **루트 `functions/`** (실제 디렉토리). `MONK_kr/functions/`는 없음 (2/20 제거).
   - Production = `--branch main`, Preview = 미지정. 이 명령 외의 배포 진입점을 두지 않는다.
   - **wrangler 버전 정본 = `package.json` 정확 고정**(범위 지정 금지). 버튼 배포도 같은 버전을 쓴다.
7. **스모크 판정**: 상태코드 단독 판정 금지. CF Pages는 미존재 경로에도 200을 반환한다(09-26 음성 대조군 실측). 판정은 **콘텐츠 어서션**으로 한다. 공개 도메인(monk.kr) 최종 판정은 **승인자 기기의 2회 히트**로 한다 — 러너는 존 정책상 403을 받으므로 CI green은 배포 도달의 증거일 뿐 monk.kr 반영의 증거가 아니다.
8. **배포 실패 표기는 미배포의 증거가 아니다.** 스모크는 배포 이후에 실행되므로 run failure 시 스텝 단위로 배포 반영 여부를 확인한 뒤 재배포·롤백을 판단한다.
9. **롤백**: 버튼에 직전 정상 커밋 `sha`를 지정해 재배포한다. 불능 시 CF 대시보드에서 직전 배포로 되돌린다. 롤백 단위 = 커밋.
10. **배포 대기 알림**: `MONK_kr/`·`functions/` 변경이 main에 푸시되면 작가님에게 "배포 대기" 알림을 보낸다(기존 텔레그램 경로). 알림 자체는 배포하지 않는다.

- **부칙**: 4항 서식 검증·5항 `sha` 입력·7항 콘텐츠 어서션·10항 알림의 기계 집행은 워크플로 구현 지시서(`ORDER_20260926_iMac쌍아_막내3_KKU_monkkr버튼배포_v21구현.md`) 완료 시 발효한다. 그 전까지 해당 항은 조문으로 집행한다. → **09-26 해소**: 4항(run 36228467825 통과·36228649112 배포 전 차단)·7항(어서션 7/7)·10항(알림 실발송) 실증. 5항 `sha` 입력은 구성 확인·실사용 미실증 — 첫 사용(롤백 포함) 시 세션 로그에 결과 기재. → **10-02 첫 사용**: run 36994859500(민아) `sha`=`ad8f9a09` 체크아웃 확인. run 목록 `headSha`는 디스패치 ref HEAD로 표시되므로 실제 배포 커밋은 실행 로그 "배포 커밋" 줄로 확인한다. 롤백 시나리오는 미실증.
- **부칙(승인·미발효, 2026-10-02)**: 꾸 범위 위임(3항 개정·3항의2 범위 게이트 신설)은 PETITION_20261002_쌍아_꾸배포권한위임_범위게이트 — 3역 조건부 찬성·작가님 승인(19:18). **발효 선행 조건 P1~P5(같은 청구안 §6) 충족 시 본문에 반영하여 시행한다.** 그 전까지 3항(트리거 = 작가님)은 현행 그대로다.

### 2조: monkos.ai 배포 (Cloud Run)

- 반드시 `deploy.sh` 경유. `gcloud run deploy` 직접 실행 **금지**. `gcloud builds submit` 단독 **금지**.
- **지시서에 배포용 gcloud 명령을 직접 기재하는 것을 금지한다.** 배포가 필요한 지시서는 `./deploy.sh {env}` 형태로만 기재한다.
- **비배포 gcloud 명령(describe, list, domain-mappings 등)은 본 조항의 금지 대상이 아니다.**
- **리전 하드코딩 금지.** deploy.sh 내 REGION 변수가 정본이다. 지시서·구두 지시·스크립트에서 리전을 별도 지정하지 않는다.
- 배포 타겟: 전 서비스 `us-central1` (MEMORY.md 참조).
- **한시적 예외: pt.monkos.ai** — `pt` 서비스는 asia-northeast1에 도메인 매핑. pt 전용 deploy.sh가 제작될 때까지 gcloud 직접 배포를 허용하되, 지시서에 `[2조 한시적 예외: pt]`를 명기한다. deploy.sh 제작 완료 시 본 예외는 자동 소멸한다.
- **적용 제외: monk-n8n** — 워크플로우 엔진 특수 서비스로 본 조항의 적용 대상에서 제외한다.
- `./deploy.sh dev` — 막내 허용.
- dev 배포 후 **반드시 동작 확인** → 완료 보고에 결과 명시.
- prod 배포가 필요한 경우 `⏳ 대기: prod 배포 필요` 명시.
- **막내 방어 의무**: 지시서에 배포용 gcloud 명령이 직접 기재되어 있을 경우 막내는 실행 전 2조 위반을 보고하고 deploy.sh 경유로 전환한다.
- **무인 실행 안전**: deploy.sh는 `--yes` 플래그 없이 비TTY 환경에서 실행 시 명시적 실패(exit≠0)한다. 무입력이 exit 0으로 조용히 미배포되는 것을 금지한다.

### 6조: 배포 게이트 표준

**라이브 서비스로 배포되는** 모든 배포 경로(`deploy.sh`·배포 워크플로·표준 수동 명령)는 다음 게이트 중 **해당 경로에 성립하는 것**을 갖춘다. 성립하지 않는 게이트는 사유를 1행으로 남긴다. 신규 작성 시에도 동일하게 적용한다. *(09-26 확대 — 종전 "모든 `deploy.sh`")*

| # | 게이트 | 요건 |
|---|--------|------|
| 1 | **엄격 모드** | `set -euo pipefail`. 미정의 변수 참조는 `${VAR:-}` 로 명시 처리한다 |
| 2 | **미커밋 게이트** | **해당 서비스 디렉터리**의 미커밋 변경 존재 시 **차단(exit 1)**. `--yes` 지정 시 경고 출력 후 진행. 비TTY 무입력이 진행으로 해석되지 않을 것 |
| 3 | **드리프트 감지** | **정적 산출물을 별도 파이프라인으로 빌드·배포하는 서비스에 한한다.** 해시 대상에서 **gitignore 산출물을 제외**한다. 불일치 시 "구본 상태" 명시 경고 |
| 4 | **사후 스모크** | **공개 도메인이 매핑된 서비스에 한한다.** 배포 후 대상 표면 실측, 실패 시 `exit≠0`. **종료는 드리프트 원장 기록 이후에 위치시킨다** |
| 5 | **이중 소스 경고** | 동일 서비스로 배포하는 디렉터리가 복수인 경우 배포 전 경고 |
| 6 | **미추적 입력 자산 금지** | 배포 페이로드에 저장소 미추적 **입력** 자산(배포자 기기에만 있는 원본)을 포함하지 않는다. 결정적 빌드의 산출물(gitignore된 `dist` 등)은 대상에서 제외한다. 작업 트리를 직접 올리는 경로(`wrangler pages deploy`, `gcloud builds submit`)에 적용하며 checkout 기반 경로는 구조적으로 충족한 것으로 본다. 집행은 CI 비블로킹 경고로 시작한다 |

- **무음 강등 금지.** 조건 미충족으로 건너뛸 때도 그 사실을 출력한다. 게이트 3·4 비적용 시 사유를 스크립트 주석 1행으로 남긴다.
- 게이트 미비 상태로 배포해야 하는 경우 **지시서 또는 세션 로그**에 `[5장 6조 예외: 사유]`를 명기한다 (경로②·③에는 지시서가 존재하지 않는다).
- **부칙(게이트별 이원화)**: 게이트 1·2·5는 **발효 후 14일**, 게이트 3·4는 **60일** 유예. 신규 작성·개정분은 즉시 적용. 서비스 미생성으로 배포가 차단된 스크립트는 **서비스 생성 시점에 의무가 발생**한다. **게이트 6은 기존 `deploy.sh`에 60일 유예**(현 빌드 컨텍스트의 미추적 이미지 정리 기간), 신규분은 즉시.
- **관찰 항목**: `-u` 승급의 실측은 스텁 기반이라 실패 경로를 전수 탐색하지 못했다. 발효 후 **첫 실배포 1회를 관찰 대상**으로 두되 장부화하지 않는다.

### 7조: 라이브 검증

- 표면이 변경됐다는 주장은 **라이브 실측**으로만 성립한다. 커밋·배포 성공·도구 exit 0은 반영의 증거가 아니다.
- **2회 히트**: **캐시 계층(CF 엣지 SWR 등)을 경유하는 GET 표면에 한하여** 1차 조회를 재검증 트리거로 버리고 **2차로 판정**한다. 쿼리 파라미터 캐시 버스팅은 무효로 간주한다.
- **비멱등 예외**: 계측·쿼터·발송·토큰 발급 등 호출 자체가 상태를 바꾸는 엔드포인트에는 2회 히트를 적용하지 않으며, 로그·DB·관리 콘솔 직접 조회로 판정한다.
- **콜드스타트 면책**: 웜 미보유 오리진(min-instances 0)의 1차 히트 지연은 실패로 계상하지 않는다.
- **브라우저 검증**: CDP 배포 확인 시 `Page.reload{ignoreCache:true}`를 필수로 한다. 캡처 판정은 뷰포트 캡처 + 실픽셀 확인으로 하며 `captureBeyondViewport` 결과만으로 부재를 판정하지 않는다.
- **대조군 의무**: 0건·404는 부재를 증명하지 않는다. 조회 자체의 유효성을 양성 대조군으로 먼저 배제한다. 1건 히트도 실물 마크업을 확인한다.
- **재측정 의무**: 과거 턴의 실측값을 재측정 없이 보고에 이월하지 않는다.
- 완료 보고에 라이브 판정을 기재할 때는 **판정 방법을 함께 적는다.** 방법 없는 판정은 미검증으로 간주한다.

**적용**: 배포 후 / CMS·Firestore 쓰기 후 / 설정·토글 변경 후.
