# 법률 제2장: 코딩 규칙

> 상위 헌법: 제3조(프로젝트 정체성), 제6조(인프라 보호)
> 변경 권한: 작가님 승인 시 개정 가능

---

### 1조: 기술 스택

- **현행**: 순수 JavaScript (async/await), HTML, CSS, Tailwind CSS.
- 기술 선택은 필요와 통제능력에 따른다. 법률로 특정 기술을 금지하지 않는다.
- **단, 새로운 프레임워크·라이브러리·언어 도입 시 구조적 설계가 선행되어야 한다.**
  - 도입 사유, 영향 범위, 기존 코드와의 정합성을 설계 문서로 제시 → 작가님 승인 후 적용.
  - 설계 없는 기술 도입은 금지한다.

> 근거: 프로젝트 초기 순수 JS 결정 (2026-01), 2026-03-14 현행화 — "기술은 필요와 통제능력에 따른 것이지 굳은 규칙으로 정할 것은 아니다. 구조적 설계가 선행되어야 한다"
> 상위 헌법: 제3조(프로젝트 정체성), 제7조(계획→승인→실행)
> 위반 시: 설계 없는 기술 도입 → 구조 파편화, 유지보수 비용 증가

---

### 2조: 네이밍 규칙

| 대상 | 규칙 |
|------|------|
| HTML/CSS | `kebab-case` |
| JavaScript | `camelCase` |
| 파일명 | `snake_case` |

> 근거: 2026-01 ~ 02-08 — CLAUDE.md 초기 규칙. 프로젝트 전반 일관 적용.
> 상위 헌법: 제3조
> 위반 시: 코드 검색/참조 실패, 에이전트 간 네이밍 혼동
> 예외: 외부 라이브러리 컨벤션 우선

---

### 3조: 언어 규칙

- **한국어 우선** (UI, 주석, 에러 메시지, 커밋 메시지).
- 일본 서비스(idphoto-jp)는 일본어 UI.

> 근거: 2026-01 ~ 02-08 — CLAUDE.md 초기 규칙. 프로젝트 초기 결정.
> 상위 헌법: 제3조(한국어 기본, 다국어 지원 EN/JA/ZH)
> 위반 시: 다국어 UI 혼재, 유저/에이전트 혼란

### 4조: CSS 규칙

- Tailwind로 표현 불가한 경우 인라인 스타일 허용.
- CSS 도구 변경 시 1조(구조적 설계 선행) 준용.

> 근거: 2026-01 ~ 02-08 — CLAUDE.md 초기 규칙.
