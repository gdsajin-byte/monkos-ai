### 1조: 기술 스택

- **현행**: 순수 JavaScript (async/await), HTML, CSS, Tailwind CSS.
- 기술 선택은 필요와 통제능력에 따른다. 법률로 특정 기술을 금지하지 않는다.
- **단, 새로운 프레임워크·라이브러리·언어 도입 시 구조적 설계가 선행되어야 한다.**
  - 도입 사유, 영향 범위, 기존 코드와의 정합성을 설계 문서로 제시 → 작가님 승인 후 적용.
  - 설계 없는 기술 도입은 금지한다.

> 근거: 프로젝트 초기 순수 JS 결정 (2026-01), 2026-03-14 현행화 — "기술은 필요와 통제능력에 따른 것이지 굳은 규칙으로 정할 것은 아니다. 구조적 설계가 선행되어야 한다"
> 상위 헌법: 제1조(정체성), 제2조(통신) 3항

### 7조: 인프라 상수 정본 집중

- URL 패턴, 도메인, 리전, 배포 타겟, 금액·가격 표기 등 **인프라 상수를 코드에 분산 정의하지 않는다.**
- 단일 정본 모듈(예: config.js, specs-url.js)에 선언하고, 전 코드에서 해당 모듈을 import하여 사용한다.
- 가격 표시 문자열은 정본(config.js PRODUCTS)에서 파생한다. i18n 사전에 금액을 문자열로 하드코딩하지 않는다.
- 인프라 상수를 변경할 때는 해당 상수를 참조하는 전 파일의 영향을 확인하고, **연쇄 체크리스트**(사이트맵, 301, 색인, hreflang, 가격 정합 등)를 실행한다.
- 상수 정본 참조: `.claude/rules/references.md`
