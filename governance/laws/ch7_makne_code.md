### 1조: 작업 흐름

**진입 경로:**

| 경로 | 시작점 | 기록 |
|------|--------|------|
| 지시서 경유 (원칙) | 지시서 수령 | 지시서 파일 참조 |
| 작가님 직접 지시 (보충) | 작가님 구두/채팅 지시 수령 | 세션 로그에 `[직접지시]` 태그 + 지시 내용 기록 |

**지시서 경유 시 흐름:**
```
지시서 수령 → 코드 읽기 → 수정 → 로컬 검증 → 커밋 → push → 완료 보고
                                                              ↑ 여기까지
                                              main 머지 + prod 배포는 막내 범위 밖
```

**작가님 직접 지시 수령 시 의무:**
1. 세션 로그에 `[직접지시]` 태그 기록 + 작가님 지시 내용 인용
2. `git pull origin main` 실행 (충돌 방지)
3. 사전 적합성 검토 (헌법·법률 위반 여부)
4. 실행 → 커밋+push → 완료 보고
5. 마무리: 기존과 동일. 엔드라인은 작가님 지시에 따른다.

#### 마무리 절차 (필수)

| 순서 | 절차 | 필수 여부 |
|------|------|----------|
| 1 | 완료 보고 파일 생성 (하단 참조) | **필수** |
| 2 | `main` 브랜치에 커밋 — 작업 파일 + 보고 파일 포함 (세션 로그 포함 시 `[log]` 태그) | **필수** |
| 3 | `git push origin main` | **필수** |
| 4 | 지시서 엔드라인에 따른 추가 작업 (ch1 3조 참조) | **조건부** |
| 5 | 터미널에 완료 보고 출력 (헌법 제3조(적립) 2항 형식) | **필수** |
| 6 | `main` 머지 + 배포 | **금지** — 작가님 별도 지시 시에만 |

#### 완료 보고 파일 생성 (필수)

모든 막내 완료 보고는 아래 경로에 파일로 생성한다:

**경로**: `monkos-ops/ops/reports/COMPLETION_YYYYMMDD_막내N_{HHMMSS}.md`

**YAML 필수 필드:**
```yaml
---
type: completion
date: YYYY-MM-DD
time: HH:MM KST
from: {디바이스}/막내N
to: {지시서 from 또는 작가님(직접지시 시)}
order: {지시서 파일명 또는 "[직접지시]"}
commit: {커밋 해시 7자리}
branch: main
---
```

**본문:** 헌법 제3조(적립) 2항 형식(`✅❌💡⏳📁🔀`) 준수. 변경 파일 목록, 커밋 해시, push 상태 포함.

**마무리 흐름 (개정):**
```
코드 작업 → 보고 파일 생성 → 커밋(작업+보고 포함) → push → 터미널 출력
```

**보안 수칙:**
- API 키, 토큰, 비밀번호, 사용자 개인정보(이메일, 전화번호, 결제 정보, OAuth 계정 ID) 기재 금지 (헌법 제4조(구속·윤리))
- 에러 로그 인용 시 민감 정보 마스킹 필수
- 서버 URL, 내부 IP는 마스킹 또는 생략
- 보고 파일은 Git 이력에 영구 기록된다. 민감 정보가 한 번이라도 커밋되면 복구 비용이 극히 높다.

**파일 충돌 방지:**
- 파일명에 `HHMMSS` 포함 → 동시 보고 시에도 충돌 없음
- 다른 막내의 보고 파일을 수정/삭제하지 않음
- 다른 에이전트의 세션 로그 파일을 편집하지 않음 (분산 기록 원칙 — 헌법 제3조(적립) 2항)

**적용 범위:**
- 완료 보고만 파일화한다. 에스컬레이션(ch7 4조)은 기존 터미널 출력을 유지한다.

#### 예외 규정

- 마무리 절차 예외는 **지시서 본문에 `[예외]` 명시** 필수
- 지시서 외부(구두/채팅)로는 예외 불가 — 추적 불가능한 예외는 예외가 아님
- 예외 히스토리는 해당 지시서에 남아 추적 가능
- **단, 작가님 직접 지시(ch1 2조 2항)는 지시서 외부 예외 금지의 적용을 받지 않는다** — 총괄 권한에 의한 직접 지시는 세션 로그 `[직접지시]` 태그로 추적성이 확보된다.

### 6조: 활성 PF 참조 의무

**원칙**: 작업 대상에 **활성 포트폴리오(PF)** 가 존재하고, 해당 PF에 **막힘 트리거
체크리스트**(또는 동격의 장애 대응 문서)가 정의되어 있을 경우, 에이전트는 예외·장애
감지 즉시 PF 기록을 선행 참조할 의무를 진다.

**참조 선행 원칙**:
- 가설 수립 전에 PF의 케이스 DB·골든패스·에디터 어댑터(또는 동격 문서)를 점검한다.
- "원리상 불가" 같은 큰 결론으로 뛰기 금지.
- 일치 케이스가 없을 때에만 새 가설을 세운다.

**신규 등록 의무**:
- 일치 케이스가 없는 장애는 해당 PF의 케이스 DB에 즉시 신규 등록한다 (append-only).
- 해결 시 원인·해법·재현성을 보강한다. 미해결 시 "다음 조치" 를 명시한다.

**스킬 위임**:
- PF별 절차 상세는 해당 PF 관할 skill로 위임한다.
- 현재 지정 skill: PF_CDP → `cdp-troubleshoot`.

**헌법 제3조(적립) 2항과의 관계**:
- 헌법은 PF **갱신(append)** 의무를 규정한다.
- 본 조는 PF **참조(read)** 의무를 규정한다.
- 두 의무는 적립-활용 사이클의 두 축이다.

**적용 범위**:
- 막내·민아·쌍아에 적용 (말머리 보편 적용 목록 참조).
- 팀원 에이전트(한·꾸)는 자체 CLAUDE.md에서 상속 여부를 정한다.
