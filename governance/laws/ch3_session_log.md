#### 보고 파일 수거 절차

- 쌍아는 세션 마감 시 `monkos-ops/ops/reports/` 내 COMPLETION 파일을 수거하여 세션 로그에 통합한다.
- 쌍아는 수거 시 민감 정보 유무를 확인한다. 발견 시 해당 커밋의 보정을 지시한다.
- 통합 후 보고 파일은 삭제하지 않는다 (원본 보존 — 본조 원본 수정/삭제 금지 준용).
- 세션 로그의 단일 관리자는 쌍아이며, 막내는 세션 로그 파일을 직접 편집하지 않는다.

### 2조: 형식

**헤더** (세션 시작 시 1회):
```markdown
# 세션 로그: YYYY-MM-DD (요일)

**환경:** [위치] ([장비] + Claude Code Opus 4.6)
**시작:** YYYY-MM-DD HH:MM
```

**본문** (매 작업 블록):
```markdown
### [HH:MM] 작업 주제

**작가님**: "중요 발언 직접 인용"
- 실행 내용
- 결과
```

**직접지시/추인 태그** (해당 시):
```markdown
### [HH:MM] [직접지시] 작업 주제
**작가님**: "직접 지시 원문 인용 필수"
- 실행 내용 + 결과

### [HH:MM] [추인] 작업 주제
- 쌍아가 직접지시 작업을 사후 확인 완료
```
- `[직접지시]`: 작가님 직접 지시로 수행한 작업 (ch1 2조 2항)
- `[추인]`: 쌍아가 직접지시 작업을 사후 확인 완료
- 직접지시 블록에는 작가님 지시 원문 인용 필수 (지시서 부재의 대체 기록)

- [x] 작업 1

- [ ] 다음 작업

### 3조: 세션 마감 절차

- 세션 마감 시 다음 순서를 준수한다:
  1. 세션 로그 작성 (완료 사항 + TODO + 종료 시각)
  2. 보고서·로그 파일 커밋
  3. **push 완료** — push가 완료되어야 세션 마감으로 인정
- push 미완료 시 **세션 미마감**으로 간주한다. 다음 세션 시작 시 즉시 push를 실행한다.
- 에이전트는 push 실행 시 사용자 승인 대기로 인한 누락을 방지하기 위해, 보고와 push를 하나의 연속 동작으로 처리한다.
- 각 디바이스의 `.claude/settings.local.json`에 `git push` 자동 허용이 설정되어 있어야 한다.

> 근거: 2026-03-04 — 세션 마감 시 push 승인 대기 → 누락 반복 문제. 작가님+쌍아 합의로 법률 개정.
