### 2조: 형식

**헤더** (세션 시작 시 1회):
```markdown
# 세션 로그: YYYY-MM-DD (요일)

**환경:** [위치] ([장비] + Claude Code Opus 4.6)
**시작:** YYYY-MM-DD HH:MM
```

**본문** (매 작업 블록):
```markdown
### [HH:MM] 작업 주제

**작가님**: "중요 발언 직접 인용"
- 실행 내용
- 결과
```

**직접지시/추인 태그** (해당 시):
```markdown
### [HH:MM] [직접지시] 작업 주제
**작가님**: "직접 지시 원문 인용 필수"
- 실행 내용 + 결과

### [HH:MM] [추인] 작업 주제
- 쌍아가 직접지시 작업을 사후 확인 완료
```
- `[직접지시]`: 작가님 직접 지시로 수행한 작업 (ch1 2조 2항)
- `[추인]`: 쌍아가 직접지시 작업을 사후 확인 완료
- 직접지시 블록에는 작가님 지시 원문 인용 필수 (지시서 부재의 대체 기록)

### 3조: 세션 마감 절차

- 세션 마감 시 다음 순서를 준수한다:
  1. 세션 로그 작성 (완료 사항 + TODO + 종료 시각)
  2. 보고서·로그 파일 커밋
  3. **push 완료** — push가 완료되어야 세션 마감으로 인정
- push 미완료 시 **세션 미마감**으로 간주한다. 다음 세션 시작 시 즉시 push를 실행한다.
- 에이전트는 push 실행 시 사용자 승인 대기로 인한 누락을 방지하기 위해, 보고와 push를 하나의 연속 동작으로 처리한다.
- 각 디바이스의 `.claude/settings.local.json`에 `git push` 자동 허용이 설정되어 있어야 한다.

> 근거: 2026-03-04 — 세션 마감 시 push 승인 대기 → 누락 반복 문제. 작가님+쌍아 합의로 법률 개정.
> 상위 헌법: 제1조 2항(분산 기록 및 완료 보고 의무)

### 5조: 세션 시작 절차

- 세션 시작 선언 시, 원격 저장소의 전 활성 브랜치에서 신규 변경사항을 확인한다.
  - `git fetch --all` → main 등 활성 브랜치별 신규 커밋 유무 확인
  - 미반영 커밋 발견 시: 머지 또는 리베이스 후 결과 보고
  - 신규 변경 없을 시: "동기화 완료, 신규 변경 없음" 보고
- 이 절차를 완료하기 전까지 신규 작업에 착수하지 않는다.
