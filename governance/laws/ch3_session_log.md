### 2조: 형식

**헤더** (세션 시작 시 1회):
```markdown
# 세션 로그: YYYY-MM-DD (요일)

**환경:** [위치] ([장비] + Claude Code Opus 4.6)
**시작:** YYYY-MM-DD HH:MM
```

**본문** (매 작업 블록):
```markdown
### [HH:MM] 작업 주제

**작가님**: "중요 발언 직접 인용"
- 실행 내용
- 결과
```

**직접지시/추인 태그** (해당 시):
```markdown
### [HH:MM] [직접지시] 작업 주제
**작가님**: "직접 지시 원문 인용 필수"
- 실행 내용 + 결과

### [HH:MM] [추인] 작업 주제
- 쌍아가 직접지시 작업을 사후 확인 완료
```
- `[직접지시]`: 작가님 직접 지시로 수행한 작업 (ch1 2조 2항)
- `[추인]`: 쌍아가 직접지시 작업을 사후 확인 완료
- 직접지시 블록에는 작가님 지시 원문 인용 필수 (지시서 부재의 대체 기록)

### 3조: 세션 마감 절차

- 세션 마감 시 다음 순서를 준수한다:
  1. 세션 로그 작성 (완료 사항 + TODO + 종료 시각)
  2. 활성 PF 히스토리 어펜드 (해당 PF가 있을 때. PF 대상 작업이 없는 세션은 스킵)
  3. 보고서·로그 파일 커밋
  4. **push 완료** — push가 완료되어야 세션 마감으로 인정
- push 미완료 시 **세션 미마감**으로 간주한다. 다음 세션 시작 시 즉시 push를 실행한다.
- 에이전트는 push 실행 시 사용자 승인 대기로 인한 누락을 방지하기 위해, 보고와 push를 하나의 연속 동작으로 처리한다.
- 각 디바이스의 `.claude/settings.local.json`에 `git push` 자동 허용이 설정되어 있어야 한다.
- PF 갱신 시점: 세션 종료뿐 아니라 **PF 간 작업 전환(일단락) 시**에도 해당 PF를 갱신한다.
- PF 갱신은 **쌍아가 수행**한다. 막내는 세션 로그 + 완료 보고서(COMPLETION)로 납품하고, 쌍아가 취합하여 PF에 반영한다. 기존 역할 체계(ch1 2조) 준용.
- 미갱신 발견 시: 다음 세션 시작 시 보정 의무.

### 5조: 세션 시작 절차

- **역할 인식**: 세션의 전제 조건. MEMORY.md 자동 인식 규칙에 따라 자신의 역할(쌍아/민아/막내)을 확인하고, 수발신 헤더·세션 로그 파일명·권한 범위를 확정한다. 역할 인식이 완료되기 전까지 후속 절차에 착수하지 않는다.
- 세션 시작 선언 시, 원격 저장소의 전 활성 브랜치에서 신규 변경사항을 확인한다.
  - `git fetch --all` → main 등 활성 브랜치별 신규 커밋 유무 확인
  - 미반영 커밋 발견 시: 머지 또는 리베이스 후 결과 보고
  - 신규 변경 없을 시: "동기화 완료, 신규 변경 없음" 보고
- 이 절차를 완료하기 전까지 신규 작업에 착수하지 않는다.
- 동기화 완료 후, **최근 맥락 요약**을 보고한다:
  - 활성 PF 목록 + 각 현재 Phase
  - 전 세션 마지막 작업 요약
  - 대기 중인 오더/보고 유무
- 작가님 선언에 따라 세션 프레이밍:
  - **PF 스타트**: "PF_XXX로 간다" → 해당 PF를 읽고 현재 상태 보고. 타겟 달리기 모드.
  - **오피스 모드** (디폴트): 선언 없음 → 서치·분석·문서화·일상 업무. 오피스에서 추적이 필요한 작업이 발생하면 PF로 분리·정의한다.
