# 파일 유형 레지스트리

> 법률(ch4 3조)은 패턴·경로만 규정한다. 본 레지스트리는 각 유형의 정의·용도·판단 기준을 담는 참조 테이블이다.
> 에이전트는 자체 정의 권한이 없으므로, 유형 판단 시 본 테이블을 참조한다.
> **원칙: 중복은 허용한다. 세상에 딱 하나만의 의미를 갖는 단어는 없기 때문이다.**

---

## 유형 테이블

| 접두사 | 정의 | 주체 | 정본 경로 | 판단 기준 |
|--------|------|------|----------|----------|
| `ORDER_` | 작가님의 의지. 미션 단위의 상의하달. 1 ORDER → N TASK 가능 | 작가님 (쌍아/철창이 대리 발행 가능) | `monkos-ops/ops/orders/` | "누군가에게 시키는 것"이 아니라 "이것을 하겠다는 결정" |
| `TASK_` | 법체계가 정의한 임무. 에이전트 단위의 실행 지시 | 쌍아 + 법체계 | `docs/monkos/tasks/YYYY-MM/` | 특정 에이전트가 수행할 구체적 작업 |
| `REPORT_` | 보고. 실행 결과의 확인 | 막내 (실행자) | `docs/monkos/reports/YYYY-MM/` | "이것을 했고 결과는 이렇습니다" |
| `RESEARCH_` | 조사. 의사결정을 위한 탐색 | 막내 (조사자) | `monkos-ops/ops/agenda/` | "이런 선택지가 있고 각각 이렇습니다" |
| `SPEC_` | 기술 명세 | 쌍아/막내 | `docs/monkos/specs/{service}/` | 서비스의 기술적 정의 |
| `INCIDENT_` | 장애 보고 | 발견자 | `docs/monkos/incidents/YYYY-MM/` | 서비스 장애 발생 시 |
| `DESIGN_` | 설계 문서 | 쌍아 | `docs/monkos/designs/YYYY-MM/` | 기능/시스템 설계 |
| `SPRINT_` | 스프린트 계획 | 쌍아 | `docs/monkos/sprints/` | 주간/격주 작업 계획 |
| `PETITION_` | 법률/헌법 개정 청구 | 누구든 | `governance/constitution/petitions/` | 법체계 변경 요청 |

## ORDER와 TASK의 관계

```
ORDER (작가님의 의지 — 미션)
├── TASK_1 (막내1 실행분)
│   └── REPORT_1 (실행 결과)
├── TASK_2 (막내2 실행분)
│   └── REPORT_2 (실행 결과)
└── RESEARCH (조사 산출물)
```

ORDER는 TASK의 상위가 아니라 **출발점**이다. 작가님의 결정이 ORDER로 기록되고, 그 결정을 실행하기 위해 TASK가 파생된다.

## 애매할 때

유형 경계가 애매한 경우 — 가장 가까운 것에 놓는다. 중복은 오류가 아니다.
