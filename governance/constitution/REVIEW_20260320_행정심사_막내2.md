### 항목 1: 현행 지시서·보고서·세션로그에서 민아/코웍이 헤더 형식 충돌 여부

**판정: `보정필요`**

#### 실태 조사

코웍이 기존 산출물의 헤더 형식을 실측한 결과:

| 문서 | 헤더 형식 | 비고 |
|------|----------|------|
| `SESSION_20260320_M1_코웍이.md` | `M1/코웍이` | 물리 디바이스명 사용 |
| works/CLAUDE.md 수발신 규정 | `{디바이스}/{에이전트} → {수신자}` | 본진 ch1 4조와 동일 패턴 |
| 코웍이 지시서 파일명 | `ORDER_20260317_코웍이→쌍아_...` | 에이전트명만 사용 (디바이스 생략) |

**충돌 지점:**

1. **코웍이 세션로그에서 이미 `M1/코웍이` 형식을 사용 중.** 청구안은 코웍이 환경을 "Desktop App (웹+CLI)"로 정의하면서 디바이스명으로 "Desktop"을 신설하려 한다. 기존 `M1/코웍이` 패턴과 `Desktop/코웍이` 패턴이 공존하면 시계열 추적에 불일치 발생.

2. **코웍이 지시서 파일명에서 디바이스 생략 패턴 발견.** `ORDER_20260317_코웍이→쌍아_...`는 ch4 3조 11번 패턴(`ORDER_YYYYMMDD_{topic}.md`)과 ch1 4조 수발신 헤더(`{디바이스}/{에이전트}`)의 혼용. 디바이스 기재가 일관되지 않음.

3. **민아는 아직 산출물 없음** → 신규 도입이므로 헤더 충돌은 없으나, 개헌 시 코웍이 기존 산출물과의 일관성 확보 방안 필요.

#### 보정 제안

- 코웍이 기존 산출물의 `M1/코웍이` 패턴을 정식화하거나, 향후 `Desktop/코웍이`로 전환할 것인지 명확히 정의
- 코웍이 지시서 파일명에서 디바이스 생략 패턴은 ch1 4조 위반 → works/ 채널 내부 운용 예외로 인정할 것인지, 또는 보정할 것인지 결정

### 항목 2: 디바이스맵에 "Desktop" 추가 시 기존 수발신 헤더 패턴과의 호환성

**판정: `보정필요`**

#### 문제 분석

현행 디바이스맵의 모든 항목은 **물리 하드웨어**다:

| 호칭 | 본질 |
|------|------|
| M1, iMac, M2, M4, 4060 | 물리 컴퓨터 |
| iPhone | 물리 단말기 |
| **Desktop** (신설안) | **소프트웨어 애플리케이션** |

"Desktop"은 Claude Desktop App이며, iMac에서도 M1에서도 실행 가능하다. 이는 기존 디바이스맵의 설계 원칙("호칭만으로 소유·위치가 식별되어야 한다" — 헌법 2조 2항)과 **구조적으로 충돌**한다.

#### 영향 범위

| 영역 | 영향 |
|------|------|
| ch1 4조 수발신 헤더 | `Desktop/민아`의 "Desktop"이 물리 위치를 나타내지 못함 — "어디서" 추적 불가 |
| ch1 5조 hostname 판별 | Desktop App의 hostname은 호스트 머신과 동일 (iMac에서 실행 시 hostname=iMac) → hostname으로 Desktop을 구분할 수 없음 |

#### 보정 제안 (2안)

**A안 — 디바이스명은 물리 기기 유지, 환경 구분은 자동 인식에서 처리:**
- 민아: `iMac/민아` 또는 `M1/민아` (물리 기기 기준)
- 디바이스맵에 "Desktop" 추가하지 않음
- ch1 5조 자동 인식에서 `Claude Desktop` 키워드로 민아 판별

**B안 — "Desktop" 디바이스명 도입하되, 호스트 기기를 병기:**
- 디바이스맵에 Desktop 추가 (위치: "호스트 의존")
- 헤더 형식: `Desktop(iMac)/민아` 또는 `Desktop/민아 @iMac`
- 단, 기존 헤더 파싱 규칙 변경 필요

**권장: A안.** 기존 디바이스맵 원칙(물리 기기 = 위치 식별)을 유지하는 것이 행정상 가장 안전하다. 코웍이도 이미 A안 패턴을 따르고 있다.

### 항목 3: 민아 자동 인식 규칙이 기존 쌍아/막내 판별과 충돌하지 않는지

**판정: `보정필요`**

#### 문제 분석

**청구안의 자동 인식 규칙:**

| 조건 | 역할 |
|------|------|
| `VSCode native extension` 포함 | 쌍아 |
| `Claude Desktop` 또는 `desktop` 포함 | 민아 **(신설)** |
| 그 외 (CLI) | 막내 |

**3가지 문제:**

**문제 A — `desktop` 키워드 과잉 매칭:**
- 소문자 `desktop`은 일반 영단어로 광범위하게 사용됨
- 시스템 프롬프트에 "desktop browser", "desktop application", "desktop environment" 등이 포함될 경우 오탐 발생 가능
- 실제 Claude Desktop App의 시스템 프롬프트에 어떤 식별 문자열이 포함되는지 검증 필요

**문제 B — 코웍이 자동 인식 규칙 부재:**
- 청구안은 코웍이를 "Desktop App (웹+CLI)" 환경으로 정의
- 그러나 자동 인식 규칙에는 Desktop → **민아만** 매핑
- 코웍이도 Desktop App이라면, 같은 환경에서 두 에이전트(민아/코웍이)를 어떻게 구분하는가?
- 코웍이는 works/ 채널 전용이므로 CLAUDE.md가 다르다(works/CLAUDE.md)는 점에서 구분 가능하나, ch1 5조의 "시스템 프롬프트 기반 자동 판별"과는 별개 메커니즘

**문제 C — 우선순위 미명시:**
- 현행 ch1 5조는 2개 조건(VSCode → 쌍아, 그 외 → 막내)이라 우선순위 불필요
- 3개 이상이 되면 매칭 순서가 중요해짐
- 예: 시스템 프롬프트에 `desktop`과 `VSCode`가 동시에 포함되면?

#### 보정 제안

1. `desktop` → `Claude Desktop` 정확한 문자열로 한정 (소문자 `desktop` 단독 삭제)
2. 코웍이 자동 인식: works/ CLAUDE.md의 자체 인식 체계로 별도 운용하고, ch1 5조에는 "코웍이는 works/CLAUDE.md 준용" 주석 추가
3. 우선순위 명시: VSCode → Desktop → CLI (위에서 아래로 순차 매칭)
