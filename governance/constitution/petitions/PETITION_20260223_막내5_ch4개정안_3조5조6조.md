## A. ch4 3조 개정안: 파일 네이밍 규칙 확장

### A-1. 패턴 #10 신설: PETITION

**현행**: 9유형 (TASK, REPORT, SPEC, INCIDENT, DESIGN, SPRINT, 세션로그 3종)
**현실**: PETITION 파일이 이미 2건 존재하고, 본 청구로 3건째. 사실상(de facto) 패턴이 확립됨.

**청구안**: 3조 패턴 테이블에 #10 추가

| # | 패턴 | 대상 폴더 | 예시 |
|---|------|----------|------|
| 10 | `PETITION_YYYYMMDD_{agent}_{topic}.md` | `governance/constitution/petitions/` | `PETITION_20260222_막내5_법률개정청구_3건.md` |

**대상 폴더 결정 근거**:
- 막내6 부대 제안에서 `monkos-ops/03_개발/tasks/` 제안
- 그러나 막내1이 governance 이행(826060d)에서 `governance/constitution/petitions/`를 신설하고 실제 이동 완료
- PETITION은 법률 개정 청구서 → **governance 소관이 자연스러움** (ops는 운영, governance는 법)
- **결론**: `governance/constitution/petitions/`가 정위치 (현행 유지)

**YAML 필수 필드**:

| 필드 | 타입 | 비고 |
|------|------|------|
| `type` | `petition` | 고정 |
| `id` | string | 파일명과 동일 |
| `from` | string | 청구자 |
| `to` | string | 수신 경로 (예: `쌍아 → 작가님`) |
| `date` | string | KST 타임스탬프 |
| `status` | enum | `pending` / `under_review` / `approved` / `rejected` |
| `category` | string | `법률 개정` / `헌법 개정` |

### A-2. 패턴 #11 신설: TEMPLATE

**현실**: `TASK_TEMPLATE.md`가 docs/monkos/ 루트에 잔존. 접두사가 `TASK_`이지만 인스턴스가 아닌 서식.

**문제**: 현행 3조는 "인스턴스 문서"만 분류. 서식/템플릿의 위치를 규정하지 않음.

**청구안**:

| # | 패턴 | 대상 폴더 | 예시 |
|---|------|----------|------|
| 11 | `TEMPLATE_{type}_{name}.md` | `governance/templates/` 또는 해당 폴더 루트 | `TEMPLATE_TASK_standard.md` |

**대안**: 패턴 신설 대신 3조 하단에 "서식 예외" 규칙 추가

> 서식(TEMPLATE) 파일은 패턴 #1~#10의 인스턴스가 아니며, `TEMPLATE_` 접두사로 구분한다. 해당 유형의 대상 폴더 루트에 배치한다.

**소견**: 템플릿은 독립 패턴(#11)보다 **예외 규칙**이 적절. 현재 TASK_TEMPLATE 1건뿐이고, 과잉 패턴화는 복잡도만 증가시킴.

### A-3. 접두사 미보유 기존 파일 처리 규칙

**현실**: docs/monkos/ 잔존 6건 중 4건이 접두사 미보유 (`20260129_MONKOS_APP_MISSION.md`, `TELEGRAM_DEPLOY_GUIDE.md`, `work_queue.md`, `YONGA.md`)

**청구안**: 3조 하단에 "기존 파일 정비 규칙" 추가

> **기존 파일 정비**:
> - 표준 접두사 부여 가능한 파일: 리네임 후 해당 폴더로 이동 (예: `PHASE1_docs_classification.md` → `REPORT_20260217_docs_classification_phase1.md`)
> - 성격이 docs/infrastructure/ 참고문헌인 파일: infrastructure/로 이관 (예: `TELEGRAM_DEPLOY_GUIDE.md`)
> - 성격이 governance/ 규범 문서인 파일: governance/로 이관 (예: `YONGA.md`)
> - 성격이 monkos-ops/ 운영 문서인 파일: ops/로 이관 (예: `work_queue.md`)
> - 정비 시 `git mv` 사용 (히스토리 보존). 세션 로그에 `[정리]` 태그 기록.
