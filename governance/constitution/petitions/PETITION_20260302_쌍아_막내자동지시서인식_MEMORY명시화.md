# 막내 자동 지시서 인식 패턴 — MEMORY 명시화 여부

> **[2026-03-02 11:47 KST] iMac/쌍아 → 작가님 논의 요청**

---

## 1. 현상

막내가 CLI에서 투입될 때 다음 행동을 **자율적으로** 수행하는 패턴이 관찰됨:

```
① git pull (원격 변경 동기화)
② monkos-ops/ops/orders/ 디렉토리 스캔
③ 파일명에서 자기 이름(막내N) 매칭
④ 해당 지시서를 Read → 즉시 실행
```

### 관찰 사례 (2026-03-02)
- 작가님이 "막내1" 한마디로 CLI에서 투입
- 막내1이 자동으로 git pull → `ORDER_20260302_iMac쌍아_막내1_P0_클라이언트_스키마설계.md` 인식 → 실행
- 복붙(지시서 내용 전달) 없이 자동 수행

---

## 2. 근거 분석

이 행동은 **명시적 규정이 아닌 추론**에서 발생:

| 근거 요소 | 출처 | 명시 여부 |
|-----------|------|----------|
| 지시서 파일명에 `막내N` 포함 | MEMORY — 지시서 운용 원칙 | 파일 네이밍만 명시, 자동 인식은 미명시 |
| 막내는 자율 코딩 | 헌법 5조 — 에이전트 역할 체계 | "자율 실행"이지 "자율 탐색"은 미명시 |
| git pull로 동기화 | MEMORY — 세션 시작 프로세스 | 쌍아 세션 프로세스, 막내 적용은 미명시 |

**결론**: 헌법·법률·MEMORY 어디에도 "막내가 orders/를 자동 스캔하여 자기 지시서를 찾아 실행한다"는 규정은 없다. Opus 4.6의 추론 능력으로 컨텍스트에서 행동을 유추한 것.

## 3. 장단점

### 장점
- 작가님 작업 부담 감소 (복붙 불필요)
- 투입 속도 향상 (한마디로 즉시 가동)
- 지시서 네이밍 컨벤션이 사실상 라우팅 프로토콜로 기능

### 위험 요소 (작가님 지적)
- **오매칭**: 파일명 패턴이 비슷한 구 지시서를 잘못 인식할 가능성
- **중복 실행**: 이미 완료된 지시서를 재실행할 가능성
- **의도 이탈**: 작가님이 다른 지시를 주려 했으나 막내가 먼저 자동 실행
- **규정 미비 상태의 자율 행동**: 명시 규정 없이 추론 기반 동작 = 재현성 불확실

## 4. 검토 방향

### 옵션 A: MEMORY에 명시 + 안전장치 규정
```
막내 투입 시:
1. git pull
2. orders/ 스캔 → 자기 이름 + 오늘 날짜 매칭
3. 매칭 건이 1건이면 자동 실행
4. 매칭 건이 2건 이상이면 목록 보고 → 작가님 선택 대기
5. 매칭 건이 0건이면 "대기 지시서 없음" 보고
```

### 옵션 B: 명시하되 확인 절차 추가
```
막내 투입 시:
1. git pull
2. orders/ 스캔 → 매칭 지시서 제시
3. "이 지시서를 실행합니까?" → 작가님 승인 후 실행
```

### 옵션 C: 현행 유지 (미명시)
- 추론 기반 자율 행동을 허용하되 공식화하지 않음
- 문제 발생 시 사후 보정
