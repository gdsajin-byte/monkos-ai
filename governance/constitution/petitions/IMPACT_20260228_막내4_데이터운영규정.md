## 실무 적합성 의견

### 1. L2 권한 (꾸) — SSH 접근 CLI 실행 현실성

- 꾸는 `sshm2` → 맥미니 M2에 접근 가능.
- 설계서에 "M2 호환: ✅ (Node.js 설치 되어있음)" 명시.
- **현실적 과제**: M2에 `@google-cloud/firestore` 패키지 설치, `gcloud auth application-default login` 완료, monk_project clone이 전제 조건. 이 초기 설정이 완료되면 CLI 실행은 문제없음.
- **결론**: 현실적으로 가능하나, 초기 환경 구축 절차(운영 가이드) 별도 작성 필요.

### 2. L3 권한 (한송이) — 텔레그램 봇 명령어 4종 충분성

- `/회원현황`, `/결제현황`, `/통계`: L3 접근 가능 (3종).
- `/회원목록`: L3 접근 불가 (작가님 chatId만 허용) → 실질 사용 가능 3종.
- **판정**: SNS 운영/마케팅 업무에 통계·요약 3종이면 충분. 개별 회원 정보가 필요한 상황은 작가님에게 요청. PERSONNEL_REGISTRY.md의 한송이 역할("SNS/마케팅, 콘텐츠 기획")에 부합.

### 3. 보고서 .gitignore — GDrive 외 백업 부재 위험

- Git 미추적 시 GDrive가 유일한 외부 백업.
- **완화 요인**: CSV/JSON 데이터는 Firestore에서 언제든 재생성 가능. 원천 데이터가 보존되므로 스냅샷 손실의 실질 리스크는 낮음.
- **잔여 리스크**: GDrive 업로드가 수동이라 누락 가능성 있음. 향후 자동화(`--gdrive` 옵션, 설계서 10-3절) 구현 시 해소.
- **결론**: .gitignore 등록은 합리적. 반복 생성 데이터를 Git에 넣으면 이력이 불필요하게 누적. 중요 스냅샷은 GDrive 수동 백업으로 커버.

### 4. user-reset 삭제 범위 — CS 운영 부합성

- 삭제 대상: users, telegram_links, telegramGateCodes → 계정 정보만 삭제.
- 보존 대상: chat_conversations, cs_conversations → CS 이력 유지.
- **판정**: CS 운영과 부합. 이전 CS 대화 이력이 남으므로 서비스 품질 검증·감사 가능.

### 5. ch4 3조 적용 제외 — 자동 생성 데이터 네이밍 면제 합당성

- 자동 생성 데이터(CSV/JSON)는 사람이 네이밍하지 않으므로 ch4 3조(13종 패턴) 적용이 부적합.
- 설계서의 `{명령}_{YYYYMMDD_HHMMSS}.csv` 패턴은 자체적으로 명확하고 검색 가능.
- **판정**: 면제 합당. 단, ch4 3조 적용 제외 섹션에 명시적 추가 필요 (상기 B절 참조).
