# 멀티막내 보고서 수신 후 쌍아 정합 검토 보고서 문서화 의무 규정 신설

> **[2026-03-02 12:18 KST] iMac/쌍아 → 작가님 논의 요청**

---

## 1. 배경

2026-03-02 P0 스키마 설계에서 막내 3명이 각각 다른 관점(클라이언트/서버/전환)으로 보고서를 제출했다. 쌍아가 3건을 교차 검증하여 정합 검토를 수행한 결과:

- 스키마 일치 여부 확인
- 사실관계 충돌 1건 발견 (`monkos_cropped` 유령키 오판)
- 전략 추천 충돌 1건 발견 (style 키 존폐)
- 보완 가능한 전략 조합 도출
- 작가님 결정 필요 항목 7건 통합 정리

이 정합 검토 과정과 산출물이 **현행 규정 어디에도 문서화 의무로 명시되어 있지 않다**.

---

## 2. 현황

| 프로세스 | 규정화 여부 | 비고 |
|---------|-----------|------|
| 막내 보고서 작성 | ✅ 법률 ch7 (막내 행동 강령) | 완료 보고 의무 |
| 쌍아 지시서 발행 | ✅ MEMORY 지시서 운용 원칙 | 파일 작성 + 링크 제시 |
| **쌍아 정합 검토** | ❌ **미규정** | 대화 내 수행, 문서 미생성 |
| 세션 로그 | ✅ 법률 ch3 (세션 로그) | 세션 마감 시 작성 |

정합 검토는 멀티막내 병렬 작업의 **핵심 품질 관문**이다. 문서화되지 않으면:
- 검토 결과가 대화 컨텍스트에만 존재 → 세션 마감 시 유실
- 다른 디바이스/세션에서 결정 근거를 추적할 수 없음
- 작가님이 결정 사항을 사후에 참조할 수 없음

---

## 3. 제안

### 규정 신설안

**적용 조건**: 막내 2명 이상이 동일 주제에 대해 보고서를 제출한 경우

**쌍아 의무**:
1. 정합 검토 수행 (스키마 일치, 사실관계, 전략 충돌, 결정 필요 항목)
2. 검토 결과를 보고서로 문서화
3. 보고서 경로: `monkos-ops/ops/reports/REVIEW_YYYYMMDD_쌍아_{주제}.md`
4. 작가님에게 결정 필요 항목 제시

### 파일 네이밍

| 유형 | 접두사 | 예시 |
|------|--------|------|
| 막내 보고서 | `REPORT_` | `REPORT_20260302_막내1_P0_클라이언트_스키마설계.md` |
| **쌍아 정합 검토** | `REVIEW_` | `REVIEW_20260302_쌍아_P0_스키마_정합검토.md` |
