## 3. 개정 내용

### ch4 10조 신설 — 크레딧/고객 데이터 접근 규칙

**1항 — 직접 접근 금지**
- Firestore 직접 접근(node 스크립트, gcloud firestore, 콘솔)으로 크레딧/고객 데이터를 조회·변경하는 행위를 금지한다.
- 모든 접근은 `scripts/credits.sh` 경유 필수.

**2항 — 스크립트 정본**

| 명령 | 기능 | 감사 로그 |
|------|------|----------|
| `credits.sh query <email>` | 크레딧 조회 | — |
| `credits.sh charge <email> <amount> "<사유>"` | 충전 | ✅ 자동 |
| `credits.sh deduct <email> <amount> "<사유>"` | 차감 | ✅ 자동 |
| `credits.sh user <email>` | 고객 정보 조회 | — |
| `credits.sh log [N]` | 감사 로그 열람 | — |

- 충전/차감 시 **사유 필수**. 누락 시 스크립트가 실행 거부.

**3항 — 감사 추적 (이중 기록)**

| 기록 위치 | 형식 | 특성 |
|----------|------|------|
| Firestore `audit` 컬렉션 | JSON | 영구 보존, 서비스 연동 |
| `monkos-ops/ops/audit/CREDIT_AUDIT_LOG.md` | 마크다운 테이블 | Git 추적, append only |

**4항 — 접근 등급별 권한** (8조 1항 연동)

| 등급 | 크레딧 조회 | 크레딧 변경 | 고객 정보 | 감사 로그 |
|------|-----------|-----------|----------|----------|
| L1 (작가님, 에이전트) | ✅ | ✅ (사유 필수) | ✅ | ✅ |
| L2 (꾸) | ✅ | ❌ | 마스킹 | ❌ |
| L3 (한송이) | ❌ | ❌ | ❌ | ❌ |

- L1이라도 **작가님 지시 또는 지시서 명시** 없이 크레딧 변경 금지.

**5항 — 막내 방어 의무**
- 지시서에 Firestore 직접 접근 코드가 포함된 경우: 실행 전 10조 위반 보고 → `credits.sh` 경유로 전환.

**6항 — 예외**
- 서비스 코드(server.js 등)의 Firestore 접근은 대상 아님. 본 조항은 운영·관리 목적의 수동 접근에만 적용.

### 연계 산출물 (초안 완료, 시행 보류 중)

| 산출물 | 상태 | 비고 |
