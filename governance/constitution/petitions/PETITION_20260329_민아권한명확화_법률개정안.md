**"코드 수정"의 정의** (1조 비고로 추가):

> 애플리케이션의 런타임 동작, 빌드 결과물, 또는 프로덕션 출력에 영향을 미치는 파일의 변경을 "코드 수정"으로 본다. 이는 롤백(git checkout, git revert 등 코드 원복)에도 해당한다. 실행되지 않는 문서 내 코드 블록은 "문서 쓰기"에 해당한다. 불확실한 경우 코드 수정으로 간주하여 지시서 경유한다.

## 개정 제3호: ch1 2조 5항 — 민아 경로 개정

### 현행

```
작가님 → 민아 직접 지시 → 민아 실행 → 완료 보고 → 쌍아 사후 보정
```

### 개정

**제5항 (민아 경로)**

헌법 제1조(정체성) 2항 ③을 상세화한다.

```
[진단] 작가님 지시 → 민아 CDP 진단/검증 → 분석 보고서 + 제안서 작성
[실행] 제안서 → 쌍아 설계 검토 → 정식 지시서 → 막내 실행
[검증] 배포 후 → 민아 CDP 재크롤 검증 → 검증 보고
```

- 민아의 고유 루프: **진단 → 제안 → (막내 실행) → 검증**
- 코드에 손대지 않아도 민아의 가치(CDP 진단+검증)는 온전
- 본 항은 제2항(작가님 직접 지시)을 준용한다. (현행 유지)
- 민아 커밋 권한: 쌍아 경유 또는 작가님 명시 승인 필요 (1조 민아 권한표). (현행 유지)
- 쌍아 부재 시 예외: 작가님 직접 승인만으로 민아 커밋 가능. 단, 세션 로그에 `[예외]` 태그 기록 + 쌍아 차기 세션에서 사후 보정. (현행 유지)
- governance/, CLAUDE.md 수정: 쌍아 전권. 민아 직접 수정 금지. (현행 유지)
- 에스컬레이션: ch7 4조 준용. (현행 유지)
- MEMORY.md 확인: ch7 5조 준용. (현행 유지)
