| 조건 | 역할 |
|------|------|
| 시스템 프롬프트에 `VSCode native extension` 포함 | 쌍아 |

→ Desktop App(민아/코웍이)은 "그 외"에 해당하여 **막내로 판별**되거나, VSCode가 아닌데도 CLI도 아니므로 판별 불능 → 임의 추정 발생.

## 2. 환경 조사 결과

Desktop App 환경에서 확인된 고유 식별자:

| 환경변수 | 값 | 비고 |
|---------|-----|------|
| `CLAUDE_CODE_ENTRYPOINT` | `claude-desktop` | CLI는 다른 값 또는 미설정 |
| `__CFBundleIdentifier` | `com.anthropic.claudefordesktop` | macOS 앱 번들 ID |

이 두 값은 CLI 터미널(`iTerm`, `tmux`)이나 VSCode 확장에서는 나타나지 않으므로 **판별 키로 사용 가능**.

## 3. 개정 제안

### 5조 1단계 — 역할 판별 (현행 → 개정안)

**현행 (2분류):**

| 조건 | 역할 |
|------|------|
| 시스템 프롬프트에 `VSCode native extension` 포함 | 쌍아 |
| 그 외 (CLI 터미널) | 막내 |

**개정안 (3분류):**

| 우선순위 | 조건 | 역할 |
|---------|------|------|
| 1 | 시스템 프롬프트에 `VSCode native extension` 포함 | **쌍아** |
| 2 | `CLAUDE_CODE_ENTRYPOINT=claude-desktop` | **민아** (기본) / 코웍이 (작가님 지정 시) |
| 3 | 그 외 (CLI 터미널) | **막내** |

### 민아 / 코웍이 구분

동일 Desktop App 환경에서 민아와 코웍이를 구분하는 방안:

- **안 A**: 기본값을 민아로 두고, 코웍이는 작가님이 세션 시작 시 명시 지정
- **안 B**: 워크트리 이름 또는 프로젝트 경로 기반 자동 판별 (추후 규칙 확립 시)
- **안 C**: 환경변수 추가 설정 (`.claude/settings.json` 등에서 역할 지정)

→ 현 시점에서는 **안 A**가 가장 실용적. 코웍이 운용이 정례화되면 안 B/C로 고도화.
