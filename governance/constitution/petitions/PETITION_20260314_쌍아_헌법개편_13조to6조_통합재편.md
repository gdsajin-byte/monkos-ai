## 3. 개정안: 6조 체계

### 신 제1조: 세션 및 문서 관리 체계

> OS 근간. 모든 에이전트가 반드시 준수해야 하는 기록 체계.

**1항 — 타임스탬프 절대 준수** (현행 1조 계승)
- 매 턴 시스템 명령(`date`)으로 KST 취득. 추정/기억 기반 절대 금지.
- 형식: `**[YYYY-MM-DD HH:MM KST]**`

**2항 — 분산 기록 의무** (신설 — 핵심)
- 모든 에이전트는 자기 세션 로그를 자체 기록한다.
- 하루 첫 세션에서 세션 로그 파일을 생성하고, 매 턴 타임스탬프 기반으로 어펜드한다.
- 기록된 세션 로그의 수정·삭제는 절대 금지한다 (append only).

**3항 — 일간 폴더 체계** (신설)
- 세션 로그는 일간 폴더에 에이전트별 파일로 분리 관리한다.
- 세션 마감 시 커밋+푸시로 확정한다. 푸시 미완료 = 세션 미마감.

**4항 — 완료 보고** (현행 2조 흡수)
- 모든 에이전트는 `✅❌💡⏳📁🔀` 형식으로 완료 보고한다.
- 보고가 세션의 마지막 출력이다 (보고 후 잡담 금지).

**5항 — 문서 규격** (현행 13조 흡수)
- 모든 공식 문서는 법률이 정한 네이밍 규칙과 YAML frontmatter를 준수한다.
- 긴급 장애 대응 시 최소 필드(type, date)로 허용, 24시간 내 보정.

**위임**: 폴더 구조·파일명 패턴·인덱싱·라우팅 → 법률 ch3. 어펜드 포맷·태그 체계 → `sessions/README.md`.

1. 구9조(I2I) 원칙 잔류 → 신5조 확장
2. 구7조(응답 규칙) 강등 철회 → 신6조로 독립 유지 (에러 묵과 금지의 헌법적 무게)
3. 대응 프로토콜 + 문서 위계 → 신7조 편입
