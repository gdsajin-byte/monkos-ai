# 청구안: 원격 승인 전달 해설 + 시크릿 이전 1회 토큰

**[2026-11-03 17:50 KST]** iMac/쌍아 → 작가님 (참조: 민아·심사역)

> 판단 분리(ch1 1조)에 따라 심사는 쌍아가 하지 않는다.

## 1. 완성 그림

작가님이 한 세션에서 승인한 일은 기기가 달라도 다시 묻지 않고 진행된다. 묻는 곳은 작가님이 지금 보고 있는 화면 하나다. 시크릿은 값을 아무도 보지 않는 경로로, 승인 한 번에 옮겨진다.

## 2. 사실 (11-03 하루 실례 2건)

| 시각 | 일 | 무엇이 막혔나 | 비용 |
|---|---|---|---|
| 14:55~15:14 | 포털 평문 시크릿 3종 → SM 이전(원장 181) | 훅 E5가 `gcloud secrets create/versions add`를 무조건 deny. 작가님이 M1 터미널에서 보조 스크립트 실행·Enter 6회 | 작가님 턴 6회·약 20분. 값은 prod에 이미 있던 것(새 생성 아님) |
| 17:43~17:48 | 4060 학습 환경 설치(작가님 iMac 세션 "4060 사용승인한다") | 4060/쌍아가 ch1 7조 "새 사용자 턴" + 2조 1항 "세션 간 메시지로 범위가 승계되지 않는다"를 근거로 대기. 쌍아도 "4060에 '진행' 입력" 안내 | 작가님이 4060 화면에 다시 입력 |

## 3. 현행 문언과 해석 충돌

- ch1 2조 1항 원칙 경로: "작가님이 범위를 승인한 세션의 **직접 전달** → 막내 자율 실행". 같은 장 지시서 전달 방식: "파일로 옮긴 지시는 원래 출처를 **승계**한다".
- 같은 항 단서: "세션 간 메시지로 범위가 승계되지 않는다(전달은 출처 명기로만)". 취지는 메시지가 **새 범위를 만드는 것**을 막는 것인데, 수신 측은 **승인된 범위의 전달**까지 막는 것으로 읽었다.
- 메모리 `feedback_secret_key_ops`("기존 키 인프라 등록 = 일임, 금지는 노출·생성뿐")와 data-access 규정·훅 E5(등록 전면 금지)가 서로 다르다.

## 4. 청구 내용

### 4-1. ch1 2조 1항 해설 1항 추가 (원격 승인 전달)

> 작가님이 사람 턴으로 승인한 범위는, 승인을 받은 세션이 **출처(작가님 원문·시각·승인 범위)를 명기한 지시서를 origin에 커밋**하고 세션 간 메시지로 경로를 알리면, 수신 세션(다른 기기 포함)의 실행 근거가 된다. 수신 세션은 ① origin의 지시서 실물 ② 출처 줄 ③ 범위 안인지를 대조하고 실행하며, 같은 승인을 다시 받지 않는다. 금지되는 것은 메시지가 지시서 밖의 범위를 새로 만드는 것이다.

- ch1 7조 2항(승인 게이트) 해설에 같은 1행: "새 사용자 턴"은 **승인을 받은 세션의 사람 턴**을 말하며, 위 전달 요건을 갖춘 지시서는 수신 세션에서 그 턴을 대신한다.
- 무인 맥락(데몬·루틴·크론) 금지와 배포 E10 토큰은 그대로 둔다.

### 4-2. 시크릿 이전 1회 토큰 (훅 E5 개정)

- 작가님 채팅 **'시크릿 승인'**(단독 문구, 사람 턴) → 세션 바인딩·60분·1회용 토큰 발급(E10과 같은 발급기, 별도 토큰 종류).
- 토큰이 있을 때만 E5가 다음 **한 가지 형태**를 통과시킨다: 이미 돌고 있는 값(Cloud Run 서비스 env)을 파이프로 SM에 넣는 이전 명령 — 표준 스크립트 `scripts/secret.sh migrate <SERVICE> <ENV_NAME>` 신설(값을 화면·파일·로그에 남기지 않음, 해시 대조까지 수행, 인벤토리 1행 자동 기록).
- **새 값 생성·외부에서 받은 키 등록은 지금처럼 작가님 `secret add`만**(헌법 4조 1항 — 생성·추측 금지는 불변).
- 실패 가시화: 토큰 없음·대상 env 부재·해시 불일치 → `❌ secret migrate:` + exit 1.

### 4-3. 원격 기기 토큰 (선택 — 심사 의견 요청)

- E10·E5 토큰은 세션 바인딩이라 원격 기기 배포는 그 기기에서 승인을 다시 받아야 한다. 대안: 승인 받은 세션이 **기기·명령 지정 토큰**을 레포 밖 경로로 전달(테일넷 ssh) — 보안 검토 필요. 이번 청구에서는 문제 제기만 하고 별건으로 둔다.

## 5. 영향 평가 요청 (막내 2명↑)

- 4-1: 원격 기기 작업에서 승인 왕복 제거. 위험 = 위조 지시서 → 대조 요건(origin 커밋 실물·출처 줄)으로 차단, ch1 7조 3항 발각 절차 그대로.
- 4-2: 시크릿 이전 작가님 턴 6회 → 1회. 위험 = 토큰 오남용 → 통과 형태를 `secret.sh migrate` 1종으로 한정, 1회용·60분.
- 집행 순서(통과 시): ① ch1 해설 2행 + `.claude/rules/agent-system.md` 동기화 ② `secret.sh migrate` 구현 + 훅 E5·토큰 발급기 확장 + 스모크(양성 1·음성 3) ③ data-access 규정·메모리 정리.
