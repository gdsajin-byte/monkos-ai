## 1. 개정 배경

작가님(총괄)이 쌍아 작업 중 막내에게 직접 지시하여 코드 수정을 실행시킨 상황이 발생했다. 현행 법체계는 `쌍아 → 지시서 → 작가님 토스 → 막내` 단일 경로만 규정하고 있어, 총괄의 직접 지시권에 대한 법적 공백이 존재한다.

---

## 2. 개정 내용

### 2-1. 헌법 제5조 개정

**현행:**
```
- 핵심: 쌍아(설계) → 작가님 토스 → 막내 자율 실행 → 완료 보고
```

**개정안:**
```
- 핵심 흐름:
  ① [원칙] 쌍아(설계+지시서) → 작가님 토스 → 막내 자율 실행 → 완료 보고
  ② [보충] 작가님 → 막내 직접 지시 → 막내 실행 → 완료 보고 → 쌍아 사후 추인
- ②는 ①의 대체재가 아닌 보충적 수단이다.
  설계가 필요한 복합 작업은 ① 경유가 원칙이다.
```

### 2-2. 법률 ch1 2조 개정 (핵심 흐름)

**현행 단일 흐름에 제2항 추가:**

```markdown
### 2조: 핵심 흐름

**제1항 (원칙 경로)**
쌍아(설계/지시서) → 작가님이 막내에게 토스 → 막내 자율 실행 → 완료 보고

**제2항 (작가님 직접 지시 경로)**
작가님 → 막내 직접 지시 → 막내 실행 → 완료 보고 → 쌍아 사후 추인

- 본 항은 제1항의 보충적 수단이다.
- 발동 조건:
  a) 쌍아가 다른 작업에 종사 중이거나 세션이 없을 때
  b) 긴급 장애 대응(INCIDENT) 시
  c) 작가님이 명시적으로 직접 지시를 선언한 경우
- 작가님이 직접 지시 시, 헌법 제7조(계획→승인→실행)의 승인은 작가님 자신에게 내재된 것으로 본다.
```

### 2-3. 법률 ch7 1조 개정 (막내 작업 흐름)

**현행 흐름 앞에 진입 경로 분기 추가:**

```markdown
### 1조: 작업 흐름

**진입 경로:**
| 경로 | 시작점 | 기록 |
|------|--------|------|
| 지시서 경유 (원칙) | 지시서 수령 | 지시서 파일 참조 |
| 작가님 직접 지시 (보충) | 작가님 구두/채팅 지시 수령 | 세션 로그에 `[직접지시]` 태그 + 지시 내용 기록 |

**직접 지시 수령 시 막내 의무:**
1. 세션 로그에 `[직접지시]` 태그 기록 + 작가님 지시 내용 인용
2. `git pull origin develop` 실행 (충돌 방지)
3. 사전 적합성 검토 (헌법·법률 위반 여부)
4. 실행 → 커밋+push → 완료 보고

**마무리 절차**: 기존과 동일 (커밋+push+보고). 엔드라인은 작가님 지시에 따른다.
```

### 2-4. 법률 ch3 2조 개정 (세션 로그 형식)

**본문 형식에 태그 규격 추가:**

```markdown
**직접지시/추인 태그 (해당 시):**
- `### [HH:MM] [직접지시] 작업 주제` — 작가님 직접 지시로 수행한 작업
- `### [HH:MM] [추인] 작업 주제` — 쌍아가 직접지시 작업을 사후 확인
- 직접지시 블록에는 작가님 지시 원문 인용 필수
```

---

## 3. 사후 추인 제도

| 항목 | 규정 |
|------|------|
| **성격** | 정보 동기화 (informational). 거부권 아님 — 작가님 승인은 이미 유효 |
| **절차** | 막내 완료 보고 → 쌍아가 커밋+세션 로그 확인 → `[추인]` 기록 |
| **시점** | 같은 세션이면 즉시, 다른 세션이면 다음 세션 시작 시 |
| **문제 발견 시** | 경미: 다음 지시서에 보정 포함 / 중대: revert 지시서 발행 → 작가님 승인 → 막내 실행 |
