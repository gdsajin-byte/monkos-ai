### D. 상위 통괄 메타 PF 위상 — 법률 ch4 9조 + 헌법 3조 주석

**왜 개정 논점인가**
- PF_OPUS 자체가 첫 사례: 개별 PF(부품)를 도는 **바퀴**(메타 통괄). 기존 PF 정의는 "프로젝트의 기안→완성 생애주기 추적"(헌법 3조2항)이라 *단일 프로젝트* 전제 → 메타 PF(여러 PF를 통괄하는 상위)는 새 위상.

**개헌이냐 법률이냐 — 헌법 5조1항 위계표 기준 판정**
- 헌법 3조2항은 **"활성 PF의 히스토리를 갱신한다"는 의무(왜/원칙)**만 규정한다. PF가 *무엇인가*의 정의·생애주기·관리 규칙은 **법률 ch4 9조** 소관(AMENDMENT_20260326이 ch4 9조로 정착시킴).
- 따라서 "메타 PF라는 새 위상 추가"는 **PF 정의의 확장 = 법률 ch4 9조 갱신**으로 충분. 헌법 3조2항의 "갱신 의무" 자체는 메타 PF에도 그대로 적용되므로 헌법 텍스트 변경 불요.
- **개헌 불요 논거**: 헌법은 "PF를 갱신하라"는 불변 원칙만 담고, "PF에 메타 종류가 있다"는 분류는 정의(무엇)의 영역 → 법률. 20260326이 PF 전체를 ch4 9조에 둔 것과 동일 논리.

**위계 판정**: **법률 ch4 9조 1항(생애주기)에 메타 PF 위상 추가** + (선택) 헌법 3조2항에 1줄 주석. 개헌 불요하나, 헌법 3조2항 "활성 PF" 표현이 메타 PF를 포괄함을 주석으로 명확화하면 해석 분쟁 예방.

> 입법 의견: D를 개헌으로 끌면 메타 PF 하나 추가에 만장일치 절차 → 과잉. 단 사법이 "메타 PF가 하위 PF와 충돌"(PF_OPUS §10 리스크) 우려를 제기할 것이므로, ch4 9조에 "메타 PF는 흐름·KPI만, 실행 세부는 하위 PF" 경계 조항을 동봉한다.

### E. 멀티에이전트 파이프라인 운용 — 특별법 신설 (헌법 논점)

**왜 이것만 개헌/특별법 논점인가**
- ch1 2조3항이 **명시적으로 예고**한다: *"멀티에이전틱 직접 운용(쌍아가 막내를 자동 투입하는 체계)은 향후 특별법으로 설계한다."* → 입법자가 이미 "이 사안은 특별법 영역"이라 선언해 둔 상태.
- 동 조항은 *"쌍아가 Agent 도구로 실행을 대행하는 것은 원칙적으로 금지('북치고 장구치기')"*를 못박는다. MEMORY.md도 "쌍아가 Task tool로 막내를 직접 spawn 금지 = 헌법 5조 위반"으로 기록.

**핵심 구분 — 무엇이 금지이고 무엇이 새 범주인가**
- **금지(현행 유지)**: 쌍아(커맨더)가 *범용 에이전트 막내*(각자 Opus 4.6, 동등 코딩력)를 자동 투입 → 밸런스 붕괴. 막내 가동은 작가님이 CLI에서 투입하는 원칙 불변.
- **새 범주(특별법 정의 대상)**: 에이전트가 *공정 워커*(단일 목적·종속적 서브 유닛, 막내와 지위 다름)를 부리는 파이프라인. ch1 2조3항 단서 *"막내는 지시 범위 내에서 서브에이전트를 자유롭게 활용할 수 있다"*가 이미 인정한 영역의 체계화.
- B(민아 오케스트레이터)와 연동: 오케스트레이터가 "공정 워커"를 조율하는 것은 E의 특별법 범위, "막내를 부리는 것"은 금지 → 분계선이 E 특별법의 핵심.

**개정하지 않으면 지속되는 병목**
- 콘텐츠 공장(PF_OPUS)의 자동 생산 라인은 본질적으로 "에이전트가 공정 워커를 부리는" 구조 필요(블로그 크롤링→가공→발행 자동 루프). E 미정의 시 자동화율 KPI(Phase1 30%, Phase3 60%) 달성 불가 → 플라이휠이 다시 "손 많이 감"(PF_OPUS §10 리스크1)에 멈칫.

**위계 판정**: **특별법 신설 (헌법 5조 절차)**.
