# [2026-05-01 15:37 KST] iMac/쌍아 → 막내3

## 미션

크롭앱(PWA 기반, 서버 제로)을 Google Play + Apple App Store에 등재하기 위한 배포 파이프라인을 리서치하고 최적 경로를 제안하라.

## 배경

- 계정: Google Play ✅ Active / Apple Developer ✅ 활성화 완료
- 앱 성격: 완전 무료, 인앱결제 없음, 광고 없음, 서버 전송 없음
- 현재: PWA 기반 (manifest.json + SW), TWA 매니페스트 존재 (`monkos_AI/crop-app/twa-manifest.json`)
- 패키지명: `ai.monkos.crop`
- 앱 사이즈: ~60~65MB (FaceMesh 16MB + 배경 제거 모델 40MB + UI/데이터)
- 새 코드베이스: `apps/crop-app/` (별도 신규, 기존 monkos_AI 보존)

## 작업

### T1. Android 래핑 비교

| 옵션 | 핵심 확인 |
|------|----------|
| **TWA (Trusted Web Activity)** | Bubblewrap CLI 빌드 흐름, assetlinks.json, 호스팅 필요성, 오프라인 동작 |
| **Capacitor** | WebView 래핑, 네이티브 API 접근(카메라/파일), 빌드 사이즈 |
| **PWABuilder** | MS 도구, TWA 자동 생성, 제약사항 |

각 옵션에 대해:
- 빌드 절차 (step-by-step)
- 장단점
- 오프라인 동작 보장 여부
- 카메라 접근 (사진 촬영 기능 향후 추가 시)
- 앱 사이즈 영향
- **추천 + 근거**

### T2. iOS 래핑 비교

| 옵션 | 핵심 확인 |
|------|----------|
| **Capacitor (iOS)** | WKWebView, Xcode 빌드, 서명 |
| **PWABuilder (iOS)** | 가능 여부, 제약 |
| **React Native WebView** | 과잉 여부 판단 |

특히 확인:
- Apple의 WebView 앱 정책 (4.2 Minimum Functionality — 웹뷰만이면 리젝 가능성)
- 우리 앱이 리젝 회피 가능한 근거 (MediaPipe WASM = 네이티브급 연산, 오프라인 완결)
- iOS에서 WASM/ONNX 성능 (Safari WebKit 제약)
- **추천 + 근거**

### T3. 스토어 심사 가이드라인 분석

#### Google Play
- 사진/카메라 권한 정책
- 무료앱 특이사항
- 데이터 세이프티 섹션 작성 (서버 전송 없음 = "데이터 수집 없음")
- 콘텐츠 등급 (증명사진 = 전체이용가)

#### Apple App Store
- **4.2 Minimum Functionality**: WebView 앱 리젝 기준과 우리 앱의 차별화 근거
- 사진 라이브러리 접근 (NSPhotoLibraryUsageDescription)
- 카메라 접근 (향후)
- App Privacy 라벨 (데이터 수집 없음)
- 심사 기간 예상 (첫 제출)

### T4. ASO (App Store Optimization) 키워드 전략

PF_CROP 기획서 키워드 기반 확장:

| 언어 | 기존 키워드 | 추가 리서치 |
|------|-----------|-----------|
| 한국어 | 증명사진 크롭, 여권사진 규격, 반명함 크롭 | 경쟁앱 키워드 분석 |
| 일본어 | 証明写真 サイズ, パスポート写真 規格 | 일본 스토어 상위앱 키워드 |
| 영어 | passport photo crop, ID photo size | 영어권 검색량 상위 키워드 |

각 언어별:
- 스토어 검색 상위 경쟁앱 5개 + 키워드
- 제목/부제 최적 조합 제안
- 설명문 초안 (한/일/영)
