# 지시서: 크레딧 차감 연동 시스템 전수 조사

## 배경

프로덕션 환경에서 **로그인 유지 상태로 다운로드를 반복해도 크레딧이 차감되지 않는** 현상이 확인되었다.
결제 연동 이전에 **크레딧 차감 자체가 작동하지 않으면** 유료 서비스 구조가 성립하지 않는다.

## 현상

- 작가님 테스트: 로그인 상태, 다운로드 반복 → 크레딧 잔액 변동 없음
- 결제 SDK와 무관한 근본적 크레딧 차감 로직 이슈

## 조사 범위

idphoto-kr (프론트 + 서버) + portal 서버 (크레딧 API 제공 시). 아래 체크리스트를 **코드 레벨에서** 전수 확인한다.

---

## 체크리스트

### 1. 크레딧 차감 엔드포인트 매핑

- `/api/credit/use` 가 실제로 존재하는지 (idphoto-kr 서버? portal 서버?)
- 라우트 핸들러 코드 전문 확인: 어떤 파라미터를 받고, Firestore에서 어떻게 차감하는지
- 차감 단위: 다운로드 1건당 몇 크레딧?

### 2. 프론트엔드 호출 지점

- 다운로드 버튼/함수에서 **실제로 `/api/credit/use`를 호출하는 코드가 있는지**
- 호출이 있다면: 어떤 조건에서 호출되는지 (로그인 체크, 크레딧 잔액 체크 등)
- 호출이 없다면: **크레딧 차감 없이 다운로드가 완료되는 구조**인지 확인
- 관련 함수명, 파일명, 라인 번호 명시

### 3. 다운로드 플로우 추적

사용자 여정의 각 단계에서 크레딧 관련 로직을 추적:

```
AI 생성 요청 → 생성 완료(결과 표시) → 클로즈업/미리보기 → 다운로드 버튼 클릭 → 이미지 저장
```

각 전환 지점에서:
- 어떤 API가 호출되는지
- 크레딧 체크/차감이 있는지
- 체크 실패 시 어떻게 처리하는지

### 4. 서버 사이드 크레딧 차감 로직

- Firestore 크레딧 필드 경로: `users/{userId}` 의 어떤 필드?
- 트랜잭션 사용 여부 (동시 요청 시 이중 차감 방지)
- 잔액 부족 시 응답: HTTP 코드 + body
- 차감 성공 시 응답: 갱신된 잔액 반환 여부

### 5. 크레딧 잔액 조회 흐름

- 프론트에서 크레딧 잔액을 어디서 읽는지 (localStorage? store? API 매번 조회?)
- 차감 후 잔액 UI 업데이트 경로
- 페이지 이동 시 잔액 동기화 방식

### 6. 무료 우회 경로 존재 여부

- 크레딧 체크 없이 다운로드 가능한 경로가 있는지
  - 직접 URL 접근 (`/api/download?id=...` 등)
  - 브라우저 이미지 저장 (캔버스/img 태그에서 직접 저장)
  - 결과 페이지에서 이미지가 이미 풀 해상도로 노출되는지
- 서버에서 이미지 제공 시 인증/크레딧 검증 없이 GCS URL 직접 반환하는지

### 7. 기존 크레딧 적립 vs 차감 정합성

- **적립**: 토스 결제 성공 → `/api/payments/toss/confirm` → Firestore 크레딧 +N
- **차감**: 다운로드 → (어떤 경로?) → Firestore 크레딧 -1
- 적립과 차감이 **같은 Firestore 필드**를 참조하는지 확인
- 적립은 portal 서버, 차감은 idphoto-kr 서버인 경우 → 크로스 서비스 정합성 이슈
