# [2026-02-26 21:15 KST] M1/쌍아 → 막내3

## 지시: 크레딧 게이트 v2 종합 전략 리서치

### 배경

크레딧 게이트 v2 백엔드(막내1)·프론트 모듈화(막내2)·Cr 모션(막내3)이 코드 구현 완료되었다.
본격 프로덕션 투입 전, 현재 설계가 실전에서 작동하는지 **여러 관점에서** 종합 점검한다.

작가님 원문: "e2e상 논리흐름이 적정한지, 마케팅 차원 UI/UX 최적점, 텔레그램 접점 고객경험 및 리스크"

---

### 작업 항목

#### 1. E2E 논리흐름 적정성 검토

**검토 대상**: 비로그인 첫 방문 → 게이트(로그인 30c + 텔레 가입 40c) → 다운로드 → 100c 미션 → 프리미엄/충전

**관점**:
- 퍼널 이탈 지점 식별: 각 단계에서 유저가 이탈할 확률이 높은 곳은?
- 유저 플로우에 불필요한 마찰(friction)이 있는가?
- 텔레그램 앱 전환 → 웹 복귀 과정에서 세션/상태 유실 리스크
- 모바일 vs 데스크탑 UX 차이 (딥링크 동작, 앱 미설치 시 분기)
- Phase 1(로그인) → Phase 2(텔레 가입) 순서가 최적인가? 역순이 나은 케이스가 있는가?
- 100c 미션의 2개 조건(이미지 전송 + 동의서)이 유저 관점에서 명확한가?

**코드 조사 대상**:
```
monkos_AI/portal/server.js           ← 백엔드 API (gate-code, mission-code, getChatMember)
monkos_AI/idphoto-kr/public/modules/gate.js      ← 게이트 모듈
monkos_AI/idphoto-kr/public/modules/mission.js   ← 미션 모듈
monkos_AI/idphoto-kr/public/modules/charge.js    ← 충전 모듈
monkos_AI/idphoto-kr/public/result.js            ← 메인 결과 페이지
monkos_AI/idphoto-kr/public/result.html          ← HTML 마운트 포인트
monkos_AI/idphoto-kr/public/shared.js            ← 공통 유틸
```

#### 2. 마케팅 차원 UI/UX 최적점 검토

**관점**:
- **배치 순서**: 프리미엄 → 미션 → 충전 순서가 전환율 관점에서 최적인가?
- **CTA 문구**: "텔레그램 가입하고 40c 받기" 등 문구가 유저 행동을 유도하기에 충분한가?
- **이벤트 카드 디자인**: Cr 모션(cr-coin.css)과 게이트 UI의 시각적 연결성
- **무료 제공량 2장의 심리**: 1장은 너무 적고 3장은 결제 전환 안 되는데, 2장은 적정한가?
- **"70c 차감"이 보이는 순간 유저 반응**: 크레딧을 받자마자 전부 쓴다는 사실이 유저에게 '속은 느낌'을 줄 수 있는가?
- **결과물 만족도 → 전환 연결**: 1장 다운로드 경험이 2장째(100c 미션) 참여 동기를 충분히 만드는 구조인가?

#### 3. 텔레그램 접점 고객경험 + 리스크

**관점**:
- **봇 첫 인상**: /start 명령 수신 시 봇 메시지가 유저에게 신뢰감을 주는가?
- **채널 가입 유도**: 봇 대화 → 채널 가입 → 웹 복귀 과정이 매끄러운가? (3단 전환)
- **100c 미션 이미지 전송**: 유저가 "캡쳐본을 보내라"는 지시를 정확히 이해하는가?
- **봇 응답 시나리오**: 유저가 엉뚱한 메시지를 보낼 때, 관련 없는 사진을 보낼 때 대응
- **개인정보 리스크**: 텔레그램에 결과물(증명사진) 전송 = 개인 얼굴 데이터가 텔레그램 서버 + 봇 보관. 유저 동의 범위가 명확한가?
- **텔레그램 미사용자 차단 리스크**: 텔레그램을 안 쓰는 한국 유저 비율이 높을 경우, 게이트에서 이탈 → 전환율 하락
- **봇 차단(block) 리스크**: 유저가 40c 받고 봇 차단 시 후속 100c 미션 불가 → 어떻게 안내?

#### 4. 업로드 시 얼굴 블러 허용 여부 검토

**맥락**: 100c 미션에서 유저가 결과물 캡쳐를 텔레그램으로 전송하는데, SNS 활용 동의와 별개로 **자신의 증명사진 원본이 그대로 노출**되는 것에 거부감이 있을 수 있다.

**검토 사항**:
- 유저가 결과물 전송 시 얼굴에 블러를 적용한 상태로 보내도 되는가?
- 블러 허용 시: SNS 활용 소재로서 가치가 떨어지는가? (before/after 비교 불가)
- 블러 미허용 시: 유저 이탈 리스크는 얼마나 큰가?
- 대안: 워터마크 유지 상태의 프리뷰를 자동 첨부하는 방식 (유저 선택 불필요)
- 법적 관점: 동의서 서명 시점과 이미지 전송 시점의 순서가 개인정보보호법상 적정한가?
