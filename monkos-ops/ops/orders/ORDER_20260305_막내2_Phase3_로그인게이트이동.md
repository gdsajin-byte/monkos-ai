# Phase 3: 로그인 게이트 이동

## 맥락

Phase 2(페이지뷰 디자인 + ChargeModule) 완료. Phase 3는 로그인 게이트를 **촬영실 진입 시점**으로 이동하고, 비회원 결제 경로를 소멸시킨다.

### 현행 구조
- `gate.js` GateModule:
  - `showLoginRequired(message)` — 로그인 필요 모달 (Google/Kakao/LINE)
  - `buyDirect()` — 비로그인 직결제 ₩9,900 (비회원 경로)
  - `initDirectPayment()` — 토스 리다이렉트 처리
  - `show()` — deprecated (Phase1/2 이미 제거됨)

### 목표 구조
- **촬영실 진입 = 로그인 필수** (소셜 원탭)
- 비회원 결제 경로 완전 소멸
- 로그인 후 촬영실로 자연스럽게 진입

---

## 작업 항목

### 1. 촬영실 진입 시 로그인 게이트

- `camera.html` 초기화 시, `store.user.id`가 없으면 **즉시 로그인 모달 표시**
- 로그인 완료 후 카메라 초기화 진행 (페이지 이동 없이 맥락 보존)
- 로그인 모달은 현행 `showLoginRequired()` 재사용
- 메시지: "촬영을 시작하려면 로그인이 필요합니다\n첫 로그인 시 10c를 드려요!"

### 2. 비회원 결제 경로 제거

- `buyDirect()` 함수 및 관련 코드 제거
- `initDirectPayment()` 토스 리다이렉트 처리 제거
- `_buyDirect()` 내부 함수 제거
- 비회원 직결제 버튼 UI가 남아있는 곳 전수 탐색 → 제거

### 3. gate.js 정리

- deprecated `show()` 제거
- `buyDirect()`, `initDirectPayment()` 제거
- 남는 것: `showLoginRequired()`, `closeLoginRequired()` + 소셜 로그인 로직
- GateModule export 정리

### 4. 다른 페이지 로그인 체크

현재 로그인 체크가 어디서 일어나는지 전수 파악:
- `camera.html` — Phase 3에서 게이트 설치
- `result.js` — 다운로드 시 로그인 체크가 있는지 확인
- `charge.html` — 결제 시 로그인 체크가 있는지 확인
- `index.html` — 랜딩은 비로그인 상태에서도 접근 가능해야 함 (로그인 강제 ❌)

### 5. 흐름 검증

| 시나리오 | 기대 동작 |
|----------|----------|
| 비로그인 → 랜딩 | 정상 접근 (로그인 불필요) |
| 비로그인 → "촬영 시작하기" → camera.html | 로그인 모달 표시 → 로그인 후 촬영 시작 |
| 로그인 상태 → camera.html | 바로 촬영 시작 |
| 비로그인 → charge.html (직접 접근) | 충전은 가능하되, 로그인 안내 또는 로그인 후 충전 |
| 로그인 → 촬영 → 결과 → 잔고 부족 → 모달 충전 | Phase 2에서 검증 완료, 깨지지 않는지 재확인 |
