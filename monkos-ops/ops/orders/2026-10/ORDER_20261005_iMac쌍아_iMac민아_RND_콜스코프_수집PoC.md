## 1. 목적

최종 구상은 안드로이드 화면분할 + 접근성 판독으로 여러 기사앱 콜을 실시간으로 모으는 것이다. 지금 기기는 **아이폰**(콜마너·카카오 T 대리·티맵 대리)뿐이고, 아이폰은 다른 앱 화면을 읽을 수 없다. 그래서 이번 PoC는 **캡처 이미지 → 판독 → 구조화 저장 → 열람**으로 다음 두 가지를 실증한다.

1. 세 앱 화면에서 콜 항목(거리·요금·결제·출처 회사·예약 시각·출발지·도착지·운행 시간)이 **얼마나 정확히 구조화되는가** (필드별 정확도)
2. 쌓인 콜 기록이 판단 재료(회사별 성격·예약/즉시 분리)로 쓸 수 있는 형태가 되는가

이 판독 스키마와 데이터 모델은 안드로이드 수집기로 그대로 넘어간다. 입력 경로만 캡처에서 접근성으로 바뀐다.

## 2. 범위

**허용**
- 포털(`monkos_AI/portal/`) 안에 어드민 내부 도구 1개 신설: 페이지 `public/admin/callscope.html`(+js) · API `/api/admin/callscope/*` · `lib/callscope/`
- 판독은 포털에 이미 있는 Gemini 호출 경로·모델 정본(`lib/shared/config.js`)을 재사용. **새 모델명 하드코딩 금지**
- 저장소는 Firestore 신규 컬렉션 1개(이름은 민아가 정하되 기존 컬렉션과 분리). 원본 이미지는 **기본 미보존**(판독 후 폐기). 디버그용 보존이 필요하면 GCS 접두사 `mina_callscope/` + 7일 수명 규칙
- 어드민 메뉴 "내부 도구" 그룹에 등재 + `monkos-ops/tech/SERVICE_MAP.md` §3 인덱스 1행 추가
- **dev 배포**: `monkos_AI/portal/deploy.sh dev` (→ `monkos-portal-dev`)
- 작가님 실기기 캡처로 실측(아래 5절)

**금지**
- 기사앱에 대한 어떤 입력·조작도 없음(탭·스크롤·위치 변경 등). 이번 PoC는 이미지 판독만 한다
- 공개 표면 노출 금지: 어드민 인증(`requireAdmin`) 뒤에만 둔다. `noindex`
- **prod 배포는 이 지시서 범위 밖** — dev 실측 보고 후 작가님 채팅 '배포 승인'으로 별도 진행
- 신규 시크릿·API 키·토큰 생성 금지(헌법 4조 1항). 아이폰 단축어 자동 업로드에 전용 토큰이 필요해지면 **만들지 말고** 결정 항목으로 보고
- 판독 결과를 외부로 발송·공유 금지

## 3. 설계

### 3-1. 입력 — 아이폰에서 올리기
- **1단계(필수)**: 아이폰 Safari로 어드민 로그인(`monkos_session` 쿠키) → `callscope.html`에서 여러 장 선택 업로드. 앱 이름은 자동 판별하되 수동 지정 드롭다운을 함께 둔다
- **2단계(선택, 가능 여부만 실측)**: iOS 단축어 "스크린샷 → URL로 POST" + 뒷면 탭 연결. 인증 방식이 쿠키로 안 되면 구현하지 말고 보고서에 필요 조건만 적는다

### 3-2. 판독 — 이미지 1장 → 콜 N건
- 한 캡처에 **목록 행 여러 개 + 상세 팝업 1개**가 함께 있을 수 있다(쌍아 세션에서 본 콜마너 캡처 2장이 이 형태다. 고객 주소가 담겨 레포에 넣지 않았으니 샘플은 작가님께 원본을 받는다). 행과 팝업을 각각 콜로 뽑고, 같은 콜이면 병합
- 출력 스키마(콜 1건):

| 필드 | 설명 | 콜마너 예 |
|---|---|---|
| `app` | 콜마너 / 카카오 / 티맵 / unknown | 콜마너 |
| `captured_at` | 캡처 시각(EXIF → 없으면 상단 상태바 시계 → 없으면 업로드 시각, 출처 표기) | 13:39 |
| `pickup_km` | 픽업까지 거리(km) — 목록 첫 숫자 = 팝업 🏃 숫자 | 17 |
| `fare_krw` | 요금(원). `45K` → 45000 | 35000 |
| `pay_tags[]` | 결제·계약 표기 | 후불, 법 |
| `badges[]` | 추천콜 등 | 추천콜 |
| `source_co` | 출처 회사 약칭(메모 앞머리) | 청(청방) |
| `memo_raw` | 메모 칸 원문 그대로 | 청/상담©셀퍼만/비흡연)10.6화)07:30/… |
| `conditions[]` | 메모에서 뽑은 조건 | 상담, 비흡연, 경유 |
| `reserved_at` | 예약 일시(메모의 `10.6화)07:30`, `14:10` 등). 없으면 null = 즉시 콜 | 2026-10-06 07:30 |
| `pickup_text` / `dropoff_text` | 출발지·도착지 원문 | 용인동천동.수지수풍로89 / (화성시동탄구)화성능동.동탄숲속로95 |
| `trip_min` | 예상 운행 시간(분) — 목록 둘째 줄 = 팝업 🚗 | 31 |
| `region_header` | 화면 상단 현재 위치 표시 | 경기/하남시/풍산동 |
| `radius_setting` | 화면의 범위 설정 | 30km |
| `confidence` | 필드별 판독 신뢰도 | — |

- 확정 용어집(작가님 확인): **법**=법인, **후**=후불, **즉후**=즉시 후불, **청**=청방(회사 이름). 추정: **상담**=사무실 통화 후 배정, **비흡연)**=비흡연 기사 요구. 미상: **셀퍼만**. 용어집은 파일 1개(`lib/callscope/glossary.json` 등)로 두고, **모르는 약어는 버리지 말고 `unknown_tokens[]`로 모은다**
- 카카오·티맵은 화면 형식을 아직 모른다. 작가님께 각 앱 캡처를 받아 형식부터 확인하고, 처음 보는 형식은 `app=unknown` + 원문 보존으로 처리한다(실패 무음 금지)

### 3-3. 저장·중복
- 같은 콜이 여러 캡처에 반복 등장한다. 중복 키 = `app + source_co + pickup_text + dropoff_text + fare_krw + reserved_at`. 재등장 시각은 `seen_at[]`에 추가(나중에 '소진 속도' 지표의 재료)
- 원본 이미지 미보존이 기본(3절 허용 참조). 고객 주소가 담기므로 어드민 인증 밖으로 나가는 경로를 만들지 않는다

### 3-4. 열람 — 어드민 페이지
- 콜 목록 표(최근순, 즉시/예약 탭 분리) · 필드별 신뢰도 낮은 칸 강조 · 원문 메모 펼침
- 요약 카드: 앱별·회사(`source_co`)별 건수·평균 요금·예약 비율 · 미상 약어 목록과 빈도
- 판독 수정 UI는 불요(PoC). 대신 **정답 표기 체크박스**(필드별 맞음/틀림)를 둬서 5절 정확도 측정에 쓴다
