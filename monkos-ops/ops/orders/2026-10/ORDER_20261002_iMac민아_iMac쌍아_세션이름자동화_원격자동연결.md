## 3. 확인된 사실과 요건

### A. 세션 이름 자동 지정

- **수단(공식 문서 원문 대조, 10-02 11:48)**: SessionStart 훅의 `hookSpecificOutput.sessionTitle` — "/rename과 같은 효과", `source`가 startup·resume·fork일 때 적용, clear·compact는 무시(`code.claude.com/docs/en/hooks.md`, SessionStart decision control 절). 훅 입력의 `session_title`은 이미 이름이 있을 때 들어오므로 **있으면 덮어쓰지 않는다**.
- **현행 훅**: `scripts/hooks/session_start.sh`(36행, `.claude/settings.json` SessionStart 블록, matcher `startup|resume|compact`). 지금은 평문 출력이다 — 문서상 `sessionTitle`을 내려면 JSON 출력 형식이 필요하다(평문 문맥 주입은 `additionalContext`로 옮겨야 함).
- **서식(작가님 11:55 제안 + 민아 보완, 작가님 11:56 진행 지시)**: `{디바이스}-{역할}-{MMDD}-{HHMM}` 예 `M2-쌍아-1002-1120`. 날짜만으로는 같은 날 새 대화끼리 겹친다(10-02 M2 실례 11:20·11:29). 빗금·공백은 쓰지 않는다(주소 문자열·세션 로그 파일명 규칙과 정합).
- **역할 판별 근거**: 환경 변수 `CLAUDE_CODE_ENTRYPOINT` — 민아 세션에서 `claude-desktop`, M2 확장 대화 기록의 메타에서 `claude-vscode`, M2 CLI 세션에서 `cli` 실측. ch1 5조 판별표(VSCode=쌍아 / 앱 Code 탭=민아 / CLI=막내)에 대응시킨다. 막내 번호는 훅이 알 수 없다 — `막내`까지만 붙이고 번호는 지시서 수신 후로 둔다. 웹(원격 컨테이너)·헤드리스·서브에이전트의 처리 방침은 쌍아 판단.
- **이름은 시작 시점으로 고정**: 이틀째 이어 쓰는 세션은 `1001`로 남는다(그 자체가 "어제 열린 세션" 정보).
- **미확정(민아 원문 미대조)**: 동명 세션이 살아 있을 때 신규 세션에 변형 이름이 붙는지. 날짜·시각 서식이면 충돌 자체가 드물다.

### B. 원격 자동 연결

- **원인 확정(공식 문서 원문 대조)**: `remoteControlAtStartup: true`는 **사용자 설정 `~/.claude/settings.json`(또는 관리 설정)에서만 유효**. 프로젝트·로컬 설정(`.claude/settings.json`, `.claude/settings.local.json`)의 `true`는 무시되고 `false`만 존중된다(`remote-control.md` "Enable Remote Control for all sessions" 절, `settings.md` 표).
- **iMac 현황(11:40 실측)**: `~/.claude/settings.json`에 이 키 없음. iMac VSCode 쌍아 세션 2개는 민아 세션과 같은 기기라 통신되지만 원격 연결에는 올라와 있지 않아 M2에서 보이지 않는다.
- **요건**: iMac 사용자 설정에 키 추가. 전역 환경 변경이므로 ch1 7조 승인 게이트 대상 — 작가님 11:56 지시가 범위 승인이나, 쌍아 세션에서 실행 전 작가님 확인 1회를 권한다.
- **이미 된 것**: iMac VSCode 사용자 설정 `claudeCode.initialPermissionMode: bypassPermissions`는 민아가 작가님 승인(11:25)으로 추가했다. 새 대화에서의 실효는 미검증.

### C. 옛 인스턴스 보고

- 이름을 자동으로 붙여도 옛 세션은 살아 있는 한 계속 응답한다. 세션 시작 절차(`.claude/commands/session-start.md`)에 "피어 목록 조회 → 같은 기기·역할의 살아 있는 세션이 있으면 첫 보고에 1줄" 추가. 닫는 것은 작가님 손이다.
- 보내는 쪽 규칙: 같은 기기·역할이 여럿이면 이름의 날짜·시각이 가장 늦은 세션으로 보낸다. 회신은 받은 메시지의 `from` 주소로.
- (선택) 새 세션이 시작 시 상대 부서장 세션에 "시작" 1줄을 먼저 보내는 방식 — 채택 여부 쌍아 판단.
