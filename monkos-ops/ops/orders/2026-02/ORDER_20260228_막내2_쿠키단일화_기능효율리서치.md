## 배경

쿠키 단일화(HttpOnly `.monkos.ai` 쿠키를 유일한 인증 수단으로 통일) 방향이 확정 단계다. 이 리서치는 **실제 코드 기준**으로 수정 범위, 파일별 영향도, 구현 효율을 분석한다.

---

## 리서치 범위: 기능효율

### 1. 현행 인증 코드 전수 인벤토리

아래 파일을 전수 읽고, **sessionStorage/localStorage/cookie 관련 코드를 줄 번호 단위로 목록화**할 것:

#### idphoto-kr (클라이언트)
| 파일 | 핵심 내용 |
|------|----------|
| `monkos_AI/idphoto-kr/public/shared.js` | initCredits() 2-phase, checkTokenExpiry(), saveSessionData/loadSessionData |
| `monkos_AI/idphoto-kr/public/modules/gate.js` | OAuth 팝업 → sessionStorage SET (3곳) |
| `monkos_AI/idphoto-kr/public/index.html` | updateAuthUI, checkTokenExpiry(중복), Google/카카오/LINE OAuth |
| `monkos_AI/idphoto-kr/public/result.js` | monkos_free_gen(localStorage), _mo_p(토스 리다이렉트 복원) |
| `monkos_AI/idphoto-kr/public/camera.js` | saveSessionData('captured') |
| `monkos_AI/idphoto-kr/public/prep.js` | loadSessionData() |
| `monkos_AI/idphoto-kr/public/thankyou.js` | 다운로드/공유 |

#### portal (서버 + 클라이언트)
| 파일 | 핵심 내용 |
|------|----------|
| `monkos_AI/portal/lib/auth.js` | 카카오/LINE/구글 OAuth 콜백, monkos_session 쿠키 SET, verify-cookie |
| `monkos_AI/portal/lib/shared/config.js` | generateAuthToken/verifyAuthToken |
| `monkos_AI/portal/server.js` | 라우트 등록 (모듈화 완료 상태) |
| `monkos_AI/portal/public/index.html` | 클라이언트 인증 (sessionStorage) |
| `monkos_AI/portal/public/credits.html` | ⚠️ localStorage.monkos_user 사용 중 (불일치) |

### 2. 수정 범위 분석

#### 분석 항목

| # | 분석 |
|---|------|
| E1 | **제거 대상 코드**: sessionStorage에서 monkos_user/monkos_token을 읽고 쓰는 모든 지점. 줄 번호 + 파일 + 현재 동작 정리 |
| E2 | **대체 로직**: 쿠키 기반으로 전환 시 각 지점이 어떻게 바뀌는지 (before → after) |
| E3 | **유지 대상 코드**: sessionStorage에서 이미지 데이터(captured/cropped/generated/_mo_p)와 선택 옵션(style/gender/age 등)은 유지. 인증과 분리 |
| E4 | **credits.html 불일치**: 현재 localStorage.monkos_user 사용 → 쿠키로 전환 시 수정 범위 |
| E5 | **index.html 중복 코드**: checkTokenExpiry()가 shared.js와 index.html에 중복 → 통합 방안 |
| E6 | **shared.js 단일 함수**: initCredits()를 쿠키 전용으로 단순화할 때의 설계 (Phase 1 제거, Phase 2만 유지) |
| E7 | **gate.js OAuth 흐름**: 팝업 postMessage 후 sessionStorage SET → 쿠키 기반이면 이 부분이 불필요해지는지, 아니면 UI 업데이트용으로 유지해야 하는지 |

### 3. 수정 파일 매트릭스

아래 형식으로 정리:

```
| 파일 | 수정 유형 | 영향 줄 수 | 난이도 | 비고 |
```

- 수정 유형: 제거 / 교체 / 신규 / 유지
- 난이도: 단순(기계적 치환) / 중간(로직 변경) / 복잡(설계 변경)
