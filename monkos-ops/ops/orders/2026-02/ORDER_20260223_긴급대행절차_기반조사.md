## 배경

2026-02-23 토스페이먼츠 긴급 대응 과정에서 **2건의 절차 예외**가 발생했다.

### 예외 1 — 막내 직접 배포 (어젠다 #6-1)
- **상황**: 카드사 심사 회신 기한 임박 → footer 수정 후 즉시 배포 필요
- **위반**: ch7 1조(main 머지 금지) + ch7 3조(gcloud run deploy 금지)
- **처리**: 작가님 구두 승인 → [예외] 기록 → 막내 직접 실행
- **문제**: 긴급 시 예외의 정규 절차가 없음. 매번 ad-hoc 승인

### 예외 2 — 철창이 역할 대행 (어젠다 #7)
- **상황**: 작가님 GUI 작업 중 → 쌍아와 대화 불가 → footer 유선번호 누락 발견
- **위반**: 헌법 5조(역할 체계) — 철창이="전략"인데 쌍아 역할(설계+지시서+배포 지휘) 대행
- **처리**: 작가님이 철창이 세션에서 직접 지시 → 예외 적용 → 사후 어젠다 상신
- **문제**: 에이전트 간 역할 대행 메커니즘 부재

## 조사 항목

### A. 현행 법체계 예외 처리 분석

1. **현행 예외 처리 메커니즘 전수 조사**
   - CLAUDE.md(헌법) 내 예외 관련 조항 목록화
   - 법률 ch1~ch8 내 예외 조항 전수 추출
   - `[예외]` 기록이 실제로 어디에 남는가 (세션 로그? 지시서? 커밋?)
   - 예외 승인 → 실행 → 사후 검증의 현행 흐름 도식화

2. **현행 법률의 공백/모순 식별**
   - ch7 3조 "gcloud run deploy 금지"와 긴급 배포 필요성의 충돌
   - 헌법 5조 역할 체계에 "대행" 개념 부재
   - 긴급도 정의 부재 (무엇이 "긴급"인가의 기준 없음)
   - 예외 승인권자 범위 미정의 (작가님만? 쌍아도?)

### B. 타 시스템 긴급 대행 패턴 조사

1. **군사 체계**: 지휘 승계 / 임시 지휘권 위임 패턴
2. **기업 거버넌스**: CEO 부재 시 CFO/COO 대행 체계
3. **소프트웨어 운영**: On-call 에스컬레이션 / Break-glass 절차 (GCP, AWS)
4. **법률 체계**: 대통령 권한대행 / 직무대리 요건

> 각 패턴에서 공통 요소 추출: 트리거 조건, 대행 범위, 시간 제한, 보고 의무, 사후 검증

### C. 에이전트 체계 적용 선택지

위 조사를 바탕으로, MONKOS 에이전트 체계에 적용 가능한 **선택지**를 제시.

1. **긴급 배포 절차 선택지** (어젠다 #6-1)
   - 옵션 A: 긴급 등급 정의 + 등급별 권한 자동 확대
   - 옵션 B: Break-glass 절차 (사전 승인 없이 실행 → 사후 필수 심사)
   - 옵션 C: 현행 유지 (매건 작가님 구두 승인)
   - 각 옵션의 장단점 + 법률 개정 범위

2. **역할 대행 체계 선택지** (어젠다 #7)
   - 옵션 A: 고정 승계 순위 (쌍아 부재 → 철창이 자동 대행)
   - 옵션 B: 작가님 지명제 (매건 작가님이 대행자 지정)
   - 옵션 C: 기능별 분리 (전략=철창이 고유, 설계/지시서=작가님 직접 지시만)
   - 각 옵션의 장단점 + 헌법 개정 범위
