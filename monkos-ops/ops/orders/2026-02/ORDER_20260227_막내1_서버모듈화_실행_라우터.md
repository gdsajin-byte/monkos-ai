## 작업 내용

### Step 1: `lib/shared/config.js` 생성

본인 보고서의 환경변수 24개 + 싱글톤 11개 + 상수 14개를 중앙화.

```
lib/shared/config.js
├─ 환경변수 전수 (process.env → 변수 export)
├─ Firestore 초기화 (db)
├─ Gemini AI 초기화 (ai)
├─ GCS 클라이언트 (없으면 portal에선 불필요 확인)
├─ 텔레그램 API URL 3개
├─ CORS 헤더
├─ log() 함수
├─ sendTelegramMessage() 함수
├─ deprecated 엔드포인트 정리 (2개 삭제)
└─ LEMONSQUEEZY_WEBHOOK_SECRET 이중 용도 주석 명시
```

**핵심**: 모든 모듈이 `const { db, ai, log, ... } = require('./shared/config');`로 가져가는 구조.
DI 불필요 (본인 보고서 근거).

### Step 2: server.js → 라우터 전용으로 축소

server.js에 남는 것:
- `require` 로 각 모듈 로딩
- HTTP 서버 생성 + 리스닝
- URL 기반 라우팅 (`if (req.url === '...') return handler(req, res);`)
- 정적 파일 서빙
- 헬스체크 (`/health`)
- 서버 시작 로그

**server.js 예상 줄 수: ~150줄** (현재 2,981줄에서)

### Step 3: 모듈 파일 스켈레톤 생성

막내2·3이 작업할 파일의 빈 스켈레톤을 미리 생성:

```
lib/
├─ shared/
│  └─ config.js          ← 막내1 (본 지시서)
├─ auth.js               ← 스켈레톤 (막내2가 채움)
├─ credits.js            ← 스켈레톤
├─ payments.js           ← 스켈레톤
├─ events.js             ← 스켈레톤
├─ prompts.js            ← 스켈레톤 (막내3이 채움)
├─ chat-engine.js        ← 스켈레톤
├─ rag.js                ← 스켈레톤
├─ telegram.js           ← 스켈레톤
├─ telegram-team.js      ← 스켈레톤
├─ kakao-chatbot.js      ← 스켈레톤
└─ coaching.js           ← 스켈레톤
```

스켈레톤 = `module.exports = {};` + 주석으로 "이 파일의 책임" 명시.
