# MONKOS 봇 시스템 통합 전략 리서치

> **[2026-02-27 13:47 KST] iMac/쌍아 → 막내1**
> 카카오 챗봇 스킬 서버 추가를 계기로, MONKOS의 전체 봇/챗봇 시스템을 조감한다.
> 포탈 챗봇 시스템 하나로 통합하는 것이 합당한지, 각각 별도 운영이 맞는지,
> 그에 뒷받침할 규정·참고 시트·학습 방안을 조사하라.

---

## 취지

현재 portal/server.js 안에 **7개 봇/챗봇 기능**이 혼재한다.
카카오 챗봇 추가로 채널이 하나 더 늘어난 시점에서,
이 구조가 지속 가능한지, 정리가 필요한지 판단 근거를 마련한다.

## 작가님 방향성 (필수 반영)

> "라인에도 챗봇이 필요하고, 이벤트·포털 각 서비스 전부를 한 챗봇으로 통일하는 게 편할 것 같다"

**핵심 가설**: chatWithMonkos() 통합 허브 구조를 유지하되,
- **CS 대화 레이어**: 채널 불문(웹/카카오/텔레그램/LINE) 하나로 통합 → CHANNEL_CONFIG 확장만으로 해결
- **트랜잭션 레이어**: 이벤트봇(게이트/미션), 팀봇(내부) 등 역할이 다른 것은 분리 유지
- **LINE 챗봇**: 일본 시장 서비스용. 카카오와 동일 패턴으로 LINE Messaging API 래퍼 추가

이 가설이 맞는지, 더 나은 구조가 있는지를 근거와 함께 검증하라.
LINE 챗봇 추가 시 아키텍처까지 포함하여 조사할 것.

**추가 방향 (작가님 판단)**:
> "이벤트봇도 한 봇으로 처리 가능한 거 아니야?"

텔레그램 CS봇 + 이벤트봇을 **한 봇으로 통합**하는 방안도 검토할 것.
메시지 타입(/start 커맨드, 이미지, 일반 텍스트)으로 분기하면 한 봇에서 CS + 게이트 + 미션 전부 가능.
팀봇만 내부용이므로 분리 유지. 이 통합 시 장단점·마이그레이션 영향 포함.

## 조사 항목

### 1. 통합 vs 분리 아키텍처 판단

현재 `chatWithMonkos()`가 채널 허브 역할을 하고 있다. 이 구조가:

- **장점**: 프롬프트/RAG/히스토리가 한 곳에서 관리됨. 채널 추가 시 CHANNEL_CONFIG만 확장
- **단점**: server.js가 비대해짐. 텔레그램 웹훅 3개 + API 4개가 한 파일에 혼재

조사할 것:
- 현재 server.js의 봇 관련 코드 비중 (전체 대비 %)
- 텔레그램 봇 3개를 하나로 합칠 수 있는가 (기술적으로)
- 합치면 안 되는 이유가 있는가 (역할 분리 관점)
- web/kakao/LINE 등 CS 채널은 chatWithMonkos 통합이 맞는가
- prep/qc 같은 특수 목적 봇은 분리가 맞는가
- 마이크로서비스 분리 필요 시점은 언제인가

### 2. 규정 체계

현재 봇 운영에 관한 법률/규정이 부재하다. 조사할 것:

- 봇 응답 정책이 코드(시스템 프롬프트)에만 존재 — 문서화 필요 여부
- CS_SYSTEM_PROMPT의 에스컬레이션 정책 (`info@monkos.ai`로 안내) — 규정화 필요 여부
- 봇별 응답 톤/범위/금기사항이 프롬프트마다 다름 — 통합 가이드라인 필요 여부
- 헌법 11조(윤리적 운용)의 "RAG/챗봇: 되는 것만 응답" 원칙과의 정합성
- 개인정보 처리 (텔레그램 chatId, 카카오 userId) — 규정 필요 여부

### 3. CS 지식 참고 시트

현재 Firestore `cs_knowledge`가 RAG 지식원이다. 조사할 것:

- 현재 지식 건수 및 커버리지 (어떤 주제가 있고, 빠진 건 무엇인가)
- 지식 갱신 프로세스 (누가, 언제, 어떻게 업데이트하는가)
- 카카오 채널 추가로 필요해진 신규 지식 항목 (카카오 특화 FAQ 등)
- 다국어 지식 분리 현황 (일본어/한국어/영어가 하나의 시트인지)
- 지식 품질 관리 방안 (정기 검토 주기, 담당자)

### 4. 학습 방안

봇 성능 개선을 위한 학습/튜닝 방안 조사:

- 현재 Firestore에 쌓이는 대화 로그 활용 방안 (빈출 질문 분석, 미응답 패턴)
- RAG 지식베이스 확장 전략 (수동 추가 vs 대화 로그에서 자동 추출)
- 프롬프트 개선 사이클 (A/B 테스트 가능성)
- 카카오/텔레그램/웹 채널별 사용자 행동 차이 → 채널별 최적화 필요성
