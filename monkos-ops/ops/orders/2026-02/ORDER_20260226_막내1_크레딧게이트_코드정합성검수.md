# [2026-02-26 16:40 KST] iMac/쌍아 → 막내1

## 지시: 크레딧 게이트 시스템 — 코드 정합성 전수검수

### 배경

크레딧 게이트 시스템이 2026-02-25 배포되었으나, 다운로드 프리뷰 화면에서 **이벤트 크레딧 중복 지급 경로**가 발견되었다. 작가님 지시로 코드 레벨 정합성 전수검수를 실시한다.

### 발견된 문제

1. **이벤트 크레딧 중복**: 게이트 팝업(30c+40c=70c)과 별도로 프리뷰 화면에 SNS 100c 이벤트 카드가 존재
2. 두 시스템이 독립적으로 크레딧을 지급하면 1인당 최대 **170c 이상** 무료 수령 가능

### 검수 항목 (7건)

#### 1. 이벤트 크레딧 중복 지급 경로 전수조사
- 게이트 팝업의 이벤트 (`signup_bonus: 30c`, `sns_share: 40c`, `photo_consent: 40c`)
- 프리뷰 화면의 SNS 이벤트 카드 (`share-bonus` 또는 별도 경로로 100c?)
- `/api/credits/event`와 `/api/credits/share-bonus` 두 엔드포인트의 관계
- **서버 사이드에서 중복 방지가 되는지**: 동일 userId에 대해 두 경로 모두 지급 가능한가?

#### 2. 프론트엔드 ↔ 백엔드 금액 정합성
- `config.js`의 `CREDIT_COST` (generate:10, download:70)
- `server.js`의 `EVENT_CREDITS` (signup_bonus:30, sns_share:40, photo_consent:40)
- `server.js`의 `TOSS_AMOUNT_CREDITS` (결제 금액 → 크레딧 매핑)
- `shared.js`의 충전 옵션 금액/크레딧
- `result.js`의 게이트 팝업 UI 텍스트에 표시된 금액
- **모든 위치의 숫자가 서로 일치하는지**

#### 3. 비로그인 1회 제한 우회 가능성
- `localStorage.monkos_free_gen` 플래그 기반 — 시크릿 모드/다른 브라우저로 우회 가능
- 서버 사이드 제한이 있는지 (IP? 디바이스 핑거프린트?)
- 워터마크로 실질 피해가 없다면 OK, 있다면 보고

#### 4. 결제 금액 ↔ 크레딧 매핑 안전성
- `TOSS_AMOUNT_CREDITS`에 없는 금액이 들어오면 어떻게 처리되는지
- 클라이언트가 금액을 조작하여 보낼 수 있는지 (토스 SDK → 서버 검증 흐름)
- 비로그인 직접결제(`/api/payments/toss/direct`)의 다운로드 토큰 보안 (TTL, 재사용 방지)

#### 5. sns_share / photo_consent 택1 로직 검증
- `server.js`에서 409 Conflict 반환 로직이 실제로 동작하는지 코드 추적
- 프론트엔드에서 하나를 선택하면 나머지가 비활성화되는지
- 둘 다 빠르게 연속 요청 시 레이스 컨디션 가능성

#### 6. 크레딧 차감 시 Firestore 트랜잭션 안전성
- 생성(10c) + 다운로드(70c) 차감이 atomic한지
- 동시 요청 시 음수 잔액 가능 여부
- 차감 실패 시 롤백 처리

#### 7. CF Workers Legacy 코드 (`functions/api/idphoto-credit-use.js`)
- MONK_kr(데스크톱)에서 이 경로를 통해 별도로 크레딧이 사용되는지
- monkos.ai 서버와 이중 차감 가능성
