### 버그 1: iOS 브라우저 캐시 — 이전 JS 로딩

**증상**: 버튼 완전 먹통 (onclick 미반응)
**원인**: iOS Safari가 이전 shared.js(store.user=null 시절)를 캐시에서 로드 → `store.user.id` 접근 시 TypeError → ES module 전체 실패 → window.confirmAndGenerate 미등록

**근거**: Android는 정상 → 코드 자체 문제가 아니라 캐시 문제

**수정 (2건)**:

// 정적 파일 서빙 (JS/CSS 캐시 방지 — 모바일 브라우저 강제 갱신)

### 버그 2: iOS Safari OAuth 팝업 차단

**증상**: 로그인 모달은 뜨지만, Google/카카오/LINE 로그인 버튼 클릭 시 미반응
**원인**: iOS Safari는 `window.open()`을 사용자 직접 클릭 이벤트 핸들러 내에서만 허용. 비동기 콜백이나 setTimeout 내부에서 호출하면 팝업 차단.

**확인 대상 파일**: `public/modules/gate.js`

현재 gate.js의 로그인 버튼 핸들러:

```javascript
overlay.querySelector('#gate-login-google-btn').addEventListener('click', () => {
    _closeLoginRequired();
    if (typeof window.loginGoogle === 'function') window.loginGoogle();
});
overlay.querySelector('#gate-login-kakao-btn').addEventListener('click', () => {
    _closeLoginRequired();
    _startKakaoLoginSimple();
});
overlay.querySelector('#gate-login-line-btn').addEventListener('click', () => {
    _closeLoginRequired();
    _startLineLoginSimple();
});
```

**점검 포인트**:

1. `window.loginGoogle` 존재 여부 확인 — result.html에서 Google 로그인이 window에 노출되는지
2. `_startKakaoLoginSimple()`의 `window.open()` 호출이 동기 컨텍스트인지 확인
3. `_startLineLoginSimple()`도 동일
4. iOS Safari에서 `_closeLoginRequired()` 후 DOM 제거가 팝업 열기에 영향을 주는지

**수정 방향**:

- **방법 A (팝업 → 리다이렉트)**: iOS Safari에서 `window.open` 대신 `window.location.href` 직접 이동
  ```javascript
  // iOS 감지
  const isIOS = /iPad|iPhone|iPod/.test(navigator.userAgent);

  // 팝업 대신 리다이렉트
  if (isIOS || !popup) {
    window.location.href = `${API.PORTAL_URL}/auth/kakao`;
    return;
  }
  ```

- **방법 B (팝업 선오픈)**: 클릭 이벤트 내에서 먼저 `window.open('')`으로 빈 창 열고, 이후 URL 설정
  ```javascript
  const popup = window.open('', 'kakao-login', 'width=500,height=600');
  popup.location.href = `${API.PORTAL_URL}/auth/kakao?popup=1&redirect_app=idphoto-kr`;
  ```

**택1 근거와 함께 선택.** A가 안정적이나 UX 변경이 큼. B가 기존 UX 유지하면서 iOS 호환.
