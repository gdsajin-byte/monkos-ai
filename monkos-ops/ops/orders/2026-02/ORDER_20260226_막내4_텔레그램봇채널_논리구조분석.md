# [2026-02-26 19:28 KST] iMac/쌍아 → 막내4

## 지시: 텔레그램 봇/채널 논리구조 분석 + CHANNEL_ID 추천

### 배경

크레딧 게이트 v2에서 **텔레그램 채널 가입 검증**(Bot API `getChatMember`)이 필요하다.
이를 위해 `TELEGRAM_CHANNEL_ID` 환경변수를 설정해야 하는데, 현재 봇과 채널이 산재해 있어 어느 채널을 지정해야 하는지 판단이 필요하다.

작가님 원문: "봇과 채널만 너무 많아져도 관리가 좀..."

### 현재 텔레그램 인프라 전수조사 결과

| 1 | @monkos_support_bot | `TELEGRAM_BOT_TOKEN` | `/api/webhook/telegram` | CS 고객지원 | portal/server.js |

- 미션: `t.me/monkos_event_bot?start=MISSION_{code}`

#### getChatMember 호출 (server.js ~L1645)

```javascript
const response = await fetch(
  `${TELEGRAM_EVENT_API}/getChatMember?chat_id=${TELEGRAM_CHANNEL_ID}&user_id=${telegramId}`

```

→ **이벤트봇 토큰**으로 **TELEGRAM_CHANNEL_ID** 채널의 멤버십을 검증.

### 작업 항목

#### 1. 봇/채널 논리구조 분석

**분석 관점**:

a) **고객 접점 봇** vs **내부 봇** 분류
b) **봇 통합 가능성** — 기능 중복이 있는가? 통합하면 이점이 있는가?
c) **레거시 정리** — @Monk_yonga_bot, @monkos_factory_bot은 현재 활성인가?
d) **getChatMember에 적합한 채널** — 어떤 채널에 가입시켜야 하는가?

**코드 조사 대상**:

```
monkos_AI/portal/server.js          ← 3봇 통합 (CS/이벤트/팀)
functions/api/telegram.js            ← 용아봇 (CF Workers)
functions/api/telegram-webhook.js    ← 용아봇 웹훅
apps/MonkosChat/functions/index.js   ← 팩토리봇 (Firebase)
monkos_AI/.env                       ← 환경변수 (변수명만 확인, 값 노출 금지)
```

#### 2. TELEGRAM_CHANNEL_ID 추천

**판단 기준**:
- 고객이 "가입"할 수 있는 **공개 채널**이어야 함
- 이벤트봇이 해당 채널의 **관리자**(또는 멤버 조회 권한)여야 함
- 향후 공지/마케팅 콘텐츠를 발행할 채널과 **동일**하면 시너지
- 봇 대화방(1:1 채팅)은 getChatMember 대상이 아님 — **채널 또는 슈퍼그룹**만 가능

**확인 사항**:
- 현재 "MONKOS AI" 채널의 username 또는 숫자 ID
- 해당 채널에 @monkos_event_bot이 관리자로 추가되어 있는지
- 없다면 추가 절차 안내

#### 3. 봇/채널 정리 추천안

**검토 후 추천**:
- 유지해야 할 봇/채널 목록
- 통합 또는 폐기 가능한 봇/채널 목록
- 관리 부담을 줄이는 구조 제안
