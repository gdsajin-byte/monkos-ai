### 2. ch7 1조 개정 (막내 행동강령 — 마무리 절차)

`governance/laws/ch7_makne_code.md` 1조 마무리 절차 테이블 뒤에 **완료 보고 파일 생성** 섹션 추가:

```markdown
#### 완료 보고 파일 생성 (필수)

모든 막내 완료 보고는 아래 경로에 파일로 생성한다:

**경로**: `monkos-ops/ops/reports/COMPLETION_YYYYMMDD_막내N_{HHMMSS}.md`

**YAML 필수 필드:**
```yaml
---
type: completion
date: YYYY-MM-DD
time: HH:MM KST
from: {디바이스}/막내N
to: {지시서 from 또는 작가님(직접지시 시)}
order: {지시서 파일명 또는 "[직접지시]"}
commit: {커밋 해시 7자리}
branch: develop
---
```

**본문:** 헌법 2조 형식(`✅❌💡⏳📁🔀`) 준수. 변경 파일 목록, 커밋 해시, push 상태 포함.

**마무리 흐름 (개정):**
```
코드 작업 → 보고 파일 생성 → 커밋(작업+보고 포함) → push → 터미널 출력
```

**보안 수칙:**
- API 키, 토큰, 비밀번호, 사용자 개인정보(이메일, 전화번호, 결제 정보, OAuth 계정 ID) 기재 금지 (헌법 6조)
- 에러 로그 인용 시 민감 정보 마스킹 필수
- 서버 URL, 내부 IP는 마스킹 또는 생략
- 보고 파일은 Git 이력에 영구 기록된다. 민감 정보가 한 번이라도 커밋되면 복구 비용이 극히 높다.

**파일 충돌 방지:**
- 파일명에 `HHMMSS` 포함 → 동시 보고 시에도 충돌 없음
- 세션 로그 파일은 건드리지 않음 (쌍아 관할)
- 다른 막내의 보고 파일을 수정/삭제하지 않음

**적용 범위:**
- 완료 보고만 파일화한다. 에스컬레이션(ch7 4조)은 기존 터미널 출력을 유지한다.
```

기존 마무리 절차 테이블의 순서도 보정:
- 현행: `커밋 → push → 완료 보고`
- 개정: `보고 파일 생성 → 커밋(작업+보고) → push → 터미널 출력`
