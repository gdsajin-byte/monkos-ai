# ORDER — `secret.sh env` 시크릿 값 출력 제거

**[2026-08-13 17:04 KST]** iMac/쌍아 → iMac/막내1

> **발행 근거**: 작가님 직접 지시(08-13 17:04) — "로테이션까지는 필요없고 출력은 제거하자".
> **착수 전 필독**: [`.claude/rules/data-access.md`](../../../../.claude/rules/data-access.md) 시크릿 운용 원칙

## 1. 배경 — 도구가 원칙을 깨고 있다

`.claude/rules/data-access.md`는 **"에이전트가 값을 채팅·컨텍스트·파일에 노출 금지"** 를 명시한다. 그런데 `scripts/secret.sh env` 실행 시 **시크릿 실값이 stdout으로 출력된다.**

16:52 실행에서 쌍아 컨텍스트로 실값 2건 유입. 17:04 재현 확인(출력 마스킹 후 재실행).

```
$ ./scripts/secret.sh env 2>&1 | sed -E 's/^([A-Za-z_]+)=.*/\1=<REDACTED>/' | tail -12
SM_VALUE=<REDACTED>
CURRENT=<REDACTED>
SM_VALUE=<REDACTED>
...
갱신 0개 / 동일 24개
```

**작가님 판단: 로테이션 불요, 출력 제거만.** 노출면은 세션 컨텍스트 한정이며 외부 전송·커밋 없음.

## 2. ⚠️ 원인 미특정 — 규명이 1차 과업

쌍아 정적 판독으로 **원인을 특정하지 못했다.** 추측으로 때우지 말고 실제 원인을 밝힌 뒤 제거할 것.

확인된 사실:
- `cmd_env()`(`scripts/secret.sh` 218~250행 부근) 본문에 `SM_VALUE`·`CURRENT`를 **echo하는 코드가 없다**
- `set -x` / `PS4` / `DEBUG` 설정 **없음**(grep 0건)
- `.env` 파일 안에 `SM_VALUE=`·`CURRENT=` 라인 **없음**(grep 0건)
- 그럼에도 재현된다

즉 출력원이 스크립트 본문 밖에 있다. 셸 초기화 파일(`.bash_profile`·`.bashrc`), 함수 오버라이드, 상위 래퍼, `gcloud` 래퍼 등을 의심할 것. **원인을 보고서에 명시**하고, 그 지점에서 차단하라.

## 3. 작업

1. **원인 규명** — §2. 재현 절차 그대로 사용.
2. **값 출력 차단** — 원인 지점에서 제거. 표시가 필요하면 **키 이름만** 출력한다(`↻ KEY_NAME` 형태는 유지 가능, 값은 금지).
3. **전 서브커맨드 점검** — `env` 외 `map`·`check`·`add`·`annotate` 등도 값이 새는 경로가 없는지 **각각 실행하여 실측**. 값이 나오는 곳이 또 있으면 동일 처리.
4. **회귀 방지 1줄** — 값 출력이 재발했을 때 즉시 드러나도록, 보고서에 각 서브커맨드별 "값 미출력" 실측 결과표를 남길 것.

## 4. 범위 밖 (착수 금지 — 별건)

- **`.env` 시크릿 제거 / 런타임 주입 전환** — 본 지시서는 출력 차단까지다. 정본 체계 재정비는 작가님 판단 대기 중인 별건(§5 참고).
- **`secret env`의 신규 시크릿 자동 편입** — 현 구조는 `.env`에 이미 있는 키만 SM 조회한다(`while ... done < "$ENV_FILE"`). 그래서 `RESEND_API_KEY`처럼 신규 등록분은 동기화되지 않는다. **의도적으로 고치지 말 것** — 정본 방향이 ".env에서 시크릿을 걷어내는" 쪽이면 자동 편입은 역방향이다. 현 동작을 보고서에 **기술만** 하라.
- 시크릿 로테이션 — 작가님이 불요 판단.

## 5. 참고 — 미결 논점 (본 지시서 밖)

`data-access.md`는 **".env / git = 비밀 아닌 설정값만"** 을 정본 원칙으로 규정하나, 실태는 `.env`에 SM 시크릿 **24건**이 동기화되어 있다(`secret env` 출력 "동일 24개"). 원칙과 실태가 어긋나 있으며, 해소 방향(런타임 주입 전환)은 작가님 판단 대기.
