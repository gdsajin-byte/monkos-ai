### 작가님 확정 타임라인 (2026-06-05) — 403의 정체
- **06-02 = 분기점**: 쌍아 유출 보고 → 작가님이 API 키 3개(monkosimagepro 포함) 삭제.

**전 서비스를 가장 빠르게 되살린다 + raw 로그로 진짜 사인을 확정한다.** 추론 금지 — 실험과 로그로만.

### 0. 🔴 충전·한도상향은 막내1 공격차단 확인 후에만 (작가님 경고 2026-06-05)

- **선결 조건**: 막내1(`ORDER_20260605_..._막내1_유출공격분석`)의 **차단책 적용 + 작가님 승인**.
- 차단 확인 **후에만**: 소액 충전 → `generateContent` 재호출 **200 검증** (결제원 문제 최종 확인). 그 전까지 빌링 명세·로그 분석은 진행하되 **실제 충전·한도변경은 보류**.

### Cloud Logging raw 에러 확정
- `gcloud logging read` 또는 콘솔 Logging에서 5/28~6/5 generativelanguage / 서비스별 **403·429 원문 사유**(message, reason, status) 추출. 403과 429가 **어느 키·어느 시점·어느 서비스**에서 났는지 분리.
- **403 사유 규명**: monkosimagepro(삭제키)·unknown keys 호출의 정체 — 유출 외부 트래픽인가, 우리 서비스가 죽은 키를 아직 참조하는가. 삭제(06-02) 전후 403 추이.
- **429 사유 규명**: 막내2 실측 429가 결제원 고갈인가, rate limit인가 — 본문 reason 원문.
- **실제 결제원 추적**: Gemini API 사용분이 어느 결제원(prepay/바우처/ANNUAL크레딧)에서 차감돼 왔고 언제 끊겼는지 빌링 명세 시간선.

### ⭐ 핵심 연결고리 확정 — 유출 호출 ↔ 결제원 소진
- **단 하나 남은 질문**: 삭제 전 유출 대량 호출(5/28~6/2)이 **우리 결제원/한도/쿼터를 소진**시켜 정상 서비스(MONKOS NEW)까지 429가 된 것인가?
- 확정 방법: **유출 호출량 급증 시점 ↔ 결제원/한도 소진 시점**이 빌링 명세에서 겹치는지 대조. 겹치면 인과 확정.
- ⚠️ **보안 — 즉시 확인**: 삭제된 키로 들어오는 대만 트래픽이 **지금도 rate limit/쿼터/한도를 소모하는지**. 403으로 튕겨도 카운트되면 공격 지속 = 정상 서비스 상시 방해 → **IP 차단 등 추가 방어 필요 여부** 판정. (단 키 제한·IP 차단은 작가님 승인 — 헌법 4조)
