# ORDER: 어드민 고객360° 정보밀도 대시보드 (1차)

## 0. 배경/목적
현재 어드민(`monkos.ai/admin/dashboard.html`)이 4섹션 세로로 늘어져 한눈에 파악 불가 + 추정 의존(크레딧 숫자로 결제 추측)·UTC 시각 착시·테스트 계정 노이즈. **한 화면에 "오늘 누가·어디서·어디까지·결제했나"** 가 잡히도록 재구조화한다.
- 설계 정본: [DESIGN_어드민_고객360_정보밀도](../../tech/designs/2026-06/DESIGN_20260623_어드민_고객360_정보밀도.md)
- 데이터: BQ `monkos.monkos_tracking.events`(실가동 중) + Firestore `users`/`transactions`. **BQ 트래킹 이벤트는 이미 적재 중**(page_view·auth_signup·upload_image·select_style·api_generate·generate_complete·credit_use·click_cta).

## 2. 상세 설계

### (1) utm 캡처 — server.js
- 현재 `server.js:89` `pagePath: req.url.split('?')[0]` 로 쿼리를 버림 → utm 유실.
- **page_path는 그대로 두고**(쿼리 제외 유지), `req.url`에서 `utm_source`·`utm_medium`·`utm_campaign`을 파싱해 page_view 이벤트 `params`에 추가 적재.
- 채널 식별용. 특히 카카오 인앱(referer NULL) 보강.

### (2) 유저360 집계 API — dashboard.js
- 신규 핸들러 `handleDashboardUsers360`(라우트 `/api/admin/dashboard/users360`). 기존 `handleDashboardUsers`(전수스캔) 패턴 참고.
- **user_id 키로 조인**:
  - Firestore `users`: 이름·이메일·provider·가입일·credits
  - Firestore `transactions`: charge 거래 → **결제여부·총결제액·최근결제일**(추정 아닌 사실)
  - BQ events: 채널(첫 page_view utm_source→없으면 referer 정규화: google=검색/naver=네이버/threads·t.co=SNS/카톡 인앱=direct), 퍼널단계(upload·select·generate·download 이벤트 유무), 최근활동(max event_timestamp)
- **KST 변환**: 모든 시각 `Asia/Seoul`(BQ `FORMAT_TIMESTAMP(...,'Asia/Seoul')`, Firestore ISO는 +9h 표시).
- **is_test 제외**: 화이트리스트 상수(작가님 google 계정 `108827115052045057530` 등 — 정확한 목록은 작가님 확인)에 해당하는 user_id는 통계·테이블에서 기본 제외(토글로 표시 가능).
- ⚠️ 현재 유저 수 적어 직접 쿼리 OK. 유저 증가 시 일배치 집계 캐시 필요(설계서 §4, 후속).

### (3) 레이아웃 재배치 — dashboard.html
설계서 §3 와이어프레임 따라:
- **Row1 KPI 스트립**(1줄): 오늘가입·결제·활성·매출·전환율·소진크레딧 (기존 summary-grid 확장, transactions 기반 매출·결제 추가)
- **Row2 압축 추세**(½높이, 좌우 분할): 트래픽 스파크라인 + 채널 누적바 (기존 trafficChart·providerChart 압축)
- **Row3 유저360 테이블**(주역): 유저·채널·가입(KST)·퍼널단계(●●●○○)·결제(✓금액)·잔액·최근활동. 테스트계정 회색+숨김 토글.
- (드릴다운 패널은 2차 — 이번 범위 제외)
