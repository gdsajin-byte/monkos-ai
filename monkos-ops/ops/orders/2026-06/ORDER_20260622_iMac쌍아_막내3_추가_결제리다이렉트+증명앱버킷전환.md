# 추가 지시서: 결제 완료 리다이렉트 + 증명사진 앱 버킷 전환

## 작업 항목

### 1. 결제 완료 후 원래 서비스로 리다이렉트

현재 결제 완료 시 `href="/"` 하드코딩 → 포털 홈으로만 돌아감.
헤드샷에서 결제를 시작했으면 헤드샷으로 돌아가야 한다.

#### 1-a. credits.js — returnUrl 전달

**파일**: `monkos_AI/portal/public/js/credits.js` (104~107행)

```javascript
// 변경 전
window.buyToss = function(amount) {
  window.closeCreditShop();
  window.location.href = '/credits';
};

// 변경 후
window.buyToss = function(amount) {
  window.closeCreditShop();
  var returnUrl = encodeURIComponent(window.location.pathname);
  window.location.href = '/credits?returnUrl=' + returnUrl;
};
```

#### 1-b. render-pricing.js — returnUrl를 토스 successUrl에 포함

**파일**: `monkos_AI/portal/lib/cms/render-pricing.js`

토스 결제 호출 시 `successUrl`에 returnUrl 쿼리 파라미터를 전달해야 함. 
pricing 페이지가 토스 SDK를 호출하는 부분을 찾아서, URL의 `returnUrl` 쿼리를 읽어 `successUrl`에 포함:

```javascript
// pricing 페이지 스크립트 내
var urlParams = new URLSearchParams(window.location.search);
var returnUrl = urlParams.get('returnUrl') || '/';
// successUrl 구성 시:
successUrl: window.location.origin + '/toss-success?returnUrl=' + encodeURIComponent(returnUrl) + '&userId=...'
```

#### 1-c. payments.js — toss-success에서 returnUrl 사용

**파일**: `monkos_AI/portal/lib/payments.js` (386~417행)

`handleTossSuccess` 함수에서 returnUrl 파라미터를 읽어서 "돌아가기" 링크에 반영:

```javascript
// 추가: returnUrl 파싱 (388행 부근)
const returnUrl = esc(params.get('returnUrl')) || '/';

// 409행 — href="/" → href="${returnUrl}"
// 411행 — href="/" → href="${returnUrl}"
// 414행 — href="/" → href="${returnUrl}"
```

**보안**: returnUrl이 `/`로 시작하는 상대 경로만 허용. 절대 URL이면 `/`로 폴백:
```javascript
const rawReturn = params.get('returnUrl') || '/';
const returnUrl = rawReturn.startsWith('/') ? esc(rawReturn) : '/';
```

### 2. 증명사진 앱 버킷 참조 전환

현재 증명사진 앱(`idphoto-kr`)이 구 버킷(`monk-ai-images`)을 바라보고 있어 신 버킷에 생성물이 안 쌓임.

Studio의 `gcs-save.js`가 이미 `CUSTOMER_GCS_BUCKET` 환경변수(기본값 `monk-customer-photos`)를 사용하므로, **Studio가 이미 신 버킷을 가리키고 있다**. 

확인 사항:
- Studio의 Cloud Run 환경변수에 `CUSTOMER_GCS_BUCKET`이 설정되어 있는지 확인
- 미설정이면 기본값 `monk-customer-photos`가 적용됨 → 정상
- 증명사진 앱이 Studio `/api/idgen`을 호출하는 구조라면, Studio 배포만으로 자동 전환
- 증명사진 앱이 자체적으로 GCS에 직접 쓰는 코드가 있다면 해당 코드의 버킷 참조도 변경 필요

→ 증명사진 앱의 GCS 저장 경로를 확인하고, Studio 경유가 아닌 직접 저장이 있으면 보고.

### 3. 구 버킷 보존 원칙

- `monk-ai-images`는 **삭제 금지** — GCS 메타데이터(생성일)가 실제 시계열 정보를 보유
- 신 버킷 복사본은 생성일이 전부 6/21로 덮여있어 시계열 소실
- 추후 스토리지 클래스 전환(Coldline/Archive)으로 비용 절감 예정
- 구 버킷 삭제는 별도 작가님 승인 후에만
