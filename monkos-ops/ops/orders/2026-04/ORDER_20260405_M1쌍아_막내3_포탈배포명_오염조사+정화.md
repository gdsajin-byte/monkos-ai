## Phase 1: 문서 오염 전수 조사

### 1-1. 프로젝트 전체 스캔

아래 패턴으로 프로젝트 전체를 grep하여 **오염 문서 목록**을 작성하라:

```bash
# 잘못된 패턴 (portal만 단독, monkos-portal 제외)
grep -rn "gcloud run deploy portal" --include="*.md" --include="*.sh" --include="*.yaml" --include="*.json" . | grep -v "monkos-portal"

# 추가: deploy 타겟이 잘못될 수 있는 패턴
grep -rn "SERVICE_NAME.*=.*\"portal\"" --include="*.sh" . | grep -v "monkos-portal"
grep -rn "deploy.*--service.*portal" --include="*.md" . | grep -v "monkos-portal"
```

## Phase 3: 유령 서비스 현황 보고

**직접 삭제하지 마라.** 아래 정보만 수집하여 보고:

```bash
# 유령 서비스 상태
gcloud run services describe portal --project=monkos --region=asia-northeast1 --format="yaml(metadata.creationTimestamp, status.latestReadyRevisionName, status.url)"

# 유령 서비스 리비전 목록
gcloud run revisions list --service=portal --project=monkos --region=asia-northeast1 --format="table(metadata.name, metadata.creationTimestamp, spec.containers[0].image)"

# 유령에 도메인 매핑 있는지 (없어야 정상)
gcloud run domain-mappings list --project=monkos --region=asia-northeast1 --format="table(metadata.name, spec.routeName)" 2>/dev/null || echo "도메인 매핑 없음"

# 트래픽이 가고 있는지 (최근 7일 로그)
gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="portal"' --project=monkos --limit=5 --format="table(timestamp, httpRequest.requestUrl)" 2>/dev/null || echo "로그 없음"
```

> 삭제는 작가님 승인 후 별도 지시. 파괴적 명령 금지 (헌법 4조 2항).
