## 2. 용도 = 마스터 갤러리 필터

### 용도 6종

| 용도 ID | 라벨 | 마스터 레퍼런스 성격 |
|---------|------|-------------------|
| `linkedin` | 링크드인 | 바스트샷, 신뢰+친근 비즈니스 |
| `professional` | 전문직종 | 상반신 팔짱, 의사·변호사·강사 |
| `executive` | 기업인 | 상반신~바스트, 대표·임원 |
| `artist` | 아티스트 | 자유 프레이밍, 감성·무드 |
| `beauty` | 뷰티 클로즈업 | 얼굴 80%, 메이크업·스킨 |
| `fitting` | 피팅모델 | 전신~상반신, 의상 중심 |

### 좌측 사이드바 용도 칩 교체

기존 6종(linkedin/sns/corporate/dating/artist/speaker) →
신규 6종(linkedin/professional/executive/artist/beauty/fitting)

### 용도 선택 → 마스터 갤러리 필터 연동

- 좌측에서 용도 칩 선택 → 중앙 갤러리의 "마스터" 카테고리 탭이 자동 활성화
- 마스터 그리드에 해당 용도의 레퍼런스만 필터 표시
- 현재 샘플 이미지는 404이므로, **직접 업로드 영역이 그리드 상단에 표시** (이건 이미 구현된 상태 유지)
- 향후 용도별 에셋이 준비되면 `templates.js`의 SAMPLES 데이터에 `purpose` 필드 추가하여 필터

### templates.js 스키마 변경

```javascript
// 기존 SAMPLES 구조에 purpose 필드 추가
SAMPLES: {
  master: [
    { id: 'master-001', label: '비즈니스 정장', purpose: 'linkedin', thumb: '...' },
    { id: 'master-002', label: '의사 가운', purpose: 'professional', thumb: '...' },
    // ...
  ],
  // fashion, hair, makeup, background는 purpose 무관 (파트별 오버라이드)
}
```

- 아직 에셋이 없으므로 SAMPLES.master는 빈 배열 또는 최소한의 placeholder로 둔다
- 직접 업로드로 대체 가능하니 비어있어도 기능 동작에 문제 없음

### PURPOSE_ASPECT_MAP 업데이트

```javascript
const PURPOSE_ASPECT_MAP = {
  'linkedin':     '1:1',
  'professional': '3:4',
  'executive':    '3:4',
  'artist':       '3:4',
  'beauty':       '1:1',
  'fitting':      '3:4',
};
```

## 3. 프롬프트 정리

마스터 레퍼런스가 있으면 → 텍스트 프리셋(FRAMING/BACKGROUND/LIGHTING/MOOD) 불필요.
마스터 레퍼런스가 없으면 → 용도 ID 기반 기본 프롬프트 생성.

```javascript
function buildProfilePrompt(body) {
  const { customPrompt, referenceImages } = body;
  const hasMaster = referenceImages?.some(r => r.role === 'master');

  if (hasMaster) {
    // 마스터 레퍼런스가 모든 것을 담당 — 텍스트 프리셋 불필요
    return customPrompt || 'Generate based on the master reference style.';
  }

  // 마스터 없으면 (직접 프롬프트만) — 용도 기반 기본 프롬프트
  const purposePrompt = PURPOSE_PROMPT_MAP[body.purpose] || '';
  return `${purposePrompt}\n${customPrompt || ''}`.trim()
    || 'Generate a professional portrait photo.';
}
```

## 4. GCS 버킷 세팅 + 프론트 연결

### 버킷 경로 구성

기존 `monk-ai-images` 버킷에 프로필스 에셋 경로 생성:

```
gs://monk-ai-images/profiles/
├── master/
│   ├── linkedin/
│   ├── professional/
│   ├── executive/
│   ├── artist/
│   ├── beauty/
│   └── fitting/
├── fashion/
├── hair/
├── makeup/
└── background/
```

```bash
# 빈 폴더 마커 생성 (GCS는 폴더 개념 없으므로 placeholder)
for dir in master/linkedin master/professional master/executive master/artist master/beauty master/fitting fashion hair makeup background; do
  echo "" | gsutil cp - gs://monk-ai-images/profiles/${dir}/.keep
done
```

### 공개 읽기 설정

에셋 이미지는 브라우저에서 직접 로드해야 하므로 공개 읽기:

```bash
gsutil iam ch allUsers:objectViewer gs://monk-ai-images
```

> ⚠️ 이미 `monk-ai-images`가 공개 읽기 상태인지 먼저 확인. 이미 설정되어 있으면 스킵.

### 프론트 연동

`templates.js`의 SAMPLES 데이터에서 thumb 경로를 GCS URL로 변경:

```javascript
// 기존: '/samples/master/...'  (로컬 404)
// 변경: 'https://storage.googleapis.com/monk-ai-images/profiles/master/linkedin/...'

const GCS_BASE = 'https://storage.googleapis.com/monk-ai-images/profiles';

// SAMPLES에서 참조
{ id: 'master-001', label: '비즈니스 정장', purpose: 'linkedin',
  thumb: `${GCS_BASE}/master/linkedin/business-suit-01.jpg` },
```

- `GCS_BASE` 상수를 `templates.js` 상단에 선언
- 현재 에셋이 없으므로 SAMPLES 배열은 비워두되, GCS_BASE 상수와 URL 패턴만 확립
- 직접 업로드 기능은 이미 구현되어 있으므로, 작가님이 GCS에 수동으로 이미지 올리면 갤러리에 자동 반영되는 구조

### 검증

```bash
# 버킷 경로 확인
gsutil ls gs://monk-ai-images/profiles/

# 테스트 이미지 1장 업로드
gsutil cp ~/Desktop/프로필스/뷰티클로즈업/스크린샷\ 2026-04-28\ 오후\ 5.41.04.png gs://monk-ai-images/profiles/master/beauty/beauty-closeup-01.png

# 브라우저에서 접근 확인
curl -sI "https://storage.googleapis.com/monk-ai-images/profiles/master/beauty/beauty-closeup-01.png" | head -3
```
