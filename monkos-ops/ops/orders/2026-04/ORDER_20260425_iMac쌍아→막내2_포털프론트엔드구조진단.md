# 지시서 — 포털 프론트엔드 구조·제약 전수 진단

## 0. 배경

철창이(Claude Chat)가 iCloud 디자인 기반으로 포털 메인 카드 그리드 JSX 시안을 만들고 있다.
이 시안을 실제 포털 코드에 반영하기 전에, **현재 포털의 HTML/CSS/JS 구조와 디자인 변경 시 부서지거나 감안해야 하는 모든 제약**을 파악해야 한다.

철창이는 포털 코드를 모른다. 막내2가 코드 실측으로 "이건 되고 이건 안 된다" 가이드를 만들어야 한다.

## 1. 진단 범위

### 1-1. HTML 구조 분석
- `monkos_AI/portal/public/index.html` 전문 읽기
- 섹션 구조 맵 작성 (hero → nav → 본문 → 사이드바 → 푸터, 각 행 범위)
- 각 섹션의 CSS 클래스 의존 관계
- `data-i18n` 속성 전수 목록 — 다국어 키 매핑
- 현재 인라인 스크립트 위치·역할

### 1-2. CSS 구조 분석
- `monkos_AI/portal/public/css/portal.css` 전문 읽기
- 레이아웃 체계: flexbox/grid 사용 현황, 브레이크포인트, 반응형 처리
- 색상 체계: 변수(CSS custom properties) 사용 여부, 하드코딩된 색상 목록
- 타이포그래피: 폰트 패밀리, 사이즈 체계, 외부 폰트 의존
- 현 디자인 토큰 (테마 변경 시 건드려야 할 곳 목록)
- 다크/라이트 모드 분기 여부
- 애니메이션/트랜지션 목록

### 1-3. JS 의존성 분석
- `monkos_AI/portal/public/js/` 전체 파일 목록 + 각 파일 역할·크기
- i18n.js: 다국어 키 전수, 언어 전환 메커니즘, DOM 바인딩 방식
- main.js: 이벤트 리스너, DOM 조작 패턴
- auth.js / credits.js / chat.js: 어떤 DOM 요소에 의존하는지 (클래스명·id)
- 외부 라이브러리 의존: CDN 로드 목록
- GA/gtag 이벤트 바인딩 위치

### 1-4. 제약·위험 목록 도출
위 분석을 기반으로 **디자인 변경 시 부서질 수 있는 것** 목록 작성:
- 이 클래스를 바꾸면 이 JS가 깨진다
- 이 섹션을 옮기면 이 CSS가 깨진다
- 이 id를 제거하면 이 기능이 죽는다
- 이 DOM 구조에 의존하는 외부 스크립트가 있다
