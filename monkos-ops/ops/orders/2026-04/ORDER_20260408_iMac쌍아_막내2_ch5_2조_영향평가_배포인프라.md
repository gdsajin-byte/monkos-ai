# 지시서 — 영향평가 ②: deploy.sh 현황 점검 + 개정안 실행 흐름 검증

> **[2026-04-08 15:10 KST]** iMac/쌍아 → iMac/막내2

## 목적

법률 제5장 2조 개정 청구안의 영향평가.
deploy.sh 현황을 점검하고, 개정안 적용 시 모든 서비스가 정상 배포 가능한지 검증한다.

## 작업

### 1. deploy.sh 전수 조사

프로젝트 내 모든 deploy.sh를 찾아 분석:

```bash
find . -name "deploy.sh" -not -path "*/node_modules/*" -not -path "*/.git/*"
```

각 deploy.sh에 대해:
- 소속 서비스명
- REGION 설정값
- 대응 도메인
- prod/dev 분기 여부

### 2. deploy.sh 미존재 서비스 식별

현재 Cloud Run 서비스 목록 (4/8 정리 후):

```
us-central1: monk-image-engine, monk-n8n, monkos-portal, monkos-portal-dev,
             monkos-idphoto-kr, monkos-idphoto-kr-dev,
             monkos-idphoto-jp, monkos-idphoto-jp-dev,
             monkos-studio, monkos-studio-dev
asia-northeast1: pt
```

각 서비스에 대응 deploy.sh가 있는지 매핑:

| 서비스 | deploy.sh | 경로 |
|--------|-----------|------|
| monkos-portal | ? | ? |
| pt | ? | ? |
| ... | ... | ... |

### 3. pt 서비스 분석

- pt.monkos.ai는 asia-northeast1에 도메인 매핑
- deploy.sh가 없으면 개정안 예외 조항의 실효성 검증
- pt용 deploy.sh 제작이 필요한지, 아니면 예외 조항으로 충분한지 의견 제시

### 4. 개정안 적용 시뮬레이션

개정안이 적용된다고 가정하고:
- 막내가 포털 배포 지시를 받았을 때의 실행 흐름
- deploy.sh가 없는 서비스(pt 등) 배포 시 어떻게 처리되는지
- 막내 방어 의무("gcloud 직접 명령 발견 시 보고") 실행 가능성

### 5. 개정안 적용 의견

- 개정안이 모든 서비스 배포를 커버하는지
- 빈틈(deploy.sh 미존재 서비스)에 대한 보완 필요 여부
- 추가 권고 사항
