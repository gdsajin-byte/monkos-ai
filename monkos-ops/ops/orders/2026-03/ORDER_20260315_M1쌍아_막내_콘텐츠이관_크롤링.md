## Firestore 스키마

기존 `blog_posts` + 홈 SSR에서 추가된 필드:

```js
{
  slug: String,           // 제목 기반 자동 생성 (영문+하이픈)
  title: String,          // 원문 제목
  content: String,        // HTML (마크다운 변환 or 원본 HTML)
  summary: String,        // 앞 200자 자동 추출
  author: String,         // 위 테이블 참조
  lang: 'ko' | 'ja',     // 자동 감지
  published: true,        // 이관 시 바로 공개
  pinned: false,          // 기본 false (작가님이 어드민에서 선택)
  category: String,       // 위 테이블 참조
  tags: Array,            // 본문 키워드 or 카테고리명
  thumbnail: String,      // 대표 이미지 URL (없으면 null)
  source: String,         // 'naver' | 'note'
  sourceUrl: String,      // 원본 URL
  publishedAt: Timestamp, // 원본 게시일
  createdAt: Timestamp,   // 이관 시각
  updatedAt: Timestamp,
}
```

## 구현

### 파일 위치
```
lib/cms/importer/
├── naver.js      ← 네이버 크롤러
├── note.js       ← note.com 크롤러
└── index.js      ← CLI 진입점
```

### 실행
```bash
node lib/cms/importer/index.js --source=note
node lib/cms/importer/index.js --source=naver
node lib/cms/importer/index.js --source=all
```

### 크롤링 전략

**네이버**: RSS 먼저 시도 (`https://rss.blog.naver.com/monkos_ai.xml`)
- RSS 가능 → XML 파싱으로 목록 + 본문
- RSS 불가 → 모바일 URL (`m.blog.naver.com`) HTML 파싱
- 카테고리 필터: 4개 카테고리만 수집

**note.com**: HTML 파싱
- 목록: `https://note.com/monkos_ai` 페이지네이션
- 본문: 각 포스트 URL 접근 → 본문 추출
- 이미지: note.com CDN URL 그대로 사용

### 중복 방지
- `sourceUrl` 기준 Firestore 중복 체크
- 이미 존재 → skip (재실행 안전)

### 언어 감지
- 제목+본문 앞 200자에서 히라가나/가타카나 비율로 판정
- 일본어 문자 10% 이상 → `lang: 'ja'`, 그 외 → `lang: 'ko'`
