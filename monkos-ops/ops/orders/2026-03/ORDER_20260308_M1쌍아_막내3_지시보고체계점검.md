# 지시서: 지시/보고 체계 점검 + 월단위 정리 검토

> **너는 막내3호다. 쌍아가 아니다.**

## 배경

지시서(ORDER) 192개, 보고서(REPORT/COMPLETION) 124개가 축적되었다. 지시 → 실행 → 보고 파이프라인이 빈틈없이 작동하고 있는지, 월단위 정리가 필요한 시점인지 점검한다.

## 관련 법률

- **법률 제1장 2조**: 핵심 흐름 (쌍아→작가님→막내→보고)
- **법률 제1장 3조**: 지시서 작성 규칙 (역할 선언, 엔드라인)
- **법률 제3장 1조**: 보고 파일 수거 절차
- **법률 제4장 3조**: 네이밍 규칙 (ORDER_, COMPLETION_)
- **법률 제4장 4조**: 정본 위치

## 작업 지시

### Phase 1: 지시서(ORDER) 체계 점검

1. `monkos-ops/ops/orders/` 전수 스캔:
   - **네이밍 패턴 분석**: `ORDER_YYYYMMDD_{From}_{To}_{Topic}.md` 준수율
   - **YAML frontmatter 준수율**: type, date, from, to, status 필수 필드
   - **역할 선언 포함 여부** (ch1 3조): "너는 막내N호다" 문구 존재 여부
   - **엔드라인 테이블 포함 여부** (ch1 3조): 마무리/산출물/문서유형/세션로그
   - **status 필드 현황**: 발행/진행중/완료/취소 분포

2. 미처리 지시서 식별:
   - status가 `발행` 또는 `pending`인 채 방치된 ORDER
   - 대응하는 COMPLETION/REPORT가 없는 ORDER

### Phase 2: 보고서(REPORT/COMPLETION) 체계 점검

1. `monkos-ops/ops/reports/` 전수 스캔:
   - **유형별 분포**: REPORT_ / COMPLETION_ / REVIEW_ / DESIGN_ / 기타
   - **YAML frontmatter 준수율**
   - **order 필드 연결**: 어떤 ORDER에 대한 보고인지 추적 가능한 비율

2. 파이프라인 연결성 점검:
   - ORDER → COMPLETION 매칭률 (지시 → 완료보고 연결)
   - 미수거 COMPLETION 파일 존재 여부 (ch3 1조 수거 절차)
   - ORDER 없이 단독 존재하는 REPORT (직접 지시 경로로 추정)

### Phase 3: 월단위 정리 필요성 판단

1. **orders/ 폴더**:
   - 2월 88개 + 3월 104개+ → 월 100개 이상 페이스
   - 연간 1,200개 예상 → flat 구조 한계점
   - 월별 하위 폴더 분리 검토: `orders/2026-02/`, `orders/2026-03/`

2. **reports/ 폴더**:
   - 2월 44개 + 3월 68개+ → 월 60개 이상 페이스
   - 동일한 월별 분리 검토

3. **정리 방안 비교**:

| 방안 | 설명 | 장점 | 단점 |
|------|------|------|------|
| A: 현행 유지 | flat 구조 | 단순 | 연말 1000+ 파일 |
| B: 월별 폴더 | YYYY-MM/ 하위 | 탐색 용이 | ch4 4조 경로 개정 필요 |
| C: 완료 아카이브 | completed/ 이관 | active만 잔류 | 이관 기준·주기 정의 필요 |
| D: 상태별 분리 | active/ + archived/ | 명확 | 파일 이동 자동화 필요 |

4. **아카이브 이관 기준** 검토:
   - 완료된 ORDER/REPORT는 언제 아카이브로 이관할 것인가
   - `docs/monkos/tasks/YYYY-MM/`(ch4 4조 지시서 정본)과의 관계 정리
   - 이관 시 기존 참조(order_ref 등) 깨지지 않는 방안
