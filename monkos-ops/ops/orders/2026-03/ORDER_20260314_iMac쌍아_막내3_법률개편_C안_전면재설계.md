# 지시서: 법률 개편 C안 — 전면 재설계

> 헌법과 법률의 경계를 재정의하고, "원칙은 헌법, 실무는 법률"로 완전 분리하는 최대 강도 개편안을 설계한다.

## 배경

현행 체계의 근본 문제:
1. **헌법이 "어떻게"까지 규정** — 타임스탬프 형식, 보고 이모지, API 키 금지 등 실무 상세가 헌법에 있음
2. **법률이 헌법을 복사** — 참조가 아니라 복사이므로 개정 시 연쇄 불일치
3. **법률이 현실을 못 담음** — MEMORY에만 있는 규칙 10건이 법률보다 실질 구속력 강함
4. **에이전트가 법률을 안 읽는 구조** — 어젠다 #12-3 "읽히지 않는 법" 문제

## C안의 원칙

1. **헌법 = "왜"만** — 원칙·가치·철학. 형식·절차·상세는 법률로 위임
2. **법률 = "어떻게"만** — 실무 규칙의 유일한 정본. 중복 0
3. **MEMORY 규칙의 법률화** — 실질 구속력 있는 것은 법률로 승격
4. **"읽히는 법"** — Claude Code rules/ 활용, CLAUDE.md 경량화 등 구조적 해법 포함

## 산출물

### 1. 헌법 재설계

현행 13조를 "원칙만" 남기고 축소:

| 현행 | 내용 | C안 처리 |
|------|------|---------|
| 1조 타임스탬프 | 형식(`date` 명령, KST 형식)까지 규정 | 원칙만 유지("정확한 시각 기록"), 형식은 법률 위임 |
| 2조 보고의무 | 이모지 형식까지 규정 | 원칙만 유지("완료 보고 의무"), 형식은 법률 위임 |
| ... | ... | ... |

13조 전부 분석. 목표: 헌법 13조 → **8조 이하**

### 2. 법률 재설계

통합 + 재배치 + MEMORY 편입을 포함한 완전한 신규 구조:

```
제1장 에이전트 체계 — 정의, 역할, 행동강령, 워크플로우
제2장 개발 표준 — 기술스택, 코딩, 커밋, 배포 (파이프라인 일원화)
제3장 문서 관리 — 폴더구조, 네이밍, YAML, 세션로그, 데이터운영
제4장 브랜드·대외 — 브랜딩, 마케팅, 윤리
```

위는 예시. 조사 결과에 따라 자유롭게 재설계 가능. **최적 구조를 제안하라.**

### 3. 조항 이동 전수 매핑

현행 헌법 13조 + 법률 38조 = **51개 조항** 전부가 신규 체계에서 어디로 가는지:

| 현행 위치 | 조항 요약 | → 신규 위치 | 처리 |
|----------|----------|------------|------|
| 헌법 1조 | 타임스탬프 | 헌법 N조(원칙) + 법률 M장 K조(형식) | 분리 |
