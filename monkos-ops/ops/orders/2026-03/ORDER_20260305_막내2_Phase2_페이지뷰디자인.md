# Phase 2: 랜딩+충전 페이지뷰 디자인

## 맥락

Phase 1(과금 엔진 교체)이 완료되었다. 현재 index.html(랜딩)과 charge.html(충전)은 기능적으로 동작하지만, 디자인 마무리와 ChargeModule 모달이 필요하다.

**목표: Phase 2 완료 = e2e 완성** — 랜딩 → 충전 → 결제 → 촬영 → 결과 → 다운로드의 전체 흐름이 완결되어야 한다.

---

## 현재 상태 (스크린샷 기준)

### 랜딩 (index.html) — 현행
- 헤더: MONKOS AI 증명사진 + Cr 뱃지
- 히어로: "20년 사진작가의 촬영코치와 리터칭" + 보라 CTA "촬영 시작하기"
- 히어로 영역 상단에 빈 공간 — `hero.webp`(725KB)가 이미 `/images/` 에 있으나 현재 표시 상태 확인 필요
- 가격 카드: 1장 80c = ₩9,900 + 보너스/절약 표시
- "상세 가격보기 →" 버튼 → charge.html 이동
- 하단 배지: 여권 발급 보장(100c 보상) + 첫 로그인 10c 증정

### 충전 (charge.html) — 현행
- 가격 산수 바: 1장 = 리터칭 10c + 다운로드 70c = 80c
- 4단 와이드 카드: 70c(₩9,900) / 100c(₩12,900) / 300c(₩34,900) / 500c(₩49,900 ★BEST)
- 소액 스테퍼: 10c 단위, ₩1,450
- 결제 버튼 + 돌아가기 + 사업자 푸터

---

## 작업 항목

### 1. 랜딩 (index.html) 디자인 마무리

- **히어로 이미지**: `images/hero.webp`가 정상 표시되는지 확인. 빈 공간이면 배경 이미지로 적용
- **히어로 섹션 레이아웃**: 이미지 + 카피 + CTA의 시각적 밸런스 점검
- **가격 카드**: 현행 유지 (이미 완성도 높음)
- **"상세 가격보기 →"**: charge.html로 정상 연결 확인
- **하단 배지**: 현행 유지
- **사업자 푸터**: 있으면 유지, 없으면 추가 (독립 페이지이므로 필요)

### 2. 충전 (charge.html) 디자인 점검

- 현행 카드 레이아웃이 이미 완성도 높음. **기능적 점검 위주**:
  - 카드 선택 → 결제 버튼 연동 정상 동작
  - 스테퍼 ± 동작 + 가격 연동
  - "돌아가기" → 이전 페이지 복귀 정상
  - 사업자 푸터 유지 (독립 페이지)

### 3. ChargeModule 모달 신설 (핵심 신규 작업)

**용도**: 촬영실/결과 페이지에서 잔고 부족 시, 페이지 이동 없이 충전하는 모달

**설계 원칙**:
- charge.html의 CHARGE_OPTIONS과 **동일한 상품 데이터** 사용 (config.js 기준)
- charge.html의 카드 렌더링 로직을 **재사용 가능한 함수**로 추출
- 모달은 오버레이(backdrop) + 카드 목록 + 결제 버튼 + 닫기
- 결제 완료 후 모달 닫힘 + 크레딧 잔액 갱신 + **원래 페이지 맥락 보존**
- `shared.js`에 `showChargeModal()` 함수로 노출

**호출 지점**:
- `result.js`: 다운로드 시 잔고 부족 → `showChargeModal()`
- 향후 다른 페이지에서도 호출 가능한 범용 구조

### 4. E2E 흐름 검증

Phase 2 완료 후 다음 전체 흐름을 검증하라:

| 흐름 | 경로 |
|------|------|
| **신규 유저** | 랜딩 → "촬영 시작하기" → 로그인 → 촬영실 |
| **가격 확인** | 랜딩 → "상세 가격보기" → charge.html → 결제 → 크레딧 충전 |
| **잔고 부족** | 결과 → 다운로드 → 잔고 부족 → ChargeModule 모달 → 충전 → 다운로드 |
| **외부 유입** | charge.html 직접 접근 → 충전 → 돌아가기 |
