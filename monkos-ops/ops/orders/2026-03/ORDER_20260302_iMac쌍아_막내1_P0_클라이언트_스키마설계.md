## 3. 분석 및 설계 항목

### 3-A. 현행 sessionStorage 키 완전 추적

각 키에 대해 **쓰기→읽기 체인**을 코드 레벨에서 추적하라:

```
| 키 | 쓰기 (파일:함수:라인) | 읽기 (파일:함수:라인) | 값 형식 | 비고 |
|----|---------------------|---------------------|---------|------|
```

**중요**: 막내3 보고서의 15키 목록을 기반으로 하되, 누락된 키가 없는지 코드에서 직접 재확인하라.

### 3-B. v5 상태변수 → sessionStorage 키 매핑 초안

철창이 기획안 §3-3의 상태변수를 기반으로, **실제 sessionStorage에 저장할 키 스키마**를 설계하라:

```javascript
// v5 sessionStorage 스키마 초안
{
  // [1p] 규격
  "monkos_format": "passport" | "id",

  // [2p] 성별+연령
  "monkos_gender": "f" | "m",
  "monkos_age": "baby" | "child" | "teen" | "adult",

  // [3p] 스타일
  "monkos_clothing": "default" | "change" | "casual" | "suit",
  "monkos_clothingColor": null | "skyblue" | "pink" | ...,
  // ... 이하 설계
}
```

설계 시 고려할 점:
- **네이밍 컨벤션**: `monkos_` 접두사 유지? 또는 v5용 새 접두사?
- **직렬화**: JSON.stringify로 한 키에 묶을지, 개별 키로 분리할지
- **UI 전용 키 분리**: `styleEdit`(아코디언 상태)는 sessionStorage 불필요 — 어떤 키가 저장 대상이고 어떤 키가 런타임 전용인지 구분

### 3-C. 데이터 흐름도 (노드별)

v5에서의 데이터 흐름을 노드 단위로 그려라:

```
[prep.js] 1p→2p→3p→4p 선택값 저장
  → sessionStorage에 {키: 값} 쓰기
  → [camera.js] 촬영 시 sessionStorage에서 읽기
  → 코칭 WS에 전달하는 필드 목록
  → [result.js] /api/idgen에 전달하는 필드 목록
  → 생성 완료 후 sessionStorage에 추가 저장하는 필드
  → [thankyou.js] 엔딩 페이지에서 읽는 필드
```

**각 노드에서 "무엇을 읽고, 무엇을 쓰는가"를 정확히 명시하라.**

### 3-D. 이미지 키 처리 방안

현행 이미지 관련 키(monkos_original, monkos_generated, monkos_cropped):
- v5에서 유지/변경 여부
- base64 저장의 용량 이슈 (sessionStorage 5MB 제한)
- 대안이 있다면 제시

### 3-E. 키 충돌 방지 전략

v5 전환 중 기존 유저가 구버전 키를 갖고 있을 때:
- 구키와 신키가 동시에 존재하면 어떤 일이 일어나는가
- 방지 방안 (예: 세션 시작 시 구키 정리, 버전 태그 등)
