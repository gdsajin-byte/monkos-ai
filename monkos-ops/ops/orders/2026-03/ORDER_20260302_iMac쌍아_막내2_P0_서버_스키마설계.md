## 3. 분석 및 설계 항목

### 3-A. 현행 /api/idgen 요청 스키마 정밀 파악

서버 코드를 직접 읽고, /api/idgen이 **실제로 받는 필드**를 전수 파악하라:

```
| 필드명 | 타입 | 필수 여부 | 출처 (클라이언트 어디서 보내나) | 서버에서 어떻게 사용하나 |
|--------|------|----------|-------------------------------|----------------------|
```

### 3-B. 현행 프롬프트 빌딩 로직 파악

서버에서 클라이언트 필드를 받아 AI 모델에 전달하는 프롬프트를 어떻게 조립하는지:

- 프롬프트 템플릿이 있는 파일과 위치
- 필드별 프롬프트 매핑 (예: gender="female" → "a Korean woman")
- 고정 프롬프트 부분 (카메라/조명 세팅 등)
- 프롬프트 조립 순서

**이것이 이번 지시서의 가장 중요한 산출물이다.** 현행 프롬프트 빌딩 로직을 정확히 파악해야 v5 프롬프트 빌더를 설계할 수 있다.

### 3-C. v5 /api/idgen 요청 스키마 초안

철창이 기획안의 v5 상태변수를 기반으로, 서버가 받아야 할 새 스키마를 설계하라:

```javascript
// v5 /api/idgen 요청 스키마 초안
{
  // 퍼널 선택값
  "format": "passport" | "id",
  "gender": "f" | "m",
  "age": "baby" | "child" | "teen" | "adult",
  "clothing": "default" | "change" | "casual" | "suit",
  "clothingColor": null | "skyblue" | ...,
  "suitColor": "navy" | ...,
  "shirtColor": "white" | ...,
  "tieColor": "notie" | ...,
  "tiePattern": "solid" | "stripe",
  "hair": "default" | "tidy" | "updo",
  "bgColor": "white" | "gray" | "blue" | "beige",

  // 이미지
  "image": "base64...",

  // 사용자
  "userId": "..."
}
```

### 3-D. v5 프롬프트 빌더 설계 초안

기획안 §3-3의 프롬프트 스택을 기반으로, 서버에서 실제 AI 모델에 전달할 프롬프트 조립 로직을 설계하라:

```
[1] 규격 레이어: format → "passport photo, 35×45mm" | "ID photo, 3×4cm"
[2] 인물 레이어: gender + age → "Korean adult woman" | "Korean baby boy" | ...
[3] 의상 레이어: clothing + clothingColor/suitColor/shirtColor/tieColor/tiePattern
    → 조건부 매핑 테이블
[4] 헤어 레이어: hair → "" | "tidy neat hair" | "updo hairstyle"
[5] 배경 레이어: bgColor → "white background" | "gray background" | ...
[6] 고정 프롬프트: 카메라/조명/공간 (현행 유지 또는 수정)
```

**각 레이어에서 v5 값→영문 프롬프트 매핑 테이블을 작성하라.**
특히 의상 레이어는 연령별 분기가 필요:
- 영유아/어린이 + clothing="change" + clothingColor → ?
- 중고생/성인 + clothing="casual" + clothingColor → ?
- 중고생/성인 + clothing="suit" + suitColor + shirtColor + tieColor + tiePattern → ?

### 3-E. 하위호환 방안

전환 기간 중 구버전 클라이언트가 구 스키마로 요청할 수 있다:
- 서버에서 구/신 스키마를 어떻게 구분할지
- 구 스키마 요청을 신 로직으로 변환할 수 있는지
- 또는 엔드포인트를 분리할지 (/api/idgen vs /api/idgen/v5)
