# 지시서 — 홈 SSR 전환 + /blog 라이트 테마 교체

**[2026-03-15 06:01 KST] M1/쌍아 → 막내**

---

## 배경

v4가 프로덕션(monkos.ai) 배포 상태. 홈의 블로그/매거진/뉴스 카드가 하드코딩 목업이라 클릭 불가 + 데이터 불일치. 인트로 문구 등도 어드민에서 수정 가능해야 함. 홈을 정적 HTML → SSR로 전환하여 Firestore 데이터를 실시간 반영한다.

동시에 /blog 페이지의 다크 테마를 라이트로 교체하여 홈과의 디자인 일관성을 확보한다.

## Task 1 — 홈 SSR 전환

### 1-1. `lib/cms/home.js` 신규 생성

기존 render.js의 fragment 패턴과 동일한 구조로 작성.

```js
// homeFragment() — Firestore 조회 + HTML 생성
export async function homeFragment() {
  // 1. site_config/main 문서 조회 (인트로 문구 등)
  // 2. blog_posts: published=true, orderBy createdAt desc, limit 4 → 블로그 카드
  // 3. blog_posts: pinned=true, published=true, limit 4 → 매거진 카드
  // 4. blog_posts: category='news', published=true, limit 2 → 뉴스 카드
  // 5. blog_posts 전체에서 tags 집계 → 태그 사이드바
  //
  // 반환: 완성된 HTML (index.html 구조 그대로)
}
```

**데이터 조회 상세:**

| 영역 | Firestore 쿼리 | 폴백 (데이터 없을 때) |
|------|---------------|---------------------|
| 인트로 | `site_config/main` → `intro` 필드 | 현재 하드코딩 문구 그대로 |
| 블로그 카드 | `blog_posts` published + 최신 4건 | "아직 포스트가 없습니다" |
| 매거진 카드 | `blog_posts` pinned=true, 최신 4건 | 블로그 최신 4건으로 대체 |
| 뉴스 카드 | `blog_posts` category='news', 최신 2건 | 섹션 숨김 |
| 태그 | blog_posts 전체 tags 집계 | 빈 태그 영역 |

**카드 HTML 생성 규칙:**

블로그 카드 (`.bi`):
```html
<!-- 현재 (하드코딩 div) -->
<div class="bi"><div class="bi-thumb">📸</div>...</div>

<!-- 변경 (링크 + Firestore 데이터) -->
<a href="/blog/{slug}" class="bi">
  <div class="bi-thumb" style="background-image:url('{thumbnail}')">
    {thumbnail 없으면 카테고리별 이모지}
  </div>
  <div class="bi-info">
    <h3>{title}</h3>
    <p>{summary}</p>
    <div class="meta">
      <span class="lt">{lang.toUpperCase()}</span>
      {author} · {날짜}
    </div>
  </div>
</a>
```

매거진 카드 (`.mag-card`):
```html
<!-- 변경 -->
<a href="/blog/{slug}" class="mag-card">
  <div class="mag-img" style="background:linear-gradient(...)">
    <span class="icon">{카테고리 이모지}</span>
    {태그 있으면 <span class="tag tip">{tags[0]}</span>}
  </div>
  <div class="mag-body">
    <h4>{title}</h4>
    <p>{summary 앞 30자}</p>
    <div class="meta">{author} · {상대 시간}</div>
  </div>
</a>
```

뉴스 카드: 동일 패턴, `NEWS` 배지 유지.

**카테고리별 이모지 매핑:**
```js
const EMOJI = {
  '증명사진': '📸',
  '여권·비자': '🛂',
  '취업·이력서': '💼',
  '헤어·메이크업': '💆',
  'news': '📰',
  'default': '💡'
};
```

### 1-2. Firestore 스키마 변경

**신규 컬렉션 `site_config`** — 싱글톤 문서 `main`:
```js
{
  intro: "MONKOS는 20년 경력 사진작가가 만든 AI 증명사진 플랫폼입니다. 여권사진, 이력서사진, 비자사진을 셀카 한 장으로 완성합니다. 사진관 촬영 노하우를 학습한 AI가 배경 정리, 조명 보정, 피부 보정, 의상 정돈까지 처리하며 발급 보장을 제공합니다.",
  updatedAt: Timestamp
}
```

**`blog_posts` 필드 추가** (기존 문서에 영향 없음):
```js
{
  ...기존,
  pinned: false,        // boolean, 매거진 영역 노출
  category: '',         // string, 카테고리 분류
}
```

→ `blog.js`의 create/update 로직에 `pinned`, `category` 필드 추가.

### 1-3. `server.js` 라우트 변경

현재 `/` 요청은 정적 파일 핸들러에서 `public/index.html`을 서빙함.
이를 SSR 라우트로 전환:

```js
// 기존 정적 핸들러 이전에 추가 (CMS 라우트 블록에)
if (pathname === '/' || pathname === '/index.html') {
  return renderHome(req, res);
}
```

`renderHome` = `homeFragment()` → `res.end(html)`

**주의**: `public/index.html`은 삭제하지 않음. SSR 렌더링의 HTML 구조 참조 원본으로 유지. 단, 라우트 우선순위로 SSR이 먼저 응답.

### 1-4. 하드코딩 유지 영역 (수정 금지)

- 헤더 3컬럼 구조 — 레이아웃
- 푸터 — 법적 정보

## Task 3 — 어드민 사이트 설정 탭

### 목표

`/admin/` 대시보드에 **설정** 탭 추가. `site_config/main` 문서를 편집하는 UI.

### 편집 가능 필드

- **인트로 문구** — textarea, HTML 허용 (`<strong>` 정도)

### API

```
GET  /api/admin/settings        → site_config/main 조회
PUT  /api/admin/settings        → site_config/main 갱신
```

### 어드민 블로그 편집에 필드 추가

기존 블로그 글 작성/수정 UI에:
- **pinned** 체크박스 (매거진 영역 노출)
- **category** 드롭다운 (증명사진 / 여권·비자 / 취업·이력서 / 헤어·메이크업 / news)
