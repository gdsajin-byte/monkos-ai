# 지시서: KR 토스 SDK → 위젯 방식 전환 사전 리서치

**[2026-03-09 20:38 KST] M1/쌍아 → 막내4**

## 배경

KR 토스페이먼츠와의 계약 절차가 마무리되어 기존 SDK 방식에서 **위젯(Widget) 방식**으로
전환이 예정됨. 실제 전환 작업 전에 현재 코드 파악 + 전환 영향 범위 리서치가 필요.

## 임무 A: 현재 KR 토스 SDK 방식 전체 파악

### 대상 파일
- `monkos_AI/idphoto-kr/public/shared.js`
- `monkos_AI/idphoto-kr/public/modules/charge.js`
- `monkos_AI/idphoto-kr/public/config.js`
- `monkos_AI/idphoto-kr/public/index.html`
- `monkos_AI/portal/lib/payments.js`

### 확인 항목
- [ ] 현재 Toss 라이브러리 로드 방식 (CDN URL, 버전)
- [ ] `TossPayments(clientKey)` 초기화 코드 위치 (파일명 + 라인)
- [ ] `requestPayment()` 호출 파라미터 전체 목록
- [ ] redirect URL 구조 (`successUrl`, `failUrl`)
- [ ] `initFromTossResult()` 전체 로직
- [ ] Portal `toss/confirm` 엔드포인트 파라미터

## 임무 B: 토스 위젯 방식 비교 분석

**현재 SDK 방식:**
```js
const tossPayments = TossPayments(clientKey);
tossPayments.requestPayment('카드', { amount, orderId, ... });
```

**위젯 방식 (예상):**
```js
const paymentWidget = PaymentWidget(clientKey, customerKey);
paymentWidget.renderPaymentMethods('#payment-method', { value: amount });
paymentWidget.renderAgreement('#agreement');
await paymentWidget.requestPayment({ orderId, orderName, ... });
```

### 리서치 항목
- [ ] 위젯 방식에서 `customerKey` 필요 — 현재 KR 앱 사용자 식별자(uid) 확인
- [ ] 위젯 DOM 렌더링 — 현재 charge UI에서 마운트 포인트 적합 위치
- [ ] 위젯 CDN URL 확인 (토스 공식 문서 참조, 웹 검색 허용)
- [ ] SDK → 위젯 전환 시 Portal `toss/confirm` 엔드포인트 변경 필요한지

## 임무 C: 전환 영향 범위 분석
