## 배경

헌법 5축 재편 전에 다른 대규모 프로젝트들이 Claude Code의 컨텍스트 레이어(CLAUDE.md, MEMORY.md 등)를 어떻게 운용하는지 파악해야 한다. 우리 체계가 Anthropic 설계 의도와 어긋나는 부분이 있는지, 더 효율적인 패턴이 있는지 조사한다.

## 조사 범위

1. **CLAUDE.md 운용 패턴**
   - 대규모 레포에서 CLAUDE.md에 담는 내용의 범위와 길이
   - 모노레포 / 멀티레포에서의 계층 분리 사례
   - 안티패턴 — CLAUDE.md에 넣으면 안 되는 것 (토큰 낭비, 컴팩팅 대상 등)

2. **MEMORY.md 운용 패턴**
   - 200줄 캡 내에서의 효율적 인덱싱 전략
   - memory type별 실전 활용도 — 어떤 type이 실제로 유용한가
   - memory vs CLAUDE.md 역할 분담 — 커뮤니티에서 관찰되는 분리 기준

3. **멀티에이전트 / 멀티디바이스 패턴**
   - 여러 에이전트가 동일 레포를 사용할 때의 컨텍스트 분리 전략
   - 디바이스별 로컬 설정 vs 공유 설정 분리 사례

4. **컨텍스트 크기 최적화**
   - CLAUDE.md가 너무 클 때의 성능 영향 (응답 품질, 토큰 소모)
   - 권장 크기 / 구조에 대한 커뮤니티 합의

## 조사 방법

- GitHub 공개 레포의 CLAUDE.md 사례 (anthropics 공식 + 유명 오픈소스)
- Reddit, Hacker News, X(Twitter) 등 커뮤니티 논의
