## Phase 1: 크롤링 + 변주

### 크롤링
- `naver.js`의 `fetchMobileContent()` 재활용
- 각 sourceUrl에서 postId 추출 → 모바일 버전 풀 크롤링
- HTML → 마크다운 변환 (이미지 태그 보존)

### 변주 (Gemini 2.0 Flash)
```
당신은 전문 에디터입니다. 아래 블로그 글을 리라이팅하세요.

규칙:
- 원본의 정보, 구조, 논리 흐름을 100% 보존
- 문장 구조와 표현을 자연스럽게 재구성 (동의어 치환, 어순 변경, 문장 분할/결합)
- 전문 용어, 브랜드명(MONKOS, Monkos.ai), 고유명사는 그대로 유지
- 원본 문체(톤앤매너) 유지
- 이미지 마크다운 ![alt](URL)은 절대 수정하지 말 것
- 마크다운 형식으로 출력

JSON 형식으로 응답:
{"title": "리라이팅된 제목", "content": "리라이팅된 본문(마크다운)", "summary": "요약(160자 이내)"}
```

- `maxOutputTokens: 16384` (translate.js와 동일)
- `responseMimeType: 'application/json'`

## Phase 2: 이미지 GCS 마이그레이션

### GCS 업로드 패턴 (`upload.js` 준용)
```javascript
import { Storage } from '@google-cloud/storage';
import { GCS_BUCKET } from '../lib/shared/config.js';

const storage = new Storage();
const bucket = storage.bucket(GCS_BUCKET);
```

### 로직
1. 크롤링된 풀 본문 + 기존 Firestore content에서 `pstatic.net` URL 전체 수집
2. **Referer 헤더 없이** 다운로드
3. GCS `blog/{slug}/{filename}` 경로에 업로드 (public-read)
4. content + thumbnail의 pstatic URL → GCS URL 교체
5. 동일 URL은 1회만 다운로드 (캐시 맵 사용)
