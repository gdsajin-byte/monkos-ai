# 지시서: GCS 현황 감사 + 이미지 호스팅 전략 방안

**[2026-03-08 11:45 KST] iMac/쌍아 → 막내1**

## 배경

이미지 에셋이 GCS 버킷, 로컬 images/, Unsplash 외부 CDN 등에 산발 배치되어 있다.
앞으로 모델/배경/광고/갤러리 등 에셋이 대량 축적될 예정이므로
**호스팅 전략을 확정**해야 한다. 그 전제로 GCS 현황 감사가 선행되어야 한다.

## Phase A: GCS 버킷 전수 감사

### 대상 버킷
1. `gs://monk-project/` (주 버킷, asia-northeast3)
2. `gs://monk-ai-images/` (광고 manifest + 이미지)
3. `gs://monk-project-soul/` (세션 로그, 폐지 예정)
4. `gs://monk_session_data/` (Gemini 대화, 폐지 예정)

### 조사 항목
각 버킷/경로별:
- **실사용 여부**: 현재 코드에서 참조하는 경로인지 (grep으로 URL 패턴 검색)
- **용량**: `gcloud storage du` 또는 콘솔 확인
- **최종 수정일**: 마지막 쓰기 시점
- **비용 영향**: 스토리지 + 네트워크 egress 추정
- **접근 권한**: 공개(allUsers) vs 인증 필요

### 분류 기준

| 분류 | 정의 | 조치 |
|------|------|------|
| **필수 유지** | 코드가 직접 참조, 서비스 운영에 필수 | 유지 + CDN 검토 |
| **통합 대상** | 데이터는 필요하나 현 위치가 부적절 | monk-project로 이관 |
| **폐지 대상** | 미참조, 대체됨 | 백업 후 삭제 |
| **미결정** | 향후 용도 불명확 | 보고서에 명시 |

## Phase B: 호스팅 전략 방안 비교

아래 4가지 방안을 **장단점 + 비용 + 복잡도 + 헌법 적합성** 관점에서 비교 분석:

### 방안 1: GCS 유지 + Cloud CDN 적용
- 현행 GCS 직접 서빙에 CDN 레이어 추가

### 방안 2: 로컬 images/ 폴더 (각 프로젝트 자체 관리)
- MONK_kr → CF Pages CDN 자동 적용
- monkos_AI → Cloud Run 정적 서빙 (현재 hero.webp가 이 패턴)
- Git 추적, 배포 시 자동 포함

### 방안 3: Cloudflare R2
- GCS_BUCKET_STRUCTURE.md에 R2 동기화 언급 있음 (assets/mina/runway/)
- S3 호환, egress 무료

### 방안 4: 혼합 (정적=로컬, 동적=GCS)
- 변경 빈도 낮은 갤러리/아이콘 → 로컬 images/
- 변경 빈도 높은 광고 로테이션 → GCS + manifest
