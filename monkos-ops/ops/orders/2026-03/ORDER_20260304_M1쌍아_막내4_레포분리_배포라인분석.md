# 지시서: 레포 분리 시나리오 — 배포라인 분석

> **[2026-03-04 05:18 KST] M1/쌍아 → M1/막내4**

---

## 배경

현재 `monk_project/` 모노레포에 monk.kr(CF Pages 정적)과 monkos.ai(Cloud Run 엔진)이 공존.
에이전트가 전체 트리를 인덱싱하면서 레거시(MONK_kr/)를 현행(monkos_AI/)으로 오인식하는 사고가 반복 발생.

**작가님 방침**: 완전 클론 상태로 두 레포를 세팅 → 배포라인만 정돈 → 한쪽씩 덜어내기.

---

## 조사 범위

### A. 배포라인 정밀 분류

현재 모노레포의 모든 배포 대상을 아래 분류로 정밀 매핑:

#### monk.kr 레포 (CF Pages 정적)
- `MONK_kr/` — 정적 HTML/CSS/JS
- `functions/api/` — CF Pages Functions (서버리스)
- 루트 `wrangler.toml`, `package.json` (CF Pages 빌드 설정)

#### monkos.ai 레포 (Cloud Run 엔진)
- `monkos_AI/portal/` — 포털 (인증/크레딧/챗봇)
- `monkos_AI/idphoto-kr/` — 증명사진 한국
- `monkos_AI/idphoto-jp/` — 증명사진 일본
- `apps/monk_imagen4/backend/` — Image Engine (Cloud Run)

#### 소속 불명확 (분류 필요)
- `apps/monk_imagen4/` (프론트: CF Pages, 백엔드: Cloud Run)
- `apps/MonkosChat/` (Firebase)
- `apps/monk-cam/`, `apps/photo-coach/` (로컬 dev)
- 레거시/아카이브: `apps/imagen3/`, `apps/photolab-monkkr-*` 등

**조사 항목 (디렉토리별)**:
1. 배포 대상 (CF Pages / Cloud Run / Firebase / 로컬 / 미배포)
2. 배포 방법 (deploy.sh / wrangler / firebase / git push)
3. 도메인 매핑
4. 환경변수/시크릿 의존
5. **다른 쪽 배포라인 코드를 참조하는가** (교차참조)

### B. 교차참조 전수조사 (핵심)

두 레포로 분리했을 때 **끊어지는 연결**을 전수 파악:

#### B-1. 코드 레벨 교차참조
```
monk.kr 쪽 코드가 monkos.ai 쪽을 참조하는 경우:
  예: functions/api/*.js → monkos_AI/ 경로를 import하는가?
  예: MONK_kr/ 프론트에서 idphoto-kr.monkos.ai API를 호출하는가?

monkos.ai 쪽 코드가 monk.kr 쪽을 참조하는 경우:
  예: monkos_AI/ 서버에서 MONK_kr/ 정적 파일을 참조하는가?
  예: Cloud Run에서 monk.kr 도메인으로 리다이렉트하는가?
```

**조사 방법**:
1. `MONK_kr/` 내에서 `monkos_AI`, `idphoto-kr`, `idphoto-jp`, `portal` 문자열 grep
2. `monkos_AI/` 내에서 `MONK_kr`, `monk.kr`, `ai_lab`, `photolab/engine` 문자열 grep
3. `functions/` 내에서 양쪽 참조 grep
4. URL 기반 교차: `monk.kr` 도메인 ↔ `monkos.ai` 도메인 상호 참조

#### B-2. 공유 리소스

#### B-3. 도메인 간 교차

```

```

전수 grep으로 모든 URL 교차점 추출.

### C. 배포라인 정돈 시나리오

작가님 방침에 따른 분리 절차 시나리오를 설계:

```
Phase 1: 완전 클론
  - monk_project → monk_kr_project (전체 복사)
  - monk_project → monkos_ai_project (전체 복사)
  - 양쪽 모두 전체 히스토리 보존

Phase 2: 배포라인 정돈
  - monk_kr: wrangler.toml + MONK_kr/ + functions/ 배포 활성
  - monk_kr: monkos_AI/ 배포 비활성화 (코드는 잔존, .gitignore 또는 docs/로)
  - monkos_ai: deploy.sh 배포 활성
  - monkos_ai: MONK_kr/ + functions/ 배포 비활성화

Phase 3: 덜어내기 (한쪽씩)
  - monk_kr에서 monkos_AI/ 제거
  - monkos_ai에서 MONK_kr/ + functions/ 제거
```

**조사 항목**:
1. Phase 2에서 비활성화만으로 양쪽 배포가 독립 동작하는지
2. Phase 3 덜어내기 시 끊어지는 교차참조 목록 (B에서 파악한 것 기반)
3. 각 Phase의 롤백 방법
4. `.gitignore`로 비활성화 vs 물리 삭제 vs `_archive/`로 이동 장단점

### D. CLAUDE.md + 거버넌스 클론 방안

분리 후 양쪽 레포에 필요한 거버넌스 문서:

| 문서 | 현재 위치 | monk_kr 레포 | monkos_ai 레포 | 비고 |
|------|----------|-------------|---------------|------|
| CLAUDE.md (헌법) | 루트 | 필요 | 필요 | 공통 → 양쪽 유지 or 상위 참조? |
| governance/ | 루트 | ? | ? | 조사 필요 |
| docs/ | 루트 | ? | ? | 어느 쪽 소속? 양쪽? |
| monkos-ops/ | 루트 | ? | ? | 세션로그/지시서/보고서 |
| MEMORY.md | ~/.claude/ | 디바이스 종속 | 디바이스 종속 | 레포 무관 |

**조사 항목**:
1. governance/ 내 문서 중 양쪽 모두에 필요한 것 vs 한쪽만 필요한 것
2. docs/ 하위 디렉토리별 소속 분류 (인프라/서비스/비즈니스/아카이브)
3. monkos-ops/의 지시서·보고서가 양쪽 레포 작업을 혼합 참조하는 경우
4. 세션 로그의 소속 (에이전트가 양쪽 레포를 번갈아 작업하는 경우)
5. CLAUDE.md를 양쪽에 동일 복사 vs 공통 부분 추출 + 레포별 부록

### E. 에이전트 컨텍스트 격리 효과 분석

분리 후 각 레포에서 에이전트가 인덱싱하는 범위:

```
[현재 — 모노레포]
에이전트 컨텍스트 = MONK_kr/ + monkos_AI/ + apps/ + functions/ + docs/ + ...
→ 레거시와 현행이 혼재, 오인식 발생

[분리 후 — monkos_ai 레포]
에이전트 컨텍스트 = monkos_AI/ + apps/(monkos 소속만) + docs/(monkos 관련만)
→ monk.kr 코드 불포함, 오인식 원천 차단
```

**조사 항목**:
1. 각 레포의 예상 트리 크기 (파일 수, 디렉토리 깊이)
2. 에이전트 인덱싱 시 혼동 가능성이 잔존하는 영역
3. 한쪽 레포에서 **다른 쪽의 존재와 맥락은 인지하되, 작업 시 불필요한 맥락을 도입하지 않는 구조** — CLAUDE.md 또는 docs/에 "상대 레포 참조 가이드" 배치 방안
