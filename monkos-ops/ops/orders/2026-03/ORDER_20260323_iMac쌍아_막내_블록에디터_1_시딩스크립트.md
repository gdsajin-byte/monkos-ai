# 지시서 #1: Firestore 초기 데이터 시딩 스크립트

## 1. 목적

`site_config/layout` 문서에 14개 블록 데이터를 시딩한다. 현재 이 문서는 빈 상태(또는 구 7개 섹션 메타만 존재). 기안서 3.1 스키마 기반 + 현재 index.html/i18n.js의 실제 텍스트를 정본으로 사용.

## 2. 작업 내용

### 2-1. 스크립트 생성

**파일**: `monkos_AI/portal/scripts/seed-layout.js`

- Node.js 스크립트 (1회성 실행)
- Firestore `site_config/layout` 문서에 `{ sections: [...], updatedAt }` 세팅
- `.env` 로드하여 Firestore 인증 (기존 config.js 패턴 참조)

### 2-2. 시딩 데이터 원본

**텍스트 정본은 아래 두 파일에서 추출** (추측 금지):
- `public/index.html` — HTML 구조 + KO 기본 텍스트
- `public/js/i18n.js` — JA/EN 번역 텍스트

### 2-3. 14개 블록 스키마

기안서 3.1절의 스키마를 그대로 사용. 아래는 블록 ID 목록:

| order | id | type | 데이터 원본 |
|-------|-----|------|------------|
| 1 | hero | hero | index.html `.hero-inner` + i18n heroTag |
| 2 | user-bar | user-bar | index.html `#userBar` + i18n ctaText |
| 3 | gallery-strip | gallery-strip | 설정값만 (이미지는 gallery_items 컬렉션) |
| 4 | nav | nav | index.html `.n-links` + i18n navHome~navPricing + navHrefs |
| 5 | service-cards | service-grid | index.html `.svc-grid` + i18n svcPhoto/Crop* |
| 6 | howto | howto-grid | index.html `.howto-grid` + i18n howto1~3 |
| 7 | faq-preview | faq-preview | 설정값만 (데이터는 faq_items 컬렉션) |
| 8 | board-preview | board-preview | 설정값만 (데이터는 board_posts 컬렉션) |
| 9 | blog-cards | blog-cards | 설정값만 (데이터는 blog_posts 컬렉션) |
| 10 | magazine | magazine | 설정값만 (데이터는 blog_posts pinned) |
| 11 | tags | tags | 설정값만 (자동 집계) |
| 12 | guide | guide-cards | index.html `.guide-card` + i18n guide1/2* |
| 13 | credit-info | credit-box | index.html `.credit-info` + i18n credit* |
| 14 | footer | footer | index.html `<footer>` |

### 2-4. 블록별 상세 스키마

기안서 3.1절 참조. 핵심 원칙:
- 다국어 텍스트: `{ ko: "...", ja: "...", en: "..." }` 객체
- Firestore 동적 블록 (faq-preview, board-preview, blog-cards, magazine, tags): `data: { maxItems, header: { title, link, href } }` 형태. 실 데이터는 각 컬렉션에서 읽음
- 순수 데이터 블록: `items[]` 또는 `data{}` 안에 실제 텍스트 포함

## 3. 실행 방법

```bash
cd monkos_AI/portal
node scripts/seed-layout.js
```

실행 후 콘솔에 시딩된 블록 ID 목록 출력.

## 4. 검증

- 스크립트 실행 후 Firestore 콘솔 또는 `GET /api/admin/layout`으로 데이터 확인
- 14개 sections 존재, 각 블록에 다국어 텍스트가 정확히 들어있는지 확인
- 기존 서비스에 영향 없음 (layout 데이터를 아직 SSR에서 읽지 않으므로)

## 5. 유의 사항

⚠️ **헌법 제4조 1항**: `.env` 파일 내용 절대 하드코딩/노출 금지. 기존 config.js import 패턴 사용
⚠️ **헌법 제1조 1항**: 타임스탬프 `date` 명령 취득
⚠️ **헌법 제2조 1항**: 완료 보고 필수
⚠️ **데이터 정합성**: i18n.js의 텍스트를 그대로 복사. 의역·수정 금지
⚠️ **멱등성**: 스크립트 재실행 시 덮어쓰기 (set, merge 아님). 이전 데이터 날아가도 OK (시딩이니까)
