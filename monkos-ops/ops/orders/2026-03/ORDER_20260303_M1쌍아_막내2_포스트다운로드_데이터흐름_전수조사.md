3. 규격 탭(다규격 전환) 자체가 v5 설계에서 제외된 기능이나 코드에 잔존

## 조사 범위

### 1. 데이터 이동 전수 파악

다운로드 플로우에서 **각 단계별로 어떤 데이터가 어디에 있는지** 매핑:

| 추적 대상 | 확인 사항 |
|----------|----------|
| `_fullOriginal` (모듈 스코프) | 생성 시점, 소실 시점, `_mo_p` 임시 보관 흐름 |
| `store.generated` | 워터마크 버전인지 원본인지, sessionStorage 저장 여부 |
| `store.cropped` | 생성 시점, `saveSessionData('cropped')` 호출 지점 |
| `store.downloadComplete` | 설정 시점, 보존 여부 (sessionStorage에 없음 확인) |
| `_specCache` / `_currentSpec` | 설정 시점, 페이지 이동 시 소실 여부 |
| `monkos_pending_action` | 설정/소비 흐름 |
| `_mo_p` (sessionStorage) | 설정/복원/삭제 시점 |

**산출물**: 데이터 생명주기 테이블 (변수명 × 이벤트별 상태)

### 2. 결제 후 리다이렉트 지점 전수 파악

result.js에서 `charge.html`로 이동하는 **모든 경로**와 복귀 후 동작:

| 확인 사항 | 상세 |
|----------|------|
| `navigateTo('charge.html?...')` 호출 전수 | 파일명, 라인번호, 파라미터(`return`, `action`) |
| charge.html → result.html 복귀 시 `init()` 동작 | 어떤 분기를 타는지 (L740~776) |
| `monkos_pending_action` 자동 진행 로직 | download 외 다른 action은? |
| 토스 리다이렉트 복귀 | 결제 완료 후 페이지 리로드 시 상태 복원 경로 |

**산출물**: 리다이렉트 매트릭스 (출발지점 × 복귀 후 상태)

### 3. thankyou.html 현황 vs v5 설계 비교

| 확인 사항 | 상세 |
|----------|------|
| 현재 thankyou.html/js 기능 목록 | 어떤 데이터를 읽는지, 어떤 액션이 가능한지 |
| v5 설계 (스크린샷 기준) 요소 대비 현황 | 다운로드 버튼, 전후비교 저장, 크레딧 잔액, 풀샷 원본, CS, SNS 이벤트 |
| result.js `cropAndShowPostDownload()`와 기능 중복 | 어떤 기능이 result에만 있고 thankyou에 없는지 |

**산출물**: v5 설계 vs 현재 코드 GAP 테이블
