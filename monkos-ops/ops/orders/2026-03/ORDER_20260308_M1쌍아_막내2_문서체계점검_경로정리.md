# 지시서: 문서 체계 전수 점검 + 경로 정리

> **너는 막내2호다. 쌍아가 아니다.**

## 배경

프로젝트 문서가 810개 이상 축적되었다. 법률 제4장(문서/폴더 구조) 기준으로 전체 문서 체계의 정합성을 점검하고, 경로상 정리가 필요한 파일을 식별해야 한다. 특히 리팩토링/디버깅/기술도입 등의 기술 명세가 체계적으로 정리되고 있는지 확인한다.

## 관련 법률

- **법률 제4장 전체**: 문서 위계(1조), 금지사항(2조), 네이밍(3조), 정본 위치(4조), 서비스 약칭(5조), YAML(7조)
- **헌법 제13조**: 문서 규격 준수

## 작업 지시

### Phase 1: ch4 기준 전수 점검

1. **정본 경로 정합성** (ch4 4조 기준):
   - 지시서(ORDER_): `monkos-ops/ops/orders/` — 정본 위치 확인
   - 보고서(REPORT_/COMPLETION_): `monkos-ops/ops/reports/` — 정본 위치 확인
   - 기술 명세(SPEC_): `monkos-ops/03_개발/specs/` 및 `docs/specs/` — 이중화 여부
   - 인시던트(INCIDENT_): 존재 여부 및 배치 확인
   - 설계서(DESIGN_): 배치 위치 확인
   - 스프린트(SPRINT_): 배치 위치 확인

2. **네이밍 규칙 준수** (ch4 3조, 13종 유형):
   - `monkos-ops/ops/orders/` 전수: ORDER_ 패턴 미매칭 파일 식별
   - `monkos-ops/ops/reports/` 전수: REPORT_/COMPLETION_/REVIEW_/DESIGN_ 패턴 미매칭 파일 식별
   - `monkos-ops/03_개발/` 하위: 규격 외 파일 식별

3. **ch4 2조 금지사항 점검**:
   - 루트 임시 .md 파일 방치 여부
   - 문서 정본 이중화 여부
   - README.md 미보유 폴더 존재 여부
   - .DS_Store, 바이너리 파일 docs/ 배치 여부

### Phase 2: 기술 명세 정리 상태

1. `monkos-ops/03_개발/specs/` 전수 점검:
   - 각 서비스별 스펙 파일 유무 (idphoto-kr, idphoto-jp, portal, photolab, monk-kr)
   - YAML frontmatter 준수 여부
   - 최신성: 실제 코드와 스펙 문서 갱신 시점 비교

2. **리팩토링 명세**: 리팩토링 관련 문서 검색 (REPORT, SPEC, ORDER에서)
   - 리팩토링 이력이 문서화되어 있는지
   - 리팩토링 전후 변경 사항이 스펙에 반영되었는지

3. **디버깅 명세**: 인시던트/버그픽스 관련 문서 검색
   - INCIDENT_ 파일 존재 여부
   - 버그 수정 이력의 문서화 수준

4. **기술 도입 명세**: 새로운 기술 도입 관련 문서 검색
   - Gemini Live, AutoShot, 크레딧 시스템 등 주요 기술 도입이 SPEC 또는 DESIGN으로 정리되었는지
   - `docs/rnd_2026/` 하위 R&D 문서와 `monkos-ops/03_개발/specs/` 간 연계

### Phase 3: 경로 정리 대상 식별

1. **위치 부적절 파일**: ch4 4조 정본 위치에 안 맞는 파일
2. **미분류 파일**: `monkos-ops/03_개발/` 루트의 프로토타입/기획 문서 (specs/tasks/로 이동 필요 여부)
3. **레거시 번호 폴더**: `monkos-ops/01~06_` 폴더와 신규 부서 체제(ops/tech/contents/marketing) 간 중복
4. **docs/ 내 이중 배치**: 동일 문서가 docs/monkos/와 monkos-ops/ 양쪽에 존재하는 경우
