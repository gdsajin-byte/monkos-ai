# Phase 4: 리다이렉트 시스템 점검

## 맥락

Phase 3(로그인 게이트 이동 + 비회원 경로 소멸)까지 완료. 비회원 결제 경로가 제거된 상태에서 전체 리다이렉트 체인이 정상 동작하는지 전수 점검한다.

### 현행 리다이렉트 구조

```
INDEX → PREP(v5 퍼널) → CAMERA → RESULT → THANKYOU
                                    │          │
                           ChargeModule(모달)  ChargeModule(모달)
                                    │          │
                              토스 결제 → 같은 페이지?toss=success
                              → initFromTossResult() → pending_action 자동진행
```

- **토스 결제**: `buyCreditsKR()` → successUrl = `현재페이지?toss=success`, failUrl = `현재페이지?toss=fail`
- **결제 확인**: `initFromTossResult()` → 백엔드 `/api/payments/toss/confirm` → 크레딧 갱신
- **자동 진행**: `sessionStorage.monkos_pending_action` → 충전 후 원래 액션 재시도

---

## 작업 항목

### 1. 토스 결제 리다이렉트 검증 (3개 페이지)

토스 `successUrl`/`failUrl`이 현재 페이지 기반 `window.location.pathname`을 사용한다. 각 페이지에서 정상 동작 확인:

| 페이지 | 시나리오 | 기대 successUrl |
|--------|----------|----------------|
| result.html | 다운로드 잔고부족 → ChargeModule → 토스 | result.html?toss=success |
| thankyou.html | 풀샷 잔고부족 → ChargeModule → 토스 | thankyou.html?toss=success |
| charge.html | 충전 페이지 직접 결제 → 토스 | charge.html?toss=success |

**확인 사항**:
- `initFromTossResult()`가 각 페이지 `init()`에서 호출되는지 (shared.js `sharedInit()` 경유)
- `history.replaceState()`로 URL 쿼리 정리가 정상인지
- 결제 실패(`?toss=fail`) 시 alert 후 원래 페이지 상태 유지되는지

### 2. pending_action 자동 진행 검증

| 페이지 | pending_action 값 | 자동 진행 대상 |
|--------|-------------------|---------------|
| result.js | `'download'` | `downloadResult()` → `doDownload()` → thankyou 이동 |
| result.js | `'generate'` | `confirmAndGenerate()` 리터칭 재시도 |
| thankyou.js | `'full_original'` | `downloadFullOriginal()` 풀샷 다운로드 |

**확인 사항**:
- 토스 결제 완료 → 페이지 reload → `sharedInit()` → `initFromTossResult()` → 크레딧 업데이트 → pending_action 체크 → 자동 진행 **순서가 보장**되는지
- pending_action이 처리 후 반드시 `removeItem`되는지 (중복 실행 방지)
- 크레딧이 아직 부족한 경우 (부분 충전) 무한 루프에 빠지지 않는지

### 3. 로그인 게이트 → 로그인 후 복귀 (핵심 개선)

Phase 3에서 `GateModule.showLoginRequired()`가 설치되었으나, **로그인 성공 후 원래 액션을 자동 재시도하는 로직이 없다**.

**현행 문제**:
- result.js에서 리터칭 요청 → 비로그인 → 게이트 모달 → 로그인 성공 → **모달만 닫힘** → 사용자가 다시 버튼을 눌러야 함
- camera.html에서도 동일한 패턴

**개선 방향**:
- `gate.js`의 로그인 성공 콜백에 **post-login callback** 구조 추가
- `showLoginRequired(message, callback)` — 로그인 성공 시 callback 실행
- 또는 `store.user` 변경을 감지하여 원래 액션 재시도

**구현 선택지** (아래 중 택 1, 네 판단에 맡긴다):

A) **콜백 방식**: `showLoginRequired(msg, onSuccess)` → 로그인 성공 시 `onSuccess()` 호출
B) **이벤트 방식**: 로그인 성공 시 `document.dispatchEvent(new Event('monk-auth-success'))` → 각 페이지에서 리스너

어느 쪽이든 **기존 showLoginRequired 호출부(result.js, camera.html)를 함께 수정**해야 한다.

### 4. charge.html 돌아가기 경로

현행: `?return=` 파라미터 → 기본값 `index`

```js
const returnPage = params.get('return') || 'index';
navigateTo(`${returnPage}.html`);
```

**확인 사항**:
- index.html에서 `charge.html?return=index` 링크가 정상인지
- 모달(ChargeModule)에서는 charge.html 이동이 아닌 모달 닫기이므로 별도 return 불필요 → 맞는지 확인
- charge.html 직접 접근(외부 링크) 시 돌아가기 → index.html (기본값) 정상인지

### 5. Phase 3 잔재 점검

비회원 결제 경로(buyDirect, initDirectPayment)가 제거되었으므로:
- 기존 코드에서 `buyDirect` 또는 `initDirectPayment` 참조가 남아있지 않은지 grep
- `gate.js`의 deprecated `show()` 참조가 남아있지 않은지 grep
- 비회원 결제 관련 sessionStorage 키가 남아있지 않은지 확인

### 6. 전체 리다이렉트 E2E 흐름 정리

아래 시나리오별 전체 경로를 코드에서 추적하고, **끊어지는 링크가 없는지** 확인:

| # | 시나리오 | 경로 |
|---|---------|------|
| 1 | 비로그인 → 촬영 시도 | index → prep → camera → 게이트 모달 → 로그인 → 촬영 시작 |
| 2 | 로그인 → 촬영 → 잔고부족(리터칭) | camera → result → 리터칭 → 잔고부족 → ChargeModule → 토스 → result?toss=success → 자동리터칭 |
| 3 | 로그인 → 촬영 → 다운로드 잔고부족 | result → 다운로드 → 잔고부족 → ChargeModule → 토스 → result?toss=success → 자동다운로드 → thankyou |
| 4 | thankyou → 풀샷 잔고부족 | thankyou → 풀샷 → 잔고부족 → ChargeModule → 토스 → thankyou?toss=success → 자동풀샷 |
| 5 | 외부유입 → charge.html 직접 | charge.html → 결제 → 토스 → charge?toss=success → alert → 돌아가기 → index |
| 6 | 랜딩 → 패키지보기 → 충전 | index → charge?return=index → 결제 → 토스 → charge?toss=success → 돌아가기 → index |
