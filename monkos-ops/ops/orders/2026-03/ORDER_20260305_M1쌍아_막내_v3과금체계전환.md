## 배경 — 왜 바꾸는가

### v2.1의 한계
- "증명사진 N장" 상품명 → 크레딧 자유소비와 불일치 (장수 약속 아님)
- 보너스율 밋밋 (14%→12%→17%) → 패키지 인센티브 약함
- 풀샷 20c → 잔액 10c에서 10c 부족 → ₩1,450 추가결제 강제

### v3 핵심 변경
- **상품 = 크레딧** ("몇 장"이 아니라 "몇 c를 사는가")
- **보너스율 계단 강화**: 14% → 30% → 40% → 50%
- **풀샷 20c → 10c**: 모든 부가기능 10c 통일
- **취소선 = 총c(보너스 포함) × ₩145**: 보너스 존재감 극대화
- **ChargePanel 모달화**: 별도 페이지 이동 → 바텀시트 모달 (같은 컴포넌트, 다른 컨테이너)

### 맥락 문서
- `monkos-ops/ops/orders/MONKOS_쌍아_맥락브리핑_v3.md` — 철창이 작성 전체 설계 의도

#### B-1-2. _buildModal() HTML 재작성 (L87-154)

**설계 원칙** (철창이 확정):
- **"얼마인가"만 답한다** — 크레딧 개념설명, 활용 힌트, 할인율 등지 전부 삭제
- 취소선 = `(credits + bonus) × ₩145` — 런타임 계산, 하드코딩 금지
- 보너스 표시: `+Nc 보너스`
- 절약 금액: `취소선 - 실결제` 표시

**각 상품 카드 구조** (HTML):
```
[라디오] {label}        ₩{취소선}  ₩{실결제}
         +{bonus}c 보너스  ₩{절약}원 절약
```

취소선과 절약 금액은 JS에서 계산:
```javascript
const totalC = opt.credits + opt.bonus;
const strikePrice = totalC * KRW_PER_CREDIT;
const saved = strikePrice - opt.price;
```

**소액충전 스테퍼**: 현행 유지 (10~100c, ₩1,450/10c, 보너스 없음)

**버튼**:
- "토스페이먼츠로 결제" (기존 유지)
- "닫기" (모달 모드) / "돌아가기" (풀페이지 모드)

#### B-1-3. 결제 호출 (L196-206)

**현재**: `buyCreditsKR(opt.amount, opt.credits)` — credits에 총c(보너스 포함)를 넘김
**변경**: `buyCreditsKR(opt.price, opt.credits + opt.bonus)` — 동일 패턴 유지. 서버가 amount로 PRODUCTS 역참조하여 분리 기록.

### B-3. shared.js showChargeModal() 변경

**파일**: `monkos_AI/idphoto-kr/public/shared.js`

**현재 (L117-120)**:
```javascript
// ─── 충전 페이지 이동 (v5: 풀페이지) ───
export function showChargeModal() {
  navigateTo('charge.html?return=' + encodeURIComponent(location.pathname.replace('.html', '').replace('/', '')));
}
```

**변경**:
```javascript
// ─── 충전 모달 (v3: 바텀시트) ───
export function showChargeModal() {
  // modules/charge.js의 ChargeModule 사용
  import('./modules/charge.js').then(m => m.ChargeModule.show());
}
```

이로써 result.html, thankyou.html 등에서 잔고부족 시 **페이지 이동 없이 바텀시트 모달**이 뜸.

**주의**: 랜딩 index.html의 `<a href="/charge.html">패키지 할인 보기 →</a>` 는 그대로 유지 (랜딩 → 풀페이지 진입).
