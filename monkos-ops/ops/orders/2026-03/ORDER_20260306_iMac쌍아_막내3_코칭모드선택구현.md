# [지시서] 촬영실 코칭 아키텍처 정리 — 모드 선택 + Live 훈육 + QC 통합

> **[2026-03-06 17:37 KST] iMac/쌍아 → iMac/막내3**
> **[2026-03-06 17:40 KST] 4차 보정** — QC/사전분석을 Live 코치로 통합 (작가님 결정)
>
> 촬영실 코칭 아키텍처 원점 회귀.
> Live 코치가 프레임을 보면서 코칭 + 촬영 판단(QC) 수행. 별도 QC/precheck API 제거.
> 현행 2.0 모델 TEXT + 브라우저 TTS 유지.

---

## 배경

### 아키텍처 변경 전후

**현행 (분리 구조)**:
```
카메라 프레임 → [Gemini Live] → 코칭 TEXT → Web Speech API TTS
캡처 → [별도 Gemini API] → 사전분석 (끊김)
캡처 → [별도 Gemini API] → QC 검증 (끊김)
```

**목표 (통합 구조)**:
```
카메라 프레임 스트리밍 → [Gemini Live 단일 세션]
                         ├─ 코칭: "고개를 왼쪽으로"
                         ├─ 촬영 판단: "좋아요, 지금 촬영하세요!"
                         └─ 모달리티: TEXT + 브라우저 TTS (음성 모드 시)

별도 QC/사전분석 API 호출 ❌ — 코치가 보고 있으니 불필요
```

### 핵심 근거
- 코치(Live)가 프레임을 **실시간으로 보고 있다** → 별도 캡처+API로 또 물어볼 이유 없음
- 초기 설계가 원래 이 구조였음 (Live 단일 세션 = 코칭 + QC)
- 분리하면서 캡처 인터럽트 + 끊김 + 복잡도 증가
- 현행 QC는 사실상 장식 (실패해도 진행 차단 안 함, 다운로드 차단 안 함)

### 이미 적용된 사항
- `camera.js` `speakKo()` 가드 해제 완료 (JP 패턴 이식)
- `if (!koVoice) return;` → `if (koVoice) u.voice = koVoice;`

## 작업 내용

### Phase 1: prep 퍼널 코칭 모드 선택 카드

**파일**: `monkos_AI/idphoto-kr/public/prep.html` (또는 해당 prep UI 파일)

촬영 시작 버튼 직전에 카드 추가:

```
[성별] → [연령대] → [스타일] → [코칭 모드 선택] → [촬영 시작]
```

```html
<div class="prep-card" id="coaching-mode-card">
  <h3>AI 코칭 안내 방식</h3>
  <div class="mode-option selected" data-mode="text">
    <span>💬</span>
    <div>
      <strong>텍스트</strong>
      <p>화면에 글자로 안내합니다</p>

    <div>
      <strong>음성</strong>
```

- **기본값**: 텍스트 (소리 없음)
- 음성: 사용자가 명시적으로 탭해야 활성화
- 선택 결과를 `store.coachingMode = 'text' | 'voice'`로 저장
- 기존 `store.format`, `store.gender`, `store.age`와 함께 sessionStorage 저장

### Phase 2: camera.js 모드 반영 + 정리

**파일**: `monkos_AI/idphoto-kr/public/camera.js`

> `speakKo()` JP 패턴 이식은 이미 적용됨. 아래 항목만 추가 작업.

#### 2-A: 초기화 시 모드 반영

현행:
```javascript
store.voiceEnabled = true;  // 무조건 ON
```

변경:
```javascript
store.voiceEnabled = (store.coachingMode === 'voice');  // prep 선택 반영
```

#### 2-B: 음성 토글 버튼 제거

- `toggleVoice()` 함수 제거
- `window.toggleVoice` 노출 제거
- `#btn-voice` UI 요소 제거
- 모드 전환은 prep에서 완료. 촬영 중 토글 불필요

#### 2-C: TTS 활성화 분기

`activateTTS()`에 음성 모드 분기 추가:
```javascript
function activateTTS() {
  if (!store.voiceEnabled || ttsActivated || !('speechSynthesis' in window)) return;
  // ... 기존 로직
}
```

### Phase 3: Live systemInstruction — 코칭 + 촬영 판단 통합

**파일**: `monkos_AI/idphoto-kr/server.js`

현행 `COACHING_INSTRUCTIONS`를 코칭 + 촬영 판단(QC) 통합 버전으로 교체:

```javascript
const COACHING_INSTRUCTIONS = {
  passport: `증명사진 촬영 AI 코치입니다. 프레임을 보면서 실시간 코칭합니다.

[코칭 규칙]
- 한국어 1문장, 15자 이내
- 문제 시 1가지만 지적 (고개 각도, 표정, 조명 등)
- 좋은 상태면 "좋아요!" 또는 "완벽해요!"

[촬영 판단 — 당신이 QC입니다]
- 다음 조건이 모두 충족되면 "지금 촬영하세요!" 발화:
  · 얼굴이 정면을 보고 있음
  · 눈을 뜨고 있음
  · 표정이 자연스러움
  · 고개가 심하게 기울지 않음
  · 조명이 대체로 균일함
- "지금 촬영하세요!"는 확실할 때만 발화
- 이 멘트가 나오면 시스템이 자동 캡처합니다

[세션 규율]
- 인사하지 마세요. 바로 코칭만 시작하세요
- 이전 대화를 기억하거나 언급하지 마세요
- 3초 이내에 같은 지적을 반복하지 마세요
- 프레임이 양호하면 침묵하세요. 할 말이 있을 때만 발화하세요

[절대 금지]
- 자기소개, 잡담, 감상, 질문
- "안녕하세요", "반갑습니다", "도움이 필요하시면" 류 발화
`,
};
```

### Phase 4: 별도 QC/사전분석 제거

#### 4-A: 클라이언트 QC 호출 제거

**파일**: `monkos_AI/idphoto-kr/public/result.js`

현행 (라인 232-260):
```javascript
// QC + 워터마크를 병렬 실행
let qcResult = null;
const qcPromise = pipe.run('qc', { ... });
// ...
await Promise.race([qcPromise, new Promise(r => setTimeout(r, 10000))]);
// ...
showQCBadge(qcResult);
```

변경:
- `qcPromise`, `qcResult` 관련 코드 전량 삭제
- `showQCBadge()` 함수 삭제
- `await Promise.race(...)` QC 대기 삭제
- 워터마크 생성 로직은 유지

#### 4-B: QC 배지 UI 제거

**파일**: `monkos_AI/idphoto-kr/public/result.html`
- `#qc-badge` 요소 제거 (라인 196-197)
- `.qc-badge` CSS 제거 (라인 94-98)

**파일**: `monkos_AI/idphoto-kr/public/app.css`
- `#qc-badge` 관련 CSS 제거 (라인 406-413)

#### 4-C: 서버 QC 엔드포인트 — 유지하되 비활성화

**파일**: `monkos_AI/idphoto-kr/server.js`
- `/api/qc` 엔드포인트 (라인 618-666): 코드는 유지 (향후 다른 용도 가능), 클라이언트가 호출하지 않으므로 사실상 비활성
- `runPreCheck()` 함수 (라인 431-467): 동일 — 호출처가 없으면 자연 비활성
- 주석으로 `// [비활성] Live 코치가 촬영 판단을 대체 (2026-03-06)` 표시

#### 4-D: 자동 캡처 트리거 (서버)

코칭 텍스트에 "촬영하세요" 포함 시 자동 캡처 신호 전송:

**server.js** WS `onmessage` 콜백에 추가:
```javascript
// 기존 텍스트 전송 후
if (text.includes('촬영하세요') || text.includes('촬영')) {
  ws.send(JSON.stringify({ type: 'auto-capture' }));
}
```

**camera.js** WS `onmessage`에 자동 캡처 핸들링:
```javascript
if (msg.type === 'auto-capture') {
  // Live 코치 승인 → 자동 촬영
  capturePhoto();
}
```

### Phase 5: 통합 테스트

1. **텍스트 모드 (기본)**: 코칭 오버레이만 표시, 음성 없음 확인
2. **음성 모드**: 코칭 오버레이 + TTS 발화 확인 (iOS Safari 포함)
3. **세션 훈육**: Live가 인사/잡담 없이 코칭만 하는지 확인
4. **촬영 판단**: Live가 "지금 촬영하세요!" 발화 → 자동 캡처 작동 확인
5. **QC 제거 확인**: 별도 QC API 호출 없이 결과 페이지 정상 표시 확인
6. **끊김 제거**: 캡처 인터럽트 없이 매끄러운 코칭 → 촬영 흐름

1. **모델 변경 금지** — `gemini-2.0-flash-live-preview-04-09` 유지
