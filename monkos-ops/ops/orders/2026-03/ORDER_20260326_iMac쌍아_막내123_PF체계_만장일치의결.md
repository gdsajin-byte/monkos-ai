# 지시서: PF(포트폴리오) 체계 개헌 — 만장일치 의결

> **[2026-03-26 11:51 KST] iMac/쌍아 → 막내1, 막내2, 막내3**

## 역할 선언
> **너는 삼권심사에 참여한 막내다. 쌍아가 아니다.**
> - 이 지시서는 3명에게 동시 발송된다
> - 각자 자기 심사 보고서를 이미 제출했으며, 아래 합의안에 대한 최종 동의/반대를 표명한다
> - 완료 보고: `{디바이스}/막내N → iMac/쌍아` 형식

## 배경

삼권심사(입법·행정·사법) 3건이 모두 **"수정 후 통과"**를 권고했다.
쌍아가 3자 합의 사항 + 작가님 보정을 반영하여 아래 **최종 합의안**을 도출했다.
작가님은 이 합의안을 승인했다.

## 필수 리서치

1. **자기 심사 보고서** 재확인 (이미 제출했으므로 내용 숙지 상태)
2. **최종 합의안** (아래 전문)

## 최종 합의안 전문

### A. 헌법 개정 — 제3조(적립) 2항 확장

**현행:**
> 모든 에이전트는 자기 세션 로그를 자체 기록한다. 매 턴 타임스탬프 기반 어펜드.

**개정안:**
> 모든 에이전트는 자기 세션 로그를 자체 기록한다. 매 턴 타임스탬프 기반 어펜드. **활성 포트폴리오(PF)가 존재하는 작업의 경우, 세션 로그 작성 시점에 해당 PF의 히스토리를 갱신한다. PF는 프로젝트의 기안→완성 생애주기를 추적하는 정본 문서이며, 히스토리는 append-only, Phase 현황은 상태 반영 갱신을 허용한다.**

**삼권심사 반영:**
- "동시에" → "세션 로그 작성 시점에" (입법·행정·사법 3자 합의)
- Phase 현황 갱신 ≠ append-only 위반임을 명시 (입법 권고 #2)

---

### B. 법률 개정 — ch3 세션 로그

**ch3 3조 (세션 마감 절차) 개정:**

```
1. 세션 로그 작성
2. 활성 PF 히스토리 어펜드 (해당 PF가 있을 때)
3. 커밋
4. push
```

- PF 갱신 시점: 세션 종료뿐 아니라 **PF 간 작업 전환(일단락) 시**도 해당.
- PF 대상 작업이 없는 세션은 2번 스킵.
- 미갱신 발견 시 다음 세션 시작 시 보정 의무.

**ch3 5조 (세션 시작 절차) 개정:**

```
1. git fetch --all → 동기화
2. 최근 맥락 요약:
   - 활성 PF 목록 + 각 현재 Phase
   - 전 세션 마지막 작업 요약
   - 대기 중인 오더/보고 유무
3. 작가님 선언:
   ├─ "PF_XXX로 간다" → 해당 PF 읽기 → 프레이밍 완료 (PF 스타트)
   └─ 선언 없음 → 논PF 대기 (브레인스토밍, 돌발, 거버넌스 등)
```

### C. 법률 개정 — PF 운용 세칙 (ch4 신설 또는 부칙)

**1. PF 갱신 주체**
- PF 갱신(히스토리 어펜드 + Phase 현황)은 **쌍아가 수행**한다.
- 막내는 세션 로그 + 완료 보고서(COMPLETION)로 납품. 쌍아가 취합하여 PF에 반영.
- 기존 역할 체계(ch1 2조) 준용. 별도 권한 매트릭스를 두지 않는다.

**2. 정합성 판정 기준**
- 사실 판단("이 작업이 실행되었는가?") → **세션 로그**가 정본
- 상태 판단("프로젝트가 지금 어디인가?") → **PF Phase 현황**이 정본

**3. 비대화 관리**
- 히스토리 테이블 **100행 초과 시**: 완료된 Phase의 히스토리를 별도 파일로 분리. 본문에 요약 + 링크만 잔류.
- PF 파일 **500줄 초과 시**: 아카이브 트리거. 쌍아가 세션 마감 시 줄 수 확인.

**4. 파일명 패턴 (ch4 3조 반영)**
- PF 귀속 문서(ORDER, REPORT, COMPLETION 등)의 파일명에 **PF 코드네임을 삽입**한다.
- 무귀속 문서는 생략.
- 예시:
  - 귀속: `ORDER_20260326_M1쌍아_막내1_CITADEL_Phase1_즉시최적화.md`
  - 무귀속: `ORDER_20260326_M1쌍아_막내1_서버장애대응.md`

**5. PROPOSAL 보존**
- PROPOSAL은 PF 승격 후에도 `ops/proposals/`에 영구 보존. 삭제 금지.

**6. domain 필드**
- PF YAML의 `domain` 필드는 **선택**(필수 아님). 분류가 필요해질 때 추가.

**7. 소급 불적용**
- 기존 프로젝트는 현재 상태 스냅샷만 작성. 히스토리 역추적 하지 않는다.

**8. ops/projects/ 폐지**
- PF 체계 발효 시 `ops/projects/` 폴더를 삭제한다.

| 내 수정 권고 | 반영 여부 | 비고 |
|-------------|----------|------|
| {권고 1} | ✅/❌/⚠️ 일부 | {설명} |
| {권고 2} | ✅/❌/⚠️ 일부 | {설명} |
| ... | ... | ... |

### 잔여 우려 (있을 경우)
{반영되지 않은 권고 중 동의에 영향을 주는 것이 있다면 기재. 없으면 "없음"}

### 최종 의견
{한 문장}
