## 1. 배경

퍼널 v5 충돌 분석 중, **인증(cookie 전환 완료)과 데이터(sessionStorage 잔존)의 경계가 불명확**한 것이 발견되었다.

특히 portal `auth.js`에서 OAuth 콜백 시 **Set-Cookie + sessionStorage 동시 주입**하는 구간이 있어, 쿠키 전환 과정에서 레거시가 덜 걷어진 가능성이 높다.

**이 지시서의 목적**: sessionStorage / cookie / localStorage가 현재 앱 전체에서 **어디에, 어떤 용도로, 어떻게** 사용되고 있는지 100% 전수 파악. 중복·충돌·레거시 잔재를 빠짐없이 식별.

## 3. 분석 항목 (보고서에 반드시 포함)

### 3-A. sessionStorage 전수 목록

`monkos_` 접두사 키를 포함한 **모든** sessionStorage 사용을 전수 조사:

```
| # | 키 | 쓰는 파일:라인 | 읽는 파일:라인 | 용도 | 생명주기 (언제 생성 → 언제 삭제) | 비고 |
|---|-----|---------------|---------------|------|-------------------------------|------|
```

**반드시 포함할 키** (사전 스캔에서 식별됨):
- `monkos_purpose`, `monkos_style`, `monkos_gender`, `monkos_age` — 퍼널 선택값
- `monkos_clothing`, `monkos_clothingColor`, `monkos_tie`, `monkos_hair`, `monkos_background`, `monkos_expression` — 퍼널 선택값
- `monkos_captured`, `monkos_cropped`, `monkos_generated` — 이미지 데이터
- `monkos_pending_action`, `_mo_p` — 결제/다운로드 임시
- `monkos_user` — 인증 (레거시? 현역?)
- `monkos_credits_from` — portal 토스 리다이렉트

이 외에 **접두사 없이 사용되는 키**가 있는지도 확인.

### 3-B. cookie 전수 목록

서버(Set-Cookie)와 클라이언트(document.cookie) 양쪽 전수 조사:

```
| # | 쿠키명 | 설정 위치(파일:라인) | 읽는 위치(파일:라인) | domain/path/SameSite | 용도 | 만료 |
|---|--------|--------------------|--------------------|---------------------|------|------|
```

**특히 확인할 것**:
- portal auth.js의 Set-Cookie가 설정하는 쿠키명은 무엇인가?
- `monkos_session`? `monkos_token`? 정확한 이름과 값 형식
- `monkos_region` cookie의 설정/읽기 경로
- idphoto-kr에서 이 쿠키를 어떻게 활용하는가?

### 3-D. 중복 탐지 — 같은 데이터가 복수 저장소에 존재하는가?

**핵심 의심 지점**: portal auth.js에서 OAuth 콜백 시 Set-Cookie **AND** sessionStorage.setItem('monkos_user') 동시 주입.

```
| 데이터 | sessionStorage | cookie | 동시 존재? | 어느 쪽이 실제 사용? | 나머지는 레거시? |
|--------|---------------|--------|-----------|--------------------|--------------|
```

질문:
- idphoto-kr의 `verify-cookie` 호출이 성공하면 sessionStorage의 monkos_user는 필요 없는 건가?
- 둘 다 있으면 어느 쪽이 우선하는가?
- 하나를 삭제해도 앱이 정상 동작하는가?

### 3-E. 레거시 잔재 식별

쿠키 기반 인증 전환 후 **더 이상 필요 없는데 남아있는 코드**:

```
| 파일:라인 | 코드 | 레거시 판정 근거 | 삭제 안전성 |
|-----------|------|-----------------|------------|
```

**확인 포인트**:
- `_legacy_spa/index.html`의 monkos_user 코드 → 현재 참조되는가?
- portal `auth.js` L138,153,302,327의 sessionStorage 주입 인라인 JS → verify-cookie가 있으면 불필요한가?
- portal `server.js.backup` → 현역 코드가 참조하는가?
- idphoto-kr의 어디에서든 `monkos_user` sessionStorage를 직접 읽는 코드가 있는가?

### 3-F. 데이터 흐름도

페이지 간 데이터 전달 경로를 추적:

```
prep.js (saveSessionData)
  → sessionStorage
  → camera.js (loadSessionData)
  → sessionStorage (captured 저장)
  → result.js (loadSessionData → /api/idgen)
  → sessionStorage (pending_action)
  → 토스 리다이렉트 → 복귀
  → result.js (initFromTossResult → pending_action 복원)
```

이 체인에서:
- 탭을 닫으면 날아가는 데이터는 무엇인가?
- 토스 리다이렉트 시 살아남는 데이터는 무엇인가? (같은 탭 내 리다이렉트이므로 sessionStorage 유지)
- 어떤 데이터가 sessionStorage에 있어야 하고, 어떤 데이터가 cookie/store로 옮겨져도 되는가?
