# 지시서 — 위성 환경 CLAUDE.md 구성 설계 리서치

**[2026-03-25 15:23 KST] iMac/쌍아 → 막내1**

---

## 배경

본진(monk_project)의 5축 개헌은 시행 완료 대기 중이다. 그러나 MONK 체계는 본진만이 아니다. 위성 레포(monk-han, monkos-works)와 위성 디바이스(M4, M2), 그리고 Claude Desktop 대화형 에이전트(코웍이, 철창이)가 존재한다. 이들의 컨텍스트 구성이 본진 헌법과 연결되지 않으면 개헌이 반쪽짜리가 된다.

---

## 조사 범위

### A. 위성 레포의 CLAUDE.md 상속 구조

현재 MONK에는 여러 레포가 있다:

| 레포 | 용도 | 사용 에이전트 |
|------|------|-------------|
| **monk_project** (본진) | 전체 코드+거버넌스 | 쌍아, 막내, 민아 |
| **monk-han** | 한송이 마케팅/SNS | 민아, 코웍이 |
| **monkos-works** | 팀원 공유 채널 | 전원 |

질문:
1. 위성 레포에 본진 헌법 핵심을 어떻게 전달하는가? 선택지:
   - (a) 위성 레포 CLAUDE.md에 본진 헌법 축약본 복사
   - (b) 위성 레포 CLAUDE.md에 "본진 헌법 참조" 링크만
   - (c) `~/.claude/CLAUDE.md` (User 레벨)에 헌법 핵심을 넣어서 전 레포 적용
   - (d) Managed Policy 활용
2. 각 선택지의 장단점 — Anthropic 컨텍스트 계층 기준
3. 위성 레포에 반드시 전달해야 하는 헌법 항목은? (파괴적 명령 금지, 타임스탬프, 수발신 헤더 등)
4. 위성 레포에 전달 불필요한 항목은? (법률 인덱스, 정본 위치 등 본진 전용)

### B. M4/M2 디바이스 MEMORY.md 초기 템플릿

현재 iMac MEMORY.md는 139행. M4/M2에도 유사한 MEMORY.md가 필요하다.

1. 전 디바이스 공통으로 들어가야 하는 MEMORY.md 항목은?
2. 디바이스별로 달라야 하는 항목은?
3. MEMORY.md 초기 템플릿을 만들면 어떤 구조인가?
4. 이 템플릿을 어디에 보관하는 게 적절한가? (본진 ops? scripts?)

### C. 코웍이/철창이 자체 지침 설계

코웍이와 철창이는 Claude Desktop 대화형이라 자체 지침 입력 창(Project Instructions)이 있다.

1. 자체 지침에 본진 헌법 핵심을 어떻게 반영하는가?
   - 전문 복사? 축약본? 핵심 3조만?
2. 코웍이/철창이가 반드시 알아야 하는 헌법 항목은?
   - 수발신 헤더, 타임스탬프, 파괴적 명령 금지, 브랜드 보호 등
3. 코웍이/철창이가 알 필요 없는 항목은?
   - 막내 행동 강령, 세션 자동 인식 등
4. 자체 지침 갱신 절차 — 본진 헌법 개정 시 자체 지침도 갱신해야 하는데, 누가 어떻게?

### D. 민아 Desktop Claude Code 특수성

어젠다 #10에서 파악된 민아 환경의 미해결 이슈:

1. 민아 세션 단절 현상 — 세션 종료 후 과거 대화 접근 불가. 이것이 Anthropic 설계인지, 버그인지, 워크트리 관련인지
2. 민아의 memory 경로 — 워크트리명이 세션마다 바뀌는지 고정인지 (확인 필요 사항이었음)
3. 민아가 본진 CLAUDE.md를 읽는 경로 — VSCode와 동일한가, 다른 경로인가
4. 민아의 `.claude/` 디렉토리 접근 — settings.json, skills, rules를 VSCode/CLI와 동일하게 사용 가능한가
