# 지시서: 이미지 뱅크 겹침 버그 — 배포 환경 + 통합 디버깅 계획

> **[2026-03-22 11:35 KST] iMac/쌍아 → 막내3**

## 목적

이미지 겹침 문제가 "코드에서는 고쳤는데 프로덕션에서 안 고쳐진" 가능성을 포함하여, 배포 파이프라인 전체를 점검하라. 또한 막내1·막내2의 분석 결과를 통합할 수 있는 **최종 버그 보고서 + 디버깅 계획서 프레임**을 선제작하라.

## 조사 범위

### 1. 배포 파이프라인 점검

- `monkos_AI/portal/deploy.sh` — 배포 스크립트 전문 분석
- `monkos_AI/portal/Dockerfile` — 2단계 빌드 과정
  - **obfuscate.mjs**: 난독화 과정에서 CSS/JS가 변형되는지
  - `public/` 복사 시점과 난독화 적용 범위
- `.gcloudignore` — 배포 제외 파일 목록

### 2. 정적 파일 서빙 검증

- `monkos_AI/portal/server.js` — 정적 파일 서빙 로직 (라인 252~278 부근)
  - Cache-Control 헤더: CSS/JS가 `no-cache`인데 실제 브라우저 캐시가 남는지
  - MIME 타입 매핑이 정확한지
  - ESM 모듈의 `type="module"` import가 Cloud Run에서 정상 작동하는지

### 3. Dev vs Prod 환경 차이

- `monkos-portal` (prod) vs `monkos-portal-dev` (dev) 서비스 차이
- 최근 prod 배포 시점 확인: **마지막 prod 배포가 v2.0 모듈 분리 이후인지** 검증
  - git log에서 `b94a0be` ([ops] 블로그 정비 prod 배포 완료 보고) 시점
  - 그 이후 커밋 (`e1556ee`, `eafde7c`) 이 prod에 반영되었는지
- Cloud Run 리비전 히스토리 확인 가능하면 확인

### 4. 브라우저 캐시 문제

- blog-edit.html에서 CSS/JS를 로드할 때 캐시 버스팅 파라미터(`?v=...`)가 있는지
- ESM import 경로에 캐시 버스팅이 적용되는지
- `Cache-Control: no-cache`가 실제로 브라우저에서 존중되는지 (stale-while-revalidate 등)

### 5. 난독화 영향 분석

- `obfuscate.mjs`가 HTML 내 `<script>` 블록만 처리하는지, 외부 JS 파일도 처리하는지
- ESM 모듈 파일 (`blog-image.js` 등)이 난독화를 거치는지
- 난독화 과정에서 CSS 클래스명이나 DOM 구조가 변경되는 경우는 없는지

### 6. 통합 디버깅 계획서 프레임 작성

막내1(코드분석)·막내2(히스토리추적)·막내3(배포환경) 결과를 하나로 엮을 수 있는 **통합 보고서 프레임**을 선제작:

```
REPORT_20260322_통합_이미지겹침_버그보고서.md
```

아래 섹션 구조로 프레임 작성 (막내1·2 결과 통합 영역은 placeholder로):

1. **버그 정의** — 정확한 증상 기술 + 재현 조건
2. **타임라인** ← 막내2 결과 통합
3. **현재 코드 상태** ← 막내1 결과 통합
4. **배포 환경 분석** ← 막내3 본인 결과
5. **근본 원인 분석** — 코드 원인 + 배포 원인 + 구조적 원인
6. **디버깅 계획** — 단계별 검증 방법 + 수정 방안 + 재발 방지 대책
7. **검증 체크리스트** — 수정 후 확인해야 할 항목 목록
