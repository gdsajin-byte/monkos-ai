## 3. 분석 항목 (보고서에 반드시 포함)

### 3-A. 페이지별 충돌 매핑

각 v5 페이지에 대해 아래 표를 작성하라:

```
| v5 페이지 | 현재 파일 | 변경 유형 | 상세 |
|-----------|----------|----------|------|
```

변경 유형: `전면교체` / `구조분리` / `리디자인` / `수정` / `신규` / `삭제`

대상 페이지:
1. **[1p] 규격 선택** vs prep.html/prep.js
2. **[2p] 성별+연령** vs prep.html/prep.js
3. **[3p] 스타일 선택** vs prep.html/prep.js
4. **[4p] CONFIRM** vs prep.html/prep.js
5. **[프리뷰]** vs result.html/result.js
6. **[충전 화면]** vs modules/charge.js
7. **[엔딩]** vs thankyou.html/thankyou.js
8. **[랜딩]** vs index.html

### 3-B. 디자인 시스템 대조

v5 프로토타입의 컬러 토큰(`C` 객체)과 현재 앱의 CSS 변수/인라인 스타일을 비교:

```
| v5 토큰 | v5 값 | 현재 앱 대응 | 일치 여부 | 조치 |
|---------|-------|-------------|----------|------|
```

### 3-C. 컴포넌트 매핑

v5 프로토타입의 공용 컴포넌트(Phone, SelectCard, ConfirmRow, ChatbotPanel)가 현재 앱에서 어떻게 구현되어야 하는지 분석:

- 현재 앱은 React가 아니라 **바닐라 JS + Monk 프레임워크**
- 각 React 컴포넌트 → 바닐라 JS 변환 방안 제시
- Monk.store 바인딩 활용 가능 구간 식별

### 3-D. HTML 구조 변경 계획

각 페이지별로:
- **유지할 수 있는 HTML 구조** (재활용)
- **새로 만들어야 하는 HTML 구조**
- **삭제할 HTML 구조**

### 3-E. CSS 영향도

- app.css에서 유지/수정/삭제할 클래스 목록
- v5 인라인 스타일 중 CSS 클래스로 추출해야 할 것
- cr-coin.css 영향 여부

### 3-F. 삭제 대상 정리

- mission.js: 참조하는 코드 전수 조사 (import, onclick, 호출부)
- premium.js: 참조하는 코드 전수 조사
- gate.js Phase1/Phase2 잔재: 이미 제거되었는지 확인
- prep.js 9스텝 로직: 전면 대체 시 남겨야 할 부분 (있다면)

### 3-G. 충전 화면 모달→풀페이지 전환 영향

현재 `ChargeModule.show()`를 호출하는 모든 코드를 전수 조사:
- 어디서 호출하는가 (result.js, gate.js, shared.js, index.html 등)
- 풀페이지로 변경 시 각 호출부의 수정 방안
