# 지시서 — 위성 환경 컨텍스트 통합 실행 설계안

**[2026-03-25 15:23 KST] iMac/쌍아 → 막내2**

---

## 배경

본진 5축 개헌과 동시에 위성 환경(M4, M2, monk-han, monkos-works, 코웍이, 철창이)의 컨텍스트 구성도 정비해야 한다. 막내1이 리서치를, 너는 실행 설계안을 담당한다.

**핵심 원칙**: 맥락 충돌만 없다면, 위성 환경은 본진보다 가벼워야 한다. 헌법 전문이 아니라 핵심만 전달.

---

## 작업

### A. 헌법 핵심 축약본 작성

위성 레포/자체 지침에 공통으로 들어갈 **"헌법 에센스"** 초안을 작성하라.

**포함 필수 항목** (에이전트 종류 불문 반드시 지켜야 하는 것):
- 타임스탬프 절대 준수 (매 턴 `date`)
- 수발신 헤더 형식
- 파괴적 명령 금지
- 비밀정보 보호
- 내부 기밀 보호 (MONKOS 외부 브랜드)
- 피드백 의무 (에러 묵과 금지)
- 완료 보고 형식

**포함 불필요 항목** (본진 전용):
- 법률 인덱스 8장
- 규정 참조 테이블
- 정본 단일 원칙 (ops 구조)
- 역할 체계 상세 (쌍아/막내 분리 등)

**목표**: 30~50줄 이내. 위성 CLAUDE.md 또는 자체 지침에 복사해서 쓸 수 있는 자체완결형.

### B. 위성 레포별 CLAUDE.md 초안

#### B-1. monkos-works 레포

works 레포는 팀원(한송이, 꾸) + 에이전트(민아, 코웍이) 공용 채널.

- 헌법 에센스 (A에서 작성한 것)
- works 전용 규칙: 파일명 스키마 `{유형}_{YYYYMMDD}_{디바이스}{주체}_{주제}.md`
- 삭제 절대 금지
- ops/ only push 원칙
- han/, kku/ 로컬 전용

#### B-2. monk-han 레포

한송이 전용. 민아/코웍이가 SNS·마케팅 작업에 사용.

- 헌법 에센스 (A에서 작성한 것)
- 한송이 작업 맥락 (SNS, 콘텐츠, 플랫폼)
- 민아/코웍이 역할 구분

### C. 코웍이/철창이 자체 지침 초안

Claude Desktop Project Instructions에 붙여넣을 수 있는 형태.

#### C-1. 코웍이 자체 지침

- 헌법 에센스
- 코웍이 역할: 전략·브라우저의 눈과 머리
- 코웍이 전용 규칙: 서치콘솔/애널리틱스 접근, works 산출물 경로
- 본진 연계: works 레포 경유, 쌍아가 subtree pull로 수신

#### C-2. 철창이 자체 지침

- 헌법 에센스
- 철창이 역할: 전략기획, 이미지/디자인 생성
- 철창이 전용 규칙: 산출물 경로 (`~/Desktop/철창이/`)

### D. MEMORY.md 초기 템플릿

새 디바이스(M4, M2 등)에 MEMORY.md를 세팅할 때 쓸 템플릿.

```markdown
# {디바이스명} MEMORY — MONK OS

## 이 디바이스: {디바이스명}
- **{디바이스명}** ({위치})
- 모든 에이전트 접두어: `{디바이스명}/쌍아`, `{디바이스명}/막내N`

## 역할 자동 인식
- 시스템 프롬프트에 `VSCode native extension` → **쌍아**
- 시스템 프롬프트에 `Claude Agent SDK` → **민아**
- 그 외 (CLI) → **막내**

## 세션 로그 파일명 패턴
- 쌍아: `monkos-ops/ops/sessions/YYYY-MM/{디바이스명}_쌍아.md`
...
```

이런 구조의 완성본 작성.

### E. 갱신 절차 제안

본진 헌법이 개정되면 위성 환경 문서도 갱신해야 한다. 이 절차를 어떻게 자동화/반자동화할 수 있는지 제안:

1. 헌법 에센스를 단일 파일로 관리 → 위성에 복사
2. 갱신 트리거: 본진 커밋 시 hook? 세션 시작 시 확인?
3. 현실적 최소안: 쌍아가 개헌 시 위성 갱신 체크리스트 수행
