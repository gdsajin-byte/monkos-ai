# 지시서: v5 퍼널 전체 로직 전수 검토 — 로그인 강제·크레딧 정산·과금 게이트

> **[2026-03-03 04:41 KST] M1/쌍아 → 막내1**

---

## 배경

v5 프로덕션 E2E에서 이중과금(#4)과 포스트 다운로드 롤백(#2) 발견. 막내2가 데이터 흐름·리다이렉트를 조사하는 동안, 막내1은 **과금 로직 자체의 정합성**을 전수 검토한다.

---

## 조사 범위

### 1. 로그인 강제 시점 전수 파악

v5 퍼널의 전체 경로(prep → camera → result → thankyou)에서 **로그인이 필요한 지점**과 **비로그인 허용 지점**을 매핑:

| 확인 사항 | 상세 |
|----------|------|
| 비로그인 무료 체험 경로 | prep→camera→result 생성(1회)까지 어디까지 가능? |
| `store.user.id` 체크 지점 전수 | 파일명·라인번호·동작(차단/우회/무시) |
| `GateModule.showLoginRequired` 호출 지점 | 언제 로그인 강제가 뜨는지 |
| `GateModule.buyDirect` 경로 | 비로그인 직결제(₩9,900) 플로우 |
| 비로그인 상태에서 충전 페이지 진입 시 | charge.html에서 로그인 체크 유무 |

**산출물**: 퍼널 단계별 로그인 요구 매트릭스

### 2. 크레딧 정산 로직 전수 파악

**모든 과금 지점**의 비용·조건·서버 엔드포인트를 매핑:

| 확인 사항 | 상세 |
|----------|------|
| `pipe.run('creditUse', ...)` 호출 전수 | 파일·라인·type 파라미터·비용(c) |
| `CREDIT_COST` 상수 정의 | 어디서 정의, 각 항목별 값 |
| 서버측 `/api/credits/use` 핸들러 | server.js에서 type별 차감 로직, 중복 차감 방지 유무 |
| 잔액 확인 → 과금 사이 레이스 컨디션 | 클라이언트 잔액 체크 후 서버 차감 사이 불일치 가능성 |
| `fetchLatestCredits` 호출 시점 | 잔액 갱신이 언제 되는지 |

**산출물**: 과금 포인트 테이블 (지점 × 비용 × 조건 × 중복방지)

### 3. 과금 게이트 정합성 검증

특히 다음 시나리오에 대해 코드 경로를 추적:

| 시나리오 | 검증 내용 |
|----------|----------|
| **생성 10c → 다운로드 70c** | 정상 1회 플로우. 총 80c 맞는지 |
| **다운로드 후 추가 규격 10c** | selectSpec() 경로. 이미 다운로드한 규격은 캐시 히트? |
| **다운로드 후 페이지 새로고침** | init() 복원 시 다시 70c 요구하는지 |
| **크레딧 부족 → 충전 → 복귀 → 자동 진행** | pending_action 플로우 정상 동작 여부 |
| **비로그인 1회 무료 → 다운로드** | 무료 생성 후 다운로드에서 어떻게 되는지 |
| **풀 원본 다운로드 20c** | downloadFullOriginal() 경로. 중복 과금 방지? |

**산출물**: 시나리오별 과금 경로 추적표
