## 조사 포인트

### 1. 비로그인 사용자 플로우

로그인 없이 촬영 → 생성 → 다운로드까지 도달 가능한가?

- 각 API 단계(`/api/precheck`, `/api/idgen`, `/api/credit/use`)에서 **인증 체크(userId/토큰 검증)** 가 있는가
- 프론트의 `downloadGate()` (또는 유사 함수)가 유일한 관문인가, 서버에서도 차단하는가
- **결론**: 비로그인 사용자가 어디까지 진행 가능한지 명확히 표시

### 2. 크레딧 0 사용자 플로우

로그인은 했지만 크레딧 0일 때:

- **생성(`/api/idgen`)** 시점에서 크레딧 차감하는가, **다운로드** 시점에서 차감하는가
- 차감 없이 생성이 되면 결제 없이 미리보기까지 도달 가능 → 결제 동기 약화
- **결론**: 크레딧 0 사용자가 어디까지 진행 가능한지 명확히 표시

### 3. 게이트 위치 매핑

아래 사용자 여정에서 **어디가 유료 벽인지** 코드 근거와 함께 정확히 표시:

```
촬영 준비 → AI 코칭 → 촬영 확인 → AI 생성 → 클로즈업 → 다운로드
                                      ↑              ↑
                               여기서 차감?     여기서 차감?
```

각 전환 지점에서 호출되는 함수/API와 크레딧 체크 로직을 명시할 것.

### 4. 서버 사이드 차단

- `/api/credit/use`가 크레딧 부족으로 실패하면 **어떤 HTTP 응답 코드 + body**가 오는지
- 프론트가 그 응답을 받아 **어떻게 처리하는지** (결제 유도? alert? 무시?)
- 서버에 `/api/credit/use` 외에 크레딧을 차감하는 다른 엔드포인트가 있는지

### 5. 토스 테스트키 행동

- 토스 테스트키(`test_ck_...`)가 `requestPayment()` 호출 시 **실제 결제창 팝업을 띄우는지**
- 아니면 테스트 모드에서 **자동 승인되어 팝업 없이 리다이렉트**되는지
- 토스 SDK 공식 문서 기반으로 테스트키 동작 확인 (웹서치 허용)
