# [긴급] 블로그 에디터 이미지 2중 삽입 + 삭제 깨짐 + 번역 로직 디버깅

**[2026-03-20 11:54 KST] iMac/쌍아 → 막내2**

## 상황

한송이가 실무 중 보고: 블로그 에디터에서 사진 뱅크(이미지 라이브러리)로 본문에 이미지 삽입 시 2장씩 들어가고, 삭제하면 에디터가 깨짐. 또한 자동 3언어 번역(복사) 과정에서도 문제 발생.

## 버그 A: 이미지 2중 삽입

### 증상
사진 뱅크에서 "본문 삽입" 클릭 시 동일 이미지가 2장 삽입됨.

### 의심 지점

**파일**: `monkos_AI/portal/public/admin/blog-edit.html`

1. **이벤트 리스너 중복 바인딩** (라인 787-791, 946-953)
   - `insertImage()` 함수가 `editor.exec('addImage')`를 호출
   - Toast UI 에디터의 `addImage` exec command가 내부적으로도 이미지를 삽입할 수 있음
   - `showLibraryToolbar()`에서 매번 새 클릭 핸들러를 생성하면서 이전 핸들러가 제거되지 않을 가능성

2. **drag-drop 핸들러 간섭** (라인 1031-1041)
   - 이미지 라이브러리에서 클릭 삽입과 드래그 삽입이 동시 트리거될 가능성
   - `editorEl.addEventListener('drop')` 리스너가 매 라이브러리 로드마다 누적되는지 확인

### 디버깅 순서

```
1. insertImage() 호출 시점에 console.log 추가하여 호출 횟수 확인
2. editor.exec('addImage') 실행 전후 editor.getMarkdown() 스냅샷 비교
3. showLibraryToolbar() 내부에서 이벤트 위임 패턴 확인
   - 기존 핸들러가 removeEventListener 되는지
   - 또는 동일 요소에 중복 바인딩되는지
4. drop 이벤트와 click 이벤트가 동시에 발생하는 시나리오 재현
```

### 수정 방향

- `insertImage()` 함수에 **debounce 또는 플래그** 추가 (연속 호출 방지)
- 라이브러리 툴바 렌더링 시 **기존 이벤트 리스너 정리** (이벤트 위임으로 통일)
- drop 핸들러는 **최초 1회만 바인딩** (에디터 초기화 시점에)

## 버그 B: 이미지 삭제 시 에디터 깨짐

### 증상
삽입된 이미지의 "삭제" 버튼 클릭 시 에디터 레이아웃 또는 마크다운 동기화가 깨짐.

### 의심 지점

**파일**: `monkos_AI/portal/public/admin/blog-edit.html` (라인 934-944)

```javascript
// showEditorImageToolbar() 내부
{ label: '🗑 삭제', action: () => {
  img.parentElement?.remove() || img.remove();  // ← 문제
  updatePreview();
}}
```

1. **Toast UI WYSIWYG 내부 DOM 직접 조작 문제**
   - WYSIWYG 모드에서 `img.parentElement.remove()`는 Toast UI의 ProseMirror 내부 상태와 불일치 유발
   - 에디터가 자체 관리하는 DOM을 외부에서 삭제하면 에디터 상태가 corrupted됨

2. **마크다운 동기화 실패**
   - DOM에서 이미지를 삭제해도 마크다운 레이어의 `![alt](url)` 텍스트는 남아있을 수 있음
   - 이후 에디터 모드 전환(WYSIWYG ↔ 마크다운) 시 삭제된 이미지가 부활하거나 깨진 HTML 생성

### 디버깅 순서

```
1. 삭제 전후 editor.getMarkdown()과 editor.getHTML() 비교
2. 삭제 후 마크다운 모드로 전환하여 잔여 마크업 확인
3. Toast UI 에디터 공식 API에서 이미지 삭제 방법 확인
   - editor.exec() 커맨드 중 이미지 관련 명령 확인
   - 또는 에디터의 setMarkdown()으로 이미지 라인 제거 후 전체 갱신
```

### 수정 방향

- **DOM 직접 조작 대신 에디터 API 사용**:
  ```
  옵션 1: editor.getMarkdown() → 정규식으로 해당 이미지 마크다운 제거 → editor.setMarkdown()
  옵션 2: Toast UI exec command 중 이미지 삭제용 명령이 있는지 확인
  옵션 3: 커서를 이미지 위치로 이동 후 에디터의 deleteSelection 사용
  ```
- `updatePreview()` 호출 전에 **에디터 상태 정합성 확인** 로직 추가

## 버그 C: 자동 3언어 번역 문제

### 증상
자동 번역(JA/EN) 과정에서 문제 발생 (구체적 증상은 작업 중 재현하여 특정).

### 의심 지점

**파일**: `monkos_AI/portal/lib/cms/translate.js` (라인 49-128)

1. **번역본 덮어쓰기**: `blogCollection.doc(translatedSlug).set()` — merge 옵션 없이 전체 덮어씀
   - 기존 번역본의 viewCount, 발행 상태 등이 초기화될 수 있음

2. **번역본 createdAt**: 원본의 `createdAt`을 그대로 사용 → 시간순 정렬에서 원본과 동일 위치

3. **번역 slug 생성**: `${slug}-${lang}` 패턴 → 원본 slug가 변경되면 기존 번역본과 연결 끊김

4. **발행 상태 동기화 없음**: 원본이 draft→published 전환 시 번역본은 자동 갱신되지 않음

### 디버깅 순서

```
1. 번역 실행 시 기존 번역본 존재 여부 확인 로직 추가
2. set() → set({...}, { merge: true }) 전환 검토
3. 번역 후 Firestore에 실제 저장된 문서 필드 전수 확인
4. 프론트엔드 번역 버튼 클릭 시 응답 처리 확인 (에러 핸들링)
```

### 수정 방향

- **기존 번역본 존재 시**: `update()`로 내용만 갱신 (viewCount, createdAt 보존)
- **신규 번역본 시**: `set()`으로 생성 (현행 유지)
- `translatedAt` 필드 추가 → 마지막 번역 시점 기록
- 번역 완료 후 프론트엔드에 **결과 명확히 표시** (성공/실패/기존 갱신)
