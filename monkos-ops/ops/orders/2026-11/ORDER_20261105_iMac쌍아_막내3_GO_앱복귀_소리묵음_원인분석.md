## 1. 분석 (코드 + 1차 출처)
1. **WebKit 문서·버그 트래커에서 1차 출처를 찾아 정리한다.**
   - iOS Safari/WKWebView AudioContext의 `interrupted` 상태 정의
   - 전화·다른 앱 오디오 이후 복귀 동작
   - `resume()`이 사용자 동작(탭) 밖에서 거부되거나 무시되는 조건
   - state가 `running`인데 출력이 없는 사례
   - 출처는 webkit.org, bugs.webkit.org, W3C Web Audio 명세, MDN.
2. **현행 코드의 구멍을 가설로 정리한다.** 각 가설에 근거 출처와 확인 방법을 붙인다.
   - (a) `interrupted` 미처리
   - (b) 탭 밖 `resume()` 거부
   - (c) `running` 표시인데 출력 경로가 죽음 → 컨텍스트 재생성과 버퍼 재디코딩이 필요
   - (d) `actx = null` 이후 `decoded` 버퍼가 옛 컨텍스트에 묶여 있음
   - (e) PWA 단독 실행 모드에서만 생기는 차이
3. **타이젬과 공통인 이유를 정리한다.** 네이티브 앱의 오디오 세션 중단(AVAudioSession interruption) 처리 누락 유형과 대응 관계를 짧게 적는다. 우리 앱을 네이티브로 갈 때(PF_GO ⑥) 같은 함정을 피하려는 목적이다.
