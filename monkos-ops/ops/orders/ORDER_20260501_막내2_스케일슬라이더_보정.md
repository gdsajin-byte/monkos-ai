# [2026-05-01 18:40 KST] iMac/쌍아 → 막내2

## 문제

스케일을 슬라이더로 바꿨는데 내부 로직을 빠뜨렸다. 단순 CSS scale만 바꾸면 8포인트 좌표가 안 맞아서 수치(얼굴 mm, 눈 %, 여백)가 전부 틀어진다.

## 기존 crop.js 스케일 로직 (613~629행) — 이것을 유지

```js
// 스케일 변경 시 핵심 3단계:

// 1. imgScale 갱신
const newScale = Math.max(0.3, Math.min(4, dragStart.imgScale + sign * dist * 0.004));
imgScale = newScale;

// 2. 스케일 중심 계산 (프레임 중앙 + imgPos 오프셋)
const cx = FW / 2 + dragStart.imgPos.x;
const cy = FH / 2 + dragStart.imgPos.y;

// 3. 8포인트(pts) 전부를 중심 기준으로 비율 재계산
const ratio = newScale / dragStart.imgScale;
for (const k of Object.keys(dragStart.pts)) {
  next[k] = {
    x: cx + (dragStart.pts[k].x - cx) * ratio,
    y: cy + (dragStart.pts[k].y - cy) * ratio,
  };
}
pts = next;

// 4. renderUI() 호출 → 새 좌표 기반 수치 전부 갱신
```

**imgScale 변경 → pts 8포인트 좌표 변환 → renderUI → 수치 갱신**이 세트다.

## 수정 작업

### 1. 사진 위 스케일 네모 제거

`scaleHandle` 요소 제거. 사진 영역은 드래그(위치 조정) 전용.

### 2. 하단 스케일 슬라이더 추가

ICAO 허용범위 슬라이더 근처에 배치:

```html
<input type="range" id="scaleSlider" min="30" max="400" value="100" step="1">
<!-- value = imgScale * 100 -->
```

### 3. 슬라이더 → crop.js 스케일 로직 연결

```js
scaleSlider.addEventListener('input', (e) => {
  const newScale = parseInt(e.target.value) / 100;
  // 기존 스케일 로직 그대로 실행:
  // - imgScale 갱신
  // - pts 8포인트 중심 기준 비율 재계산
  // - renderUI() 호출
});
```

슬라이더가 바뀔 때마다 기존 onPtrMove의 `dragging === 'scale'` 분기와 **동일한 pts 변환 로직**을 실행해야 한다. 빠뜨리면 수치가 안 맞는다.

### 4. 정수리 드래그 원 축소

현재 반지름 절반 이하로 줄이기. 기능은 유지.

## 검증

1. 슬라이더 조작 → 사진 스케일 변경 + 수치(얼굴 mm, 눈 %, 여백) 실시간 갱신
2. 정수리 드래그 → 수치 갱신
3. 사진 드래그(위치) → 수치 갱신
4. 세 가지 조작 후 Canvas 크롭 출력이 화면과 일치
