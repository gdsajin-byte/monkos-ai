## 배경

ch4 8조 2항에 **"서버 미보관 원칙"**이 법률로 발효되었다:
> "서비스 파이프라인: 사진 업로드 → AI 처리 → 사용자 전달 → **서버에 보관하지 않는다.**"

기존 이미지프로(image-engine)에서는 Imagen 생성 이미지를 GCS 버킷에 저장 후 URL로 전달하는 방식이었으나, 속도 이슈 + 미선택 이미지 자동 저장 문제로 **프론트 직접 전달 방식으로 전환**한 경위가 있다. 단, 이미지프로의 이미지는 MONKOS 에셋(실인물 아님)이므로 별도 이슈가 아니다.

**증명사진 앱은 고객의 실제 얼굴 사진을 처리**하므로, 서버 미보관 원칙이 가장 엄격히 적용되어야 한다. 법률 선언과 실제 코드가 일치하는지 전수 확인이 필요하다.

## 임무

증명사진 관련 코드베이스에서 **고객 이미지(업로드 원본 + AI 생성 결과물)가 GCS 버킷, Firestore, 또는 서버 디스크에 저장되는 로직이 있는지** 전수 검사하라.

## 검사 대상

### 1. monkos_AI/ (Cloud Run 서비스)
- `monkos_AI/` 하위 전체 — 특히 idphoto-kr, idphoto-jp 관련 핸들러
- API 엔드포인트: `/api/idgen` 및 관련 라우트
- 이미지 처리 파이프라인 전 경로

### 2. MONK_kr/ (Cloudflare Pages)
- `MONK_kr/` 하위 — photolab 관련 코드
- `functions/` — CF Workers (API 핸들러)

### 3. 공통 확인 사항
- GCS 버킷 업로드 로직 (`@google-cloud/storage`, `bucket.upload`, `file.save` 등)
- Firestore 이미지 데이터 저장 (`set`, `add`, `update`에 이미지 바이너리/base64/URL 포함 여부)
- 서버 디스크 저장 (`fs.writeFile`, `writeFileSync`, `/tmp/` 등에 이미지 기록)
- 외부 스토리지 API 호출 (R2, S3 등)
