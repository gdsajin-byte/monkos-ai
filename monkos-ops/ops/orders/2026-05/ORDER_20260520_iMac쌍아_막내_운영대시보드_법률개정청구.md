# 지시서: 운영 대시보드 기획 + ch4 10조 개정 청구안

> **[2026-05-20 10:43 KST] iMac/쌍아 → iMac/막내1(대시보드), iMac/막내2(법률 타당성)**

## 배경

작가님이 가입자 현황, 크레딧 상태, 로그인 통계 등 운영 데이터를 일상적으로 확인해야 하는데, 현재는 직접 조회 수단이 없다. ch4 10조는 "에이전트의 자율적 크레딧 변경"을 막기 위해 제정되었으나, **작가님의 읽기(조회) 접근**까지 제한하는 부작용이 있다. 읽기와 쓰기를 분리하고, 작가님이 자율적으로 확인 가능한 대시보드 채널을 구축해야 한다.

### 현황 문제점

1. **가입자 현황 확인 불가** — provider별(카카오/구글/LINE) 가입자 수, 최근 가입, 재방문율 등 기본 지표를 볼 방법이 없음
2. **credits.sh만으로는 한계** — 개별 이메일 조회만 가능. 전체 목록, 통계, 트렌드 불가
3. **ch4 10조 범위 과다** — "Firestore 직접 접근 금지"가 읽기까지 포함하여 작가님 운영 가시성 차단
4. **GA4/Firebase 대시보드 미활용** — 이미 인프라가 있으나 연동·커스텀 미완

## 막내1: 운영 대시보드 기획

### 작업 내용

#### 1-A. 현재 데이터 소스 파악

| 소스 | 데이터 | 접근 방법 | 현황 |
|------|--------|----------|------|
| Firestore `users` | 가입자, provider, 크레딧, 로그인 이력 | credits.sh (제한적) | 개별 조회만 |
| Firestore `audit` | 크레딧 변경 이력 | credits.sh log | 최근 N건 |
| GA4 | 페이지뷰, 이벤트, 유입 경로 | Google Analytics 콘솔 | 미커스텀 |
| Firebase Analytics | 앱 이벤트 (향후 IDPASS) | Firebase 콘솔 | 미연동 |
| Cloud Run 로그 | 서버 요청, 에러 | Cloud Logging | 원시 로그 |
| GSC | 검색 노출, 클릭, 키워드 | Search Console | 연동 완료 |

#### 1-B. 대시보드 방안 비교

아래 3가지 방안을 비교 평가하여 추천안을 제시:

**방안 A: Firestore → 어드민 페이지 (자체 구축)**
- monkos.ai/admin에 운영 대시보드 페이지 추가
- 기존 어드민 패널(blog, board, faq, gallery) 구조 활용
- Firestore 직접 읽기 (서버사이드, 인증 필요)

**방안 B: Firestore → Google Sheets 자동 동기화**
- Cloud Functions / 스케줄러로 일일 스냅샷 → Google Sheets
- 작가님이 GDrive에서 바로 확인 (팀원 공유 가능)
- 접점 2개 원칙(텔레그램+GDrive) 부합

**방안 C: GA4 + BigQuery + Looker Studio**
- GA4 데이터 → BigQuery export → Looker Studio 대시보드
- 가장 강력하나 설정 복잡도 높음

**방안 D: 하이브리드**
- 일일 요약 → 텔레그램 봇 (핵심 KPI 3줄)
- 상세 → Google Sheets 또는 어드민 페이지
- 트렌드 → GA4 기본 대시보드

#### 1-C. 대시보드 KPI 제안

작가님이 매일 봐야 할 핵심 지표 목록 제안:

| 카테고리 | 지표 예시 |
|---------|----------|
| 가입 | 오늘 신규, 누적, provider별 분포 |
| 활성 | DAU, 재방문율, 마지막 로그인 분포 |
| 크레딧 | 총 보유량, 오늘 충전/차감, 잔액 분포 |
| 서비스 | AI 생성 수, 크롭 수, 에러율 |
| SEO | 노출, 클릭, CTR (GSC 데이터) |
| 매출 | 결제 건수, 금액 (현재 0 — 추적 체계만 준비) |

## 막내2: ch4 10조 개정 타당성 검토 + 청구안

### 작업 내용

#### 2-A. 현행 ch4 10조 분석

- `governance/laws/ch4_docs_structure.md` 10조 전문 읽기
- `.claude/rules/data-access.md` 현행 규칙 확인
- 제정 취지 파악: 어떤 사고를 방지하기 위한 것인지

#### 2-B. 문제점 도출

- **범위 과다**: 쓰기(변경) 보호 목적인데 읽기(조회)까지 차단
- **작가님 가시성 차단**: 운영자가 자기 서비스 데이터를 못 봄
- **credits.sh 병목**: 모든 접근이 단일 스크립트에 의존 — 목록 조회, 통계, 대시보드 불가
- **실무 우회 발생**: 결국 작가님 특별 지시로 직접 조회 → 법률이 실무와 괴리

#### 2-C. 개정 청구안 작성

헌법 5조 3항(청구권)에 근거하여 개정안 제시:

- **읽기/쓰기 분리**: 조회(query/list/stats)는 에이전트 자율 허용, 변경(charge/deduct)만 작가님 승인 필수
- **대시보드 경로 신설**: credits.sh 외에 어드민 대시보드 / API 조회 경로 공인
- **감사 범위 조정**: 변경만 감사 로그 필수, 조회는 로그 선택적
