# 지시서: 202개국 규격 DB D1 시딩

## 배경

D1 `documents` 테이블에 현재 112건(주요 국가)만 들어있다. `countries.jsonl`(202개국, 각국 평균 2~3규격)의 전체 데이터를 이관해야 한다. 파라과이 등 비주요 국가 규격 질문에 챗봇이 답하지 못하는 상태.

## 소스 데이터

`apps/MonkosCrop/MonkosCrop/Resources/countries.jsonl` — 202줄, 각 줄 JSON

형식 예시:
```json
{"id": "py", "ko": "파라과이", "en": "Paraguay", "ja": "パラグアイ", "continent": "americas", "docs": []}
```

- `docs` 배열이 비어있는 국가 → ICAO 기본 규격(여권 35x45, 비자 35x45) 적용
- `docs` 배열에 커스텀 규격이 있는 국가 → 해당 규격 사용

## 현재 D1 테이블 구조

### countries 테이블 (202행 — 이미 존재)
```sql
-- id, name_ko, name_en, name_ja, continent 등
```

### documents 테이블 (112행 — 부족)
```sql
-- id, country_id, type, name_ko, name_en, name_ja, size_display, ...
```

## Task

1. `countries.jsonl`을 읽어서 현재 `documents`에 없는 국가의 규격을 INSERT하는 SQL 생성
2. `docs` 배열이 있는 국가 → 해당 규격 INSERT
3. `docs` 배열이 비어있는 국가 → ICAO 기본 규격 2건(여권, 비자) INSERT:
   - 여권: type=passport, size_display=35x45, standard=ICAO 9303
   - 비자: type=visa, size_display=35x45, standard=ICAO 9303
4. 기존 112건과 중복되지 않도록 `INSERT OR IGNORE` 사용
5. SQL 파일: `migrations/seed_specs_full.sql`
6. 리모트 실행: `npx wrangler d1 execute monk-db --file=migrations/seed_specs_full.sql --remote`

## 검증

실행 후 확인:
```sql
SELECT COUNT(*) FROM documents;  -- 예상: 500+ 행
SELECT d.*, c.name_ko FROM documents d JOIN countries c ON d.country_id = c.id WHERE c.name_en = 'Paraguay';
```
