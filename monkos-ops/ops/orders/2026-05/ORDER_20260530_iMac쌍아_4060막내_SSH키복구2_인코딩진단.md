# ORDER — SSH 키 복구 2차 (인코딩 진단)

## 현 상태

- 1차 지시서(ACL 복구) 완료 보고 받음. 키 존재·sshd_config·ACL·재시작 전부 정상 보고됨.
- **그러나 iMac→4060 SSH 여전히 `Permission denied`.** verbose상 iMac은 올바른 키를 제시하나 서버가 거부 → 키 파일 **파싱 실패** 의심.
- **최우선 의심: 파일 인코딩(BOM/UTF-16).** PowerShell `Add-Content`는 키를 BOM 붙은 UTF-8 또는 UTF-16으로 저장할 수 있고, 그러면 `Get-Content`로는 정상 보여도 **sshd가 키 라인을 못 읽는다.**

---

## Step A — 키 파일을 BOM 없는 UTF-8로 재작성 (관리자 PowerShell)

```powershell
# 0) 인코딩 확인 — 첫 바이트가 EF BB BF(UTF-8 BOM) 또는 FF FE(UTF-16)면 그게 원인
Format-Hex C:\ProgramData\ssh\administrators_authorized_keys | Select-Object -First 2

# 1) BOM 없는 UTF-8 + LF로 재작성 (키 1줄만)
$key = "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAICstbhz9x1KMT00ZxMVZKK5Rhsn4yoSP0KC3u0p+cXCd jeong-kyushin@monk.kr"
[IO.File]::WriteAllText("C:\ProgramData\ssh\administrators_authorized_keys", $key + "`n", (New-Object System.Text.UTF8Encoding $false))

# 2) ACL 재적용 (재작성으로 권한이 바뀌었을 수 있음)
icacls C:\ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant "SYSTEM:(F)" /grant "Administrators:(F)"

# 3) sshd 재시작
Restart-Service sshd

# 4) 재작성 후 인코딩 재확인 (BOM 사라졌는지 — 첫 바이트가 73 's'여야 정상)
Format-Hex C:\ProgramData\ssh\administrators_authorized_keys | Select-Object -First 2
```

→ 완료 후 **iMac/쌍아에 보고**. iMac이 `ssh 4060 'hostname'` 재검증.

---

## Step B — Step A로도 안 되면: sshd 디버그로 거부 사유 확정

> iMac과 실시간 협업. Step A 실패 보고 시 iMac이 별도 신호.

```powershell
# 기존 sshd 멈추고 디버그 인스턴스를 임시 포트로 띄움
Stop-Service sshd
& 'C:\Windows\System32\OpenSSH\sshd.exe' -d -p 2222
# ↑ 이 창을 띄워둔 채 대기 — iMac이 ssh -p 2222 접속하면 콘솔에 거부 사유 한 줄 출력됨
```

- iMac이 `ssh -p 2222 4060` 시도 → **4060 콘솔에 찍히는 거부 사유 전문**(예: `Authentication refused: bad ownership or modes`, `key_read: ...`)을 보고에 첨부.
- 확인 후 디버그 인스턴스 Ctrl+C 종료 → `Start-Service sshd`로 정상 복구.
