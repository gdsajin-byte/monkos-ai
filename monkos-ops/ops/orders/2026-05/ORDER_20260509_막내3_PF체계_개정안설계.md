# 지시서: PF 체계 개정안 설계 — 정본 통일 + 히스토리 카테고리 + 환류 규율

## 배경

- PF 정본이 루트 md / 폴더 README / 양쪽 병존으로 3분화 (오늘 쌍아 진단)
- 히스토리 테이블에 "분류(카테고리)" 열이 없어 시계열은 있으나 성격별 분류 불가
- 세션로그→PF 히스토리 환류가 규율상 의무이나 실제로는 누락 빈번
- PF 인덱스(README) 16개 중 7개만 등록
- 이 지시서는 막내1(현행 진단) + 막내2(클로드 정책)의 리서치 결과를 **선행 참조하지 않고** 독립적으로 개정안을 설계한다. 추후 쌍아가 3권을 종합.

## 임무

### 1. 현행 실태 확인

아래를 읽어 현재 PF 체계의 물리적 실태를 파악:

- `monkos-ops/ops/portfolios/` 전체 (README, PF_*.md, 폴더형 PF)
- `monkos-ops/ops/portfolios/PF_TEMPLATE.md`
- 대표 PF 3개 이상의 히스토리 테이블 구조 비교

### 2. 개정안 설계 — 4개 축

#### A. 정본 위치 통일안

- 파일형(PF_*.md)과 폴더형(PF_*/README.md)을 어떻게 통일할 것인가
- 폴더가 필요한 PF의 기준은 무엇인가 (예: 부속 문서 3개 이상 시 폴더화)
- 이중 존재(PF_CDP.md + PF_CDP/README.md) 해소 방안
- 마이그레이션 플랜 (기존 PF 이동 시 git 이력 보존)

#### B. 히스토리 카테고리 열 신설안

현재: `| 날짜 | 주체 | 내용 | 산출물 | 상태 |`

제안할 것:
- 어떤 열을 추가할 것인가 (분류? 태그?)
- 카테고리 체계 설계: 전 PF에 공통 적용 가능한 분류 목록 (예: 개발/디버깅/리팩토링/진단/설계/배포/전략/성과)
- 기존 히스토리 소급 적용 여부 (비용 vs 효용)
- PF_TEMPLATE.md 개정 초안

#### C. 세션로그→PF 환류 규율 강화안

- 현재 "쌍아가 수행" 규칙의 실효성 문제 (쌍아 세션이 없는 날 누락)
- 막내/민아가 직접 PF 히스토리에 1줄 어펜드하는 방안 vs 현행 유지
- 세션 마감 체크리스트에 PF 갱신 항목 추가 방안
- 자동화 가능 여부 (스킬/훅 활용)

#### D. PF 인덱스 관리안

- README 인덱스 갱신 주기/주체/트리거 정의
- PF 생성 시 인덱스 자동 등록 프로세스

### 3. 각 안의 장단점 + 추천안

각 축(A~D)마다:
- 선택지 2~3개 제시
- 장단점 비교
- 추천안 1개 + 근거
