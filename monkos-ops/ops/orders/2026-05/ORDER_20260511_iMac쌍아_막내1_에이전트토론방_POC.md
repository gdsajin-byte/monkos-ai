# 지시서: 에이전트 토론방 웹 UI POC

## 배경

- 에이전트 간 실시간 토론 POC 1단계 성공 (파일 기반, debate.sh)
- 2단계: 웹 UI로 업그레이드 — 사람도 참여 가능한 대화창
- CF Pages(프론트) + CF Worker(백엔드) + Workers AI(모델) — 비용 0
- 기존 monk.kr 인프라 활용

## 아키텍처

```
프론트 (HTML/CSS/JS — 단일 파일 가능)
  · 채팅 UI: 메시지 목록 + 입력창 + 보내기 버튼
  · localStorage에 대화 히스토리 저장 (세션 메모리)
  · Enter 또는 보내기 클릭 → Worker에 POST
  · 에이전트 응답 수신 → 화면에 추가
       │
CF Worker (백엔드 API)
  · POST /api/debate
  · 입력: { messages: [...전체 히스토리], sender: "사람"|자동 }
  · 턴 로직으로 다음 응답자 결정
  · Workers AI 호출 (모델별 시스템 프롬프트)
  · 응답 반환: { speaker: "에이전트1", message: "...", next_auto: true|false }
  · next_auto=true면 프론트가 자동으로 다음 턴 호출
       │
Workers AI
  · 에이전트1: @cf/google/gemma-3-12b-it (또는 gemma-4-26b)
  · 에이전트2: @cf/alibaba/qwen3-30b-a3b (또는 qwen2.5)
```

## 임무

### 1. 프론트엔드 — `apps/debate/index.html`

단일 HTML 파일. 외부 의존성 없이 vanilla JS.

**UI 구성:**
```
┌─────────────────────────────────────┐
│  MONK 토론방                    [설정]│
│                                     │
│  ┌─────────────────────────────────┐│
│  │ (대화 메시지 영역 — 스크롤)     ││
│  │                                 ││
│  │ [에이전트1] 메시지...           ││
│  │ [에이전트2] 메시지...           ││
│  │ [작가님] 메시지...              ││
│  │ [에이전트1] 메시지...           ││
│  └─────────────────────────────────┘│
│                                     │
│  ┌─────────────────────┐ [보내기]   │
│  │ 메시지 입력...       │           │
│  └─────────────────────┘           │
│                                     │
│  [주제 설정] [자동 토론 시작] [초기화]│
└─────────────────────────────────────┘
```

**기능:**
- 메시지 입력 → Enter 또는 보내기 클릭 → Worker POST
- 에이전트 메시지는 화자별 색상 구분 (에이전트1: 파랑, 에이전트2: 초록, 사람: 회색)
- 대화 히스토리 → localStorage 저장/복원
- "자동 토론 시작" 버튼: 주제 입력 → 에이전트끼리 자동 진행 (라운드 제한)
- "초기화" 버튼: 대화 초기화
- 설정: 에이전트 이름, 모델 선택, 라운드 수, 시스템 프롬프트 커스텀

**자동 토론 모드:**
- 주제 설정 후 "자동 토론 시작" 클릭
- 에이전트1 입론 → 에이전트2 반론 → 에이전트1 재반론 → ... (라운드 N회)
- 각 턴 사이 1~2초 딜레이 (UI에서 타이핑 효과)
- 사람이 중간에 메시지 입력하면 자동 진행 중단 → 사람 메시지에 우선 응답

### 2. 백엔드 — CF Worker

Worker 이름: `monk-debate` (또는 기존 Worker에 라우트 추가)

**엔드포인트: POST /api/debate**

```javascript
// 요청
{
  messages: [
    { role: "system", content: "주제: ..." },
    { role: "agent1", content: "..." },
    { role: "agent2", content: "..." },
    { role: "human", content: "..." }
  ],
  next_speaker: "agent1" | "agent2" | "auto",
  config: {
    agent1: { name: "에이전트1", model: "@cf/google/gemma-3-12b-it" },
    agent2: { name: "에이전트2", model: "@cf/alibaba/qwen3-30b-a3b" },
    max_rounds: 3
  }
}

// 응답
{
  speaker: "에이전트1",
  message: "...",
  next_auto: true,  // 다음 턴도 자동 진행할지
  round: 2,
  done: false
}
```

**턴 로직:**
```
사람 메시지 → 에이전트1 응답 → 에이전트2 응답 (자동)
에이전트1 발언 후 → 에이전트2 차례 (자동)
에이전트2 발언 후 → 에이전트1 차례 (자동)
라운드 N 도달 → done: true
사람 개입 → 자동 진행 중단, 사람 질문에 둘 다 응답
```

**시스템 프롬프트 (각 에이전트):**

에이전트1:
```
당신은 토론 참가자입니다.
이름: {agent1.name}
역할: 주어진 주제에 대해 자신의 입장을 논리적으로 주장합니다.
규칙:
- 상대 발언을 인용한 뒤 반론 (근거 필수)
- 근거 없는 동의 금지
- 2~5문장으로 간결하게
- 사람(작가님)이 질문하면 토론보다 우선 응답
- 최종 라운드에서는 합의점과 미결 사항을 정리
```

### 3. Workers AI 모델 바인딩

wrangler.toml에 AI 바인딩 추가 (이미 monk-kr에 있을 수 있음):

```toml
[ai]
binding = "AI"
```

### 4. 로컬 테스트

`wrangler dev`로 로컬 테스트 후, `wrangler deploy`로 배포.
또는 일단 `apps/debate/index.html`을 로컬에서 열어 테스트 (Worker URL 직접 지정).

### 5. 테스트 시나리오

**시나리오 A: 자동 토론**
1. 주제 입력: "1B 파인튜닝 vs 12B 양자화"
2. "자동 토론 시작" 클릭
3. 3라운드 자동 진행 확인
4. 합의/미결 정리 확인

**시나리오 B: 사람 개입**
1. 자동 토론 진행 중
2. 사람이 "그러면 비용은?" 메시지 입력
3. 자동 진행 중단 → 두 에이전트가 비용 관점 응답
4. 이후 자동 재개 또는 사람 추가 질문

**시나리오 C: 사람 주도**
1. 사람이 질문 → 에이전트1 답변 → 에이전트2 보충/반론
2. 대화형으로 진행
