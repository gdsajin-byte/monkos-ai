# 지시서: 문서 체계 전수 스캔 — 활성/비활성 판정

## 배경

- 프로젝트 운용 5개월 차. governance/, monkos-ops/, docs/ 등에 문서가 축적
- 활성화된 파트와 사실상 등외시된 파트가 혼재
- 전수 스캔으로 현황 지도를 만들어 정비 우선순위를 도출

## 임무

### 1. 대상 폴더 트리 스캔

아래 최상위 폴더들의 **하위 구조를 전부** 탐색하여 파일 목록을 확보:

```
governance/          — 법률+역사+철학
monkos-ops/          — 운영 체계
  ops/               — 세션로그, 지시서, 보고서, PF, 어젠다
  tech/              — 기술 명세, 가이드, 배포
  contents/          — 콘텐츠
  marketing/         — 마케팅
docs/                — 참고문헌+아카이브
```

### 2. 각 하위 폴더별 판정

폴더 단위로 다음을 기록:

| 폴더 경로 | 파일 수 | 최신 수정일 | 마지막 갱신 에이전트 | 활성 판정 | 비고 |
|-----------|---------|-----------|-------------------|----------|------|

**활성 판정 기준:**
- **활성**: 최근 30일 내 수정 또는 현재 진행 PF/작업과 연결
- **반활성**: 30~90일 미수정이나 향후 참조 가치 있음
- **비활성**: 90일+ 미수정, 현행 체계와 단절
- **레거시**: 구 체계 잔류물 (구 네이밍, 폐지된 구조)
- **정본 충돌**: 동일 내용이 2곳 이상 존재

### 3. 특별 점검 항목

1. **governance/philosophy/**: 어떤 철학 문서가 있고, memory/ 이관 대상과 중복되는지
2. **governance/laws/**: 8장 법률 외에 다른 파일이 있는지
3. **monkos-ops/tech/**: specs, guides, designs, deployment 각각의 활성도
4. **monkos-ops/contents/**: 콘텐츠 파이프라인 실태
5. **monkos-ops/marketing/**: 마케팅 전략 문서 실태
6. **docs/**: 아카이브 대상인데 활성으로 오인될 문서가 있는지
7. **monkos-ops/ops/reports/**: 월별 폴더 구조와 보고서 축적 실태
8. **monkos-ops/ops/orders/**: 지시서 축적 실태 (미실행/완료/폐기 비율)
