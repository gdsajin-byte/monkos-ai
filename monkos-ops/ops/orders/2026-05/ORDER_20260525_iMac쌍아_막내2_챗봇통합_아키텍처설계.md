# 지시서: 챗봇 통합 설계 보고서 (2/2) — 아키텍처 + 마이그레이션 계획

## 배경

monk.kr(CF Pages, Gemma 3)과 monkos.ai(Cloud Run, Gemini 2.0)의 챗봇을 **CF Workers AI(Gemma 4 26B MoE) + D1** 단일 엔진으로 통합한다.

**핵심 결정 사항** (작가님 확정):
- 모델: Gemma 4 26B A4B (`@cf/google/gemma-4-26b-a4b-it`)
- 인프라: CF Workers AI + D1 (RAG 지식 저장)
- 호출 구조: monk.kr → 직접 호출 / monkos.ai(Cloud Run) → CF Workers HTTPS fetch
- Firestore RAG 지식 → D1 이관
- 대화 로깅: 기존 Firestore 유지 가능 (쓰기 전용이라 병목 아님)

## Task 1: 통합 아키텍처 설계

### 설계할 구조
```
[monk.kr CF Pages] ──→ CF Workers (Gemma 4 + D1 RAG) ←── [monkos.ai Cloud Run]
     ↑                         ↑                              ↑
   웹 채팅               통합 챗봇 엔진                  웹/텔레/카카오/LINE/코칭
```

### 설계 포함 항목

#### 1) CF Workers 통합 엔진 설계
- API 엔드포인트 설계 (`/api/chat` 통합)
- 채널 분기 로직 (channel 파라미터로 프롬프트/설정 분기)
- 인증/CORS 설계 (monk.kr, monkos.ai 양쪽 허용)
- 에러 핸들링 + 폴백 전략

#### 2) 채널별 시스템 프롬프트 관리
현재 monkos.ai의 `prompts.js` 채널 설정을 분석:

| 채널 | 현행 파일 | 프롬프트 | temp | max_tokens |
|------|----------|---------|------|-----------|
| web (monkos) | chat-engine.js | SYSTEM_PROMPT_KR | 0.7 | 300 |
| web (monk.kr) | functions/api/chat.js | 몽크사진관 전용 | 0.7 | 300 |
| telegram | chat-engine.js | CS_SYSTEM_PROMPT | 0.5 | 500 |
| kakao | chat-engine.js | SYSTEM_PROMPT_KR + 카카오 안내 | 0.7 | 300 |
| idphoto-kr | chat-engine.js | SYSTEM_PROMPT_KR | 0.7 | 300 |
| idphoto-jp | chat-engine.js | SYSTEM_PROMPT_JP | 0.7 | 300 |
| line | chat-engine.js | SYSTEM_PROMPT_JP | 0.7 | 300 |
| prep | chat-engine.js | PREP_SYSTEM_PROMPT | 0.6 | 400 |
| coaching | chat-engine.js | COACHING_INSTRUCTIONS | 0.3 | 50 |

→ 통합 Workers에서 이 설정을 어떻게 관리할지 설계 (D1 테이블 vs 코드 내장 vs KV)

#### 3) D1 스키마 설계
- `chat_knowledge` — RAG 지식 (카테고리, 키워드, 다국어 콘텐츠)
- `chat_specs` — 202개국 증명사진 규격 (countries.jsonl 이관)
- `chat_prompts` — 채널별 시스템 프롬프트 (선택)
- `chat_logs` — 대화 기록 (선택 — Firestore 유지 vs D1 이관 판단)

#### 4) 호출 인터페이스 설계
- monk.kr → Workers: 현행 `/api/chat` 유지, 모델만 교체
- monkos.ai → Workers: Cloud Run에서 Workers URL fetch
  - 인증 방식 (API Key? CF Access Token? IP allowlist?)
  - 타임아웃/리트라이 전략
  - 대화 히스토리 전달 방식

## Task 2: Gemini → Gemma 4 전환 영향 분석

### 분석 항목
1. **모델 능력 차이**: Gemini 2.0 Flash vs Gemma 4 26B
   - 한국어/일본어 품질 비교
   - 시스템 프롬프트 준수력 (할루시네이션 차단, 응답 규칙)
   - 멀티모달 지원 여부 (코칭 채널은 이미지 입력 필요)
2. **코칭/QC 채널 호환성**: 현행 `coaching` 채널은 이미지를 `inlineData`로 전달 — Workers AI에서 Gemma 4 비전 입력 가능한지 확인
3. **응답 형식**: Gemini의 `candidates[0].content.parts[0].text` vs Workers AI의 `response` 필드 차이
4. **토큰 제한**: Gemma 4 256K 컨텍스트에서 RAG + 히스토리 + 프롬프트 예산 설계

## Task 3: 마이그레이션 단계 계획

### 제안 단계
- **Phase 0**: 현황 확인 + 테스트 (지금)
- **Phase 1**: monk.kr Gemma 3 → Gemma 4 모델 교체 (1줄 변경, 즉시 가능)
- **Phase 2**: D1 RAG 테이블 생성 + 데이터 시딩
- **Phase 3**: CF Workers 통합 엔진 개발 (채널 분기, RAG 검색, 프롬프트 관리)
- **Phase 4**: monkos.ai 채널을 Workers 엔진으로 전환 (Cloud Run → Workers fetch)
- **Phase 5**: Firestore RAG 읽기 제거 + 정리

각 Phase별:
- 소요 시간 추정
- 필요 리소스 (wrangler 설정, D1 마이그레이션 등)
- 롤백 전략
- 검증 방법

## Task 4: 비용 비교 분석

### 비교표 작성
| 항목 | 현행 (분산) | 통합 후 (CF 중심) |
|------|-----------|----------------|
| 모델 비용 | Gemini Flash 유료 + Gemma 3 무료 | Gemma 4 무료 티어 |
