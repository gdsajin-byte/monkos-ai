### 로직

```
Phase 1: 크롤링 + 변주
  1. 각 sourceUrl의 모바일 버전(m.blog.naver.com) 풀 크롤링
     - 기존 importer/naver.js의 모바일 파싱 로직 참조
  2. 풀 본문 확보 후 Gemini 2.0 Flash로 변주 (리라이팅)
     - 프롬프트 핵심: "동일한 정보와 구조를 유지하되, 문장을 자연스럽게 재구성하라.
       핵심 키워드와 전문 용어는 보존. 문체는 원본 톤 유지.
       네이버 유사문서 탐지를 회피할 수 있을 정도의 변주."
     - 원본 의미/정보량 100% 보존 (삭제/추가 금지)
     - 마크다운 형식 출력

Phase 2: 이미지 GCS 마이그레이션
  1. 크롤링된 풀 본문 + 기존 Firestore content에서 pstatic.net URL 전체 수집
  2. Referer 없이 다운로드 → GCS monk-ai-images/blog/ 업로드
  3. 새 GCS URL로 content + thumbnail 교체

Phase 3: Firestore 업데이트
  1. KO 원본 15건: content 교체 (변주된 풀 본문 + GCS 이미지)
  2. thumbnail: GCS URL로 교체
  3. 기존 EN/JA 번역본: 삭제하지 말 것 (Phase 4에서 재번역)

Phase 4: 재번역
  1. 복구된 KO 원본 15건에 대해 translateAndSaveBlogPost() 재실행
  2. 이번엔 풀 본문 + GCS 이미지이므로 EN/JA도 정상 생성됨
  3. translate.js의 이미지 보존 검증 로직이 이미 적용되어 있음
```

### 주의사항

- **dry-run 먼저**: 크롤링 결과 (글별 원본 글자수 vs 현재 글자수) 보고
- 네이버 URL 다운로드 시 **Referer 헤더 절대 붙이지 말 것**
- 변주 결과를 **작가님에게 1~2건 샘플로 보여준 후** 전체 실행
- 동일 네이버 이미지 URL → 1회만 다운로드 (캐시 맵)
- note.com URL (`st-note.com`)은 이번 대상 아님
- **기존 EN/JA 번역본의 slug는 유지** — content만 재번역으로 덮어씀
