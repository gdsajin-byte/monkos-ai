## 조사 범위

### 1. 연령×용도×성별 매트릭스 전수 검증

아래 조합별로 각 스텝에서 **실제로 표시되는 옵션 목록**을 표로 정리:

| 용도 | 연령 | 성별 | 의상 옵션 | 의상컬러 | 넥타이 | 헤어 | 배경 | 표정 |
|------|------|------|----------|---------|-------|------|------|------|

**검증 기준**: 각 조합에서 "이 연령대에 이 옵션이 말이 되는가?"

예시:
- `baby` + `passport` → 의상에 `suit`, `shirt` 표시되면 ❌
- `preschool` + `student_id` → 학생증에 미취학 아동? ❌
- `baby` → 넥타이 스텝이 표시되면 ❌

### 2. 의상 필터의 연령 미반영 문제

현재 `CLOTHING_FILTER`는 **용도(purpose)만 기준**이고 **연령(age)을 고려하지 않음**.

```javascript
// 현재 — 용도 기반만
CLOTHING_FILTER = {
  passport: ['as_is', 'suit', 'shirt', 'casual'],
  // ...
};
```

**필요**: 연령이 `baby`, `preschool`일 때 `suit`, `shirt` 등 성인 의상이 필터링되는지 확인. 안 되면 보고.

### 3. 넥타이 스킵 조건의 연령 미반영

현재 스킵 조건:
```javascript
// STEP 6 (tie): 남성 + (정장 or 셔츠)가 아니면 스킵
if (key === 'tie') {
  return selections.gender !== 'male' || !['suit', 'shirt'].includes(selections.clothing);
}
```

**확인**: `baby` + `male` + `suit` 선택 시 넥타이 스텝이 표시되는지. 표시되면 ❌

### 4. 헤어 옵션 프롬프트 매핑 검증

현재 헤어 옵션과 서버 프롬프트:

| 옵션 | val | 서버 프롬프트 |
|------|-----|-------------|
| 그대로 | `as_is` | `null` (프롬프트 미추가) |
| 정돈 | `tidy` | `neatly groomed hair` |
| 올림머리 | `up` | `hair tied up neatly` |
| 내림머리 | `down` | `hair down, well-groomed` |

**조사 항목**:
- `up` (올림머리): "머리를 묶어 올린" 의미 → 연령/성별 무관하게 적절한가? baby에게?
- `down` (내림머리): "머리를 내린" 의미 → 올림머리와의 대비가 맞는가?
- 연령별로 올림/내림이 의미 있는 조합인지 판단
- 헤어 옵션에도 연령 필터가 필요한지 의견 제시

### 5. 표정 옵션 "그대로" 부재 검증

현재 표정 옵션:
```javascript
expression: [
  { val: 'gentle_smile',  icon: '😊', title: '잔잔한 미소' },
  { val: 'neutral',       icon: '😐', title: '무표정' },
  { val: 'natural_smile', icon: '😄', title: '자연스러운 미소' },
  { val: 'bright_smile',  icon: '😁', title: '밝은 미소' },
],
```

**문제**: `as_is` (그대로)가 없음. 의상과 헤어에는 있음.

서버 프롬프트에서 expression은 `as_is`일 때 어떻게 처리되는지:
```javascript
// 현재: expression은 항상 프롬프트에 추가됨 (as_is 분기 없음)
if (expression) {
  const exprDesc = EXPRESSION_PROMPTS[expression];
  if (exprDesc) parts.push(`[EXPRESSION] ${exprDesc}`);
}
```

**조사**:
- `as_is` 추가 시 서버에서 expression 프롬프트를 아예 빼면 되는지 검증
- "그대로"가 디폴트인 게 UX상 자연스러운지 의견

### 6. 디폴트값 정합성 검증

현재 DEFAULTS 테이블:
```javascript
DEFAULTS = {
  passport: { clothing: 'as_is', hair: 'as_is', background: 'white', expression: 'gentle_smile' },
  student_id: { clothing: 'as_is', hair: 'as_is', background: 'white', expression: 'gentle_smile' },
  employee_id: { _gender: { male: {...}, female: {...} } },
  resume: { _gender: { male: {...}, female: {...} } },
  color_portrait: { clothing: 'as_is', hair: 'as_is' },
};
```

**조사 항목**:
- "그대로"가 디폴트인 항목과 아닌 항목 전수 대조
- 연령별 디폴트 분기가 없음 — 필요한지 의견
- 사원증 남성 디폴트가 `suit + navy + stripe_navy`인데, 연령이 baby일 수 있는 구조적 모순 확인

### 7. 서버 프롬프트 buildPrompt() 연령 반영 검증

서버의 `buildPrompt()` (server.js:251~)에서:
- `getAgeGenderPrompt(age, gender)` 함수가 연령별 outfit을 지정하는데, prep.js의 clothing 선택과 충돌 가능성 확인
- 예: 사용자가 `baby`를 선택하고 의상을 `suit`로 골랐을 때, 서버에서 "baby outfit"과 "formal suit"가 동시에 프롬프트에 들어가는지

### 8. 스킵 로직 전수 검증

shouldSkip() 함수의 모든 조건을 열거하고, 연령×용도×성별 매트릭스에서 의도치 않게 표시되거나 스킵되는 케이스 보고.
