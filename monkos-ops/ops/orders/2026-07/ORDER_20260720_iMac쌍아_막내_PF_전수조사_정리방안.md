## Task

### Task 1 — 전수 실측

31개 PF 디렉토리 전량에 대해 아래 항목을 측정:

```bash
# 각 PF_*/README.md에 대해:
wc -l     # 줄 수
wc -c     # 바이트
grep -c "^|" # 히스토리 테이블 행 수 (근사)
head -10   # YAML frontmatter status 필드
```

결과를 아래 형식의 테이블로 정리:

| PF | status(YAML) | 줄수 | 바이트(KB) | 히스토리 행 | 500줄 초과 | 40KB 초과 | 100행 초과 | 최종 갱신일 |
|---|---|---|---|---|---|---|---|---|

최종 갱신일은 `git log -1 --format="%ai" -- PF_*/README.md`로 실측.

### Task 2 — 인덱스 정합 점검

`portfolios/README.md` 인덱스의 각 PF status와 Task 1에서 실측한 YAML status를 대조. 불일치 목록 작성.

### Task 3 — 정리 방안 수립

실측 결과를 바탕으로 아래 분류별 처리안 작성:

**A. 아카이브 분리 대상** (500줄 또는 40KB 초과)
- 각 PF별: 현재 줄수/KB → 분리 후 예상 줄수/KB
- 분리 원칙: 히스토리 → 시간 이력 전량 보존 (아카이브 파일로 이동, 삭제 아님). README → 현재 스냅샷 (Phase 현황 + 최근 30행 + 아카이브 포인터)

**B. 히스토리 100행 초과 대상**
- 완료된 Phase 히스토리를 별도 파일로 분리 대상 목록

**C. 상태 불일치 대상**
- 인덱스↔README 불일치 목록 + 어느 쪽이 정본인지 판정

**D. 휴면/완료 후보**
- 최종 갱신일 기준 3개월 이상 무활동 PF 목록
- completed vs paused 판정 의견

**E. 축 귀속 제안**
