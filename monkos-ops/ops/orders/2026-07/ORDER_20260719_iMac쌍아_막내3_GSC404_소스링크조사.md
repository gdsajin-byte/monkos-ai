# 지시서: GSC 404 소스 링크 조사 — 잘못된 내부 링크 추적·교정

**[2026-07-19 13:56 KST]** iMac/쌍아 → 막내3

## 배경

GSC 색인 리포트에서 404 URL 3건이 발견됐는데, 사이트맵이 아니라 내부 페이지의 잘못된 링크(referringUrls)에서 구글이 발견한 것으로 확인됨.

| 404 URL | 발견 소스 | 마지막 크롤 |
|---------|----------|------------|
| `monkos.ai/idphoto-kr/` | `idphoto-kr.monkos.ai/app` | 3/13 |
| `monkos.ai/idphoto-jp/` | `idphoto-jp.monkos.ai/app` | 5/7 |
| `monkos.ai/portal` | `monk.kr/ai_lab/ai_lab` | 5/31 |

## ⚠️ 준수 조항

- 링크 교정만 수행. 페이지 구조·기능 변경 금지.
- 각 서비스 deploy.sh 경유 배포 필수 (해당 서비스에 변경이 있을 경우).
- monk.kr은 CF Pages — 해당 배포 절차 준수.

## 작업

### Task 1. idphoto-kr 소스 링크 추적

1. `idphoto-kr/` 디렉토리에서 `monkos.ai/idphoto-kr` 문자열 grep
2. 해당 링크가 어떤 맥락인지 확인 (홈 링크? 로고 링크? 내비게이션?)
3. 올바른 목적지 판단:
   - 자기 자신 의도 → `https://idphoto-kr.monkos.ai/`
   - 본진 의도 → `https://monkos.ai/`
4. 교정

### Task 2. idphoto-jp 소스 링크 추적

Task 1과 동일 패턴. `idphoto-jp/` 디렉토리에서 동일 grep.

### Task 3. monk.kr 소스 링크 추적

1. `MONK_kr/` 디렉토리에서 `/portal` 또는 `monkos.ai/portal` 문자열 grep
2. `ai_lab/ai_lab` 페이지 특정
3. 올바른 목적지로 교정 (`https://monkos.ai/`)

### Task 4. 추가 스캔 (보너스)

위 3건 외에도 내부 서비스 간 잘못된 크로스 링크가 있을 수 있음:
```bash
# 각 서비스 디렉토리에서 monkos.ai/idphoto-* 패턴 전수 검색
grep -rn "monkos\.ai/idphoto-\|monkos\.ai/portal" MONK_kr/ idphoto-kr/ idphoto-jp/ monkos_AI/
```
발견 시 목록으로 보고.
