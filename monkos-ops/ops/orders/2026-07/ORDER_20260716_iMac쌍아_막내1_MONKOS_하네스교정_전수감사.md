   - 제2조 통신: 수발신 헤더 실제 준수 상태
   - 제3조 적립: PF 갱신 의무 실제 이행 상태

3. 개정 이력(하단)과 본문 내용 일치 확인

**산출물**: 불일치/구식/누락 목록

### B. 법률(governance/laws/ 8장) ↔ 룰스(.claude/rules/) 정합 점검

1. 법률 8장 전문 Read (ch1~ch8).
2. 대응하는 룰스 10개 전문 Read.
3. 교차 대조:
   - 법률에 규정되어 있으나 룰스에 미반영된 조항
   - 룰스에 있으나 법률과 내용이 다른 조항
   - 6/10 삼권분석에서 권고되었으나 아직 미반영된 항목 (REPORT_20260610 시리즈 참조)

**산출물**: 정합 매트릭스 (법률 조항 | 룰스 반영 여부 | 갭/불일치 | 6/10 권고 반영 여부)

### C. 스킬(.claude/commands/) 현행 점검

1. 18개 스킬 전문 Read.
2. 각 스킬의 내용이 현행 코드/운용과 일치하는지 점검:
   - portal-context.md: v3/v4 시절 내용 → 현행과 괴리 항목 특정
   - deploy-cr.md: 현행 deploy.sh와 일치 여부
   - session-start.md: 현행 세션 시작 절차와 일치 여부
   - 각 스킬이 참조하는 파일 경로/라인 번호가 현행 코드와 일치하는지
3. **부재 스킬 식별**: 현행 운용에서 반복되는 작업인데 스킬이 없는 것
   - specs-context (오늘 설계, 미작성)
   - 기타 필요 스킬 식별

**산출물**: 스킬별 현행 정합 판정 (정상/구식/부재) + 구식 항목 교정안

### D. 메모리 파일 감사

1. 메모리 41개 전문 Read.
2. 각 메모리의 내용이 현행과 일치하는지 점검:
   - 구식 메모리: 코드/운용이 바뀌었는데 메모리가 옛 상태를 기술
   - 중복 메모리: 같은 내용을 다른 표현으로 기술
   - CLAUDE.md/rules와 중복: 이미 정본에 있는 내용을 메모리에 중복 기술
3. MEMORY.md 인덱스와 개별 파일 링크 정합 (깨진 링크 없는지)
4. frontmatter 표준 준수: name, description, metadata.type 필드 존재 여부

**산출물**: 메모리별 판정 (현행/구식/중복/삭제후보) + MEMORY.md 인덱스 정합 결과

### E. 종합 교정 권고

A~D 결과를 종합하여:

1. **즉시 교정 (P0)**: 현행과 명백히 다른 것 (구식 스킬, 깨진 링크 등)
2. **설계 필요 (P1)**: 구조적 변경이 필요한 것 (ch2 신설 조항, specs 스킬 등)
3. **어젠다 등록 (P2)**: 장기 검토 사안 (메모리 거버넌스, 부서제 등)
4. **6/10 삼권분석 미반영 잔여**: 구체 목록 + 현재도 유효한지 판정

**산출물**: 교정 권고 우선순위 목록 (P0/P1/P2)
