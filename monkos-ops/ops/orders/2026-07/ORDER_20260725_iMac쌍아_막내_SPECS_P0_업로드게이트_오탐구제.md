## 배경 — 무엇이 진짜 문제인가

`file.type`은 **파일 내용이 아니라 OS가 확장자에 붙여준 라벨**이다. macOS는 UTI로 정규화되지만 **Windows는 레지스트리 `HKEY_CLASSES_ROOT\.jpg`의 `Content Type` 값을 읽으며, 이 값이 없으면 빈 문자열**을 반환한다. 민아 4060 실측에서 `.webp`가 **Content Type 미등록** 상태로 확인됐다.

→ **정상 JPG를 올려도 게이트가 거부할 수 있다.** 그리고 거부는 `photo_upload`(224행) 발화 **이전**에 일어나므로 **계측에 아무 흔적도 남지 않는다.** 얼마나 잃는지 셀 수 없는 것이 현 상태다.

⚠️ **단, "MIME 게이트가 이탈의 진범"은 미확정이다.** Windows 10% / Mac 11%로 이탈률이 동률이며 OS 무관 요인이 남아 있다. **본 작업의 1차 목적은 오탐 구제이고, 2차 목적은 규모 측정이다.** 배포 후 지표가 안 변할 수 있으며 그것도 유효한 정보다.

## 작업 목록

### 1. 확장자 폴백 — 오탐 구제 (최대 레버)

**파일**: `monkos_AI/portal/public/js/specs-funnel.js` **217행**

현행:
```js
if(!file.type.match(/image\/(jpeg|png|heic|heif|webp)/i)) return showError(T.errFileType);
```

**요구 동작**:
1. `file.type`이 `image/(jpeg|png|heic|heif|webp)`에 매칭되면 **통과** (현행 유지)
2. 매칭되지 않으면 **즉시 거부하지 말고**, 파일명 확장자로 재판정한다
   - 허용 확장자: `jpg` · `jpeg` · `png` · `webp` · `heic` · `heif`
   - 확장자 추출은 파일명 마지막 `.` 기준, 소문자 정규화
3. 확장자도 불일치하면 거부 (→ §3 계측 발화 후 `showError`)

**구현 주의**:
- 정규식은 **기존 리터럴을 그대로 유지**하고 폴백 분기만 추가할 것. 재작성 시 07-13 이스케이프 사고 재현 위험.
- `file.name`이 없거나 확장자가 없는 경우(빈 문자열) → 거부 경로로. **예외 던지지 말 것.**
- **bmp·tiff·gif는 허용 목록에 넣지 말 것.**

### 2. 에러 문구 정직화 — 6개 언어

**파일**: `monkos_AI/portal/lib/cms/specs-i18n.js`
**대상 행**: `192`(ko) · `405`(ja) · `614`(en) · `823`(es) · `1032`(id) · `1240`(vi)

현행 ko: `'JPG, PNG, HEIC 파일만 업로드 가능합니다.'`

**문제**: 실제로는 **WEBP·HEIF도 허용**하는데 안내하지 않는다. 유저가 지원되는 파일을 안 올리게 만드는 부정확한 문구.

**요구**:
1. 실제 허용 목록을 정확히 반영: **JPG · PNG · WEBP · HEIC**
2. **BMP 대응 안내 1문장 추가** — BMP는 서버가 처리하지 못하므로 "PNG나 JPG로 저장 후 다시 시도" 취지. (그림판·캡처도구 산출물이 BMP인 경우가 실제 유입 경로)
3. 6개 언어 전부. **각 언어의 기존 문체·경어 수준을 따를 것.** 기계 번역투 금지.
4. 문구 길이가 UI를 깨지 않는지 확인(에러 영역은 1~2줄 가정).

### 3. `upload_rejected` 계측 신설 — 블랙박스 해소

**파일**: `specs-funnel.js`, 게이트 거부 지점

거부가 발생할 때마다 GA4 이벤트를 발화한다.

- 이벤트명: `upload_rejected`
- **`gaTrack(name, params, repeat)` 의 `repeat` 인자를 `true`로 줄 것** — 한 유저가 여러 번 시도할 수 있으므로 1회 제한(`gaFired`)이 걸리면 실측이 왜곡된다.
- 파라미터:
  | 키 | 값 | 목적 |
  |---|---|---|
  | `reject_reason` | `'type'` \| `'size'` | 형식 거부 vs 용량 초과 구분 |
  | `file_mime` | `file.type` (빈 값이면 `'(empty)'`) | **빈 문자열 케이스 규모 측정 — 본 작업의 핵심 지표** |
  | `file_ext` | 추출한 확장자 (없으면 `'(none)'`) | 실제 유입 포맷 분포 |

- **218행 용량 초과 거부(`T.errFileSize`)에도 동일하게 발화**할 것 (`reject_reason: 'size'`).
- ⚠️ **개인정보 금지** — 파일명 전체를 파라미터로 보내지 말 것. **확장자만** 추출해 전송한다.
