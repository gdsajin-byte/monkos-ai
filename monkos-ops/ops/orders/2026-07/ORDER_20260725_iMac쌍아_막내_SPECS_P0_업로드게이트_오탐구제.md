## 배경 — 무엇이 진짜 문제인가

`file.type`은 **파일 내용이 아니라 OS가 확장자에 붙여준 라벨**이다. macOS는 UTI로 정규화되지만 **Windows는 레지스트리 `HKEY_CLASSES_ROOT\.jpg`의 `Content Type` 값을 읽으며, 이 값이 없으면 빈 문자열**을 반환한다. 민아 4060 실측에서 `.webp`가 **Content Type 미등록** 상태로 확인됐다.

→ **정상 JPG를 올려도 게이트가 거부할 수 있다.** 그리고 거부는 `photo_upload`(224행) 발화 **이전**에 일어나므로 **계측에 아무 흔적도 남지 않는다.** 얼마나 잃는지 셀 수 없는 것이 현 상태다.

⚠️ **단, "MIME 게이트가 이탈의 진범"은 미확정이다.** Windows 10% / Mac 11%로 이탈률이 동률이며 OS 무관 요인이 남아 있다. **본 작업의 1차 목적은 오탐 구제이고, 2차 목적은 규모 측정이다.** 배포 후 지표가 안 변할 수 있으며 그것도 유효한 정보다.

### 3. `upload_rejected` 계측 신설 — 블랙박스 해소

**파일**: `specs-funnel.js`, 게이트 거부 지점

거부가 발생할 때마다 GA4 이벤트를 발화한다.

- 이벤트명: `upload_rejected`
- **`gaTrack(name, params, repeat)` 의 `repeat` 인자를 `true`로 줄 것** — 한 유저가 여러 번 시도할 수 있으므로 1회 제한(`gaFired`)이 걸리면 실측이 왜곡된다.
- 파라미터:
  | 키 | 값 | 목적 |
  |---|---|---|
  | `reject_reason` | `'type'` \| `'size'` | 형식 거부 vs 용량 초과 구분 |
  | `file_mime` | `file.type` (빈 값이면 `'(empty)'`) | **빈 문자열 케이스 규모 측정 — 본 작업의 핵심 지표** |
  | `file_ext` | 추출한 확장자 (없으면 `'(none)'`) | 실제 유입 포맷 분포 |

- **218행 용량 초과 거부(`T.errFileSize`)에도 동일하게 발화**할 것 (`reject_reason: 'size'`).
- ⚠️ **개인정보 금지** — 파일명 전체를 파라미터로 보내지 말 것. **확장자만** 추출해 전송한다.

# §11. HEIC 잠정 제외 (A안) + 디코드 실패 fail-open 차단

## 전제 반증 — 확정 사실

```
sharp.format.heif.input.fileSuffix : ['.avif']    ← AVIF만
sharp.versions.de265               : (none)       ← HEVC 디코더 부재 (특허)
① metadata()        → OK   heif 600x800 compression=hevc
② raw() 픽셀 디코드 → FAIL  bad seek to 1024
③ jpeg() 변환       → FAIL  bad seek to 1024
```

- **민아 자기교정**: 15:34 "libheif가 디코드한다"는 보고는 **`.metadata()`(헤더만 읽는 함수) 결과를 디코드 능력으로 오독**한 것. *"시도하지 않았기 때문에 성공한 것을 성공으로 읽었다."*
- **쌍아 자인**: 그 보고를 검증 없이 §10-2 설계 근거로 채택했다. **오전에 BMP를 막은 논리(「서버가 못 읽는 포맷을 클라이언트에서 열지 않는다」)가 HEIC에도 그대로 성립**하는데, "HEIC는 다르다"고 판단한 것이 오류.

## 🔴 그리고 안전망이 무력화돼 있다

`server.js:82` — `normalizeImage()` catch가 크기를 **`sharp(raw).metadata()`로 구한다.** 헤더만 읽으므로 **HEIC에서도 600x800이 나오고**, 따라서 `if (!norm.width || !norm.height)` **`DECODE_FAILED` 가드가 발동하지 않는다.** 유일한 안전망이 **민아를 속인 것과 정확히 같은 헤더-vs-디코드 혼동**으로 뚫려 있다. 이후 crop-engine 검출 실패 → **fail-open(`측정성=true, faces=null`)** → 유저는 깨진 썸네일을 보며 "규격 적합" 판정으로 진행한다.

## 11-2. [P1] 디코드 실패 무음 폴백 차단 — HEIC 무관, 구조 결함

**포맷 하나를 닫아도 이 경로는 남는다.** 미지원 포맷·손상 파일 전반에 동일하게 적용된다.

1. **`normalizeImage()` 폴백을 무음으로 두지 말 것** — 원본 반환 시 **폴백 사실을 반환값에 실어** 호출자가 알 수 있게 한다. (예: `degraded: true` 류. 형태는 구현자 판단)
2. **크기로 판정하지 말 것** — `catch` 안의 `sharp(raw).metadata()`는 **헤더만 읽어 가드를 무력화**한다. 판정 기준을 **디코드 성공 여부**로 바꿀 것.
3. **디코드 실패가 선행된 경우 `fail-open` 금지** — precheck가 **명시 실패**로 전환. *"fit이 재검출·방어한다"는 전제는 디코드 불가 이미지에 성립하지 않는다.*
4. [[feedback_paid_failure_no_degraded_delivery]] 적용 — 강등 무음 출고 경로를 남기지 말 것.
