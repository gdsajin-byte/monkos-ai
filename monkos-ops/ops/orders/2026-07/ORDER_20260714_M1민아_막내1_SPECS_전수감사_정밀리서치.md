## 3. 상세 설계

### P0. 필드 채움율 실사 (30분, 단독)
- `officialSource`·`source`·`sourceName`·`onlineGuide`·`detailSections`·`aiSummary`·`faceTargetExplicitMm` 채움율 스캔 → 리서치 우선순위표에 반영.

### P1. 국가별 공식 규정 정밀 리서치 — **Workflow 필수**
- **범위**: 1차 = priority/grade 필드 상위 + GSC 노출 실적 슬러그 + 주요국(us/uk/eu/jp/cn/au/ca/fr/de/in 등) 우선 **100슬러그**. 2차 확장은 1차 검수 통과 후.
- **워크플로우 구조 (권장 패턴)**: 국가 배치 팬아웃(agent per 국가군) → 항목별 수집 → **교차 검증 스테이지**(공식 출처 재확인, 미확인 항목 킬) → 스키마 적재 스테이지. `pipeline()` 기본, 검증은 적대적(refute) 프롬프트.
- **수집 항목** (슬러그당):
  - 공통 제한: 복장(흰색 의상 금지 여부·민소매 등), 표정(치아 노출·미소 허용 범위), 안경(허용/조건부/**절대 금지** — 예: 미국 2016~), 귀 노출 의무 여부, 눈썹·얼굴 윤곽 가림 금지, 머리카락/히잡·종교적 머리가리개 조건, 장신구
  - 수치 검증: 머리 높이 실규정(현행 DB값 대조 — **kr-resume 부류 오류 탐지**), 배경 정확값, 사이즈
  - 부가: 유효기간(6개월 규정 등), 파일 규격(디지털 제출), **공식 출처 URL(정부 도메인)**
- **⚠️ 진실성 게이트 (헌법 4조 4항 준용 — 최우선 준수)**:
  - 모든 항목에 공식 출처 URL 필수. **정부/공식 출처 미확인 항목은 공란 + `unverified` 플래그** — 추측·블로그 인용·타 사진서비스 베끼기 절대 금지.
  - 틀린 데이터 등재 > 공란 (반명함 사례). 확신 없으면 비운다.
- 산출 JSON 스키마(슬러그별): `{ slug, verified: {필드: {value, source_url, checked}}, unverified: [...], db_conflicts: [현행 DB와 충돌 항목] }`

### P2. 스키마 확장 + 렌더 반영
- specs-data.json 신설 필드: `restrictions: { clothing, expression, glasses, ears, face_visibility, headwear, accessories }` — 각 `{ko, en, ja}` + 값 없으면 필드 생략(렌더 자동 스킵).
- render-specs.js 상세규정 탭에 restrictions 섹션 추가 (v2). FAQPage·PropertyValue 구조화 연동은 기존 패턴 준수 (**재해석 금지 — 기존 렌더 함수 재사용**).
- validity·fileSpec: P1 수집분 채움 + 미채움 시 행 미노출 확인.
- details 미보강 슬러그(1차 범위 밖): ICAO 보일러 문구를 정직화 — "ICAO 9303 일반 기준 기반, 국가별 세부 확인 전" 톤으로 교체(오인 방지, 3언어).
