## 배경

막내2 전수 조사(REPORT_20260714)에서 **완료 보고서가 없는 지시서 64건**이 식별됐다. 그러나 이 64건 전부가 실행 누락인 것은 아니다:

- **터미널 보고만 하고 COMPLETION 파일을 안 만든 케이스** (실행은 됐으나 보고서 누락)
- **실제로 실행됐고 커밋도 됐는데 보고서만 빠진 케이스** (확정 처리 가능)

이 4가지를 **실측으로 분기**하여 정확한 상태를 판정한다.

## 판정 기준

각 미완료 지시서에 대해 아래 3가지 소스를 **순차 대사**하여 판정:

### 소스 1: 세션 로그

해당 지시서의 `recipient`(수신자) + 발행일 이후의 세션 로그에서:
- "완료", "✅", "배포", "커밋" 등의 실행 흔적
- 터미널 보고(채팅에서 보고했으나 COMPLETION 파일 미생성)

### 소스 2: git log + diff

- 지시서에 명시된 파일/기능이 실제로 커밋됐는지 `git log --all -- {파일경로}`
- 커밋 메시지에 지시서 내용이 언급되는지
- 커밋 시점이 지시서 발행일 이후인지

### 소스 3: 코드/배포 현황

- 지시서가 요구한 기능이 현재 코드에 존재하는지 (grep/파일 확인)
- prod/dev에 배포되어 있는지

## 판정 분기

| 판정 | 정의 | 후속 조치 |
|------|------|----------|
| **확정 (DONE)** | 실행+커밋+배포 모두 완료 확인. COMPLETION 파일만 없음 | 보고서에 "확정" 기재. 소급 COMPLETION은 쌍아 판단 |
| **보고 누락 (REPORT_MISSING)** | 세션 로그에 터미널 보고 존재 + 커밋 확인. COMPLETION 파일만 없음 | 동일 |
| **실행 누락 (NOT_DONE)** | 커밋·코드·세션 로그에 실행 흔적 없음 | 재지시 또는 폐기 판단 필요 (쌍아) |
| **기각 (OBSOLETE)** | 이후 상황 변경으로 지시서 내용이 무효화됨 (아키텍처 변경, 다른 지시서로 대체 등) | "기각" + 사유 기재 |
| **부분 완료 (PARTIAL)** | 일부만 실행됨 | 미완료 부분 명시 |
