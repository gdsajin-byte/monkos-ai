## 3. 상세 설계

### A. 복귀 동선 완결 (ko 포함 전체 — 최우선)
1. **상시 복귀 링크**: `from`이 존재·검증 통과면 페이지 상단(잔액 카드 위)에 "← 하던 사진으로 돌아가기" 상시 노출 — 로그인 전에도. 클릭 시 sessionStorage의 from 소거 후 이동(기존 returnToService의 클릭 처리 준용).
2. **로그인/가입 직후 CTA**: 로그인 성공 후 잔액 조회 결과 **10c 이상이면** 강조 CTA "돌아가서 만들기 — 10c로 바로 생성" (신규 가입 10c 지급 케이스가 핵심: 충전 없이 완주해야 하는 유저의 이탈 지점). 자동 이동은 하지 않는다(상점 구경 방해 금지) — 클릭 유도만.
3. **토스 충전 완료**: 기존 returnToService(3초 자동 복귀) 유지 — 회귀 금지.
4. 복귀 후 자동 실행은 specs 수신부가 처리한다(1절 표) — **credits.html은 from으로 보내기만 하면 된다. specs-funnel.js resume 로직 수정 금지.**

### B. 글로벌 모드 (구 지시서 흡수)
1. **lang 판별**: `?lang=` 우선 → `from` 경로의 `/{lang}/` 프리픽스(specs는 경로 기반: `/ja/specs/…`) → 기본 ko. non-ko는 **en 통일**(ja/es 개별 사전은 후속 스코프 밖).
2. **en 사전**: title/description, 로그인 카드(간편로그인 + 신규 10c 이벤트), 잔액 라벨, 상점 섹션, 복귀 링크·CTA(A-1·A-2), 토스트/에러. `document.documentElement.lang` 동기화.
3. **결제수단 분기**: non-ko는 토스 패키지·위젯 숨김 → **레몬 글로벌 5종 카드**(topup_40 $3.90 ~ package_750 $39.90). variant·가격은 클라 하드코딩 금지 — 서버가 `VARIANT_CREDITS`(lib/shared/config.js) 정본에서 내려주는 구조. **체크아웃에 userId custom 전달 필수**(웹훅 적립 매칭) — 직접결제의 체크아웃 생성 패턴(`handleDirectInit`) 확인 후 준용.
4. **ko 회귀 0**: 한국어 화면·토스 흐름 diff 0.

### C. 레몬 충전 적립 감지 → 복귀
- 레몬은 결제 완료가 웹훅 비동기 적립이라 토스 confirm 같은 동기 지점이 없다. 레몬 체크아웃으로 보낸 뒤 credits.html이 **잔액 폴링**(예: 5초 간격, 최대 3분 — specs-funnel의 startPolling 패턴 준용) → 잔액 증가 감지 시 "충전 완료" 토스트 + returnToService() 발화.
- 폴링 시작 조건: 레몬 체크아웃 창을 연 시점부터. 타임아웃 시 "적립이 지연되고 있어요 — 잠시 후 새로고침" 안내(en/ko).
