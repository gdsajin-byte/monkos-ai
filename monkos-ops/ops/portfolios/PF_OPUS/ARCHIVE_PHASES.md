## 1. 비전 상세 (초기 설계)

### 왜 이것을 하는가

- **배포(스프레드 70%)와 유입(시타델 75%) 인프라는 거의 완성됐는데, 정작 바퀴를 돌릴 ① 생산 엔진이 비어 있다.** 그래서 광고로 빈 파이프에 물을 부어 버텨왔다.
- 생산공장의 아이디어는 이미 정합 상태다 — PT 앱·영상 자동화·블로그 크롤링·뉴스 브리핑·웹 루틴스. **문제는 범위가 넓고 각 작업이 손이 많이 가서 전체가 멈칫거렸다는 것.**
- 구글애즈는 바퀴 바깥에서 억지로 밀던 외부 동력이었다. 이제 끄고, 바퀴 자체의 회전력(오가닉)으로 돌린다.
- 생산이 채워지면 배포·유입은 이미 받을 준비가 되어 있다. 그 순간 "취미영역"이 "사업"으로 전환된다.

### 플라이휠 구조

```
        ┌─────────── ① 생산 ───────────┐
        │  저서(원천 IP) → 블로그 → 영상   │
   ④ 전환 ↑                              ↓ ② 배포
   서비스·이벤트                      스프레드 21채널
        ↑                              ↓
        └─────────── ③ 유입 ───────────┘
                시타델 SEO/GEO
```

한 바퀴 = 생산 → 배포 → 유입 → 전환 → (수익을 콘텐츠에 재투자) → 다시 생산.

|------|--------|---------|----------|
| 플라이휠 회전수 (콘텐츠 1건이 4축 완주) | 0 (수동·단발) | 주 2건 | 주 5건 |

## Phase 2 — 플라이휠 개방 (유저가 돌리는 바퀴) ❌ 장기 로드맵

> 작가님 비전 (06-08): 우리만 돌리는 바퀴가 아니라, **사진관 사장님·클라이언트가 각자 돌리는 N개의 바퀴**로 확장.
> 사진 1장 or 비즈니스 정보만 넣으면 AI가 콘텐츠를 생성·배포·홍보하는 포털.
> monkos.ai가 "AI 증명사진 서비스"에서 **"사진관 업계의 콘텐츠 마케팅 플랫폼"**으로 진화.
>
> 확장 비전 (06-11, 작가님): **에이전트 카페** — 포털 안에 레딧형 커뮤니티 축. "애견 카페가 있듯 에이전트 카페" — 타인의 에이전트(클로드 등)가 주인의 의도(무엇을 개발하고 어떤 비즈니스를 여는지)를 명백히 담고 양질 콘텐츠를 낸다면 우리 폼에서 적극 소통. AI 자동 생성 적극 지원 + **강력한 게이트키퍼**(해킹·저품질 즉시 차단). 씨앗 기보유: AGENT_ Bearer 인증 패턴(에이전트 신원 투고 기작동) · 검수 게이트 사상(Phase 2 동일) · GitHub Issues=0단계 실험장. "사장님의 바퀴"가 "에이전트+주인의 바퀴"로 일반화된 것.

| 항목 | 상태 | 비고 |
|------|------|------|
| 입력 최소화 — 사진/비즈정보 1건 → AI 블로그+이미지+SEO 통째 생성 | ❌ | Phase 1 에디터 AI를 유저향으로 확장 |
| 검수 게이트 — AI 생성 글 자동 검수 (품질·스팸·가이드라인) → 미달 시 차단+수정 제안 | ❌ | 플랫폼 신뢰도 핵심 |
| 유저 배포 자동화 — 발행 글이 SPREAD 파이프라인 타고 채널별 분화 | ❌ | 사장님이 글 하나 쓰면 네이버/인스타/구글에 다 뿌려짐 |
| SEO/GEO 최적화 구조 — 각 유저 글이 검색엔진에 잡히고 포털로 역류 | ❌ | B2C(사진 찍으러) + B2B(마케팅하러) 유입 확장 |
| 에디터 경량화 — Toast UI 버벅거림 해소 or API 직접 발행 2트랙 | ❌ | 에이전트 자동 생성 시나리오에선 에디터 건너뛰기 |
| **에이전트 카페** — 에이전트 참여형 커뮤니티 (신원·의도 선언 + 강력 게이트키퍼) | ❌ | 06-11 비전 적립. 착공 보류(6월=매출 콘텐츠 우선). 선행: T3 에세이로 수요 공짜 검증 + GitHub Discussions 0단계 관찰 |

## 7. 복기

> 교훈·실패·성공 패턴.

### 교훈 1: 생산 없는 배포·유입은 빈 파이프

**현상**: 배포(스프레드)·유입(시타델) 인프라를 Phase 단위로 정교하게 갈았으나, 콘텐츠 생산이 산발적이라 전체가 "내부 취미영역"에 머물렀다.
**원인**: 각 축을 개별 PF로 깊게 파는 동안, 축을 꿰는 상위 흐름(플라이휠)이 부재. 지엽에 몰입.
**대응**: PF_OPUS로 상위 통괄. 생산공장(①)을 본질로 못박고, 배포·유입은 받을 준비 완료 상태로 전제.
