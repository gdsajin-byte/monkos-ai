## C. 세션로그→PF 환류 규율 강화안

### 현행 문제

1. **규정**: "PF 갱신은 쌍아가 수행" (README 운용 원칙, ch3 3조, ch4 9조)
2. **실태**: 쌍아 세션이 없는 날 PF 히스토리 누락. 막내가 COMPLETION 제출해도 쌍아 리뷰 전까지 PF 미갱신
3. **근본 원인**: 단일 실패점(쌍아). 컴팩팅 후 막내 세션 맥락 유실 → PF에 기록되지 않으면 영구 소실
4. **빈도**: PF_PORTAL 히스토리 28행 중 ~5행이 쌍아 직접 기록. 나머지는 막내 작업을 쌍아가 사후 어펜드. 누락 추정 건수 정량화 어려움 (누락된 것은 보이지 않으므로)

### 선택지 비교

| 안 | 방식 | 장점 | 단점 |
|----|------|------|------|
| **C1** | 현행 유지 (쌍아 전담) | 품질 통제, 일관된 표현 | 단일 실패점, 컴팩팅 후 유실 위험 |
| **C2** | 막내/민아 PF 직접 어펜드 허용 | 실시간 갱신, 누락 방지 | 품질 편차, 에이전트 간 중복 기록 위험 |
| **C3** | COMPLETION에 PF 행 초안 포함 의무화 | 데이터 수집 자동화 + 쌍아 품질 통제 유지 | 쌍아 부재 시 여전히 PF 미갱신 (COMPLETION에만 잔류) |
| **C4** | **막내 직접 어펜드 + 세션 마감 체크리스트** | 가장 실효적, 컴팩팅 전 기록 보장 | 법률 개정 필요 (ch4 9조), 품질 편차 수용 필요 |

### 추천: C4 — 막내 직접 어펜드 허용 + 세션 마감 체크리스트

**설계**:

```
[현행]
막내 작업 완료 → COMPLETION 제출 → 쌍아 리뷰 → 쌍아가 PF 어펜드
                                    ↑ 여기서 단절 (쌍아 부재)

[개정안]
막내 작업 완료 → COMPLETION 제출 + PF 히스토리 1행 직접 어펜드
                                → 쌍아 사후 리뷰 (보정만, 삭제 안 함)
```

**규율**:

1. **어펜드 권한**: 막내/민아도 자기 작업에 한해 PF 히스토리 1행 어펜드 가능
2. **어펜드 시점**: 완료 보고(COMPLETION) 작성과 동시. 세션 마감 전 필수
3. **형식 준수**: 6열 구조 (날짜, 분류, 주체, 내용, 산출물, 상태) 그대로. 분류 카테고리 필수
4. **쌍아 사후 보정**: 쌍아는 다음 세션에서 신규 PF 행을 리뷰하고 내용·분류를 보정 (오기 수정, 맥락 보충). **삭제 금지** (append-only 원칙)
5. **세션 마감 체크리스트 추가**:

```markdown
## 세션 마감 체크리스트 (추가 항목)
- [ ] 이번 세션에 활성 PF 작업이 있었는가?
  - Yes → 해당 PF 히스토리에 1행 어펜드 완료?
  - No → 스킵
```

**법률 개정 범위**:
- ch4 9조: "PF 갱신은 쌍아가 수행" → "PF 히스토리 어펜드는 작업 수행 에이전트가 완료 보고 시점에 직접 수행. 쌍아는 사후 리뷰·보정을 담당"
- ch3 3조: 세션 마감 체크리스트에 PF 항목 추가
- README 운용 원칙: 동일 반영

**자동화 가능성**:
- **단기**: 스킬(`.claude/skills/`)로 PF 어펜드 커맨드 제작 가능 (예: `/pf-append PF_CROP "05/09" "개발" "크롭앱 배경 제거 통합" "commit_hash" "✅"`)
- **중기**: 세션 마감 훅(hook)에서 COMPLETION 파일 → PF 히스토리 행 자동 추출
- **장기**: 세션 로그 파싱 → PF 히스토리 자동 생성 (AI 기반)

현실적으로 단기(스킬)까지가 비용 대비 효용 높음.

**위험 완화**:

| 위험 | 대응 |
|------|------|
| 막내가 PF 잘못 수정 (행 삭제, 기존 수정) | append-only 원칙 + 쌍아 diff 리뷰 |
| 중복 기록 (막내1, 막내2가 같은 작업 기록) | 1 에이전트 = 자기 작업만 기록 원칙 |
| 품질 편차 (막내마다 기술 수준 다름) | 쌍아 사후 보정 + 분류 카테고리로 최소 구조 보장 |
