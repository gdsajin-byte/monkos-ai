## 7. devlog (R&D 개발 노트)

> 기술 판단의 맥락과 실험 과정을 논문 수준으로 축적한다.
> 폴더형 PF(`PF_XXX/devlog/`)에 배치한다.
> 파일형 PF는 devlog 첫 편 생성 시 폴더형으로 승격한다.

### devlog/README.md — 서론 (연구 선언)

> 논문의 서론. 모든 devlog 편은 이 선언 위에 선다.
> **서론은 고정 문서가 아니다. RQ가 추가될 때마다 함께 성장하는 살아있는 문서.**
> - RQ 등록 → §3 질문 테이블에 1행 추가
> - 해당 RQ 조사 시작 → §4 선행연구에 논문·특허·경쟁사 누적
> - 새 평가 기준 필요 시 → §6 평가체계에 시나리오·지표 추가
> - 새 기술 후보 발견 시 → §7 후보 모델 테이블에 누적
>
> 질문이 늘수록 프로젝트의 연구 체력이 축적된다. 지원사업 때 서론만 펼쳐도 "이 팀이 얼마나 체계적으로 연구하고 있는가"가 보여야 한다.

```markdown
## Ⅰ. 서론

### 1. 연구 대상 — 무엇을 만드는가
### 2. 연구 동기 — 왜 필요한가
### 3. 연구 질문 (RQ) — 무엇을 알아내야 하는가
   → 질문 레지스트리. 질문이 씨앗, devlog 전체가 답변.
   → 상태: 💡 후보 → 📋 등록 → 🔄 연구중 → ✅ 완료
### 4. 선행연구 — 이미 누가 뭘 했는가
   - 학술 연구 (논문)
   - 특허
   - 경쟁사 / 유사 서비스
   - 기술 동향 / 기사
### 5. 연구 방법 — 어떻게 접근하는가
### 6. 평가 체계 — 어떤 기준으로 판단하는가 (스키마 테이블)

## Ⅱ. 본론 — 개별 연구 기록 (devlog 인덱스, 각 편 = RQ의 답변)
## Ⅲ. 비전
```

### devlog 한 편의 구조 (본론)

> **제목 = 질문/의도**. "이렇게 했다"가 아니라 "왜 이렇게 결정했는가"를 쓴다.

```markdown
# {질문/의도} — {부제}

## 1. 문제의식
## 2. 전개 / 리서치
## 3. 해결방안

## 5. 결과
## 6. 리뷰
```
