# PF_AUTOPILOT — devlog 서론

## Ⅰ. 서론

### 1. 연구 대상 — 무엇을 만드는가

GitHub Actions 기반 접착 레이어. CF Pages(정적)와 Cloud Run(엔진)을 Git 이벤트로 연결하고, 시크릿 중앙화·멀티레포 연결·웹↔로컬 에이전트 핸드오프를 자동화하는 인프라.

### 2. 연구 동기 — 왜 필요한가

- 배포 라인 완전 분리 후 수동 조율 병목 발생
- 시크릿 4곳 분산 (`.env` × 4대 + GCS + Cloud Run + CF Dashboard) — 인벤토리 부재
- PF_BRIEF 한 달 교착 — 로컬 세션 의존 구조의 한계 노출
- 웹 에이전트(Managed Agents/Routines)와 로컬 에이전트(Claude Code) 간 핸드오프 경로 없음

### 3. 연구 질문 (RQ) — 무엇을 알아내야 하는가

| # | RQ | 상태 |
|---|-----|------|
| RQ1 | GitHub Actions cron으로 GA4/GSC API를 안정적으로 호출할 수 있는가? | 📋 등록 |
| RQ2 | Managed Agents 산출물을 git commit → Actions 트리거로 자동 중계할 수 있는가? | 💡 후보 |
| RQ3 | deploy.sh 경유 원칙을 유지하면서 PR 기반 자동 배포가 가능한가? | 💡 후보 |

### 5. 연구 방법 — 어떻게 접근하는가

Phase별 점진 구축. Actions → 브리핑 → 에이전트 연결 → 자율 운용 순.
각 Phase 완료 시 devlog 1편 작성하여 기술 판단 근거 축적.

### 6. 평가 체계 — 어떤 기준으로 판단하는가

| 평가 기준 | 지표 | 합격선 |
|----------|------|--------|
| 안정성 | 워크플로우 실패율 | < 5% |
| 비용 | Actions 월간 사용량 | < 100분 (무료 쿼터 5%) |
| 적시성 | 브리핑 발행 지연 | < 30분 (09:00 KST 기준) |

## Ⅲ. 비전

AUTOPILOT이 성숙하면 MONK 인프라 전체가 "Git push 하나로 배포·진단·알림·에이전트 핸드오프"까지 자동으로 흐르는 구조가 된다. 최종 목표는 작가님이 판단과 지시만 하는 무인 운영 체계.
