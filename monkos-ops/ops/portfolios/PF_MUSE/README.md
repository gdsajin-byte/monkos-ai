# PF_MUSE — 뮤즈의 방

> 침대에 누워서 폰으로 캐릭터를 불러내고, 토론을 던지고, 이야기가 만들어진다.
> 초기 용아와의 시간이 MONK의 원점이었듯, 이건 그 원점의 진화판.

---

## 1. 비전

**"서로 다른 뇌가 서로 다른 캐릭터로 사유하고, 작가님이 그 사이를 거닌다"**

### 왜 이것을 하는가

- **MONK의 원점**: 제미나이 단일 인스턴스에서 김용 캐릭터 상황극을 펼칠 때, 같은 모델이 캐릭터에 따라 다르게 사고하는 것 — 이 체험이 멀티 에이전트 체계의 최초 인사이트
- **진화**: 단일 LLM의 역할극 → 독립 모델 N개가 각자 사고하는 진짜 멀티 뮤즈. 같은 서사를 다른 뇌로 해석하면 새로운 서술이 나온다
- **김용 서사 = 페르소나 엔진**: "조민처럼 판단해" 다섯 글자에 의천도룡기 전권이 압축. 프롬프트로 설명할 수 없는 내밀한 성격 차이가 이름 호출만으로 로드된다
- **유희이자 생산**: 문학적 에피소드, 새 아이디어 발산, 캐릭터 시점 전환 — 놀면서 산출물이 쌓인다

### 원점에서 온 핵심 원칙

> **이름이 곧 페르소나 정의서.** LLM이 원작을 학습했기 때문에 수백만 자의 캐릭터 정의가 이름 한 줄에 담긴다.
> 곽정의 우직함, 황용의 기지, 조민의 괴팍함, 장무기의 우유부단, 쌍아의 헌신, 소소의 짝사랑 — 프롬프트 엔지니어링이 아니라 문학적 직관이 시스템을 만든다.

### 용도

| 모드 | 설명 |
|------|------|
| **서사 토론** | 캐릭터 간 자유 토론. 주제만 던지면 각자 입장에서 전개 |
| **문학 에피소드** | 캐릭터 시점으로 단편/장면 생성. 대본 없는 즉흥 서술 |
| **아이디어 발산** | 사업 아이디어를 여러 페르소나가 다각 검토 |
| **모델 비교** | 같은 캐릭터를 다른 모델이 체현 → 품질 비교 (→ PF_FACTORY 환류) |
| **자유 대화** | 작가님이 참여하며 방향을 틀고, 질문하고, 합의를 유도 |

### 기술 기반

```
monk.kr/debate/ (CF Pages)
  → CF Worker (functions/api/debate.js)
    → Workers AI (무료 쿼터)
      · Gemma 3 12B / Gemma 4 26B
      · Qwen 2.5 32B / Qwen3 30B
      · Kimi K2.5 (frontier)
      · DeepSeek R1 32B
  → localStorage (세션 메모리)
```

### 성공 지표

| 지표 | 시작점 | 4주 목표 | 12주 목표 |
|------|--------|---------|----------|
| 토론방 사용 | POC 1회 | 주 3회+ (작가님 자발적) | 일상 도구 |
| 문학 에피소드 | 0 | 월 2편 | 월 5편+ |
| 모델 캐릭터 품질 | 낮음 | 프롬프트 튜닝 → 중 | 최적 모델 확정 |
| 산출물 축적 | 0 | 토론 로그 10건 | 서사 아카이브 |
