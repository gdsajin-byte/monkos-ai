# PROTOCOL: URL·슬러그 변경 SEO 안전

> **[2026-06-23 KST]** iMac/민아 정본화. 2026-06-19 specs 슬러그 사고의 재발 방지.
> 적용: PF_SPECS·PF_PORTAL·PF_OPUS 등 **SSR URL을 생성/변경하는 모든 작업**.
> 사고 전말: [REPORT_20260623_민아_SPECS_슬러그회귀_색인자산손실](../../reports/2026-06/REPORT_20260623_민아_SPECS_슬러그회귀_색인자산손실.md)

## 0. 제1원칙 — URL은 자산이다

검색 색인된 URL은 **누적된 권위(순위·신뢰)를 담은 자산**이다. 오래된 URL일수록 자산이 크다. URL을 삭제·변경하는 것은 **자산을 옮기는 행위**이며, 반드시 **301 리다이렉트(전입신고)**로 권위를 새 주소에 승계해야 한다. 301 없는 삭제 = 자산 폐기.

> 2026-06-19 사고: 슬러그 체계를 국가명(`korea-passport`)→ISO(`kr-passport`)로 통합하며 옛 슬러그를 **301 없이 삭제** → 색인된 **120 URL(24 규격 ×3언어)**이 404. 그중 운전면허(418노출/8.7위)·여권(448노출) 등 3월부터 쌓인 최고권위 페이지 다수 포함. 한 달 자산이 끊김.

## 1. 데이터 자동 변환/생성 시 (예: convert-specs-data.js)

- [ ] **기존 슬러그와 중복 충돌 검사**. 자동 생성 슬러그가 기존 수작업 슬러그와 같은 콘텐츠를 다른 키로 만들면 중복 색인이 발생한다.
  - 2026-05-25 사고 원인: 202개국 ISO 자동생성(`kr-passport`)이 기존 국가명 레거시(`korea-passport`)를 안 치우고 공존 → 한 달간 중복 색인.
- [ ] 변환 후 **slug 키 중복(같은 type+country) 리포트** 출력. 충돌 시 머지 규칙 명시.
- [ ] **비표준 type 누락 검사**: 변환 스크립트의 type 화이트리스트(예: `TYPE_MAP`)에 없는 **기존 슬러그를 경고**한다. 2026-06-19 사고에서 `halfcard`·`china-resume`이 convert `TYPE_MAP`(표준 7 type)에 없어 ISO 생성에서 조용히 누락 → 후속 일괄삭제로 폐기됨(의도 아닌 부작용). 화이트리스트 밖 기존 콘텐츠는 누락 경고 + 명시 결정(편입/폐기) 필요.
- [ ] 레거시 슬러그를 폐기할 거면 **§2의 301 절차**를 동시 수행.

## 2. 슬러그·URL 삭제/변환 시 — 완료 조건 (필수 3종)

URL이 바뀌거나 사라지는 작업은 아래 3가지를 **완료 조건**으로 한다. 하나라도 빠지면 미완료.

- [ ] **① 301 매핑**: 삭제·변경되는 모든 옛 URL → 새 정본 URL 리다이렉트. 규칙 기반(정규화) 또는 명시 맵.
  - 정본 부재(콘텐츠 자체 삭제)면 404(noindex) 또는 상위 목록으로 폴백.
- [ ] **② sitemap 확인**: 새 정본만 sitemap에 남고, 옛 URL은 제외됐는지 확인(동적 생성이면 자동).
- [ ] **③ GSC 노출 영향 체크**: 삭제 대상 URL을 GSC `search_analytics`로 조회 → **노출>0인 URL은 반드시 301**. 노출 큰 URL 삭제는 작가님 보고.

## 3. 중복 URL 상시 감지

- [ ] **sitemap vs GSC 색인 정기 대조** (월 1회+): sitemap에 없는데 색인된 URL = 죽은 자산 후보. 404면 301 처리.
- [ ] 같은 콘텐츠가 2개 URL로 잡히면 canonical 태그 또는 슬러그 단일화.

## 4. 배포 후 검증

- [ ] 변경된 URL 패턴을 **prod 실측**(curl http_code). 옛 URL 301 / 새 URL 200 확인.
- [ ] GSC에서 **색인 회복 관측**(노출·색인 그래프). 며칠~수주 소요.

## 5. 적용 메커니즘 (현재 구현)

- `render-specs.js`: `renderSpecsDetail`에 정규화 fallback — 매칭 실패 시 `canonicalCountry`(국가명→ISO) + `TYPE_ALIASES`(type 통폐합) 후 재조회 → 301. 404는 HTML(noindex)로.
- `redirects.js`: 블로그 등 명시적 301 맵.
- **이 fallback이 §2-①의 규칙 기반 301 구현체.** 슬러그 체계가 또 바뀌어도 정규화 규칙만 갱신하면 자동 승계.

## 6. 연결

- **PF_SPECS**: specs 데이터/페이지 작업 시 본 프로토콜 준수 (작업 계획 다수 — 데이터 확장·규격 보강 시 §1·§2 필수).
- **PF_PORTAL**: SSR 라우팅·404 처리.
