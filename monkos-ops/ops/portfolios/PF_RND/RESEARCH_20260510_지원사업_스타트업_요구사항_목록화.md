# 정부·기관 지원사업이 스타트업에게 요구하는 것

> **근거**: 모두의 챌린지 AX-LLM (탈락), 강한소상공인 혁신유형 v9 (제출), RIPC 특허 (접수)
> **용도**: PF devlog 서론의 공통 프레임, 사업화 프레임(§7)의 체크리스트, 향후 지원사업 대응 정본
> **원칙**: 챗봇뿐 아닌, 스타트업 전반에 적용되는 보편적 요구사항 추출

## 1. 공통 질문 체계 — "심사위원이 묻는 7가지"

모든 지원사업의 평가는 결국 이 질문들의 변주다.

| # | 심사위원의 질문 | 한 줄 핵심 | AX 대응 섹션 | 강한소상공인 배점 |
|---|---------------|----------|-------------|----------------|
| Q1 | **너 누군데?** | 팀 역량 + 도메인 적합성 | §1 일반현황, 인력구성 | 적합도 10점 |
| Q2 | **뭘 만드는데?** | 제품/서비스 정의 + 기술 구조 | §3-1 협업과제 소개 | 시장성·경쟁력 15점 |
| Q3 | **뭐가 다른데?** | 경쟁사 대비 차별성 + MOAT | §3-2 기술 경쟁력 | 창의성·독창성 15점 |
| Q4 | **지금까지 뭘 했는데?** | 실적·실증·수치 | §1 주요성과, §3 완성수준 | 성과·이력 10점 |
| Q5 | **어떻게 돈 벌 건데?** | BM + 유닛이코노믹스 + 자금계획 | §5-1 사업성, §7 사업비 | 자금계획 20점 ★ |
| Q6 | **얼마나 커질 수 있는데?** | 시장규모 + 확장경로 + 기대효과 | §5-2 확장·지속가능성 | 기대효과 15점 |
| Q7 | **왜 우리(기관)랑 해야 하는데?** | 수요기업/파트너 시너지 | §2 협업현황, §4 추진전략 | 파트너 협업 15점 |

## 3. AX 혁신 트랙 특수 요구사항 (강한소상공인과 다른 점)

AX는 **수요기업(대기업)과의 협업**이 핵심. 일반 지원사업과 다른 추가 축:

| # | AX 특수 요구 | 일반 지원사업에는 없는 것 | 우리 교훈 |
|---|------------|----------------------|----------|
| A1 | **수요기업 과제 정합** | 대기업이 제시한 구체 과제에 맞춰야 함 | 오라클 3개 과제를 통합 제안 — 범위가 넓어 포커스 분산 |
| A2 | **OCI/AWS 등 인프라 통합** | 수요기업 인프라에 이식 가능해야 함 | MONKOS = GCP 올인 → OCI 어댑터 필요 = 추가 개발 부담 |
| A3 | **GPU 활용 계획** | GPU 지원 여부 + 활용 계획 | GPU 불필요 체크 — 오히려 약점? 클라우드 API 의존 |
| A4 | **과제당 1개 기업 선정** | 극소수 선정 (과제당 1개사) | 경쟁률 극심, 팀 규모·실적이 약점 |
| A5 | **B2B SaaS 납품 능력** | 엔터프라이즈 납품 경험 요구 | B2B 실적 0건 — 가장 큰 약점 |
| A6 | **보안·컴플라이언스** | 기업 데이터 보안 + 개인정보 처리 | MONKOS 보안 체계 있으나 증빙 부족 |
| A7 | **공동 레퍼런스** | 수요기업과의 공동 마케팅 | 오라클 이벤트 참여 제안 — 아직 실적 없음 |

## 4. 탈락 원인 분석 — AX LLM 트랙

| 원인 | 상세 | 개선 방향 |
|------|------|----------|
| **팀 규모** | 4명 (대표 포함) — 대기업 협업 프로젝트 수행에 인력 부족 인상 | 외부 전문가·자문단 강화, 멀티 에이전트 시스템의 생산성 정량 증빙 |
| **B2B 실적 0건** | 라이브 서비스는 B2C — 엔터프라이즈 납품 경험이 증명 안 됨 | 파일럿 1건이라도 확보 후 재도전 |
| **인프라 이질성** | GCP 올인 → OCI 포팅 비용·리스크가 심사위원에게 보임 | 멀티 클라우드 대응 능력 증빙, 어댑터 PoC 선행 |
| **과제당 1개 기업** | 경쟁률이 구조적으로 극심 | 복수 트랙 병렬 신청, 약한 트랙은 포기 |
| **GPU 불필요** | LLM 과제에서 GPU 안 쓴다 = "본격적이지 않다" 인상 가능 | 온디바이스·파인튜닝 GPU 계획 포함 |

## 5. 지원사업 공통 체크리스트 — PF devlog·사업화 프레임이 채워야 할 것

> 이 체크리스트를 PF별로 채우면, 어떤 지원사업에도 바로 대응 가능.

| # | 항목 | PF 대응 섹션 | 체크 |
|---|------|------------|------|
| 1 | 제품/서비스 한 줄 정의 | §1 비전 | |
| 2 | 기술 아키텍처 다이어그램 | §4 아키텍처 | |
| 3 | TRL 수준 명시 | §3 Phase 현황 | |
| 4 | 경쟁사 비교표 (N개사 전수조사) | §7 사업화 프레임 - 차별성 | |
| 5 | 선행연구 서베이 (논문·특허) | devlog 서론 §Ⅰ-4 | |
| 6 | RQ + 평가 체계 (테스트 스키마) | devlog 서론 §Ⅰ-3, §Ⅰ-6 | |
| 7 | devlog (기술 판단 기록) 3편+ | devlog 본론 §Ⅱ | |
| 8 | BM + 유닛이코노믹스 | §7 사업화 프레임 - 사업모델 | |
| 9 | 매출 시나리오 3단 | §7 사업화 프레임 - 수익전망 | |
| 10 | 확장 경로 3단계 | §7 사업화 프레임 - 확장성 | |
| 11 | TAM/SAM/SOM | §7 사업화 프레임 - 확장성 | |
| 12 | 정량 성과 (커밋·배포·사용자·매출) | §2 히스토리 + PF 성과 | |
| 13 | 특허/IP | PF 관련 문서 | |
| 14 | 복기 (실패·교훈·대응) | §5 복기 | |

> 안 된 게 아니라, 안 적어둔 것이었으니까.
