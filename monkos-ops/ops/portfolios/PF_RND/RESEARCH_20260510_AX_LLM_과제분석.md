## 4. 핵심 인사이트

### 4-1. 대기업이 진짜 원하는 것 (표면 vs 본질)

| 표면 (과제 제목) | 본질 (왜 스타트업에게 시키는가) |
|----------------|---------------------------|
| "RAG 기반 지식 검색" | 자사 LLM의 **실증 레퍼런스**가 필요하다. 스타트업이 도메인 데이터를 갖고 와서 "돌아간다"를 증명해줘야 한다 |
| "AI Agent 개발" | 자사 플랫폼 위에서 **동작하는 앱 생태계**를 만들고 싶다. 스타트업 = 앱 개발자 역할 |
| "도메인 특화 파인튜닝" | 범용 LLM을 **수직 시장에 꽂는 것**은 대기업이 못 하는 일. 도메인 데이터 + 현장 지식이 스타트업에게 있다 |
| "문서 자동 분류" | 엔터프라이즈 고객의 **가장 흔한 pain point**를 풀어줄 킬러 유스케이스가 필요하다 |
| "서빙 최적화" | 자사 모델(EXAONE 등)의 **프로덕션 배포 파이프라인**을 누군가 만들어줘야 한다 |

### 4-2. 우리(MONKOS)의 포지셔닝

**강점**: RAG + 챗봇 + 다국어 + 문서 분류 + 멀티에이전트 — 이미 라이브. TRL 7~8.
**약점**: 제조 도메인 없음, B2B 실적 0, 파인튜닝 경험 없음, 팀 소규모.

**AX 재도전 전략**:
- 제조가 아닌 **기업 업무 자동화** 트랙이 우리 적합 (오라클 O2, O3)
- 차기 공고에서 **KT 의료/교육** 같은 서비스 도메인이 우리 무기(챗봇+다국어+RAG)와 맞을 수 있음
- **B2B 파일럿 1건 확보**가 재도전의 전제 조건

### 4-3. devlog/선행연구에 편입할 시사점

이 과제들이 보여주는 것은 **시장이 요구하는 AI 역량의 우선순위**다:
1. RAG (48%) — 우리가 가진 것
2. Agent (44%) — 우리가 가진 것
3. 파인튜닝 (32%) — 우리가 없는 것 → RQ 후보
4. 문서 처리 (28%) — 우리가 가진 것
5. VLM (20%) — 우리가 약한 것

devlog 서론 §4 선행연구의 "기술 동향" 섹션에 이 분석이 들어가면, **"시장이 원하는 것 중에 우리가 뭘 갖고 있고 뭘 만들어야 하는가"**의 근거가 된다.
