# PF_STYLER — 메타 PF

> "당신을 스타일링한다" — 규격부터 커머스까지, 하나의 진화 선 위에 있는 서비스 로드맵.
> 4MUSE ai_lab 시절부터 그려진 원래 그림의 정본.

---

## 1. 비전

**"내 얼굴/몸에 무언가를 입혀서 미리본다"** — 그 "무언가"가 확장된다.

```
증명사진 (규격 대응)
  → 헤드샷 (스타일링, 템플릿 프롬프트)
    → 모델스 (고객사 아이템 장착, VTON)
      → 앱 (폰 앨범 기반 스타일 제안 + 커머스 중개)
```

### 각 단계의 본질

| 단계 | 하는 일 | 핵심 기술 | 수익 모델 |
|------|---------|----------|----------|
| **증명사진** | 규격에 맞춘다 | 얼굴 인식 + 규격 크롭 | 건당 과금 |
| **헤드샷** | 스타일을 입힌다 | 스타일 프롬프트 + Imagen | 건당 과금 |
| **모델스** | 아이템을 입힌다 | VTON (가상 피팅) | B2B + 건당 |
| **앱** | 일상에서 미리본다 | Apple Vision + 온디바이스 | 구독 + 커머스 중개 |

### 앱 비전 (IDPASS 확장)

IDPASS 앱은 이미 출시 상태. Apple Vision의 온디바이스 얼굴 인식 덕분에:

- 고객이 셀카를 우리 서버에 올릴 필요 없음 — **폰 앨범 접근 허용만으로 모든 것이 가능**
- 폰 안에서 얼굴 잡고 → 서버에는 스타일 요청만 → 결과를 받아 미리보기
- 사진 업로드 마찰 0, 프라이버시 강점

**사용 시나리오:**
1. 헤드샷 생성 고객이 "이 느낌 좋은데, 다른 스타일도 보고 싶다" → 옆에 예쁜 스타일 카드 → 적용해보기
2. 쇼룸에서 예쁜 옷 발견 → 폰으로 찍으면 → 앱에 저장된 내 셀카에 즉시 가상 피팅
3. 스타일 제안 푸시 → 새로운 생성 → 마음에 들면 결제 → 커머스 연결

**연결 구조:**
```
고객 폰 앨범 (Apple Vision, 온디바이스)
  ↔ MONKOS 서버 (스타일 생성 엔진)
    ↔ 커머스 파트너 (의상/아이템 카탈로그)
```

우리가 중개하는 것: **고객의 "미리보기 욕구"와 커머스의 "전환"** 사이.

## 3. 에셋 구조 (설계 중)

> 2026-06-21 세션에서 GCS 전수 파악 완료. 전체 구조 확정 후 반영 예정.

### 현황

- GCS 고객 데이터 버킷 분리 준비 완료 (monk-customer-photos, 코드 변경 대기)
- 자체 에셋(blog/ads/profiles) monk-ai-images에 혼재
- 로컬 워크벤치 ↔ GCS 정위치 동기화 미구축

### 방향

- 고객 데이터: 서비스 라인별 prefix (`idphoto/`, `headshot/`, `models/`, `stylebook/`)
- 자체 에셋: 용도별 prefix (`blog/`, `ads/`, `lookbooks/`, `catalog/`)
- 로컬 워크벤치: GCS prefix 구조를 거울 반영하는 폴더 표준
- 어드민 에셋 브라우저: 트리+썸네일+업로드 동선
