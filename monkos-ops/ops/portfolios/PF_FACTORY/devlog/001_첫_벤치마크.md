# 4060에서 소형 LLM은 얼마나 쓸만한가

## 1. 문제의식

MONKOS 챗봇(PF_CHATBOT)은 현재 Workers AI(Cloudflare)로 추론 중이다. 자체 호스팅으로 전환하면 비용 절감 + 커스터마이징이 가능하지만, 4060 VRAM 8GB에서 실용적 품질의 추론이 가능한 모델이 있는지 먼저 확인해야 한다.

RQ001: "4060 8GB에서 실용적으로 돌릴 수 있는 최대 LLM 사이즈는?"

## 2. 테스트 설계

### 환경
- GPU: NVIDIA RTX 4060 (8GB VRAM)
- conda `factory` 환경: Python 3.10 + PyTorch 2.11.0+cu126
- transformers 5.8.0, accelerate 1.13.0

### 대상 모델
| 모델 | 파라미터 | 양자화 | 선정 이유 |
|------|---------|--------|----------|
| Qwen3-1.7B | 1.7B | fp16 | 최신 Qwen 시리즈, 경량 |
| Qwen2.5-3B-Instruct | 3B | fp16 | 중간 사이즈, 다국어 |
| Phi-3.5-mini-instruct | 3.8B | fp16 | MS 추론 특화 |

### 프롬프트
- kr1: "증명사진 촬영 시 주의사항 3가지를 알려주세요."
- kr2: "MONKOS AI 서비스를 한 문장으로 소개해주세요."
- en1: "List 3 tips for taking a passport photo."

### 측정 항목
- 모델 로드 시간, VRAM 사용량, 추론 속도(tok/s), 응답 품질

## 3. 결과

### 완료된 벤치마크

| 모델 | VRAM | 속도 | 비고 |
|------|------|------|------|
| **Qwen3-1.7B** | **3,283 MB** | **25.9 tok/s** | fp16, 3개 프롬프트 평균 |

- VRAM 8GB 중 3.3GB 사용 → 여유 충분, 4B급까지 fp16으로 수용 가능 추정
- 25.9 tok/s → 체감 응답 속도 양호 (200토큰 응답 ~8초)

### 미완료

| 모델 | 사유 |
|------|------|
| Gemma-3-4B-it | HuggingFace 게이트 모델 — 인증 필요 |
| Phi-4-mini | transformers 5.8과 호환 에러 (LossKwargs) |
| Qwen2.5-3B | 다운로드 중 네트워크 지연 (HF 비인증 rate limit) |
| Phi-3.5-mini | 동일 다운로드 지연 |

### 실행 환경 이슈
- `conda run`의 cp949 인코딩이 한국어 모델 출력을 처리 못함 → 직접 python 실행으로 우회
- HF 비인증 다운로드 속도 제한 심함 → HF_TOKEN 설정 필요

## 4. 결론

### 확인된 것
- 4060에서 1.7B fp16 모델은 **25.9 tok/s로 실용 가능**
- VRAM 3.3GB 사용 → 4B급까지 fp16 수용 여지 있음
- 팩토리 봇(`/notifyWriter`) 경유 텔레그램 보고 풀 사이클 검증 완료

### 다음 단계
1. **HuggingFace 토큰 설정** → 다운로드 속도 + 게이트 모델 접근
2. **3~4B급 모델 벤치마크** (Qwen2.5-3B, Phi-3.5-mini, Gemma-3-4B)
3. **Q4 양자화 테스트** → VRAM 절약 + 속도 비교
4. 한국어 품질 정량 평가 기준 수립
