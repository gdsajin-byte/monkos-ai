## 2. ⭐ 근본 원인 — 폴백이 도달할 수 없는 예산 구조

```
MATTE_TIMEOUT_MS = 60,000   (lib/matte.js:33)
  → 1차 호출 60s + 재시도 60s = 4060 에만 120s 소진
Cloud Run timeoutSeconds = 120   (monkos-portal / portal-dev 동일)
  → 전체 요청 예산 = 120s
∴ 4060 이 60s를 넘기는 순간, RunPod 폴백에 남는 시간 = 0s
```

**504가 정확히 119.997s에 찍힌 것은 우연이 아니라 이 산식의 결과다.** 폴백은 "있으나 마나"가 아니라 **원리적으로 늦는다**.

부수 결함 3건:

1. **생사 프리플라이트가 포화를 못 본다** — `isAlive()`는 `GET /health` 2.5s(`HEALTH_TIMEOUT_MS`). `/health`는 GPU 큐를 타지 않으므로 **포화 중에도 200**. "죽음"은 걸러도 **"밀림"은 못 걸러** 매번 4060에 전 예산을 태운다.
2. **중단된 잡이 서버에서 취소되지 않는다** — 클라이언트가 60s에 abort해도 4060은 계속 처리한다. 게다가 **재시도가 같은 엔드포인트로 한 건 더 투입**된다 → 유저 1회 시도가 **잡 2건**을 남기고, 그 유령 잡이 다음 요청의 대기열을 밀어 올린다. **13.7분 대기의 형성 기전**.
3. **성공/실패 인식 불일치** — 서버는 폴백으로 완주해 GCS 저장·`생성 완료`까지 기록했지만 **유저는 504를 봤다**. 로그만 보면 정상으로 읽힌다.

## 3. 🔴 파생 피해 — 무료 1회가 소모됐다

`server.js:688` **무료 쿼터는 선차감**(Firestore 원자)이고, 실패 경로에서만 `refundGate`로 환급한다.
이번 건은 **서버 기준 성공**이라 환급이 돌지 않는다. 반면 카운트를 동기화하는 `Set-Cookie`(`server.js:892`)는 504로 대체된 응답에 실려 **유저에게 도달하지 못했다**.

> **결과: 유저는 결과물을 못 받았는데 무료 생성권은 차감됐다.** 유료가 아닐 뿐 [[feedback_paid_failure_no_degraded_delivery]]가 금지한 **"실패했는데 생성권 소모"** 그 형태다.
