## 3. 신규 문서 경로 확정안

### 3-1. 정본 경로 단일화

| 유형 | **확정 정본** | 비고 |
|------|-------------|------|
| **지시서** | `monkos-ops/ops/orders/YYYY-MM/` | ORDER_ 단일. TASK_는 레거시 |
| **보고서** | `monkos-ops/ops/reports/YYYY-MM/` | REPORT_, COMPLETION_, REVIEW_ 통합 |
| **세션 로그** | `monkos-ops/ops/sessions/YYYY-MM/` | 패턴 #7~#9 |
| **어젠다/리서치** | `monkos-ops/ops/agenda/` | RESEARCH_, AGENDA_ |
| **기술 스펙** | `monkos-ops/tech/specs/{service}/` | SPEC_ 단일 정본 |
| **설계 문서** | `monkos-ops/tech/designs/YYYY-MM/` | DESIGN_ 단일 정본 |
| **인시던트** | `monkos-ops/ops/incidents/YYYY-MM/` | INCIDENT_ |
| **코드 리뷰** | `monkos-ops/tech/reviews/` | REVIEW_ (기술 리뷰) |
| **청구서** | `governance/constitution/petitions/` | 변경 없음 |
| **법률/헌법** | `governance/laws/` | 변경 없음 |

**원칙**: 신규 문서는 **전부 monkos-ops/ 또는 governance/**에 생성. docs/에 신규 생성 금지.

### 3-2. docs/ 역할 재정의

```
docs/ = 아카이브 (읽기전용)
├── corpus/sessions/     ← 세션 로그 아카이브 (1~2월)
├── monkos/tasks/        ← TASK_ 아카이브 (2월 레거시, 동결)
├── monkos/reports/      ← REPORT_ 아카이브 (2월 레거시, 동결)
├── monkos/designs/      ← DESIGN_ 아카이브 (2월 레거시, 동결)
├── monkos/incidents/    ← INCIDENT_ 아카이브 (기존 1건)
├── monkos/specs/        ← SPEC_ 아카이브 (구버전)
├── infrastructure/      ← 원천 아카이브 (보물창고, 변경 없음)
├── specs/               ← 기술 명세 아카이브 (구버전)
└── rnd_2026/            ← R&D (변경 없음)
```

**핵심 선언**: `docs/monkos/` 하위에 **신규 파일 생성 금지**. 참조만 허용.

### 3-3. 월별 서브폴더 도입

현재 flat 구조를 월별로 분리:

```
monkos-ops/ops/
├── orders/
│   ├── 2026-02/          ← 2월분 이관
│   ├── 2026-03/          ← 3월분 (현행)
│   └── README.md
├── reports/
│   ├── 2026-02/
│   ├── 2026-03/
│   └── README.md
├── sessions/
│   ├── 2026-02/
│   ├── 2026-03/
│   └── README.md
├── incidents/
│   ├── 2026-03/
│   └── README.md
└── agenda/               ← flat 유지 (건수 적음)
```

## 4. 컴팩팅 방어 메커니즘

### 4-1. 정본 README 방어선

각 정본 폴더 README.md 상단에:

```markdown
> ⚠️ **정본 선언**: 이 폴더가 {유형}의 유일한 정본입니다.
> docs/monkos/{대응폴더}/는 2월 이전 아카이브입니다. 참조하지 마세요.
> 최신 문서는 이 폴더의 가장 최근 월별 서브폴더에 있습니다.
```

### 4-2. 아카이브 동결 표시

`docs/monkos/` 하위 각 폴더 README.md에:

```markdown
> 🔒 **아카이브 동결**: 이 폴더는 2026-02 이전 산출물의 보존소입니다.
> 신규 파일 생성 금지. 정본은 monkos-ops/ops/{대응폴더}/에 있습니다.
> 이 폴더의 문서를 기준으로 설계/실행하지 마세요.
```

### 4-3. SPEC 정본 단일화 + 버전 표시

동일 기능의 SPEC이 여러 곳에 있을 때:

1. **정본(ops/tech/specs/)**: 파일 상단에 `version: current`
2. **아카이브(docs/specs/)**: 파일 상단에 `version: archived / superseded-by: {정본 경로}`
3. **컴팩팅 후 에이전트가 SPEC을 읽을 때**: version 필드 확인 → archived면 정본 경로로 이동
