## 1. 군사 체계: 지휘 승계 (Chain of Command Succession)

### 1-1. 체계 개요

미군의 지휘 승계 체계는 두 축으로 구성된다:
- **작전 지휘 계통**: 대통령 -> 국방장관 -> 통합전투사령관
- **행정/제도적 계통**: 각 군 장관 -> 참모총장 -> 예하 부대장

### 1-2. 핵심 메커니즘

| 요소 | 내용 |
|------|------|
| **트리거 조건** | 지휘관의 사망, 무력화, 전역, 전보, 또는 일시 부재 (AR 600-20) |
| **승계 방식** | **자동 승계 원칙**: 해당 부대에 정규 배속된 최선임 군인이 자동으로 지휘를 인수. 우선순위: 장교 > 준위 > 사관생도 > 부사관 > 병사 (AR 600-20 para 2-8) |
| **지명제 예외** | 지휘관이 후임자를 직접 지명할 경우, 차상급 지휘관의 승인을 받아 "Acting Commander"로 임명 가능 |
| **대행 범위** | Acting Commander는 임시적 지위. 상급 지휘관이 영구 지정하지 않는 한 "acting" 지위로 발표 |
| **시간 제한** | 명시적 기한 없음. 상급 지휘관 또는 적정 권한자가 영구 보직을 결정할 때까지 지속 |
| **보고 의무** | 지휘 인수 시 공식 발표(Assumption of Command Order) 필수. 상급 지휘관에게 즉시 보고 |

### 1-3. Devolution (위임 이양)

정상적 승계가 불가능할 경우(통신 두절 등), 사전 지정된 하위 단계 인력에게 권한이 이양되는 별도 메커니즘. **Designated Succession**(순서 기반)과 구별됨.

**핵 지휘 특수 사례**: 대통령 부재 시 부통령이 자신의 "핵 가방(Football)"을 통해 핵 명령 권한을 행사. FEMA는 승계선상 인물의 위치와 상태를 상시 추적.

## 2. 기업 거버넌스: 임원 부재 시 대행

### 2-1. 체계 개요

CEO 승계는 이사회(Board of Directors)의 핵심 책임이며, 3가지 시나리오를 사전 준비한다:
1. **계획적 승계** (Planned Succession): 퇴임 예정 시
2. **긴급 승계** (Emergency Succession): 갑작스러운 부재 시
3. **임시 대행** (Interim/Acting CEO): 과도기

대행 범위는 이사회 결의(Board Resolution), 정관(Bylaws), 고용계약에 의해 규정된다.

### 2-2. 핵심 메커니즘

| 요소 | 내용 |
|------|------|
| **트리거 조건** | CEO의 사망, 무력화, 사임, 해임, 또는 일시적 부재(질병, 휴가 등) |
| **대행 지정** | 이사회 결의로 Acting CEO 또는 Interim CEO 지명. 정관에 사전 승계 순서가 규정된 경우 자동 발동. COO, CFO, 또는 사외이사가 주로 지명됨 |
| **대행 범위** | **운영적 사항(Operational)**: 일상 업무 관장 가능. **전략적 사항(Strategic)**: 장기 고용계약, 대규모 투자, M&A, 조직개편 등은 이사회 승인 필수. 고용계약서에 재무 승인 한도, 인사 권한, 전략적 이니셔티브 범위를 "decision-making boundaries"로 명시 |
| **시간 제한** | 통상 Interim CEO 계약에 6개월 기한을 명시. 서면 합의로 연장 가능 |
| **보고 의무** | 이사회 정기 보고. 상장사는 SEC 8-K Filing으로 임원 변동 공시 |
| **사후 검증** | 이사회 평가 세션에서 대행 기간 의사결정 전체 검토 |

### 2-3. 직무대행 vs 직무대리 (한국법 참고)

| 구분 | 직무대행 | 직무대리 |
|------|---------|---------|
| 전제 | 재직자가 존재하나 직무 수행 불가 | 재직자가 부재(공석) |
| 권한 | 원직자의 권한을 임시 행사 | 해당 보직의 직무를 임시 대리 |
| 효과 | 원직자의 행위로 효력 발생 | 피대리기관의 행위로 효력 발생 |

## 3. 소프트웨어 운영: Break-glass / Incident Command

### 3-A. Break-glass 절차

#### 체계 개요

Break-glass는 정상적인 접근 통제가 불가능한 긴급 상황에서, 사전 정의된 프로세스를 통해 임시 상승 권한을 부여하는 보안 메커니즘이다. AWS Well-Architected Framework와 GCP 모두 핵심 보안 모범 사례로 정의.

#### 핵심 메커니즘

| 요소 | 내용 |
|------|------|
| **트리거 조건** | IdP 장애, 보안 인시던트, 핵심 인력 부재, 시스템 장애로 정상 접근 불가 |
| **대행 범위** | 사전 정의된 Break-glass Role로만 접근. 정상 운영 시 사용 감지되면 알람 발동 |
| **승인** | 1차 승인자 불가 시 2차 승인자로 에스컬레이션. AWS는 "secondary approvers" 경로를 명시적으로 요구 |
| **시간 제한** | AWS 기본 1시간 임시 자격증명. 요청 시 지정한 duration 경과 시 **자동 만료**. 재접근 시 신규 요청 필수 |
| **MFA 요구** | 하드웨어 기반 MFA(물리적 보안 키) 필수. 긴급 상황에서도 인증 통제 유지 |
| **감사 로그** | 모든 성공/실패 시도 상세 로그 생성. GCP Admin Activity 로그 기본 90일 보존 |
| **사후 리뷰** | JIT 플랫폼 로그 기반 포스트모템 리뷰. 컴플라이언스 준수 여부 확인 |

### 3-B. Incident Command System (Google SRE / FEMA ICS)

#### 핵심 메커니즘

| 요소 | 내용 |
|------|------|
| **트리거 조건** | 서비스 장애, 보안 침해, 자연재해 등 모든 유형의 인시던트 |
| **역할 구조** | **Incident Commander(IC)**: 전체 대응 조율, 인시던트 문서 유지. **Communications Lead(CL)**: 이해관계자 업데이트. **Operations Lead(OL)**: 실제 장애 완화 작업 |
| **확장/축소** | ICS 구조는 인시던트의 유형, 규모, 범위, 복잡도에 따라 확장/축소 |
| **에스컬레이션** | 명확한 통신 프로토콜과 에스컬레이션 경로 사전 문서화 |
| **Blameless Postmortem** | SRE 핵심 원칙. 개인/팀을 비난하지 않고 시스템, 절차, 교육의 개선에 집중 |

## 4. 법률 체계: 대통령 권한대행 (한국 헌법 71조)

### 4-1. 체계 개요

대한민국 헌법 제71조: "대통령이 궐위되거나 사고로 인하여 직무를 수행할 수 없을 때에는 국무총리, 법률이 정한 국무위원의 순서로 그 권한을 대행한다."

### 4-2. 핵심 메커니즘

| 요소 | 내용 |
|------|------|
| **트리거 조건** | **궐위**: 사망, 탄핵 결정, 사임 등으로 대통령직 자체가 비어 있는 상태. **사고**: 질병, 해외 순방, 탄핵 소추(직무 정지) 등으로 일시적 직무 수행 불가 |
| **승계 순서** | 1순위 국무총리 → 2순위 이하 정부조직법이 정한 국무위원 순서 (부총리 > 각부 장관) |
| **대행 범위 (학설 대립)** | **무제한설**: 헌법에 제한 규정 없으므로 동일 권한. **제한설(다수설)**: "국가 기능 유지에 필수적인 범위"로 한정. 헌법개정 발의, 특별사면, 국민투표 부의 등 제한. **절충설**: 원칙적 제한, 국정 공백 방지 필요성 있을 때만 행사 |
| **시간 제한** | **궐위 시**: 헌법 68조에 따라 60일 내 후임 선출. **사고 시**: 사고 원인 해소까지 (기한 없음) |
| **보고 의무** | 법률상 명시적 보고 의무 없음. 국무회의 의결 관행 |
| **원직 복귀** | 사고 해소 시 대통령이 자동 직무 복귀. 별도 복귀 절차 없음 |
| **실제 논쟁** | 2024-2025년 대통령 탄핵 소추 기간 중 권한대행의 헌법재판관 지명 논란 → 헌법재판소 가처분으로 제동 |

| **사후 검증** | 상급 지휘관 사후 평가 | 이사회 평가 세션 | Blameless Postmortem | 헌법재판소 가처분 | **사후 검증이 제도 개선의 피드백 루프** |

## 6. 4개 체계를 관통하는 5대 공통 원칙

1. **객관적 트리거**: 대행은 원직자의 부재/불능이 객관적으로 확인되어야 발동. 주관적 판단이나 자의적 발동은 모든 체계에서 불허.

2. **범위 제한 원칙**: 대행자의 권한은 원직자와 동일하지 않음이 기본 전제. 군사(Acting), 기업(operational only), SW(pre-defined role), 법률(다수설: 필수적 범위).

3. **임시성 보장**: 시간 제한(기업 6개월, SW 1시간, 법률 60일)이든 조건 해소(군사: 상급 결정)든, 임시적 성격을 보장하는 장치가 반드시 존재.

4. **기록/보고 의무**: 대행 기간의 모든 행위는 기록되고 보고됨. SW가 가장 체계적(자동 감사 로그), 법률이 가장 느슨(관행 기반).

5. **사후 검증 피드백**: 대행 종료 후 사후 검증을 통해 행위를 평가하고 제도 개선에 반영. Google SRE의 Blameless Postmortem이 가장 정교한 구현.
