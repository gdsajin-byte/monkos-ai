## 왜 이것이 필요한가

현행 법체계에는 PETITION(청구) → amendment(개정 절차)만 존재한다. 이미 법안이 된 것을 통과시키는 경로는 있지만, **"이것을 법으로 만들어야 하는가, 어떤 형태여야 하는가"를 논의하는 공론 과정**이 없었다.

ch4 법률 개정(2026-02-23) 완료 후 미결 4건을 검토하던 중, 위성 프로젝트(한/꾸 협업 체계) 안건에서 이 부재가 드러났다:

- 막내5가 ch1 1조 개정을 청구했으나, 법조문 논의 이전에 **시기 조율·휴먼 간 합의·인프라 성숙도 판단**이 선행되어야 함
- 즉각 법률 개정 절차로 넘기면 미성숙한 법안이 되고, 그냥 보류하면 논의 자체가 휘발됨
- 국회에 비유하면 — 본회의(amendment.md)는 있는데 **상임위원회/공청회**가 없는 상태

작가님+쌍아 합의: "운영 파트에 먼저 설치하고 구조적 논의를 충분히 진행한 후에 헌법으로 올라가는 것이 맞다."

## 이 공간의 성격

**입법 사전 토의장이자 언론.**

어젠다는 결국 입법으로 간다. 그 전에 취지를 밝히고, 발의하고, 비판하는 공론 과정을 거치는 곳이다. 누구든 발의할 수 있고, 누구든 비판할 자유를 가진다.

PETITION(청구)과 amendment(개정 절차) 사이에 놓인다:

```
발의 (누구든) → 어젠다 등록 → 공론·비판·조율 → 법안 성숙 → PETITION/amendment 이관
```

다루는 안건의 성격:
- 시기 미도래로 보류된 청구 — 법안이 되기엔 이르지만 잊혀져선 안 되는 것
- 휴먼 간 조율이 필요한 안건 — 지능만으로 결정할 수 없는 것
- 리서치가 선행되어야 하는 안건 — 영향평가 전에 탐색이 필요한 것
- 비전·전략·철학·조직·해석이 교차하는 안건 — 단일 법률 소관이 아닌 것

## 안건 생애주기

```
발의 → [어젠다 등록] → 공론·비판·조율 → 법안 성숙 → PETITION/amendment 이관 → 입법
```

어젠다는 **즉각 해결이 아닌 숙성**이 목적이다. 세션마다 조금씩 논의가 진전되면 이 README와 개별 AGENDA 문서에 기록하여, 별도로 전체 세션을 읽지 않아도 해당 안건의 취지·맥락·경과·미제 논의를 파악할 수 있도록 한다.

각 안건에는 **발의 기록**을 남긴다 — 누가, 언제, 어떤 취지로 발의했는가.

### 안건 3 상세 맥락

**근본 욕구**: 막내6의 ch3 세션로그↔보고서 연동 청구와 ch7 보고서 작성 규격 청구는 표면적으로 별개이나, 뿌리는 하나다 — **흐름(flow)을 어떻게 기록하고 추적할 것인가**.

이 논제는 다음 전부와 닿아 있다:
- **파일링**: 지시서→보고서→세션로그의 시계열 연결 (현재는 각각 독립, 연결 고리 없음)

- **데몬**: 자동 분류·자동 상태 추적·자동 연결 — 안건 #2와 의존
- **통신**: 보고 수신 → 종합 → 승인의 흐름 자체를 시스템으로 남기는 것

```
    └─ 교육 · 소통 · 커뮤니티 → 서비스 전환
```
