## 1. 발의 경위

7/13 Anthropic의 Remote Control 옵트인 회귀 사건 대응 중, 단일 UI 관제 플레인 확인 → 에이전트 회의실 비전 → 조직 구조형 하네스 → 온디바이스 경량모델 아키텍처 → 검증 MCP 서버 상품화까지 4라운드 논의로 도출.

## 2. 핵심 명제 (작가님 정식화)

1. **조직 구조형 하네스**: 프론티어 모델(전체 설계) → 온디바이스 소형모델(같은 방향성으로 처리) → 각자 상위 에이전트에게 검증받는 위계. "내부 하네스"에서 "모두가 연결되는 하네스"로 가는 길.
2. **온디바이스 경량모델의 병목은 추론이 아니라 검색·검증**: 학습 데이터만으로 대화는 되지만, 최신 정보 취득과 정합 분석 능력이 없다.
3. **해법 구조**: ①검증의 코드화 ②사용자 의도를 정확히 파악해 토큰효율화된 입력만 상향 ③의도 보고서 + 코드화 데이터 기반 정확한 출력을 하향. 완성 시 **온디바이스 2B로도 프론티어의 감각** 발휘.
4. **"검색·MCP는 코드다"**: 소형모델이 결여한 능력은 가중치가 아니라 코드(인프라) — 배포·소유 가능한 자산.
5. **비즈니스 여지**: 내부 체제를 계속 완성하면서, 그 자체가 서비스 비즈니스로서 토큰 경제학과 네트워킹의 선도를 만든다.

## 3. 민아 분석 요지

- **공식**: 모델(교체 가능 부품) + 코드(검색·MCP·검증·라우팅) + 데이터(검증 코퍼스) = 상품은 코드+데이터 패키지.
- **경제 구조**: 검증의 코드화 = 한계비용(토큰)→고정비용(엔지니어링) 전환. 400배 원가 스프레드(7/7 실측 인사이트)의 제도화. 상향 압축률 = 마진 다이얼.
- **MONK OS는 이 패턴을 이미 2층위 가동 중**: ①거버넌스(쌍아 설계→막내 실행→민아 검증→작가님 승인) ②프로덕트(crop L1 온디바이스 프리뷰→L2 서버 정본→발급보장 검증 SLA). 본 안건 = 3층위(고객 대면 서비스화).
- **지시서 양식(ORDER YAML+준수조항) = 의도압축 프로토콜의 인간판** — 거버넌스 코퍼스가 곧 프로토콜 명세서.
- **급소**: 의도 압축은 손실 압축 — 오독된 의도를 상위가 확신 있게 최적화하는 조용한 실패. 대책 = 스키마 제약 양식 + 모호성 플래그 + 불확실 시 원문 상향. 하향 데이터에는 프로버넌스(버전·검증주체·시각) 필수.

## 4. 업계 실증 (7/14 웹 확인)

- **Hermes Agent** (Nous, 오픈소스): 보조 태스크(컨텍스트 압축·웹 요약·승인 스코어링·MCP 도구 라우팅)를 작업별로 싼 모델에 개별 라우팅. 모델 애그노스틱.
- **Google Antigravity 2.0** (I/O 2026): 기본 모델 = Gemini 3.5 Flash를 하네스에 공동 최적화(12x) — 모델을 하네스에 맞춰 튜닝. 멀티모델 라우팅, 5개 배포 표면.
- 함의: "날씨 질문에 미토스 토큰 불필요"가 업계 디폴트 확정. 범용 라우팅은 커모디티화 진행 → 도메인 검증의 상대 가치 상승 + 우리 서버가 꽂힐 소켓 증가.

## 5. 상품 형상 후보

**"MONKOS 검증 MCP 서버"** — 428슬러그 규격 데이터(3언어) + precheck 검증 코드 + 정합감사를 MCP 도구로 노출. 어떤 하네스·어떤 모델이든 꽂는 순간 증명사진 도메인의 검증된 감각 획득. 모델을 파는 게 아니라 모델에 꽂히는 장기(臟器)를 판다.

## 6. 선행 적립 자산 3종 (현재 작업과의 매핑)

| 자산 | 현재 진행 작업 | 비고 |
|------|--------------|------|
| 검증 코드 | precheck 입력검수 확장(치아·컬러렌즈), 정합감사, eyeOpen 캘리브레이션 | 미래 상품의 원가 구조를 깎는 작업 |
| 실물 루프 | 발급보장, 인화 시스템 통합설계(7/13 제안서), 실결제 관통 | 원자 세계 폐루프 = 방어선 |
| 거버넌스 코퍼스 | 헌법·법률·지시서·PF·감사로그 (append-only) | 하네스를 조직처럼 행동시키는 설정 자산. 이식 가능 |

## 7. 착수 트리거 (관찰 지표)

- 오픈소스 하네스(Hermes류)의 일반인 수준 완성도 도달 (설치 마찰·안정성)
- 온디바이스 2B~12B급의 도구호출 신뢰도 임계 돌파 (Gemma 4 12B 등 후속 추이)
- MCP 생태계의 유료 서버 마켓 형성 여부 (수익화 경로)
- 프론티어사의 버티컬 검증 영역 직접 진입 여부 (경쟁 신호)

## 8. 리스크

1. **플랫폼 흡수**: 범용 하네스는 프론티어사가 네이티브 흡수 (RC 7/13 사례 — 주 단위 지형 변동). → 파이프가 아닌 검증된 결과를 판다.
2. **검증 비용 역설**: 계층 검증이 사람 손을 타면 절감분 잠식. → 검증의 코드화가 전제 조건 (6/23 원칙: 감이 아니라 데이터로, 사람이 아니라 코드로).
3. **의도 압축 손실**: 조용하고 그럴듯한 실패 형태. → §3 대책 참조.
4. MCP 반환값 인젝션 표면 → 게이트 코드화도 검증 코드화의 일부.
