## 어젠다 3: 배포라인 정리 + .env 정책

### 이번 세션 장애 경위

| 장애 | 원인 | 영향 | 조치 |
|------|------|------|------|
| JP deploy.sh KR 복사본 | 서비스명 `monkos-idphoto-kr` 하드코딩 | KR 서비스에 JP 코드 배포 | deploy.sh 수정 ✅ |
| KR↔JP 레이스 컨디션 | 동일 이미지 태그 동시 push | KR에 JP 이미지 적용 | KR 단독 재배포 ✅ |
| Portal .env 덮어쓰기 | M1 `.env`에 LS 키 미존재 → `--update-env-vars`가 빈값 설정 | JP 결제(LS) 전면 장애 | .env 보강 + Portal 재배포 ✅ |

### 근본 문제
1. **멀티 디바이스 .env 불일치**: M1과 iMac의 `.env` 키셋이 다름. 어디가 정본인지 불명
2. **deploy.sh가 .env 의존**: `.env`에 없는 키를 빈값으로 `--update-env-vars` 전달 → 기존 값 소멸
3. **병렬 배포 레이스 컨디션**: 동일 `gcr.io/monkos/{service}:latest` 태그를 동시 push

### 대안

| 방안 | 장점 | 단점 |
|------|------|------|
| **A. Secret Manager** | GCP 네이티브, 디바이스 무관 | 구현 비용, deploy.sh 전면 재작성 |
| **B. .env 정본 1곳 + 동기화** | 최소 변경 | 수동 관리, 누락 위험 잔존 |
| **C. deploy.sh 안전장치** | 빈값 체크 + 확인 프롬프트 | 근본 해결 아닌 방어선 |
| **D. B+C 병행** | 현실적 타협 | — |

### 결정 필요
- .env 정본 관리 방식 선택
- deploy.sh에 빈값 방어 로직 추가 여부
- 병렬 배포 허용 여부 (순차 강제 or 이미지 태그 분리)

## 🔥 어젠다 8: 이미지 보관 동의 정책 — 핵심 결정 사항

> **[2026-03-10 21:22 KST] 작가님+M1/쌍아 합의 — 정책 방향 확정**

### 배경
- GCS 이미지 저장 구현 완료 (사무실 세션 P1~P2)
- privacy.html에 "즉시 삭제" 기재 ↔ 실제 GCS 무기한 저장 = **법적 괴리**
- terms.html SNS 보너스 수치 KR=70c, JP=10c, Portal=8c ↔ 실제 코드=100c = **허위 기재**

### 작가님 결정 (확정)

**디폴트 = 즉시 삭제. 고객 선택권 부여.**

| 항목 | 내용 |
|------|------|
| **디폴트** | 보관 거부 (즉시 삭제) |
| **동의 시** | 90일 보관 → 재다운로드 가능 |
| **미동의 시** | 다운로드 완료 즉시 모든 이미지 삭제. 재다운로드 불가 고지 |
| **용도 제한** | AI 학습·마케팅·제3자 제공 일체 금지 명시 |
| **삭제 요청권** | 보관 동의 후에도 언제든 삭제 요청 가능 |

### 작가님 핵심 논거
- 모든 사진관이 고객 파일을 보관함 — 누구도 이의를 제기하지 않음. 오히려 "4년 전 사진 재발급 가능하냐"는 문의가 올 뿐
- "AI가 내 파일을 저장한다" = 언론 프레임. 기술적 실체는 사진관 필름 보관과 동일
- 다만 AI에 대한 막연한 두려움을 무시할 수는 없음 → **선택권으로 해소**
- "암호화 저장으로 안전" = 하나마나 한 소리. 키를 만든 쪽이 풀 수 있음. 진짜 신뢰는 **용도 제한 + 미동의 시 즉시 삭제**
- 빅테크 AI도 데이터 동의 버튼을 누르게 함 — 안 누르면 한 세션짜리. 가치 교환 구조는 동일. 차이는 **우리는 강제하지 않고 선택권을 준다**

### 구현 계획

**Phase 1: 법적 문서 교정 (P0 즉시)**
- privacy.html (KR/JP/Portal): "즉시 삭제" → 동의 기반 보관 정책으로 교정
- terms.html (KR/JP/Portal): SNS 보너스 수치 통일 (코드 정본=100c)

**Phase 2: 동의 분기 코드 구현**
- thankyou 또는 result 페이지: 보관 동의 토글 (디폴트=미체크)
- 동의 시: GCS 저장 유지 + Firestore `consent: true` + `expireAt: 90일`
- 미동의 시: GCS 저장 안 함 (또는 즉시 삭제)
- 재다운로드 API: 동의 사용자 전용

**Phase 3: 정책 정착**
- 삭제 요청 처리 프로세스
- GCS lifecycle rule (90일 자동 삭제)
