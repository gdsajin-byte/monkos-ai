1. **퀄리티는 무결** — 버킷 출고물 작가님 직접 확인. 스튜디오 20년 경력 기준 "나무랄 데 없다"

3. **크레딧 시스템 자체가 거부감** — 돈→크레딧→사진 2단계 추상화. "70c가 얼마지?" 계산하는 순간 이탈

## 2. 검토 안: "$1 = 1장 생성" 직접결제

| 항목 | 현재 | 변경안 |
|------|------|--------|
| 과금 모델 | 크레딧 충전 → 소진 | **생성 시 직접결제** |
| 단가 | 70c (~1,450원) | **$1 (≈1,400원)** |
| 프리뷰 | 있음 (워터마크) | **없음 — 바로 결과물** |
| 원가 지점 | 다운로드 시 과금 | **AI 생성 시 과금** (실제 원가 발생 지점과 일치) |
| Apple IAP | 미구현 | **Tier 1 ($0.99)** |
| 웹 결제 | 토스/Lemon Squeezy | 동일 유지, 크레딧 대신 건별 |

### 장점
- 전 세계 직관적 ($1 = 1장)
- 클레임 리스크 제로 (스타벅스 커피값 이하)
- 퍼널 한 단계로 압축 (생성 버튼 = 결제 버튼)
- iOS 앱과 웹 동일 구조

### 리스크
- 기존 크레딧 보유 유저 마이그레이션
- 결제 시스템 전면 리팩토링 (portal + idphoto-kr/jp + iOS 앱)
- 무료 체험 없이 첫 결제 유도 — 진입 장벽 고려 필요

## 3. 영향 범위 (리팩토링 스코프)

- `monkos_AI/portal/lib/credits.js` — 크레딧 로직 전면 교체
- `monkos_AI/portal/lib/payments.js` — 건별 결제 로직
- `monkos_AI/idphoto-kr/` + `idphoto-jp/` — 결제 플로우 변경
- `apps/MonkosCrop/` (iOS) — Apple IAP 구현
- Firestore users 스키마 — credits 필드 처리
- 기존 크레딧 유저 마이그레이션 정책
