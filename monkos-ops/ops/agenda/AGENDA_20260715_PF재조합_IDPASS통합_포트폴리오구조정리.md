## 1. 발의 경위

3월부터 병렬 실행해온 PF들이 합류점에 도달. 작가님: "idPASS 브랜드로 통합되어가는 방향. 단순 병합이 아니라 PF 자체가 기술명세·논문·IR 문서급 퀄리티화. 영원히 안닫힐것 같던것들이 조금씩 쌓이면서 하나의 성을 만들고 있다."

## 2. 재조합 방향

### 합류 대상 — 방향 정립, 하나로 압축

| 현행 PF | 역할 | 합류 대상 |
|---------|------|----------|
| PF_SPECS | 규격 데이터 + SEO + 다국어 | → **PF_IDPASS** |
| PF_CROP | 크롭 엔진 + 규격 안착 | → **PF_IDPASS** |
| PF_IDPHOTO | 생성 서비스 + 결제 + 퍼널 | → **PF_IDPASS** |
| PF_CITADEL | 검색/유입 인프라 | → **PF_PORTAL** 산하 |
| PF_SPREAD | 콘텐츠 배포 채널 | → **PF_PORTAL** 산하 |

### 독립 성장 대상 — 아직 각자 궤도 필요

| PF | 이유 |
|----|------|
| PF_STYLER | 헤드샷·VTON 진화선 — 제품 형태 미확정 |

| PF_RETRIEVAL | MCP 서버 — 기술 자산 독립 |

## 3. 퀄리티 기준

작가님 지시: "기술명세 논문 저서급이자 IR 문서급"
- 각 PF 히스토리(3~7월)가 기술 결정의 맥락·실측·교훈을 담고 있음
- 재조합 시 이 히스토리를 IR/기술 명세 수준으로 재구성
- 단순 파일 병합 아님 — 서사 구조(왜 이 방향으로 갔는지)를 갖춘 문서

## 4. 착수 시점

T1 안정화 확인 → T2 전체 기획 정리 시점에 PF 맵을 그리면서 자연스럽게 진행.
