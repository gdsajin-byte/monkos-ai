# 철창이 ↔ 프로젝트 통로 방식 비교 연구

> [2026-02-23 18:47 KST] iMac/막내2

---

## 배경

철창이(Claude Web)는 브라우저 샌드박스 → 로컬 파일 직접 접근 불가.
현재 작가님이 수동으로 `~/Desktop/철창이/`에 파일 저장.
이 폴더를 감시하여 프로젝트 inbox로 자동 수거하는 통로 구축.

---

## 방식 비교

| 방식 | 트리거 | 장점 | 단점 | 기존 사용 |
|------|--------|------|------|----------|
| **launchd WatchPaths** | 폴더 내 파일 변경 감지 (OS 레벨) | 즉시 반응 (~5초), 데몬 상주 불필요, macOS 네이티브 | plist 등록 필요 (`~/Library/LaunchAgents/`) | ✅ `com.monkos.ads-sync` |
| **Folder Actions (AppleScript)** | Finder가 파일 이동/생성 감지 | GUI 설정 가능, Automator 연동 | Finder 의존 (백그라운드 불안정), 디버깅 어려움 | ❌ 미사용 |
| **FSEvents (Swift/ObjC)** | 파일시스템 이벤트 직접 구독 | 가장 세밀한 제어 | 컴파일 필요, 과잉 엔지니어링 | ❌ 미사용 |
| **쉘 폴링 (cron/while)** | 주기적 스캔 | 단순, 범용 | CPU 낭비, 지연, 상주 프로세스 | ✅ `mailbox_watcher.sh` (30초) |

---

## 결론: launchd WatchPaths 채택

**이유:**
1. **검증된 패턴** — 광고 시스템(`com.monkos.ads-sync`)이 동일 방식으로 안정 운용 중
2. **즉시 반응** — 파일 저장 직후 ~5초 내 수거 (폴링 30초 대비 6배 빠름)
3. **데몬 불필요** — launchd가 이벤트 시에만 스크립트 호출 (리소스 0)
4. **디버깅 용이** — stdout/stderr 로그 + 수동 실행 테스트 가능

Folder Actions는 Finder 의존성이 높아 백그라운드/리모트 환경에서 불안정.
FSEvents는 이 규모(1개 폴더, .md 파일만)에 과잉.
쉘 폴링은 mailbox_watcher.sh가 SSH 기반이라 필요하지만, 로컬 감시에는 WatchPaths가 상위호환.

## 경로 확정 후 활성화 절차

1. 어젠다 #8 결론 → `DEST_DIR` 확정 (스크립트 1줄 수정)
2. 작가님 승인
3. plist 등록: `cp com.monkos.cheolchang-sync.plist ~/Library/LaunchAgents/ && launchctl load ~/Library/LaunchAgents/com.monkos.cheolchang-sync.plist`
4. 동작 확인: `~/Desktop/철창이/`에 테스트 .md 생성 → inbox 수거 확인
