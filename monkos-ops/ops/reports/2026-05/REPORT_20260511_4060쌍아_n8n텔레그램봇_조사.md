**결론: n8n에는 텔레그램 봇이 존재하지 않습니다.** 컨테이너는 가동 중이나 초기 셋업도 완료되지 않은 상태입니다.

### 3-2. 실제 텔레그램 발신 체계: GitHub Actions

텔레그램 봇은 **GitHub Actions 워크플로우**에서 운용 중입니다.

| 항목 | 값 |
|------|-----|
| 봇 토큰 변수명 | `secrets.TELEGRAM_BOT_TOKEN` (GitHub repo secret) |
| 발신 채팅 ID 변수명 | `secrets.TELEGRAM_CHAT_ID` (GitHub repo secret) |
| 발신 스크립트 | `.github/scripts/telegram_notify.py` |
| 메시지 형식 | HTML (`parse_mode: "HTML"`, 실패 시 plain text fallback) |

### 3-3. 텔레그램 사용 워크플로우 전수

| # | 워크플로우 | 파일 | 트리거 | 텔레그램 발신 |
|---|-----------|------|--------|-------------|
| 1 | **Telegram Notify** | `.github/workflows/notify.yml` | `workflow_call` (다른 WF에서 호출) | ✅ 직접 발신 |
| 2 | **Daily Briefing** | `.github/workflows/daily-briefing.yml` | cron `0 20 * * *` (KST 05:00) + manual | ✅ 직접 발신 |
| 3 | Weekly Dashboard | `.github/workflows/weekly-dashboard.yml` | cron 일요일 (KST 월 06:00) | ❌ 미사용 |
| 4 | Secret Scan | `.github/workflows/secret-scan.yml` | push/PR to main | ❌ 미사용 |
| 5 | Sync Works | `.github/workflows/sync-works.yml` | cron 6시간마다 | ❌ 미사용 |

### 3-4. 발신 흐름 상세

**A. Daily Briefing (자동)**
1. KST 05:00 cron 트리거
2. `daily_briefing.py` 실행 (GA4 + GSC 데이터 수집)
3. 브리핑 파일 생성 → 커밋/푸시
4. GitHub Issue 생성
5. `telegram_notify.py`로 텔레그램 알림 (브리핑 요약 + Issue URL)

**B. Telegram Notify (재사용 워크플로우)**
- `workflow_call` 인터페이스로 다른 워크플로우에서 호출 가능
- 입력: `message` (string, required)
- `telegram_notify.py` 경유 발신

### 💡 건의

1. n8n을 PF_AUTOPILOT 텔레그램 체계의 핵심으로 활용할 계획이었다면, **초기 셋업 + API 키 생성 + 텔레그램 크레덴셜 등록**이 선행되어야 합니다.

3. n8n이 당분간 불필요하면 Docker 리소스 절감을 위해 중지도 고려 가능합니다.
