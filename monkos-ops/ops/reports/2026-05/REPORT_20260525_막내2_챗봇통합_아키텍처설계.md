#### monkos.ai (Cloud Run) → Workers

```javascript
// Cloud Run 측 (chat-engine.js 수정)
const CHAT_WORKERS_URL = process.env.CHAT_WORKERS_URL;  // CF Workers URL
const CHAT_API_KEY = process.env.CHAT_API_KEY;

async function callChatWorkers(channel, sessionId, message, options = {}) {
  const controller = new AbortController();
  const timeout = setTimeout(() => controller.abort(), 8000);  // 8초 타임아웃

  try {
    const res = await fetch(CHAT_WORKERS_URL, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'X-Chat-API-Key': CHAT_API_KEY,
      },
      body: JSON.stringify({ channel, sessionId, message, ...options }),
      signal: controller.signal,
    });

    if (!res.ok) throw new Error(`Workers ${res.status}`);
    const data = await res.json();
    return data.response;
  } catch (err) {
    // 폴백: 기존 Vertex AI 경로 (이중 안전)
    log(`[Chat] Workers 호출 실패, Vertex AI 폴백: ${err.message}`);
    return fallbackToVertexAI(channel, sessionId, message, options);
  } finally {
    clearTimeout(timeout);
  }
}
```

**인증:** 환경변수 기반 API Key. Cloud Run 환경변수에 `CHAT_API_KEY` 설정.
**타임아웃:** 8초 (Workers AI 추론 평균 2~5초 + 네트워크).
**리트라이:** 타임아웃 시 1회 재시도 → 실패 시 Vertex AI 폴백.
**히스토리:** `sessionId`를 Workers에 전달, Workers 측에서 D1 또는 인메모리로 관리. (Phase 초기에는 Cloud Run 인메모리 히스토리 유지, Workers는 stateless 처리 → Phase 완료 후 히스토리도 D1 이관 검토)

### 2-2. 한국어/일본어 품질 예상

**Gemma 4는 Gemini 3 연구 기반**으로 다국어 성능이 Gemma 3 대비 크게 향상. 다만:

- **챗봇 용도** (짧은 Q&A, 3문 이내): 충분. 시스템 프롬프트 준수력이 핵심이며, 26B MoE는 instruction following에 최적화.
- **CS 용도** (텔레그램 5문 이내): 충분. 경어/존댓말 전환은 시스템 프롬프트에서 명시적 지시로 보완.
- **할루시네이션 차단**: 현행 프롬프트의 `[절대 안내 금지]` 블록 유지. Gemma 4의 instruction following 능력으로 잘 준수할 것으로 예상되나, 전환 후 테스트 필수.

**위험 요소:** Gemini 대비 미세한 뉘앙스 차이 가능. 특히 일본어 경어(특정상거래법 관련 CS 응답)에서 품질 검증 필요.

### 2-3. 코칭/QC 채널 호환성

현행 coaching 채널:
```javascript
// chat-engine.js (coaching stateless 분기)
if (options.image) parts.push({ inlineData: { mimeType: 'image/jpeg', data: options.image } });
parts.push({ text: userMessage });
const response = await ai.models.generateContent({ model: 'gemini-2.5-flash', ... });
```

Workers AI Gemma 4 비전 입력:
```javascript
const response = await env.AI.run('@cf/google/gemma-4-26b-a4b-it', {
  messages: [
    { role: 'system', content: coachingPrompt },
    { role: 'user', content: userMessage },
  ],
  image: 'data:image/jpeg;base64,<BASE64_DATA>',   // data URI 형식
  temperature: 0.3,
  max_tokens: 50,
});
```

**호환성 판정: 가능.** Gemma 4는 비전 지원. 다만:
- Gemini의 `inlineData` 형식 → Workers AI의 `image` 파라미터로 변환 필요
- Gemini는 다중 이미지 (`image`, `image2`) 지원 → Workers AI는 단일 `image` 파라미터 (다중 이미지 지원 여부 확인 필요)
- coaching 응답이 "한국어 1문장, 15자 이내"로 매우 짧아 모델 차이 영향 최소

**결론:** coaching 채널은 Phase 4에서 전환 가능. 단, 다중 이미지 입력 제한 시 QC 비교(image vs image2) 기능은 단일 이미지씩 순차 처리로 변경 필요.

### 2-4. 응답 형식 차이

| | Gemini (현행) | Workers AI (Gemma 4) |
|--|--------------|---------------------|
| 응답 경로 | `response.candidates[0].content.parts[0].text` | `result.response` 또는 `result.choices[0].message.content` |
| 스트리밍 | Vertex AI stream | SSE |
| 에러 | GaxiosError | HTTP status + JSON |

현행 `chat.js` (monk.kr)는 이미 Workers AI 응답 형식 사용 중:
```javascript
const response = result.response || result.choices?.[0]?.message?.content || '';
```
→ 변경 불필요.

### 2-5. 토큰 예산 설계

Gemma 4 컨텍스트: 256K tokens

| 항목 | 예상 토큰 | 비고 |

**D1 RAG 검색 SQL:**
```sql
-- 키워드 매칭 (현행 scoreDocument 로직의 SQL 변환)
SELECT id, title, content, keywords, category,
  (CASE WHEN keywords LIKE '%' || ?1 || '%' THEN 10 ELSE 0 END +
   CASE WHEN title LIKE '%' || ?1 || '%' THEN 5 ELSE 0 END +
   CASE WHEN content LIKE '%' || ?1 || '%' THEN 2 ELSE 0 END) as score
FROM chat_knowledge
WHERE score > 0
ORDER BY score DESC
LIMIT 3;
```

실제로는 사용자 쿼리를 단어 분리 후 UNION/합산해야 하므로, Workers 코드에서 단어 분리 후 다중 쿼리 or JS 후처리가 더 현실적.

```javascript
// Workers 측 RAG 검색
async function searchRAG(db, query) {
  const words = query.toLowerCase().split(/\s+/).filter(w => w.length > 1);
  if (words.length === 0) return [];

  const allDocs = await db.prepare(
    'SELECT id, title, content, keywords, category FROM chat_knowledge'
  ).all();

  // 현행 scoreDocument 로직 그대로 적용
  return allDocs.results
    .map(doc => ({ ...doc, keywords: JSON.parse(doc.keywords), score: scoreDocument(words, doc) }))
    .filter(d => d.score > 0)
    .sort((a, b) => b.score - a.score)
    .slice(0, 3);
}
```

**검증:**
- 각 채널별 질문 3종 테스트
- RAG 응답 정확도 비교 (Firestore vs D1)
- 레이턴시 측정

**롤백:** monk.kr은 Phase 1 상태로 유지, monkos.ai는 기존 Vertex AI 경로 유지

// chat-engine.js
const USE_WORKERS = process.env.USE_WORKERS === 'true';

export async function chatWithMonkos(channel, chatId, userMessage, options = {}) {
