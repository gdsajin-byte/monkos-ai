### 3-2. D1 통합 RAG 테이블 스키마

기존 `monk-db`에 RAG 지식 테이블을 **추가**하는 설계.

#### 신규 테이블: `rag_knowledge`

```sql
CREATE TABLE rag_knowledge (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    category TEXT NOT NULL,        -- 'service' | 'pricing' | 'guide' | 'legal' | 'brand' | 'faq'
    locale TEXT NOT NULL DEFAULT 'ko',  -- 'ko' | 'ja' | 'en'
    title TEXT NOT NULL,
    keywords TEXT NOT NULL,        -- 쉼표 구분 키워드 목록
    content TEXT NOT NULL,
    priority INTEGER DEFAULT 0,   -- 높을수록 우선 (동점 시 정렬)
    is_active INTEGER DEFAULT 1,
    updated_at TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_rag_category ON rag_knowledge(category, locale);
CREATE INDEX idx_rag_active ON rag_knowledge(is_active);
```

#### 신규 테이블: `rag_faq`

```sql
CREATE TABLE rag_faq (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    locale TEXT NOT NULL DEFAULT 'ko',
    channel TEXT DEFAULT 'all',    -- 'all' | 'web' | 'telegram' | 'kakao' | 'line'
    question TEXT NOT NULL,
    answer TEXT NOT NULL,
    hit_count INTEGER DEFAULT 0,
    is_active INTEGER DEFAULT 1,
    updated_at TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_faq_locale ON rag_faq(locale, channel);
```

#### 기존 테이블 활용: `documents` + `countries`

증명사진 규격 질문은 기존 D1 `documents` + `countries` 테이블을 **직접 쿼리**. 별도 RAG 복사 불요.

```
사용자: "한국 여권사진 규격이 어떻게 되나요?"
→ 키워드 추출: 한국, 여권
→ D1 쿼리: SELECT d.*, c.ko AS country_name 
           FROM documents d JOIN countries c ON d.country_id = c.id 
           WHERE c.ko LIKE '%한국%' AND d.ko LIKE '%여권%'
→ 결과를 시스템 프롬프트에 구조화 주입
```

#### D1 FTS5 활용 (현행 `includes()` 대체)

```sql
-- FTS5 가상 테이블 (D1 지원)
CREATE VIRTUAL TABLE rag_knowledge_fts USING fts5(
    title, keywords, content,
    content='rag_knowledge',
    content_rowid='id'
);

-- 검색 쿼리
SELECT rk.*, rank
FROM rag_knowledge_fts fts
JOIN rag_knowledge rk ON fts.rowid = rk.id
WHERE rag_knowledge_fts MATCH ?
  AND rk.is_active = 1
  AND rk.locale = ?
ORDER BY rank
LIMIT 3;
```

**현행 대비 개선점**:
- BM25 랭킹 내장 (FTS5 기본)
- 문서 길이 정규화 자동 적용
- 한국어/일본어 토큰은 유니코드 바이그램으로 처리
- Firestore 의존 제거 → 콜드스타트 개선 + 비용 절감

```
cs_knowledge (N건)          →    rag_knowledge (category별 분류)
episode_catalog.json        →    rag_knowledge (category: 'brand')
seed_cs_knowledge.js        →    시딩 스크립트로 전환
seed_cs_legal.js            →    rag_knowledge (category: 'legal')
seed_cs_brand_story.js      →    rag_knowledge (category: 'brand')
seed_cs_prep.js             →    rag_knowledge (category: 'guide')
countries.jsonl             →    기존 D1 documents 활용 (마이그레이션 불요)
```

**마이그레이션 절차**:
1. D1 스키마 마이그레이션 실행 (`rag_knowledge`, `rag_faq`, FTS5 테이블)
2. 기존 seed 스크립트를 D1 INSERT문으로 변환 (Task 2 불일치 수정 반영)
3. `wrangler d1 execute monk-db --file=seed_rag.sql`로 시딩
4. `lib/rag.js`를 D1 쿼리 기반으로 리팩토링
5. Firestore `cs_knowledge` 컬렉션은 마이그레이션 완료 후 비활성화

### 3-5. 202개국 규격 데이터 RAG 활용 설계

**결론: 전체 덤프 ❌ → 검색 기반 조회 ✅**

| 방식 | 장점 | 단점 | 판정 |
|------|------|------|------|
| 전체 덤프 (프롬프트 주입) | 구현 간단 | 320건 × ~200자 = ~64K자 → 토큰 폭발 | ❌ |
| 검색 기반 (SQL 쿼리) | 필요한 규격만 조회, 토큰 최소 | 의도 파싱 필요 | ✅ 채택 |

**구현 흐름**:
```
"일본 여권 사진 규격" 
→ 국가 매칭: countries WHERE ko='일본' OR en LIKE '%japan%'
→ 문서 매칭: documents WHERE country_id=? AND type='passport'
→ 결과: {size: "35x45", px: "413x531", head: "32-36", std: "ICAO 9303", ...}
→ 프롬프트: "[규격 정보] 일본 여권사진: 35×45mm (413×531px), 머리 높이 32~36mm, ICAO 9303 기준"
```

- 국가명은 ko/en/ja 3개 언어로 매칭 → 다국어 질문 대응
- `grade` 필드(A/B/C)로 신뢰도 표시: C등급 시 `공식 출처 확인 권장` 부가
- `warning` 필드 존재 시 특이사항 자동 포함 (예: 미국 비자 배경 흰색 필수)

### 4-3. 챗봇이 알아야 할 핵심 포인트

**1. 같은 뿌리, 다른 형태**
- 동일 대표 운영. 오프라인 20년 노하우를 AI로 서비스화한 것이 MONKOS AI.
- 몽크사진관의 증명사진 품질 기준이 MONKOS AI의 AI 보정 기준이 됨.

**2. 서비스 구분 안내**
- "사진관 방문" → monk.kr 안내 (주소, 영업시간, 예약)
- "AI 증명사진" → monkos.ai 안내 (앱 사용법, 크레딧)
- "증명사진 규격" → monkos.ai/specs (무료 정보) 또는 monkos.ai/crop (무료 크롭)

**3. 크롭앱 (monkos.ai/crop)**
- 무료 독립 서비스. 크레딧 불요.
- 사용자가 가진 사진을 원하는 규격으로 자르기만 하는 도구.
- AI 리터칭/배경 교체와는 별개.

**4. 증명사진 규격 DB (monkos.ai/specs)**
- 202개국 320개 규격 정보 무료 제공.
- 여권, 비자, 면허, 이력서 등 다양한 문서 유형.
- 크롭앱과 연동 — 규격 선택 → 크롭 바로 가능.

**5. 헌법 4조 3항 준수**
- 외부 고객에게는 "MONKOS" 브랜드만 사용.
- 내부 기술명(AI 엔진명 등) 노출 금지.
- "AI가 보정합니다" (O) / 구체적 엔진명 언급 (X)
