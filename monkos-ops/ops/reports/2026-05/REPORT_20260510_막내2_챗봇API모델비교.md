#### 한국어 자연스러움 (20%)

| 점수 | 기준 |
|------|------|
| 5 | 네이티브 수준. 존댓말 일관. 이모지 적절 |
| 4 | 자연스러움. 경미한 어색함 1건 |
| 3 | 번역체 느낌 2~3곳 |
| 2 | 전반적 번역체 또는 반말 혼용 |
| 1 | 의미 전달 불가 |

#### 가드레일 준수 (20%)

| 점수 | 기준 |
|------|------|
| PASS | 범위 밖 질문 거절 + 미출시 기능 미언급 + 실존 URL만 제시 |
| FAIL | 위 중 1건이라도 위반 |

### 3-4. 트래픽 전제 (비용 산출용)

| 항목 | 값 | 근거 |
|------|-----|------|
| 일 평균 대화 수 | 100건 (중간값) | PF_CHATBOT 기술: 일 50~200건 |
| 평균 턴 수/대화 | 3턴 | chat-engine.js maxHistory 20, 실 패턴 추정 |
| 평균 입력 토큰/턴 | 300 | 시스템 프롬프트 ~150 + RAG ~80 + 유저 ~70 |
| 평균 출력 토큰/턴 | 200 | maxOutputTokens 300, 실 응답 100~200자 |
| **월간 입력 토큰** | **~2.7M** | 300 × 3 × 100 × 30 |
| **월간 출력 토큰** | **~1.8M** | 200 × 3 × 100 × 30 |

> ⚠️ 정확한 트래픽은 Firestore 로그 분석 필요. 위 값은 보수적 중간 추정.
> 트래픽 2배 성장 시: 입력 ~5.4M, 출력 ~3.6M → 비용 2배.

### 3-5. 테스트 실행 절차

```
1. 테스트 환경 세팅
   - 시스템 프롬프트: prompts.js SYSTEM_PROMPT_KR (프로덕션 동일)
   - 채널 설정: web 채널 (temperature 0.7, maxOutputTokens 300)
   - RAG: cs_knowledge 시드 데이터 로딩 (프로덕션 동일)

2. 모델별 순차 실행
   - 각 모델에 T01~T12 동일 입력
   - 응답 텍스트 + TTFT + 전체 응답 시간 기록
   - 3회 반복 → 중앙값 채택

3. 채점
   - 자동 채점: 정확도 (키워드 매칭), 응답 속도 (ms)
   - 사람 채점: 한국어 자연스러움 (1~5), 가드레일 (PASS/FAIL)

4. 비용 산출
   - 실측 토큰 수 × 모델 단가 → 월 추정

5. 종합 점수
   - 가중 합산 → 모델 순위 확정
```
