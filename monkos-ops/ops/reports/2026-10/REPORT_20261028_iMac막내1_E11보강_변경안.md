## 4. 적용 시 주의·한계

- **미래 0분의 분 경계**: `date`를 18:31:59에 재고 18:32:00에 쓰면 "과거 1분"이라 통과합니다. 반대 방향(실측보다 늦은 분을 기재)만 막으므로 정상 사용에서 오탐은 없습니다.
- **응답 헤더의 대조 기준**: transcript 항목의 `timestamp`가 응답 생성 완료 시각에 가깝다는 전제입니다. 실제 Claude Code transcript의 `timestamp` 의미(시작/종료)는 **이 세션에서 실측하지 못했습니다**. 그래서 헤더가 생성 시각보다 1~2분 늦게 찍혀도 놓칠 수 있고, 반대로 오탐은 나지 않는 방향입니다. 적용 후 실세션 1회로 확인을 권합니다.
- **경고는 다음 턴에만 보입니다**: Stop 훅 출력은 응답이 끝난 뒤 주입되므로, 이미 나간 응답을 고치지는 못하고 다음 턴 정정을 유도합니다(지시서 의도와 같음).
- **줄 중간 인식은 SendMessage 한정**입니다. 세션 로그·보고서 본문은 다른 메시지 인용이 많아 오탐 위험이 커서 넣지 않았습니다. 필요하면 별건으로 다룹니다.
- 적용 커밋: 지시서 §4 메시지 `[ops] E11 보강 — 미래 허용 0분·줄 중간 헤더 인식·응답 헤더 사후 경고`. 적용은 `git apply`로 하고, 그 뒤 `python3 scripts/hooks/smoke.py`에서 158/158이 나와야 합니다.
