## 2. 카카오톡 채널 연동 가능성

### API 분석 (공식 문서 기반)

**핵심 API: `GET https://kapi.kakao.com/v2/api/talk/channels`**

| 항목 | 내용 |
|------|------|
| 인증 방식 | ① Bearer 액세스 토큰 (유저 본인) ② KakaoAK 어드민 키 (서버 관리자) |
| 응답 핵심 필드 | `relation`: `ADDED` / `BLOCKED` / `NONE` |

| 간편 추가 | `followChannel()` JS API — 서비스 내에서 채널 추가 유도 |

**전제조건:**
- 카카오 로그인 활성화 ✅ (이미 구현)

- "카카오톡 채널 추가 상태 및 내역" 동의항목 동의 (scope: `plusfriends`)


## 3. 라인 공식계정 연동 가능성

### API 분석 (공식 문서 기반)

**핵심 API: `GET https://api.line.me/friendship/v1/status`**

| 항목 | 내용 |
|------|------|
| 인증 방식 | Bearer 액세스 토큰 (LINE Login으로 취득) |
| 응답 핵심 필드 | `friendFlag`: `true` / `false` |
| 웹훅 | Follow Event — 친구추가 시 webhook POST 수신 |
| 로그인 연동 | `bot_prompt=aggressive` 파라미터로 동의화면에서 친구추가 유도 |
| 콜백 추가 | `friendship_status_changed` 파라미터 자동 부착 |

**Messaging API 단독으로는 "특정 유저가 친구인가?" 전용 API 없음** — LINE Login 경유가 필수.

**전제조건:**
- LINE Login 채널 + Messaging API 채널 생성 (LINE Developers Console)
- 두 채널을 같은 프로바이더에 소속
- LINE Login 채널에서 Linked Official Account 등록
- 1 Login 채널 : 1 공식계정 연결

### 기술적 가능/불가 판정

**✅ 가능 — LINE Login + Friendship Status API로 완전 지원**

### 구현 시 예상 아키텍처

```
[신규 구현]
LINE Login (scope=profile openid, bot_prompt=aggressive)
  → 동의 화면 + 공식계정 친구추가 옵션
  → 콜백에서 code 수신 (+ friendship_status_changed)
  → 토큰 교환
  → GET /friendship/v1/status (friendFlag 조회)
  → friendFlag === true → 크레딧 지급
  → friendFlag === false → 친구추가 안내 → 재검증
```

**추가 작업:**

| 작업 | 난이도 |
|------|--------|
| LINE Developers Console 채널 생성 | 낮음 |
| LINE Login OAuth 2.0 플로우 구현 | 중간 (카카오 로그인과 거의 동일 구조) |
| `bot_prompt` 파라미터 추가 | 낮음 |
| Friendship Status API 호출 | 낮음 |
| 게이트에 검증 로직 통합 | 중간 |
| 일본 법인/주소 요구 여부 | 확인 필요 |

### 비용 분석

| 플랜 | 월액(세전) | 무료 메시지/월 | 추가 메시지 |
|------|-----------|---------------|------------|

### 옵션별 상세

#### 옵션 A: 텔레그램 단일 (현행 유지)
- **장점**: 이미 구현 완료. 추가 개발 없음. 봇 메시지 무료.
- **단점**: 한국 유저 90%+, 일본 유저 95%+가 앱 설치부터 시작 → 이탈률 극대
- **전환율 예상**: 한국 10~20%, 일본 5~10% (앱 미설치 유저 대량 이탈)

#### 옵션 B: 시장별 자동 분기
- **로직**: 유저 locale/로그인 제공자 기반 자동 분기
  - 카카오 로그인 → 카카오 채널 게이트
  - LINE 로그인 → LINE 공식계정 게이트
  - 그 외 → 텔레그램 게이트
- **장점**: 각 시장에서 최적 UX. 유저 혼동 없음.
- **단점**: 3개 플랫폼 모두 구현·유지 필요. 운영 복잡도 높음.

#### 옵션 C: 유저 선택형 (추천)
- **로직**: 게이트 화면에서 "카카오톡 / LINE / Telegram 중 선택" 제시
  - 디폴트 추천은 locale 기반 (KR→카톡, JP→라인, 그 외→텔레)
- **장점**: 유저 자율성 존중. 해외 거주 한국인 등 예외 커버. UI가 직관적.
- **단점**: 3개 플랫폼 모두 구현 필요 (B와 동일).
- **핵심 차별점**: B보다 유연하고, 디폴트 추천으로 UX 가이드 가능.

#### 옵션 D: 2단계 점진 확대
- **Phase 1**: 카카오(KR) + 라인(JP) 먼저 구현. 텔레그램 일시 보류.
  - 이유: 한국·일본이 1차 타겟. 이 시장에서 텔레그램 마찰이 가장 큼.
- **Phase 2**: 글로벌 확장 시 텔레그램 추가.
- **장점**: 개발 우선순위 명확. 즉시 ROI 높은 시장부터 공략.
- **단점**: 글로벌 유저 초기 대응 어려움. 텔레그램 기존 구현 활용 못 함.

### 최종 추천 + 근거

**추천: 옵션 C (유저 선택형) — 단, 단계적 구현**

**1단계 (즉시):**
- 카카오 채널 게이트 추가 (기존 카카오 로그인 확장, 구현 1~2일)
- 텔레그램 게이트 유지 (이미 완료)
- UI: "카카오톡 채널 추가" + "텔레그램 채널 가입" 선택

**2단계 (일본 시장 진입 시):**
- LINE 공식계정 게이트 추가 (LINE Login 구현)
- UI: 3개 플랫폼 선택 + locale 기반 디폴트

**근거:**
1. **카카오톡이 가장 높은 ROI**: 이미 로그인 구현됨 → scope 추가만으로 확장 가능. 한국 타겟 전환율 극대화.
2. **텔레그램은 글로벌 백업**: 이미 구현됨. 버리지 않고 글로벌용으로 유지.
3. **라인은 일본 시장 진입 시점에 맞춰 구현**: 신규 Login 구현 필요하므로 일본 마케팅 타이밍에 동기화.
4. **유저 선택형**: Phase 1에서 카톡+텔레 2개로 시작, Phase 2에서 라인 추가하면 자연스럽게 3개 완성.
