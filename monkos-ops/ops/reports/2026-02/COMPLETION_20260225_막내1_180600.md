## 6. 무료 우회 경로 (치명적 발견)

### 우회 경로 1: 비로그인 전체 무료 이용 🔴

```
비로그인 → 생성 (server.js:593 if(body.userId) 스킵) → 다운로드 (result.js:316 바로 진행) → 수령
```

- **생성**: `server.js:593` `if (body.userId)` — userId 없으면 **크레딧 차감 없이 AI 생성 완료**
- **다운로드**: `result.js:295` `if (store.user.id)` — 비로그인이면 **차감 없이 `cropAndGoToThankyou()`**
- **수령처**: `thankyou.js:109~134` — **어떤 인증/크레딧 체크도 없이** 갤러리 저장

### 우회 경로 2: 브라우저 직접 저장 🟡

- 결과 페이지(`result.js:216`)에서 생성된 이미지가 **풀 해상도 base64**로 `<img>` 태그 src에 삽입
- 사용자가 이미지 롱프레스 → "이미지 저장" → **다운로드 크레딧(70c) 우회**
- 워터마크: `result.js`에 워터마크 로직 존재하나, 이는 **프리뷰용** — 실제 다운로드(`downloadResult`)에서는 `store.generated` 원본 사용

### 우회 경로 3: sessionStorage 접근 🟡

- 크롭된 이미지가 `sessionStorage('monkos_cropped')`에 base64로 저장 (`result.js:338`)
- 개발자 도구 → `sessionStorage.getItem('monkos_cropped')` → 풀 이미지 추출 가능

### 우회 경로 4: GCS URL 직접 접근 — 해당 없음 ✅

- 생성된 이미지는 GCS에 저장되지 않음
- 서버(`server.js`)가 Imagen API 응답의 base64를 그대로 프론트에 반환
- 외부 URL 노출 없음

## 종합 진단

### 크레딧 차감 로직 자체는 정상 작동 가능

서버 사이드(`portal/server.js:1274~1330`)의 크레딧 차감 로직은 **Firestore 트랜잭션 기반으로 올바르게 구현**되어 있다. 문제는 **호출 경로의 조건 분기**에 있다.

### 근본 원인: `if (userId)` 조건부 차감

| 지점 | 코드 | 문제 |
|------|------|------|
| 생성 시 | `server.js:593` `if (body.userId)` | 비로그인 → 무료 생성 |
| 생성 시 | `server.js:641` `if (userId)` | 동일 |
| 다운로드 시 | `result.js:295` `if (store.user.id)` | 비로그인 → 무료 다운로드 |

### 설계 판단 필요 사항 (쌍아 판단 요청)

1. **비로그인 생성 허용 여부**: 현재 비로그인도 AI 생성이 가능. 무료 체험 정책인지, 차단해야 하는지
2. **비로그인 다운로드 허용 여부**: 현재 비로그인은 크레딧 없이 풀 해상도 다운로드 가능
3. **워터마크 전략**: 결과 페이지에서 풀 해상도 이미지가 img src에 노출 — 브라우저 저장으로 70c 우회 가능. 프리뷰는 워터마크, 다운로드만 원본 제공 패턴 필요한지
4. **크레딧 차감 시점**: 현재 생성 10c(서버) + 다운로드 70c(프론트) 분리. 단일 시점(생성 80c 또는 다운로드 80c)으로 통합할 것인지
5. **"로그인 유지 상태로 다운로드 반복해도 차감 안됨"** 현상의 추가 확인 필요:
   - 코드 상으로는 로그인 시 `pipe.run('creditUse')` 호출이 정상 경로에 있음
   - 가능한 원인: (a) `store.user.id`가 런타임에 null (인증 상태 불일치), (b) 결과 페이지에서 뒤로가기 후 재진입 시 `downloadResult()` 미호출, (c) thankyou 페이지의 `saveToPhotos()`가 크레딧 체크 없이 재다운로드 가능
