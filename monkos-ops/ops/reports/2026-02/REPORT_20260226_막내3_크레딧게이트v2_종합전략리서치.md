### 세션/상태 유실 시나리오

**모바일:**
- 카카오 로그인 팝업 → Safari/Chrome에서 `window.open`이 새 탭으로 열림 → `postMessage` 수신은 정상 작동

  - **영향**: 생성된 이미지 소실 (`monkos_generated`), 게이트 상태 초기화
  - **현재 보호 장치**: `result.js:441-447`에서 `sessionStorage` 복원 시도하지만, 탭 리로드 시 sessionStorage 자체가 비어 있음
  - **개선안**: 생성 이미지를 `IndexedDB`에도 백업하거나, 서버측에 임시 저장 (5분 TTL)

**데스크탑:**
- 팝업 차단 시 `location.href` 풀 리다이렉트 → 카카오 콜백 후 원래 페이지로 돌아와야 하는데, `redirect_app=idphoto-kr` 파라미터가 포털 서버에서 올바르게 처리되는지 확인 필요
- 텔레그램 웹버전(web.telegram.org)으로 열릴 경우 딥링크 동작이 다를 수 있음

### 크레딧 심리학 분석 (70c 즉시 차감)

**E2E 크레딧 플로우:**
```
[게이트] 0c → +30c(로그인) → +40c(텔레그램) = 70c
[다운로드] 70c → -70c = 0c
[미션] 0c → +100c = 100c (2회째 다운 가능)
```

**"받자마자 전부 쓴다" 심리 분석:**

1. **인지적 프레이밍**: 유저가 직접 돈을 낸 것이 아님 → 30c+40c는 "공짜로 받은 것" → 70c 차감 시 실질적 금전 손실감 **없음**
2. **그러나**: 프로그레스바가 0c/70c → 30c/70c → 70c/70c로 올라가는 과정을 경험한 유저는 "70c를 모았다"는 성취감이 있음 → 다운로드 후 "0c"가 되면 **성취감 소멸**
3. **핵심 리스크**: "70c를 모았는데 한 장에 전부 빠진다고?" → 크레딧이 **통화가 아니라 관문 토큰**이라는 인식 → 충전 전환 의지 저하
4. **완화 장치**: 다운로드 직후 100c 미션 카드 노출 → "더 받을 수 있다" 메시지 → 긍정적 프레이밍 유지

**결론**: 현재 구조는 **수용 가능**하나, "70c 전부 차감" 순간에 "축하! 다운로드 완료 🎉" + Cr 모션 연출로 **차감 행위를 축하 이벤트로 전환**하는 것이 중요. 현재 `result.js:355`에서 "다운로드 완료!" 문구는 있으나, Cr 모션(`showEventCard`/`showThankYou`)이 이 시점에 호출되지 않음 → **Cr 모션 연동 누락**.

**무료 제공량 2장 심리:**
- 1장(생성+다운): 게이트 70c로 완성
- 2장째: 100c 미션 → 다운 70c → 잔액 30c → 3장째부터는 충전 필요
- **2장은 적정**: 1장이면 서비스 체험 불충분, 3장이면 유료 전환 동기 약화. 2장은 "결과물 만족 확인 + 충전 필요성 인식"의 최적점

## 4. 얼굴 블러 허용 여부

### 옵션 비교

| 옵션 | 유저 경험 | 마케팅 가치 | 법적 안정성 | 운영 복잡도 | 추천도 |
|------|----------|------------|------------|------------|--------|
| **A) 블러 허용** | 높음 — 심리적 부담 ↓ | **낮음** — before/after 비교 불가, 소재 활용도 ↓ | 높음 — 유저 자기결정권 존중 | 낮음 | ★★☆ |
| **B) 블러 미허용 (현재)** | 보통 — 일부 거부감 | **높음** — 실물 결과물 소재 | 보통 — 동의서는 있으나 거부 옵션 없음 | 낮음 | ★★☆ |
| **C) 워터마크 프리뷰 자동 첨부** | **높음** — 유저 선택 불필요 | **높음** — 워터마크 상태가 마케팅 소재 겸 브랜드 노출 | **높음** — 원본 노출 없음 + 서비스 홍보 효과 | 중간 — 자동 첨부 로직 구현 필요 | ★★★ |

### 최종 추천: **옵션 C (워터마크 프리뷰 자동 첨부)**

**근거:**
1. **헌법 9조 (I2I 정체성 보존 원칙) 관점**: 워터마크는 원본 정체성을 훼손하지 않으면서 (브랜드 오버레이만 추가) 무단 사용을 방지. 블러는 정체성 자체를 훼손
2. **마케팅 가치**: 워터마크가 있는 before/after 이미지는 "MONKOS" 브랜드 노출 효과가 있으며, SNS 게시 시 자연스러운 광고
3. **유저 부담 제로**: 유저가 블러 여부를 선택하는 의사결정 부담 없음. 자동으로 워터마크 버전이 첨부됨
4. **현재 코드 기반**: `result.js:266-294`에 `generateWatermarkPreview()` 함수가 **이미 구현되어 있음**. 이 워터마크 이미지를 미션 전송 시 자동 첨부하면 됨
5. **법적 안정성**: 원본 얼굴이 텔레그램 채널에 그대로 노출되지 않음 → 유저 프라이버시 보호 + 동의서 범위 내 활용 가능

**구현 방향:**
- 미션 이미지 전송 시, 유저가 직접 캡쳐를 보내는 대신 **서버가 워터마크 프리뷰를 자동 생성하여 봇이 유저에게 확인 요청** → 유저가 "확인" 누르면 채널 게시용으로 저장
- 또는 단순하게: 유저가 캡쳐를 보내되, 서버에서 마케팅 소재로 활용 시 자동 워터마크 적용

**동의서-이미지 순서 법적 적정성:**
- 현행: 순서 비강제 → **부적정**
- 개선: 동의서 서명 완료 후에만 이미지 전송 버튼 활성화 → 동의 선행 보장
