## B. Cloudflare Workers — functions/ 상세

### ⚠️ [심각] auth.js — 구(舊) 토큰 인증 미전환

**현황**: `functions/api/auth.js`가 **쿠키 단일화 이전 체계**를 그대로 유지 중.

| 항목 | auth.js (CF Pages) | portal auth.js (Cloud Run) |
|------|--------------------|-----------------------------|
| 인증 방식 | URL 쿼리 토큰 (`?token=...`) | **HttpOnly 쿠키** (`monkos_session`) |
| 토큰 저장 | `localStorage.setItem('monk_auth_token')` | **서버 측 쿠키** (`Domain=.monkos.ai`) |
| 토큰 형식 | `btoa(JSON.stringify(payload))` (base64, **서명 없음**) | HMAC-SHA256 서명 토큰 |
| 로그아웃 | "클라이언트에서 토큰 삭제" (서버 무효화 없음) | 쿠키 `Max-Age=0` 삭제 |
| 토큰 만료 | 7일 (payload.exp) | 30일 (Max-Age=2592000) |

**문제점**: monk.kr과 monkos.ai 간 인증 체계가 **완전히 분리**되어 있음. 쿠키 단일화 리팩토링이 CF Pages Functions 측에 미적용.

**영향 경로**: `auth.js` → `auth-success.html` → `localStorage` → `ai_lab.html` / `login.html` / `shared.js` (읽기)

### ⚠️ [중간] CORS `*` 전역

- 모든 functions/api/*.js에서 `Access-Control-Allow-Origin: *` 사용
- 쿠키 기반 인증(`credentials: include`)으로 전환 시, `*`는 **양립 불가** (브라우저가 차단)
- 전환 시: `*` → 특정 origin (`https://monk.kr`, `https://monkos.ai`) 지정 필요
- **현 시점**: monk.kr은 아직 localStorage 토큰이므로 즉시 문제 없음. 향후 전환 시 변경 필수.

### sessionStorage/localStorage 미사용 확인 (Workers 측)

- functions/api/ 내 `sessionStorage`/`localStorage` 참조: **0건** ✅
- Workers는 서버 측이므로 당연하나, 불필요 코드 유입 없음 확인

### auth.js signJWT placeholder

- `functions/api/auth.js:515` — `signJWT()` 함수가 **placeholder** 상태
  ```
  return `${data}.signature`;  // ← 실제 서명 미구현
  ```
- GCS 백업 기능(`backupUserToGCS`)이 이 함수에 의존
- `GCS_BACKUP_ENABLED` 환경변수가 `true`이면 **항상 실패** (잘못된 JWT → 401)
- 다만 실패해도 가입 프로세스는 정상 진행 (catch로 에러 무시)
