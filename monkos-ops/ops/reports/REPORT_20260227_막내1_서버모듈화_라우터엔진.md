- DI는 테스트 용이성이 장점이나, 현재 테스트 코드가 없어 과도한 추상화
- 마이크로서비스 분리 시점에 DI로 전환해도 늦지 않음

## 부록: server.js 라우터 패턴 분석

현재 라우터는 `if (req.url === '...')` 체인 방식. Express 등 프레임워크 미사용.

```javascript
// 현재 패턴 (L787~)
const httpServer = createServer(async (req, res) => {
  // CORS...
  if (req.url === '/health') { ... return; }
  if (req.url === '/api/stats') { ... return; }
  if (req.url === '/auth/kakao') { ... return; }
  // ... 37개 if문
  // 정적 파일 (폴백)
});
```

**분리 후 패턴 (제안)**:

```javascript
// server.js — 라우터 맵 방식
const routes = {
  'GET /health': handleHealth,
  'GET /api/stats': handleStats,
  'GET /auth/kakao': handleKakaoAuth,
  'GET /auth/kakao/callback': handleKakaoCallback,
  'POST /api/auth/google': handleGoogleAuth,
  // ... 핸들러 매핑
};

const httpServer = createServer(async (req, res) => {
  // CORS + 보안 헤더
  // OPTIONS 처리
  const key = `${req.method} ${req.url.split('?')[0]}`;
  const handler = routes[key];
  if (handler) { await handler(req, res); return; }
  // startsWith 매칭 (콜백, 패턴 URL)
  // 정적 파일 폴백
});
```

**주의**: `startsWith` 매칭이 필요한 라우트 존재 (auth/kakao/callback, auth/line/callback, api/credits, api/auth/verify, api/download/direct, api/telegram-bonus/*, toss-success, toss-fail). 이들은 별도 prefix 매칭 배열로 처리.
