## 3. 원인 확정

### 🔴 확정 원인: Google Frontend (GFE) 정적 파일 캐시

**메커니즘:**

```
[브라우저] → [monkos.ai] → [Google Frontend (GFE)] → [Cloud Run 컨테이너]
                                    ↑
                            여기서 CSS/JS 캐시됨
                            Cache-Control 헤더 없으면
                            GFE 기본 정책으로 캐싱
```

1. `monkos.ai` 도메인은 Cloud Run 도메인 매핑을 통해 Google Frontend를 경유
2. GFE는 정적 파일(CSS/JS/HTML)에 Cache-Control 헤더가 없으면 **자체 캐시 정책 적용**
3. `b94a0be` 시점의 server.js에는 **Cache-Control 헤더가 0건** — `git show b94a0be:server.js | grep Cache` 결과 없음
4. CSS 파일이 GFE에 캐시된 상태에서, 새 CSS를 배포해도 GFE는 캐시된 구버전을 반환
5. **배포 자체는 성공** — Cloud Run 컨테이너에는 새 CSS가 있었음
6. 하지만 브라우저는 GFE 캐시를 통해 구버전 CSS를 받아봄

**근거:**
- M1 세션 로그 "시점 #4에서 캐시 문제 발견"
- M1 세션 로그 "Cache-Control 헤더 없이 운용해왔기 때문에 CSS/JS 배포가 즉시 반영되지 않았음"
- M1 세션 로그 "캐시 버스팅(`?v=`)으로 우회했으나"
- b94a0be server.js에 Cache-Control 0건 (확인 완료)
- 현재 server.js:269에 `Cache-Control: no-cache` 추가됨 (03-22 세션 중 추가)

### 캐시 버스팅(`?v=`)도 실패한 이유

세션 로그 시도 #5에서 캐시 버스팅을 적용했으나:

1. `<link href="blog-editor.css?v=20260322d">` 를 HTML에 추가
2. 하지만 **HTML 파일 자체도 GFE에 캐시**되어 있었음
3. GFE가 구 HTML(캐시 버스팅 없는 버전)을 반환 → 구 CSS URL 요청
4. 결과: 캐시 버스팅이 동작하려면 HTML 캐시도 먼저 해소되어야 함
5. **이중 캐시 함정**: HTML 캐시 → 구 HTML → 구 CSS URL → 구 CSS

### "캐시 해소됐으나 겹침 지속"의 의미

세션 로그에 "캐시는 해소됐으나 겹침 지속"이라는 기록이 있음. 이것의 의미:

1. 일정 시간 후(또는 Cache-Control 추가 후) GFE 캐시가 갱신됨
2. 새 CSS가 브라우저에 도달 → **배포 자체는 성공했었음을 확인**
3. 하지만 CSS 수정 자체가 근본 원인을 못 잡아서 겹침은 여전히 존재
4. 즉, **배포 미반영 ≠ CSS 버그** — 별개의 두 문제였음

## 4. 재현/검증 방법

### 검증 1: 현재 프로덕션 CSS 캐시 상태 확인

```bash
# GFE 경유 (캐시 가능성 있음)
curl -I https://monkos.ai/admin/css/blog-editor.css

# 응답에서 확인할 항목:
# - Cache-Control 헤더 유무
# - X-Cache 또는 Age 헤더 (GFE 캐시 히트 여부)
# - Last-Modified / ETag
```

### 검증 2: Cloud Run 서비스 URL 직접 접속 (GFE 우회)

```bash
# Cloud Run 서비스 URL 확인
gcloud run services describe monkos-portal --region us-central1 --format 'value(status.url)'

# 서비스 URL로 직접 CSS 요청 (GFE 캐시 우회)
curl -I https://{SERVICE_URL}/admin/css/blog-editor.css

# monkos.ai와 비교 → 내용이 다르면 GFE 캐시가 원인 확정
```

### 검증 3: CSS 내용 비교

```bash
# Cloud Run 직접
curl -s https://{SERVICE_URL}/admin/css/blog-editor.css | head -30

# GFE 경유
curl -s https://monkos.ai/admin/css/blog-editor.css | head -30

# diff 비교 → 내용이 같으면 캐시 이미 해소됨
```

### 검증 4: Cache-Control 헤더 동작 확인 (재배포 후)

```bash
# 현재 server.js에 Cache-Control: no-cache 추가됨 (269행)
# 재배포 후:
curl -I https://monkos.ai/admin/css/blog-editor.css | grep -i cache

# 기대 결과: Cache-Control: no-cache
# 이 헤더가 있으면 GFE가 CSS를 캐싱하지 않음
```

### 검증 5: 배포 URL 불일치 확인

```bash
# 현재 서비스 상태
gcloud run services describe monkos-portal --region us-central1

# 도메인 매핑 확인
gcloud run domain-mappings list --region us-central1

# URL 형식이 -an.a.run.app이면 asia-northeast 리전 → 리전 불일치 가능성
# URL 형식이 -uc.a.run.app이면 us-central1 → 정상
```
