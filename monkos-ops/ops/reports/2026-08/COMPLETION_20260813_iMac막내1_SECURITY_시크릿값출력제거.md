## 2. 원인 — 스크립트 본문 밖이 아니라 **zsh 언어 사양**이었다

쌍아 §2가 "출력원이 스크립트 본문 밖"이라 추정했으나, 실제 원인은 **본문 안**이되 `echo`가 아니라 **`local` 선언문 자체**였다. 셸 초기화 파일·래퍼·`set -x` 전부 무관하다.

### 2-1. 메커니즘

zsh 매뉴얼 `TYPESET_SILENT` (기본 **미설정**):

> 이 옵션이 설정되지 않으면, `typeset` 계열 명령을 **옵션 없이·할당할 값 없이** 실행할 때 **이미 존재하는** 파라미터의 **값을 표시한다**.

`secret.sh`는 `#!/bin/zsh`이고, `cmd_env()`의 `local SM_VALUE` / `local CURRENT`는 **while 루프 안**에 있었다. `local`은 호출마다 새 스코프를 만드는 게 아니라 **함수 스코프 1개에 반복 실행**되므로:

- 1회차: 변수 미존재 → 조용히 선언
- **2회차부터: 변수 기존재 + 할당값 없음 → `SM_VALUE=<직전 키의 실값>` 을 stdout 출력**

즉 **직전 시크릿의 실값**이 다음 키 처리 시점에 새어나가는 구조였다. `.env` 키 24건 순회 → 23회 반복 노출.

### 2-2. 합성 재현 (실값 미사용)

```zsh
#!/bin/zsh
echo "--- TYPESET_SILENT 상태: $(setopt | grep -c typesetsilent) (0=미설정=기본) ---"
f() { for i in 1 2 3; do local SM_VALUE;    SM_VALUE="시크릿값${i}"; done }   # 재현 A
g() { for i in 1 2 3; do local SM_VALUE=""; SM_VALUE="시크릿값${i}"; done }   # 재현 B
echo "[재현 A] local VAR (할당 없음):"; f
echo "[재현 B] local VAR=\"\" (할당 있음):"; g
```

출력:
```
--- TYPESET_SILENT 상태: 0 (0=미설정=기본) ---
[재현 A] local VAR (할당 없음):
SM_VALUE=시크릿값1
SM_VALUE=시크릿값2
[재현 B] local VAR="" (할당 있음):
[끝]
```

**A는 새고 B는 안 샌다.** 원본 코드가 정확히 A 형태였다. 추측이 아니라 재현으로 확정된 원인이다.

### 2-3. 왜 `CURRENT`도 같이 샜는가

`CURRENT`는 `if` 블록 안에서 선언되어, **SM 조회가 성공한 키에 한해** 같은 조건으로 반복 선언된다. 그래서 `SM_VALUE`와 짝을 이뤄 나타났다. 쌍아가 관측한 출력 순서(`SM_VALUE` → `CURRENT` → `SM_VALUE` …)와 일치한다.

## 3. 조치 — 2층 방어

| 층 | 위치 | 내용 |
|----|------|------|
| **① 전역 차단** | `scripts/secret.sh:19` | `setopt TYPESET_SILENT` — 스크립트 전역에서 해당 출력 자체를 봉쇄. 앞으로 어느 함수에 값 미할당 `local`이 추가되어도 유출 불가 |
| **② 선언부 교정** | `cmd_env()` | `local SM_VALUE=""` / `local CURRENT=""` 를 **루프 밖으로 이동 + 초기값 할당**. 옵션 설정에 의존하지 않는 독립 방어 |

두 층은 서로를 대체하지 않는다. ①은 미래 코드까지 덮는 광역 차단, ②는 옵션이 어떤 이유로 꺼져도 유지되는 국소 차단이다. 주석으로 사유를 본문에 명기하여 후속 편집자가 되돌리지 못하게 했다.

지시서 §3-2의 "표시가 필요하면 키 이름만" 요건은 기존 `↻ $KEY` 출력이 이미 충족한다 — 변경 없이 유지.

## 4. 전 서브커맨드 실측 결과표 (§3-3, §3-4)

전 실행을 마스킹 필터 `sed -E 's/^([A-Za-z_]+)=.*/\1=<REDACTED-LEAK-DETECTED>/'` 경유로 수행. 마스킹 태그가 뜨면 유출, 안 뜨면 무유출이다.

| # | 서브커맨드 | 실행 방식 | 값 출력 | 비고 |
|---|-----------|----------|--------|------|
| 1 | `env` | 실행 | **없음** | 수정 전 23행 유출 → 수정 후 0. `갱신 0개 / 동일 24개`, `.env` 무변경 |
| 2 | `map` (무인자) | 실행 | **없음** | 이름·생성일·인벤 등재 여부만 |
| 3 | `map <NAME>` | 실행 | **없음** | 존재·버전·용도(annotation)·소비처 경로만 |
| 4 | `check <NAME>` | 실행 | **없음** | 존재 + 버전 테이블만 |
| 5 | `list` | 실행 | **없음** | 이름·생성일·복제정책 + 총 56개 |
| 6 | `get <NAME>` | 미존재 이름으로 오류 경로만 실행 | **설계상 출력** | ⚠️ §5 참조 — 유일하게 값을 출력하는 커맨드(문서 L7 명시) |
| 7 | `annotate <NAME>` | 빈 입력(EOF) | **없음** | "입력 없음 — 중단" |
| 8 | `add` (이름 누락) | EOF | **없음** | 오류 경로. 정상 경로도 `pbpaste`→stdin 파이프라 값 미출력 |
| 9 | 무인자(대화식) | EOF | **없음** | 값 수신 시 **글자 수만** 출력(`(${#SECRET_VALUE}자)`) |

잔여 위험 패턴 스캔(값 미할당 `local`) 결과 10건이 남아 있으나 **전부 루프 밖 1회 실행**이라 재선언이 발생하지 않고, ①의 전역 `setopt`가 이들까지 덮는다.

## 5. ⚠️ `secret get` — 설계상 값 출력, 판단 요망 (범위 밖으로 보아 미변경)

`cmd_get()`은 `echo "$VALUE"`로 실값을 stdout에 낸다. 이건 버그가 아니라 **문서화된 기능**이다(`secret.sh` L7 "시크릿 값 조회 (터미널 출력)", usage L59).

- `data-access.md`의 에이전트 프로토콜은 `check`·`map`만 안내하며 `get`은 등장하지 않는다 → **작가님 전용 수단**으로 보인다.
- 그러나 에이전트가 실수로 호출하면 즉시 컨텍스트 오염이 된다. 이번 사고와 노출면이 동일하다.

기능 제거는 문서화된 인터페이스를 깨는 일이라 **지시서 범위를 넘는다고 판단하여 손대지 않았다.** 선택지만 남긴다: (a) 현행 유지 (b) 실행 시 "에이전트 사용 금지" 경고 배너 추가 (c) 확인 프롬프트 게이트. **쌍아·작가님 판단 대기.**

## 6. 범위 밖 — 기술만 (§4, §5)

- **`secret env`의 신규 시크릿 미편입**: 현 구조는 `while ... done < "$ENV_FILE"` 로 **`.env`에 이미 존재하는 키만** SM 조회한다. 따라서 `RESEND_API_KEY`처럼 SM에 새로 등록된 키는 `.env`에 자동 편입되지 않는다. **지시대로 고치지 않았다** — 정본 방향이 ".env에서 시크릿을 걷어내는" 쪽이면 자동 편입은 역방향이다.
- **원칙 vs 실태 괴리**: `data-access.md`는 ".env = 비밀 아닌 설정값만"인데 실태는 SM 시크릿 24건 동기화 상태. 해소(런타임 주입 전환)는 작가님 판단 대기 별건.
- **로테이션**: 작가님 불요 판단. 미수행.
