## 2. 실측 결함 (보정 대상)

### 🔴 P1 — CMS 엣지 캐시 언어 혼선 (사용자 대면 결함, 라이브)

**사실**: 캐시 키는 `경로 + (lang·cat·page)` 파라미터뿐이다 ([worker.mjs](../../../monkos_AI/portal/edge/worker.mjs) `cmsCacheKey`). 그러나 접두사 없는 ko 기본 라우트는 **쿠키 `monkos_lang` → `Accept-Language` 순으로 언어가 갈린다** ([server.js:93-106](../../../monkos_AI/portal/server.js#L93-L106) `detectLang` → `renderHome(req,res)` 등 forceLang 미지정 경로).

즉 **캐시 키에 없는 입력이 응답 본문을 바꾼다.** `?lang=` 파라미터는 키에 있으나 `detectLang`이 읽지 않으므로 무효 방어다.

**영향 표면** (8종): `/` · `/blog` · `/blog/{slug}` · `/faq` · `/pricing` · `/guide` · `/guide/ai-photo` · `/gallery`

**재현**: JA/EN 브라우저 방문자가 `/`의 캐시를 채우면 → 이후 10분간 **전 방문자(한국인 포함)가 일본어/영어 홈**을 받는다. SWR 갱신도 그때의 방문자 언어로 이어진다. 언어 스위처로 KO를 눌러도(`setLang`은 쿠키만 세팅) 캐시가 무시하므로 **복구되지 않는다**.

**SEO 연동 위험**: 색인 모니터링 D+3/D+7 진행 중 — Googlebot이 비-ko 사본을 받으면 홈 색인 언어가 오염된다.

**현재 상태**: 실측 시점 캐시는 `<html lang="ko">` (`x-edge-cache: hit`) — 아직 발현 전이나, 조건은 이미 라이브다.

**보정 방향**: 엣지에서 언어를 확정(경로 접두사 → `monkos_lang` 쿠키 → `Accept-Language`)해 **캐시 키에 언어를 포함**한다. 또는 캐시 대상을 언어가 경로로 확정된 표면(`/ja/*`·`/en/*`)으로 한정하고 ko 기본 경로는 오리진 직결.

### 🟠 P2 — 캐시 히트 시 `monkos_sid` 미발급 (계측 결손)

**사실**: `monkos_sid`는 **GET 페이지 응답의 `Set-Cookie`로만 발급**된다 ([server.js:274-287](../../../monkos_AI/portal/server.js#L274-L287)). 캐시 히트는 오리진에 도달하지 않고, 저장 시 `Set-Cookie`를 제거하므로(세션 유출 차단 목적 — 그 자체는 정당) **히트 응답에 쿠키가 없다**. 라이브 실측에서도 `set-cookie` 헤더 부재 확인.

**영향**: 캐시된 표면(홈 포함)으로 유입된 신규 방문자는 sid를 못 받는다 → 엣지 `firePageView`가 쏘는 `page_view`가 `sessionId: null`로 적재(`/api/track`은 POST라 sid를 발급하지 않음, [server.js:1040](../../../monkos_AI/portal/server.js#L1040)). **세션 기준 지표(방문자수·퍼널·유입 정합)가 신규 유입에서 결손**된다. 홈이 주 랜딩이므로 결손 비중이 작지 않다.

**보정 방향**: 엣지가 쿠키 부재 시 sid를 자체 발급(`Set-Cookie`를 히트 응답에 부착)하고 동일 값을 `firePageView`에 실어 보낸다.

### 🟠 P2 — 엣지 신뢰 앵커가 CF **공용** 대역 (보안 설계)

**사실**: [edge-trust.js](../../../monkos_AI/portal/lib/shared/edge-trust.js) `resolveEdgeClient`는 **피어 IP ∈ Cloudflare 대역**만으로 `X-Monkos-Client-IP/Country`를 신뢰한다(공유 시크릿 불요로 설계).

**허점**: CF IP 대역은 **전 CF 고객이 공유**한다. 공격자가 자기 CF 계정의 Worker로 `monkos-portal-*.run.app`을 향해 요청을 중계하면 피어는 CF IP가 되어 **신뢰 판정을 통과**한다. 보고서가 차단했다고 본 것은 "run.app 직타"뿐이며, "타 CF 테넌트 경유"는 열려 있다.

**영향 3종**:
1. `checkRateLimit` 버킷 키가 스푸핑 가능 → **레이트리밋 우회**
2. `detectPaymentRegion` 국가 위조 → 결제 권역(Toss/Lemon) 오배정
3. `/api/track`이 **신뢰 엣지에 한해 `page_view` 주입을 허용**([server.js:1039](../../../monkos_AI/portal/server.js#L1039)) → **지표 오염 주입** 경로 개방. 레이트리밋도 같은 스푸핑 IP로 버킷되어 무력

**보정 방향**: Worker가 공유 시크릿 헤더를 부착(wrangler secret)하고, 오리진은 **CF 대역 검증 + 시크릿 일치**를 동시 요구한다. 시크릿은 헌법 4조 1항에 따라 작가님 `secret` 커맨드 경유 등록.

## 5. 추기 — 보정 착수 전 사양 보강 (2026-08-24 17:47 KST)

### 5-1. P2-1의 실제 범위는 "히트"가 아니라 **3경로 전부** (범위 정정)

§2 P2에서 캐시 히트를 지목했으나, 코드 재실측 결과 **더 넓다**:

| 경로 | Set-Cookie 결손 | 도입 |
|------|----------------|------|
| 캐시 **히트** | 저장 시 제거 + 오리진 미도달 | Phase 2 |
| 캐시 **미스** | 오리진 응답의 Set-Cookie를 **재조립 응답이 버림** (`Content-Type`·`Cache-Control`·`X-Edge-Cache` 3개만 실림) | Phase 2 |
| **specs 정적 자산** | ASSETS 서빙 — 오리진을 아예 타지 않음 | **Phase 1** |

즉 sid 결손의 **최대 지분은 Phase 2가 아니라 Phase 1(specs 2,574p)** 이다. 사이트 주력 트래픽 표면 전체가 컷오버 시점(15:06)부터 sid 미발급 상태다. **히트 경로만 고치면 결손의 소수 지분만 봉합된다.** 3경로 공통 처리로 설계할 것.

### 5-2. 캐시 키에 **버전 스탬프** 필수 (기존 오염분 격리)

언어를 "ko가 아닐 때만" 파라미터로 붙이면 **ko 요청은 키가 안 바뀌어 수정 전 엔트리에 그대로 적중**한다. 그 엔트리가 ja/en으로 채워졌다면 수정 후에도 오염이 최대 10분 생존한다.

→ 키에 `v2` 등 **스키마 버전을 무조건 포함**하고, ko도 언어를 명시적으로 실어라. 향후 키 형태 변경 시에도 같은 규율 적용(퍼지 토큰 없이 무효화하는 유일한 수단).

### 5-3. `detectLang` 미러는 **드리프트 가시화** 동반

워커의 언어 판정은 `server.js:93 detectLang`의 **두 번째 구현**이다. 한쪽만 바뀌면 캐시 키가 조용히 틀어진다 — specs SSG 스테일(§3)과 동일한 실패 계열이다.

→ 양쪽 함수에 상호 참조 주석(`// 미러: portal/edge/worker.mjs cmsLang() — 동시 수정 필수`)을 남기고, 허용 언어 목록(`ko|ja|en|es`)을 한쪽에서 베끼지 말고 **상수 이름을 일치**시켜 grep 1회로 잡히게 할 것. `es` 포함 판단은 정확하다 — `monkos_lang=es`는 `prefix='/es'`로 링크 집합이 갈리므로 별도 키가 맞다.

### 5-4. sid 쿠키 속성 **바이트 일치**

`parseCookies`는 중복 키를 **뒤엣것으로 덮어쓴다**([config.js:380-388](../../../monkos_AI/portal/lib/shared/config.js#L380-L388)). 워커가 `Domain`·`Path`를 다르게 발급하면 브라우저가 **두 개의 monkos_sid**를 보관하고 요청마다 어느 쪽이 채택될지 순서에 좌우된다 → 세션 동일성 붕괴.

→ 오리진과 **완전 동일**하게: `monkos_sid={uuid};Domain=.monkos.ai;Path=/;Max-Age=63072000;SameSite=Lax` ([server.js:281](../../../monkos_AI/portal/server.js#L281)). 이 커밋에서 속성 "개선" 금지 — 별건.
→ 발급한 sid는 **클라이언트 응답에만** 싣고 `caches.default`에 넣는 저장본에는 절대 넣지 말 것(현 구조는 저장본이 분리돼 있으니 유지). 동시에 `firePageView`가 중계하는 `Cookie` 헤더에 같은 sid를 실어 오리진 `req.sessionId`와 일치시킬 것.

### 5-5. P2-2 배포 순서 **역전 필요**

민아 제시 순서(SM 등록 → deploy.sh → **포털 재배포** → 워커 시크릿 주입)는 오리진이 시크릿을 요구하기 시작한 뒤 워커가 아직 안 보내는 **무신뢰 구간**을 만든다. 그 구간의 증상은 전 트래픽이 CF IP 단일 버킷으로 레이트리밋 → **429 폭주**, 권역 오판, page_view 전량 거부다.

→ 올바른 순서: **① 작가님 시크릿 등록 → ② 워커에 주입·배포(헤더 송출 시작) → ③ 오리진 검증 로직 배포(요구 시작)**. ②와 ③ 사이에는 무해한 중복만 존재한다.
→ 값은 **GCP SM과 CF Worker 양쪽**에 있어야 한다(워커가 SM을 읽을 수 없음) → 작가님 손이 **두 번** 필요하다: `secret` 커맨드 + `wrangler secret put`. 에이전트는 양쪽 모두 값 미접촉(헌법 4조 1항).

### 5-6. 재검증 게이트 (쌍아 수령 조건)

민아 완료 보고 시 아래 실측치를 포함할 것. 미포함분은 미완료로 본다.

1. `Accept-Language: ja` → `/` 응답이 **ja**, 직후 `Accept-Language: ko` → `/` 응답이 **ko** (동일 10분 창 내, 상호 무오염). **본 검증은 키가 분리된 뒤에만 수행할 것** — 수정 전 실행은 프로덕션 오염이다
2. `monkos_lang=en` 쿠키 단독(Accept-Language ko) → `/` 응답 **en**
3. 쿠키 없는 요청 → 히트·미스·**specs 정적** 3경로 각각에서 `set-cookie: monkos_sid=…` 존재 + 속성 문자열 오리진과 동일
4. 발급 sid가 `/api/track` 적재분의 `sessionId`와 일치 (Cloud Run 로그 또는 적재 조회)
5. 수정 배포 직후 ko 요청이 **수정 전 엔트리에 적중하지 않음** (`x-edge-cache: miss` 최초 관측으로 확인)

### 6-1. 🔴 잔여 — specs 정적 경로 sid 미발급 (§5-1 최대 지분 미이행)

보정은 `serveCms`(히트·미스)에만 적용됐고, **`env.ASSETS` 정적 서빙 분기는 손대지 않았다**. 라이브 실측:

| URL | Set-Cookie |
|-----|-----------|
| `/specs/passport/kr` | **0건** |

§5-1에서 "결손의 최대 지분은 Phase 2가 아니라 Phase 1(specs 2,574p)"임을 명시했고 게이트 ③에 `specs 정적`을 레그로 박아뒀다. 민아 완료 보고는 히트·미스 2경로만 다루며 이 레그를 언급하지 않았다 — **누락이다.**

사이트 주력 오가닉 표면 전체가 컷오버(15:06) 이후 sid 미발급 상태로, 세션 기준 지표 결손이 계속된다. `serveCms`가 쓰는 발급 로직을 정적 분기에도 동일 적용하면 되는 소규모 작업이다(`firePageView`에 sid 전달 포함).

### 6-2. 🟡 드리프트 가시화 절반 이행 (§5-3)

`effectiveLang`에 미러 사유·오염 시나리오 주석은 충실하다. 그러나 **`server.js` 쪽 `detectLang`에는 상호 참조 주석이 없다**(커밋이 worker.mjs 단독). 정본을 고치는 사람이 미러의 존재를 알 수 없다 — 요구는 **양방향**이었다. server.js 한 줄로 종결.

### 6-3. 코드 대조 — 미러 정합성 ✅

`effectiveLang` ↔ `detectLang` 전 분기 일치 확인: 경로 접두사 정규식(pathname엔 `?`가 없어 원본의 `|\?`는 무의미 — 등가), 쿠키 허용값 `ko|ja|en|es`, Accept-Language `ja`/`en` 순서. 값이 허용목록 밖일 때(`monkos_lang=korean` 등) 양쪽 모두 Accept-Language로 폴백하는 것까지 동일하다.

**해소된 우려**: 워커 정규식은 중복 쿠키에서 **앞엣것**, 오리진 `parseCookies`는 **뒤엣것**을 취하므로 불일치 가능성을 봤으나 — 클라이언트 `setCookie`도 `domain=.monkos.ai;path=/`로 오리진과 **동일 스코프**라(i18n.js:106-108) 중복 자체가 생기지 않는다. **비성립 — 조치 불요.**

### 6-4. 🟡 관찰 — `getSetCookie` 무음 폴백

`typeof originRes.headers.getSetCookie === 'function'` 미충족 시 `setCookies = []`로 **조용히 보정 이전 동작(쿠키 전량 폐기)** 으로 되돌아간다. 현 런타임에선 정상 동작 실측(미스 프로브에서 `monkos_sid` 전달 확인, 속성 문자열이 오리진과 바이트 일치). 도구 3요건 '실패 가시화' 관점에선 폴백 시 경고 로그가 낫다. 경미 — 후속.

### 6-5. ⏳ P2-2 착수 전 재고지 (§5-5 미반영)

민아 잔여 계획이 **"서버 검증 로직 + deploy.sh + 워커 주입" 순**으로 다시 기재됐다. §5-5에서 지적한 **무신뢰 구간**이 그대로 생긴다 — 오리진이 시크릿을 요구하는데 워커가 아직 안 보내는 사이, 전 트래픽이 CF IP 단일 버킷으로 몰려 **429 폭주** + 권역 오판 + page_view 전량 거부.

**필수 순서: ① 시크릿 등록 → ② 워커 주입·배포 → ③ 오리진 검증 배포.** ②③ 사이엔 무해한 중복만 남는다.

또한 값은 **GCP SM과 CF Worker 양쪽**에 필요하다(워커가 SM을 못 읽음). 민아 요청문은 `secret`(SM)만 안내했다 — 작가님 손이 **두 번**임을 함께 고지해야 한다: `secret add EDGE_TRUST_KEY` + `wrangler secret put EDGE_TRUST_KEY`. 에이전트는 양쪽 모두 값 미접촉(헌법 4조 1항).

### 7-2. P2-2 신뢰 앵커 ✅ — 배포 순서까지 실증

**구현**: `resolveEdgeClient`가 `claimedIp && isCloudflareIP(peer) && edgeKeyMatches(...)` **AND 3항**으로 전환. 대조는 `timingSafeEqual` 상수시간 + 길이 불일치 선차단. 키 미설정 시 비신뢰(fail-secure). 워커는 `originRequest`·`firePageView` **양쪽**에 `X-Monkos-Edge-Key` 부착 — `/api/track`의 page_view 게이트가 firePageView 경유이므로 후자 누락 시 계측이 죽는데, 정확히 처리됐다.

**음성 테스트** (헤더 위조 차단): `run.app` 직타 + `X-Forwarded-Host: evil.example` + `X-Monkos-Client-IP` + 오답 `X-Monkos-Edge-Key` → `redirect_uri=https%3A%2F%2Fmonkos-portal-…run.app%2F…`. **XFH 무시 = 비신뢰 확정.**
