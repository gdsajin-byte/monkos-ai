## 4. 자동화 표식 체인 E2E 검증 (쌍아 08-02 이월 미검증 해소)

인앱 브라우저로 monkos.ai 실방문하여 실측:

| 단계 | 실측 | 결과 |
|------|------|------|
| ① 감지 | webdriver=false(CDP)였으나 **UA층이 Electron 매칭** → `_mkAuto=true` | ✅ 3층 중 ②층 작동 |
| ② 태깅 | dataLayer에 양 스트림 config `traffic_type:'internal'` + `automation_hit` 이벤트 | ✅ |
| ③ 발송 | `analytics.google.com/g/collect` 비콘 3발 실발송 | ✅ |
| ④ 차단 | 판별 프로브 2발: `mk_probe_clean`(traffic_type 오버라이드)만 리얼타임 수집, `mk_probe_tagged`(internal)는 **인제스천 차단** | ✅ **필터 활성 실측 판정** |

- **`automation_hit` 0건의 재해석**: 표식 미작동이 아니라 **차단 성공**이다. internal 태깅 이벤트는 GA4 리포트에 원천 미수집 → **"언노운 계량"은 GA4 리포트로 불가, BQ 요청 로그가 정본** (쌍아 08-02 설계 그대로)
- 잔여 구멍: 작가님 수동 브라우징(실크롬·비자동화)은 UA·webdriver 층에 안 걸림 — **IP 규칙 등재 여부는 콘솔에서만 확인 가능(미실측)**. 필요 시 실크롬에 `localStorage.mk_internal='1'` 1회 심기로 대체 가능(③층)
- 프로브 흔적 고지: `mk_probe_clean` 1건(traffic_type=mina_probe, 08-06 새벽)이 데이터에 남음 — 자기기술적 명명으로 식별 가능. 민아 방문 자체는 internal 차단으로 숫자에 안 남음
