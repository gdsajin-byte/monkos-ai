## Phase D: 리스크 평가 + 백업 계획

### D-1. 클론 리스크

| 리스크 | 영향도 | 대응 |
|--------|--------|------|
| KR 코드 변경이 JP에 반영 안 됨 | **높음** — 현재도 기능 갭 발생 중 | 공유 모듈 추출 or 병합 후 분기 |
| 환경변수 혼선 (KR/JP 키 교차) | **높음** — 결제 키 교차 시 금전 사고 | deploy.sh에 환경변수 체크 추가 |
| OAuth 리다이렉트 설정 누락 | **중간** — 로그인 불가 | 배포 전 체크리스트에 포함 |
| 일본어 프롬프트 품질 저하 | **낮음** — 이미 일본어 구현 완료 | 프롬프트는 영어 유지 (I2I) |
| 레몬스퀴지 웹훅 실패 시 크레딧 미적립 | **중간** — 결제 완료 but 크레딧 0 | 웹훅 재시도 + 수동 보정 절차 |
| JPY 환율 변동 | **낮음** — 레몬스퀴지가 실시간 환산 | 가격 주기적 검토 (분기 1회) |
| 일본 APPI 대응 | **중간** — 얼굴 사진 = 생체정보 | 별도 APPI 대응 절 필요 (아래 상세) |

#### APPI (일본 개인정보보호법) 리스크

- 얼굴 인식 패턴 = **Individual Identification Codes** (생체데이터)
- 추가 의무: 보안 관리, 제3자 이전 제한, 침해 보고
- 2026년 개정안: AI 개발용 데이터 활용 완화 방향이나 아직 법제화 전
- **대응**: 프라이버시 정책 일본어판 준비 + 생체데이터 처리 명시 + 옵트아웃 절차

### D-3. 병합 전략 제안

| 전략 | 장점 | 단점 | 권장도 |
|------|------|------|--------|
| **A. 단일 코드 + 환경변수 분기** | 유지보수 1곳, 기능 동기화 자동 | 복잡도 증가, 분기 로직 비용 | 장기 추천 |
| **B. 별도 코드 유지 (현행)** | 독립 배포, 국가별 최적화 | 기능 갭 누적, 이중 관리 | 단기 현실적 |
| **C. 공유 모듈 추출 + 국가별 오버라이드** | 핵심 공유 + 현지화 분리 | 모듈 경계 설계 비용 | 중기 최적 |

**권장: C → A 순차 전환**

1. **즉시**: KR의 프론트엔드 파일을 JP로 포팅 (config.js, shared.js, modules/)
2. **중기**: 공유 모듈 추출 (`/shared/` 디렉토리) + 국가별 오버라이드
3. **장기**: 단일 코드베이스 + `COUNTRY=kr|jp` 환경변수 분기

**배포 파이프라인:**
- 현행: `idphoto-kr/deploy.sh`, `idphoto-jp/deploy.sh` (별도)
- 권장: 유지. Cloud Run 서비스 분리 유지가 롤백·모니터링에 유리
