### 미들웨어 체인 순서 (server.js L52~333)
server.js는 Express 미들웨어가 아닌 **if-return 체인** 방식:

```
1. 보안 헤더 (HSTS, X-Content-Type-Options, X-Frame-Options)
2. CORS (ALLOWED_ORIGINS 화이트리스트 기반)
3. OPTIONS preflight → 204
4. urlPath 파싱 (쿼리스트링 제거)
5. /health → JSON 헬스체크
6. /api/stats → Firestore users count
7. Deprecated 엔드포인트 → 404
8. Auth 라우트 (카카오/LINE/Google)
9. 에이전트 인증
10. 크레딧 API
11. 결제 API (토스/LemonSqueezy)
12. 이벤트 API
13. Mini App API (텔레그램)
14. 봇 웹훅 (CS/Event/Team)
15. 챗봇 (카카오/LINE/웹/코칭)
16. CMS 관리자 API (blog/faq/gallery/board/upload/settings/layout)
17. /crop → 정적 HTML 서빙
18. HEAD → GET 변환 (Googlebot 대응)
19. 블로그 리다이렉트 (301, 구슬러그→신슬러그)
20. /app → idphoto 서비스 302 (Accept-Language 기반)
21. SSR 공개 페이지 (/, /blog, /faq, /pricing, /specs, /gallery, /board, /guide)
22. /favicon.ico → PNG
23. 정적 파일 서빙 (public/ 디렉토리)
24. 404 → "Not Found"
```

### 정적 파일 서빙 (L307~333)
- `public/` 디렉토리에서 `readFileSync`로 동기 읽기
- 확장자 없는 요청 → `.html` 자동 추가 시도
- `MIME_TYPES` 맵 기반 Content-Type 설정
- 캐시: CSS/JS → `no-cache`, 기타 → `max-age=3600`

### 렌더링 방식: **100% SSR (Server-Side Rendering)**
- render.js가 Firestore에서 데이터 조회 → HTML 문자열 생성 → res.end()
- 클라이언트에게 완성된 HTML 전달 — CSR 없음
- 홈(/)만 예외: `public/index.html` 템플릿을 서버에서 regex 교체 방식으로 수정 후 서빙 (SSR 하이브리드)

### Fragment + Shell 구조 (render.js)
- **Fragment 함수**: 데이터 조회 + `{ title, description, seoMeta, htmlLang, pageStyle, bodyContent, pageScript }` 반환
- **layoutShell()**: Fragment 결과를 전체 HTML 페이지로 래핑
- 일부 페이지(FAQ, Gallery, Pricing, Board목록)는 container max-width가 달라 커스텀 셸 사용

### 블로그 자동 파이프라인
1. 한국어 원본 `published` → 자동번역 (`translate.js`) → ja/en 문서 생성
2. 번역 완료 → GitHub Issues 게시 (`github-issues.js`)
3. Google Sitemap ping 자동 전송

### Markdown 처리
- `marked` 라이브러리로 Markdown → HTML 변환
- 블로그 본문: heading 다운그레이드 렌더러 적용 (H1 → H2, H2 → H3 등, 페이지 H1 중복 방지)

⚠️ 단, `public/pricing.html`이 여전히 존재 — dead file로 정리 가능.

### 2. `/guide` 404 → **해결됨**

server.js L276에 SSR 렌더러 등록 완료:
```js
if (urlPath === '/guide' && req.method === 'GET') return renderGuide(req, res);
```
→ render.js `guideFragment()`에서 정적 콘텐츠 SSR 렌더. 정상 동작.

⚠️ 다국어 `/ja/guide`, `/en/guide` 라우트는 **미등록** — 직접 접근 시 404. hreflang 태그에는 선언되어 있어 GSC에서 404 발생 가능.

### 3. `/blog` 데이터 끊김

**원인 분석:**
- 홈의 블로그 카드: `renderHome()`에서 Firestore `blog_posts` 조회 → `published: true` + 언어 필터 + `thumbnail` 존재 필터 (L89)
- `/blog` 페이지: `renderBlogList()` → `blogListFragment()` → Firestore `blog_posts` where `published: true`

**끊김 원인:**
- 홈은 `thumbnail && thumbnail.length > 0` 필터 적용 — 썸네일 없는 글 제외
- `/blog`는 썸네일 필터 없음 — 전체 published 글 표시
- 따라서 "홈에 블로그 4건만 보이는데 /blog에서도 적게 보인다"면 **Firestore에 published: true인 글 자체가 적기 때문**

⚠️ 코웍이 보고의 "홈에 정적 목업 4건" 표현은 **오해** — 홈의 블로그 카드는 Firestore에서 동적 조회하되, `pinned` 글 우선 + 최대 4건(layout 블록 설정) 표시. 정적 목업이 아님.

**실제 확인 필요:** Firestore `blog_posts` 컬렉션의 `published: true` 문서 수. 글이 적거나 전부 `published: false` (draft)인 경우 빈 목록 표시됨.
