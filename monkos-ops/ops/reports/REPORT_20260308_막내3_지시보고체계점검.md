## 4. 종합 개선 제안

### 우선순위 1: status 필드 정상화 (즉시)

**현황**: ORDER의 26.5%, REPORT의 3.4%만 status 보유. 지시서 생애주기 추적 불가.

**제안**:
1. status 필드를 YAML frontmatter 필수 항목으로 재확인 (ch4 7조에 이미 정의됨)
2. 허용값 통일: `발행` → `진행중` → `완료` / `취소` (한/영 혼용 정리)
3. 기존 195건 ORDER의 status 일괄 보정은 비용 대비 효과 낮음 → **신규 지시서부터 의무화**
4. 쌍아 지시서 템플릿에 status 기본값 `발행` 자동 삽입

### 우선순위 2: 표기 일관성 통일 (즉시)

**현황**: type 대소문자, to 표기, priority 표기가 각각 2~30종 변종.

**제안**:
1. `type:` → **소문자 통일** (ch4 7조 기준: `order`, `report`, `completion`)
2. `to:` → **`막내N`** 통일 (디바이스 접두사는 from에만 사용)
3. `priority:` → **`P0`/`P1`/`P2`/`P3`** 4단계 통일
4. 신규 지시서부터 적용. 기존 파일 일괄 수정은 별도 판단

### 우선순위 3: 역할 선언 + 엔드라인 테이블 (단기)

**현황**: 역할 선언 10.3%, 정식 엔드라인 테이블 1.5%. ch1 3조 요구사항 대비 심각 미달.

**제안**:
1. 역할 선언("너는 막내N호다")은 지시서 본문 상단에 필수 삽입
2. 엔드라인 테이블(마무리/산출물/문서유형/세션로그)은 지시서 말미에 필수 삽입
3. 쌍아 지시서 템플릿에 양쪽 모두 포함
4. 금일(03-08) 발행 3건은 이미 준수 — 템플릿 정착 시작점

### 우선순위 4: 월별 폴더 재편 (중기 — 3월 마감 전 권고)

**현황**: 연간 orders 5,000건, reports 3,170건 투사. 플랫 구조 지속 불가.

**제안**:
1. **방안 A (월별 `YYYY-MM/` 서브폴더)** 채택 권고
2. `docs/monkos/tasks/`, `docs/monkos/reports/` 기존 패턴과 통일
3. 선행 작업: ch4 법률 개정 (1조, 3조, 4조) + ch7 경로 갱신
4. 이관 스크립트 + 126건+ 참조 경로 일괄 치환을 원자적으로 실행
5. 3월분부터 적용하고, 2월분은 일괄 이관
