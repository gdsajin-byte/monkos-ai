## 3. 오류 패턴 카탈로그

### 오류 패턴 #1: 번역 토큰 한도에 의한 본문 잘림 ★ CRITICAL

- **구간**: B
- **파일:행**: `translate.js:115`
- **현상**: `maxOutputTokens: 8192`로 긴 본문의 Gemini 번역 응답이 잘림. `responseMimeType: 'application/json'` 설정으로 Gemini가 유효한 JSON을 생성하되 content 값을 **중간에 자르고 JSON을 닫음** → `JSON.parse` 성공 → 잘린 content가 정상 저장됨
- **원인**: 8192 토큰 ≈ 6,000~8,000자. 원본 본문 4,000자 이상 + JSON 구조(title, summary, tags) 오버헤드를 합하면 content가 잘림
- **재현 조건**: 원본 content 약 4,000자 이상 (마크다운 포함)
- **영향 범위**: **JA 24건, EN 28건** (원본 KO는 Gemini를 거치지 않으므로 무관)
- **방어 코드**: 없음. 번역 content 길이 대 원본 비율 검증 없음
- **수정안**:
  1. `maxOutputTokens` → `32768` (Gemini 2.0 Flash 허용 최대)
  2. 번역 content 길이가 원본의 40% 미만이면 저장 거부 + 에러 로그
  3. 거부 시 `translationStatus` 필드에 `'truncated'` 기록

### 오류 패턴 #5: parseRawBody 크기 제한 없음

- **구간**: A
- **파일:행**: `config.js:290~297`
- **현상**: request body에 크기 제한 없음. 이론적으로 무한 데이터 수신 가능
- **원인**: Node.js 기본 스트림, maxSize 미설정
- **재현 조건**: 거대 POST body 전송
- **영향 범위**: admin API 뒤(인증 필수)라 실질 리스크 **낮음**
- **방어 코드**: 없음
- **수정안**:
  ```js
  export function parseRawBody(req, maxSize = 10 * 1024 * 1024) {
    return new Promise((resolve, reject) => {
      let body = '';
      let size = 0;
      req.on('data', chunk => {
        size += chunk.length;
        if (size > maxSize) { req.destroy(); reject(new Error('Body too large')); return; }
        body += chunk;
      });
      req.on('end', () => resolve(body));
      req.on('error', reject);
    });
  }
  ```

## 4. CITADEL 적용도 — SEO에 미친 영향 분석

### 4-1. Thin Content 리스크 (패턴 #1 + #3)

- sitemap에 잘린 번역글 ~52건(JA 24건 + EN 28건) 포함
- 구글이 이 URL들을 크롤 → **content 100자 미만 페이지 색인** → thin content 시그널
- GSC 404 33건 중 일부는 이 잘린 글의 구 slug 잔재일 가능성

### 4-2. hreflang 미스매치 (패턴 #1)

- 원본 KO가 정상이고 JA/EN이 잘려 있으면:
  - hreflang은 정상 연결 (render-blog.js가 published+exists 체크)
  - 그러나 구글이 JA/EN 페이지를 크롤하면 **KO 페이지 대비 대폭 짧은 콘텐츠** → 언어 대체 페이지 품질 불일치 시그널

### 4-3. 수동 삭제 ~20건 후 상태 (오늘)

- 작가님이 잘린 글 ~20건 수동 삭제 중
- sitemap에서 자동 제거됨 (published=false 또는 doc 삭제)
- 구글이 다음 크롤 시 "페이지 삭제" 감지 → **일시적 색인 수 감소** (정상 반응)
- 301 매핑 35건 추가 → 구 URL→신 URL 리다이렉트 → **SEO 링크 주스 전달** (긍정적)

### 4-4. Summary 빈값 (패턴 #2)

- Create 경로에서 summary 미입력 시 빈값 저장
- `<meta name="description">` 빈값 → 구글이 자체 snippet 생성 → 검색 결과에서 **의도하지 않은 문장 노출**
- CITADEL Phase 1 "블로그 타이틀 최적화" 미착수와 맞물려 블로그 검색 노출 품질 저하

```

  KO는 번역을 거치지 않으므로 패턴 #1과 다른 원인.

  (a) 에디터에서 저장 시 markdown 수집 시점 이슈 (WYSIWYG↔markdown 모드 전환 중)

  (c) 과거 다른 경로로 저장 (구 에디터, 직접 API 호출 등) — 레거시 가능성
```

| content 최소 길이 | 검증 없음 | 서버 측 200자 미만 거부 or 경고 |

| update 빈 content 보호 | 클라이언트만 | 서버 측에도 빈값 체크 |

### 6-2. 번역 품질 게이트 (패턴 #1, #6, #8)

| 항목 | 현재 | 제안 |

### 6-3. sitemap 품질 필터 (패턴 #3, #4)
