# REPORT — $6.74 온디멘드 트리거 메커니즘 분석

## 결론 (3줄)

**트리거 = 5시간 단위 "Session 한도" 도달**. 주간 한도(현 57%)와는 독립적으로, 특정 5h 창에서 Max 20x Session 한도를 터치한 순간 Extra Usage가 발동하여 API rate로 과금됨. Claude 앱·Claude Code는 동일 쿼터 공유라 양쪽 합산 사용이 한 창에서 터지면 동일 조건 발동.
**확신도: 높음** — 근거: Anthropic 공식 support 문서 "Your session limits reset every five hours as usual" 명문 + 주간 38%에도 rate limit 보고된 GitHub Issue #28450 직접 증거.
**$6.74의 ≈2회 분할 = 서로 다른 두 5h 창에서 Session 한도 터치 2회** (정확한 일시·charge-level 상세는 5/1 청구 전까지 claude.ai UI에 미노출).

### 중요한 비대칭
- **주간 한도**: 현재 57% — 한도 내 여유 있음
- **Extra Usage**: $6.74 — 이미 발생 (돌이킬 수 없음)
- **결합 해석**: Extra는 "과거 어느 5h 창에서 세션 한도를 친 결과". 지금 주간 57%여도, 그 창들이 주간 총량 57%에 이미 포함돼 있는 상태 — **주간은 세션을 덮어쓰지 않고 병렬 집계**.

## 5. 조치 제안 (누수 방지)

### 즉시 조치
1. **세션 경고 라인 도입**: `/settings/usage`에서 "현재 세션" 퍼센트를 80% 전후로 올라갈 때 자동 `/compact` 또는 세션 분할. 인간 눈으로 계속 보기 어려우니 `cdp.sh`로 5분 polling 스크립트 가능 (선택 과제)
2. **Extra Usage opt-out 검토**: 한도 도달 시 자동 차단(=작업 멈춤) vs 계속 진행(=추가 과금) 선택. 현재 활성화 상태 → 차단 경험 싫으면 유지, 예산 우선이면 꺼두기. 단 끄면 경고 없이 막히는 불편
3. **병렬 N인 운영 억제**: 합산 토큰이 한 5h 창에 몰리면 세션 한도 빨리 터치. 민아·막내·쌍아 병렬 4~5인 가동 시점을 **다른 5h 창**에 분산

### 중기 조치
4. **GitHub #38335 / #41788 추적**: 3/23 이후 세션 소진 가속 현상은 Anthropic 측 조정 여지 있음. 해소되면 Extra 발동 빈도 자연 감소
5. **Max 20x 한도 공식 수치 확인**: 공식 문서에 Max 20x 5h 세션 한도의 정확한 토큰/메시지 수치 **미공개**. 지원팀 문의로 받아두면 예산 계획에 유리

### 유지/기각
6. **1M context 가드** (`CLAUDE_CODE_DISABLE_1M_CONTEXT=1`): 본 건 주된 원인 아님 — 유지하되 긴급도 낮음
7. **PF_BRIEF trigger**: 세션 한도 기여 미미 (v2에서 검증) — 판단 별도
