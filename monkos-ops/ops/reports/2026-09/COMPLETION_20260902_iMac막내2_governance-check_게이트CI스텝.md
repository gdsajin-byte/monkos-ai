- **원인**: `git diff --name-only`는 기본값 `core.quotePath=true`에서 비ASCII 경로를 이스케이프해 내보낸다.
  ```
  "monkos-ops/ops/sessions/2026-09/2026-09-02_iMac_\354\214\215\354\225\204.md"
  ```
  이 문자열은 `[ -f ]`를 통과하지 못해 `continue`로 빠진다. **세션 로그는 파일명에 전부 한글 에이전트명(쌍아·민아·막내N)이 들어가므로 C12는 단 한 건도 검사하지 못하면서 "✅ 없음"을 보고**하고 있었다.
- **로컬에서 안 드러난 이유**: 이 iMac의 git에는 `core.quotePath=false`가 설정돼 있다(`git config --get core.quotePath` → `false`). 로컬 재현은 통과했고 러너만 실패했다.
- **수정**: `git -c core.quotePath=false diff ...` 명시. 사유를 주석 3행으로 코드에 고정했다.
- **검증**: `quotePath=true` 강제 시 검출 0건 → `quotePath=false` 시 `2026-09-02_iMac_쌍아.md` 검출, 수정본 전체 실행 `✅ [예외] 기록 1건 — 대응 COMPLETION 전건 존재` (exit 0).

## 💡 발견 — 러너 셸에서 스텝을 죽이는 패턴

작성 중 `[ -z "$X" ] && echo ...` / `[ -z "$X" ] && continue` 2곳을 `if` 문으로 교체했다. GH 러너 기본 셸은 `bash -e {0}`이며, 이 형태는 **테스트가 거짓일 때 마지막 명령이 비0을 반환해 스텝 전체가 죽는다.** 비블로킹 스텝이 조용히 블로킹으로 바뀌는 경로였다. 로컬 `bash`(=`-e` 없음) 실행으로는 드러나지 않아, **YAML에서 run 블록을 추출해 `bash -e`로 재실행**하여 검출했다. 향후 CI 스텝 작성 시 동일 검증을 권한다.
