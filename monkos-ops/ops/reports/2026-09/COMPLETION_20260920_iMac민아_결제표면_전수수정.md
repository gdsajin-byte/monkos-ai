## 4. 검증

### 헤드샷 (dev 00189-7n2, CDP 가시 크롬 360×700, 테스트 키)
실경로: 사진 업로드 → 스타일 선택 → 생성 클릭 → 결제 단계. 위젯 렌더 725ms·iframe 폭 312px·가로 넘침 없음 / 렌더 중·렌더 후 재클릭 init 1→1·iframe 1개 / 카드사 미선택 → "카드 결제 정보를 선택해주세요." 뷰포트 내(355~395)·결제하기 바로 위 + `pay_fail:request/NEED_CARD_PAYMENT_DETAIL` + 서버 보고 / 위로 스크롤 → 버튼 하단 고정(652~688/700) / `?toss=fail` → 위젯 자동 재오픈(413ms)·사유 표시·`pay_fail:return`. **재오픈 후 `monkos_hs_img`(138,479자)·`monkos_hs_style` 재저장 확인 = 사진 유실 수정 실증.**

## 5. ⚠️ 한계·부작용

1. **로그인이 필요한 결제 구간 3곳은 브라우저 검증 0** — 포털 크레딧 충전의 토스 위젯·레몬 선오픈, idphoto-kr·studio의 결제 뷰. 코드 검수·구문 검사·모의 하니스까지다. 작가님 로그인 기기에서 충전 페이지를 한 번 열어 결제 버튼이 뜨는지 확인 필요.
2. **dev 서비스 2개가 신규 생성됐다** — `monkos-idphoto-jp-dev`·`monkos-idphoto-kr-dev`(둘 다 rev 00001, 09-20 23:35 KST 생성). `references.md`는 "(+-dev)"로 기재하나 실제로는 부재였고 `deploy.sh dev`가 만들었다. 삭제는 파괴적 행위라 하지 않았다 — 존치/삭제는 작가님 판단. studio는 dev 서비스 신설을 피하려고 dev를 건너뛰고(KR과 동일 코드) prod 직행.
3. **idphoto-jp 이중 소스 경고** — `apps/idphoto-jp-v079`도 같은 서비스로 배포된다. 그쪽을 배포하면 이번 수정이 덮인다(배포 스크립트 경고 출력 확인).
4. 결제 승인 완료 이후 구간은 전 표면 미검증(계정·카드 입력은 에이전트 금지 행위).
5. 고정 버튼은 `position:fixed` + 스크롤 컨테이너 조합 — iOS 구버전에서 떨림 가능(구현 에이전트 지적, 실기기 미확인).
6. JP 복귀 안내는 최대 약 60초 뒤 `alert`로 뜰 수 있다(기존 alert 관례 유지).
7. 범위 밖 발견(미수정): JP `result.js`의 결제 복귀 폴링 분기가 `sharedInit()`의 쿼리 제거 때문에 실행되지 않음 / `navigateTo`가 URL 끝에 `?dev`를 덧붙이는 기존 버그 / studio 단가 1,450원의 포털 confirm 검증 통과 여부 미확인 / 포털 `handleCheckout`의 `redirectUrl` 무검증.
