# specs 상세페이지 레퍼런스 해부 보고

## 0. 조사 방법과 한계

**방법**
- 구조는 모바일 UA로 원문 HTML을 받아 파싱했습니다. 파싱 항목은 헤딩 아웃라인, img(alt·크기·loading), figure/figcaption, JSON-LD, robots 메타입니다.
- 시각 요소는 제 전용 탭을 열어 390×844 뷰포트로 캡처해 직접 봤습니다. 작업 후 탭은 닫았고 기존 탭은 건드리지 않았습니다.
- 작업 도중 기존 탭 목록에서 monk.kr 탭 1개가 사라졌는데, 제가 닫은 것은 아닙니다.

**차단·대체**
- `travel.state.gov`는 Cloudflare 봇 챌린지에 걸렸습니다(우회 시도 안 함). 대신 Wayback 2026-05-29 스냅샷으로 해부했습니다. 구 URL은 새 경로 `https://travel.state.gov/en/passports/apply/help/photos.html`로 이전된 상태입니다.
- Canva sizes는 403으로 해부하지 못했습니다.
- 일본 외무성 NG 예시 PDF(`https://www.mofa.go.jp/mofaj/files/100171389.pdf`)는 403이어서 내용을 확인하지 못했습니다. HTML 페이지는 확인했습니다.
- ICAO 문서는 이번 세션에서 열지 않아 인용하지 않습니다.
- IDPhoto4You·Persofoto는 홈페이지만 파싱했습니다(스크린샷은 찍지 않아 실물 확인은 없습니다). 국가별 페이지가 있는지는 따로 확인하지 않았습니다.

**부산물**
- 캡처는 `.playwright-mcp/ref_*.jpg`에 남아 있습니다(gitignore 대상). 임시 스크립트와 타일 이미지는 세션 스크래치패드에 있습니다.
- 프로젝트 파일 수정은 없습니다.
- 저작권 규칙상 직접 인용은 1건만 썼고, 캡션·CTA 문구는 뜻을 옮겨 적었습니다.

### 2. 공통 골격(권장 섹션 순서)

1. **H1과 한 줄 답**: 크기·배경·매수. papersizes식입니다.
2. **툴 히어로**: 업로드 박스와 **치수선 입힌 샘플 1장**입니다.
   - 샘플은 첫 `<img>`로 두고 lazy를 끕니다.
   - width·height를 명시하고 1200px 이상으로 만듭니다.
   - alt는 서술형으로 씁니다.
3. **한눈에 보기 박스**
   - 표 또는 아이콘 카드
   - 단위 표
   - 출처와 **확인일**
4. **신뢰 띠**: 검수자, 최종 확인일, 공식 문서 링크, 보증 조건
5. **주제별 규정 블록을 반복**합니다.
   - 블록 하나는 HTML 규칙 불릿, **합/불 짝 또는 캐러셀**, 이유 한 줄로 구성합니다.
   - 주제는 크기·머리 위치 → 배경 → 조명·그림자 → 표정·자세 → 눈·안경·렌즈 → 머리카락·귀 → 복장·가리개 → 보정·AI → 영유아 순입니다.
6. **"흔한 오해 교정" 블록**: 귀 노출, 컬러렌즈 같은 항목을 다룹니다. 정부 페이지에도 상업 페이지에도 없는 저희만의 자리입니다.
7. **주요 반려 사유 상위 N개**: 가능하면 작은 그림을 붙입니다.
8. **툴 작동 3~4단계와 전후 비교, 인쇄 배치(4×6) 그림**
   - 인쇄 시트 실물 그림은 이번에 본 어느 페이지에도 없었습니다. 빈자리입니다.
9. **기관 카드**: 제출처, 수수료, 처리 기간, 온라인 가능 여부
10. **FAQ**: FAQPage 스키마를 답니다.
11. **형제·인접 링크**: 같은 나라의 다른 문서, 같은 규격의 다른 나라
12. **맥락별 CTA**: 같은 버튼을 10번 넣지 않습니다. 5번 블록 뒤에는 "내 사진 이 항목 검사", 8번 뒤에는 "인쇄용 받기"를 둡니다.

**정부가 나은 점**
- 예시의 양과 실제 일반인 얼굴
- 허용 예 포함(종교 가리개, 휠체어, 보청기)
- 규정과 예시를 같은 자리에 붙이는 구성
- 수정일, 과장이 없음
- AI·보정에 대한 명시적 입장

**상업이 나은 점**
- 첫 화면의 답과 툴
- 치수 오버레이
- 구조화 데이터와 `max-image-preview`
- 검수자·보증
- 형제 링크
- 국가별 얼굴 변형

**둘 다 못하는 것(저희 기회)**
- 예시 캡션의 다국어 HTML화
- 오해 교정
- 인쇄 시트 그림
- ± 오차 표기
- 국가마다 예시를 다르게 넣기: 롱테일 상업 페이지는 예시가 0장이었습니다.

### 5. 검색 썸네일 관점 기술 요약(관찰된 사실만)

- `max-image-preview:large`를 선언한 곳은 PPO와 PhotoAiD뿐입니다. 그 외 상업·정부 페이지에는 없습니다.
- 상단에 눈에 띄는 비-lazy `<img>`를 둔 곳은 PPO(506×506, 1200×1201), PhotoAiD 허브(1183×922), Snap2Pass(애프터 컷)입니다. Visafoto는 작은 JPG 2장입니다.
- figure와 figcaption을 실제로 쓴 곳은 캐나다뿐입니다. PhotoAiD 블로그는 figure만 18개 씁니다.
- 스키마
  - HowTo + Article + ImageObject: PPO, PhotoAiD
  - Product + Review + FAQPage: Snap2Pass
  - FAQPage: Wise, Omni, GOV.UK
  - Dataset: papersizes
- 페이지별 og:image
  - Snap2Pass, Omni: 동적 1200×630
  - PhotoAiD: 예시 8장을 다중 선언
  - PPO: 사이트 공용 1장
- 저희 페이지 설계 메모
  - 페이지마다 **고유한 대표 이미지**(국가별 치수 샘플 + 합/불 요약 그리드)를 상단에 실제 `<img>`로 둡니다.
  - 그 이미지는 1200px 이상으로 만들고 width·height를 명시하며 lazy를 끕니다.
  - alt는 서술형으로 쓰고 figcaption은 HTML로 둡니다.
  - ImageObject에 넣고 `max-image-preview:large`를 선언합니다.
  - 이미지는 번호·배지만 든 언어 중립 1벌로 만들고, 캡션은 6개 언어 HTML로 갑니다.
