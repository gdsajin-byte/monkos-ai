### 3-2. 즉시 처리 절차 (승인 후)

**전제**: 각 교차오염 doc에 대해 Firestore에서 영문 slug 대응 doc 존재 여부 확인 필요.

**Case 1 — 영문 slug 번역본이 이미 존재하는 경우** (재번역으로 영문 slug doc 별도 생성된 경우):
1. server.js `blogRedirects`에 한글 slug → 영문 slug 301 추가
2. Firestore에서 한글 slug 번역본 doc (`{한글}-ja/en`) unpublish 또는 삭제
3. sitemap에서 자동 제거됨 (published=false면 sitemap 미포함)

**Case 2 — 영문 slug 번역본이 없는 경우**:
1. 해당 글에 대해 수동 번역 트리거 (`POST /api/admin/blog/{slug}/translate`)
2. translate.js가 Gemini로 영문 slug 생성 → 새 doc 생성
3. 생성 확인 후 Case 1 절차 실행

**Case 3 — 원본 자체가 번역 불필요 (예: claudemax 후기, exaone 후기 등 한국어 전용 콘텐츠)**:
1. 한글 slug 번역본 doc unpublish
2. sitemap에서 자동 제거
3. 301 불필요 (외부 링크 가능성 극히 낮음)

### 3-3. 추가 발견: 잠재적 중복 (C분류 후보)

**Firestore 직접 조회 필요 사항**: 교차오염 17개 base slug 중, 재번역으로 영문 slug 번역본이 이미 별도 존재하는 경우가 있을 수 있음.

예시: `ai에-대한-서론` 원본의 EN 번역이 Firestore에 2건 존재할 가능성:
- `ai에-대한-서론-en` (한글 slug doc, 교차오염)
- `introduction-to-ai-en` (영문 slug doc, 정상)

이 경우 동일 콘텐츠가 2개 URL로 노출 → **중복 콘텐츠 패널티 위험**. Firestore `originalSlug` 필드로 검색하여 확인 필요.

**hreflang 양방향 일관성**: ✓ (한글 slug 내에서는 양방향 일관)

**문제점**: hreflang이 한글 slug URL만 가리킴. 같은 글의 영문 slug 번역본이 별도 존재할 경우, 영문 slug 페이지의 hreflang과 충돌 가능. 검색엔진이 어느 쪽이 정본인지 혼란.

### 4-3. canonical 정합성

- 모든 페이지의 canonical = self-referencing ✓
- 한글 slug 페이지가 영문 slug 페이지를 canonical로 가리키지 않음 → **교정 필요**

## 5. 추천안

### 💡 옵션 B (Firestore slug 일괄 갱신 + 301) 추천

**근거**:

1. **근본 해결**: Firestore doc ID가 영문이면 sitemap, hreflang, canonical 모두 자동 정상화. 옵션 A/C는 URL층 패치일 뿐 Firestore에 한글 doc이 영구 잔존.

2. **유지 비용 0**: 갱신 후 301 매핑만 유지하면 끝. 옵션 A는 60건 매핑을 영구 관리.

3. **재번역 안전**: 현재 translate.js는 기존 doc 존재 시 update하므로, 영문 slug doc이 정본이면 재번역 시 동일 doc에 갱신. 한글 slug doc이 남아있으면 재번역 시 또 한글 slug doc을 update해서 문제 재발.

4. **기존 선례**: server.js에 이미 12건의 수동 301 매핑이 동작 중. 301 패턴 검증 완료.

5. **리스크 관리**: Firestore batch write + 301 동시 배포로 순간 404 최소화. 작업 전 Firestore 전체 export 백업.

### 실행 단계 (승인 시)

1. **Firestore 조사** — 교차오염 25건 doc의 영문 slug 대응 존재 여부 확인
2. **영문 slug 생성** — 미존재 건에 대해 번역 API 트리거 또는 수동 slug 배정
3. **Firestore 마이그레이션 스크립트** — 한글 doc → 영문 doc 이동 (batch)
4. **server.js 301 매핑** — 한글 slug → 영문 slug 60건 추가
5. **배포 + GSC 검증** — sitemap 재제출, 색인 상태 확인

### 우선순위

| 단계 | 대상 | 긴급도 | 이유 |
|------|------|:------:|------|
| 1단계 | A (교차오염 25건) | 🔴 즉시 | hreflang mismatch + 검색엔진 신뢰도 |
| 2단계 | B (KO 잔재 35건) | 🟡 1주 내 | 기능 문제 없으나 SEO 장기 불리 |
| 3단계 | translate.js 방어 | 🟢 배포 시 | 재발 방지 — slug 빈값 시 fallback 강화 |
