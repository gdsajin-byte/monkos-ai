### 4-2. BM25 검색 알고리즘 상세

```
점수 체계:
  keyword 매칭: +10점 (doc.keywords 배열의 kw가 쿼리에 포함)
  title 매칭:   +5점  (쿼리 단어가 title에 포함)
  content 매칭: +2점  (쿼리 단어가 content에 포함)

필터: score > 0
정렬: score 내림차순
상위 3건 반환
```

**평가**: 엄밀한 BM25는 아님 (TF-IDF/문서 길이 정규화 없음). 키워드 가중치 기반 간이 검색. 현재 규모에서는 충분하나, 지식 100건+ 시 임베딩 기반 검색 고려 필요.

### 4-3. RAG 주입 포맷


## 6. TG 봇 통합 설계 — CS + 이벤트

### 6-1. 현황

| 봇 | 핸들 | 용도 | AI | 웹훅 URL |
|-----|------|------|:--:|----------|
| CS | @monkos_support_bot | 고객 상담 | ✅ | /api/webhook/telegram |
| 이벤트 | @monkos_event_bot | 채널가입/미션 | - | /api/webhook/telegram-event |
| 팀 | @monkos_team_bot | 내부 협업 | - | /api/webhook/telegram-team |

**작가님 방향**: CS + 이벤트 → 1개 봇으로 통합. 팀봇은 별도 유지.

### 6-2. 통합 봇 설계 — `/start` 파라미터 분기

```
/start (파라미터 없음)
  → 통합 환영 메시지 (CS 안내 + 이벤트 안내)

/start GATE_{code}
  → 기존 이벤트봇 GATE 로직 (userId ↔ telegramId 매핑)

/start MISSION_{code}
  → 기존 이벤트봇 MISSION 로직 (이미지 수신 대기)

/start bonus_{code}
  → deprecated 안내 (기존 CS봇 호환)
```

### 6-3. 이미지 메시지 분기

```
이미지 수신 시:
  1. telegram_links에서 missionPending 확인
  2. missionPending === true → 미션 이미지 처리 (현재 이벤트봇 로직)
  3. missionPending === false → "이미지 상담은 지원하지 않습니다" 안내
```

### 6-4. 일반 텍스트 분기

```
텍스트 수신 시:
  → chatWithMonkos('telegram', chatId, text) — 기존 CS봇 AI 응답
  (이벤트봇의 "이 봇은 이벤트 전용입니다" 안내 제거)
```

### 6-5. 웹훅 변경 영향

| 항목 | 변경 내용 |
|------|----------|
| 웹훅 URL | `/api/webhook/telegram` 유지 (CS봇 URL 그대로) |
| 이벤트봇 웹훅 | `/api/webhook/telegram-event` → deprecated (제거 가능) |
| BotFather 설정 | @monkos_event_bot 비활성화, @monkos_support_bot에 통합 |
| 기존 딥링크 | GATE_/MISSION_ 코드가 @monkos_support_bot을 가리키도록 웹 프론트 변경 필요 |
| 영향 범위 | portal/server.js 핸들러 병합, 프론트엔드 딥링크 URL 변경, BotFather 설정 |

### 6-6. 마이그레이션 단계

1. **server.js**: telegram-event 핸들러 로직을 telegram CS 핸들러에 병합
2. **프론트엔드**: 딥링크 URL을 `t.me/monkos_support_bot?start=GATE_{code}` 로 변경
3. **테스트**: GATE/MISSION/일반 CS 모든 경로 E2E 검증
4. **전환**: 이벤트봇 웹훅 해제, CS봇 웹훅에 통합 핸들러 연결
5. **정리**: 이벤트봇 핸들러 코드 제거, @monkos_event_bot에 안내 메시지 설정
