### 5-2. 4060 Windows 실기 재현 (작가님 지시)

방식: 실이미지 4종 생성(System.Drawing) → Edge/Chrome `--headless=new --remote-debugging-port` 기동 → **CDP `DOM.setFileInputFiles`로 실제 파일 업로드** → MIME·게이트 판정·에러 문구·프리뷰 수집 + 스크린샷.

| 파일 | Windows 부여 MIME | 게이트 | 결과 |
|---|---|---|---|
| test.jpg | image/jpeg | ✅ | 정상 |
| test.jfif | image/jpeg | ✅ | 정상 (이 PC 레지스트리 매핑) |
| **test.bmp** | **image/bmp** | ❌ **거부** | **"JPG, PNG, HEIC 파일만 업로드 가능합니다." 실제 노출 확증** |
| test.png | image/png | ✅ | 정상 |

### 5-3. 원인

[`specs-funnel.js:217`](../../../monkos_AI/portal/public/js/specs-funnel.js)
```js
if(!file.type.match(/image\/(jpeg|png|heic|heif|webp)/i)) return showError(T.errFileType);
```
- 파일 입력은 `accept="image/*"`(관대)인데 **JS 게이트는 5종만 통과** → 불일치.
- 거부 목록 실측: bmp·tiff·gif·jfif·pjpeg·x-png·avif·octet-stream·**빈 문자열**.
- **macOS는 UTI가 jpeg/png/heic로 정규화** → 작가님 사무실 테스트에서 구조적으로 재현 불가했던 이유.
- Windows 레지스트리 실측: `.jpg`·`.jfif`=image/jpeg, `.png`=image/png, `.bmp`=image/bmp, **`.webp`=Content Type 미등록** → PC별 레지스트리 상태에 따라 빈 MIME 반환 위험 상존.
- **계측 블랙박스**: `photo_upload`는 게이트 통과 후 발화(224행) → **거부 사례가 통계에 전혀 안 남음**. 14일간 무증상이었던 이유.

### 5-4. 가설 정정 2건 (실측이 추정을 교정)

1. **"Edge 특이성" 아님** — Chrome/Windows도 `.bmp` 동일 거부. **브라우저 문제가 아니라 파일 포맷·OS 문제.** GA4의 "Edge upload 0"은 표본 36건에서 성공 케이스가 안 나온 것(Chrome도 46→7로 15%에 불과).
2. **`.jfif`는 이 PC에서 통과** — 앞서 "jfif 거부" 추정은 이 PC에선 오류. 단 `.webp` 미등록 확인으로 빈 MIME 위험은 유효.

### 5-5. 정상 경로 생존 확인

png 통과 후 서버 precheck 도달 → "얼굴을 찾지 못했어요"(더미 이미지라 정상 반응) = **게이트 통과 시 파이프라인 정상.** 고칠 지점은 217행 단일.
