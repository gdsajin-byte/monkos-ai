# 진단: 눈 41%·상단 2mm·하단 10mm 고정 + 헤어 잘림 — 전수 검수

**[2026-07-09 19:01 KST]** iMac/민아 → 작가님, iMac/쌍아

## 결론: 캐시도 배포 꼬임도 아님 — **코드가 수학적으로 그 값만 낼 수 있는 상태**

### 검산 (프로드 뱃지 = 현행 코드 항등식)

현행 배치식: `topTarget = crownY×scale − 2mm` (hairTop 미실측 폴백). 이 식의 출력은 **사진과 무관한 상수**다:

- 상단(정수리 여백) = **2mm** (식 자체가 고정)
- 하단 = 45 − 33 − 2 = **10mm** (항등식)
- 눈 = (2 + 16.5) / 45 = **41.1%** (항등식 — 눈은 두상 중앙이므로 정수리 여백이 정해지면 자동)
- 얼굴 = **33mm** (스케일 정의)

전부 mm·% 단위라 **스케일 불변** — 어떤 사진을 올려도, 몇 번을 재배포해도 같은 숫자가 나오는 게 정상 동작이다.
"새 사진인데도 동일값 = 캐시"라는 가설이 기각되는 이유: 동일값은 캐시가 아니라 **폴백 산식의 수학적 필연**이다.
역으로 배포는 잘 반영되고 있다: 어제 43%(EYE_POSITION_RATIO 0.43) → 오늘 41.1%(crown−2mm)로 상수가 바뀐 것 자체가 배포 반영의 증거다.

### 근본 원인: 헤어탑 실측 입력이 파이프라인에 존재하지 않음

```
portal /api/fit  →  crop-engine /api/fit-spec (hairScan: false 하드코딩, server.js:364)
                    → fitSpecGeometry: landmarks.hairTop ?? crownY
                       └─ landmarks.hairTop을 채우는 코드가 리포 전체에 없음 (grep 확정)
                          subjectTopRow()는 정의만 있고 호출 0곳 (사문화)
```

`hasHairTop`은 **항상 false** → 전 사진이 "정수리+2mm" 폴백 → 헤어볼륨 2mm 초과분은 전원 프레임 밖 = **모든 실사에서 헤어 잘림**.
하단 10mm 여유가 있어도 못 쓰는 이유: 최종 산식의 **밴드 확장(헤어볼륨 실측만큼 정수리밴드를 천장까지 늘림)이 미구현** — 지금 코드는 밴드 하한만 구현된 상태다.

## 수정 방향 (최종 산식 그대로 — 새 결정 불필요)

```
정수리밴드 = clamp( 헤어볼륨(실측), 2.5mm, frameHmm − faceTarget − 어깨선(실측) )
extractTop = crownY×scale − 밴드×mmPx  →  hard 클램프(정수리·턱 양단)
```

1. **resolvePlacement() 단일 함수**로 위 산식 구현, cropToFrame·fitSpecGeometry 공용 (B2·B3·B5 동시 해소)
2. **실측 입력**: 최종 크롭 = 매팅 알파에서 헤어탑(알파 최상단) + 어깨선(폭 프로파일). T0 순서 "매팅 → 실측 → 크롭"은 퍼널 설계서 §8-1에 이미 확정
3. **fit 프리뷰 입력** — 작가님 결정 1건:
   - (a) fit 시점에 매팅 선행 + 결과 재사용: 프리뷰 정확 (헤어 안 잘림), T0 전환 유저는 추가 비용 0, 이탈 유저만 매팅비 ~₩15~20 발생 (무료 3회 캡으로 상한 유계)
   - (b) 프리뷰는 폴백(밴드 하한) 유지 + "완성 시 헤어 실측 반영" 라벨: 비용 0, 시어터에서 헤어 잘려 보이는 UX 리스크 지속
4. **비권장**: soft 타겟 2→3~4mm 인상 (쌍아 제안) — 또 하나의 고정 계수. 4mm로도 펌 5mm는 잘리고 대머리는 여백 과다. 밴드 확장이 정답이며 상수 조정은 증상 이동일 뿐
