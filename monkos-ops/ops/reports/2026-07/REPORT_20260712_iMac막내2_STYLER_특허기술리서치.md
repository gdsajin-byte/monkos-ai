### B-1. 정체성 보존 규격 사진 자동 생성 시스템 — 🥇

**현재 선행기술 공백:**
- IDEMIA 특허(US11,341,612): 기존 사진 "보정" — 생성(generation)이 아님
- Snap 특허(US12,423,777): Diffusion 생성 시 정체성 보존 — 규격 준수 게이트 없음
- **MONKOS 고유 결합**: AI 생성 + ICAO 규격 자동 크롭 + 프레이밍 게이트(재생성 로직) + 다국어 1,278종 규격

**청구항 방향:**
```
[방법 청구항] 컴퓨터에 의해 수행되는 규격 사진 자동 생성 방법으로서:
(a) 사용자 단말로부터 셀카 이미지를 수신하는 단계;
(b) 확산 모델을 이용하여, 상기 셀카의 얼굴 정체성을 보존하면서 
    배경·의상·조명을 변환한 생성 이미지를 출력하는 단계;
(c) 국제 규격 데이터베이스(ICAO 등)에서 대상 규격의 
    얼굴 비율·크롭 파라미터를 조회하는 단계;
(d) 생성 이미지에 대해 자동 크롭 및 프레이밍 검증을 수행하는 단계;
(e) 프레이밍 검증 실패 시, 크롭 파라미터를 조정하여 1회 재생성하고,
    재실패 시 폴백 처리하는 단계
를 포함하는 방법.
```

**강점**: 개별 요소(Diffusion 생성, 규격 크롭, 재생성)는 알려져 있으나, "생성 + 규격 자동 검증 + 조건부 재생성"의 **통합 시스템**은 선행기술에서 발견되지 않음.

### B-3. 정체성 게이트 (ArcFace + 점진적 폴백) — 🥇

**현재 선행기술 공백:**
- Snap 특허: 생성 **시점**의 정체성 보존 (feature blending) — 생성 **후** 검증 없음
- Shopify 특허(US20240160902A1): 유사도 기반 재생성 루프 — 유사도 **초과** 시 재생성 (방향 반대)
- Apple 특허(US11,693,937): 얼굴인식 실패 시 재시도 — 인증 도메인
- **MONKOS 고유**: 생성 후 ArcFace 검증 → 미달 시 보정 강도 단계적 하향 → 최소 보정 폴백

**점진적 폴백(Progressive Degradation)이 핵심 차별점:**
```
생성(풀 보정) → ArcFace 검증 FAIL 
  → 재생성(저보정) → ArcFace 검증 FAIL 
    → 폴백(최소 보정: 피부·조명만) → 반드시 통과
```

이 "단계적 품질 양보" 로직은 어떤 선행기술에서도 발견되지 않음.

**청구항 방향:**
```
[방법 청구항] AI 생성 이미지의 정체성 보장 방법으로서:
(a) 원본 이미지의 얼굴 임베딩 벡터를 추출하는 단계;
(b) 제1 보정 강도 파라미터로 생성 이미지를 출력하는 단계;
(c) 생성 이미지의 얼굴 임베딩과 원본 임베딩의 유사도를 산출하는 단계;
(d) 유사도가 임계값 미만인 경우, 보정 강도를 하향 조정하여 
    재생성하는 단계;
(e) 재생성 결과가 다시 임계값 미만인 경우, 최소 보정 수준으로 
    폴백 생성하는 단계
를 포함하는 방법.
```

### B-4. 멀티서비스 공유 의상 피커 + 프롬프트 합성 — 🥈

**선행기술:**

- 기존 VTON 특허들: 단일 서비스 내 의류 선택 — 멀티서비스 공유 구조 없음

**MONKOS 고유:**
- 단일 의상 스키마(9-필드: category/subcategory/color/tone/pattern/fit/neckline/formality/vendor)가 증명사진·헤드샷·모델스·커머스에 걸쳐 공용
- 태그 기반 스키마 → 자연어 프롬프트 자동 합성 → Imagen/Diffusion 입력
- 벤더 메타데이터 선탑재로 커머스 확장 ready

**특허성**: 중간~높음. "멀티서비스에 동시 서빙하는 통합 의류 스키마"는 선행기술 공백이나, 청구항이 데이터 구조 위주면 진보성 인정 어려움. "스키마 → 프롬프트 자동 합성 → 생성 모델 입력"의 방법론을 기술적으로 기술하면 강화.

**특허성**: 높음. 인증 영역에서는 유사 특허가 있으나, "생성(generation) 파이프라인에서의 프라이버시 보존 분리 아키텍처"는 선행기술 공백. 앱 단계 구현 시 출원 적기.

### B-6. AI 생성 + 인화 + 배송 통합 옵션 스택 — 🥉

**선행기술:**
- US11,354,717 / US12,499,466: 이미지 품질 기반 자동 인화 상품 생성 — 일반 사진 (AI 생성 아님)
- US7,406,256: 자동 포트레이트 스튜디오 — 물리 촬영
- US5,974,401 / US6,798,532: 디지털 사진 주문+배송 — 기본 인프라

**MONKOS 고유:**
- AI 생성 → 규격 인화지 자동 배치 → 인화 주문 → 배송 일괄 처리
- "사진관 O2O"를 AI로 대체하는 통합 파이프라인

**특허성**: 중간. 개별 요소(AI 생성, 인화 주문, 배송)는 알려져 있음. 통합 시스템으로 신규성은 있으나, "당업자의 단순 결합"으로 진보성 거절 가능. 다른 출원과 종속항으로 묶어 보강 권장.

### B-7. 규격 도해 자동 생성 시스템 — 🥉

**선행기술**: 규격 도해(치수선+라벨+다국어 텍스트)를 자동 생성하는 특허 미발견.

**MONKOS 고유:**
- 규격 데이터(JSON) → 대표 이미지 + 치수선 + 다국어 라벨 → SVG/PNG 자동 생성
- 1,278종 다국어 자동 생성 실적

**특허성**: 중간. 진보성이 "단순한 그래픽 렌더링"으로 거절될 여지 있음. 독립 출원보다 B-1(규격 사진 시스템)의 종속항으로 편입 권장.

## 종합 결론

### 핵심 발견 5가지

1. **"AI VTON + 어필리에이트 커머스" 결합 특허 = 세계적으로 부재** — MONKOS의 가장 강력한 특허 기회. 즉시 출원 권장.

2. **"정체성 게이트 + 점진적 폴백" 로직 = 선행기술 부재** — Snap(생성 중 보존)과 차별화되는 MONKOS 고유 방법론. 등록 가능성 매우 높음.

3. **Snap US12,423,777이 가장 가까운 선행기술** — 그러나 "생성 중 feature blending" vs MONKOS의 "생성 후 검증 + 재생성"은 기술적으로 구별됨.

4. **CatVTON은 상업 불가 (CC BY-NC-SA 4.0)** — 상업 VTON은 FASHN v1.5(Apache 2.0) 또는 상업 API만 안전. 현재 4060 PoC에서 사용 중인 모델 라이선스 재확인 필수.

5. **한국 경쟁사(증명한컷/인핸즈/에이블리) 특허 전무** — 선점 효과 극대화 가능. 단, NAVER가 2건 보유(US 등록)하므로 VTON 시장 진입 시 주의.
