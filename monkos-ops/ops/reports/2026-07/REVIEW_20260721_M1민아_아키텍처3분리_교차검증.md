## ① CORS/Workers 판단 → **Workers 프록시 채택 권고 (확정 의견)**

| 근거 | 실측 |
|------|------|
| 쿠키 | `monkos_session` = `Domain=.monkos.ai; SameSite=Lax` (auth.js:154·175·344) — 동일 도메인 프록시면 **코드 무변경**. CORS안(별도 오리진)은 credentials CORS + 프리플라이트 추가 공수 |
| 콜백 경로 | OAuth 콜백은 `/auth/google/callback`·`/auth/kakao/callback`·`/auth/line/callback` — **`/api/*` 밖** (server.js:316~321). **프록시 범위에 `/auth/*` 포함 필수**, 아니면 로그인 전면 붕괴. §8 "기존 URI 유지 가능"은 이 조건 하에서만 성립 |
| 결제 웹훅 | Toss/Lemon 웹훅 CR 직접 수신 = 설계 그대로 무관 ✓ |

**🔴 크리티컬 1 — 클라이언트 IP 소실**: 서버가 XFF 헤더로 IP를 뽑는다 (server.js:104 `split(',')[0]`, :117-118·167-168 `split(',').pop()`). Workers 프록시 뒤에서는 pop()이 **CF 이그레스 IP**를 반환:
- `freeQuotaKey(req)`(server.js:166~168) = **무료 쿼터가 IP 키** → 전 유저가 CF IP 소수에 합산 → 개인 3회 캡이 사실상 즉시 소진, **무료 퍼널 전면 오차단**
- `detectPaymentRegion`(server.js:257) geoip → **시장별 가격(kr ₩1,500/global $1) 오판정** + trackEvent ipCountry 오염(server.js:222·226·986 — 7/10 적대검증 #1로 지킨 필드)

**처방**: Workers에서 `CF-Connecting-IP`를 커스텀 헤더로 포워딩 + server.js IP 추출 함수가 이를 최우선 신뢰(프록시 시크릿 헤더로 위조 방지). Phase 0 검증 항목에 **쿼터·지역판정 E2E** 추가.

**소건**: Workers 무료 100k req/일 — `/api/track`이 전 페이지뷰마다 편승하므로 트래픽 성장 시 상한 접촉. 유료 $5/월로 해소(절감액 대비 무시).

## ② SSR→SSG diff 실현성 → **실현 가능. 단 순수 정적이 아니다 — 블로커 1 + 이식 인벤토리 1**

- 기본 구조는 유리: 퍼널 CSS/JS 정적 분리 기완료(7/12), ASSET_VER=K_REVISION(render-specs.js:37)은 빌드 시 상수화로 치환 가능.
- **🔴 크리티컬 2 — paymentRegion SSR 주입**: render-specs.js:722·803 `parts.paymentRegion = req.paymentRegion` — **방문자 국가별로 SSR HTML이 다르다** (결제 수단·통화 표기). SSG는 URL당 1변형만 생성 → 시장별 가격 표시가 깨진다. **처방**: 가격/PG 표기 블록을 클라이언트 하이드레이션으로 이관 (`GET /api/region` 1콜 또는 CF 지역 헤더 → JS 렌더). §4-2 "T1 버튼 등"보다 범위가 깊다 — Phase 2 공수에 명시 반영.
- **서버 리다이렉트 인벤토리 이식**: server.js 301 로직 10지점 + render-specs.js 8지점 (국가 축약형 40건·1-seg·블로그 -kr/-en/-ja 변형·/crop 은퇴 등). CF `_redirects` 파일 **생성기**(COUNTRY_SLUG_TO_ISO 등 정본에서 자동 생성)를 빌드 파이프라인에 포함할 것. 설계서에 부재 — §4-3에 추가 필요.
- **diff 게이트 방법론**: 표본이 아니라 **429×9 전량 크롤 diff** (Workflow 1회면 됨). K_REVISION·빌드 타임스탬프 정규화 후 바이트 대조. 잔차 화이트리스트 방식(7/15 헤드텀 게이트 방식 준용).
- **신선도**: 주 1~2회 빌드는 데이터 핫픽스(금일 EUEU 정정류)가 라이브 반영 지연됨 → specs-data.json 커밋 훅 트리거(설계 기재) 필수화 + Phase 2 이행기 동안 SSR 원본·SSG 사본 이중 서빙 정합 절차 1줄 명기.

## ③ 공수 산정 → **개별 수치 수용. 순서 1건·원칙 1건·게이트 1건**

- Phase 0(1~2일)·Phase 1(1~2주)·Phase 2(1~2주): 팀 실측 속도 대비 타당. (작가님 요약의 "12주"는 오기 — 설계서 원문은 1~2주)
- **순서 교차 제안**: 발단이 PSI(LCP 22s)·비용이면 **Phase 2(SSG)가 직접 처방** — 절감의 대부분(portal min 0 전제)과 LCP 개선 모두 specs 정적화에서 나온다. 허브(Phase 1)는 전략 확장이므로 작가님 우선순위 판단에 따라 1↔2 스왑 검토.
- **허브 SPA 재사용 원칙**: upload→result→pay 분기는 이번 달 5차례 사고 수습을 거친 `specs-funnel.js`(기분리 정적 모듈)를 **그대로 재사용**할 것. 신규 SPA에서 퍼널 로직 재구현 금지 — 재해석 금지 원칙(7/7 각인) 지시서에 명기 필요.
- **🟠 min 0 전환 게이트**: 콜드부트 창 전면 실패는 기실증 이슈(7/18 발견 기록). API-only여도 결제·생성 경로가 콜드에 걸리면 돈 경로 실패. Phase 4에서 min 0 확정 전 **콜드 E2E(업로드→생성→결제) 실측** + 대안 비교(min 1 유지 시 실비용 vs 콜드 리스크). §2-2 ₩30,000은 이 게이트 통과 후 확정.
- 4060 상시 가동 신뢰성은 Phase 5 관찰로 기설계 ✓ (RunPod 폴백 유지 = 올바른 안전망).

## ④ DNS 해소 방안 → **실질은 NS 이관. 서브도메인 전수 인벤토리가 선행 조건**

- 실측: monkos.ai apex = GFE 직결(216.239.x, CR 매핑) — 금일 오전 확정. CF Pages 커스텀 도메인(apex)은 **CF DNS(네임서버 이관)가 사실상 요구됨** → §8의 "충돌"은 회피가 아니라 **이관 절차 설계**로 푼다:
  1. 서브도메인 전수 인벤토리 선행 — 실측된 CR 서비스만 8종(portal·portal-dev·idphoto-kr·idphoto-jp(+dev)·crop-engine·image-engine·n8n·jangsam-dev) + studio·pt 등. 각각의 도메인 매핑·인증서 소유 확인 (`gcloud beta run domain-mappings list` — 콘솔 실측 필요)
  2. CF DNS로 레코드 이식 시 **CR 매핑 서브도메인은 gray-cloud(프록시 OFF) CNAME 유지** — 구글 관리형 인증서 갱신이 프록시 뒤에서 깨지는 것 방지
  3. apex만 orange(CF Pages), TTL 사전 인하 → 전환 → CR apex 매핑 제거 순서
- `api.monkos.ai` 분리안은 차선: 쿠키는 `.monkos.ai`라 살지만(same-site) credentials CORS 코드 추가 필요. Workers 프록시가 상위안.
