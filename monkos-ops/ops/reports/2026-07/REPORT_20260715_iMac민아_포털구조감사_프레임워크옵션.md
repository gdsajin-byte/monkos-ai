# 포털 구조 감사 + 프레임워크 재설계 옵션 평가

> 작가님 지시(07-15): "작업 스코프·메인 서버·렌더러 전체 규모와 적절한 분기 정위치, 디버깅·리팩토링 설계도를 포털 전반과 함께 구조화 정합성으로 따져올 것. 필요 시 프레임워크 재설계까지 감안."

## 결론 요약

1. 포털 총 ~1.8만 행, **프레임워크 제로**(express조차 없는 순수 http). 이 자체는 결함이 아니라 자산(빌드리스·디버깅 직결·에이전트 친화).
2. 실병리는 프레임워크 부재가 아니라 **① 동일 분기 축의 다층 산재 ② 세대별 인프라 4겹 적층(정본 부재) ③ server.js 모놀리스** 세 가지.
3. 권고: **프레임워크 전환은 지금 아님** — 결정 게이트(§5)를 예약하고, 현 스택에서 분기 정위치 원칙 + 컴포넌트 계약(기안 D2) + server.js 분리를 먼저. 이 세 개가 되어 있어야 훗날 전환하더라도 이식이 싸진다.

## 3. 분기 정위치 원칙 (제안 — 아키텍처 표준 #1)

**"축 판별은 요청당 1회, 진입부에서. 이후는 ctx 전파만."**

```
요청 → [ctx 생성기] → ctx = { lang, market, tier, service, slug, user }
     → 라우터(service) → 렌더러(ctx) → 컴포넌트(ctx 필드만 소비)
     → 위젯 초기화 CFG = ctx 부분집합 직렬화 (클라 재판별 금지)
```

- 렌더러·컴포넌트·위젯 어디서도 `lang === 'ko'` 같은 재판별 금지. 게이트 상수(env)는 ctx 생성기만 읽는다.
- 이 원칙이 있으면 이번 사고류(게이트 하나에 낡은 분기 조합 노출)는 ctx 생성기 diff 하나로 리뷰가 끝난다.

## 4.5 소유권 4계층 — 컴포넌트 조화·횡단 관심사 계약 (작가님 질의 07-15)

> 배경: 지난 포털에서 박스 조합 시 "한 섹션 카드 사이즈 조정 → 타 섹션과 조화 재작업"이 단일 페이지보다 비쌌던 경험. 실측 진단: 조합 기능은 실존(home.js Layout API — Firestore sections[] 레시피의 원형)했으나 **디자인 토큰 0건**(전 CSS에 :root 변수 부재) — 조화 요소의 소유권이 각 컴포넌트에 남아 있어 조화가 컴포넌트 수²의 수동 동기화가 됐던 것. 컴포넌트화의 함정이 아니라 계약 누락.

| 계층 | 소유하는 것 | 규칙 |
|------|-----------|------|
| **L0 디자인 토큰** | 치수·간격·색·타이포·라운드 (CSS 변수 정본 1파일) | 컴포넌트의 px 직접 소유 금지. 카드 사이즈 조정 = 토큰 1줄 = 전 섹션 동시 조화 |
| **L1 셸+그리드(슬롯)** | 배치 결정권 — 페이지 골격·컬럼·브레이크포인트 | 컴포넌트는 "슬롯 몇 칸" 선언만. 배치를 컴포넌트가 알지 못하게 |
| **L2 컴포넌트** | 콘텐츠+행동만 | (ctx, data)→html / mount(el, opts). 기안 D2의 2계층이 여기 |
| **L3 전역 서비스 (횡단)** | Auth·Pay·Track·Chat | 컴포넌트는 호출만. **결제 리다이렉션 = intent 패턴**: Pay.start(intent 저장)→PG 왕복→전역 복귀 핸들러가 intent 복원. 인증 = Auth.require() 단일 진입. 컴포넌트별 리다이렉트 처리 금지 |
| **레시피** | 페이지 = 슬롯×컴포넌트 배열 선언 | home Layout API가 원형 — specs 문서타입 레시피로 일반화 |

**확장 시나리오 검증**: 이벤트 박스·파트너 연결(의상 커머스 벤더 박스)·챗봇 섹션 = L2 컴포넌트 1개 등록 + 레시피 1행. L0~L3 계약을 따르는 한 기존 페이지 재작업 0. 챗봇은 기존 chat.js를 L3 서비스+L2 섹션으로 재배치.

**실용 최소선** (신축 아닌 추출): ① 토큰 1파일 — 기존 CSS 반복값 추출 (트랙 1 P1에 편입) ② 그리드 규약 명문화 — 현행 v2 2컬럼 구조 ③ Auth/Pay 클라 파사드 — 기존 auth.js·payments.js 앞단 (트랙 2 병행). 완비형 디자인 시스템 신축은 금지 — 과설계 경계.
