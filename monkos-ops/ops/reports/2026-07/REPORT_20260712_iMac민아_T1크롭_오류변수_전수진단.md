# T1 크롭 오류 변수 전수 진단 — 해결 논리구조 + 얽힘 버그 2건 (크롭 검수 마감)

**[2026-07-12 18:37 KST]** iMac/민아 → 작가님, iMac/쌍아

> 지시: "간헐적 얼굴 과대 크롭 — T1 전체 흐름의 오류 변수 확인, 재발방지·사후검증 최선점, 잦은 디버깅으로 맥락이 섞여 생긴 버그 검출. 오늘 크롭 검수를 닫자."

## 1. 증상의 완전한 인과 사슬 (실측 재현 완료)

**"간헐적 얼굴 과대"는 단일 버그가 아니라 4개 구멍의 곱**이다. 나노2 실출력 4973으로 전 사슬을 재현했다:

```
① 원천(확률): 나노2가 간헐적으로 얼굴 과대·상단 밀착 출력
   — [FRAMING] wide 지시에도 hairTop=0 (4973 실측: 머리가 이미지 최상단에 밀착)
② 계측 공백(결정): crop-engine이 스케일 축소해도 원본에 정수리 여백이 없어
   축소본 < 프레임 → 흰 패딩 합성 경로(crop.js:205) → meta = {scale, padded} 만 반환
   — faceMM·crownMarginMM·eyePositionPercent 산출 없음
③ 판정 공백(결정): cropMetaWithinSpec — parseFloat(undefined)=NaN → Number.isFinite=false
   → 두 판정 모두 스킵 → return true. **"수치 없음 = 합격" 프리패스**
④ 출고: 얼굴 과대 + 정수리 잘림 + 하단 흰 패딩의 규격 미달품이 게이트 통과
```

재현 실측 (kr-passport spec, crop-engine 실주행):

| 입력 | fallback | faceMM | crown | eye | 현 게이트 |
|------|----------|--------|-------|-----|----------|
| 4480 v4 | false | 33.0 | 3.8mm | 45.1% | 통과 (정상) |
| 4926 v4 | false | 33.0 | 3.8mm | 45.0% | 통과 (정상) |
| **4973 v4** | **false** | **undefined** | **undefined** | **undefined** | **통과 ← 사고** |

4973 크롭 실물 = 작가님이 문제 삼은 바로 그 출력물(얼굴 과대·정수리 잘림·하단 패딩). "간헐적"인 이유 = ①만 확률이고 ②③은 결정론이라, ①이 발생하면 100% 통과한다.

**부가 변수 (이번 증상의 주범은 아니나 잠복)**: crownY 미러 산식의 자기 참조 — 턱 오검출 시 facePx 과소→scale 과대→얼굴 과대인데, meta의 faceMM도 같은 검출값으로 계산되어 33.0으로 보임(왜곡을 자기 수치로는 못 잡음). 외부 기준(hairTop 스캔) 교차가 필요한 근본 이유.

## 2. 얽힘 버그 2건 (잦은 디버깅의 맥락 충돌)

**버그 A — T1 "매팅본 유지" 폴백 사망 (86baf3c6 ↔ f64c8560 충돌)**
어제 프레이밍 게이트(f64c8560)는 "재이탈 시 매팅본 유지"였는데, 오늘 매팅 스킵(86baf3c6)으로 매팅본이 존재하지 않는다. server.js:792 `if (!t1Done && finalBase64)` — finalBase64=null이라 불발 → **805행 Gemini L3 재생성으로 흘러 의상·보정 무시 출력이 결제 고객에게 출고**. 767행 주석("결제 산출물이 무료보다 나빠지는 경우는 구조적으로 없음")·789행 로그("매팅본 유지")·genTrack(t1-framing-fallback)이 전부 옛 맥락 잔재.

**버그 B — 게이트 프리패스 (§1-③)**
f64c8560이 게이트를 넣을 때 "meta가 항상 있다"고 가정했으나, crop-engine의 패딩 경로(그 이전부터 존재)는 meta를 안 준다. 두 시점 코드의 암묵 가정 충돌.

## 3. 해결의 논리구조 — "확률 원천은 못 없앤다. 결정론 사슬을 완성한다"

나노2 출력 편차는 AI 특성상 제거 불가. 따라서 방어선은 **계측(빠짐없이) → 판정(수치 없으면 불합격) → 폴백(정직한 실패)**의 결정론 3단이 완성되어야 하고, 각 층은 독립이어야 한다(한 층의 가정이 깨져도 다음 층이 잡게).

| 층 | 위치 | 내용 | 근거 실측 |
|----|------|------|----------|
| **L1 원천 게이트** | server.js T1 루프, 크롭 전 | 나노2 출력 hairTop 스캔(흰배경 행 스캔) — 상단 마진 <2mm면 크롭 없이 즉시 재생성 | 스캔 3/3 정확, 4973 감지 실증. 크롭엔진 왕복(수 초) 절약 |
| **L2 계측 완전성** | crop-engine crop.js | 패딩 경로 포함 **전 경로 meta 필수**(faceMM·crown·eye — landmarks 있으므로 산출 가능) + `padded` 플래그 유지 + hairTopMargin 계측(스캔값 주입 → 기존 soft여백·스케일축소 루프 자동 활성) | crop.js:51~75 소비 로직 기완비. SCRFD bbox는 대체재 아님(실측 -8mm) |
| **L3 판정 강화** | portal matte.js cropMetaWithinSpec | ① **meta 없음/NaN = 불합격** (프리패스 반전) ② `padded=true` 불합격 ③ headHeight 범위 판정 — spec의 headHeightMinMm~MaxMm(**이미 crop-engine에 전달 중**, 32~36mm)를 faceMM에 적용 ④ crown 하한 ≥2mm (현행 상한 10mm 유지) | 4973이 ①②에서 차단됨. 4480/4926은 ③ 32≤33≤36 통과 — 오탐 없음 |
| **L4 폴백 정직화** | server.js T1 블록 | 게이트 2회 이탈 = **에러 + 환불(refundGate)** — 나노2 재호출은 API 실패에만(작가님 확정). `isT1Path`는 805행 L3 블록 진입 금지(의상 무시 출력 차단). 주석·로그·genTrack 옛 맥락 청소 | 버그 A 해소. L3 폴백은 비-T1 유료 경로에만 잔존 |

**최선점 판단**: 사후 검증의 정본은 **L3(서버 게이트)** — 규격 합격 여부는 서버가 결제와 함께 책임지는 계약 지점이고, 이미 재생성 루프가 그 판정을 소비한다. L1은 비용 절약(조기 반려), L2는 L3에 수치를 공급하는 전제 조건. L4는 실패의 정직성.

## 4. 구현 배정 제안

- **portal (L3+L4)**: matte.js 함수 1개 + server.js T1 블록 — 소형, 즉시 가능. 단 server.js는 쌍아 트랙 활성 파일이라 **쌍아 크롭 지시서에 통합 권고** (경합 회피).
- **crop-engine (L1 스캔 유틸+L2)**: 쌍아 예고한 크롭엔진 지시서에 본 보고서를 입력물로 — SCRFD bbox 방안은 실측 반증으로 제외, 배경 스캔으로 대체.
- 검증 기준(지시서용): ①4973 입력 → 게이트 차단+재생성(또는 환불) ②4480/4926 → 무변경 통과 ③t1-framing-fallback 로그 문구 현행화 ④T1 게이트 이탈 시 L3 미진입 ⑤ArcFace 게이트 입력 "원본 vs T1" 설계 갱신(86baf3c6 파급, 7/10 설계서 §5).

## 6. 정정 (18:49 작가님 반증 → 재실측) — 주범 확정판

작가님 실물 페어(나노2 1:1 양질 출력 → 과대 크롭) 제시로 §1의 ①(나노2 원천론)이 **주범이 아님**을 확인. 재실측 결과로 정정한다.

**정정 1 — 내 실측 입력 오류**: §1 표의 입력(result_*_v4.png)은 이미 크롭된 최종품(413×531)이었다. 진짜 나노2 원본은 `*_raw1.png`(896×1200). 4973 "상단 밀착"은 크롭본을 재크롭한 허상 — **나노2 원본은 3장 전부 여백 충분한 양질 출력** (작가님 지적 그대로).

**정정 2 — T1 크롭은 InsightFace가 아니라 FaceMesh 경로**: `/api/crop-spec`(server.js:164)은 `detectFace()`=FaceMesh 직행. InsightFace(SCRFD)는 `/api/fit-spec`·`/api/detect`에만 사용. 오늘 "InsightFace 검출 신뢰" 논의는 T1 크롭과 무관했다.

**진짜 기제 (raw1 재실측으로 재현)**: raw1 3장 크롭 → meta 3장 전부 "완벽"(face 33.0·crown 3.8·eye 45)인데 **4973 실물은 과대(헤어 밀착·어깨 소실), 4926은 정상** — 같은 수치, 다른 실물.
- 크롭 산식은 crown(두개골 추산)~chin을 faceTarget 33mm로 정규화한다. **헤어 볼륨이 큰 인물은 헤어탑~턱이 33mm를 초과** → 헤어가 프레임 상단 밀착/잘림 = 시각 과대. 기하 역산: 4973의 crown 마진 3.8mm는 두개골 기준 참이나 **실제 헤어탑 기준 ~1.3mm**.
- 이를 막도록 설계된 것이 hairTop 소비 로직(crop.js:51~75, soft 여백+스케일 축소 루프)인데 —

**얽힘 버그 C (결정판) — 죽은 hairScan**: 흰배경 머리끝 스캔 `subjectTopRow()`가 crop.js:258에 **구현되어 있고**, 소비 로직도 완비인데, **호출부가 존재하지 않는다**(grep: hairScan 사용처 = 주석뿐). fitSpecGeometry는 opts.hairScan을 받고도 미사용. 7/09 크롭 리팩토링(cropToSpecV2 폐기→cropToFrame 통합) 과정에서 연결선이 유실된 것으로 추정 — 구현↔소비 사이 다리만 증발한 전형적 맥락 섞임 버그.

**해법 수렴 (§3 갱신)**: L1·L2는 신규 개발이 아니라 **복원 1지점** — cropToSpecV2 경로에서 `subjectTopRow()` 호출 → `landmarks.hairTop` 주입(나노2 출력=순백 보장이라 안전, 실사 원본 스캔 금지 원칙은 유지). 그 순간 기존 스케일 축소 루프가 헤어까지 프레임에 앉힌다. L3 게이트는 crown이 아니라 **hairTopMarginMM ≥2mm** 판정 추가(4973: 1.3mm → 차단, 4926: 통과 — 오탐 없음). L4(폴백 정직화)와 버그 A·B 수정은 §3 그대로 유효.
