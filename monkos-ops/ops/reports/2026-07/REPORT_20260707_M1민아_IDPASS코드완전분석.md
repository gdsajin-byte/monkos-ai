## 1. IDPASS가 실패율 0인 이유 — 구조 요약

**"자동은 최소, 애매함은 사람에게, 판정은 엄격하게"** 의 3층:

```
[감지]  동공 우선 → 눈 윤곽 평균 폴백 → CIDetector 2차 폴백 → 그래도 실패면 진입 차단 (몰래 진행 없음)
[배치]  눈 앵커(43%/대형 42%) + faceTarget 스케일 — 자동 개입은 이 둘뿐
[판정]  스위트존/허용/차단 3단 신호등 + blocked 시 다운로드·확정 물리 게이트
        + 유일한 사용자 개입점 = 정수리 핀 드래그 (판정계에만 반영, 파괴 없음)
```

앱에는 엔진이 2개 공존한다(설계임 — 합치면 안 됨):
- **배치 엔진** `CropEngine.crop()`: 헤어 재앵커·하단 보장 루프 포함 (배경 재합성 경로 전용)
- **인터랙티브 엔진** `cropAutoPlace()`+`computeMetrics()`: 실사용 경로 — 자동 배치는 단순하게, 나머지는 사용자+실시간 판정

## 4. 개선점 (우선순위 제안 — 쌍아 지시서 대상)

**P0 — 산식 정렬 (그대로 포팅, 재해석 금지)**
1. faceTarget 결정식 전체 이식: 명시값(countries.jsonl `faceTarget` 필드) → 단일값 → 산식, 클램프 [fMin+1, fMax−1] — `spec-crop.js getSpecCropParams` 교체
2. 눈 앵커 `h≥60 ? 0.42 : 0.43` — crop-engine EYE_TARGET_RATIO 교체
3. 헤어: 순백 스캔 폐기(순백 입력 전용 경로에만 잔존 허용) → 정본 8% 추정 + 4.4% 재앵커 + 하단 12% 보장 루프를 fitSpecGeometry에 이식

**P1 — 판정·게이팅 이식**
4. `computeMetrics` 임계표 전량 이식 (FACE 스위트존 20%·EYE·TOP·BTM·CENTER·blocked) — 안착 가드(33~58)를 이것으로 교체, 사후 체크리스트 판정도 동일 표 사용
5. blocked 시 "만들기" 게이트 (현행: 다운로드만 게이트)
6. 커버리지 검사 + coach 메시지 우선순위 (재촬영/조정 안내문 정본화)

**P2 — UX 정본화 (쌍아 "디버그 화면" 지적의 정답이 정본에 있음)**
7. 사용자 화면 = 정본 스타일: **규격 프레임 안에 안착된 사진 미리보기** + 정수리 위/턱 아래 딤(0.35) + FACE mm·EYE% 신호등 뱃지 + READY/ADJUST — 디버그 라인 나열 폐기
8. **수동 정수리 핀 웹 이식** — IDPASS IP의 핵심(1:1 앵커+수동 보정+실시간 판정 3종 세트 완성). 유료 티어 킬러 기능 후보

**P3 — 보조 정렬**
9. 얼굴 중심 3점 평균 + 0.3mm 스냅, 좌우 중심 판정
10. 휴면 검수 시퀀스(phase 0~8 연출)는 이식 보류 — 기획 판단 (신뢰 연출 vs 속도)

## 5. 유의점

- 배치 엔진과 인터랙티브 엔진의 분리는 설계다 — 웹도 "자동 fit(서버) + 사용자 보정(클라)"의 2층으로 대응시키되 하나로 합치지 말 것
- Gemini 비전 검수(오늘 추가분)는 정본에 없는 신규층 — 정본 판정표가 이식되면 비전의 역할을 "코드 판정의 2차 확인"으로 재정의 필요 (판정 기준이 이중화되면 안 됨)
- 규격 DB: countries.jsonl에 명시 `faceTarget` 필드가 있는 문서(예: 베트남 비자 40)는 그 값이 최우선 — Task 2 병합에 이 필드 추가 병합 필요
