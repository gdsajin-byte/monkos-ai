## 3. 게이트 팝업 ↔ 프리뷰 이벤트 카드 역할 충돌 분석

### 두 이벤트의 비교

|------|-------------------|--------------------------|

| **노출 시점** | 다운로드 시도 시 | 생성 완료 후 항상 |

| **Firestore 플래그** | `events.sns_share` | `shareBonusClaimed` |
| **상호 배타** | ❌ 아님 — 완전 독립 | ❌ 아님 — 완전 독립 |

### 시간순 충돌

```
[비로그인] 생성 완료
    → 이벤트 카드 100c 노출 (이 시점에 이미 보임)
    → "다운로드" 클릭 → 게이트 팝업 등장
    → 게이트 팝업 닫기(X) 가능 → 이벤트 카드 여전히 노출
    → 이벤트 카드 클릭 → TG 봇에서 100c 수령 가능
    → 다시 "다운로드" → 게이트 → 로그인(30c) + SNS(40c) = 70c
    → 총 170c 확보 (게이트 닫지 않아도, 동선 중 접근 가능)

### 설계서와의 괴리

**설계서 (DESIGN_20260225)**: 이벤트 카드 100c 언급 **없음**. 설계서의 수지 모델은 게이트(30c+40c=70c)만 고려. 100c 이벤트 카드는 설계서 외부에서 추가된 것으로 판단.

// 이미지 메시지 수신 시 → userId 매칭 → shareBonusClaimed 체크 → 100c 지급
```

**부분 검증**: 텔레그램에 실제 이미지를 전송해야 지급. 하지만:
- 아무 이미지나 전송해도 100c 지급 (SNS 공유 스크린샷인지 미검증)
- 봇이 이미지 내용을 분석하지 않음

### `sns_share` vs `share-bonus` 이중 시스템

| | 게이트 sns_share (40c) | share-bonus (100c) |
|---|---|---|
| 서버 API | `/api/credits/event` | `/api/credits/share-bonus` 또는 TG 이벤트봇 |
| Firestore 필드 | `events.sns_share` | `shareBonusClaimed` |
| 상호 참조 | ❌ share-bonus 미확인 | ❌ events 미확인 |
| **둘 다 수령** | **가능** | **가능** |

**악용 시나리오**:
1. 가입 → 30c (`events.signup_bonus`)
2. 게이트에서 "텔레그램 공유" 클릭 (실제 공유 안 함) → 40c (`events.sns_share`)
3. 프리뷰에서 "텔레그램으로 100c 받기" → 아무 사진 전송 → 100c (`shareBonusClaimed`)
4. TG CS봇 친추 → 30c (`telegramBonusClaimed`)
5. **합계 200c = 2장+ 무료**

## 6. UI 텍스트 ↔ 실제 동작 불일치

### 6-1. "카카오 로그인 30c 증정" — 이벤트명 불일치

| UI 텍스트 | 실제 API eventType | 비고 |
|----------|-------------------|------|
| "카카오 로그인" | `signup_bonus` | 로그인이 아닌 **가입** 보너스. 기존 사용자 재로그인 시 지급되지 않음 |

사용자가 이미 가입된 상태에서 재로그인하면 `events.signup_bonus` 중복 체크에 걸려 30c 미지급. UI는 "로그인하면 30c"로 읽히지만 실제는 "최초 가입 시에만" → 혼동.

`result.js:221-224`:
```javascript
if (data.success) {
  updateGateUI(30);
} else {
  updateGateUI(Math.min(store.user.credits, 30));  // 이미 수령 시 현재 크레딧 표시
  Monk.log('가입 보너스: ' + (data.error || '이미 수령'));
}
```

이미 가입된 사용자의 경우 30c UI 업데이트가 `Math.min(store.user.credits, 30)`으로 됨 — 실제 보유 크레딧이 0c면 0c 표시, 30c 이상이면 30c로 **잘못 표시될 수 있음**.

### 6-2. "SNS 공유 또는 전후사진 동의 +40c" — 택1 명확성

게이트 UI (result.js:96-97):
```html
<span>SNS 공유 또는 전후사진 동의</span>
<span class="credit">+40c</span>
```

Phase 2에서 두 버튼이 모두 표시됨:
```html
<button>텔레그램 공유로 +40c 받기</button>
<button>전후사진 활용 동의 +40c</button>
```

서버는 택1 강제 (server.js:1552-1556):
```javascript
if ((eventType === 'sns_share' && events.photo_consent) ||
    (eventType === 'photo_consent' && events.sns_share)) {
  return { success: false, error: 'sns_share와 photo_consent는 택1입니다' };
}
```

**문제**: 하나를 완료한 후에도 다른 버튼이 여전히 활성화 상태. 클릭 시 서버에서 거부되지만, **클라이언트에서 실패 시 UI 피드백 없음** — `requestEventCredit()`이 `false` 반환 시 아무 동작 안 함.

### 6-3. "📥 고화질 다운로드 (70c)" — 잔액 부족 시 동작

`result.js:695-700`:
```javascript
if (store.user.credits < CREDIT_COST.download) {
  if (typeof window.showChargeModal === 'function') {
    window.showChargeModal();
  } else {
    showCreditModal(CREDIT_COST.download, store.user.credits, 'download');
  }
  return;
}
```

잔액 부족 시 충전 모달 표시 — 동작은 정상. 다만 버튼 텍스트 "70c"가 항상 고정이며, 잔액이 부분적으로 있는 경우 "부족분 Nc 충전 필요" 같은 안내 없음.

### 6-4. "다시 찍기" — 크레딧 미안내

`result.js:520-529`: `retakePhoto()` → camera.html 이동. 크레딧 차감 없음.
하지만 재생성 시 10c 차감 (로그인 사용자). **"다시 찍기"가 무료인 것처럼 보이지만, 결과적으로 재생성에 10c 발생** — UI에 미안내.

## 발견 사항 상세

### [F1] 직접결제 후 생성 이미지 소실 (P0)

- **파일**: `result.js:593` — `store.generated = genResult.image` (메모리 전용)

- **재현**: 비로그인 → 생성 → "바로 결제" → 결제 완료 → thankyou에서 "크롭 데이터 없음" → prep.html 리다이렉트

- **원인**: 각 이벤트 시스템이 서로 다른 Firestore 필드를 사용하여 상호 참조 없음
- **영향**: 최대 200c 무료 수령 → "첫 1장 무료" 위반
- **제안**: 이벤트 총량 캡(예: 최대 80c)을 서버에서 강제하거나, share-bonus(100c)를 게이트 이벤트와 통합
