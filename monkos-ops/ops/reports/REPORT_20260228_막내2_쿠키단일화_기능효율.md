### E4. credits.html 불일치

- googleLogin() 콜백 → localStorage 저장 제거, 쿠키가 서버에서 SET되므로 별도 저장 불필요

### E6. shared.js initCredits() 단순화 설계

**현재 (2-phase)**:
```
Phase 1: sessionStorage.getItem('monkos_user') → store.user 세팅 → return
Phase 2: fetch verify-cookie → store.user 세팅 → sessionStorage에 캐싱 → return
```

**쿠키 전용 (Phase 2만)**:
```javascript
export async function initCredits() {
  try {
    const res = await fetch(`${API.PORTAL_URL}/api/auth/verify-cookie`, {
      credentials: 'include',
    });
    if (res.ok) {
      const data = await res.json();
      if (data.user?.id) {
        store.user = {
          id: data.user.id,
          email: data.user.email,
          name: data.user.name || '',
          credits: data.user.credits ?? 0,
          avatar: data.user.picture || '',
        };
        Monk.log(`쿠키 인증: ${data.user.email} (${data.user.credits}c)`);
        return;
      }
    }
  } catch (e) {
    Monk.log('쿠키 인증 실패');
  }
  Monk.log('비로그인 상태');
}
```

- Phase 1 (sessionStorage) 전체 제거
- sessionStorage 캐싱 라인 제거
- fetchLatestCredits()에서 sessionStorage 갱신 코드 제거 (store.user만 갱신)

### E7. gate.js OAuth 흐름 분석

**현재 흐름**:
1. 팝업 윈도우 open → `${PORTAL_URL}/auth/kakao?popup=1`
2. 서버 OAuth 콜백에서 `Set-Cookie: monkos_session` + postMessage 발송
3. 부모 윈도우 `message` 이벤트 수신 → `sessionStorage.setItem('monkos_user', ...)` + `store.user` 세팅

**쿠키 전환 시**:
- **Step 2**: 서버에서 `Set-Cookie` → 그대로 유지 (이미 구현됨)
- **Step 3**: `sessionStorage.setItem` → **제거**. `store.user` 세팅만 유지
- postMessage는 **여전히 필요**: 팝업에서 부모 윈도우로 사용자 정보 전달 → `store.user` 세팅 + UI 업데이트
- 즉, postMessage의 역할이 "sessionStorage 저장" → "store.user + UI 업데이트"로 변경

**3곳 동일 패턴** (gate.js에 3개의 OAuth 핸들러):
- `_startKakaoLogin` (줄 98-114): postMessage → sessionStorage SET → store.user
- `_startKakaoLoginSimple` (줄 432-447): 동일 패턴
- `_startLineLoginSimple` (줄 460-475): 동일 패턴

모두 sessionStorage 줄 1줄씩 제거, token SET 1줄씩 제거 → **6줄 제거, 로직 변경 없음**
