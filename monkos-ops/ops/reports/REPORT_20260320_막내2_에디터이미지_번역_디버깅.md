## 버그 A: 이미지 2중 삽입 — 원인 확정 및 수정

### 원인 1: 드래그 앤 드롭 이중 처리
- **파일**: `monkos_AI/portal/public/admin/blog-edit.html` (구 line 1031)
- **문제**: drop 핸들러가 **버블링 페이즈**에서 이벤트를 잡음. ProseMirror(Toast UI 내부 엔진)가 먼저 drop 이벤트를 처리하여 `text/plain` 데이터(`![name](url)`)를 삽입하고, 이후 우리 커스텀 핸들러도 `editor.exec('addImage')`를 실행 → **2장 삽입**
- `e.preventDefault()`만 호출하고 `e.stopPropagation()` 미호출 → ProseMirror 전파 차단 실패

### 원인 2: insertImage() 연속 호출 미방어

## 버그 B: 이미지 삭제 시 에디터 깨짐 — 원인 확정 및 수정

### 원인: ProseMirror DOM 직접 조작
- **파일**: `blog-edit.html` (구 line 937-943)
- **문제**: `img.parentElement?.remove()` — Toast UI Editor의 WYSIWYG 모드는 ProseMirror 기반. ProseMirror가 관리하는 DOM을 외부에서 직접 삭제하면 내부 상태(doc state)와 실제 DOM이 불일치
- **결과**: 모드 전환(WYSIWYG ↔ 마크다운) 시 삭제된 이미지가 부활하거나, 깨진 HTML이 생성되어 에디터 레이아웃 붕괴

### 수정 내용
```diff
  { label: '🗑 삭제', action: () => {
    if (confirm('이 이미지를 삭제하시겠습니까?')) {
-     img.parentElement?.remove() || img.remove();
-     updatePreview();
+     // 에디터 API 경유: 마크다운에서 해당 이미지 제거 후 전체 갱신
+     const md = editor.getMarkdown();
+     const imgSrc = img.src;
+     const escapedSrc = imgSrc.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
+     const newMd = md.replace(RegExp(`![...](${escapedSrc})\n?`), '');
+     // fallback: URL path만으로 매칭 시도
+     editor.setMarkdown(newMd);
+     updatePreview();
    }
  }}
```

**핵심**: DOM 직접 조작 → `editor.getMarkdown()` + 정규식 제거 + `editor.setMarkdown()` 전환. ProseMirror 상태와 DOM이 항상 정합.
