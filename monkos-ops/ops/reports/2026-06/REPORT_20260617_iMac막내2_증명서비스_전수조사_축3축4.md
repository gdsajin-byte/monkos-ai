### 4-2. 코드 중복 분석

#### idphoto-kr vs idphoto-jp (90%+ 동일)

**동일한 것:**
- 전체 아키텍처, import, 인증 로직 (`verifySessionToken`, `getSessionCookie`)
- 크레딧 API 헬퍼 (`useCredits`, `refundCredits`)
- IDENTITY_PRESERVATION 프롬프트 — 글자 그대로 동일
- BG/CLOTHING/CLOTHING_COLOR/TIE/EXPRESSION/HAIR_PROMPTS — 전부 동일
- `buildPromptV5()` — 완전 동일
- API 라우트 구조, WebSocket 코칭 핸들링, 보안 헤더

**다른 것 (i18n + KR 크롭 deprecation):**

| 항목 | idphoto-kr | idphoto-jp |
|------|-----------|-----------|
| COACHING_INSTRUCTIONS | 한국어 | 일본어 |
| 코칭 ready 정규식 | 한국어 패턴 | 일본어 패턴 |
| PRE_CHECK_INSTRUCTION | 한국어, 60점 통과 | 일본어, 70점 통과, 8항목 |
| PRECHECK_MODELS | 2개 폴백 (flash + flash-lite) | 1개 (flash만) |
| 서버사이드 크롭 | deprecated (주석화) | **활성** (detectFace + cropToSpec) |
| SEO 랜딩 | 없음 | 5개 (/guide/*, /specs/*) |

#### 레거시 CF idgen.js vs 현행 idphoto-kr

| 항목 | CF idgen.js (레거시) | idphoto-kr (현행) |
|------|---------------------|------------------|
| 런타임 | CF Workers | Express (Cloud Run) |
| 프롬프트 | **구 3필드** (style, gender, age) | **v5 9필드** (buildPromptV5) |
| 크레딧 | 없음 (무인증/무과금) | Portal API 경유 |
| GCS 저장 | 없음 | 있음 |
| 워터마크 | 없음 | sharp 기반 |
| 인증 | 없음 | HMAC 세션 토큰 |

**결론**: CF idgen.js는 초기 프로토타입. v5 9필드 체계로 완전 대체. `_functions_backup_20260220/`은 순수 아카이브.

#### 인증 토큰 검증 3중 복제

`verifySessionToken()` 함수가 idphoto-kr, idphoto-jp, portal 세 곳에 동일 코드로 복제. 공유 모듈 부재.

#### 크레딧 정본 단일 (건강)

크레딧 비즈니스 로직은 Portal(`lib/credits.js`) 한 곳에만 존재. idphoto 서비스들은 Portal API에 HTTP 위임. 이 구조는 건강.
