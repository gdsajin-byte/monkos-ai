## 3. ⚠️ 후속 보강 (severity순)

### 🔴 F1 — 결제 region이 geoip 아닌 "언어 파생" (설계 미반영)
- `region = lang==='ko' ? 'kr' : 'global'` 3곳 하드코딩(`render-shell.js:158`, `home.js:218`, `render-headshot.js:341`). **geoip-lite 미구현.**
- credits.js가 이 region으로 토스(kr)/LINE·카드(global) 분기(`credits.js:38`).
- → **2축 분리 결정 미반영.** 시나리오3(미국 거주 한국어 유저: lang=ko→region=kr→토스인데 해외카드) 미해결.
- **조치**: geoip-lite 도입(설계대로) 또는 최소한 **결제창에서 통화/수단 사용자 override** 제공. 의도된 phase-1 stopgap인지 쌍아 확인.

### 🟡 F2 — `Vary: Accept-Language` 헤더 부재 (캐싱/SEO)
- 무접두사 URL(`/` 등)이 Accept-Language/쿠키로 다른 언어를 같은 URL에 dynamic serving하는데 `Vary` 없음 → CDN/프록시 도입 시 잘못된 언어 캐싱 + 구글 dynamic-serving 가이드 위반.
- **조치**: 무접두사 라우트 응답에 `Vary: Accept-Language` 추가.

### 🟡 F3 — 무접두사 `/`가 비-ko 렌더 → canonical/hreflang 불일치
- 쿠키=ja 유저가 `/` 방문 시 URL=`/`인데 콘텐츠=일본어. hreflang x-default(ko)·canonical과 URL↔콘텐츠 불일치. Googlebot이 Accept-Language=en로 크롤 시 `/`에서 영어 수신 가능.
- **조치**: 무접두사 URL은 **크롤러/무쿠키엔 ko 고정(x-default)** 유지, 사용자 언어 전환은 `/ja`·`/en` 경로로 유도. 강제 리다이렉트는 금지 유지(현행 OK).

### 🟢 F4 — 정적 자산 GET에도 detectLang+Set-Cookie 실행
- 언어 감지 블록이 라우팅 이전이라 `.css/.js/이미지` 요청에도 실행 → 불필요 오버헤드 + 자산 캐시 방해 가능. **조치**: 정적 경로는 스킵.

### 🟢 F5 — 언어 스위처가 현재 페이지 대신 홈으로 이동
- `setLang`(i18n.js)이 항상 `/` 또는 `/${lang}/`(홈)로 이동. `/specs`에서 전환 시 `/ja/`(홈)로 가 현재 페이지 컨텍스트 상실. **조치**: 현재 경로 → 언어 prefix 등가 경로 매핑.

### 🟢 F6 — 구 `monkos_region` 쿠키 orphan
- 더 이상 set/사용 안 함(monkos_lang+파생 region으로 대체). 잔존 쿠키 무해하나 정리 권장.
