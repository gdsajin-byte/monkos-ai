# 전략 보고서 — 발행은 "구글에 전화 1통"이 아니라 "유통 팬아웃"이어야 한다

> **[2026-06-15 09:24 KST] 웹/민아 → 작가님, iMac/쌍아**
> 작가님 지시(③경로): "발행이 구글사에만 알리는 로직인데 더할 여지 — 네이버·각국 메인·AI팀에도. 발행부터 실측 로드맵까지 업계 최전선 수준으로."
> 방법: 코드 실측(현행 발행 플로우) + 웹 리서치 10축(IndexNow·Bing·Google Indexing API·WebSub·AI크롤러·AEO/GEO·구조화데이터·sitemap·네이버 C-Rank·신디케이션).

---

## 0. 한 줄 결론
지금 발행은 **"구글에 (구글이 안 받는) 전화 1통"**이다. 최전선은 **하나의 발행 이벤트 → 다섯 검색엔진(IndexNow) + AI 검색(Bing 경유) + 구조화데이터 + 신디케이션으로 팬아웃**한다. 가장 강한 단일 추가분은 **IndexNow**(네이버·빙·얀덱스·Seznam·Yep 동시 + ChatGPT/Perplexity 간접) — 그리고 **specs 카탈로그까지 확장**이 어제 "색인 복구 P0"의 실행 무기다.

---

## 1. 현행 발행 프로세스 (코드 실측 — `lib/cms/blog.js`)
작가님이 발행을 누르면 `published:true`로 저장되며 다음이 돈다:
1. **Firestore 플래그 ON** (`blog_posts/{slug}.published=true`) — 동적 렌더라 즉시 사이트·sitemap.xml·llms.txt에 등장(재빌드 없음).
2. **OG 이미지 생성** (`generateOgImage`) — SNS 공유 카드.
3. **구글 Indexing API 통지** (`requestIndexing` → `indexing.googleapis.com/v3/urlNotifications:publish`, 일 200 쿼터).
4. **한국어 원본이면 백그라운드 체이닝**: JA·EN 자동번역(`translateAndSaveBlogPost`) → **GitHub Issues 게시**(`publishBlogToGitHub`, SPREAD 트리거).

> 현 자산: robots.txt에 AI봇 다수 등재(GPTBot·ChatGPT-User·ClaudeBot·PerplexityBot·Google-Extended·Naverbot 등), llms.txt 58행, sitemap 동적(1,584 URL).

---

## 2. 핵심 진단 — 현행의 3가지 구멍
1. 🔴 **구글 Indexing API는 우리 콘텐츠에 "헛스윙"**: 공식적으로 **JobPosting·BroadcastEvent 전용**. 블로그·specs는 비대상 → 구글이 통지를 사실상 무시. (관행상 던지는 사이트 많으나 효과 불확실, Google도 권장 안 함)
2. 🔴 **유통이 구글 단일채널**: 네이버·빙·얀덱스·AI 검색에 능동 통지 0. KR 주력인데 **네이버에 발행 통지를 안 한다**(sitemap 수동 의존).
3. 🟡 **구글 sitemap ping 폐기됨**(2023~): 익명 ping 죽음 → 구글은 **sitemap(GSC 등록) + 크롤**이 정도. 우리 sitemap은 단일 1,584(어제 보고서: 색인 302, 19%).

## 3. 업계 최전선 유통 메커니즘 지도 (리서치 종합)

### A. 능동 통지 (Push — "전화 거는" 채널)
| 메커니즘 | 커버리지 | 용량/속도 | 우리 적용 |
|---------|---------|----------|----------|
| **IndexNow** ⭐ | **Bing·Yandex·Naver·Seznam·Yep** (1콜 전파) | **1만 URL/POST, 수 분 내** | ❌ → **P0 신규** |
| Bing URL Submission API | Bing(+ChatGPT/Copilot 간접) | 1만/일 | IndexNow로 충분(중복), 보조 |
| Google Indexing API | 구글 — **JobPosting/BroadcastEvent 전용** | 200/일 | 현재 헛스윙 → 정리 |
| WebSub(PubSubHubbub) | RSS 구독 생태계 실시간 푸시 | 즉시 | P2 후보(RSS 보유 시) |
| ~~구글 sitemap ping~~ | — | **폐기됨** | 제거 |

> **구글은 IndexNow를 안 받는다**(2026.2 현재 유일한 예외). 구글 정도 = **sitemap + GSC**.

### B. 수동/패시브 발견 (Pull — "발견되게 두는" 채널)
- **Sitemap 정석**: 5만 URL·50MB/파일 한계 → **sitemap index 분할**. **lastmod 정확성**이 신뢰의 핵심(우리 `today` 박제 = 신뢰 훼손, 어제 지적). canonical·indexable URL만, robots.txt와 정합.
- **News sitemap**(48시간 내 기사만)·**Image sitemap**(JS 레이지로딩 이미지 발견) 확장 가능.
- **웹마스터 등록 3종**: GSC · **네이버 서치어드바이저** · Bing WMT — sitemap 제출 + 수집요청.

### C. AI/생성형 검색 레이어 (AEO/GEO — 2026 신규 유통)
> AI 검색 방문 YoY **+42.8%**(15.6억→27.4억/분기). AI Overviews가 구글 검색의 **~55%**에 노출. 인용 페이지는 비인용 대비 **클릭 +35%**.
- **ChatGPT Search·Copilot = Bing 인덱스 기반** → **IndexNow로 Bing에 넣는 것이 곧 ChatGPT 유통.** (우리 chatgpt 유입 15명이 그 증거)
- **Perplexity**: Bing 주 소스 + **신선도 가중**(30일 내 발행 글 82% 인용). → 발행 빈도·갱신일이 곧 인용률.
- **Google AI Overviews**: **상위 10위 오가닉 기반** + 스키마로 사실 검증 → 오가닉 순위가 AI 노출의 전제.
- **AI 크롤러 3봇 체계**: GPTBot(학습) / **OAI-SearchBot(검색 인덱싱)** / ChatGPT-User(사용자 요청). **검색봇 허용이 인용 가시성** — robots.txt 점검 필요(우리 OAI-SearchBot 명시 여부 확인 대상).
- **구조화데이터(JSON-LD)**가 LLM grounding·환각 감소·출처 신뢰 평가에 사용 → 2026엔 **더** 중요. (단 FAQ 리치결과는 2026.5.7 종료, **그래도 AI/음성은 FAQ 스키마를 계속 사용**)
- **커뮤니티 인용 가중**: **Reddit**이 Perplexity 최다 인용·SearchGPT/AI Mode 톱3 도메인.

### D. 신디케이션 (멀티채널 배포 — 이미 PF_SPREAD)
- 1차 = 자기 도메인(canonical·RSS·OG·JSON feed) → **canonical 태그로 중복 회피**하며 Medium·LinkedIn·X·note 크로스포스팅(지연 1~3일).
- 우리 현행 GitHub Issues 게시 = SPREAD 씨앗. DISTRIBUTION_SCHEMA(R1~R6)·백카탈로그 로드맵(PROPOSAL 06-12)과 연결.

### E. 네이버 생태계 (KR 특수 — 주력 시장)
- **C-Rank**(콘텐츠 신뢰·**외부 유입/공유량**·체류) + **D.I.A**(검색 의도) 알고리즘. **체류 3분+ → 순위 평균 +5단계.**
- **네이버 Cue**(AI 검색) 부상 → 네이버向 AEO.
- 통지: **IndexNow 지원**(2026 합류) + 서치어드바이저 sitemap + 웹페이지 수집요청.

| 채널 | 최전선 표준 | 우리 현재 | 갭 |
|------|------------|----------|----|
| 구글 | sitemap(분할·정확 lastmod)+GSC | 단일 sitemap 1,584·lastmod today·Indexing API 헛스윙 | 🔴 sitemap 재정리 |
| 네이버·빙·얀덱스 | IndexNow 1콜 | 없음 | 🔴 IndexNow 신규 |

## 5. 실측 로드맵 (Phased — 각 단계 검증 포함)

### Phase 0 — IndexNow 파이프라인 + 구글 정도화 (P0, 가장 싸고 즉효)
- **IndexNow 구현**: 루트 키파일(`{key}.txt`) 배치 → 발행/갱신 시 `api.indexnow.org` POST. **블로그 + specs 전 카탈로그**(1만 URL/POST) 대상.
- **구글 Indexing API 호출 정리**: 블로그/specs엔 비대상 → 의존 제거(또는 JobPosting 한정 유지), 구글은 **sitemap+GSC**로 일원화.
- **sitemap 재정리**(어제 제안 연동): index 분할(static/specs/blog·언어별) + **실 lastmod** + specs 정본 monkos.ai 통일.
- **웹마스터 3종 점검**: GSC·네이버 서치어드바이저·Bing WMT sitemap 등록 확인.
- ✅ 검증: IndexNow 200 응답 로그, Bing WMT "제출됨" 카운트, 네이버 수집현황, 1~2주 색인수 302→상승 추적.

### Phase 1 — AI/AEO 레이어 (P1)
- **JSON-LD 전면**: 블로그=Article/BlogPosting, specs=HowTo/Product(또는 정의형), 전역 Organization·BreadcrumbList·FAQPage(AI·음성용).
- **llms.txt 강화** + **robots.txt 검색봇 허용 점검**(OAI-SearchBot·PerplexityBot·ClaudeBot 명시 allow, 학습봇은 정책 선택).
- **신선도 루프**(Perplexity 30일): specs·핵심 글 갱신일 실 반영 → 재인용.
- ✅ 검증: Rich Results Test 통과, GSC Enhancements, AI 인용 출현(chatgpt/perplexity 유입 추적).

### Phase 2 — 신디케이션 + 실시간 푸시 (P2)
- canonical 크로스포스팅(Medium/LinkedIn/X/note) 자동화 — PF_SPREAD DISTRIBUTION_SCHEMA·백카탈로그 로드맵 인입.
- **WebSub**(RSS 실시간 푸시) — 구독 생태계·뉴스리더 패시브 확산.
- **Reddit·커뮤니티** 시드(Perplexity 최다 인용) — R5 절단선(allowlist·계정) 해소 연동.
- ✅ 검증: UTM 환류, 레퍼럴 채널 증가.

### Phase 3 — AEO 측정·자동화 (P3)
- AI 인용 추적(어느 질의에 우리가 인용되는지) + 발행→색인 리드타임 KPI화.
- 발행 팬아웃을 Routines/AUTOPILOT에 편입(자가 진단·자가 통지).

| 층 | 지표 | 현재 | 목표 방향 |

## 7. 리스크 · 비범위
- **구글은 IndexNow 미지원** — IndexNow는 *추가*지 구글 대체 아님. 구글은 sitemap 정공법.
- **AI는 직접 핑 없음** — Bing 인덱스·llms.txt·스키마로 *먹이는* 것(간접). 과대약속 금지.
- 신디케이션은 **canonical 필수**(중복 콘텐츠 리스크).
- 본 보고는 **유통·색인 인프라**. 콘텐츠 품질·전환(과금)·specs 무료유틸은 별 보고서(어제 2건)와 묶음.
- 실행은 쌍아 설계→막내. 본 보고는 진단·로드맵까지(민아 레인).
