# 포털 언어 분기 시스템 정밀 분석

> **[2026-06-22 10:40 KST] 웹/민아 → 작가님, 쌍아**
> 작가님 제보: "일본/미국으로 들어가도 내부 페이지 갔다가 메인으로 오면 다시 한국어로 뜬다." 코드 실측 근거.

---

## 1. 결론 (한 줄)

**언어가 URL 경로(`/ja`, `/en`)에만 존재하는데, 공용 헤더 `layoutNav()`가 언어 인자를 안 받고 모든 링크를 무접두사(=한국어)로 하드코딩한다.** → 내부 페이지에서 로고·네비를 누르면 한국어 페이지로 떨어진다.

## 2. 언어 분기 아키텍처 (실측)

- **방식 = 순수 경로 기반(path-based)**. 무접두사=한국어(기본), `/ja/*`=일본어, `/en/*`=영어. (`server.js:357-399`)
- **지속(persistence) 레이어 없음** — 쿠키·세션·localStorage 없음. 언어는 오직 현재 URL에만 존재.
- **Accept-Language 감지 없음** (홈 `/`). 유일한 사용처는 `/app` 리다이렉트뿐 (`server.js:342-343`). → 일본/미국 첫 방문자가 `monkos.ai/`로 와도 **무조건 한국어**.
- hreflang은 페이지별로 정상 출력됨(`render-blog.js`·`render-pricing.js`) — SEO는 OK, 문제는 온페이지 네비.

## 3. 근본원인 (3중)

### 🔴 A. 공용 헤더 `layoutNav()` 언어 미지원 (주범)
`render-shell.js:127-141` — `layoutNav()`는 **인자가 없고** 링크가 전부 하드코딩:
```
<a href="/" class="logo">           // 항상 한국어 홈
<a href="/blog">  <a href="/faq">   // 전부 무접두사 = 한국어
<a href="/gallery"> ... <a href="/pricing">
```
호출처 전부 인자 없이 호출 — `render-pricing.js:259`, `render-board.js:98`, `render-static.js:128·245`, `render-headshot.js:291`, `layoutShell`(`render-shell.js:159`).
→ **JA/EN 내부 페이지(예 `/ja/specs`)의 헤더도 한국어 링크**. 로고/네비 클릭 시 `/`(한국어)로 이탈. **= 제보된 버그 그 자체.**

### 🟡 B. 지속 레이어 부재
경로에만 언어가 있어, 무접두사 링크를 한 번 누르면 언어 단서가 영구 소실. 쿠키/Accept-Language가 없어 복구 불가.

### 🟡 C. 메커니즘 이원화 (불일치)
- 홈(`home.js:184`)은 **자체 언어 인식 네비**(`item.label[lang]`, 접두사 반영) 보유 → 홈 네비는 정상.
- 그러나 내부 페이지는 공용 `layoutNav()`(A) 사용 → 불일치. "홈은 되는데 내부 갔다 오면 깨짐"의 원인.
- 별도로 crop 도구(`crop/crop.js:133`)는 `localStorage['monkos_lang']` 사용 — 포털 경로 방식과 또 다른 3번째 메커니즘.

## 4. 버그 재현 흐름
1. `/ja`(홈) 진입 → 홈 자체 네비(정상, JA 링크).
2. Specs 클릭 → `/ja/specs` (정상 렌더, but 헤더는 `layoutNav()` 한국어).
3. 로고 또는 네비 클릭 → `/` 또는 `/blog`(**한국어**)로 이동. **언어 리셋.** ✅ 제보 일치.

## 5. 수정 권고

### P0 — `layoutNav(lang)` 언어 인자화 (버그 직접 해소)
- `layoutNav(lang='ko')`로 변경, 접두사 헬퍼 `p = lang==='ko' ? '' : '/'+lang` 적용:
  로고 `href="${p}/"`, 네비 `href="${p}/blog"` 등. 라벨도 lang별.
- 호출처 6곳에 현재 lang 전달. `layoutShell`은 이미 `htmlLang` 보유 → 그대로 넘김.

### P1 — 언어 지속 + 첫 방문 감지
- 언어 선택/진입 시 쿠키(`monkos_lang`) 기록 → `/` 접근 시 쿠키 우선, 없으면 Accept-Language로 `/ja`·`/en` 302. (국제 방문자 첫 화면 한국어 문제 해소)
- crop의 localStorage 방식과 쿠키 단일화 검토.

### P2 — 언어 스위처 UI
- 헤더에 KO/JA/EN 토글 추가(현재 없음). hreflang은 있으나 사용자 수동 전환 수단 부재.

## 6. 영향·우선순위
- P0는 **국제 사용자 이탈 직결**(영어권 headshot 전략의 전제 — JA/EN 진입자가 한국어로 튕김). 사진 플랫폼 글로벌 전환과 직결되므로 최우선.
- 수정 규모: P0 = `render-shell.js` 1파일 + 호출처 6곳 lang 전달(막내 1건). P1·P2 후속.

## 7. 인계
- 쌍아: P0 막내 지시서(layoutNav 언어 인자화 + 호출처 lang 전달). P1 쿠키/Accept-Language 설계.
- 검증: 수정 후 `/ja/specs`→로고→`/ja` 유지, `/en/blog`→네비→`/en/*` 유지 확인.
