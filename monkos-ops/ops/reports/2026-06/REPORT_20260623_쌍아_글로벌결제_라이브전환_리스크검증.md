## 🔴 리스크 1: Webhook Signing Secret — 스토어별 분리 필요

### 경위

쌍아 직전 세션 판정: "API Key/Webhook Secret은 계정 단위 공유 → 분리 불필요"

민아 검증 결과: **API Key는 계정 공유 맞지만, Webhook Signing Secret은 스토어별 발급. 쌍아 판정 일부 오류.**

### 코드 실태

| 파일 | 라인 | 현황 | 문제 |
|------|------|------|------|
| `lib/shared/config.js` | 23 | `LEMONSQUEEZY_WEBHOOK_SECRET` 단일 env | JP↔글로벌 구분 없음 |
| `lib/payments.js` | 80-88 | `createHmac('sha256', LEMONSQUEEZY_WEBHOOK_SECRET)` | 글로벌 webhook 서명 불일치 시 401 → **크레딧 미적립** |
| `deploy.sh` | 152 | `--set-secrets`에 `LEMONSQUEEZY_WEBHOOK_SECRET` **미포함** | 콘솔 직접 설정 추정, 현재 값 = JP용 가능성 |
| `lib/shared/config.js` | 28 | `AUTH_SECRET \|\| LEMONSQUEEZY_WEBHOOK_SECRET` 폴백 | webhook secret 교체 시 AUTH_SECRET 독립 확인 필요 |

### 사고 시나리오

```
글로벌 스토어(415328) 라이브 → 유저 USD 결제 → 레몬 webhook 발송
→ 포털 payments.js HMAC 검증 (JP용 secret으로)
→ 서명 불일치 → 401 반환
→ 크레딧 미적립 → 유저 결제만 되고 서비스 이용 불가
```

### 대응 (라이브 전환 시 필수)

1. 레몬 글로벌 스토어(415328) 대시보드 → Settings → Webhooks → signing secret 발급
2. `secret add LEMONSQUEEZY_WEBHOOK_SECRET` — 글로벌 값으로 교체 (JP 스토어 폐기 전제)
3. `deploy.sh` L152에 `LEMONSQUEEZY_WEBHOOK_SECRET=LEMONSQUEEZY_WEBHOOK_SECRET:latest` 추가
4. AUTH_SECRET 독립 설정 확인 (webhook secret 교체 시 인증 토큰 서명에 연쇄 영향 없는지)
5. 배포 후 test webhook으로 HMAC 검증 통과 확인

> JP 스토어 병행 운영 필요 시: 듀얼 시크릿 분기 코드 필요. 현재 설계는 글로벌 단일 전환 전제.
