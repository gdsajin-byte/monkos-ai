## 임무 A: 챗봇 클라이언트 현재 상태 분석

### 대상 파일
- `monkos_AI/idphoto-kr/public/modules/chatbot.js` (222줄)
- `monkos_AI/idphoto-jp/public/modules/chatbot.js` (222줄)

### 두 파일의 실질적 차이점

| 항목 | KR | JP |
|------|----|----|
| `lang` 파라미터 | `'ko'` | `'ja'` |
| `channel` 파라미터 | `'idphoto-kr'` | `'idphoto-jp'` |
| 초기 메시지 | "안녕하세요! MONKOS AI 증명사진 서비스에 대해 궁금한 점을 물어보세요." | "こんにちは！MONKOS AI証明写真サービスについてお気軽にお問い合わせください。" |
| 닫기 버튼 aria-label | "닫기" | "閉じる" |
| placeholder | "메시지를 입력하세요..." | "メッセージを入力してください..." |
| 에러 메시지 (API 실패) | "죄송합니다. 잠시 후 다시 시도해주세요." | "申し訳ございません。しばらくしてからもう一度お試しください。" |
| 에러 메시지 (네트워크) | "네트워크 오류가 발생했습니다. 잠시 후 다시 시도해주세요." | "ネットワークエラーが発生しました。しばらくしてからもう一度お試しください。" |
| 파일 주석 | 정상 | ⚠️ "idphoto-kr 전 페이지" 그대로 (복사 잔재) |

**로직·CSS·DOM 구조·이벤트 바인딩은 100% 동일.**

### 초기 메시지
- KR: 한국어 인사 + 서비스 안내
- JP: 일본어 인사 + 서비스 안내
- 양쪽 모두 단일 정적 텍스트. 동적 빌드 없음

### 메시지 플로우 (KR/JP 공통)
```
사용자 입력 → _sendMessage()
  → fetch(${API.PORTAL_URL}/api/chat, POST)
    body: { message, sessionId, lang, channel }
  ← { reply, sessionId } (또는 { message })
  → _addMessage(reply, 'bot')
```
- `API.PORTAL_URL` = `https://monkos.ai` (프로덕션) — KR/JP 공통 동일 포털
- 응답에서 `data.reply || data.message` 순으로 폴백

### sessionId 생성 방식
```js
let _sessionId = `idphoto_${Date.now()}_${Math.random().toString(36).slice(2, 8)}`;
```
- 페이지 로드 시 1회 생성, 탭 닫으면 소실
- 서버가 `data.sessionId`를 내려보내면 갱신 (Firestore 복원용)
- KR/JP 동일한 `idphoto_` 접두사 — 구분 불가 (관리 이슈 가능)

### 에러 처리 현황
- `try/catch`로 fetch 실패만 처리
- **타임아웃 처리 없음** — 서버 응답이 늦어도 무한 대기
- **HTTP 상태 코드 미확인** — `res.json()` 성공하면 200이든 500이든 reply 시도
- 네트워크 오류 시 정적 메시지 출력

### UI 트리거 방식
1. **index.html**: `#logoChatTrigger` (로고 영역) 클릭 → `toggleChat()`
2. **camera/result/thankyou/charge 페이지**: `#header h1` 클릭 → `toggleChat()`
3. 백드롭 클릭 → 닫기
4. 닫기 버튼(×) → 닫기
5. index.html에서 `#logoBubble` 말풍선 숨김 처리 포함

## 임무 B: Portal 챗봇 엔진 분석

### 대상 파일
- `monkos_AI/portal/lib/chat-engine.js` (273줄)
- `monkos_AI/portal/lib/prompts.js` (242줄)
- `monkos_AI/portal/lib/coaching.js` (96줄)
- `monkos_AI/portal/lib/rag.js` (44줄)

### KR/JP channel 분기 처리 방식

**CHANNEL_CONFIG 등록 현황:**

| 채널명 | 시스템 프롬프트 | temperature | maxOutputTokens | 상태 |
|--------|---------------|-------------|----------------|------|
| `web` | SYSTEM_PROMPT (일본어) | 0.7 | 300 | ✅ |
| `telegram` | CS_SYSTEM_PROMPT (일본어) | 0.5 | 500 | ✅ |
| `prep` | PREP_SYSTEM_PROMPT (한국어) | 0.6 | 400 | ✅ |
| `coaching` | COACHING_INSTRUCTIONS (한국어) | 0.3 | 50 | ✅ |
| `qc` | 동적 생성 | 0.2 | 300 | ✅ |
| `kakao` | SYSTEM_PROMPT + 카카오 추가 | 0.7 | 300 | ✅ |
| `idphoto-kr` | SYSTEM_PROMPT_KR (한국어) | 0.7 | 300 | ✅ |
| **`idphoto-jp`** | — | — | — | **❌ 미등록** |

> **CRITICAL: `idphoto-jp` 채널이 CHANNEL_CONFIG에 존재하지 않음.**
> JP 챗봇이 `channel: 'idphoto-jp'`를 전송하면 `chatWithMonkos()`에서
> `throw new Error('Unknown channel: idphoto-jp')` → `handleWebChat()`에서 500 반환
> → 사용자에게 "ネットワークエラーが発生しました" 표시

### 현재 사용 중인 AI 모델
```js
model: 'gemini-2.0-flash'
```
- **Gemini 2.0 Flash** — 전 채널 동일 (Claude 아님)
- stateless 채널(coaching/qc)과 stateful 채널(web/telegram/kakao/idphoto-kr) 모두 동일 모델

### 시스템 프롬프트 내용

#### SYSTEM_PROMPT (web/kakao 채널 — 일본어 기반)
- 자기소개: "モンコス" (MONKOS AI 공식 어시스턴트)
- 서비스 안내: JP + KR 양쪽 URL 포함
- 크레딧 시스템: 가입 10c, 리터칭 10c, 다운로드 70c, SNS 100c, 텔레그램 40c
- **가격 정보 (글로벌 LS)**: `10c/$10 | 30c/$25 | 50c/$40` ← ⚠️ 현행 JP 가격과 불일치
- 결제: Toss(한국) / Lemon Squeezy(글로벌)
- 응답 정책: 3단계 (서비스→사진일반→무관)
- 언어: 사용자 언어에 맞춰 응답

#### SYSTEM_PROMPT_KR (idphoto-kr 채널 — 한국어 전용)
- 자기소개: "몽코스"
- 서비스: KR URL만 (idphoto-kr.monkos.ai)
- 크레딧: KR 가격표 (₩9,900 1장팩 등) — **config.js와 일치**
- 카카오 채널 보너스 40c 포함
- "반드시 한국어로 응답" 지시

#### CS_SYSTEM_PROMPT (telegram — 일본어 기반)
- 고객지원 전용. 환불 정책, 에스컬레이션 안내 포함
- 문화적 배려 지시 (일본어=경어, 한국어=존댓말, 영어=전문적 톤)
- 로그인 안내: 카카오(한국), LINE(일본), Google

### 대화 히스토리 관리 방식

| 구분 | 저장소 | TTL | 최대 히스토리 |
|------|--------|-----|-------------|
| **인메모리** (chatHistories) | Map() | 30분 | 20턴 |
| **인메모리** (csHistories) | Map() | 60분 | 20턴 |
| **Firestore** | 채널별 컬렉션 | 90일 | 40턴 (trim) |

- `chatHistories`는 web/kakao/idphoto-kr이 공유
- `csHistories`는 telegram 전용
- Firestore 컬렉션 매핑:
  - web → `chat_conversations`
  - kakao → `kakao_conversations`
  - idphoto-kr → `idphoto_kr_conversations`
  - prep → `prep_conversations`
  - **idphoto-jp → 미등록 (CHANNEL_COLLECTION_MAP에도 없음)**
- 세션 복원: `web` 채널만 Firestore에서 히스토리 복원 (`loadChatHistory`)

### 응답 스트리밍 여부
- **스트리밍 없음**. `ai.models.generateContent()` 단발 호출 → 전체 텍스트 한 번에 반환
- 클라이언트에서도 typing indicator만 표시, 스트리밍 수신 없음

### RAG (검색 증강 생성)
- Firestore `cs_knowledge` 컬렉션에서 지식 로드 (10분 캐시)
- 키워드 매칭 기반 검색 (TF-IDF나 임베딩 없음)
- stateful 채널에서만 RAG 적용 (coaching/qc는 stateless → RAG 미적용)

## 임무 C: 업데이트 필요 항목 도출

### 1. ❌ JP 챗봇 채널 미등록 (CRITICAL)

**현상**: `idphoto-jp` 채널이 chat-engine.js CHANNEL_CONFIG에 없음
**영향**: JP 사용자가 챗봇을 사용하면 100% 에러
**필요 작업**:
- CHANNEL_CONFIG에 `'idphoto-jp'` 채널 추가
- JP 전용 시스템 프롬프트 (`SYSTEM_PROMPT_JP`) 신규 작성
- CHANNEL_COLLECTION_MAP에 `'idphoto-jp': 'idphoto_jp_conversations'` 추가

### 2. ⚠️ JP 가격/크레딧 정책 불일치 (HIGH)

**현상**: SYSTEM_PROMPT(web)의 글로벌 LS 가격이 현행 JP 가격과 불일치

| 항목 | SYSTEM_PROMPT 기재 | JP config.js 실제 |
|------|-------------------|------------------|
| 10c | $10 | ¥150 |
| 30c | $25 | 없음 |
| 50c | $40 | 없음 |
| 70c+10 bonus | 없음 | ¥990 |
| 100c+30 bonus | 없음 | ¥1,490 |
| 300c+120 bonus | 없음 | ¥3,990 |
| 500c+250 bonus | 없음 | ¥5,990 |

**필요 작업**: JP 전용 프롬프트에 현행 ¥ 가격표 반영

### 3. ⚠️ JP 결제 방식(LS) 관련 챗봇 안내 (MEDIUM)

**현상**: web 채널 SYSTEM_PROMPT에 `Lemon Squeezy（グローバル、カード・PayPal・Apple Pay・Google Pay）` 기재 있으나, 패키지·가격이 구형
**필요 작업**: JP 전용 프롬프트에서 LS 결제 안내를 현행 패키지에 맞게 교체

### 4. ℹ️ KR 토스 위젯 전환 — 챗봇 영향 (LOW)

**현상**: 챗봇은 결제 흐름에 직접 관여하지 않음. 가격/결제수단 안내 텍스트만 포함
**영향**: 토스 위젯 전환 시 SYSTEM_PROMPT_KR의 결제 안내 문구만 갱신하면 됨
**현재 상태**: KR 프롬프트는 "토스페이먼츠" 기재 → 위젯 전환 후에도 문구 변경 불필요 (결제 브랜드 동일)

### 5. ⚠️ 챗봇 서비스 정보 최신화 필요 (MEDIUM)

| 항목 | 현재 상태 | 최신 여부 |
|------|----------|----------|
| KR 크레딧 가격 | ₩ 가격표 기재 | ✅ 최신 |
| KR SNS 보너스 (인스타) | 100c 기재 | ✅ 최신 |
| KR 카카오 보너스 | 40c 기재 | ✅ 최신 |
| JP 가격 | $ 기반 구형 | ❌ 구형 |
| JP SNS 보너스 (X/Twitter) | SYSTEM_PROMPT에 기재 | ✅ 최신 |
| JP LINE 로그인 | CS 프롬프트에만 기재 | ⚠️ web 프롬프트엔 미기재 |
| JP 규격 (パスポート/マイナンバー) | SYSTEM_PROMPT에 기재 | ✅ 최신 |

### 6. ℹ️ 기타 관찰 사항

- **JP chatbot.js 주석 오류**: 파일 헤더에 `idphoto-kr 전 페이지`, `channel: 'idphoto-kr'` 기재 (복사 잔재)
- **sessionId 접두사**: KR/JP 모두 `idphoto_` → Firestore에서 KR/JP 구분 불가
- **타임아웃 미구현**: 서버 응답 지연 시 사용자가 무한 대기
- **HTTP 에러 코드 미처리**: 500 응답도 JSON 파싱 시도 → 에러 메시지 대신 빈 응답 가능
