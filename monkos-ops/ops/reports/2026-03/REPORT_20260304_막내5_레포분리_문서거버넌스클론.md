### 권장안: **D3 (monkos_ai에 유지) + monk_kr 경량 ops**

**근거**:
1. **세션 로그가 분할 불가** — 한 세션에서 양쪽 작업을 동시 언급. 복사하면 이중화, 분할하면 맥락 파괴
2. **ops는 "운영체제"** — 작가님 선언("옵스는 운영체제"). 운영체제는 메인 엔진에 귀속이 자연스러움
3. **monk.kr은 정적 사이트** — ops 규모의 운영 체계가 불필요. 경량 ops로 충분
4. **D2(별도 레포)는 이상적이나**: git submodule 복잡도 + 에이전트 컨텍스트 분산 → 현 팀 규모에서 과도

**실행 방안**:
```
monkos_ai/
└── monkos-ops/          ← 기존 전체 유지 (정본)

monk_kr/
└── ops/                 ← 경량 ops (신규 생성)
    ├── orders/          ← monk.kr 전용 지시서
    ├── reports/         ← monk.kr 전용 보고서
    └── sessions/        ← monk.kr 전용 세션 로그 (발생 시)
```

- 분리 시점 이전 과거 이력은 monkos_ai에만 보존
- 분리 이후 monk.kr 작업은 monk_kr/ops/에 생성

### .claudeignore 조사 결과

**현황**:
- 프로젝트에 `.claudeignore` 파일 존재 (65줄). node_modules, 이미지, 바이너리 등 제외
- **gitignore 스타일 문법** 사용

**Claude Code 네이티브 지원 여부**:
- `.claudeignore`는 **Claude Code의 공식 네이티브 기능이 아님**
- Claude Code는 자체적으로 `.claudeignore`를 파싱·강제하지 않음
- `.gitignore`는 코드베이스 인덱싱 시 일부 존중하나, 직접 `Read` 명령으로는 우회 가능

**대안 메커니즘**:

| 방법 | 신뢰도 | 설명 |
|------|--------|------|
| **settings.json deny 규칙** | ⚠️ 중간 | `permissions.deny`에 경로 패턴 지정. 단, 강제력에 알려진 이슈 존재 |
| **PreToolUse 훅** | ✅ 높음 | 셸 스크립트로 파일 읽기 차단. `claude-ignore` npm 패키지 등 |
| **.gitignore 연동** | ⚠️ 제한적 | 인덱싱에만 영향, 직접 읽기는 차단 불가 |
| **CLAUDE.md 경계 선언** | ⚠️ 소프트 | 에이전트가 "읽지 말라"는 지시를 따르나, 강제력 없음 |

**권장**:
- 분리 후 각 레포는 **별도 프로젝트 디렉토리** → 물리적으로 상대 레포 파일에 접근 불가 (가장 확실한 격리)
- `.claudeignore`는 기존 유지 (바이너리/빌드 아티팩트 제외 용도)
- 보안 민감 파일은 `PreToolUse` 훅으로 차단 권장
