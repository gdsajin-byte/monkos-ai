## 3. 5축별 배치 최적화 제안

### 3-1. "항상 로딩" vs "읽어야 참조" 경계

| 축 | CLAUDE.md 필수 여부 | 근거 |
|----|-------------------|------|
| **제1조(정체성)** | ✅ **필수** | 에이전트가 자기 역할을 모르면 모든 행동이 무의미. 첫 턴부터 필요. |
| **제2조(통신)** | ✅ **필수** | 수발신 헤더는 매 턴 적용. 디바이스 맵도 헤더 구성에 필요. |
| **제3조(적립)** | ✅ **필수** | 타임스탬프 절대 준수(1항)는 매 턴 적용. 분산 기록(2항)도 세션 전체에 적용. |
| **제4조(구속·윤리)** | ✅ **필수** | 안전 규칙(파괴적 명령 금지, 비밀정보 보호)은 **단 한 턴도 빠지면 사고 발생**. |
| **제5조(메타)** | ✅ **필수** | 대응 프로토콜(4항)은 매 지시 수령 시 적용. 문서 위계 인식은 모든 판단의 전제. |

**판정: 5축 모두 CLAUDE.md 항상 로딩이 필요하다.** 어떤 축도 "나중에 읽으면 됨"으로 분류할 수 없다.

### 3-2. 축 내부의 최적화 가능 지점

5축 전체를 유지하되, 각 축 내에서 "위임(delegation)" 구문을 통해 상세를 법률 파일로 분리한 현 5축 초안의 구조는 **Anthropic 설계 의도에 정합한다**:

| 항목 | 현행 7조 | 5축 초안 |
|------|---------|---------|
| 위임 구문 수 | 3개 | 5개 (매 축마다) |
| 법률 참조 명시성 | 낮음 (산재) | 높음 (축 말미에 집중) |
| 에이전트 행동: "상세가 필요하면 어디를 읽나?" | 불명확 | 위임 구문이 가이드 |

**이 위임 패턴은 Anthropic의 "시스템 프롬프트=지침, 상세=별도 파일" 설계와 정확히 일치한다.**

### 3-3. 추가 최적화 제안

1. **근거(> 근거:) 라인 축약 검토**: 현재 각 항에 역사적 근거(날짜 + 인용)가 포함되어 있다. 이는 개정 추적에 필수적이지만, **에이전트 행동에는 무관**하다. 근거를 별도 파일(`governance/constitution/ARTICLE_PROVENANCE.md`)로 분리하면 **~30행, ~1,500 토큰 절감** 가능.

   - **찬성**: 토큰 효율, CLAUDE.md 간결화
   - **반대**: 개헌 심사 시 근거를 즉시 확인 불가, 추가 Read 필요
   - **권장**: 현 단계에서는 유지. 토큰 압박이 실제 문제가 될 때 분리 검토.

2. **"위반 시" 라인 통합 검토**: 각 항의 "위반 시" 경고도 에이전트 행동 지침이라기보다 설계 문서 성격. 단, 위반 경고가 준수 동기를 강화하므로 **유지 권장**.

## 4. 충돌 지점

### 4-1. Anthropic 설계 의도와의 긴장

| # | 긴장 지점 | 심각도 | 설명 |
|---|----------|--------|------|
| 1 | **시스템 프롬프트 크기** | 중 | ~10KB는 Anthropic이 의도한 "간결한 지침"보다 크다. 그러나 Claude Code의 CLAUDE.md는 복잡한 프로젝트 규칙 수용을 설계 목적으로 갖고 있으므로, 이 크기 자체가 "위반"은 아니다. |
| 2 | **매 턴 `date` 명령** | 낮 | 타임스탬프 취득을 위한 매 턴 Bash 호출은 1회 tool call 오버헤드. Anthropic 설계상 문제 없으나, 세션 길이에 비례해 tool call 누적. 이는 헌법 1조(현 3조) 불변 원칙이므로 수용. |
| 3 | **멀티에이전트 조율을 파일 기반으로 운용** | 낮 | Claude Code는 네이티브 멀티에이전트 조율 기능이 없다. 지시서/보고서 파일 기반 조율은 현실적 차선책이며, Anthropic 설계와 충돌하지 않는다. |
| 4 | **MEMORY.md 200행 캡 vs 축적 교훈** | 낮 | 현재 139행으로 여유 있으나, 교훈이 계속 축적되면 캡에 도달. 오래된 교훈의 외장 메모리 이관 프로세스가 필요할 수 있다 (현재 외장 메모리 참조 체계로 대응 가능). |

### 4-2. 5축 재편 특유의 긴장: 없음

5축 재편 자체는 **내용 변경이 아닌 위상 정렬**이므로, Anthropic 설계와의 새로운 긴장을 생성하지 않는다. 오히려:

- **위임 구문 명시화** → Anthropic의 "필요 시 Read" 패턴에 부합
- **축별 응집도 향상** → 에이전트가 관련 규칙을 한 곳에서 파악 → 참조 효율 개선
- **조번호 감소 (7→5)** → 상호 참조 복잡도 감소

### 4-3. 개선 제안

| # | 제안 | 대상 | 효과 |
|---|------|------|------|
| 1 | 근거 라인 외부화 (향후) | 5축 헌법 | ~1,500 토큰 절감 |
| 2 | works subtree 규정 법률 승격 | MEMORY.md → ch4 or ch6 | 전 디바이스 정합성 확보 |
| 3 | MEMORY.md 교훈 아카이빙 프로세스 | MEMORY.md | 200행 캡 관리 |

| **디바이스 전환 시 일관성** | ✅ 적절 | 헌법(불변)은 Git으로 동일, 디바이스 특수(에이전트 접두어 등)는 MEMORY.md로 분리. |
| **신규 디바이스 온보딩** | ⚠️ 주의 | MEMORY.md는 수동 작성 필요. 템플릿 또는 초기화 스크립트 있으면 개선. |

| 역할 자동 인식 (VSCode→쌍아, CLI→막내) | MEMORY.md | ✅ 디바이스별 에이전트 구성 상이 |

### 5-3. 결론

현 CLAUDE.md/MEMORY.md 분리 구조는 멀티디바이스 운용에 **적합**하다. 다만 MEMORY.md에 있는 **전 디바이스 공통 규정 2건**(세션 로그 파일명 패턴, works subtree 운용)은 법률로 승격하여 Git 동기화 대상으로 만드는 것이 정합적이다.
