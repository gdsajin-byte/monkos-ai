## 6. develop→main 통합 실행 절차 제안

### 현재 상태

| 항목 | 값 |
|------|-----|
| main → develop (develop 미반영) | 0 커밋 |
| develop → main (main 미반영) | **5 커밋** |
| 로컬 브랜치 | `develop`, `main`, `dev-home`, `dev-office` |
| 원격 브랜치 | `origin/develop`, `origin/main` |

develop에 main에 없는 5커밋 존재:
```
208f1dc [log] M1/쌍아 새벽세션 — 크롭앱 설계 확정 + 엔진 UI 테스트
cbfbcab [log] M1/쌍아 야간세션 — 정수리 추산 방법론 논의 + 막내 리서치 수신
8c86242 [log] crop-engine 정수리 리서치 방향 추가 — M1 막내 지시용
8934548 [feat] crop-engine v2 — 눈 앵커 기반 배치 + 조건부 보정 + 300dpi
a64d66d [log] 2026-03-11 iMac/쌍아 오후세션 — LS API 키 사고 + 수습 기록
```

### 실행 순서

```
[사전] 법률 개정 의결 완료 확인

[Step 1] main에서 develop 머지
  $ git checkout main
  $ git merge develop        # fast-forward 예상 (main→develop 0커밋이므로)
  $ git push origin main

[Step 2] 원격 develop 삭제
  $ git push origin --delete develop

[Step 3] 로컬 develop 삭제
  $ git branch -d develop

[Step 4] 불필요 로컬 브랜치 정리 (선택)
  $ git branch -d dev-home
  $ git branch -d dev-office
  (머지 안 된 내용 있으면 확인 후 판단)

[Step 5] 타 디바이스 안내
  - M1: git fetch --prune && git checkout main
  - M2: git fetch --prune && git checkout main
  - M4: git fetch --prune && git checkout main
  - 각 디바이스 로컬 develop 삭제: git branch -d develop

[Step 6] 법률 조문 + 운영 문서 반영 (상기 5-2 목록)
```

### 히스토리 보존

- develop의 모든 커밋은 main 머지 시 그대로 보존됨 (fast-forward)
- `git log`에서 develop에서 작업한 이력 전부 유지
- 브랜치 포인터만 삭제되므로 **히스토리 손실 없음**
- `git tag develop-final` 태그를 남기면 삭제 시점 기록 가능 (선택)
