## 산출물 2: CMS SSR 충돌 분석표 — 각 렌더러별 3컬럼 적합성

### 2-1. SSR 렌더러 호환성

현재 모든 SSR 렌더러(`lib/cms/render.js`)는 **전체 페이지 HTML**을 반환 (`<!DOCTYPE>` ~ `</html>`):

| 렌더러 | 반환 형태 | 포함 요소 | 3컬럼 호환 | 필요 작업 |
|--------|----------|----------|:---------:|----------|
| `renderBlogList` | 전체 HTML | head + nav + container + footer | ❌ | fragment 분리 |
| `renderBlogPost` | 전체 HTML | head + nav + container + footer + hreflang | ❌ | fragment 분리 |
| `renderFaq` | 전체 HTML | head + nav + container(800px) + footer | ❌ | fragment 분리 + 폭 제약 제거 |
| `renderGallery` | 전체 HTML | head + nav + container + lightbox + footer | ❌ | fragment 분리 + lightbox 분리 |
| `renderBoardList` | 전체 HTML | head + nav + container(900px) + footer | ❌ | fragment 분리 + 폭 제약 제거 |
| `renderBoardPost` | 전체 HTML | head + nav + container + 댓글 + footer | ❌ | fragment 분리 |
| `renderBoardWrite` | 전체 HTML | head + nav + container + 폼 + footer | ❌ | fragment 분리 |
| `renderSitemap` | XML | sitemap.xml | ✅ | 해당 없음 |

**핵심 문제**: 각 렌더러가 `layoutHead()` + `layoutNav()` + `layoutFooter()`를 항상 포함 → 3컬럼 쉘에 삽입하면 head/nav/footer 중복.

### 2-2. 리팩토링 방향

```
[현재] server.js → renderBlogList(req, res) → 전체 HTML 반환
[v4]   server.js → layoutShell(renderBlogListFragment()) → 3컬럼 쉘 + 메인만 삽입
```

필요한 작업:
1. 각 렌더러에서 **fragment 함수** 분리 (메인 영역 HTML만 반환)
2. **3컬럼 레이아웃 쉘** 신규 작성 (좌사이드바 + 메인 + 우사이드바)
3. `server.js` 라우터에서 쉘이 fragment를 호출하도록 수정

### 2-3. server.js 현재 라우트 목록

```
/sitemap.xml       → renderSitemap
/ja/blog           → renderBlogList(ja)
/en/blog           → renderBlogList(en)
/ja/blog/:slug     → renderBlogPost(ja)
/en/blog/:slug     → renderBlogPost(en)
/blog              → renderBlogList
/blog/:slug        → renderBlogPost
/faq               → renderFaq
/gallery           → renderGallery
/board             → renderBoardList
/board/write       → renderBoardWrite
/board/:id         → renderBoardPost
```

**v4 추가 필요**: `/crop` (크롭앱), `/pricing` (가격)

### 2-4. 네비게이션 변경

| 현재 | v4 |
|------|-----|
| Blog \| FAQ \| Gallery \| Board | 홈 \| 블로그 \| FAQ \| 갤러리 \| 게시판 \| **크롭앱** \| **가격** |

변경점:
- **크롭앱** 추가 → `/crop` 라우트 신규
- **가격** 추가 → `/pricing` 라우트 신규
- **홈** 명시 추가

- `layoutNav()` (SSR 렌더러 내부)도 동일 수정 필요

### 2-5. 다국어 URL과 SPA 라우팅 정합성

현재 다국어 URL은 SSR 서버사이드에서 처리 (`/ja/blog/slug`). v4에서 "메인 영역만 교체"를 SPA로 구현할 경우:
- SSR → CSR 전환 필요 (또는 하이브리드)
- 또는 SSR 유지하되 전체 페이지를 3컬럼 쉘로 감싸는 방식

**판단 필요**: SPA 전환 vs SSR+쉘 래핑

### 위험도 H 항목 상세

#### H-1. SSR 렌더러 비호환
- 현재 7개 렌더러가 전체 HTML 반환 → 3컬럼 쉘에 삽입 불가
- **해결**: 각 렌더러에 `renderXxxFragment()` 분리 → 메인 영역 HTML만 반환
- **규모**: render.js 전면 리팩토링 (현재 코드 유지하면서 fragment 함수 추가 가능)

#### H-2. 다크→라이트 테마 전환
- CSS 변수명 체계 자체가 변경 (`--text-*` → `--ink-*`)
- 서브페이지(refund/privacy/terms)는 메인과 다른 색상 사용 중 → 통일 필요
- **해결**: `:root` 변수 전면 교체 + 하드코딩 색상 grep 후 변수 참조로 변경

#### H-3. SPA vs SSR 라우팅 결정
