### 1. 외부 플랫폼 ToS 위반 리스크

**판정: `중대한우려`**

#### 플랫폼별 분석

**네이버 블로그 — 위험도: 높음**
- 네이버는 블로그 작성 공식 API를 제공하지 않는다. 검색 API만 존재한다.
- 네이버 이용약관 제17조(금지행위): "자동화된 수단을 이용하여 서비스에 접근"을 명시적으로 금지한다.
- 네이버의 봇 탐지 시스템은 국내 최고 수준이며, 비정상 패턴 감지 시 계정 영구 정지 가능하다.
- 기안서가 제안하는 "세션 쿠키" 방식은 사실상 브라우저 자동화이며, 이는 ToS의 자동화 금지 조항에 직접 해당한다.
- **사업 리스크**: MONKOS 네이버 블로그 계정이 정지되면 한국 SEO 전략 전체가 차단된다. 복구 절차가 매우 어렵다.

**note.com — 위험도: 중간**
- note.com은 공식 API를 제공하지 않는다.
- 이용약관에서 자동화 접속을 제한할 가능성이 높다.
- 일본 부정경쟁방지법(不正競争防止法) 제2조 제1항: 기술적 제한을 우회하는 행위를 불정경쟁으로 규정한다.
- 일본 시장에서의 브랜드 리스크가 한국보다 더 치명적일 수 있다 (신뢰 기반 시장).

**X (Twitter) — 위험도: 낮음**
- X API v2는 OAuth 2.0 기반 공식 API를 제공한다.
- 기안서가 제안하는 `X_AUTH_TOKEN` (OAuth 2.0 Bearer)은 **공식 경로**이다.
- API를 통한 게시는 ToS 상 합법적이다.
- 단, 유료 플랜 필요 (Basic: $100/월).

**Instagram — 위험도: 높음**
- Instagram은 자동화에 대해 업계에서 가장 엄격한 정책을 유지한다.
- Meta Business Suite / Instagram Graph API는 공식이지만 기능이 제한적이다 (비즈니스 계정 필수).
- 브라우저 자동화(세션 기반)는 ToS 명시적 위반이며, 계정 정지 + IP 차단이 즉각 발생한다.
- 기안서의 "Instagram Business API 또는 세션" 중 세션 방식은 절대 불가하다.

#### 종합

| 플랫폼 | 공식 API | 브라우저 자동화 ToS | 위험도 |
|--------|---------|-------------------|--------|
| 네이버 블로그 | 작성 API 없음 | **명시적 금지** | 높음 |
| note.com | API 없음 | 제한 추정 | 중간 |
| X | OAuth 2.0 ✅ | API 사용은 허용 | 낮음 |
| Instagram | Graph API (제한적) | **명시적 금지** | 높음 |
| Pinterest | API 있음 (제한적) | 제한 추정 | 중간 |

#### 대안

**(필수) API 우선 원칙 수립:**
```
1순위: 공식 API 사용 (X OAuth, Instagram Graph API, Pinterest API)
2순위: 공식 API가 없는 플랫폼은 수동 운용 (작가님/한송이가 직접 게시, 민아는 콘텐츠 생성까지만)
3순위: 브라우저 자동화는 자체 서비스(monkos.ai)에만 한정
```

네이버 블로그는 **Open API(검색)로 SEO 분석은 가능**하지만, 게시 자체는 수동 또는 한송이 담당으로 전환을 권고한다. 헌법 5조 1항("불법/비윤리 자동화 금지")에 비추어, ToS 위반이 명확한 플랫폼의 브라우저 자동화 env 등록은 부적절하다.

### 2. 인증 정보 유출 리스크

**판정: `경미한우려`**

#### 우려 근거

(1) **다중 플랫폼 인증 집중**: 기안서가 제안하는 env 체계는 8개 플랫폼의 인증 정보를 에이전트 로컬에 저장한다. 하나의 `.env` 파일이 유출되면 작가님의 네이버, X, Instagram, Google 등 전 계정이 동시에 위험해진다.

(2) **에이전트 접근 권한**: 막내들은 `--dangerously-skip-permissions`로 실행한다. 풀 파일시스템 접근 권한이 있으므로, `.env` 파일에 대한 기술적 접근 통제가 없다.

(3) **세션 쿠키의 장기 보관 문제**: API 토큰은 scope가 제한적이지만, 세션 쿠키는 해당 플랫폼에 대한 완전한 접근 권한을 부여한다. 세션 쿠키를 파일로 저장하는 것은 보안상 최선이 아니다.

#### 우려가 "경미"인 이유

- 기안서의 보안 원칙(4-1)이 합리적이다: 로컬 전용, Cloud Run 미등록, git 커밋 금지.
- `.gitignore`에 `.env*` 패턴이 등록되어 있으면 실수 커밋을 방지할 수 있다.
- 에이전트는 작가님 직접 운용이므로, 외부 공격자가 에이전트를 통해 `.env`에 접근하는 시나리오는 현실적이지 않다.

#### 대안

```
1. env 파일을 플랫폼별로 분리: .env.naver, .env.x 등 (하나 유출 시 피해 한정)
2. 세션 쿠키 대신 API 토큰 우선 사용 (scope 제한 가능)
3. 주기적 토큰 갱신 주기 설정 (30일 등)
4. .gitignore 검증: monkos_AI/.gitignore에 .env* 패턴 포함 확인
```

### 3. 권한 범위 확대 우려

**판정: `경미한우려`**

#### 우려 근거

(1) **점프 폭**: 어드민 인증(자체 서비스, 완전 통제) → 외부 플랫폼 8개(타사 서비스, 통제 불가)는 한 단계의 도약이 크다.

(2) **게시 행위의 비가역성**: 자체 어드민에서의 오류는 즉시 삭제·수정 가능하다. 외부 플랫폼에서의 오류 게시는 캐시·크롤링으로 확산되어 삭제해도 잔존한다.

(3) **나라장터·혁신바우처**: 정부 시스템에 에이전트가 접속하는 것은 법적·행정적 리스크가 전혀 다른 차원이다. "향후"라고 했지만 env 목록에 포함된 것 자체가 기대 설정이 된다.

#### 우려가 "경미"인 이유

- 기안서 4-2에서 "게시(publish) 행위는 작가님 사전 승인 필요"를 명시했다.
- 민아 권한 테이블(개정 발효분)에서 커밋·푸시·배포는 쌍아 경유 또는 작가님 명시 승인이 필요하며, 외부 게시도 이와 동일하게 운용된다.
- 기안서의 우선순위가 명확하다 (네이버 → note → X → 나머지).

#### 대안

```
1. 1단계 승인: 자체 서비스(monkos.ai) + API 기반 외부 플랫폼(X)만 즉시 구축
2. 2단계 승인: 각 플랫폼 ToS 확인 결과 제출 후 개별 승인
3. 정부 시스템(나라장터, 혁신바우처): 별도 기안서로 분리. 본 기안 범위에서 제외
4. 게시 전 "드래프트 확인" 의무: 민아가 게시 전 콘텐츠를 작가님 또는 쌍아에게 확인 받는 절차 명문화
```

### 4. 레퍼런스 수집의 법적 리스크

**판정: `경미한우려`**

#### 우려 근거

(1) **"맥락 데이터"의 정의 모호성**: 기안서에서 "패션코드·포즈·배경의 맥락 데이터"라고 했으나, 이것이 구체적으로 무엇인지 정의되어 있지 않다.
  - 이미지 파일 자체를 다운로드하면 → **복제권 침해** 가능
  - 이미지를 보고 텍스트로 기술하면 → 합법 (아이디어 참조)
  - 이미지를 AI 모델 입력으로 사용하면 → **법적 회색지대** (각국 법률 상이)

(2) **초상권과 퍼블리시티권**: "특정인 초상 카피·노출 절대 금지"라고 했으나, Pinterest/Google 이미지 검색에서 패션 레퍼런스를 수집하면 모델·연예인 이미지가 불가피하게 포함된다. 수집 단계에서의 필터링이 기술적으로 어렵다.

(3) **국가별 법률 차이**:
  - 한국: 저작권법 제35조의5 (정보분석을 위한 복제 — AI 학습 관련 개정 논의 중)
  - 일본: 저작권법 제30조의4 (정보해석 목적의 이용 — 상대적으로 관대)
  - 미국: Fair Use 판단 (변형적 이용 여부가 핵심)

#### 우려가 "경미"인 이유

- 기안서의 최종 목적은 레퍼런스를 "카피"하는 것이 아니라, MONKOS 엔진(Imagen)으로 **새 이미지를 생성**하는 것이다. 이는 변형적 이용에 해당할 가능성이 높다.
- 헌법 5조 2항("원본의 정체성 보존을 최우선")은 자체 서비스에 대한 원칙이지, 외부 레퍼런스 수집에 대한 규정이 아니다.
- "인간이 브라우저로 보는 것과 동일" — 레퍼런스 수집 자체는 디자이너의 일상적 업무이며, 에이전트가 이를 대행하는 것은 행위의 본질을 변경하지 않는다.

#### 대안

```
1. "맥락 데이터" 정의 명문화:
   - 허용: 색상 코드, 레이아웃 구조, 포즈 방향, 배경 유형 등 스타일 속성의 텍스트 기술
   - 허용: 공개 이미지의 일시적 열람 (브라우저 캐시 수준, 영구 저장 안 함)
   - 금지: 이미지 파일 직접 다운로드·저장 (GCS 등에 보관)
   - 금지: 특정인이 식별 가능한 이미지의 AI 입력 사용

2. 수집 로그 의무: 어떤 URL에서 어떤 맥락을 참조했는지 기록 → 추후 분쟁 대비

3. Creative Commons / 로열티프리 소스 우선 사용
```

### 핵심 조건

기안서의 env 체계 구축 자체는 합리적이나, **"브라우저 자동화 = 합법적 대행"이라는 전제가 모든 플랫폼에 적용되지는 않는다.** 특히:

1. **네이버 블로그**: 작성 API 없음 + 자동화 명시적 금지 → 브라우저 자동화 게시는 헌법 5조 1항("불법/비윤리 자동화 금지")에 저촉된다.
2. **Instagram**: 브라우저 자동화 명시적 금지 → 동일.

### 권고 사항 요약

1. **(필수)** API 우선 원칙: 공식 API가 있는 플랫폼(X, Instagram Graph API)은 API 사용. 공식 API가 없는 플랫폼(네이버, note)의 브라우저 자동화 게시는 **ToS 확인 완료 전까지 보류**.
2. **(필수)** 브라우저 자동화 게시를 자체 서비스(monkos.ai)에 한정하고, 외부 플랫폼은 콘텐츠 생성까지만 에이전트가 수행 → 게시는 수동 또는 공식 API.
3. **(강권고)** 정부 시스템(나라장터, 혁신바우처) env를 본 기안 범위에서 분리.
4. **(권고)** "맥락 데이터" 정의 명문화 + 수집 로그 의무화.
5. **(권고)** env 파일 플랫폼별 분리 + 토큰 갱신 주기 설정.

위 1~2번이 반영된다면 본 기안서는 **적합**으로 전환될 수 있다.
