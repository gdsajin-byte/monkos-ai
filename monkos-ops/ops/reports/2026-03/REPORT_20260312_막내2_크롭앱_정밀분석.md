## 1. crop-engine 코드 현황

### 1-1. server.js (139줄)

| 엔드포인트 | Method | 역할 | 요청 스펙 | 응답 스펙 |
|------------|--------|------|-----------|-----------|
| `/api/crop` | POST | 핵심 크롭 API | `{ image: "base64", format: "passport", country: "KR" }` | `{ success, cropped: "base64", fallback: bool, meta }` |
| `/api/specs` | GET | 지원 규격 목록 | 없음 | `{ specs: [{key, name, width, height, ...}] }` |
| `/health` | GET | 헬스체크 | 없음 | `{ status: "ok", model: "loaded"/"not_loaded" }` |

**구조**:
- `node:http` 순수 HTTP 서버 (Express 미사용)
- CORS 전체 허용 (`Access-Control-Allow-Origin: *`)
- 최대 요청 크기 20MB
- 기동 시 FaceMesh 모델 프리로드 → `detector` 변수로 health에서 참조
- 에러 시 500 + JSON 에러 메시지 반환

**흐름**: `readBody → JSON.parse → detectFace → (성공) cropToFrame / (실패) fallbackCrop → sendJSON`

### 1-2. lib/crop.js (208줄) — v2 "조건부 배치 로직"

**핵심 알고리즘**:

```
1. 눈 중심(eyeCenter) 실측
2. 정수리 추산: crownY = eyeCenterY - (chin.y - eyeCenterY)  ← 눈~턱 1:1 반전
3. 헤어탑 추산: hairTopY = crownY - (faceHeight × 0.08)  ← 고정 8% 볼륨
4. 스케일: targetFaceH / faceHeight (타겟 33mm / 프레임 45mm 기준)
5. 눈 앵커 배치: 눈이 프레임 상단에서 43% 위치에 오도록 배치
6. 조건부 보정:
   6a. 헤어탑 잘림 방지 → extractTop 밀어내기
   6b. 하단(어깨) 부족 → 스케일 축소 (최소 32mm까지)
7. sharp: resize → extract → 300dpi PNG 출력
```

**배치 상수**:

| 상수 | 값 | 의미 |
|------|-----|------|
| `EYE_POSITION_RATIO` | 0.43 | 눈 위치: 프레임 상단에서 43% |
| `HAIR_MARGIN_MIN` | 0.044 | 헤어탑 최소 여백: 2mm/45mm |
| `HAIR_VOLUME_RATIO` | 0.08 | 정수리 위 헤어 볼륨: 얼굴높이의 8% |
| `FACE_TARGET_MM` | 33 | 얼굴 기본 타겟 (mm) |
| `FACE_MIN_MM` | 32 | 얼굴 최소 허용 (mm) |
| `FRAME_MM` | 45 | 프레임 높이 (mm) |
| `BOTTOM_MIN_RATIO` | 0.12 | 하단 최소: ~5.4mm (어깨선 가시) |

**부가 기능**:
- `cropWithPadding()`: 스케일 후 이미지가 프레임보다 작을 때 흰색 패딩 처리
- `fallbackCrop()`: 얼굴 감지 실패 시 상단 중앙 커버 크롭 (sharp cover + top)

**meta 반환**: `spec`, `scale`, `faceMM`, `topMarginMM`, `bottomMarginMM`, `eyePositionPercent`, `extractRegion`

### 1-3. lib/face-detect.js (99줄)

**모델**: MediaPipe FaceMesh (478 랜드마크, 눈동자 포함 refineLandmarks)

**핵심 랜드마크 인덱스**:

| 인덱스 | 이름 | 용도 |
|--------|------|------|
| #10 | FOREHEAD_TOP | 정수리 추산 기준 (이마 중간~상단) |
| #152 | CHIN | 턱 최하단 |
| #159 | LEFT_EYE | 좌눈 중심 |
| #386 | RIGHT_EYE | 우눈 중심 |
| #1 | NOSE_TIP | 코끝 (참조) |
| #234 | LEFT_CONTOUR | 좌측 윤곽 |
| #454 | RIGHT_CONTOUR | 우측 윤곽 |

**정수리 추산 방식 (face-detect.js 내부)**:
```
faceHeight = chin.y - forehead.y  (#152 - #10)
crownY = forehead.y - (faceHeight × 0.30)  ← CROWN_OFFSET_RATIO
```

**주의**: 이 추산값은 `crop.js`에서 **사용되지 않음**. `crop.js`는 자체적으로 `eyeCenterY - eyeToChin` (1:1 반전)을 사용. `face-detect.js`의 `CROWN_OFFSET_RATIO = 0.30`과 `crop.js`의 1:1 방식은 **독립적으로 병존하며 역할이 정리되지 않은 상태**.

**이미지 처리**: `sharp → removeAlpha → raw RGB → tf.tensor3d → estimateFaces → keypoints 추출 → tensor.dispose()`

|---------|------|-----------|-----------|-----------|-------------|

| 실제 배포 | ❌ | 미배포 |

### 4-3. idphoto-kr/jp 연동 포인트

| 파일 | 내용 | 현재 crop-engine 연동 |
|------|------|----------------------|
| `idphoto-kr/gcs-save.js` | `cropToSpec` 함수 (Gemini Flash 좌표 역산 방식) | ❌ 미연동 |
| `idphoto-kr/server.js` | 얼굴 감지 (현재 Gemini Flash 사용) | ❌ 미연동 |
| `idphoto-jp/gcs-save.js` | 동일 구조 | ❌ 미연동 |
| `idphoto-jp/server.js` | 동일 구조 | ❌ 미연동 |

**연동 설계 (세션 로그 기반)**: idphoto-kr/jp의 result 페이지에서 crop 페이지로의 진입점을 만들어 연동하는 방향이나, 구체적 연동 코드는 별도 지시서 예정.
