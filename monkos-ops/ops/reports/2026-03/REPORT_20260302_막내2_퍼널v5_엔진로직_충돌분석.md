## 5. PG 결제 흐름 영향 (3-E)

### 현재 토스 결제 플로우

```
[idphoto-kr] buyCreditsKR(amount, credits)
  → TossPayments.requestPayment('카드', { successUrl: 현재페이지?toss=success })
  → [토스 결제창] → 리다이렉트
```

### v5에서 충전 화면이 풀 페이지로 바뀌면

| 항목 | 현재 | v5 후 | 영향 |
|------|------|-------|------|
| successUrl | `result.html?toss=success` (result.js에서 호출 시) | 충전 페이지에서 호출 시 → 충전 페이지로 돌아옴 | ⚠️ 프리뷰로 돌아가는 라우팅 필요 |
| pending_action 저장 | `sessionStorage.setItem('monkos_pending_action', 'download')` | sessionStorage는 동일 origin 내 유지 → ✅ 동작 | — |
| _fullOriginal 임시 보관 | `sessionStorage.setItem('_mo_p', _fullOriginal)` | 동일 origin 내 유지 → ✅ 동작 | — |
| 충전 후 복귀 | result.js L732-764: 생성 이미지 존재 시 결과 화면 복원 | 충전 페이지에서 result 페이지로 이동하는 로직 필요 | ⚠️ |

### buyDirect() (비로그인 직결제)

```
[gate.js] _buyDirect()
  → amount:9900, successUrl: 현재페이지?toss=direct
  → 토스 결제 → 리다이렉트
  → result.js init() → GateModule.initDirectPayment()
    → /api/payments/toss/direct (portal)
    → downloadToken 발급 → 즉시 다운로드
```

v5에서는 비로그인 buyDirect 경로를 유지하되, 기획안 §7에 "로그인 게이트: 1p 이전, 촬영실 진입 시 소셜 원탭 로그인"이므로 **비로그인 진입 자체가 차단되면 buyDirect는 dead path가 됨**. 단, 기획안에 buyDirect 삭제가 명시되지는 않았으므로 **확인 필요**.

### 핵심 위험

1. **충전 페이지 분리 시 토스 리다이렉트 경로 재설계 필요** — successUrl을 어디로 보내고, 복귀 후 어디로 이동할지
2. **현재 result.js의 토스 복귀 로직이 result.html에 하드코딩** — 충전 페이지가 분리되면 이 로직을 공유 모듈로 추출해야 함

## 8. 프롬프트 빌딩 로직 (3-H)

### 현재 데이터 체인

```
[prep.js] selections (9필드)
  → saveSessionData() (9키 저장)
  → applyLegacyMapping() → store.style, store.age, store.gender 저장
  → navigateTo('camera.html')

[camera.js] loadSessionData (9필드 읽기)
  → store에 세팅
  → WS set-style: store.style ("id_photo" | "resume")
  → 프레임 전송 (코칭용)

[result.js] confirmAndGenerate()
  → pipe.run('generate', { 9필드 + style + image + userId })
  → 서버 /api/idgen → 프롬프트 빌딩 → AI 생성
```

### v5에서 변경되는 체인

```
[1p~3p] v5 상태 (12필드)
  → saveSessionData() (12키 저장)
  → format → style 변환 (레거시 호환 또는 직접 전달)
  → navigateTo('camera.html')

[camera.js] loadSessionData (12필드 읽기)
  → WS set-style: format ("passport" | "id") 또는 변환값
  → 코칭 WS의 스타일 분기도 변경 필요

[result.js] confirmAndGenerate()
  → pipe.run('generate', { 12필드 + image + userId })
  → 서버 /api/idgen: 새 프롬프트 스택으로 빌딩
```

### 정장 옵션 프롬프트 매핑 예시

현재 (tie: `"solid_navy"`) → 서버: 프롬프트에 "무지 네이비 타이"

v5 (tieColor: `"navy"`, tiePattern: `"solid"`) → 서버: 프롬프트에 "네이비 민타이"

**변환 레이어가 필요하거나, 서버 API를 v5 스키마로 직접 교체해야 함.**

### WS 코칭 영향

camera.js L124: `wsCoaching.send(JSON.stringify({ type: 'set-style', style: store.style || 'id_photo' }))` — 서버 WS가 `style` 키로 코칭 규칙을 분기하므로, v5에서 `format`으로 바뀌면 서버 WS도 수정 필요.
