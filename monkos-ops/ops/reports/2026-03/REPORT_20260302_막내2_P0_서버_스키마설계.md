## 2. 현행 프롬프트 빌딩 로직 (3-B) ⭐ 핵심

### 프롬프트 구조 개요

`buildPrompt(body)` (server.js L251-309)가 최종 프롬프트를 조립한다.
최종 출력 형태 (L308):

```
{IDENTITY_PRESERVATION}

[IMAGE-TO-IMAGE TRANSFORM]
[STYLE] {purposePrompt}
[BACKGROUND] {bgPrompt}
[SUBJECT] This person is a {genderLabel}, {ageLabel}.
[OUTFIT] Dress this person in {outfitDesc}. With {tieDesc}.
[HAIR] {hairDesc}
[EXPRESSION] {exprDesc}
[CONSTRAINT] Keep the person's face and body exactly the same...
```

### Layer 1: IDENTITY_PRESERVATION (고정 프롬프트)

**위치**: server.js L144-162 (상수)

```
IDENTITY RULE: 90% SAME PERSON + 10% ENHANCEMENT

PRESERVE (90%):
- Face shape, eye shape, nose, lips, skin tone
- Overall facial structure and unique characteristics
- The person must be clearly recognizable as the SAME individual

ENHANCE (10% creative freedom):
- Slightly smoother skin, subtle beauty enhancement
- Optimal lighting and flattering angles
- Minor imperfections can be softened
- Make them look their BEST version (not a different person)

DO NOT:
- Change gender, ethnicity, or age by more than 2-3 years
- Alter fundamental facial features
- Make them unrecognizable

GOAL: "This is ME, but on my best day" - perfectly front-facing, studio flat lighting, 90% accuracy, 10% professional retouching.
```

→ **v5에서도 변경 불필요. 헌법 9조 정체성 보존 원칙의 프롬프트 구현체.**

### Layer 2: [STYLE] 용도 프롬프트

**위치**: server.js L243-249 (PURPOSE_PROMPTS)

```javascript
const PURPOSE_PROMPTS = {
  passport:     'Professional passport/ID photo, perfectly front-facing looking directly at camera, sharp focus, head straight, symmetric composition, forehead and eyebrows must be visible',
  student_id:   'Student ID photo, perfectly front-facing, clean and neat appearance, symmetric composition',
  employee_id:  'Professional corporate ID photo, perfectly front-facing, business-appropriate appearance, symmetric composition',
  resume:       'Professional resume photo for job application, perfectly front-facing looking directly at camera, business formal, 3:4 ratio, approachable yet professional',
  color_portrait: 'Professional color portrait photo, perfectly front-facing, studio lighting, clean and polished look',
};
```

**fallback 로직** (L257):
```javascript
const purposePrompt = PURPOSE_PROMPTS[purpose] || PURPOSE_PROMPTS[style === 'id_photo' ? 'passport' : 'resume'];
```
→ `purpose`가 없으면 `style`로 fallback (passport 또는 resume)

### Layer 3: [BACKGROUND] 배경 프롬프트

**위치**: server.js L193-200 (BG_PROMPTS)

```javascript
const BG_PROMPTS = {
  white:  'pure white (#FFFFFF) background',
  blue:   'soft blue (#4A90D9) studio background',
  gray:   'neutral gray (#9CA3AF) studio background',
  beige:  'warm beige (#D4B896) studio background',
  pink:   'soft pink (#F5A0B8) studio background',
  yellow: 'warm yellow (#FBBF24) studio background',
};
```

**fallback** (L261): `BG_PROMPTS[background] || BG_PROMPTS.white`

### Layer 4: [SUBJECT] 인물 정보

**위치**: server.js L264-267

```javascript
const genderLabel = gender === 'female' ? 'female/woman' : 'male/man';
const ageLabels = { child: 'young child (under 12)', teen: 'teenager (13-18)', adult: 'adult' };
parts.push(`[SUBJECT] This person is a ${genderLabel}, ${ageLabels[age] || 'adult'}.`);
```

→ `baby` 연령대 매핑 없음 (현재 코드에 `baby` 키 없으므로 `'adult'`로 fallback)

### Layer 5: [OUTFIT] 의상 프롬프트 — 가장 복잡한 레이어

**위치**: server.js L269-291

**매핑 테이블**:

| clothing 값 | CLOTHING_PROMPTS 영문 |
|-------------|---------------------|
| `as_is` | null → "Keep current clothing as-is" |
| `suit` | `"formal business suit"` |
| `shirt` | `"clean dress shirt"` |
| `casual` | `"smart casual top"` |
| `uniform` | `"neat school uniform"` |

| clothingColor 값 | CLOTHING_COLOR_PROMPTS 영문 |
|------------------|---------------------------|
| `black` | `"black"` |
| `navy` | `"dark navy"` |
| `charcoal` | `"charcoal gray"` |
| `white` | `"white"` |
| `beige` | `"beige"` |
| `wine` | `"wine/burgundy"` |
| `pastel` | `"soft pastel-toned"` |

**조합 로직**:
```

→ 예: "dark navy formal business suit"
```

**특수 분기**:
1. **여성 + shirt**: `"a {colorMod} clean blouse, simple and professional"` (L278-279)
2. **넥타이**: 남성(`gender === 'male'`) + 정장/셔츠(`clothing !== 'as_is'`) + `tie !== 'none'`일 때만 추가 (L283-286)

| tie 값 | TIE_PROMPTS 영문 |

| `stripe_navy` | `"navy striped tie"` |
| `stripe_wine` | `"wine striped regimental tie"` |

### Layer 6: [HAIR] 헤어 프롬프트

**위치**: server.js L236-241

| hair 값 | HAIR_PROMPTS 영문 |
|---------|-----------------|
| `as_is` | null (비표시) |
| `tidy` | `"neatly groomed hair"` |
| `up` | `"hair tied up neatly"` |
| `down` | `"hair down, well-groomed"` |

### Layer 7: [EXPRESSION] 표정 프롬프트

**위치**: server.js L229-234

| expression 값 | EXPRESSION_PROMPTS 영문 |
|---------------|----------------------|
| `gentle_smile` | `"gentle, subtle smile"` |
| `neutral` | `"neutral, composed expression"` |
| `natural_smile` | `"natural, friendly smile"` |
| `bright_smile` | `"bright, confident smile"` |

### Layer 8: [CONSTRAINT] 공통 제약 (고정)

**위치**: server.js L306

```
Keep the person's face and body exactly the same — only apply the specified styling.
DO NOT change apparent gender or age.
```

### 프롬프트 조립 순서 (최종)

```
1. IDENTITY_PRESERVATION (고정)
2. "\n\n[IMAGE-TO-IMAGE TRANSFORM]\n"
3. [STYLE]      ← PURPOSE_PROMPTS[purpose || style fallback]
4. [BACKGROUND]  ← BG_PROMPTS[background || 'white']
5. [SUBJECT]     ← gender + age
6. [OUTFIT]      ← clothing + clothingColor + tie (조건부)
7. [HAIR]        ← hair (as_is면 생략)
8. [EXPRESSION]  ← expression (없으면 생략)
9. [CONSTRAINT]  ← 고정
```

### SPA 호환 경로: generatePhoto() + /api/generate

**주의**: server.js에는 **두 개의 생성 경로**가 있다:

| 경로 | 엔드포인트 | 프롬프트 빌더 | 사용처 |
|------|----------|-------------|--------|
| SPA (레거시) | `/api/generate` (L578-619) | `generatePhoto()` + `getOutfitPrompt()` | app.html (SPA 뷰) |

## 4. v5 프롬프트 빌더 설계 (3-D) ⭐ 핵심

### 프롬프트 스택 구조

기획안 §3-3의 레이어 순서를 따르되, 현행 `buildPrompt()`의 검증된 태그 구조([STYLE], [SUBJECT] 등)를 유지한다.

```
IDENTITY_PRESERVATION (고정 — 변경 없음)

[IMAGE-TO-IMAGE TRANSFORM]
[1] [FORMAT]     ← format → 규격 프롬프트
[2] [SUBJECT]    ← gender + age → 인물 프롬프트
[3] [OUTFIT]     ← clothing + 세부 → 의상 프롬프트
[4] [HAIR]       ← hair → 헤어 프롬프트 (default면 생략)
[5] [BACKGROUND] ← bgColor → 배경 프롬프트
[6] [CONSTRAINT] ← 고정 (변경 없음)
```

**변경점**: 현행은 [STYLE]→[BACKGROUND]→[SUBJECT]→[OUTFIT]→[HAIR]→[EXPRESSION]→[CONSTRAINT] 순서.
v5는 [FORMAT]→[SUBJECT]→[OUTFIT]→[HAIR]→[BACKGROUND]→[CONSTRAINT] 순서로 변경. (기획안 프롬프트 스택 순서 반영, EXPRESSION 삭제)

### [1] FORMAT 레이어 — 규격 프롬프트

현행 PURPOSE_PROMPTS 5값 → v5 FORMAT_PROMPTS 2값으로 축소.

| format | 영문 프롬프트 |
|--------|-------------|
| `"passport"` | `"Professional passport/ID photo, 35×45mm format, perfectly front-facing looking directly at camera, sharp focus, head straight, symmetric composition, forehead and eyebrows must be visible"` |
| `"id"` | `"Professional ID photo, 30×40mm format, perfectly front-facing looking directly at camera, clean background, sharp focus, approachable yet professional expression"` |

**설계 근거**:
- passport: 현행 PURPOSE_PROMPTS.passport 기반 + 규격 사이즈 명시
- id: 현행 PURPOSE_PROMPTS.resume + color_portrait 통합. "이력서/학생증/사원증" 공통 프롬프트
- 기획안 §3-1: "여권/신분증"(passport)과 "증명사진"(id) 2택

### [2] SUBJECT 레이어 — 인물 프롬프트

| gender | age | 영문 프롬프트 |
|--------|-----|-------------|
| `"f"` | `"baby"` | `"This person is a baby girl (infant/toddler)."` |
| `"f"` | `"child"` | `"This person is a young girl (child, under 12)."` |
| `"f"` | `"teen"` | `"This person is a teenage girl (13-18)."` |
| `"f"` | `"adult"` | `"This person is an adult woman."` |
| `"m"` | `"baby"` | `"This person is a baby boy (infant/toddler)."` |
| `"m"` | `"child"` | `"This person is a young boy (child, under 12)."` |
| `"m"` | `"teen"` | `"This person is a teenage boy (13-18)."` |
| `"m"` | `"adult"` | `"This person is an adult man."` |

**설계 근거**:
- 현행은 `"female/woman"` 형태 → baby/child에 부자연스러움
- v5: 연령별로 자연스러운 영문 표현 사용

**여성 분기**: shirtColor 시 `"blouse"` 대체
```
여성: "...with a {shirtColor} blouse{tieClause}."
남성: "...with a {shirtColor} dress shirt{tieClause}."
```

**tieClause 조립** (tieColor + tiePattern):

| tieColor | tiePattern | tieClause |
|----------|-----------|-----------|
| `"notie"` | (무시) | `""` (넥타이 조항 생략) |
| `"navy"` | `"solid"` | `" and a solid navy tie"` |
| `"navy"` | `"stripe"` | `" and a navy striped tie"` |
| `"wine"` | `"solid"` | `" and a solid wine tie"` |
| `"wine"` | `"stripe"` | `" and a wine striped regimental tie"` |
| `"black"` | `"solid"` | `" and a solid black tie"` |
| `"black"` | `"stripe"` | `" and a black striped tie"` |

**조합 예시**:
```
// 디폴트 정장 (네이비 수트 + 화이트 셔츠 + 네이비 민타이)
남성: "Dress this person in a dark navy formal business suit with a white dress shirt and a solid navy tie."
여성: "Dress this person in a dark navy formal business suit with a white blouse and a solid navy tie."

// 노타이
"Dress this person in a gray formal business suit with a light blue dress shirt."

// 와인 스트라이프
"Dress this person in a black formal business suit with a white dress shirt and a wine striped regimental tie."
```

**넥타이 성별 제한**: 현행 코드는 tie를 남성에만 적용 (L283: `gender === 'male'`). v5 기획안에는 성별 제한 명시 없음. **쌍아/작가님 결정 필요**: 여성도 넥타이 표시할 것인지.

### [4] HAIR 레이어

| hair | 영문 프롬프트 |
|------|-------------|
| `"default"` | *(생략 — 프롬프트에 포함 안 함)* |
| `"tidy"` | `"neatly groomed and tidy hair"` |
| `"updo"` | `"hair styled up neatly (updo)"` |

**설계 근거**: 현행 `"tidy"` → `"neatly groomed hair"`, `"up"` → `"hair tied up neatly"`. v5에서 키 이름만 변경(`up`→`updo`), 프롬프트는 유사하게 유지.

### [5] BACKGROUND 레이어

| bgColor | 영문 프롬프트 |
|---------|-------------|
| `"white"` | `"pure white (#FFFFFF) background"` |
| `"gray"` | `"neutral gray (#9CA3AF) studio background"` |
| `"blue"` | `"soft blue (#4A90D9) studio background"` |
| `"beige"` | `"warm beige (#D4B896) studio background"` |

**현행에서 삭제**: `pink`, `yellow` (v5 기획안에 없음)

**format="passport" 강제**: bgColor가 뭐든 `"white"` 고정. 서버에서 오버라이드.

### [6] CONSTRAINT 레이어 (고정)

```
Keep the person's face and body exactly the same — only apply the specified styling.
DO NOT change apparent gender or age.
```

→ 현행 유지. 변경 불필요.

### v5 buildPromptV5() 의사코드

```javascript
function buildPromptV5(body) {
  const { format, gender, age, clothing, clothingColor,
          suitColor, shirtColor, tieColor, tiePattern,
          hair, bgColor } = body;

  const parts = [];

  // [1] FORMAT
  parts.push(`[FORMAT] ${FORMAT_PROMPTS[format]}`);

  // [2] SUBJECT
  parts.push(`[SUBJECT] ${SUBJECT_PROMPTS[gender][age]}`);

  // [3] OUTFIT
  if (clothing === 'default') {
    parts.push('[OUTFIT] Keep current clothing as-is. Only ensure it looks neat and tidy.');
  } else if (clothing === 'change') {
    // 영유아/어린이 전용
    parts.push(`[OUTFIT] Dress this child in a clean ${CHILD_COLOR_PROMPTS[clothingColor]} top, age-appropriate and neat.`);
  } else if (clothing === 'casual') {
    parts.push(`[OUTFIT] Dress this person in a ${CASUAL_COLOR_PROMPTS[clothingColor]} smart casual top, clean and neat.`);
  } else if (clothing === 'suit') {
    const suitDesc = SUIT_COLOR_PROMPTS[suitColor];
    const shirtType = gender === 'f' ? 'blouse' : 'dress shirt';
    const shirtDesc = SHIRT_COLOR_PROMPTS[shirtColor];
    let tieClause = '';
    if (tieColor && tieColor !== 'notie') {
      const tieDesc = buildTiePrompt(tieColor, tiePattern);
      tieClause = ` and ${tieDesc}`;
    }
    parts.push(`[OUTFIT] Dress this person in a ${suitDesc} formal business suit with a ${shirtDesc} ${shirtType}${tieClause}.`);
  }

  // [4] HAIR
  if (hair && hair !== 'default') {
    parts.push(`[HAIR] ${HAIR_PROMPTS_V5[hair]}`);
  }

  // [5] BACKGROUND
  const effectiveBg = format === 'passport' ? 'white' : bgColor;
  parts.push(`[BACKGROUND] ${BG_PROMPTS_V5[effectiveBg || 'white']}`);

  // [6] CONSTRAINT
  parts.push("[CONSTRAINT] Keep the person's face and body exactly the same — only apply the specified styling. DO NOT change apparent gender or age.");

  return `${IDENTITY_PRESERVATION}\n\n[IMAGE-TO-IMAGE TRANSFORM]\n${parts.join('\n')}`;
}
```

## 5. 하위호환 방안 (3-E)

### 옵션 비교

| 방안 | 장점 | 단점 | 권장 |
|------|------|------|------|
| A. 필드 자동 감지 | 클라이언트 수정 최소 | 감지 로직 복잡, 엣지 케이스 | ❌ |
| B. 엔드포인트 분리 (`/api/idgen/v5`) | 깔끔한 분리, 롤백 용이 | URL 변경, 클라이언트도 반드시 수정 | ❌ |
| **C. 버전 필드 추가** (`v: 5`) | 현행 URL 유지, 분기 명확 | 약간의 조건문 | **✅ 권장** |

### 권장안: 버전 필드 기반 분기

```javascript
// server.js /api/idgen
app.post('/api/idgen', async (req, res) => {
  const body = req.body;
  const schemaVersion = body.v || 4;  // v 필드 없으면 구버전(4)

  const instruction = schemaVersion >= 5
    ? buildPromptV5(body)    // 새 빌더
    : buildPrompt(body);     // 기존 빌더 (그대로 유지)

  // ... 이하 동일
});
```

**구버전 클라이언트 처리**:
- `v` 필드 없음 → `buildPrompt()` (현행 로직 그대로)
- `v: 5` → `buildPromptV5()` (새 로직)

**장점**:
1. 엔드포인트 URL 변경 없음 → 클라이언트 config.js 수정 불필요
2. 구버전 클라이언트가 계속 동작 (전환 기간 안전)
3. v5 클라이언트는 `v: 5` 추가만 하면 됨
4. 전환 완료 후 `buildPrompt()` 제거하면 클린업 끝

**전환 기간 판단 기준**:
- Cloud Run은 단일 버전 배포 → 프론트/백엔드 동시 배포가 가능하므로 전환 기간은 짧아도 됨
- 다만 사용자 브라우저 캐시로 구 JS가 로딩될 수 있으므로 최소 48시간 하위호환 유지 권장

## 6. 설계 판단이 필요한 사항 (쌍아/작가님 결정 필요)

### D-1. 여성 넥타이 적용 여부

현행 코드 (server.js L283): `if (tie && tie !== 'none' && gender === 'male')` — 남성만 넥타이 적용.

v5 기획안에는 성별별 넥타이 제한 명시 없음. 정장 선택 시 여성도 넥타이 옵션이 보이는 것인지?

**선택지**:
- (A) 현행 유지 — 남성만 넥타이 적용
- (B) 성별 무관 — 여성도 넥타이 적용 가능

→ 프롬프트에서 여성+타이 조합이 자연스러운 결과를 내는지 테스트 필요

### D-2. baby 연령대의 프롬프트 범위

현행 서버에 `baby` 매핑 없음 (클라이언트 prep.js에서 `AGE_TO_LEGACY`로 `child`로 변환 후 전송).

v5에서 `baby`를 서버에 직접 전송할 때:
- `baby`에 대한 SUBJECT 프롬프트: "infant/toddler" vs "baby"?
- `baby` + `clothing="change"`: "Dress this child in..." 공통 사용 vs "baby" 전용 표현?

### D-3. clothingColor 영유아/캐주얼 분리 검증

기획안에서 clothingColor의 enum이 clothing 값에 따라 달라진다:
- change (영유아): skyblue, pink, lemon, green
- casual (중고생/성인): beige, blue, wine, green

같은 필드에 다른 값 세트 → **서버에서 clothing 값으로 유효성 검증 필요**.
green은 양쪽에 공존하나 의미가 다를 수 있음 (영유아 초록 vs 성인 초록). 프롬프트는 `"green"`으로 동일하게 처리해도 AI가 연령에 맞게 해석할 것으로 예상. **확인 필요**.

### D-4. format="passport" 시 배경 외 추가 제약

기획안 §3-3: "여권/신분증은 배경 흰색 고정" — bgColor 오버라이드는 명확.

추가로:
- 여권 시 expression 관련 고정 프롬프트 필요한가? (v5에서 expression 삭제되었으므로 FORMAT_PROMPTS에 "neutral expression" 포함?)
- 현행 PURPOSE_PROMPTS.passport에는 "forehead and eyebrows must be visible" 포함 → v5 FORMAT_PROMPTS에도 유지?

**제안**: passport FORMAT 프롬프트에 이마/눈썹 노출 + 무표정 정면을 포함시키고, id FORMAT에는 포함하지 않음.

### D-5. Gemini API 모델 + config 변경 여부

현행 (L657-658):
```
models/gemini-3-pro-image-preview:generateContent
generationConfig: { imageConfig: { aspectRatio: '3:4' } }
```

v5에서 format에 따라 aspectRatio를 분기해야 하는지:
- passport (3.5×4.5): 비율 ≈ 0.778 → `3:4` (0.75)와 근사 ✅
- id (3×4): 비율 = 0.75 → `3:4` 정확 일치 ✅

→ **aspectRatio 변경 불필요**. 두 규격 모두 `3:4`로 충분.

### D-6. SPA /api/generate 경로의 v5 대응 범위

`/api/generate` (L578-619)는 `generatePhoto()` + `getOutfitPrompt()` 사용 (별도 로직).
이 경로도 v5 대응이 필요한지, 아니면 MPA `/api/idgen` 전용인지?

**현재 판단**: v5는 MPA 퍼널 대상. SPA(`/app`)는 별도 계획이 없다면 현행 유지.
