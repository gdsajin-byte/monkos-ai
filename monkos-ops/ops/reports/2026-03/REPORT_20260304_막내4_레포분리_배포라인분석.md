## C. 분리 시나리오 (Phase 1→2→3)

### 작가님 방침 재확인
> "완전 클론 상태로 두 레포를 세팅 → 배포라인만 정돈 → 한쪽씩 덜어내기"

### Phase 1: 완전 클론

```
monk_project/ (원본 — 건드리지 않음)
  ├── git clone → monk_kr_project/    (전체 복사)
  └── git clone → monkos_ai_project/  (전체 복사)
```

**절차**:
1. GitHub에 `monk_kr_project`, `monkos_ai_project` 리포지토리 생성
2. 원본에서 `git clone --mirror` 또는 `git push --mirror`로 전체 히스토리 복사
3. 양쪽 레포에서 `.git/config`의 remote origin을 각자의 GitHub URL로 변경
4. 원본 레포는 아카이브 상태로 보존 (삭제하지 않음)

**롤백**: 원본 레포가 그대로이므로 언제든 클론 재시작 가능

## F. 종합 권장안

### 1. 분리는 유효하다

교차참조 전수 결과, **코드 레벨 import는 0건**이다. 모든 교차는 **URL 기반 HTTP 호출** 또는 **UI 링크**이므로, 레포가 분리되어도 런타임에 끊어지는 것은 없다. `functions/api/`(Image Pro)는 이미 "monkos.ai 교차 호출 제거" 완료 상태.

### 2. 핵심 결정 포인트

| 결정사항 | 선택지 | 권장 |
|----------|--------|------|
| photolab 코드 소속 | monk.kr 잔존 vs monkos.ai 이관 | **monk.kr 잔존** (_redirects로 이미 비활성이나, 코드 이력 보존. Phase 3에서 최종 판단) |
| photolab/engine (Cloud Run) | monk.kr 소속 vs monkos.ai 이관 | **미배포 상태이므로 Phase 1~2에서는 보류**, Phase 3에서 판단 |
| GCS 공개 URL 참조 | monk.kr 자체 CDN 이관 vs GCS URL 유지 | **GCS URL 유지** (읽기 전용, 레포 분리와 무관) |
| CLAUDE.md | 양쪽 복사 vs 분할 | **양쪽 동일 복사** + 상대 레포 인지 섹션 |
| monkos-ops | 별도 레포 vs 클론 후 분기 | **클론 후 분기** (현실적) |
| _saga (15,951건) | 양쪽 포함 vs 별도 아카이브 | **별도 아카이브 또는 양쪽 .claudeignore** |

### 3. 권장 실행 순서

```
Phase 1: 완전 클론 (안전, 가역)
  ├─ GitHub에 2개 레포 생성
  ├─ git push --mirror로 전체 히스토리 복사
  └─ 원본 레포 아카이브 보존

Phase 2: 배포라인 정돈 (안전, 가역)
  ├─ 각 레포에 .claudeignore로 상대 측 코드 차단
  ├─ 상대 측 deploy.sh 비활성화
  ├─ CLAUDE.md에 상대 레포 인지 섹션 추가
  └─ 검증: 각 레포에서 자기 배포만 가능한지 확인

Phase 3: 덜어내기 (비가역이나 Git 복원 가능)
  ├─ monk_kr에서 monkos_AI/, apps/(Cloud Run) 물리 삭제
  ├─ monkos_ai에서 MONK_kr/, functions/ 물리 삭제
  ├─ 아카이브 디렉토리 일괄 정리
  └─ 검증: 각 레포 독립 배포 + 서비스 정상 동작
```
