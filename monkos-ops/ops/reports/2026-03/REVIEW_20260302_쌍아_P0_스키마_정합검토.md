## 2. 사실관계 충돌 — 1건

### `monkos_cropped` 키 상태

| 출처 | 판정 | 근거 |
|------|------|------|
| **막내3** (이전 보고서 + 현 §2) | "setItem 0건. 유령 키. 삭제 안전" | `sessionStorage.setItem('monkos_cropped', ...)` 직접 grep 미발견 |
| **막내1** (§1-3) | "**현역 키**. result.js:400, result.js:568 두 곳에서 `saveSessionData('cropped', ...)` 경유 저장" | `saveSessionData` 헬퍼가 `monkos_` 접두사 자동 추가 → 직접 grep 미탐지 |

**판정**: 막내1이 맞다. `saveSessionData('cropped', ...)` → 내부에서 `sessionStorage.setItem('monkos_cropped', ...)` 호출. 막내3의 직접 grep 방식으로는 헬퍼 경유 저장이 미탐지.

**영향**: 막내3 §2 레거시 정리 대상에서 `monkos_cropped` 제외. 실제 레거시 잔재는 `monkos_user`(portal auth.js 4줄) **1건만**.

## 4. 보완 전략 — 레이어별 조합

3명의 전략은 **충돌이 아니라 레이어별 역할 분담**으로 조합 가능:

```
[클라이언트 전체 전략] 막내3 → 빅뱅 전환 + 세션 클리어 가드
[클라이언트 키 정리]   막내1 → monkos_schema_version 태그로 구키 자동 정리
[서버 API 하위호환]    막내2 → v 필드 (body.v = 5)로 48시간 하위호환
```

### 조합 시나리오

```
1. v5 배포 (빅뱅 — prep.js/camera.js/result.js/shared.js 원자적 교체)
2. prep.js init() → monkos_schema_version 체크 → 구키 정리 (막내1)
3. result.js → /api/idgen에 v:5 추가 전송 (막내2)
4. server.js → v >= 5이면 buildPromptV5(), 아니면 buildPrompt() (막내2)
5. 48시간 경과 → 구 buildPrompt() 삭제 가능 (캐시 만료)
```

## 6. 보고서 품질 평가

| 막내 | 완료 조건 | 특기 사항 | 오류 |
|------|----------|----------|------|
| 막내1 | ✅ 전수 달성 | `monkos_cropped` 오류 발견+정정 우수. 흐름도 코드레벨 추적 정밀 | 없음 |
| 막내2 | ✅ 전수 달성 | 프롬프트 빌더 역분석 핵심 산출물. `buildPromptV5()` 의사코드 작성 | 없음 |
| 막내3 | ⚠️ 오류 1건 | `monkos_cropped` 유령키 오판 (직접 grep 한계). 전환 전략 분석 자체는 우수 | `monkos_cropped` 판정 오류 |

### 오류 원인 분석

막내3의 `monkos_cropped` 오판은 **이전 보고서(저장소 전수조사)**에서 발생한 것이 현 보고서까지 전파.
원인: `sessionStorage.setItem('monkos_cropped', ...)` 패턴으로 직접 grep → `saveSessionData('cropped', ...)` 헬퍼 경유 패턴 미탐지.
교훈: **헬퍼 함수 경유 저장은 직접 grep으로 잡히지 않는다**. sessionStorage 전수 조사 시 헬퍼 함수 체인까지 추적 필요.
