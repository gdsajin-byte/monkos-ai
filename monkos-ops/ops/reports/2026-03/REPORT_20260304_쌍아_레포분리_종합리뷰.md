## 2. 핵심 판단: 분리는 유효하고 안전하다

### 2-1. 코드 레벨 import = 0건

막내4가 전수 grep으로 확인한 가장 중요한 사실:

> **두 레포 간 코드 레벨 import/require는 단 한 건도 없다.**
> 모든 교차는 URL 기반 HTTP 호출 또는 UI 링크.
> 레포를 분리해도 런타임에 끊어지는 것이 없다.

`functions/api/`(Image Pro)는 이미 "monkos.ai 교차 호출 제거" 주석 달린 상태.
`MONK_kr/config.js`의 PORTAL/IDPHOTO 참조도 빈 문자열로 차단 완료.

### 2-2. 교차참조 전수 현황

| 등급 | 건수 | 성격 | 분리 시 영향 |
|------|------|------|-------------|
| CRITICAL | 6건 | photolab config → monkos.ai API URL, Portal CORS 허용 | **영향 없음** — HTTP 호출은 도메인 기반, 레포 위치 무관 |
| HIGH | 8건 | 301 리다이렉트, UI 링크, SEO canonical | **영향 없음** — 외부 URL 링크 |
| MEDIUM | 6건 | OG이미지, 카카오 공유 URL | **영향 없음** — 에셋 URL |
| LOW/NONE | 16건 | 레거시/주석/이미 차단 완료 | 없음 |

**방향별**: monk.kr → monkos.ai = 17건 / monkos.ai → monk.kr = 4건 (CORS + postMessage origin)

### 2-3. 공유 리소스 판정

| 리소스 | 판정 | 근거 |
|--------|------|------|
| GCS `monk-ai-images` | **분리 무관** | monk.kr은 읽기 전용 공개 URL. 레포 위치와 무관 |
| Firestore `monkos` | **monkos.ai 전용** | monk.kr은 Portal HTTP API 경유만 |
| D1/R2 | **양쪽 미사용** | apps/monk_imagen4 바인딩만 잔존 (아카이브) |
| GEMINI_API_KEY | **이미 분리됨** | CF Secret vs GCP Secret Manager, 별도 저장소 |
| Vertex AI/토스/Lemon | **monkos.ai 전용** | monk.kr 미사용 |

## 3. 3-Phase 분리 시나리오 검수

작가님 방침("완전 클론 → 배포라인 정돈 → 한쪽씩 덜어내기") 기반.

| Phase | 작업 | 가역성 | 쌍아 검수 |
|-------|------|--------|----------|
| 1: 완전 클론 | git push --mirror × 2개 레포 | **완전 가역** (원본 보존) | 적정. 원본은 아카이브로 보존 |
| 2: 배포라인 정돈 | .claudeignore + deploy.sh 비활성 | **가역** (.claudeignore 제거로 복원) | 적정. 에이전트 격리 + 배포 격리 동시 달성 |
| 3: 덜어내기 | monk_kr에서 monkos_AI/ 삭제, 역방향도 | **Git 히스토리 복원 가능** | 적정. Phase 2 검증 완료 후 진행 |

### Phase 2→3 전환 기준 (쌍아 제안)

Phase 3 진입 전 다음 항목 전부 확인:
1. 각 레포에서 **자기 배포만** 성공하는가 (교차 배포 불가 확인)
2. 에이전트가 **상대 레포 코드를 참조하지 않는가** (3회 이상 세션 테스트)
3. CLAUDE.md 경계 선언이 **에이전트 행동에 반영**되는가
4. 양쪽 프로덕션 서비스가 **정상 동작**하는가
