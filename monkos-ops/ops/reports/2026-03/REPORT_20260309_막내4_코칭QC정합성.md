## 중요 발견: 프롬프트 3중 구조

프롬프트가 **3곳에 독립 존재**하며, 동기화되지 않음.

| 위치 | 용도 | 코칭 키 | 언어 |
|------|------|---------|------|
| `portal/lib/prompts.js` | Portal 챗봇 (prep/coaching/qc 채널) | `id_photo`, `resume` | 한국어 |
| `idphoto-kr/server.js` (로컬) | **KR 실제 WebSocket Gemini Live 코칭** | `passport`, `id` | 한국어 |
| `idphoto-jp/server.js` (로컬) | **JP 실제 WebSocket Gemini Live 코칭** | `passport`, `id` | 일본어 |

> **KR/JP 앱의 실제 코칭은 각 server.js의 로컬 프롬프트를 사용.**
> Portal prompts.js는 Portal 챗봇 채널에서만 사용됨.
> 이 3곳 간 **스타일 키·트리거 문구·옵션 매핑이 불일치**.

## 임무 A: PREP_SYSTEM_PROMPT 점검

**파일**: `portal/lib/prompts.js:188-207`
**사용처**: `portal/lib/chat-engine.js:150` (채널 `prep`)

### A-1. "여권/이력서/학생증 등" — v5 옵션과 일치?

| 프롬프트 기재 | v5 실제 옵션 | 판정 |
|-------------|-------------|------|
| 여권 | `passport` | ✅ |
| 이력서 | `id` (증명사진) | ⚠️ 이력서≠증명사진이지만 용도상 포괄 |
| 학생증 | 없음 | ❌ |

- `PHOTO_SPECS`에는 `passport`(35x45mm)와 `id`(30x40mm) 2종만 존재
- "학생증"은 별도 규격이 없으며, `id` 규격으로 커버됨
- **❌ 불일치**: 존재하지 않는 규격을 별도 옵션처럼 나열. "여권/증명사진" 또는 "여권/이력서·증명사진"으로 수정 권장

### A-2. "한국/일본 증명사진 규격 차이 안내 가능"

| 규격 | KR | JP |
|------|-----|-----|
| passport | 35x45mm | 35x45mm |
| id | 30x40mm | 30x40mm |

- **❌ 불필요**: 양국 규격이 동일. "차이 안내 가능"은 오해 유발
- 삭제하거나 "한국/일본 규격 안내 가능"으로 수정 권장

### A-3. "사용자 언어에 맞춰 응답 (한국어/일본어/영어)"

- prep 채널은 Portal `chat-engine.js:149-156`에서 정의
- Portal 웹 챗봇의 `channel=prep`으로 호출됨
- **KR 앱에는 prep 전용 모듈 없음** (`modules/prep.js` 파일 부재)
- KR 앱의 `/prep` 라우트는 `prep.html` 정적 페이지 서빙만 함
- JP 앱도 동일 구조
- **⚠️ prep 채널이 실제로 사용되는지 불확실** — Portal 챗봇에서 prep 채널을 어떤 경로로 호출하는지 확인 필요
- 다국어 지원 자체는 문제없음 (Portal 챗봇은 다국어 대응)

### A-4. 내부 기술명 노출

- ✅ `PREP_SYSTEM_PROMPT`에 Gemini/Google AI 등 기술명 없음
- ✅ "MONKOS AI" / "AI 코치"로만 표현

## 임무 B: COACHING_INSTRUCTIONS 점검

### B-1. Portal vs KR/JP 스타일 키 불일치

| Portal prompts.js | KR server.js | JP server.js |
|-------------------|-------------|-------------|
| `id_photo` | `passport` | `passport` |
| `resume` | `id` | `id` |

- **❌ 키 완전 불일치**: Portal은 `id_photo`/`resume`, 실제 앱은 `passport`/`id`
- Portal의 `id_photo`는 KR의 `passport`와 내용이 거의 동일 (여권/증명사진)
- Portal의 `resume`는 KR의 `id`와 거의 동일 (이력서)
- 용도별 매핑은 맞지만 키 이름이 다름

### B-1a. 트리거 문구 불일치 (핵심)

| 컴포넌트 | 트리거 문구 | isReady 정규식 |
|---------|-----------|---------------|
| Portal prompts.js | "좋아요! 지금 촬영하세요" | N/A (READY_KEYWORDS 사용) |
| KR server.js 프롬프트 | "이제 촬영할게요!" | `/이제\s*촬영할게\|완벽\|좋아요\|좋습니다/` |
| JP server.js 프롬프트 | "いいですね！今撮影してください" | `/今\s*撮影してください\|完璧\|いいですね/` |
| Portal READY_KEYWORDS | — | `['좋아요', '완벽', '촬영하세요', 'OK', '좋습니다', '잘 맞', '훌륭', '지금']` |

- **❌ Portal 프롬프트의 트리거 "지금 촬영하세요"가 KR server의 isReady 정규식에 매칭되지 않음**
  - KR regex는 "이제 촬영할게"를 찾음 ← "지금 촬영하세요"는 해당 안 됨
- **✅ KR server 자체는 정합**: 프롬프트 "이제 촬영할게요!" ↔ regex "이제\s*촬영할게" 매칭
- **✅ JP server 자체는 정합**: 프롬프트 "今撮影してください" ↔ regex "今\s*撮影してください" 매칭
- Portal prompts.js의 트리거와 READY_KEYWORDS는 Portal 챗봇에서만 사용되므로, **실제 서비스 영향은 없음** (KR/JP 앱은 자체 프롬프트 사용)

### B-1b. 체크 순서 5항목 — 정합성

| 항목 | Portal `id_photo` | KR `passport` | KR `id` |
|------|-------------------|--------------|---------|
| 1. 정면 응시 | ✅ | ✅ | ✅ |
| 2. 조명 균일 | ✅ | ✅ | ✅ |
| 3. 표정 | ✅ 무표정/미소 | ✅ 무표정/미소 | ✅ 호감가는 미소 |
| 4. 눈썹 | ✅ | ✅ | — (자세로 대체) |
| 5. 얼굴 라인 | ✅ | ✅ | — (헤어·의상 정돈) |

- ✅ Portal `id_photo` ≒ KR `passport` (내용 거의 동일)
- ✅ KR `id`(이력서)는 체크 항목이 다름 (자세·의상 중점) — 용도 차이로 적절

### B-2. resume 스타일 사용 여부

- Portal `COACHING_INSTRUCTIONS.resume` 존재
- KR server.js: `passport`, `id` — **resume 키 없음**
- JP server.js: `passport`, `id` — **resume 키 없음**
- v5 `V5_OPTIONS.format`: `['passport', 'id']` — **resume 없음**
- **❌ Portal의 `resume`는 실제 앱에서 사용되지 않는 잔재**. 내용상 KR `id`와 동일 역할

### B-3. READY_KEYWORDS — JP 언어 문제

| 컴포넌트 | 키워드 언어 | 판정 |
|---------|----------|------|
| Portal READY_KEYWORDS | 한국어만 | ❌ JP에서 사용 시 문제 |
| KR server.js isReady | 한국어 regex | ✅ KR 전용 |
| JP server.js isReady | 일본어 regex | ✅ JP 전용 |

- **❌ Portal READY_KEYWORDS에 일본어 키워드 없음**: `いいですね`, `完璧`, `撮影してください` 미포함
- **✅ 실제 서비스 영향 없음**: KR/JP 앱은 각 server.js의 자체 isReady regex 사용. Portal READY_KEYWORDS는 Portal 챗봇 코칭 채널에서만 사용
- **⚠️ Portal 코칭 채널이 JP 사용자에게 노출되면 ready 판정 불가**

### B-4. buildCoachingPrompt() — v5 옵션 매핑 불일치

**파일**: `portal/lib/prompts.js:244-271`

| buildCoachingPrompt 파라미터 | v5 실제 옵션 | 판정 |
|---------------------------|-------------|------|
| `style` (`id_photo`/`resume`) | `format` (`passport`/`id`) | ❌ 키 불일치 |
| `purpose` | 없음 | ❌ v5에 존재하지 않음 |
| `clothing` (`suit`/`shirt`/`casual`/`uniform`) | `clothing` (`default`/`change`/`casual`/`suit`) | ❌ `shirt`→없음, `uniform`→없음, `change`→없음 |
| `clothingColor` (`black`/`navy`/`charcoal`/`white`/`beige`/`wine`/`pastel`) | child: `skyblue`/`pink`/`lemon`/`green`, adult: `beige`/`blue`/`wine`/`green` | ❌ 대부분 불일치 |
| `tie` (단일 합성키) | `tieColor` + `tiePattern` (2필드) | ❌ 구조 불일치 |
| `hair` (`tidy`/`up`/`down`) | `hair` (`default`/`tidy`/`updo`) | ❌ `up`→`updo`, `down`→없음 |
| `expression` | 없음 | ❌ v5에 존재하지 않음 |
| — | `suitColor` | ❌ 미처리 |
| — | `shirtColor` | ❌ 미처리 |
| — | `bgColor` | ❌ 미처리 |
| `gender` (`male`) | `gender` (`m`/`f`) | ❌ 값 형식 불일치 |

**총평**: buildCoachingPrompt()는 v5 이전 스키마 기준으로 작성됨. **v5 옵션과 전면 불일치**.
현재 실제 앱에서는 이 함수를 사용하지 않음 (KR/JP는 자체 WebSocket 코칭 사용).

## 핵심 발견 요약

### 1. 프롬프트 3중 분산 구조
- Portal `prompts.js`, KR `server.js`, JP `server.js`에 각각 독립된 코칭/QC 프롬프트 존재
- **동기화 메커니즘 없음** → 수정 시 3곳 동시 반영 필요

### 2. Portal prompts.js = v5 이전 잔재

- `COACHING_INSTRUCTIONS` 스타일 키(`id_photo`/`resume`)가 v5(`passport`/`id`)와 불일치

- Portal 챗봇의 코칭 채널로 사용될 때만 영향

### 3. JP 코칭 언어 문제 — 현재 안전
- JP server.js는 일본어 자체 프롬프트 + 일본어 isReady regex 사용 → **✅ 정상**
- Portal READY_KEYWORDS는 한국어만 → Portal 코칭이 JP에 노출 시 문제 발생
- **현재 JP 앱은 Portal 코칭을 사용하지 않으므로 안전**

### 4. QC 재활성화 시 필요 작업
- gender 매핑: `'m'`/`'f'` → `'male'`/`'female'` 변환 추가
- ageMap: `baby` 추가
- 프롬프트 간소화: 사용하는 4개 필드만 요청 → 앵무새 문제 완화 가능
