### 4. MEMORY.md 중복 정리

**판정: ✅ 중복 최소. 대규모 정리 불필요**

#### 분석

MEMORY.md는 **디바이스별 행동강령**(로컬, Git 미추적)이고, 헌법/법률은 **프로젝트 공통 규범**(CLAUDE.md, Git 추적)이다. 역할이 본질적으로 다르다.

| MEMORY.md 항목 | 헌법 격상 여부 | 정리 필요성 |
|---------------|-------------|-----------|
| "이 디바이스: iMac" | 아님 (디바이스 맵은 신2조이나 MEMORY는 *자기 디바이스*만 기술) | ❌ 유지 |
| "세션 로그 타임스탬프 규칙" (역추적 의무) | 신1조 1항은 타임스탬프 원칙. 역추적은 ch3 4조 특칙 | ❌ 유지 (운영 리마인더) |
| "세션 로그 파일명 패턴" | 법률 ch3 또는 sessions/README 영역 | ❌ 유지 (디바이스별 퀵 레퍼런스) |
| "세션 시작/마감 프로세스" | ch3 3조·5조 (이미 법률 수준) | ⚠️ 슬림화 가능 — "ch3 3조·5조 참조"로 축약 가능 |
| "쌍아 본분" | MEMORY 고유. 헌법 아님 | ❌ 유지 |
| "지시서 운용 원칙" | ch1 영역. 헌법 아님 | ❌ 유지 |

**실질적 중복**: MEMORY.md에서 헌법 내용과 직접 중복되는 항목은 **0건**. 법률 내용의 **운영 리마인더** 성격 항목이 3건 있으나, 이는 "매 세션 자동 로딩되는 퀵 레퍼런스"라는 MEMORY의 본래 목적에 부합.

**권고**:
- 헌법 개편 시 MEMORY.md는 **현상 유지** 가능
- 단, "세션 시작/마감 프로세스" 항목은 "ch3 3조·5조 참조"로 축약하면 MEMORY 줄 수 절약 (현재 3줄→1줄)
- 헌법 조항 번호를 직접 참조하는 MEMORY 항목은 **0건**이므로 번호 변경에 따른 MEMORY 갱신 불필요
