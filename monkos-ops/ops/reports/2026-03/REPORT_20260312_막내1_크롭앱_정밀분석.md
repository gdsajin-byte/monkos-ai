## 1. crop-engine 코드 현황

### 1-1. server.js — 엔드포인트

| Method | Path | 역할 | 요청 스펙 | 응답 스펙 |
|--------|------|------|----------|----------|
| POST | `/api/crop` | 이미지 크롭 (핵심) | `{ image: "base64", format: "passport", country: "KR" }` | `{ success, cropped: "base64", fallback: bool, meta: {...} }` |
| GET | `/api/specs` | 지원 규격 목록 | 없음 | `{ specs: [{ key, name, width, height, ... }] }` |
| GET | `/health` | 헬스체크 | 없음 | `{ status: "ok", model: "loaded"|"not_loaded" }` |

- 프레임워크: **Express 미사용**, `http.createServer` 직접 구현
- CORS: `Access-Control-Allow-Origin: *` (전역 허용)
- Body 제한: 20MB
- 모델 프리로드: `start()` → `initFaceDetector()` 후 서버 리스닝
- 에러 핸들링: 500 응답 + `err.message` 반환

### 1-2. lib/crop.js — v2 크롭 알고리즘

**핵심 전환: 지시서 v1(정수리 앵커) → v2(눈 앵커 기반 조건부 배치)**

#### 배치 상수 (45mm 프레임 기준)

| 상수 | 값 | 의미 |
|------|-----|------|
| `EYE_POSITION_RATIO` | 0.43 | 눈 위치: 프레임 상단에서 43% |
| `HAIR_MARGIN_MIN` | 0.044 | 헤어탑 최소 여백: 2mm/45mm |
| `HAIR_VOLUME_RATIO` | 0.08 | 정수리 위 헤어 볼륨: 얼굴높이의 8% |
| `FACE_TARGET_MM` | 33 | 얼굴 타겟 크기 (mm) |
| `FACE_MIN_MM` | 32 | 축소 한계 (mm) |
| `FRAME_MM` | 45 | 프레임 높이 (mm) |
| `BOTTOM_MIN_RATIO` | 0.12 | 하단 최소: ~5.4mm (어깨선 가시) |

#### 계산 순서

1. **눈 위치 실측**: 양 눈 중심(Y) 산출
2. **정수리 추산**: 눈~턱 거리를 눈 위로 1:1 반전 (해부학 근사)
3. **헤어탑 추산**: 정수리 위 `faceHeight × 0.08` 추가
4. **스케일 결정**: 얼굴 타겟(33mm/45mm ≈ 0.733)에 맞춰 스케일
5. **눈 앵커 배치**: 눈이 프레임 상단 43%에 오도록 extractTop 결정
6. **조건부 보정**:
   - 6a. 헤어탑이 프레임 밖이면 extractTop 밀어내기
   - 6b. 밀어낸 후 하단 부족이면 스케일 0.5%씩 축소 (32mm까지)
7. **경계 보정**: 프레임이 이미지 밖으로 나가지 않도록
8. **sharp**: `resize(scale) → extract(frame) → withMetadata({ density: 300 })`

#### 특이사항
- v1 지시서의 `spec.faceRatio`, `spec.topMargin`을 **사용하지 않음** — crop.js 내부 상수가 우선
- `specs/formats.js`의 `faceRatio/topMargin/bottomMargin`은 현재 **dead code** (getSpec은 width/height만 실질 참조)
- 300 DPI 메타데이터 주입 (`withMetadata({ density: 300 })`)
- 폴백: `fallbackCrop()` — 얼굴 감지 실패 시 상단 커버 크롭

#### 메타 정보 출력
- `faceMM`: 실제 얼굴 크기 (mm)
- `topMarginMM`: 헤어탑 상단 여백 (mm)
- `bottomMarginMM`: 턱 아래 여백 (mm)
- `eyePositionPercent`: 눈 위치 (%)

### 1-3. lib/face-detect.js — FaceMesh 호출

#### 변경점 (v1 → 현재)

| 항목 | v1 (iMac 초기 구축) | 현재 (M1 세션 수정) |
|------|---------------------|---------------------|
| import | `@tensorflow/tfjs-node` | `@tensorflow/tfjs` (범용) |
| `CROWN_OFFSET_RATIO` | 0.12 | **0.30** |
| 코멘트 | "이마 상단" | "이마 중간 — 헤어라인+볼륨 감안하여 충분히 올려야 함" |

#### 핵심 로직
- MediaPipe FaceMesh (478 랜드마크, `refineLandmarks: true`)
- 서버 기동 시 1회 로드 (`initFaceDetector()`)
- sharp → removeAlpha → raw RGB → `tf.tensor3d` → `estimateFaces`
- 7개 핵심 랜드마크 추출: #10(이마), #152(턱), #159(좌눈), #386(우눈), #1(코끝), #234(좌윤곽), #454(우윤곽)
- 정수리 추산: `crownY = forehead.y - (faceHeight × 0.30)`
- tensor dispose 보장 (`finally` 블록)

#### 주의: face-detect.js vs crop.js 정수리 이중 추산
- **face-detect.js**: `crownY = #10.y - (#152.y - #10.y) × 0.30` → #10 기반 보정계수 방식
- **crop.js**: `crownY = eyeY - (chinY - eyeY)` → **눈~턱 1:1 반전**, face-detect.js의 crown을 무시
- **결론**: face-detect.js의 `crown` 출력값은 server.js의 응답 meta에만 포함되고, **실제 크롭 배치에는 미사용**

| 메모리 | 1Gi (tfjs-node: 적정. 부족 시 2Gi 상향 지시서에 명시) |

### 4-3. idphoto-kr/jp 연동

- **연동 코드 없음**. 지시서에서도 "별도 지시서" 명시.
- 현재 idphoto-kr의 `gcs-save.js:90-135` — Gemini Flash 기반 `cropToSpec` 독립 동작 중
- 향후 연동 포인트: result 페이지 → crop 페이지 진입, 또는 gcs-save에서 crop-engine API 호출
