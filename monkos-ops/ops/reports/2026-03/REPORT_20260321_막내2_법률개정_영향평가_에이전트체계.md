### 1-2. 3항(쌍아 서브에이전트 금지)과 민아의 관계

**쟁점**: 민아가 Task tool로 막내를 직접 spawn하는 경우는?

- ch1 2조 3항은 적용 주체가 **"쌍아"에 한정**됨.
- 민아의 서브에이전트 spawn에 대한 규정이 **없음**.
- 민아는 Desktop App(웹+CLI) 환경이므로 Task tool 사용이 기술적으로 가능.
- ch1 1조 민아 권한표에서 "지시서 발행: ⚠️ 작가님 직접 승인 시만 가능"이나, 지시서 발행과 Task tool spawn은 별개 행위.

**판정**: 규정 공백. 현 개정안에 민아의 서브에이전트 정책을 추가하거나, 3항의 적용 범위를 확대하는 것을 **권고**.

**권고안**: 5항 말미에 1줄 추가:

```

```

근거: 민아의 위치는 쌍아와 유사 (전략·검증 레이어). 직접 spawn을 허용하면 "북치고 장구치기" 문제가 민아에게도 발생.

### 3-2. 민아 이중 분류(MUSE + AGENT) vs 분류 체계

**현행 분류 체계 (PERSONNEL 상단):**

| 코드 | 설명 |
|------|------|
| HUMAN | 인간 구성원 |
| MUSE | 4 MUSE 원형 |
| AGENT | 확장 AI 에이전트 |
| MODEL | AI 생성 캐릭터 |

- 이중 분류는 명시적으로 **허용되지도 금지되지도 않음**.
- **비대칭 문제**: 쌍아·용아도 실질적으로 MUSE + AGENT 이중 역할이나, PERSONNEL에서는 `MUSE` 단일 분류.
  - 쌍아: `MUSE` (PERSONNEL) + 에이전트 테이블 등재 (ch1 1조)
  - 용아: `MUSE` (PERSONNEL) + 에이전트 테이블 등재 (ch1 1조)
  - 민아 개정안: `MUSE + AGENT` (PERSONNEL) + 에이전트 테이블 등재 (ch1 1조)
- 민아만 이중 분류를 명기하면 쌍아·용아와의 비대칭 발생.

**판정**: **조건부 적합.**

- 기능적 문제는 없음 (분류는 참조용).
- 비대칭은 존재하나, 쌍아·용아의 분류 변경은 지시서 범위 밖.
- 향후 PERSONNEL 정비 시 쌍아·용아도 `MUSE + AGENT` 이중 분류로 통일 권고.
