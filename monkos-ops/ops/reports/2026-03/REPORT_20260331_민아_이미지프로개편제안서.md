## 1. 현행 구조 및 문제점

### 현행 아키텍처

```
image.monkos.ai (Cloud Run: monk_imagen4/backend/server.js)

├── POST /generate  (T2I)
│   ├── model=fast  → Vertex AI imagen-4.0-fast-generate-001
│   └── model=ultra → Vertex AI imagen-4.0-ultra-generate-001
│
├── POST /refine    (I2I / EDIT / UPSCALE)
│   └── 모델 고정   → Google AI Studio gemini-3-pro-image-preview (Nano Banana Pro)
│
└── UI 선택지
    ├── Engine: Standard(fast) / Premium(ultra) — T2I에만 실제 적용
    └── Resolution: 1K / 2K
```

### 발견된 문제

| # | 문제 | 상세 | 영향 |
|---|------|------|------|
| 1 | **VARIATION 고정프롬프트 오염** | NEW GENERATE(T2I) 전환 시 fixedPrompt 필드가 초기화되지 않음. VARIATION의 "CRITICAL INSTRUCTION: Maintain the exact facial features..." 가 T2I에도 딸려감 | Imagen 4 Ultra에 참조 이미지 없이 "정체성 보존" 지시가 들어가 결과물 뒤틀림 |
| 2 | **Refine API responseModalities 미설정** | `generationConfig: { imageConfig: {} }` — Photolab(정상)에 있는 `responseModalities: ['TEXT', 'IMAGE']` 누락 | I2I 출력이 간헐적으로 일러스트/그림체로 출력 (preview 모델 동작 변동) |
| 3 | **모델 선택 불가** | I2I는 NB Pro 고정, T2I는 Imagen 4만 선택 가능. 새 모델(NB2 등) 추가 확장성 없음 | 모델 다양화 불가, 가격 최적화 불가 |
| 4 | **Standard/Premium 표기 혼동** | UI에 Standard/Premium으로 표시되나 실제로는 Imagen 4 fast/ultra. 사용자가 무슨 모델인지 알 수 없음 | 내부 운영 시 혼란 |

## 3. 개편안 — 원채널 + 모델 드롭다운

### 목표 아키텍처

```
image.monkos.ai (통합 백엔드)

├── POST /generate  (통합 엔드포인트)
│   ├── mode: "t2i" | "i2i" | "edit" | "upscale"
│   ├── model: (드롭다운 선택)
│   │   ├── "imagen4-fast"    → Vertex AI imagen-4.0-fast-generate-001
│   │   ├── "imagen4-ultra"   → Vertex AI imagen-4.0-ultra-generate-001
│   │   ├── "nb-pro"          → AI Studio gemini-3-pro-image-preview
│   │   └── "nb2"             → AI Studio gemini-3.1-flash-image-preview (NEW)
│   ├── resolution: "1k" | "2k" | "4k"
│   └── (기존 /refine 엔드포인트 → /generate로 통합 또는 유지)
│
└── UI
    ├── 모드 탭: NEW GENERATE / VARIATION / EDIT / UPSCALE
    ├── 모델 드롭다운: 모드별 호환 모델만 표시
    ├── 해상도: 1K / 2K / 4K
    └── 고정프롬프트: 모드별 독립 관리
```

### 모드-모델 호환 매트릭스

| 모델 | T2I | I2I | EDIT | UPSCALE | 비고 |
|------|-----|-----|------|---------|------|
| Imagen 4 Fast | ✅ | ❌ | ❌ | ❌ | T2I 전용 |
| Imagen 4 Ultra | ✅ | ❌ | ❌ | ❌ | T2I 전용, 최고 퀄리티 |
| NB Pro | ✅ | ✅ | ✅ | ✅ | 만능, 현행 검증됨 |
| NB2 | ✅ | ✅ | ✅ | ✅ | 만능, 50% 저렴, **I2I 품질 검증 필요** |

**UI 동작**: 모드 선택 시 비호환 모델은 드롭다운에서 비활성화(disabled + 사유 표시)

### 고정프롬프트 분리

현재 `fixedPrompt` 하나로 모든 모드가 공유하여 오염 발생.

**개편**: 모드별 독립 프롬프트 상태 관리

```
promptState = {
  t2i: {
    fixedPrompt: '',           // T2I에는 기본 비어있음
    mainPrompt: ''
  },
  i2i: {
    fixedPrompt: Ia.EN,        // VARIATION용 CRITICAL INSTRUCTION
    category: 'pose',          // pose/outfit/background/hair/lighting/accessory
    mainPrompt: ''
  },
  edit: { ... },
  upscale: { ... }
}
```

모드 전환 시 해당 모드의 프롬프트 상태만 로드. 교차 오염 원천 차단.

### Refine API responseModalities 수정

```javascript
// 현행 (문제)
generationConfig: { imageConfig: {} }

// 수정 (Photolab 정본 패턴 적용)
generationConfig: {
  responseModalities: ['TEXT', 'IMAGE'],
  imageConfig: { aspectRatio: finalAspectRatio }
}
```

## 4. 백엔드 설계

### Option A: 통합 엔드포인트

`/generate` 하나로 통합. `mode` + `model` 파라미터로 라우팅.

```javascript
app.post('/generate', async (req, res) => {
  const { mode, model, prompt, config, inputImage } = req.body;

  // 호환성 검증
  if (['imagen4-fast', 'imagen4-ultra'].includes(model) && mode !== 't2i') {
    return res.status(400).json({ error: 'Imagen 4 is T2I only' });
  }

  switch (model) {
    case 'imagen4-fast':
    case 'imagen4-ultra':
      return handleVertexImagen(req, res);    // Vertex AI 경로
    case 'nb-pro':
    case 'nb2':
      return handleGeminiImage(req, res);     // AI Studio 경로
  }
});
```

**장점**: 프론트엔드 단순, 엔드포인트 1개
**단점**: 기존 /generate, /refine 분리 구조 리팩토링 필요

### Option B: 기존 엔드포인트 유지 + model 파라미터 추가

- `/generate` (T2I): 기존 유지 + `model` 파라미터에 nb-pro, nb2 추가
- `/refine` (I2I/EDIT/UPSCALE): 기존 유지 + `model` 파라미터에 nb2 추가 + responseModalities 수정

**장점**: 변경 최소화, 안전
**단점**: 프론트엔드가 모드별로 다른 엔드포인트 호출해야 함 (현행과 동일)

### 권장: Option B

기존 검증된 구조 유지하면서 model 파라미터만 확장. 리스크 최소.
