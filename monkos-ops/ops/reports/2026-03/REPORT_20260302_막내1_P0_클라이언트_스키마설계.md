## 2. v5 스키마 초안 (3-B)

### 2-1. 네이밍 컨벤션 결정 분석

| 방안 | 장점 | 단점 | 판단 |
|------|------|------|------|
| A. `monkos_` 접두사 유지 | 기존 헬퍼(saveSessionData/loadSessionData) 재사용, 코드 변경 최소화 | 구키와 신키 혼재 가능성 | **권장** |
| B. `monkos_v5_` 신규 접두사 | 구키/신키 명확 분리, 전환기 충돌 방지 | 헬퍼 수정 필요, 코드량 증가 | 대안 |
| C. 단일 JSON 키 `monkos_funnel` | 한 키로 묶어 관리 편리 | 부분 갱신 시 전체 파싱+직렬화, 용량 비효율 | 비권장 |

**권장안: A안 (`monkos_` 접두사 유지)** — 전환 시 키 충돌은 §5 키 충돌 방지 전략으로 해결.

### 2-2. 직렬화 방식 결정 분석

| 방안 | 장점 | 단점 | 판단 |
|------|------|------|------|
| 개별 키 분리 | 기존 패턴 유지, 부분 읽기/쓰기 간단, 디버그 용이 | 키 수 증가 (현행 10 → 12) | **권장** |
| JSON 단일 키 | 트랜잭션 정합성 보장 (한 번에 읽고 쓰기) | 부분 갱신 불편, 파싱 오버헤드 | 비권장 |

**권장안: 개별 키 분리 유지** — 기존 `saveSessionData`/`loadSessionData` 패턴 그대로 활용.

### 2-3. v5 sessionStorage 스키마 초안

```javascript
// ═══ v5 sessionStorage 스키마 (클라이언트 관점) ═══
// 접두사: monkos_ (saveSessionData 헬퍼 자동 부여)
// 저장 대상: 페이지 간 데이터 전달이 필요한 필드만

// ──── [1p] 규격 ────
"monkos_format":        "passport" | "id"
// 현행 monkos_purpose(5값) + monkos_style(2값)을 대체
// format 하나로 규격 결정 (여권/신분증 vs 증명사진)

// ──── [2p] 성별 + 연령 ────
"monkos_gender":        "f" | "m"
// 현행 "male"/"female" → "f"/"m" 축소

"monkos_age":           "baby" | "child" | "teen" | "adult"
// 현행 5값(baby/preschool/elementary/teen/adult) → 4값
// 현행 AGE_TO_LEGACY 매핑(3값) 삭제

// ──── [3p] 스타일 — 의상 ────
"monkos_clothing":      "default" | "change" | "casual" | "suit"
// 현행 "as_is" → "default"
// "shirt"/"uniform" 삭제, "change" 신설(영유아용)

"monkos_clothingColor": null | "skyblue" | "pink" | "lemon" | "green" | "beige" | "blue" | "wine" | "green"
// 값 세트 완전 교체
// 영유아 4색(skyblue/pink/lemon/green) + 캐주얼 4색(beige/blue/wine/green)
// 정장 선택 시 null (정장은 suitColor 사용)
// clothing="default" 시 null

"monkos_suitColor":     null | "navy" | "brown" | "gray" | "black"
// ★ 신규 키. clothing="suit" 시에만 유효
// 디폴트: "navy"

"monkos_shirtColor":    null | "white" | "lightblue" | "lightpink" | "lightbeige"
// ★ 신규 키. clothing="suit" 시에만 유효
// 디폴트: "white"

"monkos_tieColor":      null | "notie" | "navy" | "wine" | "black"
// ★ 신규 키 (현행 monkos_tie 합산형에서 분리)
// clothing="suit" 시에만 유효
// 디폴트: "navy"

"monkos_tiePattern":    null | "solid" | "stripe"
// ★ 신규 키 (현행 monkos_tie 합산형에서 분리)
// tieColor="notie" 시 null (노타이 → 무늬 숨김)
// 디폴트: "solid"

// ──── [3p] 스타일 — 헤어 ────
"monkos_hair":          "default" | "tidy" | "updo"
// 현행 "as_is" → "default", "up" → "updo", "down" 삭제

// ──── [3p] 스타일 — 배경 ────
"monkos_bgColor":       "white" | "gray" | "blue" | "beige"
// ★ 키 이름 변경: background → bgColor (v5 변수명과 통일)
// 값 축소: pink/yellow 삭제 (4값)
// format="passport" 시 "white" 고정 (저장은 하되 UI에서 변경 불가)

// ──── 이미지/상태 키 (변경 없음) ────
"monkos_captured":       base64 data URL      // camera.js에서 저장
"monkos_generated":      base64 data URL      // result.js에서 저장 (크롭+워터마크)
"monkos_cropped":        base64 data URL      // result.js에서 저장 (규격 크롭)
"monkos_pending_action": "download"           // 충전 복귀 시 자동 다운로드
"_mo_p":                 base64 data URL      // 풀 원본 임시 보관 (난독화)

  │   ※ 현행: loadSessionData('purpose') → USAGE_GUIDE[purpose]
  │   → v5: format 2값 기반으로 가이드 재설계 필요
  │   (현행 5값 가이드 → 2값 가이드로 축소)
```

### 3-2. 노드별 읽기/쓰기 요약

| 노드 | 읽기 키 | 쓰기 키 |
|------|---------|---------|
| **prep.js** | (init 시 복원: 11필드 전부 loadSessionData) | format, gender, age, clothing, clothingColor, suitColor, shirtColor, tieColor, tiePattern, hair, bgColor |
| **camera.js** | format(필수), gender, age, clothing, clothingColor, suitColor, shirtColor, tieColor, tiePattern, hair, bgColor | captured |
| **result.js** | captured, format, gender(store), age(store), clothing, clothingColor, suitColor, shirtColor, tieColor, tiePattern, hair, bgColor | generated, cropped, pending_action, _mo_p |
| **thankyou.js** | cropped, format | — |
| **shared.js (sharedInit)** | format(→store.format), gender(→store.gender), age(→store.age) | — |

### 3-3. v5에서 변경되는 sharedInit 복원 대상

현행 `sharedInit()`은 `style`, `gender`, `age` 3키만 복원한다 (shared.js:341-346).

v5에서 `style` → `format`으로 변경 필요:

```
현행: loadSessionData('style')  → store.style
v5:   loadSessionData('format') → store.format
```

**`gender`, `age` 키는 유지되지만 값 형식이 변경**되므로, 구버전 값("male"→"m", "child"→"child")과의 호환에 주의.

## 4. 이미지 키 처리 (3-D)

### 4-1. 현행 이미지 키 상태

| 키 | 내용 | 저장 시점 | 용량 추정 | v5 유지 여부 |
|----|------|----------|----------|-------------|
| `monkos_captured` | 촬영 원본 (base64 JPEG, quality 0.6) | camera.js 촬영 시 | ~200-400KB | ✅ 유지 |
| `monkos_generated` | 크롭+워터마크 프리뷰 (base64 JPEG, quality 0.85) | result.js 생성 완료 시 | ~300-500KB | ✅ 유지 |
| `monkos_cropped` | 규격 크롭 완성본 (base64 JPEG) | result.js 다운로드 완료 시 | ~100-200KB | ✅ 유지 |
| `_mo_p` | 풀 원본 (base64, 고화질) | result.js 다운로드 클릭 시 | ~500KB-1MB | ✅ 유지 |

### 4-2. 용량 이슈 분석

**동시 존재 최대 구간**: 다운로드 클릭 후 토스 리다이렉트 전

```
monkos_captured   ~400KB
monkos_generated  ~500KB
monkos_cropped    ~200KB
_mo_p             ~1MB
──────────────────────────
합계              ~2.1MB
```

**sessionStorage 제한**: 대부분의 브라우저에서 5-10MB.

**판단**: 현행 기준으로는 제한에 근접하지 않음. 단, 고화질 카메라(4K)나 비압축 이미지 시 초과 위험.

### 4-3. v5에서의 변경/대안

| 항목 | 현행 | v5 권장 | 사유 |
|------|------|---------|------|
| captured 저장 | sessionStorage | **유지** | 촬영 데이터가 camera→result 페이지 간 전달에 필수 |
| generated 저장 | sessionStorage | **유지** | 토스 리다이렉트 복귀 시 복원 필수 |
| cropped 저장 | sessionStorage | **유지** | result→thankyou 페이지 간 전달에 필수 |
| _mo_p 저장 | sessionStorage | **유지** | 토스 리다이렉트 대비 필수 |
| IndexedDB 전환 | — | **향후 검토** | 현 시점에서는 불필요한 복잡도 증가. 용량 이슈 발생 시 전환 |

**결론: v5에서 이미지 키 구조 변경 불필요. 키 이름·저장 방식 모두 현행 유지.**

## 5. 키 충돌 방지 (3-E)

### 5-1. 충돌 시나리오

v5 전환 중 기존 유저가 구버전 페이지를 방문한 세션에서 신버전 페이지로 이동할 때:

| 시나리오 | 구키 | 신키 | 충돌 결과 |
|---------|------|------|----------|
| 구 prep.js → 신 camera.js | `monkos_purpose="passport"` | camera.js가 `monkos_format` 기대 | **format 미존재 → prep.html 리다이렉트** (안전 실패) |
| 구 prep.js → 신 result.js | `monkos_tie="solid_navy"` | result.js가 `monkos_tieColor` 기대 | **tieColor 미존재 → null 전송** (생성 시 타이 없는 결과) |
| 신 prep.js → 구 result.js | `monkos_format="passport"` | result.js가 `monkos_purpose` 기대 | **purpose 미존재 → API에 null 전송** (서버 에러 가능) |

### 5-2. 방지 전략

**권장안: 세션 시작 시 구키 전수 정리 + 버전 태그**

```javascript
// prep.js init() 시 실행
const SCHEMA_VERSION = 'v5';
const currentVersion = sessionStorage.getItem('monkos_schema_version');

if (currentVersion !== SCHEMA_VERSION) {
  // 구 퍼널 선택 키 전수 삭제
  const LEGACY_KEYS = [
    'monkos_purpose', 'monkos_style', 'monkos_expression',
    'monkos_tie', 'monkos_background'
  ];
  LEGACY_KEYS.forEach(k => sessionStorage.removeItem(k));

  // 이미지 키는 삭제하지 않음 (진행 중인 촬영 데이터 보존)
  sessionStorage.setItem('monkos_schema_version', SCHEMA_VERSION);
}
```

**전략 요점**:
- 퍼널 선택 키만 정리, 이미지/상태 키는 보존
- `monkos_schema_version` 태그로 1회만 실행
- 이미지 키(captured, generated, cropped, _mo_p)는 구/신 동일이므로 충돌 없음
- 중복 실행 방지: 이미 v5이면 스킵

### 5-3. 전환기 camera.js 필수값 체크 변경

현행 camera.js:273:
```javascript
if (!store.style || !purpose) {  // style = 레거시 키
```

v5 변경:
```javascript
if (!store.format) {  // format = v5 키
```

**이 한 줄이 전환 시 가장 위험한 지점**. prep.js와 camera.js가 반드시 동시 배포되어야 함.

## 6. 설계 판단이 필요한 사항 (쌍아/작가님 결정 필요)

### 6-1. format ↔ style/PHOTO_SPECS 매핑 전략

현행 코드에서 `store.style`은 **PHOTO_SPECS 키**(`id_photo` | `resume`)로 사용된다:
- result.js:381 `PHOTO_SPECS[store.style]` → 크롭 규격 결정
- thankyou.js:77 `PHOTO_SPECS[style]` → 규격 정보 표시

v5의 `format`은 `"passport"` | `"id"`이므로 PHOTO_SPECS 키와 불일치.

| 방안 | 설명 | 영향 |
|------|------|------|
| **A. PHOTO_SPECS 키 변경** | `id_photo` → `passport`, `resume` → `id` | config.js + 모든 PHOTO_SPECS 참조 변경 |
| **B. format→style 변환 레이어** | prep.js에서 format 저장 시 `format→style` 매핑도 함께 저장 | prep.js에 변환 로직 추가. 하류 코드 변경 최소화 |
| **C. 양쪽 저장** | `monkos_format`(v5 신규) + `monkos_style`(레거시 호환)을 prep.js에서 둘 다 저장 | 중복 저장이지만 하류 코드 변경 없이 안전 전환 |

**막내1 의견**: **C안(양쪽 저장)**이 전환기에 가장 안전. 완전 전환 후 style 키 삭제 가능. 단, 이는 서버 스키마(막내2 영역)와도 연동되는 판단이므로 **쌍아+작가님 결정 필요**.

### 6-2. 정장 서브옵션의 null 처리

clothing ≠ "suit" 일 때 suitColor/shirtColor/tieColor/tiePattern의 sessionStorage 값:

| 방안 | 설명 |
|------|------|
| **A. null 문자열 저장** | `saveSessionData('suitColor', null)` → sessionStorage에 `"null"` 문자열 |
| **B. 빈 문자열 저장** | `saveSessionData('suitColor', '')` → sessionStorage에 빈 문자열 |
| **C. 키 자체 미저장** | clothing ≠ "suit" 시 해당 키를 setItem하지 않음 |

**막내1 의견**: **B안(빈 문자열)** 권장. 현행 prep.js:603의 `saveSessionData(key, selections[key] || '')` 패턴과 일관됨. `loadSessionData`는 빈 문자열이면 falsy이므로 읽는 쪽에서 자연스럽게 무시.

### 6-3. thankyou.js USAGE_GUIDE 재설계

현행 USAGE_GUIDE는 5값(passport/student_id/employee_id/resume/color_portrait) 기반.
v5에서 format 2값("passport"/"id")으로 축소되면:

```javascript
// v5 USAGE_GUIDE 초안
const USAGE_GUIDE = {
  passport: [
    '여권 발급 (온라인/오프라인)',
    '주민등록증 / 운전면허증',
    '외국인등록증',
  ],
  id: [
    '이력서 / 자기소개서',
    '학생증 / 사원증 발급',
    '원서접수 프로필',
  ],
};
```

**쌍아/작가님 결정 필요**: 기존 5종 용도 가이드를 2종으로 합치는 문구 확정.

### 6-4. `monkos_cropped` 저장 시점과 thankyou.js 진입

현행 `monkos_cropped`는 다운로드 **완료 후** (`cropAndShowPostDownload`) 저장된다.
v5 기획안의 엔딩 페이지는 다운로드 완료 후 진입.

**확인 필요**: v5에서 result.js → thankyou.html(엔딩) 전환 시 `navigateTo`를 사용하는지, 아니면 같은 페이지 내에서 상태 전환인지. 현행은 `showThankYou()` 함수로 같은 페이지 내 오버레이 → v5에서 별도 페이지 분리 시 `monkos_cropped` 저장 → 페이지 전환 순서 보장 필요.

### 6-5. clothingColor의 "green" 중복

v5 기획안에서:
- 영유아 의상변경 컬러: skyblue, pink, lemon, **green**
- 캐주얼 컬러: beige, blue, wine, **green**

두 컨텍스트에서 `"green"` 값이 동일. sessionStorage에는 문제 없으나, **서버 프롬프트 빌딩 시 영유아 green(아이다운 초록)과 캐주얼 green(성인 초록)이 다른 프롬프트를 생성해야 하는지** 확인 필요. (이 부분은 막내2 서버 영역)
