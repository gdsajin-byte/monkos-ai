### 1-3. 핵심 알고리즘

#### 스플라인 타원 Path (L97-119)
- 8점(정수리, 턱, 좌우광대, 4모퉁이) 경유 cubic bezier
- `cp = 0.55` 텐션으로 자연스러운 타원 생성
- 좌우광대 폭(`w`)과 정수리~턱 높이(`h`)에서 bezier 제어점 산출
- 4개 C(cubic bezier) 세그먼트로 닫힌 경로 구성

#### 수치 계산 (L84-94)
```
faceMm    = (chin.y - crown.y) / MM          // MM = FH / spec.hMm
topMm     = crown.y / MM
bottomMm  = spec.hMm - topMm - faceMm
eyeY      = (leftPupil.y + rightPupil.y) / 2
eyeRatio  = eyeY / FH
faceOk    = faceMm ∈ [faceMin, faceMax]
eyeOk     = eyeRatio ∈ [0.40, 0.45]
```

#### 드래그 시스템 (L141-204)
- `pointerdown` → 타입 분기 (img/crown/scale)
- `pointermove` (window 레벨): dx/dy 산출 + 타입별 처리
  - **img**: 사진 + 오버레이 전체 이동
  - **crown**: 정수리 핀만 수직 이동 (턱 위 최소 20px 제한)
  - **scale**: 벡터 거리 → 배율 변환 (0.3~4x), 프레임 중심 기준 오버레이도 연동 스케일
- `pointerup` (window 레벨): 드래그 해제

#### ICAO 범위 바 (L122-124)
```
rangeMin = faceMin / hMm * 100
rangeMax = faceMax / hMm * 100
dotPos   = clamp(faceMm / hMm * 100, 3, 97)
```

## 2. vanilla JS 전환 실행 방안

### 2-1. 파일 구조 제안

```

```

- 기존 idphoto-kr 패턴(camera.html+camera.js, prep.html+prep.js, result.html+result.js)과 **동일 패턴**
- CSS 분리 추천: 인라인 스타일이 약 200줄 이상 → 유지보수 위해 crop.css 분리

### 2-2. React 의존성 제거 방법

| React 패턴 | vanilla 전환 | 비고 |
|-----------|-------------|------|
| `useState(val)` | `let val = initialVal` + DOM 갱신 함수 | 상태 변경 시 `render()` 호출 |
| `useRef(null)` | `document.getElementById()` / `document.querySelector()` | 직접 DOM 참조 |
| `useCallback(fn, deps)` | 일반 함수 (클로저로 변수 참조) | deps 추적 불필요 |
| `useEffect(() => {}, [])` | `document.addEventListener()` + `init()` 함수 | 라이프사이클 → 초기화 함수 |
| JSX 엘리먼트 | HTML 템플릿 + `innerHTML` 또는 직접 DOM 조작 | 정적 구조는 HTML, 동적은 JS |
| JSX 조건부 렌더 | `el.style.display` 또는 `classList.toggle` | `{condition && <div>}` → CSS 토글 |
| `Object.values(SPECS).map()` | `for...of` + `createElement` 또는 HTML 하드코딩 | 2개 규격뿐이므로 하드코딩도 가능 |

### 2-3. SVG 오버레이 전환

**프로토 현황**: React JSX 내에 SVG 직접 선언 (L266-298)

**전환 방법**:
```
crop.html에 <svg id="overlay"> 고정 배치
  → crop.js에서 setAttribute()로 좌표 갱신
  → path.setAttribute('d', splinePath())
  → line.setAttribute('y1', crown.y)
  → circle.setAttribute('cx', pupil.x)
```

- SVG 요소는 HTML에 정적 선언 (구조 변경 없음)
- 좌표만 JS에서 동적 갱신 → **가장 깔끔한 전환**
- `setAttribute` 성능: 10개 내외 요소 갱신이므로 무시 가능

### 2-4. Pointer 이벤트 전환

```javascript
// 프레임 영역
frame.addEventListener('pointerdown', (e) => onPtrDown(e, 'img'));
// 정수리 핀
crownPin.addEventListener('pointerdown', (e) => onPtrDown(e, 'crown'));
// 스케일 핸들
scaleHandle.addEventListener('pointerdown', (e) => onPtrDown(e, 'scale'));
// window 레벨 (React useEffect 대체)
window.addEventListener('pointermove', onPtrMove);
window.addEventListener('pointerup', onPtrUp);
```

- React의 `onPointerDown={e => fn(e, type)}` → `addEventListener` 직접 등록
- 프로토의 window 레벨 이벤트 패턴 그대로 유지 가능
- `e.preventDefault()` + `e.stopPropagation()` 동일

## 3. crop-engine과의 연동 분석

### 3-1. 프로토 v4에서 crop-engine API 호출 부분

**현재: 없음.** 프로토는 순수 UI 프로토타입. 서버 호출 코드 미구현.

실서비스에서 필요한 API 호출:
1. **FaceMesh 좌표 획득**: 프론트 또는 서버에서 수행
2. **최종 크롭 요청**: `POST /api/crop` (image base64 + format + 좌표)

### 3-2. 프론트/백엔드 역할 분리

세션 로그(03-12) 확정 아키텍처:

```
[프론트: crop.html + crop.js]
├── FaceMesh 실행 (브라우저 WASM)
├── 랜드마크 → 오버레이 좌표 자동 배치
├── 사용자 정수리 핀 조정 (human label)
├── 수치 피드백 (mm, %, 범위 판정)
├── 확정 좌표 전송 → crop-engine API
└── 다운로드 결과 수신

[백엔드: crop-engine (Cloud Run)]
├── POST /api/crop — 이미지 + 좌표 수신
├── sharp: resize → extract → 300dpi PNG
├── 메타 정보 반환 (faceMM, eyePos 등)
└── GET /api/specs — 규격 목록 제공
```

### 3-3. FaceMesh 실행 위치: 브라우저 vs 서버

| 항목 | 브라우저 실행 | 서버 실행 (crop-engine) |
|------|-------------|----------------------|
| **라이브러리** | `@mediapipe/face_mesh` (WASM/WebGL) | `@tensorflow/tfjs` + `@tensorflow-models/face-landmarks-detection` |
| **응답 속도** | 즉시 (네트워크 왕복 없음) | 이미지 업로드 + 추론 + 응답 (수 초) |
| **서버 비용** | 없음 | Cloud Run 인스턴스 비용 |
| **브라우저 부하** | WASM 로드 ~5MB, 추론 ~200ms | 없음 |
| **호환성** | WebGL2 필수 (구형 모바일 제한) | 서버 측 — 호환성 무관 |
| **오프라인** | 가능 (WASM 캐시 후) | 불가 |
| **데이터 보안** | 이미지가 서버로 전송되지 않음 | 이미지 서버 경유 |
| **이미 구현** | 미구현 | `face-detect.js` 구현 완료 |

**추천: 브라우저 실행 (프론트)**

- 세션 로그 확정 방향과 일치
- 응답성이 핵심 (드래그 인터랙션 → 즉시 피드백)
- 서버 비용 절감
- 개인정보 보호 (사진이 서버로 올라가지 않음, 최종 크롭 요청 시에만)
- 단, 폴백으로 서버 측 감지도 유지 (WASM 미지원 브라우저)

|------|--------|----------|
| **상태-DOM 동기화** | 중 | `render()` 함수로 일괄 갱신. 프레임 내 요소만 갱신하므로 범위 제한적 |
| **SVG 동적 path 갱신** | 하 | `setAttribute('d', path)` — 직접적이고 성능 문제 없음 |
| **인라인 스타일 → CSS 분리** | 하 | 기계적 작업. 조건부 스타일(fc/ec)만 JS에서 처리 |
| **이벤트 바인딩 관리** | 하 | addEventListener 직접 등록, cleanup 불필요 (SPA 아님) |
| **스케일 연동 계산** | 중 | 프로토 로직 그대로 이식. 프레임 중심 기준 스케일 변환 수학 동일 |

### 4-3. FaceMesh WASM/WebGL 브라우저 호환성

| 환경 | WebGL2 지원 | FaceMesh 가동 | 비고 |
|------|-----------|-------------|------|
| Chrome 80+ (Android/Desktop) | ✅ | ✅ | 주력 타겟 |
| Safari 15+ (iOS 15+) | ✅ | ✅ | WebGL2 2021년 지원 |
| iOS 14 이하 | ❌ | ❌ | WebGL1만 → 폴백 필요 |
| 구형 Android (WebView) | ⚠️ | ⚠️ | 기기별 상이 |
| Firefox | ✅ | ✅ | |

- **WASM 로드 크기**: ~5MB (CDN 캐시 가능)
- **첫 추론 시간**: ~500ms~2s (모델 초기화 포함)
- **이후 추론**: ~100~200ms/프레임
- **폴백 전략**: WebGL2 미지원 시 서버 측 crop-engine에 이미지 전송하여 FaceMesh 결과 수신

### 4-4. 모바일 터치 이벤트

| 항목 | 현재 프로토 | 실서비스 대응 |
|------|-----------|-------------|
| Pointer Events API | ✅ 사용 | 모바일 터치도 자동 호환 |
| 멀티터치 (핀치 줌) | ❌ 미구현 | 스케일 핸들 드래그로 대체 중. 핀치 줌 추가 검토 |
| 터치 영역 크기 | 20×20px 핀 | 모바일에서 작을 수 있음 — 터치 영역 44px 이상 권장 (WCAG) |
| 스크롤 간섭 | 미검증 | `touch-action: none` 필요 (프레임 영역) |
| 300ms 딜레이 | 미검증 | `touch-action: manipulation` 권장 |

### 4-5. 성능 우려 (SVG 실시간 갱신 + 드래그)

| 항목 | 분석 | 결론 |
|------|------|------|
| SVG 요소 수 | ~15개 (path 1, line 3, circle 2, rect 6, text 3) | **문제 없음** — 수십~수백 개에서나 병목 |
| 드래그 중 갱신 빈도 | pointermove = ~60fps | **문제 없음** — setAttribute 15개는 마이크로초 단위 |
| bezier path 재계산 | 문자열 연결 6줄 | **문제 없음** |
| 이미지 CSS transform | translate + scale | **GPU 가속** — 성능 우수 |
| 전체 render() 호출 | 모든 상태 변경 시 | 영향 범위 제한적 (DOM 부분 갱신 가능) |

**결론: 성능 리스크 없음.** SVG 요소가 극소수이고, CSS transform은 GPU 가속됨.
