| **실행 경과** | 설계서 → Phase 1(Image Pro 이관) → Phase 3(Workers 삭제) → Phase 2(functions/ 제거) → **연쇄 에러** → 교차오염 감사 → v6→v5 롤백 → Workers 선별 복원 → 탯줄 절단 |
| **방향 전환** | **2회**: (1) Phase 2 실행 후 `_redirects` 프록시 위반 발견 → 부분 롤백, (2) 작가님 "탯줄을 끊어줘야" → 완전 분리 원칙 선언 |
| **연쇄 에러** | **(1)** `_redirects /api/*` 프록시가 헌법 10조 위반, **(2)** index-v6.js API 변경→Image Pro 500에러, **(3)** 교차오염 21건 발견(15건 monk.kr→monkos.ai, 6건 역방향), **(4)** Workers 복원 필요 |
| **현재 상태** | **부분 완료** — 4개 Image Pro Workers 선별 복원, `/api/*` 프록시 제거, generate.js Gemini 직접 호출 전환. 16건 교차오염은 전략적 결정 대기 |

**진단**: 3일간 가장 심각한 연쇄 에러를 유발한 이니셔티브. 근본 원인은 **Phase 1(이관) 완료 전에 Phase 2(제거)를 실행**한 것. 설계서에 "Phase 1 완료 후 Phase 2" 의존성이 명시되어 있었으나 실행 시 이를 검증하지 않았다. `_redirects` 규칙 생성은 functions/ 제거의 보상으로 자연스럽게 추가되었으나, 이것이 **헌법 10조(프록시 금지) 정면 위반**임을 사전에 인지하지 못했다.

## 4. 구조적 진단

### Q1. 방향성 일관성

**일관된 큰 방향은 존재했다.**

3일간의 작업은 크게 3개의 전략적 축으로 수렴한다:
1. **인증 체계 단일화**: sessionStorage→쿠키 폴백→쿠키 단일 (진화 방향 일관)
2. **monk.kr/monkos.ai 분리**: 기능 이관→정적화→분리 원칙 (방향 일관, 실행에서 혼선)
3. **크레딧 게이트 재설계**: v1 감사→v2 설계→v3 확장 (합리적 진화)

다만 **하루 단위**에서 보면 산발적으로 보이는 이유는 다음과 같다:
- 한 이니셔티브 실행 중 부수 버그 발견 → 긴급 수정 → 원래 작업 중단
- 여러 이니셔티브가 같은 날 병렬 진행 (2/27: 서버모듈화 + 토스수정 + 문서통합 + 크로스도메인 동시)
- P0 긴급수정이 계획된 작업을 밀어냄

### Q2. 연쇄 에러 패턴

**실제로 발생했다. 3건의 명확한 연쇄 패턴이 존재한다.**

#### 패턴 A: v3 scope → 카카오 로그인 차단

```
**근본 원인**: 카카오 비즈앱 전환 전에는 plusfriends scope가 사용 불가하다는 사전 조사 부재.

#### 패턴 B: 쿠키 단일화 → 4건 연쇄
```

    → monkos_free_gen 영구차단(12:19) — 전수 점검

**근본 원인**: 인증 변경 후 비로그인 사용자 시나리오 E2E 테스트 미실시. 설계서에 8개 테스트 시나리오가 명시되어 있었으나 코드 리뷰로만 검증.

#### 패턴 C: functions/ 제거 → 5건 연쇄

**근본 원인**: Phase 1(이관) 미완료 상태에서 Phase 2(제거) 실행. 설계서의 의존성을 무시. 제거와 동시에 생성한 `_redirects`가 프록시 역할을 하는 것에 대한 헌법 10조 점검 미실시.

### Q3. 병렬 작업 충돌

**직접적 충돌은 2건 확인된다.**

1. **config.js 충돌 (2/27 새벽)**: 쌍아가 지시서 작성 중 config.js를 실수로 수정 → git restore했으나 막내1의 동시 작업과 간섭
2. **git push 충돌 (2/28)**: 막내3과 막내4가 동시에 push 시도 → git pull --rebase로 해결

병렬 작업 자체의 구조적 충돌은 적었다. 이는 쌍아의 지시서 체계가 에이전트간 작업 범위를 분리하는 데 효과적이었음을 의미한다.

### Q5. 롤백/되돌리기

### Q7. 기준 부재

**3건의 기준 부재가 연쇄 에러의 직접 원인이다.**

1. **인증 변경 후 E2E 검증 기준 부재**: 쿠키 단일화 설계서에 8개 테스트 시나리오가 있었으나, "누가, 언제, 어떻게" 테스트하는지 절차가 없었다. 코드 리뷰로 검증했다고 판단했으나 실제 브라우저 테스트는 하지 않았다.

2. **배포 전 cross-domain 점검 기준 부재**: monk.kr↔monkos.ai 간 교차 참조를 배포 전에 점검하는 절차가 없었다. Phase 2 실행 시 `_redirects`가 프록시 역할을 하는 것을 헌법 10조와 대조하지 않았다.

3. **전수 수정 기준 부재**: 토스 키 불일치 같은 "동일 유형 문제가 여러 파일에 산재"하는 경우, grep으로 전수 검색 → 일괄 수정하는 절차가 없어 4건의 커밋으로 분할 수정되었다.

## 5. 권고사항

### R1. 인증/결제 변경 시 E2E 체크리스트 의무화

쿠키 단일화의 4건 연쇄는 **브라우저 E2E 테스트 부재**가 직접 원인이다. 인증·결제·세션 관련 변경 시 아래 시나리오를 실제 브라우저에서 테스트하는 절차를 ch2(코딩 규칙)에 추가할 것을 권고한다:

- 비로그인 사용자 → 생성 → 게이트 → 로그인 → 결제/이벤트
- 기존 로그인 사용자 → 크레딧 표시 → 다운로드 → 결제
- 크로스도메인 이동 (portal ↔ idphoto-kr)
- 모바일 Safari / 카카오톡 인앱 브라우저

### R2. 설계서 의존성 게이트 체크

CF 이관의 연쇄 에러는 **설계서에 명시된 의존성을 실행 시 무시**한 것이 원인이다. 실행 전 "사전 적합성 검토"(현재 헌법 규정)에 **설계서 의존성 확인**을 포함할 것을 권고한다:

- "이 작업의 선행 조건(Phase N)이 완료되었는가?"
- "이 작업의 부수 생성물(예: _redirects)이 헌법/법률과 충돌하는가?"

### R3. 전수 수정 패턴 정착

토스 키 불일치의 4건 분할은 **영향 범위 전수 파악 부재**가 원인이다. ch7(막내 행동 강령)에 다음을 추가할 것을 권고한다:

- 버그 수정 시 `grep`으로 동일 패턴 전수 검색 의무
- "이 파일에만 있는가, 다른 파일에도 있는가?" 자문 절차

### R4. 배포 전 교차도메인 점검 자동화
