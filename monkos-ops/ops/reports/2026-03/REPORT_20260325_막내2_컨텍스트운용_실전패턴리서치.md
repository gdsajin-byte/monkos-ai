## 1축: CLAUDE.md 운용 패턴

### 1-1. Anthropic 공식 권장

공식 문서가 명시하는 원칙:

- **파일당 200줄 이하** 목표. 길어질수록 지시 준수율(adherence) 저하
- CLAUDE.md는 **매 세션 시작 시 전체 로딩** — 모든 세션에 보편적으로 적용되는 것만 넣어야 함
- 리트머스 테스트: **"이 줄을 삭제하면 Claude가 실수할까?"** 아니라면 삭제

| 포함해야 할 것 | 제외해야 할 것 |
|---|---|
| Claude가 추측 불가능한 Bash 명령 | 코드를 읽으면 알 수 있는 것 |
| 기본값과 다른 코드 스타일 규칙 | 표준 언어 관례 (Claude가 이미 아는 것) |
| 테스트 지침, 선호 테스트 러너 | 상세 API 문서 (링크로 대체) |
| 레포 에티켓 (브랜치 네이밍, PR 규칙) | 자주 변경되는 정보 |
| 프로젝트 고유 아키텍처 결정사항 | 긴 설명이나 튜토리얼 |
| 비직관적 gotcha/주의사항 | "클린 코드 작성하라" 같은 자명한 지시 |

> 출처: [Claude Code Best Practices](https://code.claude.com/docs/en/best-practices)

### 1-2. Anthropic 자체 레포 실전 사례

**`anthropics/claude-code-action`** CLAUDE.md — 5개 섹션으로 구성:
- Commands (빌드/테스트 명령)
- What This Is (1문단 개요)
- How It Runs (실행 흐름)
- Things That Will Bite You (비직관적 함정)
- Code Conventions (코딩 관례)

핵심: **"Things That Will Bite You"** 섹션 — 비직관적인 것만 명시. 아키텍처 설명도 한 문단 수준.

> 출처: [anthropics/claude-code-action CLAUDE.md](https://github.com/anthropics/claude-code-action/blob/main/CLAUDE.md)

### 1-3. 모노레포 계층 분리 패턴

**공식 로딩 메커니즘 — 5단계 계층:**

| 계층 | 위치 | 로딩 시점 | 공유 범위 |
|---|---|---|---|
| Managed Policy | `/Library/Application Support/ClaudeCode/CLAUDE.md` | 항상 | 조직 전체 |
| User | `~/.claude/CLAUDE.md` | 항상 | 개인 전역 |
| Project | `./CLAUDE.md` | 항상 | 팀 (Git) |
| Rules | `.claude/rules/*.md` | 항상 또는 path 매칭 시 | 팀 |
| Auto Memory | `~/.claude/projects/<project>/memory/` | 첫 200줄만 | 로컬 전용 |

**서브디렉토리 CLAUDE.md = 지연 로딩(Lazy Loading):**
- 하위 디렉토리의 CLAUDE.md는 해당 디렉토리 파일을 읽을 때만 로딩
- 모노레포에서 도메인별 규칙을 분리하는 핵심 메커니즘

**실전 사례 — 47,000단어에서 9,000단어로 80% 감축** (An Vo):
```
CLAUDE.md           ← 항상 로딩 (공통 규칙만)
frontend/CLAUDE.md  ← frontend/ 작업 시만 로딩
backend/CLAUDE.md   ← backend/ 작업 시만 로딩
core/CLAUDE.md      ← core/ 작업 시만 로딩
```

> 출처: [How I Organized My CLAUDE.md in a Monorepo](https://dev.to/anvodev/how-i-organized-my-claudemd-in-a-monorepo-with-too-many-contexts-37k7)

### 1-4. 안티패턴 6가지

| 안티패턴 | 문제 | 대안 |
|---|---|---|
| 프로젝트 전체 히스토리 기재 | 매 세션 불필요한 역사 로딩 | Git log에 위임 |
| 상세 API 문서 삽입 | 컨텍스트 오염 | `@docs/api.md` 링크 |
| 파일별 코드베이스 설명 | Claude가 직접 읽으면 되는 정보 | 구조 개요 1~2줄만 |
| 코드 스타일을 LLM에 위임 | 린터보다 비싸고 부정확 | Hook으로 린터 자동 실행 |
| `/init` 자동 생성 그대로 사용 | 뻔한 내용 대부분 | 수동 큐레이션 |
| 특정 작업에만 필요한 지식 삽입 | 모든 세션에 로딩 | Skills로 분리 |

HumanLayer 핵심 인사이트:
> "프론티어 LLM은 ~150~200개 지시를 합리적으로 따를 수 있다. Claude Code 시스템 프롬프트가 이미 ~50개를 사용하므로, CLAUDE.md에 남은 예산은 100~150개."

> 출처: [Writing a Good CLAUDE.md - HumanLayer](https://www.humanlayer.dev/blog/writing-a-good-claude-md)

## 2축: MEMORY.md 운용 패턴

### 2-1. 핵심 메커니즘

- MEMORY.md의 **처음 200줄만** 세션 시작 시 자동 로딩
- 200줄 이후는 Claude가 명시적으로 Read 도구를 사용해야 접근 가능
- CLAUDE.md와 달리 **로컬 전용**, Git 공유 불가

### 2-2. 효율적 인덱싱 4가지 전략

**전략 1: 인덱스+토픽 파일 분리 (Anthropic 공식 패턴)**
```
memory/
├── MEMORY.md           # 인덱스 (200줄 이하)
├── debugging.md        # 디버깅 패턴 상세
├── api-conventions.md  # API 설계 결정
└── architecture.md     # 아키텍처 노트
```
MEMORY.md에는 각 토픽의 1줄짜리 참조만 남기고, Claude가 필요할 때 Read.

> 출처: [Anthropic 공식 - How Claude remembers your project](https://code.claude.com/docs/en/memory)

**전략 2: 날짜 스탬프 + 주간 로테이션 (Ian Paterson, 34개 프로젝트 검증)**
- 모든 교훈에 `[YYYY-MM-DD]` 날짜 표기
- 주간 cron으로 오래된 항목을 `OLD-MEMORY-ENTRIES.md`로 아카이브
- 결과: MEMORY.md가 항상 ~130줄로 유지

> 출처: [Claude Code Memory Architecture](https://ianlpaterson.com/blog/claude-code-memory-architecture/)

**전략 3: 1줄 압축 원칙**
- 각 항목을 1줄짜리 응축 교훈으로 작성
- SFEIR 통계: 10세션 후 MEMORY.md에 약 30% 중복 항목 — 정기 정리 필수

> 출처: [SFEIR Institute Tips](https://institute.sfeir.com/en/claude-code/claude-code-memory-system-claude-md/tips/)

**전략 4: Auto Dream (자동 정리)**
- 24시간 + 5세션 조건 충족 시 자동 메모리 정리
- 4단계: Orient → Gather Signal → Consolidation → Prune and Index
- 사례: 280줄 → 142줄 자동 압축

> 출처: [Claude Code Auto Dream](https://claudefa.st/blog/guide/mechanics/auto-dream)

### 2-3. 메모리 유형별 유용도

| 유형 | 유용도 | 이유 |
|------|--------|------|
| 빌드/테스트 커맨드 | **최상** | 매 세션 반복 사용, 코드에서 유추 불가 |
| 디버깅 교훈 | **최상** | 동일 실수 재발 방지. "130+ 교훈 축적 후 같은 에러 재발 없음" |
| 아키텍처 결정사항 | **상** | 왜 이 구조인지, 대안은 무엇이었는지 |
| 코드 스타일 선호 | **중상** | 명시하면 일관성 40% 향상 |
| 워크플로우 습관 | **중** | 커밋 전 테스트 실행 등 프로세스 |
| 성격/톤 설정 | **낮음** | "Memory는 성격 인코딩이 아니라 행동 조율용" |

> 출처: [Claude Code Auto Memory 가이드](https://claudefa.st/blog/guide/mechanics/auto-memory)

### 2-4. MEMORY.md vs CLAUDE.md 역할 분담 공식 기준

| 속성 | CLAUDE.md | MEMORY.md |
|------|-----------|-----------|
| 작성자 | 사용자 (수동) | Claude (자동) |
| 내용 | 지시사항, 규칙 | 학습 내용, 패턴 |
| 로딩 | 전체 파일 (길이 무관) | 처음 200줄만 |
| 공유 | Git을 통해 팀 공유 | 로컬 전용, 공유 불가 |
| 용도 | 코딩 표준, 워크플로우 | 빌드 커맨드, 디버깅 인사이트 |

> "CLAUDE.md는 당신이 Claude에게 하는 **지시**. MEMORY.md는 Claude가 프로젝트에 대해 쓰는 **노트**."
> — Jose Parreo Garcia

> 출처: [You (probably) don't understand Claude Code memory](https://joseparreogarcia.substack.com/p/claude-code-memory-explained)

## 3축: 멀티에이전트/멀티디바이스 패턴

### 3-1. `.claude/agents/` 서브에이전트 정의

Claude Code는 `.claude/agents/`에 마크다운 파일로 서브에이전트를 정의할 수 있다. 각 서브에이전트는 **독립된 컨텍스트 윈도우**에서 동작.

```yaml
---
name: makne-coder
description: 자율 코딩 전문 에이전트
tools: Read, Write, Edit, Bash, Grep, Glob
model: inherit
permissionMode: acceptEdits
---
```

**서브에이전트 스코프 우선순위:**
1. `--agents` CLI 플래그 (세션 한정)
2. `.claude/agents/` (프로젝트, Git 공유)
3. `~/.claude/agents/` (유저 전역, 로컬)
4. Plugin `agents/` (플러그인 제공)

각 서브에이전트에 설정 가능: 모델 선택, 도구 제한, 권한 모드, MCP 스코핑, 전용 훅, 영구 메모리, 워크트리 격리.

> 출처: [Claude Code - Create custom subagents](https://code.claude.com/docs/en/sub-agents)

### 3-2. `.claude/rules/`의 경로별 스코핑

```yaml
---
paths:
  - "monkos_AI/portal/**"
  - "monkos_AI/idphoto-kr/**"
---
# 포털 SEO 규칙
```

현재 프로젝트에 이미 `portal_seo.md` 1건 사용 중. 이 패턴을 확장하면 도메인별 규칙 분리 가능:
```
.claude/rules/
  coding_standards.md   # paths: ["MONK_kr/**", "monkos_AI/**"]
  ops_workflow.md       # paths: ["monkos-ops/**"]
  governance_rules.md   # paths: ["governance/**"]
```

> 출처: [Claude Code Rules Directory](https://claudefa.st/blog/guide/mechanics/rules-directory)

### 3-3. Agent Teams (실험적 기능)

복수 Claude Code 인스턴스를 팀으로 편성하여 병렬 작업. 각 팀원은 독립 컨텍스트 윈도우(1M 토큰).

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

| 항목 | 서브에이전트 | Agent Teams |
|------|------------|-------------|
| 컨텍스트 | 독립, 결과만 반환 | 독립, 완전 독립 |
| 통신 | 메인에만 보고 | 팀원 간 직접 메시지 |
| 비용 | 결과 요약으로 저비용 | 3에이전트 = ~2.5배 토큰 |
| 적합 | 포커스된 단독 작업 | 토론/협업 필요한 복합 작업 |

> 출처: [Claude Code - Agent Teams](https://code.claude.com/docs/en/agent-teams)

### 3-4. Git Worktree 기반 물리적 격리

`--worktree` 플래그로 에이전트별 물리적 분리 레포 복사본 생성. 파일 충돌 원천 차단.

서브에이전트에서도 `isolation: worktree` 설정 가능.

> 출처: [Claude Code Worktrees Guide](https://claudefa.st/blog/guide/development/worktree-guide)

### 3-5. 디바이스별 로컬 vs 공유 설정 분리

**Claude Code 공식 분리 체계:**

| 파일 | Git 추적 | 용도 |
|------|---------|------|
| `.claude/settings.json` | O (공유) | 팀 공통 권한, 환경변수 |
| `.claude/settings.local.json` | X (로컬) | 개인 권한, MCP, 실험 |
| `CLAUDE.md` | O (공유) | 프로젝트 지시사항 |
| `~/.claude/settings.json` | X (로컬) | 전역 개인 설정 |
| `~/.claude/CLAUDE.md` | X (로컬) | 전역 개인 지시 |

**설정 우선순위 (높은 순):**
1. Managed (IT/관리자, override 불가)
2. CLI Arguments (세션 한정)
3. Local (`.claude/settings.local.json`)
4. Project (`.claude/settings.json`)
5. User (`~/.claude/settings.json`)

배열 값은 **병합(concat + dedup)** 적용.

> 출처: [Claude Code Settings](https://code.claude.com/docs/en/settings)

## 4축: 컨텍스트 크기 최적화

### 4-1. 성능 영향 — 실증 데이터

**공식 경고 시스템:**
- CLAUDE.md가 **40,000자** 초과 시 경고 표시: `Large [file] will impact performance`

> 출처: [GitHub Issue #2766](https://github.com/anthropics/claude-code/issues/2766)

**지시 무시 현상 (GitHub Issue #26160):**
- 컴팩팅 이후 CLAUDE.md 규칙이 사실상 소실
- 에이전트가 "CLAUDE.md는 선택사항"이라고 응답
- 안전 규칙 위반: settings.json 금지 수정 실행, git add -A 명시 금지에도 실행

> 출처: [GitHub Issue #26160](https://github.com/anthropics/claude-code/issues/26160)

**컨텍스트 충전률과 품질:**
> "Quality degrades significantly as the context window fills, with reliable performance in the 0-20% range and progressive degradation after that."

시스템 프롬프트+도구 정의+MCP 스키마+메모리 파일만으로 **30,000~40,000 토큰 선점**.

> 출처: [GitHub Issue #10881](https://github.com/anthropics/claude-code/issues/10881)

### 4-2. 권장 크기 — 커뮤니티 합의

| 접근법 | 권장 크기 | 근거 |
|--------|-----------|------|
| 공식 문서 | 200줄/파일 | 준수율 저하 방지 |
| 보수적 실무 | 50줄 이하 | CLAUDE.md를 인덱스로만 |
| 중간 실무 | 200~500줄 | 필수 정보만, 주기적 pruning |
| 대형 프로젝트 | 모듈 분할 | `.claude/rules/` + Skills 분산 |

### 4-3. 컨텍스트 절약 전략 — 메커니즘별

**Skills = 진정한 온디맨드 로딩:**

| | CLAUDE.md / rules | Skills |
|--|-------------------|--------|
| 로딩 시점 | 매 세션 시작 시 전체 | 사용 시에만 |
| 상시 비용 | 전체 내용 토큰 | ~100 토큰 (이름+설명만) |

> "With 20 skills, that's ~2,000 tokens at startup instead of ~40,000."

> 출처: [Claude Code Skills](https://code.claude.com/docs/en/skills), [Tyler Folkman - Claude Skills](https://tylerfolkman.substack.com/p/the-complete-guide-to-claude-skills)

**절약 효과 순위:**

| 전략 | 토큰 절감 | 적용 난이도 |
|------|-----------|-------------|
| CLAUDE.md 200줄 이내 pruning | 중간 | 낮음 |
| `paths` 스코핑된 rules 활용 | **높음** | 중간 |
| 도메인 지식을 Skills로 이전 | **높음** | 중간 |
| 조사 작업은 서브에이전트 위임 | **높음** | 낮음 |
| `/clear`로 관련 없는 컨텍스트 정리 | 높음 | 낮음 |
| `/compact focus on X`로 방향 지정 | 중간 | 낮음 |

### 4-4. 컴팩팅과의 관계

**공식: CLAUDE.md는 컴팩팅 후 디스크에서 재로드하여 재주입.** 요약 대상이 아님.

**현실 (GitHub Issue #26160, #19471):**
- 기술적으로는 재주입되지만, 모델이 **의무적 지시로 취급하지 않는** 경우 존재
- CLAUDE.md는 시스템 프롬프트가 아니라 **user message로 전달**되기 때문

**대화가 길어질수록 약해지는 메커니즘:**
1. 컨텍스트 충전률 증가 → 전반적 검색/준수 능력 저하
2. 컴팩팅 반복 → CLAUDE.md 재주입이 항상 완벽하지 않음
3. 주의력(attention) 분산 → CLAUDE.md의 상대적 "무게" 감소

**대응:**
- 관련 없는 작업 전환 시 `/clear`
- CLAUDE.md에 핵심 규칙만 유지
- `IMPORTANT`, `YOU MUST` 등의 강조 표현 활용
- 동일 실수 2회 반복 시 `/clear` 후 새 세션

> 출처: [Claude Code Best Practices](https://code.claude.com/docs/en/best-practices), [GitHub Issue #6004](https://github.com/anthropics/claude-code/issues/6004)
