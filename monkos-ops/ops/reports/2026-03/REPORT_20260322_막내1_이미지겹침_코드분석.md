### `switchTab()` 동작 분석 (blog-editor.js:85-90)
```
switchTab(tabName):
  1. 모든 .tab → classList.toggle('active', match)
  2. 모든 .tab-content → style.display = 'none'
  3. 타겟 .tab-content → style.display = '' (inline 제거 → CSS 기본값 block)
```
- `display: ''`로 설정 시 CSS `.tab-content`에 explicit `display` 없으므로 `block` 적용
- `block`이어도 `.editor-right` flex container의 flex item으로 동작 → `flex:1; min-height:0` 정상 작동 ✅
- 숨겨진 `.tab-content`는 flex flow에서 제외 → 가시 탭만 `flex:1` 적용 ✅

## 5. 겹침 가능 시나리오 — 확률 순위

### 🔴 [확률 95%] 시나리오 1: `#imageLibrary` 이중 그리드 충돌

**근본 원인**: `#imageLibrary`의 인라인 `display:grid; grid-template-columns:repeat(4,1fr)`과 자식 `.img-lib-grid`의 CSS `display:grid; grid-template-columns:repeat(4,1fr)` 충돌

**메커니즘**:
1. `#imageLibrary`는 4컬럼 그리드 (인라인 스타일)
2. `loadImageLibrary()`가 `.img-lib-date` + `.img-lib-grid` 자식을 생성
3. `.img-lib-date`는 `grid-column: 1/-1`로 전체 스팬 → 정상
4. `.img-lib-grid`는 `grid-column` 미지정 → **4컬럼 중 1번 컬럼만 차지 (1/4 폭)**
5. `.img-lib-grid` 내부에 또 `repeat(4, 1fr)` → 1/4 폭을 다시 4등분
6. 썸네일이 원래 크기의 **1/16**로 렌더링됨

**시각적 증상**:
- 썸네일이 극단적으로 작게 보임
- 날짜 헤더(전체폭)와 썸네일 그리드(1/4폭) 사이에 시각적 불일치
- 각 날짜 그룹의 `.img-lib-grid`가 좌측에 몰려 레이아웃 파괴

**추정 원인**:
`#imageLibrary` 인라인 그리드는 과거 썸네일(`.img-thumb`)이 `#imageLibrary`의 직접 자식이던 시절의 잔재. 날짜별 그룹핑(`.img-lib-grid` 래퍼)을 도입하면서 인라인 grid를 제거하지 않음.

### 🟡 [확률 40%] 시나리오 2: `toggleImageLibrary()` display 복원 시 grid 재활성

**메커니즘**:
1. "접기" 클릭 → `lib.style.display = 'none'`
2. "펼치기" 클릭 → `lib.style.display = 'grid'`
3. `display: 'grid'`로 복원하면 인라인의 `grid-template-columns:repeat(4,1fr)`이 다시 활성화
4. 시나리오 1의 문제가 재현됨

**비고**: 이 시나리오는 시나리오 1의 연장선. `display: 'grid'` 대신 `display: 'block'`으로 복원하면 인라인 grid 비활성화되지만, 그래도 근본 원인(인라인 grid)은 해결해야 함.

### 🟢 [확률 5%] 시나리오 3: 플로팅 툴바 뷰포트 경계 클리핑

**메커니즘**:
1. `.img-float-toolbar`는 `position:fixed`로 뷰포트 기준 배치
2. `getBoundingClientRect()` 기반으로 anchor 위에 배치 (top = rect.top - 40)
3. 뷰포트 좌/우 경계 체크 없음 → 우측 패널 이미지 클릭 시 toolbar이 화면 밖으로 나갈 수 있음
4. 단, 현재 코드에서는 `transform: translateX(-50%)`로 중앙 정렬하고 있어 실질적 문제 가능성 낮음

### ⚪ [확률 1%] 시나리오 4: 다중 z-index:300 오버레이 동시 표시

**메커니즘**: `.img-preview-overlay`, `.seed-popup-overlay`, `.research-img-popup` 모두 z-index:300. 동시 표시 시 DOM 순서에 의존. 실제로는 하나만 표시되므로 문제 없음.

## 결론

### 근본 원인: `#imageLibrary` 인라인 그리드 잔재

`blog-edit.html:128`의 `#imageLibrary` 인라인 스타일에 `display:grid;grid-template-columns:repeat(4, 1fr)`이 남아있는 것이 핵심 문제.

이 인라인 그리드는 썸네일(`.img-thumb`)이 `#imageLibrary`의 직접 자식이던 과거 구조의 잔재로 추정되며, 현재 날짜별 그룹 구조(`.img-lib-date` + `.img-lib-grid`)에서는 `.img-lib-grid`가 부모 그리드의 1컬럼만 차지하여 레이아웃이 파괴된다.

### 수정 방향 (코드 수정은 본 보고서 범위 외)

1. `#imageLibrary`의 인라인 `display:grid;grid-template-columns:repeat(4,1fr);gap:6px` 제거
2. 또는 `.img-lib-grid`에 `grid-column: 1 / -1` 추가
3. `toggleImageLibrary()`의 `display: 'grid'` → 적절한 값으로 변경
