## 1. 로그인 경험

### 1-1. 로그인 모달 이중 패턴

KR/JP 모두 **2가지 로그인 모달**이 공존:

| 패턴 | 소스 | 사용 위치 | 트리거 |
|------|------|----------|--------|
| **인라인 모달** | index.html (HTML 직접 작성) | index.html 헤더 "로그인" 버튼 | `openLoginModal()` |
| **GateModule 모달** | modules/gate.js (JS 동적 생성) | camera.js, result.js, shared.js (충전) | `GateModule.showLoginRequired(msg, cb)` |

| 항목 | 인라인 모달 (index.html) | GateModule (gate.js) | 문제 |
|------|------------------------|---------------------|------|
| **KR 버튼** | Google + Kakao + LINE | Google + Kakao + LINE | ✅ 일치 |
| **JP 버튼** | Google + LINE | Google + LINE | ✅ 일치 |
| **닫기 방식** | X 버튼 + 배경 클릭 | "닫기" 텍스트 버튼 | ⚠️ UX 차이 |
| **디자인** | 바텀시트 (슬라이드업) | 중앙 카드 (흰색 배경) | ⚠️ 비주얼 불일치 |
| **콜백 기능** | 없음 (단순 로그인) | 있음 (로그인 후 원래 액션 재시도) | ⚠️ 기능 차이 |

**판정:** 기능적으로는 동작하지만, 사용자가 같은 서비스에서 다른 스타일의 로그인 모달을 경험하게 됨.

### 1-2. 게이트 메시지 일관성

| 트리거 | KR 메시지 | JP 메시지 | 일관성 |
|--------|----------|----------|--------|
| 헤더 로그인 | (모달 타이틀만) | (모달 타이틀만) | ✅ |
| 촬영 진입 | "촬영을 시작하려면 로그인이 필요합니다\n첫 로그인 시 10c를 드려요!" | "撮影を開始するにはログインが必要です\n初回ログインで10cプレゼント！" | ✅ |
| 리터칭 시도 | "리터칭을 진행하려면 로그인이 필요합니다\n첫 로그인 시 10c를 드려요!" | "リタッチするにはログインが必要です\n初回ログインで10cプレゼント！" | ✅ |
| 다운로드 시도 | "다운로드하려면 로그인이 필요합니다" | "ダウンロードにはログインが必要です" | ⚠️ 10c 보너스 안내 누락 |
| 충전 시도 | "크레딧 충전은 로그인이 필요합니다\n첫 로그인 시 10c를 드려요!" | "クレジットチャージにはログインが必要です\n初回ログインで10cプレゼント！" | ✅ |

**판정:** 다운로드 게이트 메시지만 10c 보너스 안내가 빠져있음 (KR/JP 동일). 의도적일 수 있으나 일관성 부족.

### 1-3. 로그인 후 헤더 상태 전환

| 항목 | KR | JP | 일관성 |
|------|----|----|--------|
| 로그인 전 | "로그인" 버튼 | "ログイン" 버튼 | ✅ |
| 로그인 후 | Cr 코인 + 잔고 표시 | Cr 코인 + 잔고 표시 | ✅ |
| 전환 방식 | `updateAuthUI()` display 토글 | 동일 | ✅ |
| 크레딧 뱃지 클릭 | **Portal 이동** (`monkos.ai/credits?from=...`) | **로컬 이동** (`/charge.html?return=index`) | **❌ 불일치** |

**판정:** KR은 크레딧 뱃지 클릭 시 Portal 외부 페이지로 이동, JP는 로컬 charge.html로 이동. 사용자 경험이 완전히 다름.

## 2. 충전 모달(ChargeModule) UX

### 2-1. 상품 카드

| 항목 | KR | JP | 일관성 |
|------|----|----|--------|
| 패키지 수 | 4개 (70c/100c/300c/500c) | 4개 + topup_10 (총 5개) | ⚠️ JP 1개 더 |
| BEST 배지 | package_500 (₩49,900) | package_100 (¥1,490) | ⚠️ 의도적 차이 |
| 통화 | ₩ KRW | ¥ JPY | ✅ 지역화 |
| 카드 구조 | 좌: 크레딧+보너스, 우: 취소선+실가 | 동일 | ✅ |
| 카테고리 라벨 | "1장 완성" / "패키지" | "1枚分" / "パッケージ" | ✅ |

### 2-2. 투터치 결제 UX

| 항목 | KR | JP | 일관성 |
|------|----|----|--------|
| 1탭: 선택 | 초록 그라데이션 + "₩X,XXX 결제" | 초록 + "¥X,XXX 決済" | ✅ |
| 2탭: 결제 실행 | `buyCreditsKR(amount, credits)` | `buyCreditsJP(opt)` | ✅ (API 차이) |
| 선택 해제 | 다른 카드 탭 or 빈 영역 탭 | 동일 | ✅ |
| 안내 문구 | 없음 (투터치 UX 설명 없음) | 없음 | ⚠️ 양쪽 모두 없음 |

**판정:** 투터치 결제 패턴 자체는 잘 동작하나, "한 번 더 탭하면 결제됩니다" 등의 안내가 없어 첫 사용자가 혼동할 수 있음.

### 2-3. 소액 스테퍼

| 항목 | KR | JP | 일관성 |
|------|----|----|--------|
| 범위 | 10c~100c | 10c~100c | ✅ |
| 단가 표시 | ₩1,450 / 10c | ¥150 / 10c | ✅ |
| 최소·최대 안내 | "최소 10c · 최대 100c" | "最小10c · 最大100c" | ✅ |
| 결제 방식 | `buyCreditsKR(qty*1450, qty*10)` | `CHARGE_OPTIONS.find(topup_10)` → `buyCreditsJP(opt)` | ⚠️ 로직 차이 |

**판정:** KR 스테퍼는 수량에 비례한 자유금액 결제, JP 스테퍼는 항상 topup_10 단일 상품으로 결제. **JP에서 20c~100c 스테퍼 결제 시 실제로는 10c 상품 1개만 결제됨** — 표시 수량과 결제 수량 불일치 가능성.

### 3-2. 다운로드 흐름

```
사용자 클릭 "📥 고화질 다운로드 (70c)"
  → 로그인 체크 (미로그인 → GateModule)
  → GCS path 확인
  → 크레딧 체크 (부족 → showCreditModal → ChargeModule)
  → POST /api/download { userId, gcsPath, format }
  → 서버: 크레딧 차감 + 크롭 + 서명URL 반환
  → 클라이언트: sessionStorage 저장 → thankyou.html 이동
```

KR/JP 동일 흐름. ✅

### 3-3. 서버 크롭 vs 클라이언트 크롭

| 단계 | 처리 위치 | 용도 | 품질 |
|------|----------|------|------|
| **생성 프리뷰** | 클라이언트 (Monk.media.crop) | UI 미리보기 | 워터마크 포함 |
| **최종 다운로드** | 서버 (/api/download) | 실제 납품물 | 원본 품질 |

**판정:** 사용자 관점에서 크롭 차이는 보이지 않음 (프리뷰 → 최종본 자연 전환). ✅

**판정:** JP thankyou.html에서 이벤트·보증·CS·정책 카드가 모두 삭제됨. 사용자 신뢰·참여·지원 기능이 전면 부재. 의도적 현지화인지 누락인지 확인 필요.

### 4-3. sessionStorage 의존

| 항목 | 동작 |
|------|------|
| 데이터 소스 | `sessionStorage` (monkos_cropped, monkos_format, monkos_compare, monkos_originalUrl) |
| 탭 닫기 | sessionStorage 삭제 → **재방문 불가** |
| 재방문 시 | `/` (홈)으로 리다이렉트 |
| 뒤로가기 | `history.replaceState`로 차단 |

**판정:** sessionStorage 의존 = 탭 닫으면 사진 소멸. 다운로드 완료 사용자에게는 문제 없으나, 실수로 탭을 닫을 경우 복구 불가. KR/JP 동일 동작. ✅ (제약사항 인지)
