### 과금 경로 상세

#### ① 생성 (10c) — 서버측 차감

```
클라이언트                              서버 (/api/idgen)
  pipe.run('generate', {userId}) ──→   userId 존재?
                                         ├─ Y → useCredits(userId, 'generate')
                                         │    ├─ 성공 → Imagen 호출 → 결과 반환
                                         │    └─ 실패 → 402 {error, credits, required:10}
                                         └─ N → 무료 로그 기록 → Imagen 호출
                                       Imagen 실패 시 → refundCredits(userId, 'generate')
```

- **환불 로직 있음**: 서버에서 생성 실패 시 `refundCredits()` 호출 (server.js:689-693, 770-771, 777)
- **비로그인**: userId 미전달 시 서버측 차감 스킵, 클라이언트측 localStorage로 1회 제한

#### ② 다운로드 (70c) — 클라이언트측 차감 요청

```
downloadResult()
  ├─ 비로그인 → GateModule.buyDirect() [₩9,900]
  ├─ 잔액 부족 → pending_action='download' → charge.html 이동
  └─ 잔액 충분 → doDownload()
       └─ pipe.run('creditUse', {type:'download'}) → /api/credit/use → Portal API
           ├─ 성공 → store.user.credits 갱신 → showThankYou → cropAndShowPostDownload
           └─ 402 → charge.html 이동
```

- **환불 로직 없음**: 다운로드 실패 시 환불 미구현
- **⚠️ 버튼 비활성화 없음**: doDownload() 실행 중 다운로드 버튼이 활성 상태 유지

#### ③ 추가규격 (10c)

```
selectSpec(specKey)
  ├─ specKey === _currentSpec → 무시 (return)
  ├─ _specCache[specKey] 존재 → switchToSpec() [무과금]
  ├─ 비로그인 → return [무동작]
  ├─ 잔액 부족 → charge.html 이동
  └─ 잔액 충분 → pipe.run('creditUse', {type:'extra_crop'}) → crop → 캐시 저장
```

- **캐시 방어**: 한번 구매한 규격은 `_specCache`에 저장, 재선택 시 무과금
- **⚠️ 캐시 소실**: 페이지 새로고침 시 `_specCache` 초기화 → 재구매 필요

#### ④ 풀원본 (20c)

```
downloadFullOriginal()
  ├─ _fullOriginal 없음 → return
  ├─ 비로그인 → return
  ├─ 잔액 부족 → charge.html 이동
  └─ 잔액 충분 → pipe.run('creditUse', {type:'full_original'}) → JPEG 변환 → 다운로드
       └─ 성공 시 버튼 onclick → redownloadFullOriginal(jpegUrl) [추가 과금 없음]
```

- **재다운로드 방어**: 구매 후 버튼 onclick을 `redownloadFullOriginal()`로 교체 → 무과금 재다운로드
- **⚠️ 방어 소실**: 페이지 새로고침 시 버튼 onclick 교체가 초기화됨

| 과금 지점 | 클라이언트 잔액 체크 | 서버 차감 | 레이스 가능성 |
|----------|-------------------|----------|-------------|

| 다운로드 | result.js:347 `store.user.credits < 70` | `/api/credit/use` | ⚠️ 클라이언트 체크 → 서버 차감 사이 갭 |

## 3. 시나리오별 과금 경로 추적표

### 시나리오 A: 생성 10c → 다운로드 70c (정상 1회)

```
[1] confirmAndGenerate() → pipe.run('generate', {userId})
    → 서버 /api/idgen → useCredits(userId, 'generate') → -10c
[2] 생성 성공 → 워터마크 프리뷰 표시 → 다운로드 버튼 활성화
[3] downloadResult() → 잔액 체크 (>=70) → doDownload()
    → pipe.run('creditUse', {type:'download'}) → -70c
[4] showThankYou → 원본 교체 → cropAndShowPostDownload()
```

**총 과금: 80c** ✅ 정상

### 시나리오 B: 다운로드 후 추가 규격 10c

```
[1] 다운로드 완료 → 포스트 다운로드 화면 → 규격 탭 표시
[2] _currentSpec = 'passport' (최초 생성 규격, cropAndShowPostDownload에서 캐시됨)
[3] selectSpec('id') → _specCache['id'] 없음 → 10c 차감
    → pipe.run('creditUse', {type:'extra_crop'}) → crop → _specCache['id'] 저장
[4] selectSpec('passport') → _specCache['passport'] 존재 → switchToSpec() → 0c
```

**추가 과금: 10c** ✅ 캐시 히트 시 무과금 정상
**⚠️ 캐시 미영속**: `_specCache`는 모듈 스코프 → 새로고침 시 소실 → 재구매 필요

### 시나리오 C: 다운로드 후 페이지 새로고침 ← ⚠️ 이중과금 핵심

```
[1] doDownload() 성공 → store.downloadComplete = true (메모리만)
[2] downloadResult() 시작 시 sessionStorage._mo_p 저장됨 (result.js:337)
[3] cropAndShowPostDownload() → showStep3Actions = false (다운로드 버튼 숨김)

--- 페이지 새로고침 ---

[4] init() 실행:
    - sessionStorage._mo_p → _fullOriginal 복원 → _mo_p 삭제 (result.js:709-714)
    - sessionStorage.monkos_generated → store.generated 복원 (워터마크 버전)
    - store.downloadComplete = false (기본값, 미영속)
    - store.generated 존재 → step 3 복원 → showStep3Actions = true ← 다운로드 버튼 재표시!
    - pending_action 없음 → 자동 진행 없음

[5] 사용자가 다운로드 버튼 클릭 → downloadResult()
    - _mo_p 다시 저장 (복원된 _fullOriginal)
    - 로그인 체크 통과, 잔액 체크 통과 → doDownload()
    - pipe.run('creditUse', {type:'download'}) → -70c 재차감!
```

**⚠️ 이중과금 발생. 원인:**
1. `store.downloadComplete` 미영속 (sessionStorage에 저장하지 않음)
2. 새로고침 시 step 3 + 다운로드 버튼 상태로 복원
3. `_mo_p` → `_fullOriginal` → `downloadResult()` → `_mo_p` 재저장 → **무한 반복 가능**

### 시나리오 D: 크레딧 부족 → 충전 → 복귀 → 자동 진행

```
[1] downloadResult() → 잔액 부족 (< 70c)
    - sessionStorage.monkos_pending_action = 'download'
    - sessionStorage._mo_p = _fullOriginal (result.js:337)
    - navigateTo('charge.html?return=result&action=download')

[2] charge.html에서 충전 완료 → 돌아가기 클릭 → result.html

[3] init() 실행:
    - _mo_p → _fullOriginal 복원 (result.js:709-714)
    - GateModule.initDirectPayment() → toss=direct 아님 → 스킵
    - store.generated 복원 → step 3 표시
    - pendingAction === 'download' + 잔액 >= 70
      → sessionStorage.removeItem('monkos_pending_action')
      → setTimeout(downloadResult, 300) ← 자동 진행!

[4] downloadResult() → 잔액 충분 → doDownload() → -70c → 포스트 다운로드
```

**자동 진행 정상 동작** ✅

**⚠️ 단, selectSpec/downloadFullOriginal은 pending_action 미설정:**
- `selectSpec()` → charge.html 이동 시 `pending_action` 미기록 (result.js:549)
- `downloadFullOriginal()` → charge.html 이동 시 `pending_action` 미기록 (result.js:590)
- 충전 후 복귀해도 자동 진행 없음 → 사용자가 수동으로 다시 클릭해야 함

### 시나리오 E: 비로그인 1회 무료 → 다운로드
