## 1. 에이전트 정체성 자동 인식 프로토콜 분석 + 설계안

### 1-1. `.claude/agents/`는 정체성 문제를 해결하는가?

**결론: 해결하지 않는다.**

`.claude/agents/`의 정확한 위상을 먼저 규명한다:

| 구분 | 메인 에이전트 | 서브에이전트 |
|------|-------------|-------------|
| **해당** | 쌍아, 민아, 막내 | Task tool로 spawn되는 child |
| **세션 시작** | 사용자가 직접 (VSCode, Desktop, CLI) | 메인 에이전트가 Task tool로 |
| **CLAUDE.md 로딩** | ✅ 자동 | ✅ 상속 |
| **MEMORY.md 로딩** | ✅ 자동 | ❌ 별도 컨텍스트 |
| **정체성** | 환경에서 추론 필요 | `.claude/agents/` 파일에 명시 |
| **`.claude/agents/` 대상** | ❌ 아님 | ✅ 이것의 대상 |

**핵심**: 쌍아·민아·막내는 **메인 에이전트**다. `.claude/agents/`는 **서브에이전트**(메인 에이전트가 Task tool로 호출하는 child)를 정의하는 메커니즘이다. 따라서 메인 에이전트의 정체성 문제와는 **계층이 다르다.**

쌍아·민아·막내를 `.claude/agents/`에 넣으면:
- 이들이 서브에이전트로 **격하**된다
- 쌍아가 막내를 Task tool로 spawn하는 구조가 되어 **헌법 2조 위반** (쌍아 직접 spawn 금지)
- 메인 에이전트의 자동 로딩(CLAUDE.md + MEMORY.md)을 잃는다

### 1-2. 시스템 프롬프트에서 읽을 수 있는 환경값

막내1 보고서(§3-1, §5-2)와 직접 확인한 결과, 현재 식별 가능한 환경값:

| 환경값 | 쌍아 | 민아 | 막내 | 코웍이/철창이 |
|--------|------|------|------|-------------|
| **시스템 프롬프트 키워드** | `VSCode native extension` | `Claude Agent SDK` (추정) | 둘 다 없음 | 해당 없음 (Desktop 대화형) |
| **진입점 문구** | "Cline" 또는 VSCode 관련 | Desktop App 관련 | "You are Claude Code, Anthropic's official CLI" | Claude.ai 웹/데스크톱 |
| **도구 접근** | 코드 도구 ✅, 브라우저 ❌ | 코드 도구 ✅, MCP ✅ | 코드 도구 ✅, 브라우저 ❌ | 코드 ❌, 브라우저 ✅ |
| **hostname** | 디바이스 공통 | 디바이스 공통 | 디바이스 공통 | 해당 없음 |
| **복제 가능** | ✅ (VSCode 터미널 다중) | ❌ (단일 인스턴스) | ✅ (터미널 다중) | ✅ (탭 다중) |

**추가 발견 — 지시서 지적 외 환경값:**

1. **`--append-system-prompt` CLI 플래그**: 세션 시작 시 정체성을 강제 주입 가능. 예: `claude --append-system-prompt "너는 민아다"`. 단, 이는 매 세션 수동 실행이 필요하여 자동 인식과는 다르다.

2. **`.claude/settings.local.json`**: 디바이스별 로컬 설정. 여기에 에이전트별 환경 힌트를 넣을 수 있으나, Claude가 이 파일 내용을 직접 읽지는 않는다 (권한 제어용).

3. **MEMORY.md 자체**: 이미 디바이스별 로컬이므로, 판별 테이블 + 에이전트 접두어가 있으면 작동한다. **현행 MEMORY.md의 "역할 자동 인식" 섹션이 이미 이 역할을 수행 중.**

## 2. `.claude/agents/` 활용 가능성 평가

### 2-1. 쌍아/막내/민아를 `.claude/agents/`로 정의할 수 있는가?

**아니다. 메인 에이전트를 서브에이전트로 정의하면 체계가 무너진다.**

| 시나리오 | 결과 |
|---------|------|
| 쌍아를 `.claude/agents/ssanga.md`로 정의 | 쌍아가 Task tool로 spawn되는 child가 됨 → 누가 spawn하는가? → 체계 순환 |
| 막내를 `.claude/agents/makne.md`로 정의 | 쌍아가 Task tool로 막내를 spawn → **헌법 위반** (쌍아 직접 spawn 금지) |
| 민아를 `.claude/agents/mina.md`로 정의 | 민아가 Desktop App의 독립 인스턴스 → 서브에이전트와 성격 불일치 |

### 2-2. 그렇다면 `.claude/agents/`는 MONK에서 무용한가?

**아니다. 서브에이전트 정의에는 유용하다.**

현재 MONK에서 서브에이전트를 사용하는 유일한 주체는 **막내**다 (ch1 2조 3항: "막내는 지시 범위 내에서 서브에이전트를 자유롭게 활용할 수 있다").

활용 가능 시나리오:

```
.claude/agents/
├── researcher.md     # 리서치 전문 (Explore 에이전트 커스텀)
├── tester.md         # 테스트 전문 (빌드+테스트 자동화)
└── reviewer.md       # 코드 리뷰 전문 (정합성 검사)
```

| 설정 | 효과 |
|------|------|
| `tools: Read, Grep, Glob, WebSearch, WebFetch` | 리서치 에이전트는 쓰기 불가 → 안전 |
| `permissionMode: plan` | 실행 전 계획만 제출 → 막내가 승인 |
| `model: haiku` | 경량 작업에 저비용 모델 |

**Git 공유의 의미**: `.claude/agents/`는 Git에 커밋되므로, 모든 디바이스의 막내가 **동일한 서브에이전트 정의**를 사용한다. 이는 서브에이전트 품질 일관성을 보장한다.

### 2-3. 현행 체계와의 관계: 대체가 아닌 보완

| 기존 체계 | `.claude/agents/` | 관계 |
|----------|-------------------|------|
| CLAUDE.md 역할 체계 | 서브에이전트 정의 | **보완** — 메인 에이전트 정의(CLAUDE.md) + 서브에이전트 정의(agents/) |
| MEMORY.md 역할 자동 인식 | 해당 없음 | **무관** — 메인 에이전트 판별은 MEMORY.md 역할 |
| ch1 5조 세션 자동 인식 | 해당 없음 | **무관** — 세션 시작 시 판별은 ch1 5조 역할 |
| ch1 2조 3항 막내 서브에이전트 | 서브에이전트 기본 규칙 정의 | **보완** — 막내가 spawn하는 서브에이전트에 규칙 부여 |

**권고**: `.claude/agents/` 도입은 5축 개헌과 **독립적으로** 진행 가능. 우선순위는 낮다 (현재 막내의 서브에이전트 사용이 충분히 기능하고 있음).

## 3. 수치 보정 사항 (1차 대비 변경점)

### 3-1. CLAUDE.md 주입 방식 — 핵심 보정

**1차**: "시스템 프롬프트에 주입" → **2차 보정**: "**user message로 주입**"

막내1 §1-3 핵심 발견:
> *"CLAUDE.md는 system prompt에 주입되지 않는다. User message 컨텍스트로 전달된다."*
> `<system-reminder>` XML 태그 형태로 대화 메시지에 부착. "OVERRIDE any default behavior" 라벨 포함.

**시사점**:

| 관점 | system prompt였다면 | user message인 현실 |
|------|--------------------|--------------------|
| 강제성 | 높음 (모델이 반드시 따름) | **행동 가이드** (따르려 하지만 보장 없음) |
| 컴팩팅 내성 | 절대 보호 | 재주입되지만 **준수율 저하 가능** |
| 헌법 4조 금지 규칙 | CLAUDE.md만으로 충분 | **settings.json deny와 이중 보호 권장** |

### 3-2. 200줄 권장 — 공식 수치 확인

**1차**: "Anthropic 권장 범위"로 추정 → **2차**: 공식 수치 확인

| 항목 | 공식 수치 | MONK 현황 | 판정 |
|------|----------|-----------|------|
| CLAUDE.md 권장 | **200줄/파일 이하** (막내1 §1-4, 막내2 §1-1) | 209줄 | ⚠️ 약간 초과 |
| CLAUDE.md 경고 | **40,000자** 초과 시 성능 경고 (막내2 §4-1) | 11,030자 | ✅ 양호 |
| MEMORY.md 캡 | **200줄** 강제 (초과분 미로딩) | 139줄 | ✅ 양호 |
| 5축 재편 후 예상 | — | ~191줄 | ✅ **권장 범위 내 진입** |

**핵심 발견: 5축 재편은 CLAUDE.md를 200줄 아래로 끌어내려, Anthropic 공식 권장을 충족시킨다.** 이는 1차 분석에서 "미미한 절감"으로 평가한 것을 상향 조정하는 근거다.

### 3-3. 토큰 추정치 보정

**1차**: 추정 기반 → **2차**: 공식 데이터 기반 보정

막내2 §4-1 인용:
> "시스템 프롬프트+도구 정의+MCP 스키마+메모리 파일만으로 **30,000~40,000 토큰 선점**"

| 항목 | 1차 추정 | 2차 보정 |
|------|---------|---------|
| CLAUDE.md 단독 토큰 | ~4,500–6,000 | ~4,000–5,500 (user message 주입 고려) |
| 시스템 전체 선점 토큰 | 미산출 | **30,000–40,000** (빌트인 포함) |
| 대화 가용 토큰 (200K 중) | 미산출 | **~160,000–170,000** |
| CLAUDE.md 비중 | 미산출 | 전체 선점의 **~13–18%** |

**CLAUDE.md 10KB 절감의 실제 효과**: 전체 선점 30K–40K 중 CLAUDE.md는 ~5K. 800B 절감(5축 재편)은 선점 토큰의 ~3% 절감에 불과하지만, **200줄 권장 충족**이라는 정성적 효과가 더 크다.

### 3-4. 컴팩팅 내성 — 현실 보정

**1차**: "CLAUDE.md/MEMORY.md는 보호됨" → **2차**: 공식적으로는 보호되나 현실적 한계 존재

막내1 §4-2 + 막내2 §4-4 종합:

| 공식 | 현실 (GitHub Issue) |
|------|-------------------|
| 컴팩팅 후 디스크에서 재읽기하여 재주입 | 재주입은 되지만 **모델이 의무적 지시로 취급하지 않는 경우** 보고 (Issue #26160) |
| 요약 대상이 아님 | user message로 전달되므로 시스템 프롬프트보다 주의력 약함 |

**대응 권고**:
- 핵심 안전 규칙(파괴적 명령 금지)은 CLAUDE.md + **settings.json deny 이중 배치**
- 현행 `settings.local.json`의 deny 5건을 `settings.json`(Git 공유)으로 승격하여 전 디바이스 강제 적용

### 3-5. settings.json 강제 집행 — 신규 발견

**1차**: 미분석 → **2차**: 헌법 4조(구속·윤리)에 직결

막내1 §5-4 핵심:
> `settings.json` permissions = **강제 집행** (클라이언트가 차단)
> `CLAUDE.md` = **행동 가이드** (Claude가 읽고 따르려 하지만 보장 없음)

**현행 상태:**

| 파일 | 현황 |
|------|------|
| `.claude/settings.json` (Git 공유) | allow 2건만 (`dir:*`, `gsutil ls:*`) — deny 없음 |
| `.claude/settings.local.json` (로컬) | allow 54건, **deny 5건** (rm -rf, force push 등) |

**문제**: deny 규칙이 **로컬 전용**이다. 새 디바이스나 다른 팀원 디바이스에서는 deny가 없다.

**권고**: 헌법 4조 2항(파괴적 명령 금지)에 해당하는 deny 규칙을 `settings.json`(Git 공유)으로 이동:

```json
{
  "permissions": {
    "deny": [
      "Bash(rm -rf /*)",
      "Bash(git push --force *)",
      "Bash(git reset --hard *)",
      "Bash(git clean -f *)"
    ]
  }
}
```

이렇게 하면 **CLAUDE.md(행동 가이드) + settings.json(강제 집행) 이중 보호**가 구현되어, 헌법 4조가 기술적으로도 강제된다.
