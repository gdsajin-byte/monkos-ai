## 2. 원인 분석

### A. 코칭 "음성이 안 나옴" — 서버 정상, 클라이언트 TTS 의존

| 구간 | 상태 | 근거 |
|------|------|------|
| WebSocket 연결 | ✅ 정상 | Cloud Run 로그 |
| Gemini Live 세션 | ✅ 정상 | 세션 초기화 완료 로그 |
| 코칭 텍스트 응답 | ✅ 정상 | 실제 한국어 코칭 메시지 확인 |
| 클라이언트 TTS (Web Speech API) | ⚠️ 브라우저 의존 | 코드 정상, iOS Safari user gesture 요구 |

서버→클라이언트 텍스트 전달은 정상. "음성이 안 나옴"은 다음 중 하나:
1. 모바일 브라우저 TTS 비활성 상태에서 첫 코칭 메시지 도달 (user gesture 미완)
2. 특정 기기에서 한국어 음성(Yuna/ko-KR)이 지원되지 않음
3. 이전 배포 버전에서의 이슈 (현재 배포본은 정상)

코칭 텍스트 자체는 화면에 표시됨 (`#coaching-text` data-bind).

### B. QC 결과 미전달 — **핵심 버그**

**Root cause: KR result.js에서 /api/qc를 호출하지 않음.**

| 항목 | JP (정상) | KR (버그) |
|------|----------|----------|
| 생성 후 QC 호출 | ✅ `/api/qc` 자동 호출 | ❌ 호출 안 함 |
| QC 결과 UI | ✅ 챗 스타일 배지 | ❌ UI 없음 |
| QC 폴백 모델 | ✅ gemini-3-flash → 2.0-flash | ❌ 단일 모델 |

KR server.js에 `/api/qc` 엔드포인트는 존재하지만, 클라이언트 result.js 파이프라인에서 완전히 누락.

### C. QC/PreCheck 폴백 없음

| 항목 | JP | KR (수정 전) |
|------|----|----|
| QC 모델 | `['gemini-3-flash-preview', 'gemini-2.0-flash']` | `'gemini-2.0-flash'` 단일 |
| PreCheck 모델 | 동일 폴백 | `'gemini-2.0-flash'` 단일 |
