## 임무 A: 현재 KR 토스 SDK 방식 전체 파악

### A-1. 현재 Toss 라이브러리 로드 방식

| 항목 | 값 |
|------|-----|
| CDN URL | `https://js.tosspayments.com/v1/payment` |
| 로드 위치 | `charge.html:37` (`<script>` 태그) |
| 버전 | v1 SDK (API 개별 연동 방식) |
| 키 종류 | **API 개별 연동키** (위젯 연동키 아님) |

> **주의**: `index.html`에는 토스 SDK 스크립트가 없음. `charge.html`에서만 로드됨.

> `TossPayments` 글로벌 미정의로 에러 발생 가능성 있음.

### A-2. TossPayments 초기화 코드 위치

| 파일 | 라인 | 코드 |

### A-3. requestPayment() 호출 파라미터 전체

**위치**: `shared.js:157-165`

```js
await tossPayments.requestPayment('카드', {
  amount: amount,
  orderId: orderId,
  orderName: `MONKOS ${credits} 크레딧`,
  successUrl: `${window.location.origin}${window.location.pathname}?toss=success`,
  failUrl: `${window.location.origin}${window.location.pathname}?toss=fail`,
  customerEmail: store.user.email || undefined,
  customerName: store.user.name || undefined,
});
```

| 파라미터 | 값 |
|---------|-----|
| 결제수단 | `'카드'` (하드코딩) |
| amount | 함수 인자 (패키지 가격 또는 스테퍼 가격) |
| orderId | `MONKOS_{uid8자}_{timestamp}_{random6자}` |
| orderName | `MONKOS {credits} 크레딧` |
| successUrl | 동일 페이지 + `?toss=success` |
| failUrl | 동일 페이지 + `?toss=fail` |
| customerEmail | `store.user.email` (Firebase Auth) |
| customerName | `store.user.name` (Firebase Auth) |

### A-4. redirect URL 구조

- **successUrl**: `{origin}{pathname}?toss=success`
  - 토스가 `paymentKey`, `orderId`, `amount`를 추가 쿼리 파라미터로 붙여줌
- **failUrl**: `{origin}{pathname}?toss=fail`
  - 토스가 `message` 파라미터를 붙여줌
- 동일 페이지로 리다이렉트 → `initFromTossResult()`에서 쿼리 파라미터 처리

### A-5. initFromTossResult() 전체 로직

**위치**: `shared.js:188-229`

```
1. URL params에서 toss=fail 체크 → alert(message) → history.replaceState로 정리
2. URL params에서 toss=success 체크:
   a. 로딩 오버레이 표시
   b. paymentKey, orderId, amount 추출
   c. history.replaceState로 URL 정리
   d. Portal에 POST 확인 요청
   e. 성공 → store.user.credits 갱신 + alert
   f. 실패 → alert(error)
```

### A-6. Portal toss/confirm 엔드포인트 파라미터

**위치**: `portal/lib/payments.js:171-263` (`handleTossConfirm`)

**요청 파라미터**: `{ paymentKey, orderId, amount, userId }`

**처리 흐름**:
1. PRODUCTS에서 `amount`로 상품 매핑 → `credits + bonus` 산출
2. 매핑 실패 시 정가(₩145/c) 기준 10c 배수 검증
3. 토스 API `https://api.tosspayments.com/v1/payments/confirm` 호출 (Basic Auth)
4. Firestore 크레딧 추가 (트랜잭션)
5. payments 컬렉션 기록
6. 응답: `{ success, credits, creditsAdded, orderId }`

## 임무 B: 토스 위젯 방식 비교 분석

### B-1. SDK 방식 vs 위젯 방식 비교

| 항목 | 현재 (SDK v1 개별연동) | 위젯 v1 | 위젯 SDK v2 |
|------|----------------------|---------|------------|
| CDN URL | `js.tosspayments.com/v1/payment` | `js.tosspayments.com/v1/payment-widget` | 변경됨 (v2 통합 SDK) |
| 초기화 | `TossPayments(clientKey)` | `PaymentWidget(clientKey, customerKey)` | `TossPayments(clientKey)` → `.widgets({customerKey})` |
| 결제수단 | `requestPayment('카드', {...})` 직접 지정 | 위젯이 결제수단 UI 자동 렌더링 | `setAmount()` → `renderPaymentMethods()` |
| DOM 필요 | 없음 (팝업/리다이렉트) | `#payment-method`, `#agreement` 마운트 | 동일 |
| customerKey | 불필요 | **필수** | **필수** |
| 클라이언트 키 | API 개별 연동키 | **결제위젯 연동키** (별도) | **결제위젯 연동키** (별도) |
| 결제수단 선택 | 없음 (카드 고정) | 카드/간편결제/계좌이체 등 자동 | 동일 |
| confirm API | `v1/payments/confirm` | **동일** | **동일** |

### B-2. 위젯 v1 코드 예시 (블로그 참조)

```js
// CDN
<script src="https://js.tosspayments.com/v1/payment-widget"></script>

// 초기화
const paymentWidget = PaymentWidget(clientKey, customerKey);
// 비회원: PaymentWidget(clientKey, PaymentWidget.ANONYMOUS)

// 렌더링
paymentWidget.renderPaymentMethods('#payment-method', amount);
paymentWidget.renderAgreement('#agreement');

// 결제 요청
paymentWidget.requestPayment({
  orderId: 'AD8aZDpbzXs4EQa-UkIX6',
  orderName: '토스 티셔츠',
  successUrl: 'http://localhost:8080/success',
  failUrl: 'http://localhost:8080/fail',
  customerEmail: 'customer@email.com',
  customerName: '김토스',
});
```

### B-3. 위젯 SDK v2 코드 예시

```js
// 초기화
const tossPayments = TossPayments(clientKey);
const paymentWidget = tossPayments.widgets({ customerKey: `customer_${userId}` });

// 금액 설정 (v2 필수)
await paymentWidget.setAmount({ currency: 'KRW', value: totalAmount });

// 렌더링
await paymentWidget.renderPaymentMethods({ selector: '#payment-method', variantKey: 'DEFAULT' });
await paymentWidget.renderAgreement({ selector: '#agreement' });

// 결제 요청
await paymentWidget.requestPayment({
  orderId: orderId,
  orderName: 'MONKOS 80 크레딧',
  successUrl: `${origin}/checkout/success`,
  failUrl: `${origin}/checkout/fail`,
  customerEmail: user.email,
  customerName: user.name,
});
```

### B-4. customerKey 필요 — 현재 KR 앱 사용자 식별자(uid) 확인

- `store.user.id` = Firebase Auth uid (Portal `/api/auth/verify-cookie`로 취득)
- `shared.js:261-262`: `data.user.id` → `store.user.id`에 바인딩
- Firebase Auth uid는 28자 랜덤 문자열 (예: `abc123XYZ...`) → **customerKey로 사용 가능**

### B-5. 위젯 DOM 렌더링 — 마운트 포인트 적합 위치

현재 충전 UI:
- `charge.html`: 패키지 카드 + 스테퍼 (풀 페이지)
- `modules/charge.js`: 바텀시트 모달 (다른 페이지에서 호출)

**위젯 마운트 고려사항**:
- 위젯은 결제수단 선택 UI(카드/간편결제/계좌이체)를 **자체 렌더링**
- 현재 패키지 카드(금액 선택) → 위젯(결제수단 선택) → 결제 순서가 됨
- `charge.html`에 `<div id="payment-method"></div>`, `<div id="agreement"></div>` 추가 필요
- 바텀시트 모달(`charge.js`)에도 동일 DOM 필요 → 모달 높이 증가 예상

### B-6. 위젯 CDN URL

| 방식 | URL |
|------|-----|
| 위젯 v1 | `https://js.tosspayments.com/v1/payment-widget` |
| SDK v2 (통합) | 토스 공식 문서 참조 필요 (JS 렌더링 사이트라 정확한 URL 미확인) |

### B-7. Portal confirm 엔드포인트 변경 필요 여부

**변경 불필요**. 토스 공식 문서 확인 결과:
> "API에는 변경사항이 없기 때문에 클라이언트 코드만 변경하면 바로 최신 버전의 SDK를 사용할 수 있습니다."

`https://api.tosspayments.com/v1/payments/confirm` 동일하게 사용.

## 임무 D: customerKey 전략 파악

### D-1. Firebase Auth uid 사용 여부

**예, 사용 중.**

- `shared.js:254-279` (`initCredits`): Portal `/api/auth/verify-cookie` → `data.user.id` → `store.user.id`
- `shared.js:152`: orderId에 `store.user.id.slice(0, 8)` 포함
- `shared.js:213`: confirm 요청에 `userId: store.user.id` 전송

### D-2. 익명 로그인 구조

**비회원 결제 불가 (현재).**

- `shared.js:135-142`: `buyCreditsKR()`에서 `store.user.id` 없으면 로그인 요구 모달 표시
- 별도로 `handleTossDirect` (Portal)이 비로그인 직접결제를 지원하지만, 현재 KR 앱 프론트에서는 호출하지 않음

### D-3. customerKey = uid 사용 가능 여부

| 항목 | 판단 |
|------|------|
| Firebase Auth uid 형식 | 28자 영숫자 랜덤 문자열 |
| 유추 가능성 | 낮음 (UUID급 랜덤) |
| 토스 요구사항 충족 | **충족** (충분히 무작위적인 고유 값) |
| 별도 생성 필요 | **불필요** |

### D-4. customerKey 전략 제안

```js
// 회원 결제 (현재 프론트 구조에 적합)
const customerKey = store.user.id;  // Firebase Auth uid

// 비회원 결제 (향후 필요 시)
// v1: PaymentWidget(clientKey, PaymentWidget.ANONYMOUS)
// v2: tossPayments.widgets({ customerKey: PaymentWidget.ANONYMOUS })
```

## 전환 설계 시 고려사항

### 1. 위젯 연동키 발급 필요
- 현재 `test_ck_6bJXmgo28eBJk12vvDAW3LAnGKWx`는 API 개별 연동 **테스트키**
- 위젯 방식은 **별도 위젯 연동키** 필요 → 토스 대시보드에서 발급
- 테스트키/라이브키 모두 새로 필요

### 2. UX 설계 필요 — 위젯 UI 배치
- 위젯은 결제수단 선택 UI + 약관 동의 UI를 **자체 렌더링**
- 현재 플로우: 패키지 선택 → 바로 결제창 팝업
- 위젯 플로우: 패키지 선택 → 위젯 UI(결제수단+약관) 표시 → 결제 버튼 클릭
- **바텀시트 모달에서 위젯 렌더링 시 높이 증가** → UX 설계 필요

### 3. v1 위젯 vs v2 SDK 선택
- v1 위젯: 단순, 코드량 적음, 하지만 업데이트 중단 예고
- v2 SDK: 최신, 장기 지원, 하지만 `setAmount()` 등 추가 단계 필요
- **권장: v2 SDK** (토스 공식 권장, v1은 업데이트 중단)

### 4. 간편결제 확장 이점
- 위젯 전환 시 카카오페이, 네이버페이, 삼성페이 등 **노코드 추가** 가능
- 현재 `'카드'` 하드코딩 → 위젯이 자동으로 간편결제 포함
- 결제 전환율 향상 기대
