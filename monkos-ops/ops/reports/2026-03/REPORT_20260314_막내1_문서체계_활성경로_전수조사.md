### 괴리 분석

| 항목 | 상세 |
|------|------|
| **"변경 없음" vs 10건 Add** | "변경 없음"은 **기존 파일의 수정 금지**를 의미하는 것인지, **신규 추가도 금지**를 의미하는 것인지 해석이 모호 |
| **`reports/` 서브폴더 미등록** | ch4 1조 트리에 `reports/`가 없음. 9건이 이곳에 추가되었으나 트리 갱신 없음 |
| **`architecture/`에 V4 SPEC 추가** | architecture/는 ch4 트리에 "시스템 아키텍처, API 설계"로 등록 — 배치 자체는 적법 |
| **docs/monkos/와의 차별점** | docs/monkos/는 "신규 생성 금지"가 **명시적**. docs/infrastructure/는 "변경 없음"이라는 **성격 기술**만 존재 |

### 권고안

**선택지 A: "원천 아카이브 + 신규 리서치 허용"으로 성격 재정의**
- ch4 1조의 "변경 없음"을 "기존 파일 수정 금지, 신규 추가는 허용"으로 명확화
- `reports/` 서브폴더를 트리에 추가
- 근거: 인프라 기술문서는 축적형 성격 — 보물창고에 보물이 계속 쌓이는 것은 자연스러움

**선택지 B: 신규 파일을 monkos-ops/tech/로 이관, 동결 유지**
- 3월 추가된 10건을 `monkos-ops/tech/specs/` 또는 `monkos-ops/ops/reports/`로 이관
- docs/infrastructure/는 "변경 없음" 원칙 엄수
- 근거: 법률 문언 준수 우선

**판단 근거 제시**: 선택지 A 권고. 이유:
1. 실질적으로 docs/infrastructure/는 **참조 문헌 저장소**로 기능하고 있음 (CLAUDE.md, MEMORY.md, ch2, ch4 에서 모두 참조)
2. `monkos-ops/tech/`에도 유사한 카탈로그 파일들이 docs/infrastructure/를 가리키고 있어, 인덱싱 체계가 이미 연결됨
3. 동결을 엄수하면 기술문서를 넣을 새 경로를 또 만들어야 하는 비용 발생
