### 설계 원칙

현행 헌법의 문제: **원칙(Why)과 실무(How)가 혼재**

| 현행 예시 | 문제 |
|----------|------|
| 1조: "`date` 명령으로 KST 취득, 형식: `[YYYY-MM-DD HH:MM KST]`" | 도구명·형식이 헌법에 있음 |
| 2조: "`✅❌💡⏳📁🔀` 형식 보고" | 이모지 규격이 헌법에 있음 |
| 6조: "`.env`, `secrets/`, `deploy.sh` 수정 전 승인" | 파일명이 헌법에 있음 |
| 8조: "`rm -rf`, `git push --force`..." | 명령어 나열이 헌법에 있음 |

**C안**: 헌법은 한 문장의 원칙만 선언. 형식·절차·목록은 전부 법률로 위임.

### C안 헌법 조문 초안

```markdown
## 헌법 — 제1조~제8조

> 불변 원칙. 원칙만 선언하고 실무 상세는 법률에 위임한다.
> 개정: 삼권심사 + 전원 만장일치 (governance/constitution/amendment.md)

### 제1조: 추적성
모든 행위는 정확한 시각과 함께 기록·보고되어야 한다.
시각은 시스템에서 취득하며, 추정·기억 기반을 금지한다.

### 제2조: 정체성·기밀
외부 브랜드는 MONK.KR / MONKOS.AI로 통일한다.
내부 운영 정보(에이전트 호칭, 프로토콜, 기술 스택 상세)의 외부 유출을 금지한다.

### 제3조: 역할 분리
작가님이 총괄하고, 각 에이전트는 법률이 정한 역할 범위를 준수한다.
역할 간 월권을 금지한다.

### 제4조: 인프라·안전
인프라 자산(API 키, 비밀번호, 배포 환경)을 보호한다.
비가역적·파괴적 행위를 금지한다. 모르면 추측하지 말고 질문한다.

### 제5조: 정직·투명
에러를 묵과하지 않고, 수정·대안을 즉시 제시한다.
맥락 없는 아부를 금지한다.

### 제6조: 서비스 핵심가치
I2I에서 원본 인물의 정체성을 보존한다.
근원 해결 없이 우회(프록시)하지 않는다.

### 제7조: 윤리·법규
불법·비윤리 자동화를 금지한다.
미출시·미확정 사항을 외부에 단정적으로 표현하지 않는다.

### 제8조: 거버넌스
모든 구성원은 법률·헌법의 개정을 청구할 수 있다.
공식 문서는 법률이 정한 규격을 준수한다.
```

**결과: 24줄** (현행 헌법 부분 ~80줄 → 24줄, 약 70% 감축)

## 4. "읽히는 법" 구조 제안

### 현행 구조의 문제

```
에이전트 세션 시작
  ↓
CLAUDE.md 자동 로딩 (194줄, 매 턴)
MEMORY.md 자동 로딩 (~200줄, 매 턴)
  ↓
법률 8장 (1,169줄) = 에이전트가 Read하지 않으면 인지 불가
  ↓
"법이 있어도 읽히지 않으면 없는 것" (어젠다 #12-3)
```

### Claude Code rules/ 메커니즘 (조사 결과)

| 기능 | 상세 |
|------|------|
| **위치** | `.claude/rules/*.md` (재귀 탐색, 서브디렉토리 지원) |
| **무조건 로딩** | `paths` frontmatter 없으면 매 세션 자동 로딩 (CLAUDE.md와 동급) |
| **조건부 로딩** | `paths: ["glob/pattern"]` 설정 시 해당 파일 Read 시에만 로딩 |
| **컨텍스트 비용** | 무조건 로딩 = CLAUDE.md와 동일 비용. 조건부 = 해당 시에만 비용 |
| **파일 수** | 제한 없음. 파일당 200줄 이하 권장 |
| **서브디렉토리** | 완전 지원. 재귀 탐색 |
| **심링크** | 지원 (순환 참조 감지) |

### C안 제안: 3층 로딩 아키텍처

```
┌─────────────────────────────────────────────┐

│  ├─ 법률 인덱스 + rules/ 안내 (10줄)           │
│  ├─ 디바이스 맵 (10줄)                        │
│  └─ 규정 참조 (8줄)                           │
├─────────────────────────────────────────────┤
│ Layer 2: rules/ 무조건 로딩 (~80줄)            │
│  ├─ core-workflow.md (수발신 + 보고 형식)      │
│  └─ agent-identity.md (에이전트 인식 프로토콜)  │
├─────────────────────────────────────────────┤
│ Layer 3: rules/ 조건부 로딩 (필요 시만)          │

└─────────────────────────────────────────────┘
```

### 로딩 비용 비교

| 상태 | 매 턴 로딩량 | 비고 |
|------|-------------|------|
| **현행** | CLAUDE.md 194줄 + MEMORY.md ~200줄 = **~394줄** (법률 0) | 법률 1,169줄은 미로딩 |
| **C안** | CLAUDE.md ~80줄 + MEMORY ~200줄 + rules 무조건 ~80줄 = **~360줄** + 조건부 rules | 법률의 핵심이 rules/로 자동 로딩 |

**핵심 개선**: 현행은 법률 0줄 로딩 → C안은 작업 맥락에 맞는 법률이 자동으로 로딩됨.
동일한 컨텍스트 비용으로 **법률 실효성**이 근본적으로 해결.

### rules/ 파일 구조 제안

```
.claude/rules/
├── core-workflow.md          ← 무조건 로딩 (수발신·보고 형식·헤더)
├── agent-identity.md         ← 무조건 로딩 (역할 인식·디바이스 매핑)
├── coding.md                 ← paths: ["**/*.{js,html,css}"]
├── deployment.md             ← paths: ["**/deploy.sh", "MONK_kr/**"]
├── git-workflow.md           ← paths 없음 (항상 필요) 또는 경량
├── session-logging.md        ← paths: ["monkos-ops/ops/sessions/**"]
├── document-rules.md         ← paths: ["monkos-ops/**", "governance/**"]
├── branding.md               ← paths: ["MONK_kr/**", "monkos_AI/**/*.html"]
└── data-security.md          ← paths: [".env", "scripts/**"]
```

### 법률 파일과 rules/ 파일의 관계

| 구분 | 법률 (governance/laws/) | rules/ (.claude/rules/) |
|------|----------------------|----------------------|
| **역할** | 정본 (입법·개정·심사 대상) | 실행본 (에이전트 로딩용 요약) |
| **상세도** | 근거·위반 시·개정 이력 포함 | 행동 지침만 (근거 생략) |
| **변경 권한** | 작가님 승인 필수 | 법률 갱신 시 연동 갱신 |
| **Git 추적** | governance/ 하위 | .claude/ 하위 |
| **비유** | 법전 (판사용) | 실무 매뉴얼 (현장 직원용) |

**핵심**: 법률을 없애는 것이 아니라, 법률의 "실행 가능한 요약"을 rules/에 배치하여 **자동 전달**하는 구조.

C안은 어젠다 #12-3 "읽히지 않는 법"의 **근본 해법**이다. rules/의 조건부 로딩이 "법이 쓰여진 대로 작동하는 구조"를 실현한다. 그러나 이행 비용이 크다. **권고**: A안 즉시 실행 + C안을 이행 로드맵으로 확정 (2-3세션에 걸쳐 단계 이행). B안은 C안의 중간 기착지로서 의미가 있으나, B안에서 멈추면 rules/ 도입 없이 "경량화만 한 셈"이 되어 #12-3의 근본 해법에 도달하지 못한다.
