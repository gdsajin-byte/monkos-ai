| Project CLAUDE.md | **헌법** | 매 세션 전체 로딩 | ✅ |
| `.claude/rules/` | **법률** (참조형) | 상시 또는 path 매칭 | ✅ |
| `.claude/skills/` | **명령** (실행형) | 키워드 트리거 시 온디맨드 | ✅ |
| Auto Memory (MEMORY.md) | **규정** | 첫 200줄 자동 | ✅ |

**Anthropic이 의도한 구조와 4계층이 1:1 매핑된다.** 3계층에서는 "법률"이 참조형과 실행형을 혼재했으나, 4계층에서는 Anthropic이 제공한 `rules/`(참조)와 `skills/`(실행)으로 자연스럽게 분리된다.

### 5축 구조에 충돌 없이 삽입 가능한가?

**가능하다.** 변경 지점은 제5조(메타) 1항 문서 위계 테이블 1건뿐:

```markdown
**1항 — 문서 위계**

| 계층 | 성격 | 물리 위치 | 변경 권한 | 위반 시 |
|------|------|----------|----------|---------|
| **헌법** (5조) | 왜 — 불변 원칙 | CLAUDE.md | 만장일치 | 조항 인용 → 영향 경고 → 승인 대기 |
| **법률** (8장) | 무엇 — 정의·목록 | .claude/rules/ + governance/laws/ | 쌍아+작가님 | 조항 인용 → [예외] 기록 |
| **명령** (Skills) | 어떻게 — 실행 절차 | .claude/skills/ | 쌍아+작가님 | 조항 인용 → [예외] 기록 |
| **규정** | 디바이스 상세 | MEMORY.md 등 | 에이전트 자율 | 변경 보고 → MEMORY 갱신 |
```

**5축 본문에 변경 필요한 부분**: 제5조 1항 테이블(3행→4行)のみ. 他 4축은 변경 없음.

### 실무적 이점

| # | 이점 | 설명 |
|---|------|------|
| 1 | **키워드 매칭 자동화** | "세션 시작해" → 절차 자동 로딩. 작가님이 절차를 기억할 필요 없음 |
| 2 | **토큰 효율** | 실행형 절차는 필요할 때만 로딩 (~100 토큰/Skill at rest) |
| 3 | **참조/실행 분리** | 에이전트가 "이것은 무엇인가(rules)"와 "어떻게 하는가(skills)"를 혼동하지 않음 |
| 4 | **유지보수 용이** | 절차 변경 시 Skill 파일만 수정. CLAUDE.md/MEMORY.md 무변경 |
| 5 | **Git 공유** | `.claude/skills/`는 Git → 전 디바이스 동일 절차 보장 |

### 위험/단점

| # | 위험 | 심각도 | 대응 |
|---|------|--------|------|
| 1 | **Skills 기능 안정성** | 중 | Skills는 Claude Code 공식 기능이나, 비교적 신규. 초기에는 법률 원문도 병행 유지 |
| 2 | **이중 유지보수** | 중 | Skill 내용 = 법률 원문의 재구성. 법률 개정 시 Skill도 동시 갱신 필요 → **Skill에 법률 참조 명시** (`> 원천: ch7 1조`)로 추적성 확보 |
| 3 | **트리거 미매칭** | 낮 | 작가님이 예상 외 표현 사용 시 Skill 미발동 → 수동 `/skill-name` 호출 가능 |
| 4 | **명령 계층의 변경 권한** | 낮 | 법률과 동일 (쌍아+작가님) 또는 별도 정의 필요 → 법률과 동일 권한 권장 |
