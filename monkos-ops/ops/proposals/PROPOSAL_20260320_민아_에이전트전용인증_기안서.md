# 에이전트 전용 인증 — 기안서

> **배경**: 민아(Claude Desktop, MCP 브라우저)가 monkos.ai 어드민 영역 접근 시 OAuth 로그인 벽에 막힘.
> 에이전트가 블로그 에디터 QA, 채널 점검, CMS 관리를 자율적으로 수행하려면 인증 우회가 필요.

---

## 1. 현재 인증 구조

```
[브라우저] → OAuth (Google/Kakao/LINE) → monkos_session 쿠키 발급
                                          ↓
[admin-auth.js] → parseCookies → verifyAuthToken → ADMIN_UIDS 화이트리스트 체크
```

- `ADMIN_UIDS`: 환경변수(Cloud Run)에 comma-separated UID 목록
- `AUTH_SECRET`: 토큰 서명 키
- 인증 토큰: HMAC 기반, `monkos_session` 쿠키에 저장

**문제**: OAuth는 브라우저 리다이렉트 + 사용자 인터랙션 필수 → 에이전트 자동화 불가

---

## 2. 제안: API Key 기반 에이전트 인증

### 2-1. 방식

```
[에이전트] → Authorization: Bearer AGENT_{KEY} 헤더
                ↓
[admin-auth.js] → 기존 쿠키 인증 실패 시 → Bearer 토큰 체크
                → AGENT_API_KEYS 환경변수에 포함 여부 확인
                → 에이전트 전용 payload 반환 (userId: 'agent_desktop', isAdmin: true)
```

### 2-2. 환경변수 추가

| 변수 | 값 | 설명 |
|------|-----|------|
| `AGENT_API_KEYS` | `key1,key2,...` | 에이전트별 API 키 (comma-separated) |

- 키 생성: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
- Cloud Run 환경변수에 등록, `.env`에는 placeholder만

### 2-3. admin-auth.js 수정 (최소 변경)

```javascript
// 기존 쿠키 인증 실패 시 폴백
const authHeader = req.headers['authorization'];
if (authHeader && authHeader.startsWith('Bearer AGENT_')) {
  const key = authHeader.slice(7);
  const AGENT_KEYS = (process.env.AGENT_API_KEYS || '').split(',').filter(Boolean);
  if (AGENT_KEYS.includes(key)) {
    return { userId: 'agent_desktop', isAdmin: true, isAgent: true };
  }
}
```

### 2-4. 에이전트 측 사용

- `.env`에 `MONKOS_AGENT_KEY=AGENT_xxxxx` 저장
- MCP 브라우저 접근 시: 쿠키 대신 fetch 헤더로 인증
- 또는 서버에서 에이전트 키로 세션 쿠키를 발급하는 `/auth/agent` 엔드포인트 신설

---

## 3. 보안 고려사항

| 항목 | 대응 |
|------|------|
| 키 유출 | Cloud Run 환경변수 only. 코드/깃에 하드코딩 절대 금지 (헌법 4조 1항) |
| 권한 범위 | `isAgent: true` 플래그로 에이전트 행위 구분. 감사 로그에 `[AGENT]` 태그 |
| 키 로테이션 | 분기 1회 갱신 권장. Cloud Run 환경변수 업데이트로 즉시 적용 |
| 남용 방지 | Rate limit (분당 60회) 추가 권장 |
| 다중 에이전트 | 키를 에이전트별로 분리 발급 (desktop_key, cowork_key 등) |

---

## 4. 활용 범위

에이전트 인증이 열리면:

- ✅ 블로그 에디터 풀 QA (글 로딩/편집/저장/발행 테스트)
- ✅ CMS 콘텐츠 점검 (FAQ, 갤러리, 게시판 CRUD)
- ✅ 어드민 대시보드 모니터링
- ✅ SPREAD 자동 배포 트리거 (블로그 발행 → 채널 배포 자동화)
- ✅ 코웍이/데스크탑 에이전트의 QA 자율화

## 6. 대안 검토

| 방식 | 장점 | 단점 | 채택 |
|------|------|------|------|
| **API Key (Bearer)** | 구현 간단, 에이전트별 분리 용이 | 키 관리 필요 | ✅ 권장 |
| Service Account JWT | GCP 네이티브, 자동 로테이션 | 구현 복잡, 오버엔지니어링 | ❌ |
| 하드코딩 세션 쿠키 | 즉시 가능 | 보안 취약, 만료 관리 불가 | ❌ |
| OAuth 자동화 (Puppeteer) | 기존 인증 유지 | 불안정, MCP 브라우저와 충돌 | ❌ |
