## 2. 개편 9원칙 — 3축

### 축 A. 노이즈 억제

**A1. 녹색 침묵** — 정상 항목은 서술하지 않는다. `🔧 순찰: 이상 없음 (라이브 5/5, 시크릿 0, PR 0)` 한 줄로 끝낸다. 이상이 있을 때만 문장을 쓴다.

**A2. 지표는 갱신일에만 해석** — `data_date`가 전일과 같으면 `지표: 갱신 없음(data 08-09 유지)` 한 줄. 같은 데이터를 재해석하지 않는다.

**A3. TODO 3건 이하** — 초과분은 승계 목록에만 남긴다. 매일 5~7건을 제안하면서 실행률이 낮으면 목록이 아니라 소음이다.

### 축 B. 정확성 보존 (오늘 오경보 3건의 직접 대응)

**B1. 확실성 등급 의무** — 모든 승계·긴급 항목은 `[확정]` `[추정]` `[미확인]` 중 하나를 문장에 단다. **등급 없는 항목은 기재 금지.** 등급이 빠지면 다음 재서술에서 확정으로 승격된다(Lemon 실증).

**B2. 영향 범위 의무** — `유저 대면 / 내부 전용 / 매출 직결 / 영향 없음` 중 하나를 병기한다. 마감일만 남고 영향 범위가 탈락하면 내부 도구 이슈가 🔴가 된다(Imagen 실증).

**B3. 의도적 상태 배제 선행** — 인프라 이상은 **의도적 비가동 가능성을 배제한 뒤** 장애로 판정한다. 배제 못 하면 "비가동(의도 여부 미확인)"으로 쓴다. 4060은 가정 사정으로 꺼질 수 있다(08-13 확인).

**B4. 0건·404는 대조군 없이 결론 금지** — 조회 결과가 0건이거나 404일 때, **정상 동작하는 대상으로 같은 조회를 한 번 더 해** 쿼리·엔드포인트 오류를 배제한 뒤 보고한다. 08-13 쌍아가 두 번 걸릴 뻔했다(Vertex 404, 매팅 로그 0건).

### 축 C. 루프 폐쇄

**C1. 전날 TODO 실행 여부 선보고** — 새 TODO 제안 **앞에** 전날 3건의 실행/미실행을 먼저 적는다. 루프가 닫히지 않으면 제안은 계속 쌓이기만 한다.

**C2. 승계는 재서술 대신 정체 진단** — 형식을 고정한다.
```
② Lemon 결제키 [확정·매출직결] — 5일째 / TODO 1번 5회 연속 미실행
   막힌 지점: 콘솔 접근 필요(에이전트 대행 불가)
   다음 1수: 작가님 2분 — 키 목록 확인
```
같은 설명 문장을 다시 쓰지 않는다. **나이 · 막힌 지점 · 다음 1수** 3요소만.

**C3. 3일 연속 미실행 → 에스컬레이션 블록 분리** — 별도 섹션으로 빼고 **결정을 강제**한다: `재우선순위 / 막내 위임(쪼개기) / 보류 전환 / 폐기` 중 택1을 작가님께 묻는다. 4일째 같은 자리에 두지 않는다.

### 추가 1건 (08-13 탈퇴 건 파생)

**D1. 법정 기한 고객 요청은 🔴 승격** — 회원 탈퇴·개인정보 열람/삭제·환불 요청은 `📅 일정·메일`이 아니라 `🔴 긴급`으로 올린다. 벤더 점검 공지와 같은 층위에 두지 않는다.

## 5. 기대 효과 / 리스크

**효과**: 분량이 줄고 신호 밀도가 오른다. 확실성 등급이 남으면 오늘 같은 오경보가 재서술로 굳지 않는다. 정체 섹션이 결정을 강제해 5일 연속 미실행이 반복되지 않는다.

**리스크 1 — 녹색 침묵이 실제 장애를 가릴 수 있다.** 완화: 정상 요약 줄에 **점검 대상 수를 명시**(`라이브 5/5`)하여 미점검과 정상을 구분한다.

**리스크 2 — 등급 판정 자체가 틀릴 수 있다.** 완화: 확신 없으면 `[미확인]`이 기본값. 미확인은 긴급 승격 금지이므로 안전 측 실패다.

**리스크 3 — 브리핑을 고쳐도 일은 안 끝난다.** Lemon이 5일 미실행이었던 건 형식 문제가 아니다. **C3(정체 블록)이 이 부분을 다루지만, 실행은 여전히 작가님·막내 몫이다.** 개편을 실행 개선으로 오해하지 않아야 한다.
