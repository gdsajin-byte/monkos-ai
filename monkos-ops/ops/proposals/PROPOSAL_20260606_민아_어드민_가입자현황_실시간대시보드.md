- 현황 파악이 "보고서를 뒤져 흩어진 숫자를 모으는" 방식에 의존하고 있어, 시점·정합성이 매번 흔들린다.
- 모바일/웹 등 인증 없는 세션에서는 실시간 집계가 불가하다. **어드민에 상시 대시보드가 있으면, 어느 디바이스에서든 작가님이 즉시 현황을 본다.**

## 1. 핵심 발견 — "신규 구축"이 아니라 "확장"

전수 확인 결과, 백엔드 절반은 **이미 구현되어 있다.** 재활용 자산:

| 자산 | 위치 | 현재 상태 |
|------|------|----------|
| `/api/stats` 엔드포인트 | `monkos_AI/portal/server.js:83~95` | `usersCollection.count()`로 **총 가입자 실시간 반환** (단 totalUsers 숫자 1개) |
| 어드민 인프라 | `monkos_AI/portal/public/admin/` (css/js) | 공통 스타일·스크립트 존재 |
| 어드민 인증 게이트 | `monkos_AI/portal/lib/cms/admin-auth.js` | 적용 가능 |
| 채널(provider) 분해 로직 | `monkos_AI/portal/scripts/find_admin_uids.js` | Google/카카오/LINE 구분 보유 |

→ 따라서 작업 규모는 **막내 1회 수준의 확장**이다.

---

## 2. 목표

어드민에서 **로그인 게이트 뒤** 가입자 현황을 실시간 집계로 보여주는 대시보드 페이지. 새로고침 시점 기준 Firestore 실측값.

---

## 3. 범위 — 2단계 제안

### Phase 1 (MVP · 권장 우선 착수)
1. **`/api/stats` 확장**
   - `totalUsers` (기존 유지)
   - **채널별 분해**: Google / 카카오 / LINE / 이메일 / no-email
   - **기간별 신규**: 오늘 / 7일 / 30일 (created 타임스탬프 기준)
2. **대시보드 페이지** `public/admin/dashboard.html`
   - 상단 카드: 누적 가입자 · 오늘/주/월 신규
   - 채널 분해(도넛 또는 막대)
   - 마지막 집계 시각 표기 + 수동 새로고침
3. **admin-auth 게이트** 적용 (가입자 데이터 = 고객정보, 비인증 노출 차단)

### Phase 2 (확장)
4. **퍼널**: 가입 → 서비스 사용(생성 1회+) → 결제자 (전환율 자동 산출)
5. **크레딧/활성**: 크레딧 보유 분포, 최근 활성 사용자
6. **GA 지표 병기**: 방문자(트래픽)와 가입자를 한 화면에서 **구분**해 표기
7. (선택) 일자별 신규 추이 라인차트 — 가입 created 집계 누적

---

## 4. 데이터·보안 규칙 준수

- 가입자/고객 데이터 집계는 **서비스 코드(server.js) 내 Firestore 접근**으로 처리 → data-access 규칙 10조 6항 "서비스 코드는 대상 아님"에 부합. 수동 `node -e`/콘솔 직접 접근 아님.
- 크레딧 **변경**은 본 대시보드 범위 **밖**(조회 전용). 변경이 필요하면 `scripts/credits.sh` 경유 원칙 유지.
- 어드민 인증 필수 — 가입자 명부·이메일 등 PII 노출 차단.
- 외부 노출 문서/화면에서는 내부 기밀 보호 규칙(헌법 4조 3항) 준수.
