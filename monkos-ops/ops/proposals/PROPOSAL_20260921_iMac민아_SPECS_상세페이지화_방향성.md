# specs 상세페이지화 — 레퍼런스 기반 방향성

**[2026-09-21 11:42 KST]** iMac/민아 → 작가님 (수신 후 꾸·쌍아 전달용)

## 0. 한 줄 방향

**"정부 페이지처럼 보여주고, 상업 페이지처럼 시작하고, 우리만 아는 것을 그림으로 말한다."**
글은 지금처럼 전부 HTML 텍스트로 두고, 그림은 근거로 덧붙인다. 그림 안에는 글자를 넣지 않고 번호·✓✗만 넣어 6개 언어가 그림 한 벌을 공유한다.

## 1. 왜 지금인가 (실측)

- specs 본문에 콘텐츠 이미지가 없다. 한국 여권 페이지는 제목 8개·약 8,000자·표 1개·이미지 0장.
- 핵심 주장("귀 노출 폐지", "컬러렌즈·앞머리 반려")이 사진 한 장이면 끝날 내용인데 글로만 설명돼 있다.
- 구글 평균 순위는 7위권까지 올라왔는데 클릭률은 2%대에 멈춰 있다. 데스크톱 방문자는 5분대를 머무르며 읽는다 — 읽는 독자에게 시각 근거가 없다.
- 국내 1위 서비스(픽미)의 여권 규격 페이지도 **본문 이미지 0장**이다. "귀 안 보여도 됨"을 글로만 말한다. 한국 검색 결과에서 그림으로 보여주는 곳이 아직 없다.

## 2. 레퍼런스 — 가져올 곳 5곳과 가져올 것

| 순위 | 레퍼런스 | 가져올 것 | 버릴 것 |
|---|---|---|---|
| 1 | **미국 국무부 사진 예시** `travel.state.gov/en/passports/apply/help/photos.html` | 주제별 섹션마다 "규칙 불릿 + 예시 캐러셀"을 한자리에 붙이는 구조. 예시 50장, 큰 사진에 빨강/초록 테두리 + 허용/불가 배지 + **HTML 캡션 1~2문장** + ✓✗ 썸네일 띠. **허용 예시도 섞는다**(종교 가리개·휠체어·미색 배경). 실제 일반인 얼굴. 최종 수정일 표기 | 도구·시작 버튼이 없음 |
| 2 | **캐나다 IRCC** `canada.ca/.../canadian-passports/photos.html` | **"허용 | 불가" 2열 짝**, 같은 인물, `figure`+`figcaption`에 2~4단어 HTML 캡션. "왜 웃으면 안 되는가"처럼 규정에 이유를 붙임. "이 요건을 사진사에게 보여주세요" 프레이밍 | 예시가 페이지 맨 아래 — 도달률 낮음. alt 전부 빈칸 |
| 3 | **영국 GOV.UK** `gov.uk/photos-for-passports` | **"한 행 = 한 주제, 같은 모델, 변수 하나만 바꾼다"**(합격 1 + 불합격 2) 12컷이 폰 한 화면에 들어오는 요약 포스터 → 우리 페이지 상단 대표 이미지로 | 캡션을 이미지에 구워 넣음(번역 불가·모바일 판독 불가) |
| 4 | **Passport-photo.online / PhotoAiD** `passport-photo.online/us-passport-photo` · `photoaid.com/blog/passport-photo-examples/` | 요건 1항목 = 카드 1장 + 치수선 얹은 사진 + 공식 출처 링크. 샘플 사진으로 돌려보는 도구 실연. 검수자 박스. **번호 배지 + HTML 캡션**(그림 한 벌로 다국어 대응). 국가에 맞춘 샘플 얼굴 | 업로드 버튼 10개 이상 난사, 근거 없는 언론 로고 띠, 파일명 그대로인 alt, 나라 풍경 예찬 도입부, 패션 스톡 모델 얼굴, 20개월 묵은 수정일 |
| 5 | **Wise IBAN · papersizes.io** `wise.com/gb/iban/germany` · `papersizes.io/a/a4` | **답이 먼저**(수치를 제목 바로 아래 가장 크게), 도구가 첫 화면, 단위 표(mm / inch / px@300dpi), 예시 1건을 부품별로 분해한 도해, 섹션 맥락마다 **다른** 버튼, 하단 형제 링크 허브 | 이미지가 없어 썸네일 해법은 아님 |

보조: Snap2Pass의 제출처·수수료·처리 기간 카드 / 일본 외무성의 **±허용 오차까지 적은 치수 도해**(상업 사이트 어디에도 없음) / 호주 여권청의 alt 문형("불가 예시, 사유 …")과 폭넓은 주제(무선 이어버드 ✗·보청기 ✓·피부 보정 ✗) / 픽미의 공식 문구 인용 블록.

**반면교사 1건(중요)**: Snap2Pass 한국 여권 페이지는 "2017년부터 안경 전면 금지"라고 단정한다 — 사실이 아니다(외교부는 반사 없고 눈을 가리지 않으면 허용). 대량 페이지를 검수 없이 채우면 이렇게 된다. **공식 문서 정독·실반려 중심이라는 우리 기준이 곧 해자**라는 증거다.

## 3. 페이지 골격 (권장 섹션 순서)

| # | 섹션 | 내용 | 출처 레퍼런스 |
|---|---|---|---|
| 1 | 제목 + 한 줄 답 | "3.5×4.5cm · 흰 배경 · 6개월 이내" — 수치를 가장 크게 | papersizes |
| 2 | **도구 + 대표 도해** | 사진 올리기 상자 + 치수선 얹은 샘플 1장(페이지 첫 실제 이미지, ±오차 표기) | Wise · 일본 외무성 |
| 3 | 한눈에 보기 | 규격 표(항목 | 값 2열) + 단위 표 + 공식 출처 + **확인일** | Visafoto · papersizes |
| 4 | 신뢰 띠 | 검수자 · 최종 확인일 · 공식 문서 링크 | PPO |
| 5 | **주제별 규정 블록 × 8~9** | 블록 1개 = 규칙 불릿(HTML) + 합격/불합격 짝 + "왜" 한 줄. 순서: 크기·머리 위치 → 배경 → 조명·그림자 → 표정·자세 → 눈·안경·렌즈 → 머리카락·귀 → 복장·가리개 → 보정·AI → 영유아 | 국무부 구조 + 캐나다 짝 |
| 6 | **흔한 오해 교정** | 귀 노출·컬러렌즈 등 "낡은 통념 vs 현행 규정" — 정부에도 상업에도 없는 우리 자리 | (없음 — 선점) |
| 7 | 대표 반려 사유 상위 N | 작은 그림 포함 | 호주 |
| 8 | 도구 3~4단계 + 전/후 + **인화 배치 그림(4×6)** | 인화 시트 실물 그림은 조사한 어느 페이지에도 없었다 | (없음 — 선점) |
| 9 | 제출처 카드 | 제출처 · 수수료 · 처리 기간 · 온라인 가능 여부 | Snap2Pass |
| 10 | 자주 묻는 질문 | 기존 유지(구글 FAQ 리치 결과는 2026-05-07 종료 — 효과 기대 말 것) | — |
| 11 | 형제 링크 | 같은 나라 다른 서류 · 같은 규격 다른 나라 | Wise |

- 버튼은 같은 것을 반복하지 않는다: 5번 뒤 "내 사진 이 항목 검사", 8번 뒤 "인화용 받기".
- 모바일 고정 버튼은 얇은 하단 바, 누르면 **도구를 바로 여는** 방식(단순 위로 이동보다 근거가 강함).
- 보조 섹션(9·11)은 모바일에서 접되 HTML에는 전량 포함. 핵심 규격·반려 사유는 접지 않는다.

## 4. 그림 제작 원칙

1. **그림 안에 글자 금지** — 번호 배지와 ✓✗만. 사유는 전부 HTML 캡션. → 그림 한 벌이 6개 언어 약 2,570페이지에서 공용.
2. **한 행 = 한 주제 = 같은 인물 = 변수 하나.** 합격 1 + 불합격 1~2.
3. **허용 예시를 섞는다** — "귀를 덮어도 합격", "종교 가리개 허용", "보청기 허용". 금지만 나열하면 겁만 준다.
4. **선점 가능한 그림 2건**: ① "귀가 안 보여도 합격 / 눈썹을 가리면 불합격" 짝 ② 컬러렌즈 눈 확대 짝(자연 동공 / 서클렌즈 테두리). 조사한 전 세계 페이지 중 그림으로 보여준 곳이 없다.
5. 인물은 **가상 인물 생성**(실존 인물·고객 사진 금지), 국가 맥락에 맞는 얼굴 변형. 그리드 하단에 "예시 인물은 AI로 생성한 가상 인물입니다" 고지 + 이미지 메타데이터 표기. 패션 모델풍 금지 — 일반인처럼.
6. 정부 로고·여권 표지 엠블럼·"공식"·"합격 보장" 배지 금지. 공식 규정은 **인용 블록 + 출처 링크 + 확인일**로.
7. 모든 그림은 `figure`+`figcaption`, 서술형 alt("불가 예시 — 앞머리가 눈썹을 가림" 문형), width·height 명시, 첫 장만 즉시 로딩·나머지는 지연 로딩. 도해는 SVG, 인물은 AVIF/WebP/JPEG. 그림 파일은 페이지 간 공용 주소로 재사용(캐시 효율).

## 5. 검색 쪽 확인 사항 (조사 2 요지)

- 구글은 공유용 메타 이미지·구조화 데이터 이미지도 썸네일 후보로 쓴다(2026-03 문서 명시). 본문 첫 이미지·메타 이미지·구조화 데이터 이미지를 **같은 주소로 일치**시키는 것이 가장 확실. 일반 썸네일의 공식 최소 크기는 없다(1200px는 Discover 기준) — 그래도 대표 도해는 1200px 이상으로.
- `max-image-preview:large` 추가. 이미지 사이트맵은 `image:loc`만 유효.
- **이미지 도입 전에 서치 콘솔 기준선을 일반 검색/이미지 검색으로 나눠 저장.** 이미지 묶음 노출이 늘면 순위·클릭률 수치가 구조적으로 흔들린다("3.5 4.5 사진" 상위권·클릭 0이 이 현상일 가능성 — 우리 가이드 이미지는 이미 구글 이미지에 색인 중).
- 투자하지 말 것: FAQ·HowTo 리치 결과(종료), 서비스 페이지에 상품 마크업 일괄 적용(위험), 지어낸 평점.
- 네이버는 조사자가 공식 문서 원문을 열지 못했다 — 서치어드바이저 가이드의 이미지·구조화 데이터 항목은 **사람이 1회 확인** 필요.

## 6. ⚠️ 방향성보다 먼저 봐야 할 사업 리스크 (보고 의무)

레퍼런스를 해부하다 확인된 것 — 상세페이지에 "보정·AI" 블록을 그리려면 우리 제품의 입장부터 정해야 한다.

| 기관 | 공식 입장(원문 확인 여부) |
|---|---|
| **한국 외교부** (민아 원문 확인, 2022-10 개정) | "사진 편집 프로그램, 사진 필터 기능 등을 사용하여 임의로 보정된 사진(AI를 활용한 편집·가공·합성·창조 제작물 포함)은 허용 불가함" / "사진 편집 프로그램(예: 포토샵 등)을 사용하여 **배경을 지우거나 흰색 배경에 인물을 임의로 합성한 사진은 제출 불가**함" / "미용·컬러·서클렌즈 … 착용 불가함" |
| **미국 국무부** (조사자 확인, 수정일 2026-03-24) | 보정 도구로 배경을 잘라낸 사진, AI 도구로 바꾼 사진, 필터 사진을 **불가 예시 이미지로 게시**. 배경이 부적합하면 고치지 말고 새로 찍으라고 안내 |
| **호주 여권청** (조사자 확인) | 온라인 여권사진 서비스·모바일 앱 사용을 직접 비권장(신원 도용 위험) |

- 우리 무료 트랙은 **배경을 떼어 흰 배경에 맞추는** 방식이고, 유입 1위 페이지가 한국 여권이다. 08-27에 적발된 "kr 여권 AI 편집 불허" 건과 같은 계열이며 이번엔 배경 처리 문구까지 원문으로 확인됐다.
- 참고: 외교부 해당 페이지에는 **귀 노출에 관한 문구가 없다**. 우리 본문의 "귀 노출 의무 폐지" 서술은 다른 1차 출처에 근거한 것일 텐데, 상세페이지에서 그림으로 강조하려면 그 출처를 페이지에 링크로 명기해야 한다.
- 이 표는 판단이 아니라 사실 보고다. 나라별로 "규격·재단만 제공 / 배경 처리 제공 / 안내만"을 가르는 출고 정책은 작가님 결정 사항이다.

## 7. 단계 제안

| 단계 | 내용 | 주체 | 측정 |
|---|---|---|---|
| **0** | 서치 콘솔 기준선 저장(일반/이미지 분리) | 민아 | — |
| **1** (저비용·즉시) | 기존 가이드 이미지를 본문 상단 실제 이미지로 + `max-image-preview:large` + 이미지 사이트맵. es·id·vi는 en 이미지 폴백 | 민아 집행 가능(승인 시) | 2~4주 후 썸네일 표시·클릭률 |
