# 블록 에디터 통합 기안서

## 1. 배경

현재 두 개의 독립된 편집 체계가 동일한 핵심 니즈를 공유:
- **블로그 에디터**: 콘텐츠 제작 (이미지+텍스트 레이아웃)
- **홈 레이아웃 매니저**: 페이지 구성 (섹션 배치)

둘 다 결국 **"블록 단위로 콘텐츠를 배치하는 시스템"** — 통합 설계가 필요.

## 2. 현재 Toast UI 에디터의 한계

| 기능 | 지원 여부 |
|------|----------|
| 텍스트 서식 (볼드/이탤릭/리스트) | ✅ |
| 이미지 삽입 (드래그앤드롭) | ✅ |
| 이미지 옆 텍스트 배치 | ❌ |
| 2단/3단 컬럼 레이아웃 | ❌ |
| 비포/애프터 비교 블록 | ❌ |
| 갤러리 그리드 블록 | ❌ |
| 커스텀 블록 타입 정의 | ❌ |

→ Toast UI는 "글쓰기 도구"이지 "페이지 빌더"가 아님.

## 3. 진화 경로

### Phase A: 커스텀 HTML 블록 삽입 (단기, Toast UI 유지)

Toast UI WYSIWYG 위에서 미리 정의된 HTML 블록을 삽입하는 방식.

**템플릿 예시:**
```
[좌우 분할]  →  <div class="block-split"><div class="col-img">이미지</div><div class="col-text">텍스트</div></div>
[갤러리 2열] →  <div class="block-gallery-2">이미지×2</div>
[비포/애프터] →  <div class="block-ba"><div class="before">전</div><div class="after">후</div></div>
[풀 와이드]  →  <div class="block-full">전폭 이미지 + 오버레이</div>
```

- 우측 사이드바 "템플릿" 섹션에서 원클릭 삽입
- 블로그 CSS에서 렌더링 처리
- **난이도: 중** / 막내 1명 / 기존 에디터 유지

### Phase B: Editor.js 전환 (중기, 블록 에디터 도입)

Toast UI → [Editor.js](https://editorjs.io/) 또는 유사 블록 에디터로 교체.

**Editor.js 장점:**
- 블록 단위 편집 (Notion 스타일)
- 커스텀 블록 플러그인 지원
- JSON 출력 (마크다운 대비 구조화된 데이터)
- 이미지/비디오/임베드 네이티브 지원

**고려사항:**
- Firestore 저장 형식 변경 (markdown → JSON blocks)
- 기존 마크다운 콘텐츠 마이그레이션 필요
- 렌더링 로직 재작성 (render.js)

### Phase C: 홈 페이지 블록 에디터 통합 (장기, v4 Phase 6~7)

블로그 블록 에디터 + 홈 레이아웃 매니저를 **단일 블록 시스템**으로 통합.

```
blocks[] 스키마 (Firestore)
├── 블로그 블록 타입: text, image, split, gallery, ba-compare, embed
├── 페이지 블록 타입: hero, service-card, how-to, credit, faq-strip
└── 공통: id, type, data{}, style{}, order
```

- 어드민에서 블로그/홈 모두 동일한 블록 에디터로 편집
- Portal v4 Evolution Spec Phase 6~7과 합류

## 4. 권고 로드맵

| 단계 | 내용 | 시기 | 의존성 |
|------|------|------|--------|
| **지금** | 3컬럼 에디터 + 이미지 저장소 | 즉시 (지시서 발행됨) | 없음 |
| **Phase A** | HTML 블록 템플릿 삽입 (3~4종) | 1~2주 내 | 블로그 CSS 정의 |
| **Phase B** | Editor.js 전환 PoC | v4 Phase 5 이후 | site-wrapper 완료 |
| **Phase C** | 홈+블로그 통합 블록 시스템 | v4 Phase 6~7 | Phase B 검증 후 |

## 5. 벤치마크 대상

- Apple Pages / Keynote: 마스터 레이아웃 + 미디어 배치
- Notion: 블록 단위 편집 + 드래그 재배치
- Squarespace: 섹션 템플릿 + 커스텀 레이아웃
- Editor.js: 오픈소스 블록 에디터 (플러그인 생태계)

## 6. 결정 필요 사항

1. **Phase A 착수 시점** — 현재 에디터 안정화 후 바로 갈 것인지
2. **블록 타입 우선순위** — 사진 비즈니스 기준 어떤 레이아웃이 가장 시급한지
3. **Editor.js PoC 시점** — Phase 5(site-wrapper) 전에 선행할 것인지
