# 콘텐츠 자동 배포 파이프라인 기안서

## 1. 핵심 원칙

> **작가님은 한글로 한 번만 쓴다. 나머지는 전부 자동.**

## 2. 현재 vs 목표

### AS-IS (수동)
```
작가님 → monkos.ai 어드민 발행
      → 수동으로 note.com 복붙
      → 수동으로 티스토리 복붙
      → 수동으로 Medium 복붙
      → 수동으로 GitHub 복붙
      → 각 채널 SNS 공유 수동
```

### TO-BE (자동)
```
[작가님 한글 발행] monkos.ai 어드민에서 Publish 클릭
     │
     │ ── 자동 번역 (이미 동작 중) ──
     ├─→ Gemini API → EN 번역 저장 (Firestore)
     ├─→ Gemini API → JA 번역 저장 (Firestore)
     │
     │ ── 자동 배포 (신규 구축) ──
     ├─→ KO → 티스토리 (공식 API)
     ├─→ EN → GitHub Issue (공식 API)
     ├─→ EN → Medium (공식 API)
     ├─→ JA → note.com (비공식 API or 반자동)
     │
     │ ── SNS 자동 공유 (2차) ──
     ├─→ X/Twitter 자동 포스팅
     └─→ note.com 자체 X 배포 (note.com 기능)
```

## 3. 채널별 API 현황

| 채널 | API | 자동화 | 난이도 | 비고 |
|------|-----|--------|-------|------|
| **monkos.ai** | 자체 CMS | ✅ 이미 동작 | - | 원본 저장소 |
| **GitHub Issue** | 공식 REST API | ✅ 완전 자동 | 낮음 | PAT 토큰 1개 |
| **Medium** | 공식 API v1 | ✅ 완전 자동 | 낮음 | Integration Token |
| **티스토리** | 공식 Open API | ✅ 완전 자동 | 중 | OAuth2 인증 |
| **note.com** | 비공식 (API 미제공) | ⚠️ 반자동 | 높음 | Puppeteer or 수동 |
| **X/Twitter** | 공식 API v2 | ✅ 완전 자동 | 중 | OAuth 1.0a |

## 4. 구현 설계

### 4-1. translate.js 확장 (Phase 1)

번역 완료 후 자동 배포 트리거:

```javascript
// translate.js — translateAndSaveBlogPost 내부
// 번역 저장 완료 후

if (lang === 'en') {
  // GitHub Issue 자동 게시
  await publishToGitHub(translated, originalDoc);
  // Medium 자동 게시
  await publishToMedium(translated, originalDoc);
}

if (lang === 'ko' || srcLang === 'ko') {
  // 티스토리 자동 게시
  await publishToTistory(originalDoc);
}
```

### 4-2. 채널별 퍼블리셔 (신규 파일들)

```
monkos_AI/portal/lib/cms/publishers/
├── github.js      — GitHub Issue 게시
├── medium.js      — Medium 게시
├── tistory.js     — 티스토리 게시
└── note.js        — note.com (반자동/큐)
```

### 4-3. GitHub Issue 퍼블리셔 (즉시 구현 가능)

```javascript
// publishers/github.js
const GITHUB_TOKEN = process.env.GITHUB_TOKEN;
const REPO = 'gdsajin-byte/monkos-ai';

export async function publishToGitHub(translated, original) {
  const response = await fetch(`https://api.github.com/repos/${REPO}/issues`, {
    method: 'POST',
    headers: {
      'Authorization': `token ${GITHUB_TOKEN}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      title: translated.title,
      body: `${translated.content}\n\n---\n*Originally published on [monkos.ai](https://monkos.ai/blog/${original.slug})*`,
      labels: [original.category || 'blog', 'auto-published'],
    }),
  });

  if (!response.ok) throw new Error(`GitHub API: ${response.status}`);
  return response.json();
}
```

### 4-4. Medium 퍼블리셔

```javascript
// publishers/medium.js
const MEDIUM_TOKEN = process.env.MEDIUM_TOKEN;

export async function publishToMedium(translated, original) {
  // 1. 사용자 ID 조회
  const me = await fetch('https://api.medium.com/v1/me', {
    headers: { 'Authorization': `Bearer ${MEDIUM_TOKEN}` }
  }).then(r => r.json());

  // 2. 게시
  const response = await fetch(`https://api.medium.com/v1/users/${me.data.id}/posts`, {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${MEDIUM_TOKEN}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      title: translated.title,
      contentFormat: 'markdown',
      content: translated.content,
      tags: original.tags || [],
      publishStatus: 'public',
      canonicalUrl: `https://monkos.ai/blog/${original.slug}`,
    }),
  });

  if (!response.ok) throw new Error(`Medium API: ${response.status}`);
  return response.json();
}
```

### 4-5. 티스토리 퍼블리셔

```javascript
// publishers/tistory.js
const TISTORY_TOKEN = process.env.TISTORY_ACCESS_TOKEN;
const BLOG_NAME = process.env.TISTORY_BLOG_NAME;

export async function publishToTistory(original) {
  const response = await fetch('https://www.tistory.com/apis/post/write', {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: new URLSearchParams({
      access_token: TISTORY_TOKEN,
      output: 'json',
      blogName: BLOG_NAME,
      title: original.title,
      content: original.content,  // 마크다운→HTML 변환 필요
      visibility: '3',  // 공개
      category: '0',
      tag: (original.tags || []).join(','),
    }),
  });

  if (!response.ok) throw new Error(`Tistory API: ${response.status}`);
  return response.json();
}
```

## 5. 필요 토큰/키

| 서비스 | 환경변수 | 발급 방법 |
|--------|---------|----------|
| GitHub | `GITHUB_TOKEN` | Settings → Developer settings → PAT (repo, issues 권한) |
| Medium | `MEDIUM_TOKEN` | Settings → Integration tokens |
| 티스토리 | `TISTORY_ACCESS_TOKEN` + `TISTORY_BLOG_NAME` | 오픈 API 앱 등록 → OAuth2 |
| X/Twitter | `TWITTER_API_KEY` 등 | Developer Portal → OAuth 1.0a |

**헌법 4조 1항**: API 키는 `.env`에만 저장. 코드에 하드코딩 절대 금지.

## 6. 실행 로드맵

| Phase | 내용 | 시기 | 의존성 |
|-------|------|------|--------|
| **1** | GitHub Issue 자동 게시 | 즉시 | PAT 발급만 필요 |
| **2** | Medium 자동 게시 | 1주 내 | Integration Token 발급 |
| **3** | 티스토리 자동 게시 | 1주 내 | OAuth2 앱 등록 |
| **4** | note.com 반자동 (큐 시스템) | 2주 | 비공식 API 조사 필요 |
| **5** | X/Twitter 자동 공유 | 2주 | Developer Portal 승인 |

## 7. 중복 게시 방지

- Firestore `blog_posts` 문서에 `publishedChannels` 필드 추가:
  ```json
  {
    "publishedChannels": {
      "github": { "issueNumber": 3, "publishedAt": "..." },
      "medium": { "postId": "abc123", "publishedAt": "..." },
      "tistory": { "postId": "456", "publishedAt": "..." }
    }
  }
  ```
- 이미 게시된 채널은 스킵 (수정 시 업데이트 여부는 별도 판단)

## 8. 결정 필요 사항

1. **Phase 1(GitHub) 즉시 착수 여부** — PAT 발급 후 바로 가능
2. **Medium/티스토리 계정** — 이미 있는지, 새로 만들 건지
3. **canonicalUrl 전략** — monkos.ai를 원본으로 설정 (SEO 중복 방지)
4. **note.com 우선순위** — 비공식 API라 리스크 있음, 수동 유지할 건지
