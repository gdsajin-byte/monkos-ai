# MONKOS ID Photo — iOS 네이티브 앱 전환 제안서

**[2026-05-09 15:58 KST] iMac/민아 → 작가님**

---

## 1. 배경

현재 MONKOS 증명사진 서비스(idphoto-kr.monkos.ai)는 웹 기반 Cloud Run 서비스로 운영 중이다. AI 생성 백엔드가 안정화된 상태에서, iOS 네이티브 앱으로 전환하면 Apple App Store 채널을 확보할 수 있다.

핵심 전제: **AI 처리는 서버 유지, 앱은 클라이언트 껍데기** — 결제·인증 로직이 Apple 시스템으로 위임되어 자체 구현이 대폭 줄어든다.

---

## 2. 앱 용량 추정

| 구성 요소 | 용량 | 비고 |
|-----------|------|------|
| SwiftUI 프레임 | 3-5MB | |
| 카메라/갤러리 | ~0 | AVFoundation, PhotosUI (시스템 내장) |
| StoreKit 2 결제 | ~0 | 시스템 프레임워크 |
| 규격 크롭 | 1-3MB | Vision 얼굴 인식 (시스템 내장) + Core Graphics |
| UI 에셋 | 2-5MB | 아이콘, 가이드 이미지 |
| **합계** | **~10-20MB** | App Store 표기 기준 |

- 배경 제거 ML 모델 불필요 (AI 생성 결과가 이미 배경 정리됨)
- 온디바이스 ML 모델 포함 시 100MB+ 이지만, 현 구조에서는 해당 없음

## 3. 기술 구조

### 3-1. 웹 → 앱 전환 대응표

| 웹 (현재) | iOS 앱 | 변화 |
|-----------|--------|------|
| Google OAuth 로그인 | Sign in with Apple | 자체 구현 → 시스템 위임 |
| 크레딧 충전 (charge.html) | StoreKit 2 IAP | 결제 로직 전부 Apple 위임 |
| 생성(10c) → 워터마크 프리뷰 → 다운로드(70c) | 1컷 = 1크레딧 소모 → 원본 즉시 반환 | 프리뷰 단계 삭제, 단가 $1/컷 |
| 카메라 (WebRTC) | 네이티브 AVFoundation | 가이드 오버레이 |
| 크롭 (crop.js, FaceMesh) | Vision + Core Graphics | 규격 데이터 동일 |
| Gemini Live 코칭 (WebSocket) | Phase 1 제외 | 차별화 기능이나 복잡도 높음 |

### 3-2. 화면 구성 (SwiftUI, 6화면)

```
1. 홈 — 잔여 크레딧 표시 + 촬영 시작 CTA
2. 옵션 선택 — 규격(여권/반명함), 성별, 나이, 의상, 배경색
3. 카메라 — 네이티브 카메라 + 가이드 오버레이
4. 생성 중 — 로딩 애니메이션
5. 결과 + 크롭 — AI 생성 결과 확인 → 규격 크롭 → 사진 앱 저장
6. 크레딧 구매 — StoreKit 2 시트
```

### 3-3. 서버 변경 사항

기존 `/api/idgen` 유지. 추가/변경:
- 앱 전용 인증 헤더 (Apple ID 토큰 검증)
- 앱 요청 시 워터마크 없이 원본 직접 반환
- **신규 엔드포인트**: `POST /api/iap/verify` — StoreKit 영수증 검증 + 크레딧 적립

## 4. 크레딧 장부 로직

StoreKit 2 소모성 IAP(Consumable)는 Apple이 잔량을 관리하지 않는다. 장부는 서버 책임.

### 구매 흐름
```
사용자 → 앱 내 "크레딧 구매" 탭
      → StoreKit 2 결제 (Apple 처리)
      → 결제 완료 → JWS 영수증 수신
      → 앱 → 서버 POST /api/iap/verify (영수증 전송)
      → 서버 → Apple App Store Server API v2 검증
      → 검증 OK → Firestore 크레딧 +N 적립
      → 앱 → Transaction.finish()
```

### 사용 흐름
```
사용자 → "촬영 → 생성" 요청
      → 서버: Firestore 잔량 확인
      → 충분 → 차감 → AI 생성 → 원본 반환
      → 부족 → 402 응답 → 앱이 구매 시트 표시
      → 생성 실패 시 → 서버 자동 환불 (현재 웹 로직 재활용)
```

### 장부 방식: 앱 전용 Firestore 컬렉션 (B안 권장)

- 웹과 별도 크레딧 풀 → Apple ID를 키로 사용
- 기존 포털 인증 체계를 건드리지 않음
- 웹/앱 통합이 필요해지면 이후 매핑 추가 가능

### 수익 구조

## 5. 출시 전략: 크롭 무료 선행 → AI 앱 단계적 출시

### Phase 1: 크롭 무료 앱 선행 출시

| 항목 | 내용 |
|------|------|
| 앱명 | MONKOS 증명사진 크롭 (가칭) |
| 가격 | 무료 |
| 기능 | 여권/반명함 규격 자동 크롭, Vision 얼굴 인식 |
| 용량 | ~10MB |
| 목적 | App Store 심사 경험 축적 + ASO "증명사진" 키워드 선점 + 유저 풀 확보 |
| 서버 의존 | 없음 (완전 오프라인) |

전략적 이점:
- 무료 → 다운로드 허들 제로 → 오가닉 자산 축적
- 결제 없으니 심사 단순 (첫 심사 경험으로 적합)
- 크롭 사용자 = AI 앱 출시 시 크로스 프로모션 대상

### Phase 2: AI 생성 앱 (Phase 1 반응 보고 결정)

**선택지 A — 별도 앱 출시**
- 크롭 앱에서 AI 앱으로 딥링크 유도
- 각 앱 독립 관리

**선택지 B — 기존 크롭 앱에 IAP 추가**
- 무료 크롭 + 유료 AI 생성 (인앱 구매)
- 하나의 앱으로 완결
- 기존 유저 업그레이드 경로 자연스러움

→ Phase 1 유저 반응·리뷰·다운로드 수 기반으로 결정. 통합은 언제든 가능하지만 분리는 어려움.
