## 3. 재정리 항목 (쌍아 지시서 분해 단위)

### 단계 0 — 선결 감사 (301 전 필수, 막힘 방지)
- monk.kr 442 specs URL(계층 `/{country}/{doc}`) ↔ monkos.ai 평면 `/{slug}` **대응표 작성**.
- ⚠️ **대응 없는 URL을 301하면 404로 깨짐(중복보다 악화).** 누락분은 (a) monkos.ai 페이지 생성 선행 or (b) 해당 건 301 보류·개별 처리.
- 산출: 301 매핑 테이블 (monk.kr 경로 → monkos.ai 경로, 1:1).

### 단계 1 — specs 정본 통일
- monk.kr `/specs/*` → monkos.ai 대응 경로 **301**(매핑 테이블 기반). 구현 위치: monk.kr Cloudflare(`functions/specs/`) 또는 `_redirects`.
- monk.kr `robots.txt`의 `Sitemap: https://monk.kr/specs/sitemap.xml` 선언 **제거**, `monk.kr/specs/sitemap.xml`도 301 또는 제거.
- monkos.ai specs 페이지 **자기참조 canonical 명시**(curl 미검출 → 누락 의심, 확인 후 보강).

### 단계 2 — 사이트맵 인덱스 분할
- `/sitemap.xml`을 **sitemap index**로 전환 → 하위 `sitemap-static.xml` / `sitemap-specs.xml` / `sitemap-blog.xml`(필요 시 언어별). `render-sitemap.js` 리팩터.
- robots.txt는 인덱스 1개만 선언.

### 단계 3 — 실 lastmod 주입
- specs·static `lastmod = today` 제거 → **실제 갱신일**. SPECS_DATA에 갱신일 필드 부재 시 콘텐츠 기준일/배포일로 대체. 블로그(실 updatedAt)는 유지.

### 단계 4 — 크롤/전환 우선순위 (경량)
- 상업의도 페이지(증명사진 생성·가이드) priority 상향 + specs→생성 내부링크 점검(전환 다리 사전 정지).

## 4. 검증 (막내 완료 기준)
- 301 체인: monk.kr 샘플 10건 `curl -I` → 301 → monkos.ai 200 (404·체인루프 0).
- 사이트맵: 인덱스·하위맵 200 + GSC 재제출. 단일맵 1,584 → 분할 후 합계 동일.
- 색인: GSC URL검사로 정본 인지 확인. 색인 302 상승·미색인 219 감소를 1~2주 추적(PF_SPECS).
- lastmod: 동일 페이지 2일 연속 사이트맵에서 lastmod 불변(today 박제 해소) 확인.

## 5. 비범위 (경계 명시)
- 상업 키워드 콘텐츠 생산·CTA 전환 카피 — **별도 제안**(본 건은 색인 인프라).
- GA4 측정ID 분리 — **PF_IDPHOTO, 막내2 실행 중**. 본 제안은 "데이터·색인 신뢰성 복구" 묶음 참조만, 코드 중복 지시 금지.
- specs 장르·국가 재분류 — 범위 밖.
