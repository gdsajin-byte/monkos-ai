## 0. 문제 정의

생산공장(PF_OPUS Phase 1)의 본질은 **"콘텐츠를 매번 새로 쓰는 것"이 아니라 "키워드 코퍼스에서 retrieve해 SEO/GEO 규칙대로 조립"하는 RAG 시스템**이다. 현재 ~70% 가동(자판기·LLM·톤 정본·발행 게이트 완비), 빠진 30% = **살아있는 코퍼스 + retrieve/게이트 자동화**. 네이버 2-API가 이미 연동돼 마지막 조각이 채워졌다.

## 1. 비전 (한 줄)
**두 네이버 API가 자동으로 채우는 라이브 키워드 코퍼스에서 retrieve → SEO/GEO 규칙으로 조립 → 사람 게이트만 거쳐 발행.** 사람 손은 "발행 클릭"만.

## 2. 아키텍처

```
[① 수집·자동]  네이버 검색광고 API (검색량·경쟁도·연관키워드)
              네이버 검색 API (블로그 total 문서수 = 경쟁난이도·상위노출)
                    ↓ 주기 갱신
[② 코퍼스]    기계가독 키워드 DB
              (키워드·검색량·경쟁도·문서수·관문유형·CTA·대표노드·순위)
                    ↓ retrieve (주제/관문 → 키워드 클러스터)
[③ 게이트]    헤드텀 충돌 점검(경고형) — 자기잠식·채널 귀속 검증
                    ↓
[④ 생성]      네이버 SEO/GEO 템플릿 (톤 T1~T4 + 자수·이미지·키워드분포·JSON-LD)
                    ↓
[⑤ 발행]      자판기(멱등 드래프트) → 작가님 에디터 게이트 → 자동 번역·색인 체이닝
                    ↓
[⑥ 환류]      발행 2주 후 검색API/GSC 순위 → 코퍼스 갱신 (자기학습 루프)
```

## 3. 컴포넌트 상세

### ① 수집 레이어 (자동)
| API | 산출 | 용도 | 상태 |
|-----|------|------|------|
| 네이버 검색광고 (쌍아 연동) | 월 검색량·경쟁도·연관키워드 | 키워드 발굴 + 볼륨 | ✅ |
| 네이버 검색 (`portal/lib/cms/search.js`) | 블로그/뉴스 total·상위 결과 | 경쟁 난이도·차별화 각도 | ✅ |

- 갱신 주기: 코퍼스 키워드 전수 월 1회 + 신규 주제 발굴 시 on-demand. (GH Action 스케줄 or 루틴 6-1 편입)

### ② 코퍼스 스키마 (신설 — 기계가독 정본)
```yaml
keyword: "근처사진관"
volume_naver: 24310          # 검색광고 API
competition: "low|mid|high"  # 검색광고 API
doc_total: 0                 # 검색 API total (경쟁 문서수)
gateway_type: "①등록장벽"     # 관문 5유형
cta_landing: "/id-photo"
representative_node: "blog/near-studio-intercept"  # 자기잠식 기준
channel: "blog|specs|headshot"
gsc_rank: null               # 환류 갱신
status: "target|published|tracking"
```
> 현 산문 자산(HEADTERM_REGISTRY·GATEWAY맵·축C·캘린더)을 이 스키마로 1회 마이그레이션 → 이후 API 자동 적재.

### ③ Retrieve + 헤드텀 게이트 (경고형)
- 입력: 주제/관문 키워드 → 코퍼스에서 헤드+롱테일 클러스터 retrieve.
- 게이트(쌍아 6/20 = **경고형**): 동일 도메인·동일 키워드 대표노드 기존재 시 경고, blog에서 서비스 헤드텀(예 "AI 증명사진") 사용 시 차단. 현 "사람 최종 게이트" 철학상 하드차단 아닌 경고+사람 확인.
- 구현: `publish_blog_drafts.py`에 `headterm:` frontmatter 읽고 코퍼스 대조 (기술부 막내A 스코프).

### ④ 생성 템플릿 — 네이버 SEO/GEO
| 항목 | 규칙 |
|------|------|
| 톤 | T1 가이드(P1)·T2 후기 — CONTENT_STRATEGY 정본 준수 |
| 자수 | 1,500~2,500자 (C-Rank/D.I.A. 체류 로직) |
| 키워드 | 제목 전방배치 + 본문 자연 분포(스터핑 페널티 회피) + 연관키워드 코퍼스서 주입 |
| 이미지 | N장 배치(체류시간↑) — 썸네일 + 본문 1+ (AI 생성 노드, PF_PORTAL) |
| 구조 | 문제→표/체크리스트(필수)→방법→FAQ→**CTA 1회**(코퍼스 cta_landing) |
| GEO | AI 인용용 명료 정의·표·Q&A + JSON-LD (DESIGN_20260615 GEO 로드맵 정렬) |

### ⑤ 발행 게이트
- 자판기(`blog-draft-publish.yml`·`publish_blog_drafts.py`) 멱등 드래프트 → 작가님 에디터 발행 → JA/EN 자동 번역·색인 체이닝(기존).

### ⑥ 환류 (자기학습)
- 발행 2주 후 검색API/GSC 순위 → 코퍼스 `gsc_rank` 갱신 → 다음 retrieve 우선순위 보정. 성과 낮은 키워드 회피, 높은 클러스터 확장.
