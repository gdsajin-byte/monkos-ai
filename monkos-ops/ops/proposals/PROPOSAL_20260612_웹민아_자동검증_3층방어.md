## 0. 진단 — 왜 "더 많은 순찰"이 답이 아닌가

오늘 사고의 뼈아픈 사실: **데일리 루틴이 이미 매일 프로브를 돌렸으나 장애를 못 잡았다.** 프로브가 본 것 = HTTP 200(표면 생존). 실제 장애 = "로그인 고객이 생성 버튼 → 충전 페이지로 튕김"(핵심 여정). 홈페이지는 200을 주므로 표면 순찰로는 불가시.

또한 순찰은 **사후 감지** — 발견해도 이미 세션이 날아간 뒤다. 피해를 줄일 뿐 막지 못한다. 막는 것은 **배포 전 게이트**다.

> 결론: 강화 방향 = "더 자주 200 확인"(❌) 이 아니라 ① **예방 게이트 신설** ② **표면 200 → 핵심 여정으로 순찰 깊이 전환**.

## 1. 3층 방어 (우선순위순)

### Layer P0 — 배포 영향 게이트 (예방. 사고 재발 차단의 본체)

- **무엇**: 인증·시크릿·세션·결제를 건드리는 PR/지시서에 **"기존 세션/토큰 영향평가" 필수 항목** 부과.
- **트리거 파일 패턴**: `*auth*`, `*config*`(시크릿 폴백), `deploy.sh`(--set-secrets/env 변경), `*credits*`, `*session*`.
- **체크 질문 (지시서·PR 템플릿)**:
  1. 이 변경이 토큰 서명 키·검증 로직·쿠키 발급/삭제에 영향을 주는가?
  2. 주면, 기발급 토큰(현 세션)의 호환성은? 무효화되면 영향 사용자 규모(세션 TTL 기준)는?
  3. 무중단 전환 경로(다중 키 검증·grace period)를 검토했는가, 아니면 일괄 무효화를 수용하는가? 수용 시 고객 공지 계획은?
- **위치**: ch5(배포 규칙) 보강 + `order-write` 스킬에 1항 추가. **쌍아+작가님 합의 사항**(법률 개정).
- **자동화 보조**: governance-check.yml에 "위 패턴 파일 변경 PR인데 본문에 '세션 영향' 키워드 없으면 ⚠️ 경고" 1줄(차단 아닌 알림).

### Layer P1 — 합성 모니터 (핵심 여정 자동 주파. 작가님이 말한 "자동 검증 순찰"의 본형)

- **무엇**: 전용 테스트 계정으로 **로그인 → verify-cookie → 크레딧 조회 → 생성 직전 단계**까지 매일 자동 주파. 핵심 여정이 깨지면 즉시 🔴.
- **수행 주체**: 웹 루틴 **불가**(작가님 계정 금지 + GCP 인증 없음 — 06-12 실측 ENOENT). 따라서:
  - **GH Actions cron** (1순위) — 테스트 계정 자격은 GH Secrets(전용 저비밀 계정, 실고객 무관). idphoto-kr/jp/portal 핵심 여정 합성 체크.
  - 또는 **로컬 민아/막내 스케줄 + CDP** (2순위) — 실브라우저 재현.
- **검증 항목**: verify-cookie 200+user.id 존재, credits 응답 스키마, 생성 API precheck 통과. **결과만 기록**(생성 실행은 비용 발생 — precheck까지만).
- **선결**: 전용 테스트 계정 개설(작가님) + 핵심 여정 단계 정의(쌍아). 크레딧 변경 절대 불가(ch4 10조 — 조회만).

### Layer P2 — 웹 루틴 프로브 심화 (인증 없이 가능한 범위)

- 현 200 체크에 추가: ① `verify-cookie`가 **401 정상 반환**하는지(5xx면 인증 인프라 이상 신호) ② 응답 본문 스키마/에러코드 변화 ③ 핵심 API 엔드포인트(precheck 400 바디검증 정상 등) 패턴.
- 루틴 프롬프트 4번(외부 점검)에 1~2줄 추가 — **쌍아 v5 보정 사이클에 합류**(REVIEW #3 3줄요약·#4 무음가드와 동일 개정분).
