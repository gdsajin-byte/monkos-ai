# 제안서 — 크로스 환경 호환 체커 도구화 (브라우저·OS·인앱)

**[2026-07-25 08:10 KST]** iMac/민아 → 작가님·쌍아

> 발단: 작가님 지시 — "맥 개발·맥 테스트라 윈도우·안드로이드 환경이 절대적으로 부족하다. 무엇을 개발하고 배포하던 항상 병목이니 오늘 세션을 교훈으로 도구화할 필요가 있다. 테스트 이미지는 실제 에셋에서 가장 모범적인 것을 채택하고, 브라우저·인앱 등 다양한 체커 도구 설계가 필요하다."
> 근거 사건: `.bmp` 클라이언트 차단 결함이 **Windows 유입 최대층(164명)을 때리며 최소 14일간 무증상 방치** → 맥 전용 테스트로는 구조적으로 검출 불가였음.

---

## 1. 문제 정의 — 왜 지금 도구화인가

| 사실 | 실측 근거 |
|------|----------|
| 개발·테스트 환경이 macOS 단일 | iMac/M1/M2 전부 Mac. 작가님 테스트 = 사무실 iMac + 폰 |
| 실 유입 최대층은 Windows 데스크톱 | 오염 제외 164명/192세션 (iOS 106·Android 82·Mac 33) |
| macOS는 결함을 구조적으로 은폐 | macOS UTI가 MIME을 jpeg/png/heic로 정규화 → `.bmp` 문제 재현 불가 |
| 결함 검출까지 14일+ | GA4 이벤트로도 안 보임(거부는 `photo_upload` 발화 **전**이라 계측 공백) |
| 인앱 브라우저는 분석상 투명인간 | 코드는 감지(`specs-funnel.js:107`·`auth.js:7`)하나 **GA4 커스텀 디멘션 0개** → 인앱이 Chrome/Safari로 위장 계상 |

**핵심**: 이것은 버그 1건이 아니라 **검출 체계의 공백**이다. 같은 클래스의 결함이 앞으로도 배포마다 재발한다.

## 3. 설계 — 3층 게이트 + 픽스처 정본

### 3-1. 계층 구조 (비용 순, 위로 갈수록 느리고 정확)

```
L1  Playwright 매트릭스 (Mac 로컬, ~2분)      ← 매 배포 전 필수
    Chromium / Firefox / WebKit × 데스크톱·모바일 뷰포트
    + UA 스푸핑으로 인앱(카카오·네이버·인스타) 시뮬레이션
    ↓ 통과
L2  4060 Windows 실기 (SSH+CDP, ~5분)         ← 클라이언트 로직 변경 시 필수
    실제 Edge 150 / Chrome 150 — OS 고유 MIME·파일 다이얼로그
    ※ 오늘 .bmp를 잡은 유일한 층. L1 에뮬레이션은 이 클래스를 못 잡는다.
    ↓ 통과
L3  4060 Android 에뮬레이터 (adb, ~10분)      ← 모바일 동선 변경 시
    Chrome for Android + WebView(인앱 실체)
```

**설계 원칙**: L1은 빠르니 항상, L2·L3은 **변경 표면에 따라 조건부**. 전부 돌리면 아무도 안 쓴다.

### 3-2. 픽스처 정본 — "가장 모범적인 이미지" (작가님 지시 반영)

⚠️ **절대 금지: `gs://monk-customer-photos` 고객 사진 사용** — 개인정보. 테스트 픽스처로 부적격(헌법 4조).

**채택**: 이미 공개 브랜드 에셋인 AI 생성 모델 사진을 원본으로 고정.
- 1순위 `portal/public/images/headshot/style-professional.webp` — 정면·흰배경·상반신, 증명사진 규격에 가장 부합
- 2순위 `hero-result.jpg` (실 결과물 샘플) · `style-corporate.webp`
- 후보 보강: `gs://monk-ai-images/ads/*` 마케팅 승인 이미지(고객 데이터 아님)

**픽스처 생성 규칙** — 단일 원본에서 파생해 변수를 격리한다:

| 축 | 케이스 | 검증 목적 |
|---|---|---|
| 포맷 | jpg · png · webp · **bmp** · **tiff** · **jfif** · heic | MIME 게이트 (오늘의 결함 클래스) |
| MIME 이상 | `file.type` 빈 문자열 강제 · `application/octet-stream` | 레지스트리 손상 PC 재현 |
| EXIF | 회전 90/180/270 · EXIF 제거 | 업로드 후 회전 오류 |
| 용량 | 9.9MB(경계 통과) · 10.1MB(경계 거부) | 크기 게이트 경계 |
| 내용 | 정면 1인(정상) · 측면 · 다인 · 얼굴 없음 | 서버 precheck 반응 |

→ 산출: `tests/fixtures/` 에 커밋(용량 큰 것은 생성 스크립트로, 원본만 커밋).
→ **정본 원칙**: 픽스처는 "무엇을 통과/거부해야 하는가"의 기대값 표(`expected.json`)와 쌍으로 관리. 기대값 없는 픽스처는 회귀 테스트가 아니라 구경거리.

### 3-3. 체커 종류 (작가님 "다양한 체커")

| 체커 | 무엇을 잡나 | 오늘 사건 관련 |
|---|---|---|
| **업로드 호환** | 포맷·MIME·EXIF·용량 게이트 통과/거부 | ⭐ 직결 (.bmp) |
| **인앱 브라우저** | 카카오·네이버·인스타 WebView에서 업로드·**다운로드** 동작 | ⚠️ 인앱은 `a[download]` blob 저장을 차단하는 사례 다수 → `free_download` 이탈 잠재 원인 |
| 렌더·레이아웃 | 뷰포트별 잘림·가로스크롤 (07-24 모바일 잘림 재발 방지) | 기왕력 있음 |
| 콘솔·네트워크 | JS 에러·4xx/5xx·CSP 위반 | 무증상 장애 |
| 퍼널 계측 | 이벤트 실발화 검증(`spec_select`→`photo_upload`) | 계측 공백 재발 방지 |

### 3-4. 계측 공백 동시 보정 (도구만으론 부족)

도구는 배포 전을 지키지만, 프로덕션 실패는 여전히 안 보인다. **2건 병행 필수**:
1. **`upload_rejected` 이벤트 신설** — 거부 시 `{mime, ext, reason}` 전송. 현재 거부는 통계상 존재하지 않음.
2. **인앱 여부를 GA4 커스텀 디멘션으로** — 코드는 이미 판정(`specs-funnel.js:107`). 파라미터 1개 추가로 "인앱 사용자 전환율"이 분석 가능해짐. (현재 커스텀 디멘션 0개 실측)

## 4. 구현 범위 제안 (쌍아 지시서 분할 단위)

| 단계 | 산출물 | 담당 | 선행 |
|---|---|---|---|
| **P0** | `.bmp` 등 MIME 게이트 핫픽스 + `upload_rejected` 계측 | 막내 | 없음 (즉시) |
| **P1** | 픽스처 세트 + `expected.json` (`tests/fixtures/`) | 막내 | P0 |
| **P2** | L1 러너 `scripts/tools/compat_check.sh` (Playwright 매트릭스 + 인앱 UA) | 막내 | P1 |
| **P3** | L2 러너 (4060 Windows 실기, 오늘 `run_one.ps1` 승격·일반화) | 막내 | P2 |

| **P5** | L3 Android (AVD 생성 필요) · 배포 게이트 편입(deploy.sh 훅 or 체크리스트) | 막내 | P3 |

## 6. 리스크·한계 (정직 기재)

- **에뮬레이션의 한계**: L1 Playwright는 오늘의 `.bmp`를 **못 잡는다**(파일 다이얼로그·OS MIME은 실기 고유). L1만 도입하면 "테스트했는데 또 터지는" 최악 신뢰 붕괴 → **L2 없는 L1 단독 도입 반대**.
- **4060 의존**: L2·L3은 4060 가동·SSH 전제. 4060 오프라인 시 게이트 공백 → 상태를 명시 경고로 노출.
- ~~AVD 미확인~~ → **해소**: `Pixel_8` AVD·Android 37 이미지 실측 확인, L3 즉시 착수 가능. 단 에뮬레이터 기동은 4060 GPU·RAM을 점유하므로 **ComfyUI/VTON 작업과 시간대 충돌 주의**(4060은 GPU 서버 겸용).
- **iOS 실기 부재**: WebKit 엔진은 Playwright로 커버되나 iOS Safari 실기는 없음(작가님 폰이 유일). 우선순위 낮음(iOS 유입 106명이나 오늘 결함은 Win 특이).
- **유지비**: 브라우저 버전은 계속 오른다. 매트릭스를 넓히면 관리비가 붙는다 → **초기 범위는 Win Edge/Chrome + 인앱 3종으로 좁게** 시작 권고.

## 7. 결론

오늘 사건의 교훈은 "버그를 놓쳤다"가 아니라 **"macOS 단일 환경은 최대 유입층의 결함을 구조적으로 볼 수 없다"**다. 자산은 이미 8할 갖춰져 있고(Playwright·cdp_utils·4060 실기·Android SDK), 없는 것은 **픽스처 정본 + 매트릭스 러너 + 배포 게이트 배선** 3개다.

**요청**: ① P0 핫픽스 즉시 발행 ② P1~P3 도구화 지시서 설계(쌍아) ③ 픽스처 원본으로 `style-professional.webp` 채택 승인 ④ 고객 사진(`monk-customer-photos`) 픽스처 사용 금지 명문화.
