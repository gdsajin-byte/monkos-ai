## 0. 요약 (TL;DR)

**시장 판독**: 한국 무인 인화 키오스크(염료승화)는 다이소·편의점 침투 **형성 초기** — 일본이 편의점 멀티카피기로 이미 완성한 "동네 출력망"이 한국에서 지금 깔리는 중이다. 일본에서 그 망 위에 ピクチャン(누적 700만)·ラムネ 같은 **콘텐츠 레이어**가 얹혀 검증된 사업이 됐는데, **한국의 그 자리가 아직 비어 있다.** 스타트업 윈도우 전략(빈틈 선점) 그대로 — 하드웨어 망은 그들이 깔고, 우리는 AI 생성+규격+검수라는 상류 콘텐츠 레이어를 선점한다.

**우리 포지션**: MONKOS는 프린터 회사가 아니라 **"제출 가능한 사진 데이터"의 생산자**다. 출력은 4채널로 내보낸다:

| 채널 | 포지션 | 시점 |
|------|--------|------|
| ① 몽크스튜디오 P800 직접 인화·배송 | **프리미엄** (안료 8색 색·질감, T2 인간 검수 동봉, ₩2,900 우편 포함 = 배송형 총액 최저 수준) | 즉시 (스마트스토어 가동 초기 → 자체 몰 흡수) |
| ② 국내 키오스크 협업 (셀픽→폴라폴라→프린팅박스 순 접촉) | **즉시성** (전국 편의점·다이소 1,300대+178점, 원격 코드 인프라 기실재) | 협상 트랙 (형성기 = 적기) |
| ③ 일본 편의점 망 (netprint/networkprint) | 글로벌 무물류 (¥30~40 셀프 출력 → API 제휴) | G-1 (기술 즉시 가능) |
| ④ 해외 협업 (키타무라 라보네트워크 API/무재고 1순위, 동남아는 필리핀 우선) | 현지 실물 (일본 법인 없이 위탁 성립 가능성) | G-2+ |

**한 문장**: T1이 이미 뱉는 300dpi·mm 정밀 크롭 위에 **안착(imposition) 엔진 한 층**을 얹으면, 같은 파일이 P800 프리미엄 인화·키오스크 코드·일본 편의점 L판·해외 위탁 출력으로 전부 나간다. 안착 엔진이 4채널의 공용 심장이다.

### 2-3. 동남아 — 미성숙·저가 (선별 진입) [리서치 E 확정]

**베트남 실측**:
- 규격: 여권 **4×6cm**·면허 3×4cm(옅은 파랑 배경)·이력서 4×6cm. ⚠️ 주민증(CCCD)은 공안 현장 촬영으로 **사진 지참 불필요** — 주민증 수요는 시장에서 제외하고 여권·비자·이력서·면허에 집중.
- 가격 수준: 사진관 4장 25,000~40,000 VND(약 ₩1,300~2,100), 하노이 1시트 20,000 VND — **한국의 1/3~1/2 지불의향**. 온라인 인화 배송 업체 다수 존재하나 전국 단일 대형 플랫폼 미확인(지역 스튜디오 난립).
- 인프라: 편의점(Circle K·GS25·WinMart+) 사진 프린트 미확인 — 그 역할은 동네 photocopy shop. 모바일 결제는 성숙(MoMo 68%·3,100만 유저) — 단 LS 커버리지 밖(현지 지갑) = **결제 게이트**.
- **판정**: 물류·플랫폼 공백 = 선점 여지는 실재하나, 저지불의향+현지결제 장벽으로 **후순위(G-3)**. 진입 시 모델 = 데이터 판매 + photocopy shop 출력 가이드 (specs 베트남어 확장이 선행 수순 — CITADEL 결).
- **필리핀이 동남아 중 증명사진 문화 최강** (1×1·2×2인치 관공서 관행, Great Image 몰 직영 79점) + 영어권 = specs 영어 자산 즉시 적용 — 동남아 1순위 검토 대상으로 승격 제안. 인생네컷 베트남 34점·포토이즘 필리핀 진출 = K-포토 수용성 검증됨.

### 2-5. 포지셔닝 선언

> **MONKOS = "제출 가능한 사진"의 생산·보증 레이어.** 하드웨어 망(키오스크·편의점·랩)과 경쟁하지 않고 그 위에 얹힌다. 자체 P800은 "품질의 정점 + 검수의 물리적 실행처"로서 프리미엄 채널을 직영한다 — 전 채널이 안착 엔진 하나에서 나오므로, 채널이 늘수록 한계비용은 0에 수렴한다.

### 3-2. 채널 ② 키오스크 협업 — 제안 구조 (프린트박스류)

**서로의 결핍이 정확히 교차한다:**

| | 키오스크 사업자 | MONKOS |
|--|----------------|--------|
| 가진 것 | 전국 물리 출력망 (다이소·편의점 임대 지점) | AI 생성·규격 코드 정본·specs 유입(1,284페이지)·발급보장 |
| 없는 것 | 콘텐츠·트래픽·증명사진 규격 역량 (기기 가동률이 수익) | 즉시 출력망 ("오늘 당장 8매" 수요를 배송이 못 받음) |

**제안 패키지 (협상 카드 순)**:
1. **코드 연동형** (이상형, 일본 ピクチャン 구조): monkos.ai에서 생성·결제 → 출력 코드 발급 → 유저가 키오스크에서 코드 입력 → 출력. 수익: 콘텐츠 요금은 우리, 출력비는 그들 / 또는 합산징수 후 셰어. **선결 조건 해소 [리서치 D]: 원격 업로드→코드 인프라가 프린팅박스(인쇄코드)·폴라폴라(폴라코드) 양사에 이미 실재** — 신규 개발이 아니라 기존 코드 체계에 우리 콘텐츠를 싣는 계약 문제로 축소됐다.
2. **규격 엔진 공급형** (B2B SaaS): 그들 키오스크의 "증명사진 메뉴"에 우리 규격·안착 엔진을 화이트라벨 공급 (건당 라이선스). TOPPAN スマートコンフォト의 역방향 — 우리가 기술 공급자. 프린팅박스의 정부24 연동 이력 = 증명·서류 결이 이미 있는 조직이라 수용성 근거.
3. **상호 송객형** (최소형, 계약 문턱 최저): 우리 완료 화면에 "근처 키오스크에서 즉시 출력" 안내(안착 파일 제공) ↔ 그들 기기 대기화면에 monkos.ai QR. 정산 없는 트래픽 교환으로 시작해 데이터를 쌓고 1로 승격.

**접촉 우선순위 [리서치 D 기반]**:

| 순위 | 대상 | 근거 | 첫 카드 |
|------|------|------|--------|
| 1 | **셀픽** | "API 파트너십" 공식 프로그램 명시 (3사 중 유일) — 문턱 최저. **사진관·산후조리원 300+ 설치** = 사진관 상생 결 + 신생아 여권사진(우리 IDENTITY_BABY 프롬프트 자산) 수요처 직결 | 코드 연동형 API 문의 |
| 2 | **폴라폴라** | 폴라코드 원격 발급 기실증 + **자사 스토어에서 콘텐츠를 코드 상품으로 판매 중** — "증명사진 폴라코드" 입점은 그들 기존 상품 문법 그대로. 다이소 178점 = 생활동선 | 콘텐츠 입점(콜라보 계약) |
| 3 | **프린팅박스** | 최대망(1,300대·4대 편의점)·자본력(시리즈A) — 파급 최대지만 공개 API 미확인, IP 콜라보가 HYBE급 위주라 문턱 추정 상 | 상호 송객형 → 규격 엔진 공급 |

- **타이밍 논거**: 망 형성기의 사업자는 가동률·콘텐츠 파트너가 절실하다 (프린팅박스 매출 +168%는 망 확장 국면의 증거). 망이 완성되고 자체 증명사진 기능이 고도화된 뒤에는 우리 협상력이 급락한다. **PF_PARTNER(인크루트 B2B 선례) 트랙에 키오스크 협업을 정식 어젠다로 등재 제안.**

### 3-3. 채널 ③·④ 글로벌 (요지)

- **③ 일본 편의점**: 모델 A(셀프 등록, ラムネ 방식 기실증)는 제휴 없이 즉시. jp T1 데이터 가격은 ピクチャン ¥200 앵커 대비 "AI 생성 포함" 상위 가치로 책정 (가격 정책 게이트 §12). API 제휴(모델 B)는 진출 시점에 후지필름BI·샤프 양쪽 견적 문의 — 외국법인 배제 조문 없음, Google 포토 선례.

### 3-4. 채널 간 정합 (자기잠식 방지)

- ①직영(₩2,900 프리미엄·검수·배송)과 ②키오스크(즉시·저가)는 **시간축이 다른 수요** — "내일까지 받으면 되는 사람" vs "지금 당장 필요한 사람". 잠식이 아니라 커버리지 확장.
- 전 채널에서 **데이터 요금(생성·규격·검수)은 우리에게 귀속**된다는 원칙 고정 — 출력·물류만 채널별로 위임. 이 원칙이 무너지는 계약(데이터 요금까지 셰어)은 하지 않는다.

## 5. 자체 몰 설계 (monkos.ai/print)

### 5-1. 구조 원칙

- **별도 앱·별도 도메인 없음** — 포털 내 라우트 `/print` (idpass 허브 라우터 구조화 어젠다와 동일 결). 수천 그물코 전략 그대로: specs 1,284페이지가 유입구, `/print`는 전환 허브.
- 즉시 인터랙션 패턴 준수: 진입 → 업로드/생성물 선택 → **안착 미리보기 즉시** → 결제 → 업셀(추가 대지·무광·등기).

### 5-2. 진입점 3개

| 진입점 | 고객 | 플로우 |
|--------|------|--------|
| ① T1 완료 업셀 카드 | AI 생성 고객 | 결과 화면에서 원클릭 (§7-1) — 파일 이동 0 |
| ② `/print` 직접 진입 | **파일 지참 고객** (스마트스토어 상품1 수요) | 업로드 → 규격 자동 검수(기존 precheck 재활용) → 부적합 시 "비율 조절" 업셀(₩2,000, 현행 스마트스토어 옵션가 승계) 또는 T1 재생성 제안 |
| ③ specs 페이지 인화 CTA | 규격 검색 유입 | "이 규격으로 인화까지" — slug→세트 자동 매핑 |

- ②가 전략적으로 중요: **파일 지참 인화 고객이 AI 생성(T1)의 최근접 잠재군** — 검수 실패 시 "규격 문제를 AI로 해결" 상향 제안이 자연 동선. 인화가 T1의 업셀이기도 하지만, **T1이 인화의 업셀이기도 한 양방향 구조.**

### 5-3. 스마트스토어와의 관계

| | 스마트스토어 (유지) | 자체 몰 |
|--|--------------------|---------|
| 역할 | 네이버 검색 유입·신뢰 획득 | 마진·데이터·재구매 본진 |
| 가격 | 현행 유지 (₩1,900/9,900/11,800) | 총액 우위 (₩2,900~4,900) + 크레딧 적립 |
| 전환 장치 | 발송 봉투 삽입물 (QR+첫 크레딧 보너스) | 마이페이지·재인화 원클릭 (파일 보관 = 재구매 락인) |

- **재인화 락인**: 구매 파일 보관 기간 내 "같은 사진 8매 더" 원클릭 재주문 (₩1,500 대지가) — 증명사진은 소모품이다 (분실·추가 제출). 스마트스토어가 못 하는 자체 몰 고유 가치.

## 6. 기술 설계 A — 안착 엔진 (Imposition Engine, 4채널 공용 심장)

### 6-1. 위치와 원칙

- 모듈: `monkos_AI/portal/lib/print-imposition.js` (신규, sharp 기반 — spec-crop.js와 동일 스택, 신규 의존성 0)
- 원칙: **코드=판정 정본.** mm 산술 전부 300dpi 정수 px 라운딩 고정 — 수치 재현 가능한 배치.

### 6-2. 데이터 정본

```
portal/lib/print/print-papers.json   — 대지 { id, mm, dpi, surfaces, channel: ["p800","kiosk","jp-conbini"] }
portal/lib/print/print-layouts.json  — 세트 { setId, cell_mm, paper, count, grid, rotate,
                                        gutter_mm, bleed, cutmarks }
specs-data.json                      — 슬러그별 printSet 필드 1개 추가 (428슬러그 → 세트 수렴)
```

### 6-3. 처리 흐름

```
입력: T1 최종 크롭 PNG (300dpi, mm-exact, sRGB) 또는 /print 업로드 검수 통과본
  ↓ 검증: px == cell_mm×300dpi ±1px (불일치 시 안착 거부 — 상류 버그 하류 흡수 금지)
  ↓ 대지 캔버스 → 셀 N개 컴포지팅 (grid+gutter+센터링, rotate 시 90°)
  ↓ 재단선: 헤어라인(기본, 셀프 재단 배려) | 크롭마크 | 없음 — 세트 설정
     (시장 관행: 포토몬 기본 없음+옵션, 퍼블로그 가이드 이미지 [리서치 ③])
  ↓ 출력 3종:
     ① 인쇄 파일: JPEG q95, density 300, sRGB → GCS print-queue/ (채널별 규격)
     ② 미리보기: 장변 800px PNG — 업셀 카드·몰의 전환 장치 ("8매가 이렇게 온다")
     ③ (채널③) L판 파일 + 편의점 등록 가이드 링크
```

### 6-4. P800 운용 모드 (직영 채널 전용)

| 모드 | 방식 | 시점 |
|------|------|------|
| **낱장 모드 (Phase 1)** | 주문별 4R 시트 출력 (P800 최소 급지 3.5×5" — 4R 가능) | 일 ~수십 건 |
| **갱업 모드 (Phase 2)** | 여러 주문을 17×22"/A2 시트에 배치(4R 환산 12~24면) 일괄 출력 → 재단 | 물량 증가 시 |

- 갱업 = 안착 엔진의 **2단 안착** (고객 단위 4R 대지 → 프린터 단위 대판 시트). 같은 엔진의 배치 대상만 재귀 적용 — 별도 개발 최소.
- P800 속도 한계(분 단위/장, 승화형 수십 초 대비)는 프리미엄 채널이므로 허용 — 단 **일일 처리량 상한 실측**(§12-1) 후 초과분 대비책(드라이랩 증설 게이트)을 Phase 2 판단.

```

  ③ Firestore print_orders { orderId, uid/email, slug, setId, sheets, surface,
     shipping{...}, status:"paid", files{...}, amounts{...}, channel:"p800" }
  ④ 텔레그램 알림: "🖨 인화 #1234 | 여권 8매×1 광택 | 우편 | [인쇄파일] [미리보기]"
```

### 7-3. 매장 운영 (몽크사진관 — M2 거점)

### 7-4. 데이터·개인정보

## 11. 리스크·논점

1. **색 정합**: 모니터 sRGB vs P800 실물 — P1.5 실측 3회(광택/무광×표준 피부톤), 필요 시 출력 보정 LUT 1개 고정. 실물 대조로 판정 ("그럴듯한 색" 금지).
2. **P800 처리량**: 분 단위/장 — 프리미엄 채널이라 허용하되 일일 상한 실측 후 갱업·증설 게이트 설정. 자동기기와 속도 경쟁하지 않는다 (그건 채널 ②의 몫).
3. **무료 PDF 잠식 논점**: 디지털 구매자에게 가정 인쇄용 PDF 무료 제공 = 잠식이 아니라 서비스 (파일은 이미 고객 소유). 인화의 값은 "P800 질감+검수+배송"에 있음. — 작가님 판단 게이트.
4. **키오스크 협업 실패 시나리오**: 그들이 자체 증명 기능을 내재화하면 코드 연동 협상력 하락 → 상호 송객형(카드 3)으로라도 조기 접점 확보가 방어. 최악에도 직영+일본 채널은 독립 성립.
5. **통신판매업 표기**: 스마트스토어 운영 중 = 기신고 추정 — monkos.ai 결제 페이지 표기 정합만 확인.
6. **운영 부하**: 초기 일 수십 건까지 현행 인력 흡수 가능 전제 (작가님 체감 확인) — 초과 시 P2 대시보드 갱업 큐.

## 12. 작가님 확인 필요 (P0 게이트)

1. **P800 실측 3종**: ① 사용 용지 (브랜드·표면·평량·보유 재고) ② 4R 장당 실원가 (잉크+용지 체감치) ③ 일일 쾌적 처리량 (몇 대지까지 무리 없는지)
2. **가격 확정**: 애드온 ₩2,900 / 파일지참 ₩2,900 / 대지 추가 ₩1,500 / 등기 +₩2,000 / 택배 +₩3,500 (§4-3)
