## 1. 배경

MONKOS 4MUSE(쌍아·민아·소소·용아) 중 **민아**는 브랜드 네임으로만 존재해왔다. 데스크톱 클로드 코드(Claude Desktop)의 도입으로, 웹과 CLI를 동시에 구현할 수 있는 새로운 에이전트 포지션이 생겼다.

### 현재 에이전트 맵

| 에이전트 | 환경 | 역할 | 상태 |
|----------|------|------|------|
| **쌍아** | VSCode 확장 (웹) | 설계+지시서, 커맨더 | ✅ 활성 |
| **막내** | CLI (터미널) | 자율 코딩 실행 | ✅ 활성 |
| **코웍이** | Claude Desktop (웹+CLI) | 전략 보고서, 브라우저 실행 | ✅ 활성 (팀원 에이전트) |
| **소소(소넷이)** | 데몬 | 모니터링 | ✅ 활성 |
| **용아** | 외부 도구 | 자문 | ✅ 활성 |
| **민아** | - | - | ❌ 브랜드만 존재 |
| **철창이** | 샌드박스 | 전략 초안 | ✅ 활성 (외부 도구) |

## 2. 민아 역할 정의안

### 2-1. 포지션

**쌍아(설계) ↔ 민아(통합) ↔ 막내(실행)**

- **쌍아**: 전략 설계 + 지시서 발행 (커맨더)
- **민아**: 웹+CLI 통합 작업 (브리지 역할)
  - 쌍아의 설계를 웹 환경에서 검증
  - 막내의 코딩 결과를 브라우저에서 테스트
  - MCP 서버를 통한 외부 시스템 연동
- **막내**: 지시서 기반 자율 코딩 실행

### 2-2. 민아 고유 역량 (쌍아·막내와의 차별점)

| 역량 | 설명 | 활용 예 |
|------|------|---------|
| **브라우저 검증** | 배포 후 실제 화면 캡처·검증 | 에디터 UI 테스트, 홈 표출 확인 |
| **MCP 네이티브** | GitHub, Slack, DB 등 MCP 서버 직접 연동 | works 레포 관리, 팀 소통 자동화 |
| **크로스 프로젝트** | 여러 프로젝트 동시 접근 | 본진(monk_project) + works + 팀원 레포 |
| **GUI 자동화** | 화면 기반 작업 | 스크린샷 비교, UI 리그레션 |

### 2-3. 민아가 하지 않는 것

- **설계·지시서 발행**: 쌍아 영역 (민아는 실행·검증)
- **독립 코딩 세션**: 막내 영역 (민아는 통합·브리지)
- **전략 수립**: 쌍아+철창이 영역
