# SPREAD PF 전략 재기획 — 코어 루프 자동화 우선

**[2026-06-07 16:38 KST] iMac/민아 → 작가님, iMac/쌍아**

> SPREAD v2 기안(3/19) 이후 3개월간 검토 대기 상태로 정체된 PF_SPREAD를
> **전략 추가가 아닌 실행 엔진 확립** 관점에서 재기획한다.
> 한송이 퇴사로 발생한 JP 운영 공백을, 원래 SPREAD 비전("코드→에이전트")대로
> 에이전트 배포로 흡수하는 것을 핵심 축으로 삼는다.

---

## 1. 현황 진단 (3축 종합)

### 1-1. 전략 지형 (기획 문서)
- **SPREAD = Strategic Publishing, Reach, Engagement, And Distribution** — 1주제를 21채널로 전방위 배포.
- 3/19 작가님 전략 전환 선언: **코드 파이프라인(n8n) → 에이전트(코웍이) 기반 배포**. 3방식 혼용 체계(A.OG직접 / B.n8n / C.코웍이가공).
- v2 종합전략(`PROPOSAL_20260319_SPREAD_v2`) **3개월째 "검토 대기"** — 의사결정 미결.

### 1-2. 실행 현실 (PF 히스토리·실측)
- 4/7 **첫 순환 완료**(EXAONE 콘텐츠 4/5채널) 이후 정기 순환 **멈춤**.
- 4/22 실측: 활성 5채널 운영 + 2 준비. 에셋30 임계점 **3채널 돌파**(네이버 50+·인스타 47·X 34).
- 병목: 3방식 중 핵심 **C(코웍이 가공) 워크플로우 미확립**. "전략은 있는데 매일 도는 엔진이 없음."

### 1-3. 인력 변동 (조직)
- **한송이 5/27 퇴사** → note·X JP·인스타 JP 등 **JP 마케팅 수동 운영 리드 공백**.
- 한이 손으로 메우던 다채널 루틴이 멈추면 SPREAD 실측 채널이 추가 위축될 위험.

### 진단 결론
> SPREAD의 병목은 **전략이 아니라 실행 엔진**이다.
> 21채널 "전부 다" 야심이 의사결정을 마비시켰고, 한송이 공백이 수동 동력마저 끊었다.
> 해법: **폭(breadth)을 좁히지 않되, 순환 가능한 최소 루프부터 자동화해 속도(velocity)를 만든다.**

## 2. 전략 전환 — "21채널 동시" → "코어 루프 자동화 우선"

```
기존: 1주제 → [21채널 동시 배포] 야심       → 마비
제안: 1주제 → [코어 3채널 반자동 순환] 확립 → 매일 순환 → 점진 확장
```

마침 6/6 쌍아가 정리한 스킬 인프라가 이 엔진의 부품으로 정합한다:
- **`monkos-content` 스킬** — 1주제 → 한/영/일 본문 + X/인스타 캡션 + 해시태그 일괄 생성 (한송이 도메인 흡수)
- **CDP `SPREAD_DEPLOY_MANUAL`** — 12채널 실전 배포 패턴 (v1.0 민아 실전 검증)
- **`/PF현황` 스킬** — 순환 추적 대시보드

## 3. 재설계 — 3 Phase

### Phase 1.5 (즉시) — 코어 루프 확립
| 단계 | 도구 | 산출 |
|------|------|------|
| 원본 | monkos.ai 블로그 1주제 | 정본 |

- **졸업 기준**: "1주제 → 3채널 30분 순환" 1건 완주.

### Phase 2 — 임계점 집중 + JP 공백 흡수
- 에셋30 돌파 채널(네이버 50+·인스타 47·X 34)에 화력 집중.
- 한송이 공백 JP 채널(note·인스타 JP)을 **코웍이+CDP 에이전트 운영으로 전환**.

### Phase 3 — 스케줄 자동화
- `/schedule` + CDP Phase 4(스케줄 배포) 연결 → 데일리 무인 순환.
