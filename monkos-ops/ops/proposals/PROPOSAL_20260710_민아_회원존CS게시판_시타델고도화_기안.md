## 0. 관통 원칙

**CS는 비용이 아니라 T2 상품의 본체다.** 발급보장 ₩9,900의 실체가 "반려 시 책임지는 사후처리"이므로, CS 체계 = 상품 이행 체계. 동시에 1인 운영 구조상 **사람이 개입하는 CS는 금액·보증 판정뿐**이어야 하고, 나머지는 셀프서브(게시판·FAQ)와 에이전트 루틴이 흡수한다.

```
고객 접점:  게시판(공개·적층) / 텔레그램(즉답) / 이메일(공식) / 마이페이지(셀프서브)
                     │
에이전트 루틴(1차):  분류 → RAG 즉답(되는 것만) → 티켓화
                     │
사람(작가님, 2차):   보증 판정 · 환불 승인 · 크레딧 변경   ← 자동화 금지 영역(헌법·ch4 10조)
```

## 2. T2 발급보장 — 사후처리 로직 (스튜디오 검수 후)

### 2-1. 상태 기계

```
결제 → [검수 대기] → 스튜디오 검수(어드민 리뷰 큐) → [납품] → 고객 접수(관공서)
                                                        │
                     ┌──────────────────────────────────┘
                     ▼
              [반려 신고] (마이페이지 보증 센터, 납품 후 90일 내)
                     │  증빙: 접수처·반려 사유 사진/문구 업로드
                     ▼
              [판정] ── 우리 귀책(규격·품질) ──→ 선택지 제시: 재제작(우선 권장) or 100% 환불
                     └─ 고객 귀책(정보 오기·다른 사진 제출 등) ──→ 사유 설명 + 재제작 1회 호의 제공(무상)
                     ▼
              [처리 완료] — 전 과정 SLA: 신고 접수 확인 2시간 내(에이전트), 판정 24시간 내(사람)
```

### 2-2. 판정 기준 명문화 (분쟁 방어의 핵심)
- **우리 귀책**: 규격 치수 이탈, 배경·품질 문제, 파일 사양 미달 — 접수 기관의 반려 사유가 사진 규격일 때.
- **고객 귀책**: 신청 정보 불일치, 우리가 납품하지 않은 사진 제출, 접수 기관의 비규격 사유.
- 애매 구간: **고객 우호 원칙**(파일럿 단계 — 분쟁 1건의 평판 비용 > 재제작 원가 ₩100). 단 케이스 전건 기록 → 기준 정교화 데이터.
- 근거 보존: 납품물의 postcheck 수치(33.0mm·눈 45% 등)를 주문 문서에 박제 — "규격 적합을 수치로 증명"이 판정의 우리 측 증거.

### 2-3. 어드민
- 현행 idphoto-review 확장: `?service=idpass` + **보증 큐 탭**(신고 목록·증빙 뷰어·판정 버튼·환불 실행 링크). 환불 실행은 토스 취소 API — 사람 클릭 필수(자동화 금지).

## 3. 게시판 활성화 — 리뷰 채널 + T1 후처리

### 3-1. 역할 3분할

| 보드 | 역할 | 운영 |
|------|------|------|
| **후기** | 사회적 증거 적층 — 후기 이벤트(10c 지급)와 연동, 베스트 후기는 랜딩 노출 | 에이전트: 감사 응답+이벤트 크레딧 티켓화(지급은 credits.sh·사람) |
| **문의/도움** | 공개 Q&A — 답변이 곧 FAQ 자산으로 적층(SEO 부수 효과) | 에이전트 1차 답변(RAG, 되는 것만) → 미해결만 사람 |
| **T1 후처리** | ₩2,000 결과 불만 접수 창구 | §3-2 정책 |

### 3-2. T1 후처리 정책 (₩2,000 티어)
- 원칙: **재생성 1회 무상** — "다른 사진으로 다시 시도"를 가이드(사진 탓인 경우가 다수)와 함께 제공. 게시판 접수 → 에이전트가 재생성 쿠폰 코드 발급(정액·1회) → 셀프서브 재생성.
- 환불 요구 시: 결제 7일 내 + 재생성 미사용 조건으로 수용(현행 refund.html 준용) — 판정은 사람.
- 효과: T1 불만이 비공개 CS(이메일)가 아니라 **공개 게시판에서 해소되는 모습 자체가 신뢰 콘텐츠**가 된다.

### 3-3. 위치
- monkos.ai 기존 Board 인프라 재사용(헤더 메뉴 실재). 파일럿 페이지 땡큐 화면에 "후기 남기고 10c 받기" 링크 — 이벤트 슬롯과 연결.

## 4. 에이전트 CS 루틴 — 게시판·텔레그램·이메일 즉시 대응

### 4-1. 구조: 폴링 데몬 + 분류 + 3단 대응

```
[수집] 게시판 신규 글 API / 텔레그램 봇 업데이트 / info@monkos.ai IMAP  — 5분 폴링 (소넷이 데몬 or 크론 에이전트)
[분류] ① 단순 문의(규격·사용법·가격)   → RAG 즉답 — "되는 것만 응답"(ch8), 미확정 표현 금지
       ② 후기/감사                     → 감사 응답 + 이벤트 티켓
       ③ T1 불만                       → §3-2 재생성 쿠폰 플로우 (정액 자동)
       ④ 보증·환불·금액                 → 즉답 금지. 접수 확인 응답("24시간 내 답변") + 티켓 생성 + 작가님 텔레그램 알림
       ⑤ 스팸/무관                      → 무응답 로그
[기록] 전 건 Firestore cs_tickets + 일일 다이제스트 (BRIEF 편입)
```

### 4-2. 안전 경계 (헌법 정합)
- 에이전트가 절대 하지 않는 것: 크레딧 지급/차감 실행(credits.sh·작가님), 환불 실행, 보증 판정, 미출시 기능 언급.
- 응답 어조 사전: 공식 카피 사전에서만 조합(환각 차단) — RAG 소스는 specs 상세규정·FAQ·본 기안의 정책 조항.
- SLA 목표: 1차 응답 게시판·텔레그램 5분(자동), 이메일 30분, 사람 개입 건 24시간.

### 4-3. 단계 도입
1. **주간 1단계**: 게시판+텔레그램만, 응답은 "초안 → 작가님 승인 발송"(감독 학습 기간, 1~2주)
2. **2단계**: ①②③ 유형 자동 발송 승격, ④는 영구 사람
3. **3단계**: 이메일 편입 + 일일 다이제스트를 BRIEF 루틴에 통합

## 5. 시타델 고도화 — 검색 노출의 2대 전략

### 5-1. 이미지 정합 노출 (쌍아·막내 썸네일 트랙의 specs 확장)

현황: 쌍아 지시서(구글썸네일최적화)가 idphoto-kr 히어로 이미지·JSON-LD로 진행 중. 이것을 **specs 428페이지로 일반화**한다:

- **규격별 대표 결과물 이미지 자동 생성 파이프라인**: 규격마다 샘플 인물의 완성본(그 규격 비율 그대로)을 렌더 → 같은 도메인 `/images/specs/{slug}-result.webp` 서빙 → `og:image` + JSON-LD `image` + 페이지 상단 배치. 428장은 수작업 불가 — 오늘 하네스 계열(생성→재크롭)의 배치 실행으로 자동화.
- 원칙: 구글이 "이 페이지의 결과물"로 읽을 이미지 = **그 규격의 실물 비율 완성본**(캐릭터 OG 카드 아님). 경쟁사(증명한컷 등)의 검색 썸네일이 전부 얼굴 결과물인 이유.
- 검증 루프: GSC 이미지 노출·CTR 추적(진단 보고서의 quick wins 지표에 편입).

### 5-2. "딱 떨어지는 검색어" 대응 — exact-match 노출 전략

증명한컷(idcut)의 교훈: **검색어 자체가 서비스명**("증명 한 컷"으로 검색하는 사람을 브랜드가 통째로 받음). 우리 대응 3층:

1. **쿼리-페이지 1:1 정합**: 실검색어마다 정확 대응 랜딩 — "여권사진 무료"→무료 퍼널 랜딩, "미국비자사진"→us-visa ko(GSC 진단의 백지 타깃), "여권사진 규격"→kr-passport. 타이틀은 검색어 어순 그대로 전방 배치("여권사진 무료로 만들기 — 3초 규격 완성"). 막내 키워드 리서치(진행 중)의 헤드텀 목록이 이 매핑의 입력.
2. **검색어형 네이밍 자산**: 서비스 별칭을 검색어와 정합시키는 검토 — 예: "무료 증명사진"(GSC에서 CTR 100% 실측된 계열), "여권사진 3초" 류의 기능 서술형 별칭을 랜딩 H1·OG 타이틀에 이식. IDPASS 브랜드와 병기(브랜드는 재방문용, 검색어형은 유입용 — 역할 분리).
3. **언어별 실쿼리 패턴 준수** (GSC 진단 확정): ko "규정·2026년형" / ja "サイズ·色 질문형" / en "size·requirements형" — 직역 금지, 언어별 별도 작성.

### 5-3. 우선순위 (시타델 실행 대기열과 병합)
① en 타이틀 패턴 개선(노출 867·클릭 2 — 최대 지렛대) ② 미국 비자 ko 키워드 이식 ③ 규격별 이미지 정합 파이프라인(파일럿 kr-passport 1장 → 검증 → 428 배치) ④ exact-match 랜딩 매핑(막내 리서치 합류 후)
