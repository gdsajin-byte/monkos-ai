# PROPOSAL — 글로벌 결제·다국어 시스템 재설계 (글로벌 USD 단일 출발)

> **[2026-06-23 11:04 KST]** M1/민아 → 작가님
> 경로③: 민아 진단·제안 → 작가님 확정 → 쌍아 설계서 → 막내 실행 → 민아 재검증

## 0. 한 줄 요약

다국어 결제를 **"글로벌 USD 단일 채널"로 MVP 오픈** → 자리잡은 후 기축통화권(EUR·JPY·CNY) 단계 확장 → 파트너십 발생 시 정밀 현지화 재구축. 결제 실적 0인 현 시점에 멀티스토어를 미리 짓지 않는 walking-skeleton 전략.

---

## 1. 배경 — 무엇이 잘못 묶여 있었나

현재 **언어 = 통화 = 결제채널이 한 축으로 수직 결합**돼 있다.

```
KR → 한국어 → KRW → 토스
JP → 일본어 → JPY → 레몬(단일 스토어 290457, JPY 상품)
EN → (JP에 얹힘) → 번역만 → JPY로 결제 누수   ← 구조적 문제
```

EN은 독립 결제 축이 없어 JP 위에 번역으로 얹혀 있어, 결제로 가면 JP 통화(¥)로 떨어진다. 이는 코드 버그가 아니라 **"레몬 스토어에 JPY 단일통화 상품만 존재"하는 구조적 귀결**이다.

### 레몬 통화 정책 실측 (결정 근거)
- **스토어당 통화 1개 고정.** 고객 국가별 자동 통화전환(presentment) **미지원** (최다 요청 미구현 기능).
- 모든 거래는 내부적으로 USD로 환산 처리(중간환율, 추가수수료 없음).
- **멀티 스토어는 지원** → 통화별 스토어 분리가 레몬의 공식 우회법.
- 출처: docs.lemonsqueezy.com/help/payments/currencies, /help/your-account/multiple-stores

→ "단일 스토어 + 고객별 통화 자동표시"는 레몬에 없다. 진짜 다통화는 통화별 스토어 분리뿐.

## 2. 설계 원칙 (불변 기준)

```
언어(L10n)  ⊥  지역·통화  ⊥  결제 프로바이더
"언어를 골라도 통화가 따라오지 않는다"가 핵심 불변식
```

단, 결제 실적 0인 현 단계에서는 **서비스 = 통화 고정 매핑**으로 단순화한다 (geoip 동적 라우터 불요).

---

## 3. 작가님 확정 사항 (2026-06-23)

1. **결제 실적 0** — 지금은 부담 없이 단순화 가능.
2. **글로벌 USD 단일 채널로 출발** — 영어 + 달러로 글로벌 구축.
3. **포털(monkos.ai) = 글로벌 USD/영어 정체성.** 포털 레몬 연동을 신규 글로벌 스토어로 교체.
4. **idphoto-jp 동결** — 기존 ¥ 시스템(store 290457) 손대지 않음. 흡수가 아니라 보류. 미래 일본 현지화 재구축 시 재활용 자산으로 보존.
5. **idphoto-kr 토스(KRW) 유지** — 본진 한국.
6. 달러 해외결제 마찰(¥ 앵커링 상실·해외수수료)은 수용. "필요하면 그냥 쓴다, 그것 때문에 돌아서지 않는다" (작가님).
7. 레몬이 스트라이프 직결보다 결제 UX가 번거로운 점 인지 — 단 글로벌은 레몬 MoR(세금·인보이스 대행) 가치가 큼. 스트라이프 재검토는 차기(P5).

## 4. 확정 구조 (MVP)

```
portal (monkos.ai) → 레몬 글로벌 스토어 (USD · 영어 기본)   ★ 신규 단일 글로벌 채널
idphoto-kr         → 토스 (KRW)                            본진 한국, 유지
idphoto-jp         → 동결 (현 ¥ store#290457 그대로)        손 안 댐
```

## 5. 단계적 확장 전략

```
[NOW]  영어 + USD 글로벌 스토어 1개 오픈 (포털)        ← 단일 채널, 최소 복잡도
   ↓ 자리잡으면
[NEXT] 기축통화권 확장 — EUR · JPY · CNY              ← 레몬 통화별 스토어 증설
   ↓ 파트너십 발생 시
[LATER] 정밀 현지화 재구축 — 현지 결제수단·언어 깊이
```

## 6-2. 시크릿 분리 설계 (🔴 P3 핵심 — 포털·idphoto-jp 충돌 방지)

`idphoto-jp/server.js`도 동일 `LEMONSQUEEZY_WEBHOOK_SECRET`을 참조 → 포털만 글로벌로 바꾸려 덮어쓰면 JP가 깨짐. 네이밍 분리:

```
LEMONSQUEEZY_API_KEY                = 계정 공유 (모드 정합 시)
LEMONSQUEEZY_STORE_ID              = 290457  (idphoto-jp 동결 전용)
LEMONSQUEEZY_WEBHOOK_SECRET        = JP 웹훅 (idphoto-jp 전용)
LEMONSQUEEZY_STORE_ID_GLOBAL       = 415328  (포털 신규) ★
LEMONSQUEEZY_WEBHOOK_SECRET_GLOBAL = 글로벌 웹훅 secret (라이브 단계 발급) ★
```

- 기존 SECRET_INVENTORY 등록분(2026-06-03): `LEMONSQUEEZY_API_KEY`·`LEMONSQUEEZY_WEBHOOK_SECRET` 2종 = JP 기준. 글로벌용 2종(★)은 **라이브 단계에서 신규 발급·등록**.
