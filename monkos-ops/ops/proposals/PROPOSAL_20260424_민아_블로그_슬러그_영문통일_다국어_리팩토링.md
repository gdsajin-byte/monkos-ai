# 블로그 슬러그 영문 통일 + 다국어 URL 리팩토링 제안서

## 1. 배경 — 4.7 블로그 SPREAD 중 발견된 구조 결함

### 1-1. 사건 (2026-04-24)
작가님 4.7 블로그 발행 → 3언어 자동번역본을 SPREAD 배포하던 중 **JP 자동번역이 "Claude Max 20X" → "Claude-v2-200K"로 오역**. 슬러그까지 오염 (`opus-4-7-problems-claude-v2-200k-user-ja`).

### 1-2. 영향
- 일본 독자가 본문을 **2023년 Claude 2 구버전 관련 글로 오해** 가능
- **SEO·신뢰도 손상**: 제목이 잘못된 고유명사 포함
- URL 자체가 오염 → 수동 수정하려면 **발행된 글 리스키 작업**

### 1-3. 근본 원인
1. **자동번역기가 고유명사(플랜명·모델명) 미보존**
2. **슬러그가 번역 대상에 포함됨** (원칙적으로 제외되어야)
3. **번역 엔진 지식 컷오프** — "Max 20X"는 2024~ 신규 플랜명. 오래된 번역 모델은 미학습 → 친숙한 유사 용어("Claude v2 200K")로 자동 치환

### 1-4. 현재 URL 구조 문제
| 언어 | 현 URL | 문제 |
|---|---|---|
| KR | `/blog/47-20x` | 의미 불분명한 축약 슬러그 |
| EN | `/en/blog/opus-4-7-whats-the-problem-a-claude-max-20x-users-perspectiv` | 70자 가까운 장문 슬러그 |
| JP | `/ja/blog/opus-4-7-problems-claude-v2-200k-user` | **오번역 반영** |

→ 3개 언어 슬러그가 완전히 달라 **동일 콘텐츠의 다국어 버전으로 인식되기 어려움** (hreflang·검색엔진 매핑 저해)

## 2. 제안 구조

### 2-1. 핵심 원칙
1. **슬러그는 영문 원문 하나로 고정** (DB master)
2. **언어 구분은 URL 경로 접두어**로 (기존 MONKOS 부분 채택 구조 확장)
3. **자동번역 파이프라인에서 슬러그 번역 제외**
4. **고유명사 glossary**로 본문·제목 번역 시 오염 방지

### 2-2. 새 URL 패턴

```
KR (기본): /blog/{canonical-slug}
EN:        /en/blog/{canonical-slug}
JP:        /ja/blog/{canonical-slug}
(향후 추가) /zh/blog/{canonical-slug}, /es/blog/{canonical-slug} ...
```

**예시 (4.7 블로그)**:
```
/blog/opus-4-7-claude-max-20x      (KR)
/en/blog/opus-4-7-claude-max-20x   (EN)
/ja/blog/opus-4-7-claude-max-20x   (JP)
```

### 2-3. 대안 비교 (기록 목적)

| 방식 | 예시 | 평가 |
|---|---|---|
| **A. 경로 접두어 + 공통 슬러그** (권고) | `/en/blog/{slug}` | Google 공식 권장, hreflang 표준, URL 짧음 |
| B. 슬러그 접미어 | `/blog/{slug}-en` | 허용되나 비주류. 작가님 최초 제안이었으나 A가 MONKOS 기존 구조와 호환 |
| C. 서브도메인 | `en.monkos.ai/blog/{slug}` | 별도 도메인 운영 부담 |
| D. 쿼리스트링 | `/blog/{slug}?lang=en` | SEO 비추천, 크롤링 이슈 |

## 3. 구현 상세

### 3-1. DB 스키마 변경 (추정)
```sql
-- blog_post 테이블
ALTER TABLE blog_post ADD COLUMN canonical_slug VARCHAR(255) UNIQUE NOT NULL;
-- 기존 slug 컬럼은 레거시 호환용 유지, 점진적 deprecate

-- blog_post_translation 테이블 (언어별 번역)
CREATE TABLE blog_post_translation (
  id SERIAL PRIMARY KEY,
  post_id INT REFERENCES blog_post(id),
  lang VARCHAR(5) NOT NULL,   -- 'ko', 'en', 'ja'
  title VARCHAR(500),
  content TEXT,
  meta_description VARCHAR(500),
  UNIQUE (post_id, lang)
);
-- slug는 blog_post.canonical_slug만 사용 (번역본별 slug 저장 X)
```

### 3-2. 라우터 (Hono / Express / Next 추정)
```javascript
// 언어 prefix 감지 middleware
app.get('/:lang?/blog/:slug', (req, res) => {
  const lang = ['ko','en','ja'].includes(req.params.lang) ? req.params.lang : 'ko';
  const slug = req.params.slug;
  const post = db.findByCanonicalSlug(slug);
  const translation = db.findTranslation(post.id, lang);
  return renderPost(post, translation, lang);
});
```

### 3-3. 자동번역 파이프라인 수정
```python
# 현재 (추정 구조)
def translate_post(post, target_lang):
    return {
        'title': translate(post.title, target_lang),
        'slug': translate(post.slug, target_lang),      # ⚠ 오염 소스
        'content': translate(post.content, target_lang),
        'meta_description': translate(post.meta_description, target_lang)
    }

# 수정안
PROPER_NOUNS = {
    # 모델·플랜·제품명
    'Claude Max 20X', 'Claude Max 5X', 'Claude Code',
    'Opus 4.7', 'Opus 4.6', 'Sonnet 4.6', 'Haiku 4.5',
    'Anthropic', 'OpenAI', 'Google', 'Gemini', 'GPT', 'Llama', 'Qwen',
    # 개발 용어
    'MCP', 'CDP', 'CLAUDE.md', 'MEMORY.md',
    # MONKOS 브랜드
    'MONKOS', 'MONK OS', 'monkos.ai', 'monk.kr',
}

def translate_post(post, target_lang):
    return {
        'title': translate_with_glossary(post.title, target_lang, PROPER_NOUNS),
        'slug': post.canonical_slug,                     # ✅ 원문 고정
        'content': translate_with_glossary(post.content, target_lang, PROPER_NOUNS),
        'meta_description': translate_with_glossary(post.meta_description, target_lang, PROPER_NOUNS)
    }

def translate_with_glossary(text, lang, glossary):
    # 1. 고유명사를 마스킹 토큰으로 치환
    masked = text
    mapping = {}
    for i, term in enumerate(sorted(glossary, key=len, reverse=True)):
        token = f'__PN{i}__'
        if term in masked:
            masked = masked.replace(term, token)
            mapping[token] = term
    # 2. 번역
    translated = translate(masked, lang)
    # 3. 마스킹 복원
    for token, original in mapping.items():
        translated = translated.replace(token, original)
    return translated
```

### 3-4. hreflang 메타태그 자동 생성
```html
<!-- /blog/opus-4-7-claude-max-20x 에서 렌더 -->

<link rel="alternate" hreflang="en" href="https://monkos.ai/en/blog/opus-4-7-claude-max-20x" />
<link rel="alternate" hreflang="ja" href="https://monkos.ai/ja/blog/opus-4-7-claude-max-20x" />
<link rel="alternate" hreflang="x-default" href="https://monkos.ai/blog/opus-4-7-claude-max-20x" />
<link rel="canonical" href="https://monkos.ai/{current-lang}/blog/opus-4-7-claude-max-20x" />
```

- `<xhtml:link rel="alternate" hreflang="..." href="..." />` 각 엔트리에 포함

## 4. 마이그레이션 전략 (기존 글)

### 4-1. 기존 글 재슬러그 매핑 표 예시
| 기존 URL | 새 URL | redirect 코드 |
|---|---|---|
| `/blog/47-20x` | `/blog/opus-4-7-claude-max-20x` | 301 |
| `/en/blog/opus-4-7-whats-the-problem-a-claude-max-20x-users-perspectiv` | `/en/blog/opus-4-7-claude-max-20x` | 301 |
| `/ja/blog/opus-4-7-problems-claude-v2-200k-user` | `/ja/blog/opus-4-7-claude-max-20x` | 301 |

### 4-2. 301 redirect 구현
- Cloudflare Workers 또는 서버 측 miss-handler에서 legacy slug → canonical slug 매핑
- Redirect 테이블 `blog_slug_redirect`:
```sql
CREATE TABLE blog_slug_redirect (
  old_slug VARCHAR(255) PRIMARY KEY,
  old_lang VARCHAR(5),
  new_canonical_slug VARCHAR(255) NOT NULL,
  created_at TIMESTAMP DEFAULT NOW()
);
```

### 4-3. 외부 링크 영향
- **네이버 블로그·note·X·GitHub Issue 등 이미 발행된 외부 링크**는 301 redirect로 자동 추적 → 수정 불필요
- **검색엔진 인덱스 갱신**: Google은 301 감지 후 점진적 이전 (~몇 주)
- **Google Search Console**: "URL 이전 변경" 알림 설정 권고
