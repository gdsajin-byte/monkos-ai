# SPECS en/ja 퍼널 정합 제안 — 구형 유료 퍼널 + 한글 카피 글로벌 노출

## 요약

en/ja 스펙스 페이지의 전환 퍼널이 ① 폐기된 구형 유료 UX로, ② 한글 하드코딩 카피 그대로 라이브 중이다. 근본 원인은 하나 — **파일럿 판별이 `lang === 'ko'` 기준**이라, 7/13 "T1 전 슬러그 개방"으로 slug 축은 풀렸지만 lang 축이 ko에 묶인 채 en/ja v2가 env 게이트로 개방됨. 코드 주석의 전제("en/ja는 퍼널 문구 3언어화 후 개방 예정", render-specs.js:784)가 미이행 상태로 노출됐다.

## 증상 (작가님 실캡처 2건 + 민아 실측 2026-07-15)

- `/ja/specs/visa/kr` 업로드 후: "규격 안착"(폐기 문구) 패널 + 한글 칩(얼굴 33mm/기울기 3°) + 한글 CTA "이대로 만들기/다른 사진으로".
- CTA 진행 시: 구형 유료 퍼널 — 한글 "찍힌 분(성인/청소년/영유아)"·"의상 선택(그대로/정장/블라우스/캐주얼)" + $1.99 결제 박스.
- **무료 배경제거(T0)가 아예 실행되지 않음** — ko 신형 퍼널(무료 3회 배경제거+규격 크롭)이 en/ja에는 부재.
- GSC 기준 이 퍼널이 노출되는 실유입 존재: ja/visa/kr 클릭 2건(7/1~14), ja 전체 임프레션 상위 passport/jp 148건.

## 카피 개정 (작가님 지적 2026-07-15)

'찍힌 분'(render-specs.js:1141)은 **한국어 원문 자체가 어색** — 피동형 '찍히다'(CCTV에 찍힌/몰래 찍힌 뉘앙스)에 존칭 '분'이 결합해 부자연. 번역 이전에 ko 원문부터 재작성 대상.

- 맥락: Phase 2 결제 패널의 피사체([SUBJECT]) 선택 라벨 — 구매자≠피사체 케이스(부모가 영유아 사진 제작 등) 구분용.
- **권고: ko '사진 속 인물'** (중립·명확). 대안: '사진 속 주인공'(온기, 영유아 케이스 친화).
- 3언어화 시: en "Person in the photo" / ja "写真の人物" 계열 — 확정 문안은 지시서 단계에서.
- 동일 블록 내 `v2.altPreview`·`v2.btnOtherPhoto`는 이미 i18n인데 형제 라벨('찍힌 분'·연령/성별 칩·'의상 선택'·의상 카드)만 하드코딩 — 혼재 상태로, A안 작업 시 블록 단위 일괄 편입이 효율적.

## 아키텍처 노트 (작가님 질의 2026-07-15 — "기능 코드는 컴포넌트여야 하지 않나")

**실측**: 428페이지는 정적 복제가 아니라 단일 SSR 템플릿(`specsDetailV2Fragment(slug, lang)`) + 데이터(`specs-data.json`) 구조 — 페이지 축은 이미 표준적. 문제는 **기능 위젯 축**:
- 퍼널 위젯(업로드/분석/결제/의상/땡큐) 마크업이 독립 컴포넌트가 아니라 페이지 템플릿 문자열에 인라인 (render-specs.js 1,809행, 상세 프래그먼트 단일 함수 ~500행).
- 위젯 로직도 마운트형이 아닌 페이지 전역 스크립트(specs-funnel.js 1,232행) + 문자열 인라인.
- 파일럿/비파일럿이 컴포넌트 버전 교체가 아니라 템플릿 내 삼항연산자 다수로 산재 — **이번 사고의 구조적 원인**(게이트 하나 열리자 낡은 분기 조합이 그대로 노출).
- 반면 attire-picker.js(381행)는 정확한 컴포넌트 패턴(mount(el, opts) + UI_TEXT 사전) — 단 실사용처가 demo.html뿐(미편입).

**권고 방향**: 순수 JS 스택 유지 전제에서 attire-picker 패턴을 사내 위젯 표준으로 삼아, B안 진행 시 퍼널을 `mount(el, {slug, lang, market, tier})` 컴포넌트로 추출. 이후 언어·시장·티어 축은 opts 주입으로 종결 — lang 분기 산재 재발 차단. idpass 라우터 구조화(server.js 모놀리스 분리) 트랙과 동일 방향. 단 지혈(A안·공통 P0~P1)과 분리된 중기 트랙으로 — 리아키텍처가 지혈을 지연시키지 않도록.

## 권고

무료 쿼터 글로벌 정책이 즉시 결정 가능하면 **B안 직행**(두 축 동시 해소). 결정에 시간이 필요하면 **A안 선행 지혈 후 B안** — 현재 실유입이 한글 UI에 노출되는 시간을 최소화하는 순서. A안·공통 1~3은 막내 1인 지시서 1건 분량으로 판단.
