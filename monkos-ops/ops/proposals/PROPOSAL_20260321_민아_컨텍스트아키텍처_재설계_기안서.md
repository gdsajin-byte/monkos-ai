## 7. 설계 제안

### 축 1: rules 확장 전략

**제안: 도메인별 분리 (경로 매칭 활용)**

| 파일 | paths 매칭 | 내용 | 예상 크기 |
|------|-----------|------|----------|
| `rules/portal_seo.md` | `monkos_AI/portal/**` | ✅ 기존 유지 | 2.9KB |
| `rules/blog_editor.md` | `monkos_AI/portal/public/admin/**`, `monkos_AI/portal/lib/cms/**` | 에디터 기술명세 핵심 | ~2KB |
| `rules/spread_publish.md` | `monkos-ops/marketing/**`, `monkos-ops/works/**` | 채널별 배포 규칙, 톤앤매너 | ~2KB |
| `rules/studio_imagen.md` | `monkos_AI/studio/**`, `apps/monk_imagen4/**` | 이미지 생성 파이프라인 규칙 | ~2KB |
| `rules/browser_ops.md` | — (수동 또는 향후 경로 추가) | 민아 브라우저 작업 가이드 | ~1.5KB |

**장점**: 파일 접근 시 자동 로딩 → 토큰 절약 (항상 먹지 않음)
**한계**: 역할(에이전트)별 분리가 아니라 도메인별 분리. 같은 파일을 쌍아와 민아가 모두 읽을 수 있음.

### 축 2: 역할별 분리 우회 전략

Claude Code는 현재 **에이전트 식별 → 조건부 로딩** 기능이 없다. 우회 방법:

| 방법 | 원리 | 장점 | 단점 |
|------|------|------|------|
| **외장 메모리 패턴** | `memory/mina_state.md` 등 역할별 파일. 세션 시작 시 수동 Read | 역할별 분리 가능 | 매 세션 수동 Read 1회 |
| **하위 CLAUDE.md** | `monkos_AI/portal/CLAUDE.md` 등 디렉토리에 역할 힌트 | 디렉토리 진입 시 자동 | 디렉토리 = 역할이 아님 |
| **MEMORY.md 역할 섹션** | MEMORY 안에 `## 민아 전용`, `## 쌍아 전용` 구분 | 추가 파일 불필요 | 200줄 캡 더 빠르게 소진 |

**제안**: 외장 메모리 패턴 채택. MEMORY.md는 디바이스 OS로 유지하고, 역할별 상태는 `memory/` 하위에 분리.

### 축 3: 팀원 디바이스 (코웍이/철창이) 동기화

| 방법 | 현재 | 제안 |
|------|------|------|
| **works CLAUDE.md** | 125줄 (인터페이스 규칙만) | 헌법 핵심 요약 + 현재 프로젝트 상태 추가 |
| **프로젝트 지식** | 수동 첨부 | works CLAUDE.md를 정본으로 지정. 코웍이 세션 시 자동 읽기 |
| **규칙 동기화** | 없음 | rules 변경 시 works에 요약본 자동 반영 (쌍아/민아가 커밋 시) |

## 8. 글로벌 CLAUDE.md 신설 여부

### 옵션 A: 신설 (`~/.claude/CLAUDE.md`)

```
내용: 디바이스 공통 원칙 (타임스탬프 절대 준수, 파괴적 명령 금지 등)
효과: monk_project 외 프로젝트(monk-han, monk-kku)에도 자동 적용
위험: 프로젝트별 독립성 침해. monk-han의 코웍이에게 불필요한 규칙 주입
```

### 옵션 B: 미신설 (현행 유지)

```
현행: 프로젝트 루트 CLAUDE.md가 최상위
효과: 프로젝트별 완전 독립
단점: 디바이스 공통 규칙을 각 프로젝트에 중복 기재
```

**제안**: 옵션 B 유지. 현재 iMac에서 주로 monk_project만 운용하므로 글로벌 레이어 불필요. 향후 멀티프로젝트 운용이 본격화되면 재검토.
