# 포털 monkos.ai 전체 개편 기안서

> **[2026-04-25 15:27 KST] iMac/민아 → 작가님 + iMac/쌍아**

## 1. 배경

### 1-1. 어제(4/24) idphoto 진단 결과
- 막내1이 idphoto-kr/jp 랜딩(`monkos_AI/idphoto-kr|jp/public/index.html`)을 진단·개편·prod 배포 완료. 핵심 처방 — **히어로에 결과물 0장 → 3장 신규 배치**, H1·CTA·신뢰지표·3단계 프로세스 신규 도입. 라이브 반영 확인됨.
- 그러나 진단·처방 범위는 **idphoto 서브페이지 한정**. **포털(monkos.ai) 자체는 손대지 않음**. 향후 검토 대상 1번 "포털 히어로에 idphoto CTA 추가"로 명시.

### 1-2. 포털 자체 문제 — 작가님 4/25 직접 지적
- **헤더 증명사진 개연성 부재**: `<h1>MONKOS AI</h1>` + 부제 `Photography × AI × K-Beauty` — 추상 브랜드 메시지만, 증명사진 단서 0. K-Beauty 표기는 검색 유입자에게 **헤어메이크업/뷰티 도메인 오해 유발**.
- **/specs 자산 노출 부재 (작가님 핵심 지적)**: `lib/cms/specs-data.json`에 **26국·5권역**(한국·일본·USA·유럽·기타) 규격 데이터 적재 + 어제 AEO 1단계로 Article + FAQPage + HowTo 스키마 완비. 라이브 페이지(`/specs`, `/ja/specs`, `/en/specs`) 200 OK. **그러나 포털 메인 네비게이션 진입 동선 0** — 일반 방문자는 specs 존재 자체를 인지 불가, 검색 유입자는 다른 페이지로 못 옴 = 도메인 권위 약화.
- **우측 사이드바 가이드 영상 목업 잔존 (작가님 지적)**: `<div class="guide-card">` 2종 — phone-screen 아이콘만 그린 목업. 한송이 연구원이 vol.33~vol.35로 사용법 관련 쇼츠 콘텐츠 누적 중인데 **포털과 단절** 상태. 자체 자산을 자체 노출에 미활용.
- **포털 v4 미해결 이슈** (`.claude/rules/portal_seo.md` 등재):
  - #4 히어로 CTA 부재
  - #5 Before/After 갤러리 플레이스홀더

### 1-3. 통합 진단
포털은 어제 idphoto가 받은 처방을 **부분 차용 + 자체 차별화**가 필요. idphoto는 단일 서비스 랜딩, 포털은 multi-서비스 entry point + 콘텐츠 허브이므로 처방을 그대로 복제하면 정체성이 흐려진다.

### 트랙 1. 헤더 개편 (브랜드 보존 + 행동 유도)

**Before**
```
배지: AI Creative Platform
H1:   MONKOS AI
부제: Photography × AI × K-Beauty
CTA:  (헤더 영역 외)
```

**After (A안)**
```
배지: AI CREATIVE PLATFORM (유지)
H1:   MONKOS AI (유지, 살짝 축소)
서브: 셀카 한 장 → 증명사진. 사진관 품질 AI.
듀얼 CTA: [📷 AI 증명사진]  [✂️ 무료 크롭앱]
트러스트: 3분 · ICAO 국제 규격 · ₩9,900
```

**근거**
- 포털 = multi-서비스 entry이므로 brand 보존 필요. idphoto 톤(브랜드 강등 + "셀카 한 장으로 증명사진 완성" 메인) 그대로 차용 시 정체성 흐려짐.
- 듀얼 CTA — 두 핵심 서비스(idphoto / crop) 동시 진입로 확보. user-bar `촬영 시작하기` 버튼은 보조 CTA로 유지.
- "Photography × AI × K-Beauty" 제거 — K-Beauty 표기는 작가님 비전 슬로건이지만 증명사진 검색 유입자에게는 노이즈.

**비제안 안 (참고용)**
- B안 (idphoto 처방 복제): H1 "셀카 한 장으로 증명사진 완성"으로 교체. → 포털을 idphoto 단일 서비스로 좁힐 때 유효. 현 단계 비추천.

### 트랙 2. 네비게이션 재정렬 (specs 신설 + 슬림화)

**Before**: `홈 / 블로그 / FAQ / 갤러리 / 게시판 / 가격` (6개)

**After (B안)**: `홈 / 규격 / 블로그 / FAQ / 가격` (5개)
- **규격** = `/specs` 진입 (다국어 시 `/ja/specs`, `/en/specs` 자동 분기)
- 갤러리 / 게시판은 푸터로 강등 (사용 빈도 대비 nav 점유 과대)

**근거**
- specs는 어제 AEO 1단계로 26국 스키마 완비된 SEO·AEO 핵심 자산. 검색 의도 강한 콘텐츠를 nav 2번째 슬롯에 배치하면 일반 방문자 동선 + 검색 유입자 사이트 회유 동시 해결.
- 메뉴 7개 → 5개로 모바일 가독성 개선.
- 갤러리(결과물 샘플)·게시판(글 0건)은 푸터 강등 후 재활성화 시 nav 복귀 검토.

**비제안 안**
- A안 (현 메뉴 + 규격 추가, 7개): 모바일에서 빡빡함.
- C안 (드롭다운 메가메뉴): 모바일 UX 복잡. 향후 specs 권역이 커지면 재검토.

### 트랙 3. 본문 specs 카드 섹션 신설

**위치**: 인트로 텍스트(`<p class="intro-text">`) **직후**, 서비스 카드 2개(`.svc-grid`) **직전**.

**구조**:
```
<section class="specs-quick">
  <h2>국가별 증명사진 규격</h2>
  <div class="specs-grid">
    🇰🇷 한국    → /specs#korea (여권·신분증·이력서·반명함·운전면허·주민등록 6종)
    🇯🇵 日本    → /specs#japan (여권·이력서·마이넘버·반명함·재류카드 5종)
    🇺🇸 USA     → /specs#usa (여권·헤드샷 2종)
    🇪🇺 Europe  → /specs#europe (여권·이력서·스페인·독일·UK 5종)
    🌏 기타      → /specs#others (호주·캐나다·싱가폴·태국·인도·중국·베트남·인도네시아 8종)
  </div>
  <a href="/specs" class="specs-all">전체 26국 규격 보기 →</a>
</section>
```

**근거**
- 작가님 직접 지적: "각국 증명사진 규격 탭으로 있어야 일반인들에게도 노출". nav만으로는 약함 — 본문에서도 시각적으로 보여야 1차 유입자가 즉시 자기 용도 식별.
- 5권역 타일은 데이터 정합성 ✅ (specs-data.json에 5권역 분류 그대로 존재).
- `/specs#korea` 같은 앵커 링크 시 `renderSpecsList`가 한국 섹션으로 스크롤되도록 보강 (트랙 3에 포함).
- 각 권역 타일은 specs 진입로이자 idphoto 촬영 동선의 게이트웨이.
