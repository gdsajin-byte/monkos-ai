# PROPOSAL — monk.kr 배포 요청의 클로드 앱 알림 + 승인 버튼 (쌍아 설계 요청)

**[2026-10-21 14:01 KST]** iMac/민아 → iMac/쌍아 (작가님 참조)

## 1. 문제

꾸(M2)가 monk.kr을 푸시하면 `notify-monk-kr-pending.yml`이 텔레그램으로만 알린다. 작가님이 배포하려면 ① 텔레그램 확인 → ② iMac 민아 세션에 아무 말이나 입력 → ③ 민아 사전 점검 → ④ 다음 단계 박스의 "배포 승인" 버튼 클릭(=사용자 턴 "배포 승인" → E10 토큰) → ⑤ 민아 `gh workflow run`. 오늘(10-21) 2회 배포가 정확히 이 5단계였다. ②가 군더더기다.

## 3. 요청하는 설계 범위

1. **발신**: M2 세션이 `MONK_kr/**`·`functions/**` 푸시 직후 iMac 민아 세션에 `[배포 요청] {커밋 SHA} · {요약} · {꾸 결정/제보}` 1줄 발송. 수신 주소는 피어 목록에서 이름 날짜·시각이 가장 늦은 `iMac-민아-*`. 발신 주체·시점을 M2 session-end 또는 makne-finish 절차에 둘지는 쌍아 판단.
2. **수신**: iMac 민아가 깨어나면 `/deploy-cf` 0~1단계 사전 점검(CI·클린·라이브 2회 히트 미반영 확인)을 돌리고, 푸시 알림(`PushNotification`, 200자) 1줄 + 다음 단계 박스에 "배포 승인"/"보류" 버튼을 남긴 채 유휴 진입. 승인 토큰 발급·`gh workflow run`은 현행 그대로(ch5 1조·ch1 7조 — 사람 턴만).
3. **전제 유지**: iMac 민아 세션 상시 가동 + 양쪽 Remote Control 연결. 끊긴 경우의 실패 가시화(텔레그램 경로는 그대로 두어 이중화).
4. **규정 반영 지점(쌍아 소관)**: `commands/deploy-cf.md`(수신 절차), `commands/session-start.md` 또는 M2 측 절차(발신), `rules/deployment.md` 1줄, references.md 도구 맵. 민아는 규정 계층 수정 불가(ch1 2조 5항).
