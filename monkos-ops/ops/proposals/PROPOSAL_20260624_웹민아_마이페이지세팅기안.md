## 0. 한 줄 요약

**백엔드(인증·크레딧·결제·GCS 저장)는 프로덕션 수준이나, 사용자가 자기 자산을 확인할 프론트 마이페이지가 0이다.** 가장 큰 단일 갭은 **생성 이미지의 Firestore 인덱스 부재** — GCS에 저장은 되지만 "내 사진 목록"을 조회할 수단이 없다. 본 기안은 ① 마이페이지 정보구조(IA) ② 생성내역 인덱스 신설 ③ 4단계(T0~T3) 구축 로드맵을 제시한다. 최근 활성 PF(STYLER 진화선·EVENT 전환·PARTNER B2B·OPUS 플라이휠)의 방향성을 수용한 확장형 골격을 채택한다.

## 1. 배경 — "백엔드는 견고, 프론트는 공백"

### 1-1. 이미 구현된 것 (실측 확인 완료)

| 영역 | 상태 | 정본 파일 | 핵심 |
|------|------|----------|------|
| **인증** | ✅ 프로덕션 | `monkos_AI/portal/lib/auth.js` | Google/Kakao/LINE OAuth, HMAC 세션 쿠키(`monkos_session`, 30일), `/api/auth/verify-cookie` |
| **크레딧** | ✅ 프로덕션 | `lib/credits.js` | `/api/credits` 조회·사용·환불, `transactions` 원장, `audit` 감사 |
| **결제** | ✅ 프로덕션 | `lib/payments.js` | 토스(KR)·Lemon Squeezy(글로벌), 웹훅 서명 검증 |
| **이미지 저장** | 🟡 저장만 | `lib/gcs-save.js` | `saveImages(service, userId, style, ...)` → `gs://monk-customer-photos/{service}/{userId}/{ts}_{style}_*.{jpg,png}` |
| **다국어** | 🟡 UI만 | `public/js/i18n.js` | `monkos_lang` 쿠키, ko/ja/en 경로 분기 |
| **관리자 대시보드** | ✅ 어드민용 | `lib/cms/dashboard.js` | `/api/admin/dashboard/*` — 일반 사용자 미노출 |

### 1-2. 없는 것 (마이페이지 갭)

- ❌ **마이페이지/계정 페이지 자체** (`/mypage`, `/account` 라우트·HTML 전무)
- ❌ **생성내역 조회** — `saveImages()`는 GCS 객체 메타데이터만 남기고 **Firestore 인덱스를 쓰지 않는다.** `/api/history`도 없다. → 사용자별 "내 사진" 목록 조회 **구조적으로 불가**
- ❌ 구매 이력 사용자 조회 UI (원장 `transactions`는 있으나 노출 화면 없음)
- ❌ 언어·알림 등 개인 설정 저장 (`users.settings` 미사용)
- ❌ 회원 탈퇴/계정 삭제, 데이터 삭제 요청

> **결론: 구축 순서는 "화면 신설"이 아니라 "인덱스 신설 → 화면"이다.** 인덱스 없이 갤러리를 못 만든다.

## 2. PF 방향성 정렬 — 왜 확장형 골격인가

최근 활성 PF들이 마이페이지에 부과하는 요구를 수용한다. 지금 다 만들지는 않되, **데이터 모델이 이들을 막지 않도록** 설계한다.

| PF | 방향성 | 마이페이지에 거는 요구 | 본 기안 반영 |
|----|--------|----------------------|-------------|
| **STYLER** | 증명사진→헤드샷→VTON→앱→커머스 진화선 | 서비스 종류가 늘어난다. 스타일별 생성 갤러리 | 생성내역에 `service`·`style` 1급 필드 → 서비스 탭 무한 확장 |
| **EVENT** | ₩9,900 프로모션 → 첫 paying customer | 쿠폰·프로모션 현황, 이벤트 경로 태깅 | `transactions.metadata`에 프로모션 코드/채널, 크레딧 출처(이벤트 vs 구매) 구분 표시 |
| **PARTNER** | 인크루트 등 B2B 코브랜딩 입점 | 채널별 사용 현황, 엔타이틀먼트 분기 | 생성내역에 `channel`(origin) 필드 예약 → 본진/파트너 구분 집계 |
| **OPUS** | 콘텐츠 플라이휠(사진→콘텐츠 자동배포) | 사용자 사진의 UGC 활용 동의/현황 | 설정에 `marketingConsent` 필드 예약 (Phase 후순위) |
| **INFRA** | 고객사진 버킷(`monk-customer-photos`) 테넌트 격리 | 조회 시 userId 테넌트 검증 | 갤러리 API는 세션 userId로만 prefix 접근, 교차조회 차단 |
| **(전제)** 결제·다국어 | USD 단일 → 단계 확장(어제 제안서) | 통화/언어 표시 일관성 | 본 기안은 결제 재설계 제외, 표시만 연동 |

## 3. 마이페이지 정보구조(IA) 설계

```
/account  (로그인 필수 — 미인증 시 로그인으로 리다이렉트)
│
├─ 👤 프로필
│    ├─ 이름 / 프로필 사진 / 이메일 (verify-cookie 응답 그대로)
│    ├─ 가입 제공자 배지 (Google/Kakao/LINE)
│    ├─ 가입일 · 최근 로그인
│    └─ [설정] 언어 · 알림 · (마케팅 활용 동의)
│
├─ 💳 크레딧 & 결제
│    ├─ 현재 잔액 (대형 표시) + [충전] → 기존 credits.html
│    ├─ 거래 내역 (transactions): 일시 / 유형(충전·사용·환불) / 금액 / 잔액 / 출처
│    └─ 크레딧 출처 구분: 이벤트 지급 vs 직접 구매 (EVENT 정렬)
│
├─ 📸 나의 생성 이미지 (갤러리)  ★ 신규 인덱스 필요
│    ├─ 서비스 탭: 증명사진 / 헤드샷 / 크롭 / (VTON…)  ← STYLER 확장
│    ├─ 썸네일 그리드: 규격·스타일·생성일
│    ├─ 라이트박스: 원본·생성본 비교
│    ├─ 액션: 다운로드(HQ) / 추가규격 변환 / 재생성 / 삭제
│    └─ "30일 후 자동 삭제" 안내 (GCS TTL — INFRA/법적)
│
└─ 🗑️ 데이터 & 계정
     ├─ 사진 즉시 삭제 요청
     ├─ 개인정보처리방침 링크
     └─ 회원 탈퇴 (계정·데이터 삭제)
```

## 4. 데이터 모델 — 핵심 갭 해결

### 4-1. 신규 컬렉션 `generations` (생성내역 인덱스) — **최우선**

`saveImages()` 호출 시점에 Firestore 1건을 함께 기록하도록 보강한다.

```javascript
// Firestore: generations/{autoId}
{
  userId:    string,        // 테넌트 키 (세션 userId와 일치할 때만 조회 허용)
  service:   string,        // 'idphoto' | 'headshot' | 'crop' | 'vton' ...  (STYLER 확장축)
  style:     string,        // 프리셋/규격 (예: 'kr-passport-35x45', 'linkedin')
  channel:   string,        // 'monkos' | 'incruit' | ...  (PARTNER 예약, 기본 'monkos')
  gcsOriginal:  string,     // {service}/{userId}/{ts}_{style}_original.jpg
  gcsGenerated: string,     // {service}/{userId}/{ts}_{style}_generated.png
  status:    string,        // 'active' | 'deleted'
  createdAt: ISO string,
  expiresAt: ISO string,    // createdAt + 30d (TTL 표시·정책 일치)
}
```

> 인덱스: `(userId, createdAt desc)` 복합 인덱스. 기존 GCS 경로 규칙을 그대로 재사용하므로 저장 로직 변경 최소.

### 4-2. `users.settings` 활성화 (기존 스키마 확장)

```javascript
users/{userId}.settings = {
  language: 'ko' | 'ja' | 'en',      // monkos_lang 쿠키와 동기화
  emailNotifications: boolean,
  marketingConsent: boolean,         // OPUS UGC 활용 (Phase 후순위)
}
```

### 4-3. API 신설 (순수 JS, 기존 server.js 라우팅 패턴 준수)

| 메서드 | 경로 | 설명 | 인증 |
|--------|------|------|------|
| GET | `/api/account` | 프로필+잔액+설정 통합 | 세션 |
| GET | `/api/generations?service=&cursor=` | 내 생성내역 페이지네이션 | 세션, userId=본인 강제 |
| GET | `/api/generations/:id/download` | HQ 다운로드 (서명 URL) | 세션, 소유 검증 |
| DELETE | `/api/generations/:id` | 사진 삭제 (status=deleted + GCS 삭제) | 세션, 소유 검증 |
| PATCH | `/api/account/settings` | 언어·알림·동의 저장 | 세션 |
| GET | `/api/account/transactions?cursor=` | 거래 내역 (기존 원장 read) | 세션 |
| POST | `/api/account/delete` | 회원 탈퇴 (계정·데이터 삭제) | 세션 + 재확인 |

> 보안: 모든 `/api/generations*`·`/api/account*`는 verify-cookie 세션의 `userId`로만 접근. URL의 userId 파라미터 신뢰 금지(교차조회 차단 — 보안 페일클로즈 원칙).

## 5. 구축 로드맵 (Phase)

| 단계 | 범위 | 산출물 | 비고 |
|------|------|--------|------|
| **T0 (선결)** | 생성내역 인덱스 백필 + 저장 보강 | `saveImages()` → `generations` 동시 기록, 기존 GCS 객체 1회 백필 스크립트 | 화면 없이도 데이터부터 쌓기 시작 |
| **T1 (MVP)** | 마이페이지 셸 + 프로필 + 크레딧 잔액·거래내역 | `/account` 페이지, `/api/account`, `/api/account/transactions` | 기존 verify-cookie·credits 재사용 → 빠름 |
| **T2 (핵심)** | 생성 갤러리 + 다운로드 + 삭제 | 서비스 탭 그리드, `/api/generations*` | 사용자 체감 가치 최대 |
| **T3 (정리)** | 설정 저장 + GCS 30일 TTL 정책 + 회원 탈퇴 | `/api/account/settings`, 라이프사이클 룰, 탈퇴 플로우 | 법적/개인정보 마감 |

> T0가 빠지면 T2 갤러리에 표시할 과거 데이터가 없다. **T0를 화면보다 먼저** 착수하는 것이 본 기안의 핵심 권고.

## 6. 작가님·쌍아 결정 필요 사항

1. **라우트 명**: `/account` vs `/mypage` vs `/마이` — 본 기안은 `/account` 권고(영문 URL·SEO 무해). 확정 필요.
2. **GCS 보존기간**: "30일 자동 삭제"를 실제 정책으로 확정할지(법적 FAQ와 일치). 유료 사용자는 연장 보관 옵션을 둘지.
3. **백필 범위**: 기존 GCS 저장분을 전부 `generations`로 백필할지, 신규부터만 인덱싱할지.
4. **회원 탈퇴 시 데이터**: 즉시 완전삭제 vs 30일 유예(복구 가능). 개인정보 정책과 연동.
5. **본 기안 → 쌍아 설계서 토스 여부**: 경로③에 따라 작가님 확정 후 쌍아가 `DESIGN_20260624_마이페이지.md`로 정밀 설계.

## 7. 요약

- **갭의 본질**: 화면이 아니라 **인덱스**. `generations` 컬렉션 신설이 모든 것의 선결.
- **재사용 자산**: 인증·크레딧·결제·GCS 저장 전부 프로덕션 → 마이페이지는 "조립"에 가깝다.
- **확장 안전**: STYLER 진화선(서비스 무한 확장)·PARTNER 채널 분기·EVENT 출처 태깅·OPUS 동의를 데이터 모델이 막지 않도록 필드 예약.
- **권고 착수 순서**: **T0(인덱스) → T1(셸·크레딧) → T2(갤러리) → T3(설정·탈퇴)**.

> 다음 액션: 작가님 6개 결정사항 회신 → (확정 시) 쌍아 설계서 발행 → 막내 T0 착수.
