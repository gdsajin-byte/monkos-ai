## 2. Tailscale의 전략적 포지션

### 2.1 내부 인프라 — 지하 통신선

Tailscale은 OS보다 아래, 네트워크 레이어에서 모든 디바이스를 묶는다. 앱이 뭐가 깔려있든, OS가 무엇이든, 위치가 어디든 상관없이 밑바닥에서 하나로 연결된 상태.

이 지하 통신선 위에 Claude Code가 올라가면 어떤 디바이스에서든 동일한 개발 환경, 동일한 에이전트 접근, 동일한 코드베이스에 즉시 도달.

빅테크의 제약은 전부 그들의 레이어 위에서 작동하므로, 작가님의 tailnet 안에서는 원천적 통제권 확보.

### 2.2 대기업 인프라의 압축판

대기업이 수십억 들여서 구축하는 사내 네트워크(시스코 장비, VPN 게이트웨이, 방화벽, 전담 엔지니어)를 Tailscale이 소프트웨어 한 줄로 대체. 하드웨어 비대칭이 무의미해진 시대에 코드 몇 줄로 동등한 구조를 갖추는 것이 핵심.

### 2.3 고객향 서비스 레이어 (후술)

내부 도구에서 끝나지 않고, 고객에게 디바이스 간 직결 연동 경험을 제공하는 서비스 기반으로 확장.

## 3. 아이폰의 눈과 귀 — 서비스 설계

### 3.1 검증 완료 사항

증명사진 서비스에서 이미 검증됨:
- 고객 폰 카메라 → MONKOS 서버 → AI 처리 → 결과 반환
- Tailscale 없이도 공개 접점(monkos.ai)을 통해 파이프라인 작동 확인
- iOS 카메라 권한 등 OS 레벨 연동에 서비스적 장벽 없음

### 3.2 서비스 확장 방향

메인(monkos.ai) 챗봇 GUI를 기반으로 눈과 귀 기능 확장:

| 서비스 | 입력 | 처리 | 출력 |
|--------|------|------|------|
| 증명사진 | 카메라(셀피) | 배경 제거, 규격 맞춤, 보정 | 증명사진 이미지 |
| 패션 분석 | 카메라(거리 촬영) | 아이템 인식, 유사 검색 | 코디 제안, 구매 링크 |
| 헤어 분석 | 카메라(촬영) | 스타일 분류, 유사 추천 | 스타일 정보, 근처 미용실 |
| 음악 분석 | 마이크(주변 음악) | 곡 인식, 분위기 태깅 | 곡 정보, 플레이리스트 |
| 프레젠테이션 | 텍스트/이미지 입력 | 자동 구성, 디자인 | 프레젠테이션 파일 |

### 3.3 모듈러 아키텍처

apps 하위에 단위 컴포넌트 노드를 구성하고, 각 서비스가 필요한 노드를 조합:

```
monkos/
├── apps/                    # 컴포넌트 노드 (레고 블록)
│   ├── cam/                 # 카메라 입력
│   ├── mic/                 # 마이크 입력
│   ├── vision/              # 이미지 분석 엔진
│   ├── audio/               # 음성/음악 분석 엔진
│   ├── imagen/              # Imagen 4 생성 엔진
│   └── ...
├── services/                # 서비스 (노드 조합)
│   ├── photo-id/            # cam + vision + imagen
│   ├── fashion/             # cam + vision + 추천로직
│   ├── hair/                # cam + vision + 추천로직
│   ├── music/               # mic + audio
│   ├── presentation/        # 복합
│   └── ...
└── core/                    # 오케스트레이션
    ├── orchestrator/
    ├── auth/
    └── gateway/
```

기반은 이미 깔려있으며, 새 서비스 추가 시 기존 노드 조합으로 빠르게 구성 가능.

## 4. 디바이스 직결 — 고객 락인 전략

### 4.1 핵심 컨셉

작가님이 오늘 체험한 구조를 그대로 고객에게 제공:
- 작가님: Mac Mini + iMac + 4060 + iPhone → Tailscale → 하나의 환경
- 고객: 폰 + 노트북 → MONKOS 앱 → 하나의 AI 비서 환경

### 4.2 고객 경험 흐름

1. 폰에 MONKOS 앱 설치 (네이티브)
2. 노트북에 MONKOS 앱 설치 (네이티브)
3. 로그인하면 끝 — 두 디바이스 연결

폰에서 찍은 사진이 노트북 MONKOS에 즉시 반영되고, 노트북 작업 결과가 폰에서 바로 확인. Tailscale 기반 P2P 직결로 중간 서버 미경유.

### 4.3 크로스 플랫폼 차별화

- Apple: Apple 기기끼리만 연동 (AirDrop, Handoff)
- Samsung: Galaxy끼리만 연동
- **MONKOS: 어떤 조합이든** (iPhone + Windows, Android + Mac 등)
- 빅테크가 구조적으로 제공 불가한 크로스 플랫폼 디바이스 연동 + AI 파워

### 4.4 락인 철학

빅테크식 데이터 인질 락인이 아닌, **경험의 매끄러움으로 자발적으로 머무는 락인**. 한번 디바이스들이 MONKOS로 연결되면 그 편리함 때문에 떠나기 어려워지는 구조.

## 5. 로컬 모델 — 시스템 반도체

### 5.1 역할 정의

고객 디바이스에 탑재되는 튜닝된 경량 모델(3B/7B)은 범용 AI가 아닌 **시스템 반도체(ASIC)**:

- 범용 대화 처리 ✗
- 디바이스 간 라우팅 판단 ✓
- 입력 분류 및 모듈 호출 ✓
- 서버 전송 여부 판단 ✓
- 로컬 처리 가능 여부 판단 ✓

기능이 고정된 처리 봇. 창의적일 필요 없고 빠르고 정확하기만 하면 됨.

### 5.2 계층 구조

```
[고객 입력]
    ↓
[로컬 3B — 시스템 반도체]
 "증명사진 요청" → cam + vision + imagen 호출
 "서버 필요"     → Tailscale 타고 서버로
 "로컬 처리 가능" → 바로 결과 반환
 "노트북으로 전송" → 디바이스 간 라우팅
    ↓
[각 모듈 실행]
    ↓
[필요시] MONKOS 서버 — Gemini / Claude / Imagen 4
```

### 5.3 장점

- **오프라인 작동**: 인터넷 끊겨도 기본 기능 유지
- **API 비용 절감**: 단순 판단은 로컬, 무거운 처리만 서버
- **즉각 응답**: 서버 왕복 없는 로컬 처리로 체감 속도 향상

### 5.4 튜닝 인프라

| 장비 | 역할 |
|------|------|
| 5090 x4 클러스터 (예정) | 모델 튜닝 공장 — 파인튜닝, 실험 |
| 4060 | 추론 서버 + 3B 튜닝 테스트 |
| 고객 디바이스 | 배포된 경량 모델 추론만 |

4060에서 3B 파인튜닝, 7B 추론 검증 완료. 7B 파인튜닝은 5090 클러스터 도입 후 본격화.

### 5.5 핵심 IP

작가님이 MONKOS 서비스 구조와 라우팅 규칙에 특화 튜닝한 경량 모델 자체가 복제 불가능한 MONKOS 고유 자산.

## 8. 빅테크 비대칭 전략 — 벙커와 협업

### 8.1 원칙

빅테크 자원은 최대한 끌어쓰되, 동시에 벙커를 구축. 어느 하나가 빠져도 티가 나지 않는 구조에서 협업.

### 8.2 현 상태

- Google: 수천불 바우처 + Gemini Pro 1년 무료 확보, 그러나 종속 없음
- Anthropic: $200 Max 직결, 철학적 공감 있으나 감정적 종속 없음
- 벙커: Anthropic + Git + Cloudflare + Tailscale + 자체 GPU → 구글 없이도 작동
- 원칙: 합리적이면 스테이, 오버페이면 아웃. 더 나은 대안이 나오면 이동.

### 8.3 구조적 강점

빅테크는 경쟁자의 기술을 자기 파이프라인에 통합 불가. MONKOS는 중립적 오케스트레이터로서 각 빅테크의 최고 기술만 골라 쓰되 어디에도 묶이지 않는 포지션. 빅테크가 구조적으로 점유할 수 없는 자리.
