### 2.2 한송이 연구원 — 최적화된 파트너

**학력**
- 미용교육학 석사 → 교육 콘텐츠 설계 역량
- 향장 생물학 박사 과정 → 학술적 토대 + 연구 역량

**경력**
- 사진스튜디오 실무 → 촬영/조명/구도 현장 감각
- 헤어메이크업 실무 → K-뷰티 트렌드 + 기술 이해

**위임 영역**
- K-뷰티 에셋 확보 — 전문적 감각 기반 큐레이션
- 학술적 토대 — BWYA 학문 체계의 논문/연구 근거
- RLHF 휴먼 검수자 — AI 생성물 품질 피드백
- 전문적 태깅 — 헤어/메이크업 정밀 용어 체계
- 데이터 스키마 — K-뷰티 도메인 지식 기반 설계

### 3.1 BWYA 6대 학문 체계

**BWYA (Become Who You Are)**: 니체 철학에 기반한 AI 시대 크리에이터 양성 학문 체계

```
BWYA Academy
│
├── 제1학문: 사진학 (Photography)
│   └── 조명, 구도, 색감의 예술과 과학
│   └── Irving Penn, Peter Lindbergh, Dan Winters 레퍼런스
│
├── 제2학문: 패션학 (Fashion Studies)
│   └── 소재, 텍스처, 스타일링의 이해
│   └── 9-Grid 구성법, 란제리/언더웨어 표현
│
├── 제3학문: 헤어조형학 (Hair Design)
│   └── 볼륨, 컬러, 형태의 조형 원리
│   └── 에어리 룩, 허쉬, 보브앤슬릭 정밀 스타일링
│
├── 제4학문: 신체구조학/포즈론 (Body Semiotics)
│   └── 해부학 기반 포즈와 신체 언어
│   └── S-curve, 콘트라포스토, 다이나믹 플로우
│
├── 제5학문: AI 디렉팅학 (AI Directing)
│   └── Imagen, Midjourney, FLUX 활용법
│   └── 멀티모달 파이프라인 설계
│
└── 제6학문: 언어의 철학 (Philosophy of Language)
    └── 프롬프트 엔지니어링과 커뮤니케이션
```

**코퍼스 현황**: 48개 문서, 2,347 문단, 206,131자, 53개 프롬프트 태그

### 3.2 레이어드 아키텍팅: 패션

**핵심 인사이트**: "옷은 한 겹만 입는 것이 아니다"

```
일반 접근 (누구나 가능)
─────────────────────
"예쁜 블라우스 입은 한국 여성 모델"
          ↓
Generic한 "예쁜 옷" 결과
브랜드 코드 없음, 레이어 개념 없음
→ 실제 비즈니스에서 사용 불가

MONK 접근 (진입장벽)
─────────────────────
Layer 0: 이너웨어 (브라/팬티/슬립)
    ↓
Layer 1: 실크 캐미솔 (은은히 비침)
    ↓
Layer 2: 시스루 블라우스 (의도적 노출)
    ↓
Layer 3: 트위드 자켓 (구조감)
    ↓
= 콰이엇 럭셔리의 완성
```

**왜 이너웨어부터인가**
- 누구나 나노바나나로 "예쁜 모델"은 만들 수 있음
- 그러나 **브랜드 코드 + 히스토리 + 레이어 구조**를 소화하는 모델은 불가
- "예쁜 블라우스, 멋진 자켓" 수준 프롬프트로는 비즈니스 사용 불가
- 이너웨어(Layer 0)부터 완벽히 설계해야 레이어드 패션 아키텍팅 가능

### 3.3 레이어드 아키텍팅: 헤어

**헤어조형학 창설**: 같은 레이어드 논리 적용

```
일반 프롬프트
─────────────
"긴 머리 한국 여성" / "예쁜 헤어스타일"
          ↓
Generic한 머리카락 덩어리
볼륨감? 레이어? 텍스처? 전부 랜덤

MONK 헤어조형학
─────────────────
[Base] 두상 형태 + 피부톤 + 기반 헤어
    ↓
[Structure] 레이어드 컷 / 허쉬컷 / 태슬컷
    ↓
[Volume] 루트 볼륨 / 에어리 / 슬릭
    ↓
[Texture] 웨이브 / 스트레이트 / C컬
    ↓
[Color] 발레아쥬 / 옴브레 / 청담톤 / 쉐도우루트
    ↓
= 정교한 K-뷰티 헤어 스타일링 완성
```

## 4. 기술적 차별화

### 4.1 빅테크 세이프가드 정면돌파

**과제**: 오픈소스(SD)가 아닌 Gemini/Imagen 등 상용 모델로 정체성 유지 전신 이너웨어 생성

**발견**: Identity Preservation 90:10 비율 최적화

```javascript
// 성공의 비밀 (apps/monk-ai-studio-pro/backend/server.js)

model: 'gemini-3-pro-image-preview'  // AI Studio 모델
safety: BLOCK_NONE                    // 최소 제한

// IDENTITY_PRESERVATION 프롬프트
"CRITICAL INSTRUCTION: Maintain the exact facial features,
body proportions, skin tone, facial structure, eye shape,
nose, lips, and overall model identity. Preserve 90% identity
with 10% artistic freedom for style adaptation."
```

**핵심 인사이트**:
- 100% 동일 요구 시 오히려 세이프가드 발동 → 변형/거부
- 90% 정체성 보존 + 10% 보정 자유도 = 최적값 (실전 테스트 검증)
- 연령/성별 불문 이 비율 유지

### 4.2 K-뷰티 데이터 스키마

**BWYA 6개 학문 기반 자동 태깅 시스템**

| Layer | 카테고리 | 태깅 항목 |
|-------|---------|----------|
| Layer 1 (Face) | 헤어스타일 | style_name, length, texture, volume |
| | 헤어컬러 | base_color, highlight, tone, trend_name |
| | 피부질감 | skin_type, texture, finish |
| | 메이크업 | eye_style, lip_style, blush_style, brow_style |
| Layer 2 (Body) | 이너웨어 | type, material, coverage, color |
| | 패션룩 | style, silhouette, season, occasion |
| | K-뷰티 스타일 | aesthetic, vibe, reference |
| | 포즈 | pose_type, pose_mood, body_line |

**데이터베이스 스키마**:
- `soso_prompt_dictionary` — 프롬프트 태그 사전 (53개+)
- `soso_face_tags` — 헤어/메이크업 태깅
- `soso_body_tags` — 패션/바디 태깅
- `mina_model_instances` — AI 모델 인스턴스
- `mina_model_variants` — 모델 변형 이미지

## 6. ML 테스트 프로세스

### 6.1 연구 철학: 벤치마크 ❌ 직접 검증 ✅

```

• 벤치마크 좋다는 모델 4~5개 직접 테스트
• 실무 도입 가능성 직접 판단
• 모델별 장단점 비교분석 → 도입/탈락 결정
```

## 7. 인프라 전략

### 7.1 5090 도입 필요성

**현재 vs 목표**

| 항목 | 4060 (현재) | 5090 (목표) |
|------|-------------|-------------|
| VRAM | 8GB | 32GB |
| 파인튜닝 | 2B~3B | **7B~35B** |
| 추론 | 7B (양자화) | **70B+** |
| FLUX | ❌ OOM | ✅ 전체 튜닝 |
| 영상 모델 | ❌ | ✅ 진입 가능 |

**비즈니스 필수 논거**

```
현재 (테스트 단계)
─────────────────
소넷(Sonnet) 데몬으로 운용
우리 디바이스니까 가능 (Claude Max 구독)

실제 납품 (프랜차이즈 현장)
───────────────────────────
부스 100개 × Claude API 비용 = ???

[시나리오 A: API 납품]
• 부스당 월 $100~300 API 비용
• 100개 부스 = 월 $10,000~30,000
• 내가 다 내면서 납품? → 비즈니스 불가

[시나리오 B: 자체 모델 납품]
• 70B 파인튜닝 모델 → 부스에 배포
• API 비용 = $0
• 전기료 + 유지보수만

→ 5090 멀티 MLOps = 비즈니스 생존 조건
```
