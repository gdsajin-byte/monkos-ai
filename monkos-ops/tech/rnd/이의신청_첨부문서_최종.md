과제명: K-뷰티 전문가 지식 기반의 생성형 AI 룩북 제작 및 지능형 비주얼 큐레이션 서비스 플랫폼 개발

## 1. 이의신청 개요

### 1-1. 핵심 주장

본 이의신청은 서면평가 의견 8건 중 다수가 제안서의 내용을 명백히 잘못 해석한 평가임을 지적합니다.

■ 제안서에 "발색"이라는 단어가 단 한 번도 등장하지 않음에도 "발색 수치 구현의 정확성"을 평가하였습니다.
■ 제안서에 언급되지 않은 Adobe Firefly, Stitch Fix를 평가자가 독자적으로 추가하여 경쟁사로 비교하였습니다.
■ 연구장비(GPU)를 서비스 인프라로, 크롤링을 저작권 침해로, 도메인 전문 큐레이션을 편향으로 해석하는 등 기술 용어의 체계적 오독이 관통합니다.

본 이의는 평가 결과의 보완(재평가)이 아니라, 평가자의 명백한 해석 오류를 지적하고 대면 발표(시현)를 통해 실제 가동 중인 서비스를 보여줄 기회를 요청하는 것입니다.

### 1-2. 제안서 포맷의 구조적 제약

디딤돌 연구개발계획서는 본문1 기준 **20페이지 이내** 작성 제한이며, **초과 시 평가에 불이익이 발생할 수 있음**이 공고문에 명시되어 있습니다 (증거: 제출서류 안내문 캡처).

이 포맷 하에서 다음을 전제합니다:
- 사업화 전략은 최대 1페이지로 제한됩니다. "구체성이 미흡하다"는 지적은 포맷이 허용하지 않는 분량을 요구하는 것입니다.
- "크롤링 데이터의 저작권 수익 배분 방안"을 기술할 포맷/란이 제안서 양식에 존재하지 않습니다.
- 서면평가 배점표(100점)에 "저작권 수익 배분" 항목은 존재하지 않습니다.

### 1-3. K-뷰티 가점 미신청 확인

본 과제는 "디딤돌(첫걸음) 여성참여활성화 R&D" 트랙으로 신청하였으며, **K-뷰티 가점을 신청한 적이 없습니다.** 공고문의 K-뷰티 가점 분야는 "기능성 원료(화장품)" / "친환경 부자재(화장품용)"로 화장품 제조에 해당합니다. 본 연구자는 화장품을 제조하겠다는 논거를 제시한 바 없습니다.

제안서에서 사용한 "K-뷰티"는 헤어/패션/메이크업/포즈/디렉팅을 총괄하는 **한국적 비주얼 브랜딩 개념**이며, 서구 중심 생성 AI의 편향적 시각을 완화하고 동양인이 자연스럽게 생성되는 파이프라인에 대한 프롬프트 고도화를 "K-뷰티 도메인 큐레이팅"이라고 표현한 것입니다.

## 2. 지적사항별 상세 반론

### 2-1. 지적① "발색 수치 구현 정확성 미흡"

**평가등급**: 다소 미흡
**오류 유형**: 제안서에 존재하지 않는 연구과제를 평가

**[평가 원문]**
"뷰티 산업의 핵심은 미세한 발색과 피부 텍스처로 오픈소스 기반(SD, FLUX) 모델은 조명과 구도 최적화에는 우수하나, 특정 화장품의 실제 발색 수치 구현의 정확성 및 신뢰성을 확보하기 위한 방안의 제시가 다소 미흡함"

**[제안서 원문 대조]**

| 검색어 | 제안서 등장 횟수 |
|:---|:---|
| "발색" | **0회** |
| "화장품" | **0회** |
| "정체성" | **6회** (1-1항 제목부터 등장) |

- 제안서 1-1항 원문: "AI 이미지 **정체성 유지율** 90% 달성, 외부 API 의존율 50% 이하로 기술 자립화"
- 검증방법 테이블: "정체성유지율 | 원본 vs 생성 모델 유사도 측정 | 90% 이상"

**[반론]**
제안서의 핵심 연구과제는 "인물 정체성 유지"이지 "화장품 발색 구현"이 아닙니다. 평가자는 "뷰티 산업 = 화장품"이라는 전제를 깔았으나, 본 연구에서 "K-뷰티"는 헤어/패션/메이크업/포즈/디렉팅을 총괄하는 한국적 비주얼 브랜딩 개념입니다. 연구책임자는 인물사진 촬영업 10년 이상 경력의 스튜디오 대표이며, 연구원은 헤어메이크업 실무 7년/미용교육학 석사/향장생물학 박사과정의 도메인 전문가입니다.

또한 본 과제는 K-뷰티 가점을 신청하지 않았으며(1-3항 참조), 화장품을 제조하겠다는 논거를 제시한 바 없습니다. "K-뷰티 = 화장품 발색"이라는 해석은 제안서 본문을 읽었다면 도달할 수 없는 결론입니다.

**[인정할 점]**
"K-뷰티"라는 과제명이 화장품으로 오독될 여지를 준 표현의 한계는 인정합니다.

### 2-2. 지적⑥ "Adobe Firefly, Runway, Stitch Fix 등 글로벌 기업 대비 경쟁력 부족"

**평가등급**: 다소 미흡
**오류 유형**: 비교 대상 오류(범주 오류)

**[평가 원문]**
"기존의 Adobe(Firefly), Runway, Stitch Fix 등 글로벌 거대 기업들이 유사한 기능을 상용화하고 있는 상태에서 K-뷰티 특화라는 점만으로 경쟁력을 갖추기에는 부족하다고 판단됨"

**[제안서 원문 대조]**
- Adobe 등장 횟수: **0회**
- Stitch Fix 등장 횟수: **0회**
- Runway 등장 횟수: **1회** — "외산 AI SaaS(Midjourney, Runway 등) 의존 → 내부 엔진 대체" (경쟁이 아닌 탈피 대상)

**[반론]**
본 연구자는 Adobe, Runway, Stitch Fix를 경쟁자로 상정한 적이 없습니다. 평가자가 이 3개 기업을 독자적으로 추가한 것은 **제안서 외부 정보로 평가**한 것입니다.

- Adobe Firefly: B2B 크리에이티브 도구 (연매출 $19.4B) — 증명사진 서비스 없음
- Runway: AI 영상 생성 플랫폼 (기업가치 $5.3B) — 정지 이미지 증명사진과 무관
- Stitch Fix: AI 의류 추천 커머스 — 이미지 생성이 아닌 의류 판매

이 세 기업은 본 과제와 시장/고객/가치제안이 전혀 겹치지 않습니다. Google, AWS, OpenAI 등 빅테크는 훌륭한 엔진을 제공하는 **공급업체**입니다. 본 연구자는 모든 서비스 엔진을 자체 제작하였으며, 그 위에 그 시점 가장 탁월한 AI 모델을 선택하여 구동하는 구조입니다.

이 논리대로라면 디딤돌 통과 과제들은 **빅테크 AI가 전혀 할 수 없는 영역**만 개발한 연구자를 선정했다는 의미입니다. 음악, 법률, 의료, 디자인, 산업설계 — 대형 글로벌 기업의 AI가 다루지 않는 영역이 있는지 묻고 싶습니다.

### 2-3. 지적② "로컬 GPU(RTX 5090) 처리 속도 유지 방안 부족"

**평가등급**: 다소 미흡
**오류 유형**: 연구장비를 서비스 인프라로 오독

**[평가 원문]**
"로컬 GPU(RTX 5090)를 활용해 의존도를 50% 이하로 낮추겠다고 제시하였으나, 최신 모델(FLUX 등)의 연산 요구량을 고려할 때 다수 사용자가 몰리는 플랫폼 환경에서 로컬 서버만으로 처리 속도(10초 이하)를 유지하기 위한 구체적 방안의 제시가 다소 부족함"

**[제안서 원문 대조]**
- 제안서 연구계획: "3단계 | 하이브리드 파이프라인 구축 (Cloud API + Local 5090x2) | 4~7월"
- 제안서 검증방법: "API 의존율 | 월간 API 호출 비율 모니터링 | 50% 이하"

**[반론]**
평가자는 GPU를 "연산 속도를 위한 서비스 서버"로 전제하였으나, AI 개발에서 GPU의 최우선 스펙은 연산 속도가 아닌 **VRAM 적재량**입니다.

API 의존율 50% 목표는 단순 비용 절감이 아닌 3중 전략입니다:
1. **자체 모델 고도화**: 오픈소스 MLOps 과정을 통한 K-뷰티 특화 모델 내재화
2. **서비스 정지 리스크 방어**: API 100% 의존 시 공급자 정책 변경으로 서비스 전체 정지 가능
3. **기술 추격 — 소형화 대비**: 실사 이미지 생성이 빠르게 소형화되는 추세. "실사인지 여부" 자체가 경쟁력이 아닌 시점이 오면 자체 모델로 대체/보완할 수 있는 기반 확보

5090은 3단계(4~7월)에 도입, 4단계에 파인튜닝으로 배치되어 있습니다. 서비스 인프라였다면 서비스 개시 전(1단계)에 구축되어야 하나, 연구 후반부에 배치된 것은 **연구장비임을 단계표 자체가 증명**합니다.

**[실증 데이터] RTX 4060(현 보유) vs RTX 5090(도입 목표)**

본 연구자는 RTX 4060(8GB VRAM) 환경에서 3개월간 28종 AI 모델을 대상으로 벤치마크를 실시하였습니다:

- FLUX.1-dev(차세대 이미지 생성 표준): 12GB 필요 → 4060(8GB) **실행 불가** → 5090(32GB) 해소
- 7B QLoRA 파인튜닝: 5GB/8GB로 불안정 → 5090에서 안정적 여유
- 멀티모델 동시 서빙: 8GB 벽 → 5090(32GB) 해소
- 서구권 학습 데이터 기반 모델은 'Korean' 프롬프트를 추가해도 K-Beauty 피부 표현에 한계 → **자체 LoRA 파인튜닝의 필요성 실증**

▶ 증거: RTX 4060 벤치마크 28종 모델 실측 데이터, GCP 과금 내역 캡처

**[인정할 점]**
"GPU = 연구장비"라는 명시가 약했고, "하이브리드"라는 표현이 서비스 분산으로 오독될 여지를 주었습니다.

### 2-4. 지적⑦ "고해상도 4K/300dpi 운영 비용과 소상공인 대상 저비용 서비스 간 모순"

**평가등급**: 다소 미흡

**[평가 원문]**
"고해상도 4K/300dpi 및 정밀 큐레이션은 운영 비용이 클 것으로 예상되며, 소상공인을 대상으로 하는 B2B의 경우 고품질, 저비용을 만족시킬 수 있는 방안의 제시가 부족함"

**[반론]**
1-2항(고해상도)과 1-4항(저비용 챗봇)은 서로 다른 연구과제이자 서로 다른 상품 라인입니다.

제안서 작성 시점(25.12) 생성AI 출력이 1024×1024에 머물러 있었습니다. 상업용 사진을 업으로 하는 연구자에게 그 정도 해상도는 부족하여, 독자적 **9그리드 프로세스**(1MB급 모듈 9개 분위로 ~10MB급 상업용 사진 품질 실현)를 연구하였습니다. 그러나 비슷한 시기, 현재 주 엔진으로 사용하는 모델은 2K 화질 기준 불과 400~700KB의 용량으로 디스플레이상 충분한 화질이 나옵니다.

**현 시점 실측 원가:**
- 1회 서비스 원가: **$0.04**
- 판매가: **$10**
- 마진율: **99.6%**

"고해상도 = 비용 과다"라는 우려는 기술 진화를 반영하지 못한 정적 시각입니다. 적어도 고해상도 서비스라서 단가가 걱정이라는 것은 스튜디오 경력 10년차인 본 연구자에게는 과한 우려입니다.

▶ 증거: GCP 과금 내역 캡처, 원가 실측 데이터

제안서에서 9그리드 업스케일 솔루션이 대표 연구과제처럼 표현된 점은 인정합니다.

**평가등급**: **미흡** (8건 중 유일한 최하 등급)

"학습 데이터 크롤링 과정에서 전문가 지식과 이미지를 활용할 때, 원저작권자와의 수익 배분이나 권리 관계가 명확하지 않을 경우 법적 분쟁의 소지가 있을 것으로 예상되며, 이에 대한 대책의 제시가 미흡함"

**[반론]**
1) 크롤링은 데이터 수집의 **일반명사**입니다. 네이버 검색 API 명칭 자체가 "크롤러"이며, Google/네이버 모두 크롤링 기반 기업입니다. 크롤링이라는 단어 자체를 범죄·해킹·지적재산 침탈과 동일시하는 것은 협의적 시각입니다.

2) 본 과제의 참고 데이터는 모두 **공식 오픈 API 경유 오픈 이미지 소스**입니다. 10년 넘게 스튜디오를 운영하며 레퍼런스 이미지를 연구했으나 단 한 차례도 관련 문제가 발생하지 않았고, 그럴 이유도 없습니다. 스스로를 크롤러에게 노출시키고자 하는 데이터의 양만으로도 원하는 데이터를 충분히 수집할 수 있습니다.

### 2-6. 지적③ "전문가 집단 취향 편향이 대중적 K-뷰티 트렌드와 괴리될 우려"

**평가등급**: 다소 미흡
**오류 유형**: AI 학습 표준 방법론(RLHF)에 대한 이해 부족

**[평가 원문]**
"전문가 피드백 루프를 통해 진화하는 구조는 이상적이지만, 특정 전문가 집단의 취향이 반영된 데이터 편향이 발생할 경우 대중적인 K-뷰티 트렌드와의 괴리를 극복할 방안이 필요함"

**[반론]**
본 과제는 글로벌 표준 범용 AI 모델을 개발하는 것이 아닙니다. 연구 과정(크롤링 → 프롬프트 설계 → AI 자체 검수 → 도메인 전문가 코멘트 → 생성물 판단 → 재학습)의 반복을 통해 생성 결과물이 목표치에 수렴하는 구조입니다.

1) **"편향"이라 하려면 절대적 기준이 필요합니다.** 뷰티 영역에서 그 글로벌 표준 정답은 부재합니다. 사진관 10년 + 뷰티실무 7년 + 미용교육학 석사 + 향장생물학 박사과정의 전문성을 "편향"이라 하면, 샤넬의 독특한 감각도 프랑스 어느 디자이너의 취향이 반영된 편향이 됩니다.

2) **RLHF는 글로벌 AI 표준 학습 방식입니다.** Google, OpenAI 등 모든 빅테크가 채택하고 있습니다. 전문가 피드백을 편향이 아닌 "검증"으로 보는 것이 AI 산업의 보편적 관점입니다.

3) **평가자가 요구한 "트렌드와의 괴리 극복 방안"은 본 과제의 자가 진화 파이프라인 자체입니다.** 지속적인 트렌드 크롤링 → 프롬프트 주입 → AI 자체 검수 → 전문가 코멘트 → 재학습의 반복 패턴이 이미 제안서에 기술되어 있습니다. 한번 굳힌 "편향"이 아니라 영속적인 연구와 개선을 전제하는 구조입니다.

4) **만약 모든 AI가 참조해야 할 "정답" 데이터셋이 실재한다면, 전 세계 모든 AI는 동일한 결과물을 생성하게 되고, 비즈니스는 브랜드를 상실합니다.** 목표치에 수렴하는 연구 과정을 "편향"이라 해석하는 것은 AI 서비스의 브랜딩 자체를 부정하는 논리입니다.

**[인정할 점]**
편향 우려 자체는 학술적으로 유효할 수 있습니다. 그러나 본 과제는 범용 AI가 아닌 도메인 특화 서비스이며, 브랜딩은 본질적으로 "선택된 관점"입니다.

## 3. 평가의 구조적 문제

### 3-1. "K-뷰티 = 화장품"이라는 협의적 해석의 관통

8건의 지적 전반에 K-뷰티 = 화장품이라는 협의적 해석이 관통합니다. 지적①에서 "발색 수치", 지적③에서 "화장품 취향 편향", 지적⑥에서 "Adobe/Stitch Fix 비교". 본 연구자가 사용한 "K-뷰티"는 한국적 매력/동양적 매력을 통괄하는 비주얼 브랜딩 개념이며, K-뷰티 가점을 신청한 적도 없습니다.

### 3-2. 이율배반적 지적 구조

- 지적④: "Google API만 쓰잖아, 자체 기술이 뭐냐" (API 의존 비판)
- 지적②: "5090 왜 필요해, 현실성 없다" (GPU 자립화 비판)

API만 쓰면 "기술자립 없다", 로컬 GPU로 내재화하면 "필요성 부족". 제안자에게 **해법 자체를 부정**한 구조입니다.

### 3-3. 평가 프레임의 연쇄적 전환

기술을 말하면 "학술적 검증이 부족", 차별화를 말하면 "빅테크를 이길 수 없다", 비전을 말하면 "사업성이 구체적이지 않다", 사업성을 말하면 "비용 구조가 모순", 비용을 절감하겠다면 "GPU가 왜 필요", 자립하겠다면 "API 의존인데 자체 기술이 뭐냐". 어떤 답을 제시해도 다음 프레임으로 비틀어 비판하는 구조입니다.

### 3-4. 지적사항과 제안서 파트의 연계 불명확

각 지적사항이 제안서의 어느 파트를 평가한 것인지 특정할 수 없습니다. 전체 맥락에 대한 이해 없이 키워드 단위로 분리하여 지적한 수준의 평가입니다.
