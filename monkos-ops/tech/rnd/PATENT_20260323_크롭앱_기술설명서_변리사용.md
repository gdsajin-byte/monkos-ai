# MONKOS 크롭앱 — 특허 검토용 기술 설명서

**작성일**: 2026-03-23
**작성**: MONKOS AI (Monk Studio)
**대상**: 변리사 사무소 검토용
**서비스 URL**: https://monkos.ai/crop

---

## 1. 발명의 명칭 (안)

**AI 얼굴 랜드마크 기반 국제 규격 자동 대응 증명사진 크롭 시스템 및 방법**

---

## 2. 기술 분야

본 발명은 AI 얼굴 인식(MediaPipe FaceMesh 478점 메쉬)을 활용하여, 사용자가 업로드한 사진에서 얼굴 랜드마크를 추출하고, 국가별·용도별 증명사진 규격(ICAO 여권, 반명함 등)에 자동으로 대응하는 크롭 영역을 산출하며, 규격 적합성을 실시간 판정하는 **완전 클라이언트 기반** 이미지 처리 시스템에 관한 것이다.

---

## 3. 해결하고자 하는 과제

### 3-1. 종래 기술의 문제점

**(1) 규격 복잡성**: 증명사진 규격은 국가·용도마다 상이하다. 한국 여권(35×45mm, ICAO 9303), 반명함(30×40mm), 미국 여권(2×2인치), 일본 여권(35×45mm) 등 출력 크기·얼굴 비율·여백 기준이 모두 다르다. 일반 사용자가 이를 정확히 충족하기 어렵다.

**(2) 서버 전송 필수**: 기존 온라인 크롭 서비스는 사진을 서버에 업로드하여 처리한다. 증명사진에는 안면 정보가 포함되어 개인정보 유출 우려가 있다.

**(3) 정수리 인식 불가**: AI 얼굴 인식 기술(FaceMesh 등)은 이마까지는 인식하지만, 두정부(정수리)를 직접 감지하지 못한다. 그러나 증명사진 규격은 정수리~턱 끝 거리를 기준으로 얼굴 크기를 정의한다.

**(4) 사후 판정**: 기존 도구는 크롭 결과물을 생성한 후에야 규격 적합 여부를 확인할 수 있다. 조정 과정에서 실시간 피드백이 없어 시행착오를 반복해야 한다.

### 3-2. 본 발명의 해결책

- **양안대칭 정수리 추정 알고리즘**: 눈 중심~턱 거리를 상방 반전하여 정수리 위치를 산출한다.
- **완전 클라이언트 처리**: AI 모델 로드부터 크롭·다운로드까지 모든 과정이 브라우저 내에서 완결되어 사진이 서버로 전송되지 않는다.
- **실시간 3단계 적합성 판정**: 크롭 영역 조정 즉시 적합(녹)/허용(황)/부적합(적) 피드백을 제공한다.
- **규격 DB 기반 자동 대응**: 규격 데이터만 추가하면 알고리즘 변경 없이 신규 국가·용도에 대응 가능하다.

## 4. 시스템 구성

### 4-1. 전체 동작 흐름

```
[1단계: 입력]
    사용자 → 사진 업로드 (File API / sessionStorage)
    사용자 → 규격 선택 (여권/신분증 탭, 반명함 탭)

[2단계: AI 얼굴 분석]
    MediaPipe FaceMesh (CDN → 브라우저 내 실행)
    → 478개 랜드마크 추출 (정규화 좌표 0~1)
    → 핵심 5점 선별: 좌동공(159), 우동공(386), 턱(152), 좌볼(234), 우볼(454)
    → 정수리 산출 (양안대칭 알고리즘)
    → 얼굴 윤곽 8점 보간 (볼·턱·정수리 4개 모퉁이)

[3단계: 크롭 영역 자동 배치]
    규격 DB에서 목표 얼굴 크기(mm) 조회
    → 배율(imgScale) 산출: 목표 얼굴 px / 실측 얼굴 px
    → 수직 앵커링: 눈 위치를 프레임 높이의 43% 지점에 배치
    → 수평 앵커링: 양안 중심을 프레임 중앙에 배치
    → 모든 랜드마크를 프레임 좌표로 변환

[4단계: 실시간 프리뷰 + 적합성 판정]
    SVG 오버레이: 정수리선, 턱선, 눈 위치선, 스플라인 윤곽, 치수선
    수치 패널: 상단 여백(mm), 얼굴 크기(mm), 하단 여백(mm), 눈 위치(%)
    3단계 색상 판정: 적합(녹) / 허용(황) / 부적합(적)
    ICAO 범위 바: 얼굴 크기가 허용 구간 내 어디인지 시각화

[5단계: 수동 미세 조정]
    정수리 핀(↕): 정수리 위치 수직 드래그
    이동 핸들(✋): 사진 전체 평행 이동
    확대/축소 핸들(⤢): 사진 배율 조절
    → 조정 즉시 [4단계] 재계산·재렌더링

[6단계: 다운로드]
    Canvas API로 CSS transform 재현 → JPEG 300dpi 출력
    파일명: MONKOS_crop_{규격}_{W}x{H}.jpg
    서버 전송 없이 Blob → 로컬 다운로드
```

### 4-2. 규격 데이터베이스 (확장 가능)

```javascript
// 현재 탑재 규격
passport: {
  wMm: 35, hMm: 45,           // 출력 크기 (mm)
  pxW: 413, pxH: 531,          // 출력 크기 (px, 300dpi 기준)
  faceMin: 32, faceMax: 36,    // ICAO 얼굴 크기 허용 범위 (mm)
  faceTarget: 34,              // 최적 얼굴 크기 (mm)
  topDefault: 5, bottomDefault: 6  // 기본 여백 (mm)
}

id (반명함): {
  wMm: 30, hMm: 40,
  pxW: 354, pxH: 472,
  faceMin: 24, faceMax: 32,
  faceTarget: 28,
  topDefault: 4, bottomDefault: 5
}
```

규격 추가 시 위 형태의 데이터 객체만 추가하면 크롭 알고리즘·UI가 자동 대응한다. 미국(2×2인치), 중국(33×48mm), EU 각국 등 국제 확장이 데이터 추가만으로 가능하다.

## 5. 핵심 발명 — 양안대칭 정수리 추정 알고리즘

### 5-1. 과제

MediaPipe FaceMesh는 478개 얼굴 랜드마크를 제공하지만, 이마 상단까지만 커버하며 두정부(정수리)는 감지하지 못한다. ICAO 9303 등 증명사진 규격은 **정수리~턱 끝 거리**로 얼굴 크기를 정의하므로, 정수리 위치를 추정하는 방법이 필요하다.

### 5-2. 해결 — 눈-턱 거리의 상방 반전

인체 해부학적 비례에 따라, 정면에서 본 얼굴의 눈 중심~정수리 거리는 눈 중심~턱 끝 거리와 근사적으로 동일하다(양안대칭 원리).

```
정수리_Y = 눈_중심_Y − (턱_Y − 눈_중심_Y)
```

**코드 구현** (crop.js:704~707):
```javascript
const eyeCenterY = (leftPupil.y + rightPupil.y) / 2;
const crownY = eyeCenterY - (chin.y - eyeCenterY);
const crown = { x: eyeCenterX, y: crownY };
```

### 5-3. 종래 기술과의 차이

| 항목 | 종래 기술 | 본 발명 |
|------|-----------|---------|
| 정수리 인식 | 이마 최상단 랜드마크를 정수리로 간주 | 눈-턱 거리의 상방 반전으로 정수리 추정 |
| 헤어스타일 영향 | 이마 가림·긴 앞머리 시 오차 큼 | 눈·턱만 인식하면 되므로 영향 최소 |
| 모자/히잡 착용 | 이마 인식 불가로 실패 | 눈·턱 인식 가능하면 정상 동작 |
| 필요 랜드마크 | 이마 상단 포함 다수 | 양 동공(2점) + 턱(1점) — 최소 3점 |

### 5-4. 사용자 보정 기능

AI가 추정한 정수리 위치가 부정확할 경우, 사용자가 **정수리 핀(↕)**을 수직 드래그하여 미세 조정할 수 있다. 조정 즉시 얼굴 크기(mm)·여백·적합성이 재계산된다.

## 6. 핵심 발명 — 규격 자동 배치(autoPlace) 알고리즘

### 6-1. 목적

AI가 추출한 얼굴 랜드마크를 기반으로, 선택된 규격에 최적화된 크롭 영역을 **자동으로** 산출한다.

### 6-2. 알고리즘 (crop.js:731~780)

**입력**: 얼굴 랜드마크(이미지 픽셀 좌표), 이미지 원본 해상도(natW×natH)
**출력**: 크롭 배율(imgScale), 사진 위치(imgPos), 프레임 내 랜드마크 좌표

```
Step 1: Cover 스케일 계산
   coverScale = max(프레임폭/이미지폭, 프레임높이/이미지높이)
   → CSS object-fit: cover와 동일한 이미지 맵핑

Step 2: 얼굴 크기 맞춤
   목표 얼굴 px = 규격.faceTarget(mm) × MM(px/mm)
   imgScale = 목표 얼굴 px / 실측 얼굴 px(cover 좌표 기준)

Step 3: 눈 위치 앵커링
   imgPos.y = 0.43 × 프레임높이 − 프레임중심 − (눈_cover_y − 프레임중심) × imgScale
   → 눈이 프레임 높이의 43% 지점에 오도록 수직 배치

Step 4: 좌우 중앙 정렬
   imgPos.x = −(양안중심_cover_x − 프레임중심) × imgScale
   → 양안 중심이 프레임 수평 중앙에 오도록 배치

Step 5: 전체 랜드마크 좌표 변환
   각 랜드마크 = 프레임중심 + (cover좌표 − 프레임중심) × imgScale + imgPos
```

### 6-3. 규격 전환 시 재배치

사용자가 규격 탭(여권 ↔ 반명함)을 전환하면, 마지막으로 감지된 랜드마크 데이터(`lastDetectedLandmarks`)를 기반으로 autoPlace를 재실행한다. 사진 재업로드나 AI 재분석 없이 즉시 새 규격에 맞게 재배치된다.

## 7. 핵심 발명 — 실시간 3단계 적합성 판정

### 7-1. 판정 기준

**여권/신분증 모드** (ICAO 준수):

| 판정 항목 | 적합 (녹) | 허용 (황) | 부적합 (적) |
|-----------|-----------|-----------|-------------|
| **얼굴 크기** | 33~35mm | 32~36mm (ICAO) | <32mm 또는 >36mm |
| **눈 위치** | 43~45% | 40~48% | <40% 또는 >48% |
| **좌우 중심** | <1mm 이탈 | 1~2mm 이탈 | >2mm 이탈 |
| **상단 여백** | ≥3mm | — | <3mm |

**반명함 모드** (간소화 판정):
- 좌우 중심 2mm 초과 이탈 시 경고
- 정수리 여백 2mm 미만 시 경고
- 얼굴 비중 50% 미만 시 경고

### 7-2. 다운로드 차단 로직

여권/신분증 모드에서 얼굴 크기가 ICAO 범위(32~36mm)를 벗어나거나, 눈 위치가 허용 범위(40~48%)를 벗어나면 **다운로드 버튼이 비활성화**된다. 부적합 사유가 화면에 구체적으로 표시되며, 사용자에게 조정 방향을 안내한다.

### 7-3. ICAO 범위 바

프레임 하단에 진행 바(progress bar)를 표시한다. 허용 범위(32~36mm)가 초록 구간으로 표시되고, 현재 얼굴 크기가 점(dot)으로 표시된다. 사용자가 핀이나 스케일을 조정하면 점이 실시간으로 이동하여 현재 위치를 직관적으로 파악할 수 있다.

## 8. SVG 오버레이 — 얼굴 윤곽 스플라인 렌더링

### 8-1. 구성

프레임 위에 SVG 레이어를 겹쳐 다음 요소를 실시간 렌더링한다:

| SVG 요소 | 역할 |
|----------|------|
| **상단/하단 마스크** | 정수리 위·턱 아래 반투명 처리 (크롭 외 영역 표시) |
| **정수리선** (수평) | 정수리 위치, 적합성 색상 적용 |
| **턱선** (수평) | 턱 위치, 금색 고정 |
| **눈 위치선** (수평) | 양안 중심 높이, 적합성 색상 적용 |
| **중심선** (수직) | 프레임 중앙, 좌우 이탈도에 따라 녹/황/적 색상 변환 |
| **스플라인 윤곽** | 정수리→우볼→턱→좌볼 4점 + 모퉁이 4점 = 8점 베지어 곡선 |
| **치수선** (우측) | 정수리~턱 거리 표시 |
| **동공 포인트** | 좌·우 동공 위치 원형 마커 |
| **텍스트 라벨** | 정수리/턱끝/눈 위치(%) 수치 표시 |

### 8-2. 스플라인 얼굴 윤곽

8개 랜드마크(정수리, 좌볼, 우볼, 턱, 4개 모퉁이)를 3차 베지어 곡선(Cubic Bezier)으로 연결하여 부드러운 얼굴 윤곽을 그린다. 모퉁이 4점은 볼·턱·정수리 좌표에서 보간 생성한다.

```javascript
// 모퉁이 보간 예시 (crop.js:710~725)
tlCorner = {
  x: leftCheek.x + (crown.x - leftCheek.x) × 0.3,
  y: crown.y + (leftCheek.y - crown.y) × 0.4
}
```

## 9. Canvas 크롭 출력 — CSS Transform 재현

### 9-1. 과제

프레임 내 사진은 CSS `transform: translate() scale()`과 `object-fit: cover`로 표시된다. 다운로드 시 이 시각적 결과를 Canvas API로 정확히 재현해야 한다.

### 9-2. 구현 (crop.js:852~891)

```javascript
// 1. 출력 해상도 스케일 (프레임 → 규격 px)
const outScale = spec.pxH / FH;    // 예: 531 / 400 = 1.3275
ctx.scale(outScale, outScale);

// 2. CSS transform 재현
ctx.translate(FW/2 + imgPos.x, FH/2 + imgPos.y);  // 사진 중심 이동
ctx.scale(imgScale, imgScale);                     // 사용자 배율 적용
ctx.translate(-FW/2, -FH/2);                       // 원점 복원

// 3. object-fit: cover 재현
const coverScale = Math.max(FW/natW, FH/natH);
const dw = natW × coverScale, dh = natH × coverScale;
ctx.drawImage(img, (FW-dw)/2, (FH-dh)/2, dw, dh);

// 4. JPEG 출력 (품질 95%, 300dpi)
canvas.toBlob(blob => { /* Blob 다운로드 */ }, 'image/jpeg', 0.95);
```

출력 파일명: `MONKOS_crop_{passport/id}_{413x531/354x472}.jpg`

## 10. 완전 클라이언트 처리 — 개인정보 보호 설계

| 처리 단계 | 실행 위치 | 서버 전송 |
|-----------|-----------|-----------|
| 사진 로드 | 브라우저 File API | **없음** |
| AI 얼굴 분석 | 브라우저 내 MediaPipe (CDN 모델 로드) | **없음** (모델만 CDN 캐시) |
| 크롭 계산 | 브라우저 JavaScript | **없음** |
| 프리뷰 렌더링 | 브라우저 SVG + CSS | **없음** |
| JPEG 생성 | 브라우저 Canvas API | **없음** |
| 다운로드 | 브라우저 Blob URL | **없음** |

사용자의 안면 사진이 네트워크를 통해 외부로 전송되는 구간이 **일체 없다**. AI 모델 파일은 CDN에서 1회 다운로드 후 브라우저 캐시에 저장되며, 이후 오프라인에서도 동작 가능하다.

## 11. 사용자 인터랙션 설계

### 11-1. 핀 & 핸들 조작 체계

| 조작 요소 | 기능 | 드래그 방향 | 커서 |
|-----------|------|-------------|------|
| **정수리 핀 (↕)** | AI 추정 정수리 위치 미세 조정 | 수직만 | ns-resize |
| **턱 핀 (◯)** | 턱 위치 시각적 참조 | 조작 불가 (표시 전용) | — |
| **이동 핸들 (✋)** | 사진 전체 평행 이동 | 자유 | grab → grabbing |
| **확대/축소 핸들 (⤢)** | 사진 배율 조절 (0.3x~4x) | 대각선 | nwse-resize |

### 11-2. 스케일 조작 시 중심 보존

확대/축소 시 사진의 시각적 중심(imgPos 반영)을 기준으로 스케일링하여, 얼굴이 프레임 밖으로 밀려나지 않도록 한다. 모든 랜드마크 좌표도 동일한 비율로 변환된다.

### 11-3. 미리보기 모드

"미리보기" 버튼을 **누르고 있는 동안** SVG 오버레이·핀·핸들·배지가 모두 숨겨져 최종 크롭 결과만 확인할 수 있다. 버튼에서 손을 떼면 가이드가 복원된다.

### 11-4. 터치 최적화

Pointer Events API를 사용하여 마우스·터치·스타일러스를 통합 처리한다. 모바일 환경에서 viewport 고정(`user-scalable=no`)과 `apple-mobile-web-app-capable` 설정으로 네이티브 앱과 유사한 전체 화면 경험을 제공한다.

## 13. 종래 기술 대비 차별점 종합

| 항목 | 종래 크롭 서비스 | 본 발명 |
|------|-----------------|---------|
| **처리 위치** | 서버 업로드 필수 | 완전 클라이언트 (서버 전송 제로) |
| **정수리 인식** | 이마 랜드마크 기반 (오차·헤어 영향 큼) | 양안대칭 반전 알고리즘 (눈·턱 3점 최소) |
| **규격 대응** | 단일 규격 또는 사용자 수동 입력 | 규격 DB 자동 대응 + 데이터 추가로 국제 확장 |
| **자동 배치** | 없음 (수동 크롭) | AI 분석 → 규격별 최적 배치 자동 산출 |
| **규격 전환** | 사진 재업로드 필요 | 랜드마크 캐시로 즉시 재배치 |
| **적합성 판정** | 사후 확인 | 실시간 3단계 (적합/허용/부적합) + 다운로드 차단 |
| **시각 피드백** | 크롭 프레임만 표시 | SVG 8점 스플라인 윤곽 + 치수선 + 범위 바 + 수치 패널 |
| **출력 품질** | 해상도 미보장 | 300dpi 고정 출력 (사진관 인쇄 품질) |
| **개인정보** | 서버 저장 리스크 | 완전 클라이언트 (제로 전송) |

## 14. 기대 효과

1. **접근성**: 브라우저만 있으면 누구나 무료로 국제 규격 증명사진 크롭 가능
2. **정확성**: AI 얼굴 인식 + 양안대칭 정수리 추정 + 규격 DB 자동 대응으로 ICAO 국제 규격 자동 준수
3. **안전성**: 안면 사진이 서버로 전송되지 않아 개인정보 유출 원천 차단
4. **즉시성**: 규격 전환 시 AI 재분석 없이 캐시된 랜드마크로 즉시 재배치
5. **확장성**: 규격 데이터 객체 추가만으로 신규 국가·용도 즉시 대응 (알고리즘 변경 불필요)
6. **경제성**: 사진관 방문·유료 서비스 비용 절감
