## 2. 프레임워크 — 재사용 자산 3층

### Layer 1 — 디자인 토큰 (정본: `public/css/portal.css :root`)

- **현황**: 이미 부분 존재 (`--bg #FAFAF8`, `--ink` 5단계). → *추출이 아니라 정비·확장*.
- **할 일**: 토큰을 한 블록으로 정규화 + 누락분 신설(브랜드/서메이스/radius/shadow/타이포).
- **원칙**: 모든 서비스 CSS가 이 `:root`를 **단일 정본**으로 참조. 하드코딩 색상값 금지.

```css
:root {
  /* Brand */    --brand: #6c4fff; --teal: #00c9a7; --coral: #ff6b6b; --gold: #ffc940;
  /* Surface */  --bg: #FAFAF8; --surface: #fff;
  /* Ink */      --ink: #1A1A18; --ink-s/m/l/xl: …(기존 5단계 유지)
  /* Radius */   --r: 18px; --r-sm: 12px; --r-icon: 16px;
  /* Shadow */   --shadow: 0 1px 2px rgba(0,0,0,.04), 0 2px 8px rgba(0,0,0,.03);
  /* Type */     --font: 'Pretendard','Noto Sans JP',-apple-system,sans-serif;
}
```
> ⚠️ 철창이 목업의 `#f2f2f7`/`Outfit`은 기존 정본(`#FAFAF8`/Pretendard)으로 **흡수**. 목업 색은 참고일 뿐 정본 아님.

### Layer 2 — 컴포넌트 / 타일 시스템

| 자산 | 구현 | 비고 |
|------|------|------|
| 타일 그리드 | `portal.css` (12컬럼 CSS Grid, span 4/6/8/12, 모바일 4컬럼 풀폭) | 토큰 기반 |
| SSR 타일 렌더 | **`lib/cms/render-home-tiles.js` 신규** | 기존 `render-*.js` fragment 패턴 계승 (결정1 해소: tiles.js 신규가 아니라 render 확장) |
| 클라 인터랙션 | `public/js/tiles.js` 신규 (config→DOM, 어드민 토글) | SSR 불요 타일만 |
| 공통 컴포넌트 | 카드·버튼·뱃지·Apps 아이콘 | 토큰 참조, 서비스 간 재사용 |

> **렌더 분담 원칙**: SEO 크리티컬(블로그·FAQ·활용법) = SSR(`render-home-tiles.js`). 비크리티컬(Apps·크레딧·영상) = 클라(`tiles.js`).

### Layer 3 — 서비스 레지스트리 (정본: `config/services.json` 신규)

Apps 타일에 무엇이 LIVE/BETA/예비로 뜨는지 = **브랜드 위상의 코드화**.

```json
{ "services": [
  { "id": "idphoto", "label": "AI 증명사진", "badge": "LIVE", "brand": "MONKOS", "href": "...", "order": 1 },
  { "id": "crop",    "label": "크롭앱",      "badge": "FREE", "href": "crop.monkos.ai", "order": 2 },
  ...
]}
```
> 🔗 **아침의 MONKOS↔IDPASS 브랜드 위상 결정이 여기 박힌다.** "증명사진"을 `MONKOS`로 둘지 `IDPASS`로 분리할지가 `label`/`brand` 필드를 좌우. → 브랜드 위상 설계서 확정 전엔 `brand:"MONKOS"` 잠정.

## 3. 워크플로우 — 반복 파이프라인

```
시안 → 검토 → 컨버트 → preview(0%) → 검증 → 전환
```

| # | 단계 | 담당 | 산출물 | 통과 게이트 |
|---|------|------|--------|------------|
| 1 | 시안 | 철창이 / (필요시 Figma) | 목업 HTML | 작가님 컨셉 OK |
| 2 | 검토 | 민아(UX·브랜딩) + 쌍아(헌법·정합) | 결정서 | 결정 항목 전부 클리어 |
| 3 | 컨버트 | 막내 | 코드 (**토큰 준수 필수**) | 빌드 통과 + 토큰 하드코딩 0 |
| 4 | preview | 막내 | 0% 트래픽 배포 | preview URL 200 |
| 5 | 검증 | 민아 (CDP 9223) | 반응형·SSR·SEO 체크리스트 | 합격 |
| 6 | 전환 | 작가님 승인 | prod (`deploy.sh prod`) | GA 이벤트 추적 부착 |

**게이트 원칙**: 각 단계는 산출물 + 통과조건이 명시돼야 다음으로 넘어간다. 멈추면 *어느 게이트에서 멈췄는지*가 PF에 남아, 재개 시 그 지점부터.

**검증 체크리스트(단계 5)** — 민아 CDP 9223 고정 담당:
- 반응형: Desktop(>768) 12컬럼 / Mobile(≤768) 풀폭 스택
- SSR: 블로그·FAQ·활용법 텍스트가 view-source에 존재
- SEO: JSON-LD(BlogPosting·FAQPage) 유지, hreflang 정상
- 인터랙션: 타일 클릭·전체보기 링크·Apps 아이콘 동작 (v4 롤백 원인 재발 방지)
