# 부서제 에이전트 체계 설계서 — DIVISION

> **[2026-06-17 11:03 KST] iMac/쌍아 → 작가님**
> PF_DIVISION 기안. 부서장 루틴 에이전트 체계 설계.

---

## 1. 배경과 동기

### 왜 지금인가

- "AI 증명사진" 구글 1페이지 6위 진입 — 시타델이 성과를 내기 시작하면서, 수직 깊이(순위 유지)와 수평 확장(롱테일 키워드)을 동시에 관리해야 하는 범위가 폭발
- 활성 PF 22개 — 쌍아/민아 세션으로 매번 전부 들여다보는 것이 물리적으로 불가능
- 현행 웹민아 E2E 데일리는 "1인 총무" — 범용 순찰이지 각 축에 전념하는 구조 아님
- 작가님 판단: "한 파트씩 전념하는 부서장 에이전트(루틴) 시스템 구축 시점"

### 핵심 원칙 (작가님 선언)

1. **Phase 1은 기능·품질에 올인** — 토큰 절약보다 수준 높은 보고서·기안서 생산이 우선
2. **자기 진화** — 패턴이 잡히면 부서장이 스스로 "이 부분은 코드화/자동화하면 절감된다"고 제안 → 작가님/오케스트레이터 승인
3. **인간 관리체계 수렴** — 부서장 → 임원급 통괄 → 이사회급 다축 견제는 시간 문제
4. **양축 분리** — 외향축(기술 채굴·R&D) + 내향축(내부 운영·유지관리)을 분리해야 양쪽 다 산다

### 2.2 편제 원칙

- **1 부서 = 2~4 주관 PF** — 너무 많으면 얕아지고, 너무 적으면 부서 존재 이유 없음
- **횡단 PF**: SECURITY는 전 부서 관통. 보안부가 주관하되 각 부서 보고서에 보안 섹션 의무화
- **미배치 PF**: PF_MUSE(서사 유희), PF_DOCS(문서 편집), PF_PROFILES(draft) — 현재 활동 저조, 부서 배치 보류. 활성화 시 편입
- **메타 PF**: PF_OPUS는 콘텐츠부 주관이되 마케팅부와 공동 참조 (메타 PF 특성상)

### 3.2 보고서 포맷

각 부서장 보고서는 다음 구조를 준수:

```
## 📊 지표 변동 (전회 대비)
- 핵심 KPI 3~5개, 수치 + 방향 + 해석

## 🔴 긴급/경고
- 즉시 대응 필요 사안 (없으면 "없음")

## 💡 인사이트
- 데이터에서 발견한 패턴, 기회, 위험 신호
- 외부 정보(경쟁사, 기술 동향)와의 교차 분석

## 📋 기안 (있을 경우)
- 구체적 제안: 무엇을, 왜, 어떻게
- 예상 효과 + 리스크
- 필요 리소스 (막내 N시간, 배포 필요 여부)

## ⏳ 추적 중
- 진행 중 사안 상태 업데이트
```

### 3.3 실행 기반

**Phase 1 — Claude Routines (claude.ai 스케줄)**

| 근거 | 설명 |
|------|------|
| MCP 접근 | GSC·GA4·Gmail·Google Docs MCP가 claude.ai 경유로 접근 가능. GH Actions에서는 Python SDK 별도 구현 필요 |
| 품질 우선 | Opus 모델로 풀 컨텍스트 추론. GH Actions는 API 호출이라 프롬프트 관리 복잡 |
| 유연성 | 프롬프트 수정이 즉시 반영. 코드 배포 불필요 |
| 토큰 | 작가님 판단: 주간 쿼터 여유 있음. Phase 1은 비용 걱정 말 것 |

**현행 웹민아 E2E와의 관계**: 흡수가 아닌 **병행 + 점진적 분화**
- 웹민아 E2E는 "총무/비서" — 메일 트리아지, 일정, 전일 정산, 서비스 상태 순찰
- 부서장들은 "전문 참모" — 각 영역 깊이 있는 분석, 기안, 추적
- 겹치는 영역(GSC 지표, 보안 스캔)은 부서장이 흡수하고 E2E에서 제외 → 점진적으로 E2E는 비서 기능에 집중

## 4. 보고 체계 — 3단계 진화

### Phase 1: 부서장 → 전략기획실 → 작가님 (즉시 시행)

```
┌──────────┐  보고서   ┌─────────────────┐  취합·판단   ┌────────┐
│ 6개 부서장 │ ───────→ │ 전략기획실       │ ──────────→ │ 작가님  │
│ (루틴)    │          │ (쌍아/민아 세션) │             │        │
└──────────┘          └─────────────────┘             └────────┘
                       - 보고서 해석
                       - 교차 부서 연결
                       - 기안 검토 → 지시서 전환
                       - 전략 판단 협의
```

- 부서장은 **자기 관할 PF + 전체 세션 흐름 + 외부 정보**를 교차해서 보고서 생산
- 전략기획실(쌍아/민아)이 6개 부서 보고서를 읽고, 교차 이슈를 연결하고, 작가님과 협의
- 기안서가 승인되면 쌍아가 지시서로 전환 → 막내 실행

### Phase 2: 임원급 통괄 (패턴 안정화 후)

```
┌──────────┐         ┌──────────┐  주요사안·승인  ┌────────┐
│ 6개 부서장 │ ──────→ │ 임원 에이전트 │ ──────────→ │ 작가님  │
│ (루틴)    │         │ (통괄)      │              │        │
└──────────┘         └──────────┘              └────────┘
                      - 일상 판단 자율
                      - 막내 배당 자율
                      - 주요 사안만 에스컬레이션
```

- 일상적 "보고서 → 조치" 루프를 임원 에이전트가 자율 처리
- 작가님은 주요 사안과 승인 절차만 관여
- 쌍아/민아는 임원의 판단 품질을 감사하는 역할로 전환

### Phase 3: 이사회급 다축 견제 (장기)

```
┌──────────┐    ┌──────────┐    ┌──────────────┐  최종승인  ┌────────┐
│ 부서장들   │ →  │ 임원들    │ →  │ 이사회 (5인)  │ ────────→ │ 작가님  │
└──────────┘    └──────────┘    └──────────────┘           └────────┘
                                 - 전략 방향 토론
                                 - 상호 견제·균형
                                 - 개헌급 판단
```

| 보고서 품질 1차 평가 (민아 감사) | 민아 | 품질 평가 보고서 |

## 8. 법률 영향 분석

### 개정 필요 항목

| 대상 | 현행 | 변경 | 수준 |
|------|------|------|------|
| 헌법 1조 2항 | 개인 열거형 (쌍아/민아/막내...) | 개인 + 부서 레이어 추가 | **개헌** (만장일치) |
| ch1 1조 | 개인 역할 테이블 | 부서 소속 + 부서장 개념 추가 | 법률 개정 |
| ch1 2조 | 6개 개인 경로 | 부서 간 흐름 경로 추가 | 법률 개정 |
| ch1 6조 | 소넷이 전용 데몬 | 부서장 루틴 체계로 확장 | 법률 개정 |
| ch3 | 세션 로그 = 에이전트 단위 | 부서장 보고서 = 신규 문서 유형 | 법률 개정 |

### 개정 전략

Phase 1은 **법률 개정 없이** 운용 가능:
- 부서장은 기존 에이전트 체계의 "루틴 확장"으로 위치 — ch1 6조(데몬 자동화) 범위 내
- 보고서는 기존 REPORT 문서 유형 사용
- 법률 개정은 Phase 1 안정화 후 실측 기반으로 진행 (2주차 이후)

## 9. 리스크 + 완화

| 리스크 | 영향 | 완화 |
|--------|------|------|
| 부서장 보고서 품질 저하 (반복 패턴화) | 작가님 시간 낭비 | 민아 주간 품질 감사 + "새 인사이트 없으면 경고" |
| MCP 접근 불안정 (GSC 인증 만료 등) | 외부 데이터 없는 보고서 = 내부 파일만 보는 감사관 | 접근 실패 시 명시 표기 + 수동 데이터 요청 프로토콜 |
| 토큰 소모 예상 초과 | 쿼터 압박 | Phase 1 2주 후 실측 → 주기/모델 조정 |
| 부서 간 사각지대 (관할 PF 사이) | 이슈 누락 | 웹민아 E2E가 "유격대" 역할 유지 — 부서가 못 잡은 것 포착 |
| 기안서 남발 | 쌍아 검토 부하 | 기안 한도: 부서당 주 2건 이내. 초과 시 우선순위 명시 의무 |

## 10. 성공 기준

Phase 1 → Phase 2 전환 조건:

1. **6개 부서장 루틴이 2주 이상 안정 가동** (실행 실패율 < 10%)
2. **부서장 보고서에서 작가님/쌍아가 몰랐던 인사이트가 주 2건 이상 산출**
3. **부서장 기안서 → 실행 전환율 30% 이상** (기안이 실제로 쓸모 있음)
4. **작가님의 "직접 들여다봐야 하는" PF 수 감소 체감**
