# DESIGN: 어드민 고객 360° + 정보밀도 대시보드

> **[2026-06-23 KST]** iMac/민아 → 작가님
> 기반: 어제 [BQ 유저트래킹 설계](DESIGN_20260622_유저트래킹_BigQuery_어드민대시보드.md) D5~D7 구체화 + 6/23 채널·동선·UTM 논의.
> 데이터: BQ `monkos_tracking.events`(실가동 중, 오늘 page_view 2,694) + Firestore `users`/`transactions`.

## 1. 문제 (현재 어드민)

1. **세로로 4섹션이 늘어져 한눈에 파악 불가** — 트래픽 차트(240px) → 가입 차트 2개 → 유저표 → 크레딧 차트+로그. 스크롤 과다, 차트가 공간 독식.
2. **추정 의존** — 유저표가 이름·이메일·인증·크레딧·가입일 5필드뿐. "크레딧 0이니 프리뷰만 봤나?" 식 추측. 행동·채널·결제가 안 보임.
3. **UTC 표시** — 가입 시각이 UTC라 한국 고객이 "새벽 몰림" 착시(실제 가입자 04:48 UTC = 13:48 KST 점심).
4. **테스트 계정 노이즈** — 작가님 계정(`108827…`)이 오늘 22이벤트로 진짜 가입자(카카오 7·2)를 압도, 통계 오염.

## 2. 고객 360° 스키마 (고객 1명 = 알 수 있는 전부)

| 차원 | 필드 | 소스 |
|------|------|------|
| **A 신원** | user_id·이름·이메일·provider·**가입일시(KST)**·`is_test` | Firestore users |
| **B 유입** | 채널(검색/네이버/카톡/SNS/직접)·캠페인·랜딩페이지 | BQ first_touch: **utm_source→referer 정규화** |
| **C 행동** | 첫진입~가입 소요·방문수·재방문/공백·**퍼널단계**(프리뷰/스타일/생성/다운로드) | BQ events |
| **D 결제** | **결제여부**(charge 거래)·총결제액·횟수·최근결제일·크레딧사용·잔액 | Firestore transactions |
| **E 전환** | 퍼널 위치·LTV·리텐션 (파생) | 조인 계산 |

→ **추정 폐기**: `크레딧0+charge없음+generate없음`=가입만 / `generate있음`=무료1컷 / `charge있음`=결제. **사실로 판정.**

## 3. 레이아웃 재설계 — "한 화면 정보밀도"

원칙: **차트는 요약으로 압축, 유저 360° 테이블이 주역, 깊이는 드릴다운.**

```
┌─ Row 1 — KPI 스트립 (1줄, 전일대비 ▲▼) ────────────────────────┐
│ 오늘가입 2 │ 결제 1 │ 활성 14 │ 매출 ₩9,900 │ 전환율 % │ 소진크레딧 │
├─ Row 2 — 압축 추세 (높이 ½, 좌우 분할) ───────────────────────┤
│ [트래픽 30일 스파크라인]        │ [가입 채널 도넛 + 일별 미니바] │
├─ Row 3 — 유저 360° 테이블 (메인·정보밀도 핵심) ───────────────┤
│ 유저 │ 채널 │ 가입(KST) │ 퍼널단계 │ 생성 │ 결제 │ 잔액 │ 최근활동│
│ map3939│카톡 │6/23 13:48│●●●○○ 생성│  2  │ ✓₩9,900│ 0 │ 5분전  │
│ …(테스트계정 회색 토글로 숨김/표시) …                          │
└─ 행 클릭 → 우측 슬라이드 패널: 동선 타임라인 + 채널 + 결제내역 ─┘
```

### Row 1 — KPI 스트립
6칸 한 줄, 숫자 크게 + 전일 대비 ▲▼. 현재 summary-grid 재활용하되 **매출·전환율·결제** 추가(추정 아닌 transactions 기반).

### Row 2 — 압축 추세
현재 트래픽(240px)·가입 차트 2개가 공간 독식 → **높이 절반, 좌우 2분할**. 트래픽은 스파크라인 수준, 가입은 채널 도넛+미니 일별바 통합.

### Row 3 — 유저 360° 테이블 (주역)
현재 5필드 → **8필드 360° 압축**. 핵심:
- **퍼널단계**: ●●●○○ 식 5단계 진행바(방문→가입→프리뷰→생성→다운로드) — 한 칸에 고객 상태.
- **결제**: ✓+금액(charge 사실) / ✗.
- **채널**: 뱃지(카톡/검색/네이버/직접).
- **가입·최근활동**: KST + 상대시각("5분 전").
- **테스트 계정**: `is_test` 회색 처리 + 토글로 숨김(기본 숨김).

### 드릴다운 — 행 클릭 → 우측 슬라이드 패널
어제 D6 유저상세: 동선 타임라인(BQ session 시퀀스, 정적에셋 필터) + 유입 채널/캠페인 + GCS 파일 + 결제내역. (별도 페이지 이동 없이 한 화면 내 패널)

## 4. 데이터 파이프라인 (선결 보강)

1. **utm 캡처** 🔴 선결 — `server.js:89`이 현재 `req.url.split('?')[0]`로 쿼리를 버림. **utm_source/medium/campaign 추출해 events.params에 적재**해야 채널(특히 카톡 referer NULL)이 잡힘.
2. **KST 변환** — 모든 시각 `FORMAT_TIMESTAMP(..., 'Asia/Seoul')`.
3. **테스트 필터** — `is_test` 화이트리스트(작가님 user_id 등) → 집계·테이블 제외.
4. **조인 뷰** — user_id 키로 BQ events(채널·행동) + Firestore users/transactions(신원·결제) → 어드민 API. 전수스캔 방지 위해 일배치 집계(`user_stats` 머티리얼라이즈) 권장.
