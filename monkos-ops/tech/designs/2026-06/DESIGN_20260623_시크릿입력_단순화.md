# DESIGN — 시크릿 입력 단순화 (발급→입력→등록 단일 경로)

> **[2026-06-23 12:25 KST]** M1/쌍아 → 작가님
> 배경: 레몬 글로벌 스토어 API 키 1개 입력에 30분 소요 — 경로가 많고 흩어져 있음.
> 목표: **"키 발급 → 1줄 입력 → 끝"**. 나머지(SM 등록·인벤토리·배포 반영)는 스크립트+에이전트가 처리.

---

## 1. 현재 문제 — 왜 30분이 걸리나

키 하나 등록하려면 **5곳을 수동으로 건드려야** 한다:

```
① gcloud secrets create <NAME> --data-file=-    # SM 등록 (명령 복잡)
② .env 파일 수동 편집                              # 로컬 반영
③ SECRET_INVENTORY.md 수동 편집                    # 메타 기록
④ deploy.sh --set-secrets 라인 수동 추가           # 배포 반영
⑤ 타 디바이스 .env 수동 동기화                      # M1/M4/4060 각각
```

에이전트도 ①번 gcloud 명령어 조합이 번거럽고, 작가님은 터미널에서 값 입력 자체가 스트레스.

---

## 2. 확정 구조 — 단일 스크립트 `scripts/secret.sh`

### 작가님 입력 플로우 (키 등록)

```bash
scripts/secret.sh add LEMONSQUEEZY_API_KEY_GLOBAL
```

```
[신규] LEMONSQUEEZY_API_KEY_GLOBAL — 시크릿을 생성합니다.
값을 붙여넣고 Enter:
████████████████████████  ← 화면 미노출 (read -rs)

✅ 등록 완료 — LEMONSQUEEZY_API_KEY_GLOBAL (version 1)

[인벤토리] monkos-ops/ops/SECRET_INVENTORY.md 에 메타 정보를 추가하세요:
  | LEMONSQUEEZY_API_KEY_GLOBAL | (용도) | (사용처) | 2026-06-23 |
```

**작가님이 하는 것**: 스크립트 실행 → 값 붙여넣기 → Enter. **끝.**
**에이전트(쌍아/막내)가 하는 것**: 인벤토리 메타 추가 + deploy.sh 반영 + .env 동기화.

### 전체 명령어

| 명령 | 누가 | 설명 |
|------|------|------|
| `secret.sh add <NAME>` | 작가님/에이전트 | SM 등록 (값 화면 미노출) |
| `secret.sh get <NAME>` | 에이전트 | 값 조회 (복원·검증용) |
| `secret.sh list` | 누구나 | 등록된 시크릿 전체 목록 |
| `secret.sh check <NAME>` | 누구나 | 존재 여부 + 버전 이력 |
| `secret.sh env` | 에이전트 | SM → .env 일괄 동기화 |

## 3. 시크릿 생애주기 — 3단계

```
[1단계] 발급            작가님이 외부 서비스에서 키 발급
                         (레몬 대시보드, 토스 콘솔, GCP 등)
         ↓
[2단계] 입력            scripts/secret.sh add <NAME>
                         → GCP Secret Manager 단일 정본 등록
                         → 값 화면 미노출, stdin 파이프
         ↓
[3단계] 전파            에이전트가 처리:
                         ① SECRET_INVENTORY.md 메타 1행 추가 (값 절대 금지)
                         ② deploy.sh --set-secrets 라인에 추가 (해당 시)
                         ③ secret.sh env 로 .env 동기화 (해당 시)
                         ④ 타 디바이스는 secret.sh get 으로 개별 복원
```

## 4. 인벤토리 메타 스키마 (값 아닌 메타정보만)

```
| 시크릿명 | 용도 | 사용 서비스 | 등록일 | 비고 |
```

예시:
```
| LEMONSQUEEZY_API_KEY_GLOBAL | 레몬 글로벌(USD) API | portal | 2026-06-23 | store#415328 전용 |
| LEMONSQUEEZY_WEBHOOK_SECRET_GLOBAL | 레몬 글로벌 웹훅 검증 | portal | — | 라이브 단계 발급 |
```

## 5. 글로벌 스토어 전환 시크릿 체크리스트

민아 제안서(§6-2) 기준, 글로벌 전환에 필요한 시크릿 조치:

| 시크릿 | 현재 | 조치 | 담당 |
|--------|------|------|------|
| `LEMONSQUEEZY_API_KEY` | JP 계정 공유 | **변경 없음** — 계정 단위, 스토어 무관 | — |
| `LEMONSQUEEZY_WEBHOOK_SECRET` | JP 웹훅 | **변경 없음** — idphoto-jp 동결, 포털도 동일 계정이면 공유 가능 | — |
| `LEMONSQUEEZY_STORE_ID` | 코드 상수 290457 | config.js에서 `415328`로 교체 (시크릿 아님) | 막내 |
| `VARIANT_CREDITS` | JP variant 맵 | config.js에서 USD variant 맵으로 교체 (시크릿 아님) | 막내 |

**결론: 글로벌 전환에 신규 시크릿 발급 불필요.** API Key와 Webhook Secret은 계정 단위로 스토어 간 공유. 코드 상수(STORE_ID, VARIANT_CREDITS)만 교체하면 됨.

단, 향후 idphoto-jp에 **별도 웹훅 URL**을 세팅하는 경우에만 `LEMONSQUEEZY_WEBHOOK_SECRET_GLOBAL` 분리가 필요 — 현 시점에서는 불필요.

## 6. 불변 원칙

1. **정본은 GCP Secret Manager 1곳.** .env·GitHub Secrets·CF Dashboard는 파생.
2. **값은 절대 문서에 기재하지 않는다.** 인벤토리는 메타만.
3. **에이전트는 값을 생성/추측하지 않는다.** (헌법 4조 1항)
4. **작가님 입력은 `secret.sh add` 한 줄.** 나머지는 에이전트가 전파.
