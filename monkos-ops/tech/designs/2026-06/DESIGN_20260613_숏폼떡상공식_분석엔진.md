## 0. 배경 — "감"으로 만드는 숏폼을 "공식"으로

현재 MONK.KR 콘텐츠 생산(PF_KKU)은 블로그 원본(PSSR 공식)은 체계화돼 있으나, **숏폼은 레퍼런스를 사람이 눈으로 보고 감으로 따라 하는 단계**다. 본 설계는 이 과정을 데이터 파이프라인으로 전환한다.

핵심 질문: **"왜 이 숏폼은 떡상했고, 우리가 재현할 수 있는 변수는 무엇인가?"**

- 단순 수집(조회수 랭킹)이 목표가 아니다 → 그건 누구나 본다.
- 목표는 **재현 가능한 공식(formula)의 추출**: 후킹·구조·제목·해시태그·길이의 어떤 조합이 velocity를 만드는가.
- 산출물은 **"이번 주 떡상 공식 Top N" 리포트** → kku-blog/kku-specs 소재로 직결.

### 헌법·법률 정합성 (착수 전 검토 — 헌법 5조 4항)
- **헌법 4조 4항(윤리)**: 가짜 트래픽·리뷰 생성 아님. **공개 데이터의 분석적 수집**만. ✅
- **저작권 라인**: 영상 원본 다운로드·재배포 금지. 자막/스크립트는 **내부 분석 목적 일시 추출** 후 원본 미보관 원칙. ⚠️ 준수 조항화.
- **ch2 코딩규칙**: 순수 JS(async/await), 새 프레임워크 도입 시 설계 선행. ✅ (본 문서가 선행 설계)
- **ch4 10조(데이터 격리)**: 수집 데이터는 크레딧/고객 데이터와 **물리적으로 분리된 별도 컬렉션**. 본 엔진은 credits.sh 대상 아님(서비스 외부 분석 데이터).

## 1. 아키텍처 — 3-레이어 파이프라인

```
[수집 RADAR] → [해부 DECODER] → [공식 SYNTH] → [리포트/연동]
   API/yt-dlp     AI 패턴분석      클러스터링      kku-blog·specs
```

| 레이어 | 역할 | 기술 | 산출 |
|--------|------|------|------|
| **L1 RADAR** | 도메인 키워드 숏폼 수집 + velocity 계산 | YouTube Data API v3 (1순위) + yt-dlp(보조) | 정규화된 영상 메타 레코드 |
| **L2 DECODER** | 후킹·구조·제목 패턴을 변수로 해부 | Gemini/MONKOS 엔진 (멀티모달) | 영상별 특징 벡터 |
| **L3 SYNTH** | 떡상군 vs 평범군 대조 → 공식 추출 | 클러스터링 + LLM 요약 | 떡상 공식 리포트 |

> 수집 방식은 **공식 API 우선 / 크롤링 보조** 하이브리드. API 미제공 항목(정확한 숏폼 길이·자막)만 yt-dlp로 보강하여 ToS·쿼터 리스크 최소화.

## 2. L1 RADAR — 수집 스키마

### 2.1 수집 대상 선정
- **도메인 키워드 셋**: 증명사진·여권사진·비자사진·AI보정·프로필사진·취업사진 등 (PF_KKU specs 국가/용도와 동기화)
- **벤치마크 채널 셋**: 지정 경쟁/레퍼런스 채널 N개 신규 숏폼 추적
- **수집 범위**: 키워드당 상위 50개 + 최근 30일 게시분

### 2.2 영상 레코드 (정규화)

| 필드 | 출처 | 용도 |
|------|------|------|
| `video_id` | API | PK |
| `title` / `description` / `tags` | API | 제목·해시태그 공식 분석 |
| `published_at` | API | velocity 분모 |
| `view_count` / `like_count` / `comment_count` | API | 성과 지표 |
| `channel_id` / `channel_subs` | API | 채널 규모 보정(구독자 대비 조회수) |
| `duration_sec` | yt-dlp | 길이 분포 분석 |
| `thumbnail_url` | API | L2 썸네일 OCR 입력 |
| `collected_at` | 시스템 | 수집 시점(velocity 재계산용) |

### 2.3 떡상 지표 (velocity)
```
velocity = view_count / hours_since_publish
engagement_rate = (like + comment) / view_count
subs_normalized = view_count / channel_subs   // 작은 채널의 떡상 포착
```
→ 단순 조회수가 아니라 **속도 + 구독자 대비 정규화**로 "진짜 떡상"을 식별.

## 3. L2 DECODER — 패턴 해부 (떡상 공식의 변수들)

> 떡상군 영상에 대해서만 심층 해부(비용 최적화). L3에서 평범군과 대조.

| 변수군 | 추출 방법 | 산출 특징 |
|--------|----------|----------|
| **후킹 (첫 3초)** | 썸네일 OCR + 초반 자막/멘트 추출 → AI 분류 | 후킹 유형(질문형·반전형·결과선공개형…) |
| **제목 공식** | 제목 토큰화 + AI 패턴 분류 | 길이·이모지·숫자·키워드 위치 패턴 |
| **해시태그 전략** | 태그 빈도/조합 분석 | 떡상군 공통 태그 클러스터 |
| **구조** | 자막 밀도·길이·BGM 유무(yt-dlp 메타) | 컷 호흡·정보 밀도 패턴 |
| **댓글 반응** | 상위 댓글 감성/키워드 추출 | 시청자가 반응한 포인트 |

### 자막/스크립트 처리 (준수 조항)
- yt-dlp 자동 자막 우선. 없으면 Whisper로 음성→텍스트.
- **추출 텍스트는 분석 후 특징 벡터만 저장, 원본 스크립트·영상은 미보관** (저작권 라인 준수).

## 4. L3 SYNTH — 공식 추출 & 리포트

### 4.1 대조 분석
- 동일 키워드군 내 **떡상군(velocity 상위 20%) vs 평범군(하위 50%)** 특징 대조.
- "떡상군에만 공통으로 나타나는 변수 조합" = 후보 공식.

### 4.2 리포트 산출물 (`SHORTS_FORMULA_YYYYMMDD.md`)
```
## 이번 주 떡상 공식 Top 5
1. [후킹: 결과 선공개형] + [제목: 숫자+이모지] + [길이 15~22s] → 평균 velocity 3.2x
   - 대표 사례: (video_id, 조회수, 채널규모)
   - 우리 적용안: "여권사진 5초만에" 류 후킹 → kku-blog #N 소재
...
## 우리 콘텐츠 갭
- 경쟁사는 하는데 우리는 안 하는 포맷: [BGM 없는 ASMR형 보정 과정]
```
- **kku-specs 연동**: 떡상 포맷을 specs 페이지 영상 임베드/CTA 카피에 반영.
- **kku-blog 연동**: 공식을 블로그 PSSR 본문 + 숏폼 스크립트 초안으로 변환.

## 5. 기술 스택 & 저장 (ch2 부합)

| 구분 | 선택 | 근거 |
|------|------|------|
| 수집 런타임 | Node.js 순수 JS(async/await) | ch2 코딩규칙 |
| API | YouTube Data API v3 | 합법·무료 쿼터(일 10,000) |

| AI 분석 | Gemini/MONKOS 엔진 | 기존 인프라 재사용 |

| 배치 | monk-n8n 워크플로우 | 주간 정기 수집 |
| 시크릿 | YouTube API 키 → GCP Secret Manager | data-access 규칙 |

> ⚠️ **준수 조항**: API 키는 Secret Manager 등록 후 참조. .env 하드코딩·git 커밋 금지(헌법 4조 1항).
