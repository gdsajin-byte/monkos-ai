## §3 IDPASS 허브 설계

### 3-1. 아키텍처 선택: 바닐라 SPA

- ch2 코딩 규칙 준수 (순수 JS, Tailwind)
- React/Vue/Astro 도입 없음
- 라우팅: History API + 경량 라우터 (직접 구현, ~50줄)
- 상태: 클라이언트 메모리 (세션 단위, 새로고침 시 초기화 허용)

### 3-2. 페이지 구조

```
/idpass
  ├─ / (허브 랜딩 — 서비스 소개 + 규격 검색)
  ├─ /upload (사진 업로드 + 규격 선택)
  ├─ /result (판정 + T0/T1/T2 분기)
  ├─ /pay (결제)
  └─ /mypage (회원 히스토리)
```

### 3-3. CR API 호출 패턴

```
CF Pages (SPA)                    CR API
  사진 업로드  ──POST──→    /api/idphoto/precheck
  규격 적용   ──POST──→    /api/idphoto/fit
  생성 요청   ──POST──→    /api/idphoto/generate
  결제       ──POST──→    /api/payments/toss/init
  크레딧 조회  ──GET───→    /api/credits
```

CORS: CR에 `Access-Control-Allow-Origin: https://monkos.ai` 헤더 추가.
또는 CF Workers로 /api/* 프록시 → 동일 도메인, CORS 불필요.

### 3-4. 검증 항목 (허브 MVP)

1. CF Pages → CR API 크로스 오리진 호출 (CORS 또는 Workers 프록시)
2. 파일 업로드 (multipart/form-data → CR)
3. OAuth 콜백 (리다이렉트 URI 변경)
4. 결제 콜백 (Toss/Lemon 웹훅은 CR 직접 → 무관)

## §4 specs SSG 전환

### 4-1. 전환 방법

현재 render-specs.js가 요청 시마다 specs-data.json + specs-i18n.js를 읽어 HTML을 생성.
→ **빌드 스크립트로 전환**: 동일 로직으로 HTML 파일을 디스크에 쓴다.

```javascript
// build-specs.js (신규, 4060에서 실행)
import { renderSpecsPage } from './render-specs.js';
import specsData from './specs-data.json';

for (const slug of Object.keys(specsData)) {
  for (const lang of ['ko', 'en', 'ja', 'es', 'id', 'vi', ...]) {
    const html = renderSpecsPage(slug, lang, specsData);
    writeFileSync(`dist/specs/${lang}/${slug}/index.html`, html);
  }
}
```

### 4-2. 변경 범위

| 항목 | 변경 |
|------|------|
| render-specs.js | 거의 무변경 — 출력을 res.send() 대신 return html |
| server.js | specs 라우트 제거 (CF가 서빙) |
| specs 동적 부분 (T1 버튼 등) | 클라이언트 JS로 전환 (API 호출) |
| 사이트맵 | 빌드 시 정적 생성 |

### 4-3. 빌드 파이프라인

```
4060:
  1. git pull (최신 코드 + specs-data.json)
  2. node build-specs.js → dist/ (3,500+ HTML)
  3. node build-blog.js → dist/blog/
  4. node build-static.js → dist/ (pricing, FAQ, guide, 랜딩)
  5. cp -r public/ dist/ (CSS, JS, 이미지)
  6. wrangler pages deploy dist/ --project-name=monkos-ai
```

빌드 트리거: specs-data.json 변경 시 (git hook 또는 수동) / 주기: 주 1~2회

## §8 리스크 및 제약

| 리스크 | 대응 |
|--------|------|
| CF Pages 커스텀 도메인 + CR 동시 운용 시 DNS 충돌 | CF Workers로 /api/* 프록시, 또는 api.monkos.ai 서브도메인 분리 |
| specs 동적 부분 (T1 버튼, 크레딧 잔액) SSG 전환 | 클라이언트 JS에서 API 호출로 렌더 (hydration) |
| SEO 영향 — SSR → SSG 전환 시 | HTML 출력 동일하면 영향 없음. diff 검증 필수 |
| 4060 다운 시 빌드 불가 | 마지막 빌드 결과가 CF에 남아 있으므로 서빙 무중단. 빌드만 지연 |
| OAuth 리다이렉트 URI | CF SPA에서 /auth/* → CR 직접 호출. 기존 URI 유지 가능 |
