**[2026-07-15 13:03 KST]** iMac/쌍아 → 작가님

> 작가님 핵심 지시:
> - "최근 가입한 사람이 어느 사이트에서 어떤 경로로 왔나, 로그인 가입 하는지, 무료만 보는지 한눈에"
> - "각 개인별로 페이징해주면 자체로 마이페이지가 되고 노출 데이터 스키마만 조정하면 되도록"

## 1. 핵심 원리: 하나의 데이터, 두 개의 뷰

```
┌──────────────────────────────────────────────┐
│          유저 프로필 데이터 모델               │
│                                              │
│  Firestore users ─┐                          │
│  Firestore transactions ─┤                   │
│  Firestore generations ──┤  ← 신설           │
│  BQ events + identity_map ┤                  │
│  GCS monk-customer-photos ┘                  │
│                                              │
│         ┌──────────┴──────────┐              │
│         ▼                     ▼              │
│  ┌─────────────┐     ┌──────────────┐        │
│  │ 어드민 뷰    │     │ 마이페이지 뷰 │        │
│  │ (전 필드)    │     │ (필터링)      │        │
│  │ /admin/users │     │ /account      │        │
│  │ /:userId     │     │ (본인만)      │        │
│  └─────────────┘     └──────────────┘        │
└──────────────────────────────────────────────┘
```

**같은 API, 같은 스키마**에서:
- 어드민: `requireAdmin` → 아무 userId 조회 가능, 전 필드(유입경로·BQ동선·내부메모 포함)
- 마이페이지: `requireAuth` → 본인 userId만, 노출 필드 제한(갤러리·크레딧·설정만)

## 2. 현행 자산 실측

### 있는 것

| 자산 | 위치 | 상태 |
|------|------|------|
| users 컬렉션 | Firestore | provider, email, credits, createdAt, lastLogin, signupSource, acquisition(referrer·landing_url·first_visit) |
| transactions 컬렉션 | Firestore | 크레딧 원장 (charge/use/refund), amount, provider, description |
| BQ events 테이블 | monkos.monkos_tracking.events | page_view, auth_login, auth_signup, credit_charge, api_generate 등 — referer, page_path, lang, region, session_id |
| BQ identity_map | monkos.monkos_tracking.identity_map | session_id ↔ user_id 매핑 |
| GCS 이미지 | monk-customer-photos | {service}/{userId}/{ts}_{style}_{type}.{ext} — 메타에 userId, service, style, createdAt |
| 어드민 API 5종 | /api/admin/dashboard/* | summary, users, users360, credits, traffic |
| 어드민 인증 | admin-auth.js | 쿠키+ADMIN_UIDS / Bearer+AGENT_API_KEYS |
| 유저 인증 | auth.js | Google/Kakao/LINE OAuth, monkos_session 쿠키 |

### 없는 것 (= 이번 설계 범위)

| 갭 | 영향 |
|----|------|
| **generations 컬렉션** | "내 사진 목록" 조회 불가. GCS에 저장만 되고 인덱스 없음 |
| **유입경로 → 행동 → 전환 통합 뷰** | users360이 transactions만 조인, BQ 동선·referrer 미합류 |
| **/api/account (마이페이지 API)** | 유저 자기 정보 조회 엔드포인트 전무 |
| **/api/generations (생성내역 API)** | 존재하지 않음 |
| **어드민 유저 상세 전용 페이지** | 사이드패널(420px)에 끼워넣어 좁고 정보 부족 |
| **유입 채널별 대시보드** | referrer 분해 시각화 없음 |
| **자동 보고서 파이프라인** | 수집 데이터 → 판단 가능한 정량/정성 보고 체계 없음 |

## 3. 데이터 모델 신설/확장

### 3-1. `generations` 컬렉션 (신설) — 민아 기안 수용

```javascript
// Firestore: generations/{autoId}
{
  userId:       string,    // 테넌트 키
  service:      string,    // 'idphoto' | 'headshot' | 'crop' | 'vton'
  style:        string,    // 'kr-passport-35x45', 'linkedin' 등
  slug:         string,    // specs 슬러그 (연결 시)
  channel:      string,    // 'monkos' | 'incruit' ... (PARTNER 예약)
  gcsOriginal:  string,    // GCS 경로
  gcsGenerated: string,    // GCS 경로
  thumbnailPath: string,   // GCS 경로만 저장. 서명 URL은 API 조회 시 생성 (7일 만료 방지)
  status:       string,    // 'active' | 'deleted'
  createdAt:    string,    // ISO
}
// 비로그인 생성(specs-visitor): userId='anonymous_{sessionId}'로 마킹 후 적재.
// 비로그인→가입 전환 시 identity_map 조인으로 userId 귀속.
// 퍼널 집계에서 anonymous 볼륨은 전환율 분모로 활용.
```

**적재 시점**: `saveImages()` 호출 시 동시 기록.
**인덱스**: `(userId, createdAt desc)` 복합.
**백필**: 기존 GCS 객체 메타데이터에서 1회 마이그레이션 스크립트.

### 3-2. users 확장 (settings 활성화)

```javascript
users/{userId}.settings = {
  language: 'ko' | 'ja' | 'en',
  emailNotifications: boolean,
  marketingConsent: boolean,    // 후순위
}
```

### 3-3. 통합 프로필 응답 스키마

하나의 함수로 유저 프로필을 조립. 어드민/마이페이지 양쪽에서 호출.

```javascript
async function buildUserProfile(userId, { includeAdmin = false } = {}) {
  // 1. Firestore users
  const user = await usersCol.doc(userId).get();

  // 2. Firestore transactions (최근 50건)
  const txs = await txCol.where('userId', '==', userId)
    .orderBy('createdAt', 'desc').limit(50).get();

  // 3. Firestore generations (최근 50건)
  const gens = await gensCol.where('userId', '==', userId)
    .orderBy('createdAt', 'desc').limit(50).get();

  // 4. BQ 동선 (어드민 전용)
  let timeline = [];
  if (includeAdmin) {
    const [rows] = await bq.query({
      query: `SELECT event_name, event_timestamp, page_path, referer, params
              FROM \`monkos.monkos_tracking.events\`
              WHERE user_id = @userId OR session_id IN (
                SELECT session_id FROM \`monkos.monkos_tracking.identity_map\`
                WHERE user_id = @userId
              )
              AND event_date >= DATE_SUB(CURRENT_DATE(), INTERVAL 90 DAY)
              ORDER BY event_timestamp DESC LIMIT 200`,
      params: { userId }
    });
    timeline = rows;
  }

  return {
    // 기본 (양쪽 공통)
    profile: { name, email, provider, picture, createdAt, lastLogin, credits },
    transactions: txs.map(formatTx),
    generations: gens.map(formatGen),   // 갤러리 데이터

    // 어드민 전용
    ...(includeAdmin && {
      acquisition: user.acquisition,    // referrer, landing_url, first_visit
      signupSource: user.signupSource,
      timeline,                         // BQ 이벤트 전체
      funnelStage: deriveFunnel(txs, gens),
      totalPaid: sumCharges(txs),
      isTest: isTestUser(userId),
    }),
  };
}
```

## 4. API 설계

### 4-1. 어드민 전용 (기존 확장)

| 메서드 | 경로 | 설명 | 인증 |
|--------|------|------|------|
| GET | `/api/admin/dashboard/user/:userId` | 유저 프로필 전체 (BQ 동선 포함) | requireAdmin |
| GET | `/api/admin/dashboard/funnel` | 채널별 퍼널 집계 (referrer → signup → generate → charge) | requireAdmin |
| GET | `/api/admin/dashboard/channels` | 유입 채널 분해 (7d/30d/90d) | requireAdmin |

### 4-2. 유저 대면 (마이페이지)

| 메서드 | 경로 | 설명 | 인증 |
|--------|------|------|------|
| GET | `/api/account` | 내 프로필 + 잔액 + 설정 | 세션(본인) |
| GET | `/api/account/generations?service=&cursor=` | 내 생성 이미지 목록 | 세션(본인) |
| GET | `/api/account/generations/:id/download` | HQ 다운로드 (GCS 서명 URL) | 세션(소유 검증) |
| DELETE | `/api/account/generations/:id` | 사진 삭제 | 세션(소유 검증) |
| GET | `/api/account/transactions?cursor=` | 내 거래 내역 | 세션(본인) |
| PATCH | `/api/account/settings` | 설정 저장 | 세션(본인) |

**보안 원칙**: 모든 `/api/account*`는 세션의 userId만 접근. URL에 userId 파라미터 없음 — 서버가 세션에서 추출.

## 6. 보고서 파이프라인

수집 데이터 → 판단 가능한 정량/정성 보고.

### 6-1. 자동 보고서 (daily_briefing 확장)

현행 daily_briefing.py가 GSC/GA4를 수집하여 md 보고서를 생성. 여기에 추가:

| 항목 | 소스 | 판단 기준 |
|------|------|----------|
| **신규 가입** | Firestore users (당일 createdAt) | "오늘 n명, 이번주 m명, 주간 추이 ↑↓" |
| **유입 채널 Top 5** | BQ events (referrer 집계) | "네이버 블로그 x%, 구글 오가닉 y%" |
| **퍼널 드롭** | BQ events (단계별 카운트) | "upload→generate 전환율 z%, 전주 대비 ↑↓" |
| **결제 전환** | transactions (당일 charge) | "결제 n건, 총 ₩x, 전환율 y%" |
| **이상 신호** | 급변 감지 | "가입 급증/급감, 퍼널 특정 단계 막힘, 결제 0" |

### 6-2. 주간 종합 보고서 (신설)

매주 월요일 자동 생성. 7일간 집계 + 전주 대비 + 정성 판정.

```markdown
## 주간 CITADEL 보고서 (7/8~7/14)

### 핵심 숫자
- 신규 가입: 12명 (전주 8, +50%)
- 유입 Top: 네이버 블로그 35% → 구글 오가닉 28% → 직접 20%
- 퍼널: 방문 2,800 → 가입 12 (0.4%) → 생성 8 (67%) → 결제 2 (25%)
- 매출: ₩19,800 (전주 ₩9,900, +100%)

### 판정
- 네이버 블로그 유입 첫 1위 — vol.36 개보수 효과 추정
- 생성→결제 드롭 75% — 무료 크레딧 소진 후 이탈 패턴
- [액션] 무료 크레딧 소진 유저 대상 리텐션 동선 필요
```

## 8. 작가님 결정 필요

1. **마이페이지 라우트**: `/account` vs `/mypage` — 본 설계는 `/account` 권고 (영문 URL)
2. ~~GCS 보존기간~~ → **확정**: 기본 무기한 보관 + 고객 선택 삭제. 마이페이지에서 즉시 삭제 버튼 제공. 개인정보처리방침에 "고객 요청 시 즉시 삭제, 미요청 시 보관" 명시. (작가님 7/15 확정)
3. ~~백필 범위~~ → **확정**: 전량 백필. 기존 GCS 전부 generations 인덱싱. (작가님 7/15 확정)
