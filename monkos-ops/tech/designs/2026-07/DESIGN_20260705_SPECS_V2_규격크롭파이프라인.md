# 설계서 — 스펙스 V2 규격 크롭 파이프라인

**[2026-07-05 18:59 KST]** iMac/쌍아

## 1. 문제

현재 스펙스 V2 생성은 "흰 배경 3:4 세로 사진"을 만들어줄 뿐, 국가별 실제 규격(mm 단위)을 적용하지 않는다. ₩2,000/$1.99를 받고 규격 미적용 결과물을 주면 상품 가치가 없다.

## 2. 목표

생성 결과물이 해당 국가·문서 type의 공식 규격(W×H mm, 얼굴 비중, 상단 마진)에 맞도록 후처리한다.

## 3. 현재 자산

| 자산 | 위치 | 역할 |
|------|------|------|
| AI 생성 (배경 제거) | `portal/lib/idphoto-generate.js` | gemini-3-pro / 2.5-flash-image로 배경 제거 + 3:4 |
| 크롭앱 (클라이언트) | `portal/public/crop/crop.js` | FaceMesh 얼굴 감지 + 규격 크롭 (브라우저) |
| 규격 DB | `portal/lib/cms/specs-data.json` | 428슬러그, W×H(mm), 배경, type 등 |
| crop-engine (서버) | `monkos_AI/crop-engine/` | Node.js + TF.js FaceMesh 서버사이드 크롭 (미배포) |
| sharp | portal 의존성 | 이미지 리사이즈/크롭 |

## 4. 파이프라인 설계

```
[사용자]
  ↓ 사진 업로드
[검수] precheck (gemini-2.5-flash)
  ↓ 통과
[결제] 토스 ₩2,000 / 레몬 $1.99
  ↓ 토큰 발급
[생성] AI 배경 제거 (gemini-2.5-flash-image 또는 gemini-3-pro)
  ↓ 흰 배경 3:4 이미지
[규격 크롭] ← 신규
  ↓ 국가·문서 type 규격 적용
[결과] 규격 맞춤 사진 제공
```

### 4-A. 규격 크롭 단계 상세

**입력**: AI 생성 결과 (흰 배경 3:4 base64)
**참조**: specs-data.json에서 해당 slug의 규격 수치

**처리 옵션 (검증 필요)**:

#### 옵션 A — AI 프롬프트 규격 대응 (단일 단계)
- 생성 프롬프트에 규격 수치를 직접 지시 ("35×45mm, 얼굴 비중 70-80%, 정수리 상단 여백 3-5mm")
- 2.5-flash-image가 이 수준의 정밀 크롭을 프롬프트로 대응 가능한지 **실측 필요**
- 장점: 파이프라인 단순, 추가 의존성 없음
- 리스크: AI가 mm 단위 정밀도를 보장할 수 없을 가능성 높음

#### 옵션 B — AI 생성 + FaceMesh 서버 크롭 (2단계)
- AI: 배경 제거만 담당. 얼굴 비중 충분히 크게 생성 (FaceMesh 감지 가능 범위)
- FaceMesh (서버): 랜드마크 추출 → specs-data 수치로 정밀 크롭
- crop-engine 로직을 포털 lib에 인라인 or crop-engine 배포 후 API 호출
- 장점: mm 단위 정밀도 보장
- 리스크: TF.js 서버 의존성 추가, FaceMesh 감지 실패 시 폴백 필요

#### 옵션 C — AI 생성 + sharp 단순 크롭 (2단계, FaceMesh 없이)
- AI: 배경 제거 + 얼굴 중앙 정렬 (프롬프트 지시)
- sharp: AI 출력을 specs-data의 W:H 비율로 센터 크롭 + 리사이즈
- FaceMesh 없이 "얼굴이 중앙에 있다"는 AI 출력을 신뢰
- 장점: 의존성 최소, 구현 단순
- 리스크: 얼굴 위치가 AI마다 흔들리면 규격 이탈

### 4-B. 작가님 판단 (미결)

> "2.5 이미지가 규격까지 완벽 대응이 가능한지 모르겠네"

**→ 실측 선행 필요**: 옵션 A 검증 후, 불가능하면 옵션 B/C로 결정

## 5. 인화지 배치 (후순위)

규격 크롭 이후, 4×6 또는 A4 인화지 위에 사진 N장 배열하는 기능. 국가별 관행(여권 2장, 비자 4장 등) 적용. 이 단계는 규격 크롭 안정화 후 추가.
