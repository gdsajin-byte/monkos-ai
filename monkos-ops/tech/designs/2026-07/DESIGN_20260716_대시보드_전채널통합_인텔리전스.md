# 설계서: 대시보드 전 채널 통합 + 인텔리전스 레이어

**[2026-07-16 17:38 KST]** iMac/쌍아 기안

---

## 1. 문제 정의

### 현행

어드민 대시보드(dashboard.js 733줄)가 **GA4 + BQ 2개 소스만** 사용.
네이버·빙·GSC·PageSpeed 데이터는 별도 파이프라인(seo_collectors.py → daily_briefing.py)에서 수집하지만 대시보드에 미연결.

| 소스 | 수집기 존재 | 대시보드 연결 | 갭 |
|------|-----------|------------|-----|
| GA4 | ✅ | ✅ | - |
| BQ (events) | ✅ | ✅ | 봇 미필터(46%) |
| GSC | ✅ seo_collectors.py | ❌ | 키워드·순위·CTR 미표시 |
| 네이버 검색광고 | ✅ fetch_naver_searchad() | ❌ | 한국 검색량 미표시 |
| 네이버 DataLab | ✅ fetch_naver_datalab() | ❌ | 트렌드 미표시 |
| Bing WMT | ✅ fetch_bing_wmt() | ❌ | 일본 시장 Bing 36% 미반영 |
| PageSpeed | ✅ fetch_pagespeed() | ❌ | 성능 지표 미표시 |

### 구조적 문제

- daily_briefing(Python, GitHub Actions)과 대시보드(Node.js, Cloud Run)가 별개 코드베이스
- 같은 데이터를 두 곳에서 중복 수집하거나 한쪽만 수집
- 대시보드가 숫자만 나열 — 해석·제안 없음

### 방향

- **대시보드 = 데이터 정본** (인프라). 전 채널 수집을 대시보드 API로 통합
- **에이전트 = 소비자** (보고). 대시보드 API를 호출해서 판독·해석·보고
- daily_briefing은 수집 로직을 대시보드로 이관하고, API 호출→보고서 생성으로 전환

## 2. 설계

### 2.1 Phase 1 — 전 채널 수집 API 통합

dashboard.js에 핸들러 4개 신설:

| API | 소스 | 반환 | 캐시 |
|-----|------|------|------|
| `/api/admin/dashboard/gsc` | GSC Search Analytics API | 키워드 top 30 (쿼리·클릭·노출·CTR·순위) + 페이지별 top 20 | 1h |
| `/api/admin/dashboard/naver` | 네이버 검색광고 API + DataLab API | 키워드별 PC/모바일 검색량 + 트렌드 | 6h |
| `/api/admin/dashboard/bing` | Bing WMT API | 키워드·클릭·노출·순위 | 6h |
| `/api/admin/dashboard/performance` | PageSpeed Insights API | URL별 LCP·FID·CLS·점수 | 24h |

기존 API 보강:
- `/channels`: BQ 쿼리에 봇 UA 필터 추가 (AhrefsBot, Bingbot, SemrushBot, Googlebot, YandexBot, GPTBot 등)
- `/citadel`: GSC 키워드 요약 카드 추가 (top 10)

**인증**: GSC = SA 키(GCP_SA_KEY, plain JSON). 네이버 = NAVER_SEARCHAD_* 3종 + NAVER_DATALAB_* 2종. 빙 = BING_WMT_API_KEY. PageSpeed = 공개 API(키 선택적).

**참조 코드**: seo_collectors.py의 fetch_* 함수를 Node.js로 포팅. 로직 동일, 언어만 전환.

### 2.2 Phase 2 — 추가 채널 + 해석 레이어

#### 추가 데이터 채널 (3종)

| API | 소스 | 반환 | 인증 | 캐시 |
|-----|------|------|------|------|
| `/api/admin/dashboard/google-keywords` | **Google Ads Keyword Planner API** | 키워드별 월간 검색량 (글로벌), 경쟁도, CPC | Google Ads 개발자 토큰 + OAuth | 24h |
| `/api/admin/dashboard/instagram` | **Instagram Graph API** | 계정별 인사이트 (도달·인게이지먼트·팔로워 인구통계), 게시물별 성과 | Meta 앱 토큰 | 6h |
| `/api/admin/dashboard/trends` | **Google Trends** (비공식 라이브러리) | 키워드 상대 트렌드 (30/90일) | 불필요 | 6h |

**Instagram 계정 2개:**
- `monk_photo` (몽크사진관, 한국, 게시물 80, 팔로워 69) — 꾸 운영, 활성
- `monkos.ai` (MONKOS.AI, 일본, 게시물 66, 팔로워 25) — 한송이 퇴사 후 비활성, 콘텐츠 자산 존치

**Google Ads Keyword Planner:**
- 네이버 검색광고 = 한국 검색량, Google KP = 글로벌 검색량. 양쪽 있어야 완전한 그림
- Google Ads 계정 기존재. 개발자 토큰 승인 필요 (기본 접근은 승인 후 즉시)

**citadel.html UI 추가 섹션:**
- 글로벌 검색량 카드: Google KP 키워드 테이블 (검색량·경쟁도·CPC)
- Instagram 성과 카드: 계정 2개 탭 (monk_photo / monkos.ai), 최근 게시물 인게이지먼트
- 트렌드 카드: 네이버 DataLab + Google Trends 병렬 비교

#### 해석 레이어 — 서버 자동 감지 인사이트

서버에서 자동 감지하는 인사이트:

| 인사이트 | 감지 조건 | 출력 |
|----------|---------|------|
| 순위 급등/급락 | 전주 대비 ±5위 이상 | "kr-passport 11위→6위 (↑5)" |
| 높은 노출 낮은 CTR | 노출 50+ & CTR < 2% | "남자 증명사진: 134노출 1클릭 → 타이틀 개선 권고" |
| 신규 클릭 키워드 | 전주 0클릭 → 이번주 1+ | "취업사진 앞머리: 첫 클릭 발생" |
| 체류시간 양극화 | 같은 페이지에서 <10초 & >60초 공존 | "passport/in: 바운스 vs 장기 체류 — CTA 위치 검토" |
| 봇 비율 이상 | 봇 > 50% | "봇 비율 52% — 크롤 예산 점검" |

`/api/admin/dashboard/insights` 엔드포인트로 제공. 대시보드 상단에 "인사이트 카드" 영역.

### 2.3 Phase 3 — 에이전트 연동

- daily_briefing.py: 수집 로직 제거 → 대시보드 `/api/admin/dashboard/*` 호출 → 해석+보고서 생성
- 소넷이: 이상 감지 시 텔레그램 알림 (순위 급락, 500 에러, 봇 급증)
- 민아: 세션 시작 시 `/insights` API 호출 → 판독 보고 자동 첨부
