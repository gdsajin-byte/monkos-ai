## 2. 설계 결정

**D1. `isPilot` 언어 분기 폐지 — 전 언어 단일 T0 퍼널.**
무료 전면 개방 결정으로 파일럿/비파일럿 이원 구조의 존재 이유 소멸. 신형 T0 퍼널(업로드→fit+매팅 병행→무료 3회→소진 시 유료)이 ko/en/ja 공통 경로가 된다. 구형 유료 직행 레이아웃(성인/의상/$1.99 패널로 바로 가는 "구 디자인")은 **삭제**. T1 의상·리터칭은 신형 퍼널의 후속 업셀 단계로 일원화.

**D2. 페이지 전체를 2계층 컴포넌트 체계로 재편.** *(작가님 확장 지시 2026-07-15 — 지난 포털 컨테이너 조합 설계 사상 계승)*

수천 페이지 확장의 실제 병목은 페이지 수(데이터 행으로 이미 스케일)가 아니라 **섹션 진화** — 규정 테이블 스키마·FAQ 형식·퍼널 기능이 바뀔 때 428×3언어에 동시 반영되는 통로다. 단일 ~500행 프래그먼트 함수에서 섹션 하나를 고치면 전체가 diff되는 현 구조를, 컴포넌트 단위 수정으로 국소화한다.

```
[1층] SSR 콘텐츠 컴포넌트 — 순수 함수 (slug, lang) → html, lib/cms/components/
  specHero        H1·요약·칩·브레드크럼
  specCard        규정 테이블 (+출처 링크)
  specDiagram     규격 대표 이미지 박스 (치수 주석)
  specDetails     상세 규정·반려 사유 탭
  docsAccepting   동일 사진 제출 가능 서류
  faqSection      FAQ (+FAQPage JSON-LD)
  relatedServices 내부링크·업셀

[2층] 클라 인터랙티브 위젯 — mount(el, opts), public/components/
  specs-funnel/   증명사진 처리 (업로드→fit→무료 생성→결제→T1 업셀)
    SpecsFunnel.mount(el, { slug, lang, market, t1, quota, onEvent })
  attire-picker/  의상 선택 (기존재 — D5에서 편입)

[조합] 페이지 = 문서타입별 레시피(컴포넌트 배열 선언) × specs-data.json
```

- 원칙: **정보 수정 = 데이터(specs-data.json)만, 형식 수정 = 해당 컴포넌트 1개만, 기능 수정 = 위젯 1개만, 조화(치수·간격·색) 수정 = 토큰 1줄만.**
- *(07-15 보강)* 상위 계약: 감사 보고서 §4.5 소유권 4계층 — 본 기안의 1·2층 위에 **L0 디자인 토큰**(CSS 변수 정본, 컴포넌트 px 소유 금지 — P1에서 기존 CSS 반복값 추출로 신설)과 **L3 전역 서비스**(Auth·Pay intent 패턴 — 트랙 2)가 있다. 퍼널 위젯의 결제 진입은 L3 Pay 파사드 호출로 설계해 차후 교체 지점을 봉인.
- 확장 이점: 문서 타입별 상이한 섹션 구성(여권/비자/이력서)은 레시피 선언으로 해결. specCard·faqSection은 블로그·허브 등 타 지면 재사용 가능(꾸 콘텐츠 연동).
- **마크업 동결 원칙**: 1층 분해는 출력 HTML diff 0을 조건으로 한다(라이브 SEO 자산 보호). 구조 개선은 분해 완료 후 별도 커밋.
- 프레임워크 도입 없음 — 순수 JS 함수 + mount 패턴 (ch2 준수, 지난 포털 모듈화 사상의 현 스택 이식).

**D3. 문자열 전면 사전화 (3층).**
- SSR: SPECS_I18N을 `lib/cms/specs-i18n.js` 별도 모듈로 분리, 하드코딩 잔존분 편입
- 위젯: UI_TEXT {ko,ja,en} (attire-picker 동일 패턴)
- 서버 API: **code 정본화** — 서버는 `code`만 보장, 사용자 문구는 위젯이 로케일 매핑 (서버 25건 한국어 문자열은 폴백으로 존치)

**D4. 카피 개정 동시 반영 (ko 정본 → ja/en).**

**D5. attire-picker 정식 편입.**
T1 의상 단계의 구형 인라인 UI(그대로/정장/블라우스/캐주얼 카드, specs-funnel.js 797~818)를 제거하고 attire-picker mount로 대체. lang 전달로 3언어 자동 해결.

**D6. 게이트 재정의.**
- `LEMONSQUEEZY_VARIANT_SPECS_SINGLE` = **결제 가용성 플래그로 축소** (퍼널 노출 게이트에서 분리 — 퍼널은 항상 노출, 미설정 시 유료 버튼만 비활성)
- market 분기(kr=토스 / global·jp=레몬 USD) 유지
- `V2_DIRECT_SLUGS(kr-passport)` 폐지 → 301 합류 (파일럿 졸업 정합, GSC 재색인 요청 동반)

**D7. 원가 fail-safe 재확인 (작가님 우려 대응).**
- 전역 캡 300회/일 유지 = 글로벌 개방해도 원가 상한 ~₩6,000/일 불변. 트래픽 증가 시 캡 상향은 작가님 단독 결정 항목으로 명시.
- 런팟 빌링 소진 → `FREE_UNAVAILABLE` → 3언어 안내 + 유료 길 개방 (현행 ko 동작의 3언어화)
- 쿼터 소진·글로벌 캡·매팅 불가 3종 상태의 로케일별 문구를 D3 사전에 포함

## 5. 리스크·롤백

- **결제 라이브 경로 변경** — 최대 리스크. 배포 전 dev에서 레몬 테스트 모드 검증, 배포 직후 실결제 1건 스모크. 롤백 = 직전 rev 재배포 (deploy.sh).

- 울트라코드 대규모 diff → P1/P2를 커밋 단위 분리 지시 (컴포넌트 추출 커밋 ≠ 분기 삭제 커밋), 리뷰 가능성 확보.
- '무료 전면 개방' 어뷰징 → 기존 레이트리밋 + 쿠키/IP 키 유지. 이상 트래픽은 소넷이 모니터링 항목에 추가 제안.
