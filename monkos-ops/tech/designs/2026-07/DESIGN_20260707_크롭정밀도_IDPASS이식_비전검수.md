## 1. 문제 — 왜 지금 크롭이 흔들리는가

현행 crop-engine은 FaceMesh로 턱(#152)·눈(#159/#386)을 잡고, 정수리를 **산술 추정**(눈~턱 거리를 위로 대칭)한다. 이 추정이 잔머리·두상 형태에 따라 흔들려 카나리 4연속 안착 가드 이탈이 발생했다.

IDPASS(앱)는 같은 FaceMesh를 쓰되 **1:1:1 원칙 + 수동 검수**로 이 문제를 해결한다. 웹에서는 수동 검수를 **Gemini 비전이 대행**한다.

---

## 2. 핵심 원칙 — IDPASS 1:1:1

```
┌─────────────────────┐ ← 프레임 상단
│     여백 (1)         │
├─────────────────────┤ ← 정수리
│                     │
│   머리 (1)           │
│                     │
├─────────────────────┤ ← 눈 높이
│                     │
│   얼굴 하부 (1)      │
│                     │
├─────────────────────┤ ← 턱
│     하단 여백         │
└─────────────────────┘ ← 프레임 하단
```

- **턱~눈 : 눈~정수리 = 1:1** — FaceMesh 턱·눈 실측 기반, 정수리를 대칭 산출
- **정수리~프레임상단 = 규격 여백** — headHeight(min_mm~max_mm)에서 역산
- 사람마다 두상·헤어로 벗어나는 부분을 **검수 단계**에서 보정

## 3. 현행 vs 목표

```
[현행] 원본 → precheck(규정 검수) → FaceMesh(실패 빈발) → 크롭 → 안착 가드
[목표] 원본 → Gemini 프리크롭(측정 가능성 검증) → FaceMesh(안정 입력) → 1:1:1 피팅 → 비전 검수 → 크롭 → 규정 검수(사후)
```

### 핵심 전환: precheck의 역할 재정의

```
[현행 precheck] "이 사진이 규격에 맞는가?" — 사전 규정 검수
[신규 precheck] "이 사진으로 측정이 되는가?" — 입력 품질 검증
```

| 단계 | 역할 | 체크 항목 |
|------|------|----------|
| **precheck (사전)** | 측정 가능성 | 얼굴 1명인가 / 얼굴 크기 적정한가 / 정면인가 / 심한 가림 없는가 |
| **크롭 후 (사후)** | 규정 검수 | 머리높이 범위 / 눈 위치 / 정수리 여백 / 배경 / 해상도 |

### 목표 파이프라인 — 전체 타임라인

모든 구성요소는 기존 자산(FaceMesh, crop-engine, BiRefNet, Gemini, precheck)의 **재배열**이다.

```
[0초] 사진 업로드 — 2개 동시 발사
      ├─ 🔵 Gemini 프리체크 (측정 가능성 판정)
      └─ 🟢 RunPod 의자 줄서기 (백그라운드 웜업)

[2~3초] 프리체크 결과
      ├─ ❌ 부적합 → 사유 안내 (얼굴 작음/다수/옆모습/가림), 재업로드 유도
      └─ ✅ 적합 → 프리뷰 + "이 사진으로 진행하시겠습니까?"

[사용자 "진행" 클릭] — 3개 순차 실행
      ① FaceMesh 감지 (프리체크가 정규화한 안정 입력) → 턱·눈 좌표
      ② crop-engine 1:1:1 예비 프레임 피팅 (규격 DB headHeight 기반)
      ③ Gemini 비전 검수 → 정수리·눈·동공·헤어끝 좌표 역제공
         → JSON: { crown_px, eye_px, hair_end_px, adjustment_y_px, pass }

[+2초] 클라이언트 가이드 오버레이 표시
      ├─ 정수리 라인 (비전 제공)
      ├─ 눈 높이 라인 (FaceMesh)
      ├─ 턱 라인 (FaceMesh)
      ├─ 헤어 끝단 (비전 제공)
      └─ 규격 프레임 — "실제 규격에 맞게 올리기" 액션
      (= IDPASS 카메라 가이드의 업로드 버전)

[이 사이 ~10~30초] 🟢 RunPod 의자 확보 완료

[사용자 "만들기" 클릭]
      ├─ 백엔드: BiRefNet 매팅 (0.4초, 이미 웜 상태)
      ├─ 백엔드: 규격 DB 최적값 + 비전 좌표 통합 → 확정 크롭 + 배경 합성
      └─ 결과물 노출

[결과 화면]
      ├─ 사후 검수 체크리스트 (✅머리높이 ✅눈위치 ✅배경 ✅해상도 ...)
      ├─ [다운로드] — 무료 티어
      ├─ [AI 보정] — ₩2,000 (Gemini 조명·피부 보정)
      └─ [다른 사진으로]
```

### 핵심 설계 원리

1. **병렬 은폐**: 의자 줄서기는 사용자가 프리체크·가이드를 보는 동안 백그라운드 완료
2. **측정 먼저, 규정은 나중**: precheck = "측정 되는가", 규정 검수 = 결과물 나온 뒤 사후 체크
3. **비전은 판단만, 실행은 코드**: Gemini가 좌표를 주면 crop-engine이 산술 처리
4. **가이드 = 신뢰 형성**: 사용자에게 "여기에 맞춰집니다"를 보여주는 순간이 전환 핵심
5. **기존 자산 재배열**: FaceMesh·crop-engine·BiRefNet·Gemini·precheck — 새 엔진 없이 순서만 재구성

## 5. 티어별 적용

| 티어 | 크롭 | 검수 | 비용 |
|------|------|------|------|
| **무료** | 1:1:1 프레임 피팅 + 코드 검수(FaceMesh 수치 기반 자동 판정) | Gemini 비전 없음 | ₩0 |
| **AI 보정 ₩2,000** | 1:1:1 + **Gemini 비전 검수** (정수리·헤어·눈 위치 정밀 판독) + 산술 보정 | Gemini 2.0 Flash | ₩수십 |
| **프리미어** | AI 보정 + 발급보장 + 인화 | Gemini + QA | 별도 |

무료 티어에서도 현행보다 정밀도가 올라감 — 1:1:1 산식 + headHeight 범위 가드. Gemini 비전은 유료 부가가치.

## 6. Gemini 프롬프트 설계 (초안)

### 6-1. 프리크롭 (①단계, 업로드 직후)

```
이 사진에서 증명사진을 만들 수 있는지 판정하세요.
JSON으로 응답:
1. face_count: 감지된 얼굴 수
2. face_box: 주요 얼굴의 바운딩 박스 [x, y, w, h] (픽셀)
3. face_ratio: 얼굴이 이미지 전체에서 차지하는 비율 (0~1)
4. frontal: 정면인가 (true/false)
5. occlusion: 심한 가림이 있는가 (true/false)
6. measurable: FaceMesh 정밀 측정이 가능한 입력인가 (true/false)
7. rejection_reason: measurable=false일 때 사유 (face_too_small/multiple_faces/side_angle/occluded/no_face)
```

→ measurable=true면 face_box 기준 러프 크롭 → FaceMesh에 전달. false면 사용자 안내 후 차단.

### 6-2. 비전 검수 (④단계, 프레임 피팅 후)

```
이 이미지는 증명사진 규격 프레임(초록선)이 원본 위에 오버레이된 것입니다.
규격: {country} {type}, 프레임 {w}×{h}mm, 머리높이 {min}~{max}mm

다음을 JSON으로 판정하세요:
1. crown_ok: 정수리가 프레임 안에 있는가 (true/false)
2. crown_margin_px: 정수리~프레임 상단 여백 (픽셀, 음수면 잘림)
3. hair_overflow: 머리카락이 프레임 밖으로 과도하게 나갔는가 (true/false)
4. eye_center_ratio: 눈 높이가 프레임 높이의 몇 % 위치인가 (0=상단, 100=하단)
5. adjustment_y_px: 프레임을 위/아래로 몇 픽셀 이동해야 최적인가 (양수=아래, 음수=위)
6. pass: 현재 상태로 규격 통과 가능한가 (true/false)
```

→ 코드는 `adjustment_y_px`만 받아서 프레임 위치를 산술 보정. Gemini는 **판단만**, 실행은 코드.

## 7. 구현 범위

### Phase 1: 코드 검수 강화 (무료 티어 즉시 개선)
- specs-data.json에 headHeightMin/Max 수치 필드 병합
- crop-engine 1:1:1 산식 정식 적용 (현행 IDPASS 산식 기반, 이미 일부 이식됨)
- 코드 기반 자동 검수: headHeight 범위 가드 + 눈 위치 비율 체크 + 정수리 추정 신뢰도
- 가드 이탈 시 faceTarget 조정 → 재크롭 (현행 1회 → 3회까지)

### Phase 2: Gemini 비전 검수 (유료 티어)
- 프레임 오버레이 캡처 생성 → Gemini 2.0 Flash 비전 호출
- JSON 응답 파싱 → 산술 보정 → 최종 크롭
- 무료 티어 결과물과 비전 검수 결과물 A/B 비교 실측

### Phase 3: 확산
- kr-passport 파일럿 검증 후 전 규격 확산 (MATTE_SLUGS 확장)

## 8. 리스크

1. **Gemini 비전 비용**: 검수용 이미지 1장 + 프롬프트 → 건당 ₩수십. 유료 티어에서만 사용하면 ₩2,000 매출 내 감수
2. **비전 판단 정확도**: Gemini가 정수리를 잘못 판독할 가능성. 코드 가드(headHeight 범위)가 최종 안전망
3. **규격 DB 병합 공수**: 428건 headHeight 파싱·수치화 필요. v2 데이터 정본이 있으니 매핑 작업
