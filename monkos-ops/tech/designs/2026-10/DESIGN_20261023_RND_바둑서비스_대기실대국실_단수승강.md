# 바둑 서비스 구조 설계서 — 대기실·대국실·단수 승강

> 출처: 작가님 2026-10-23 저녁 대화(사람 턴, iMac 쌍아 세션) — "방 개념이 없어 한 방에 지난 대국이 떠 있다 → 대국실·대기실", "마이페이지·CMS·기보 저장·채팅", "대기실 채팅·초청·강의 대국, 참여자 단수별 목록, 가입 시 단수 설정, 최근 20국 기준 승강·10연승 자동 승급", "승강제는 회원끼리도 적용, 초기 설정 최대 5단, 대부분 타이젬 준용, 차후 크레딧 내기 가능 구조", "테스터 50명 차차 모집, 라이브엔 GPU(RunPod·4060은 그때)".

## 1. 현재(PoC)와 한계

| 항목 | 지금 (go.monkos.ai, 10-23) | 한계 |
|---|---|---|
| 판 | 서버 1개 = 판 1개 | 지난 판이 그대로 떠 있음 · 재시작 시 판 소실 · 두 사람이 같은 판 |
| 사용자 | 구분 없음(Access 임시 개방) | 마이페이지·전적·단수 불가 |
| 엔진 | iMac GPU(Radeon) KataGo — 최강 1500v·17초, 급수=humanSL | 동시 여러 판 시 지연 · iMac 꺼지면 중단 |
| 기보 | iMac 로컬 SGF | 사용자별 보관·공유 없음 |
| 해설·리뷰 | review.py(Haiku) + 대화형 참고도 | 방·사용자 단위로 묶여 있지 않음 |

## 2. 구조

```
[사용자 폰·PC]
   │  포털 로그인(OAuth)·크레딧(공용 원장)
   ▼
[바둑 서비스 앱]  대기실 · 대국실 · 마이페이지 바둑 칸 · 채팅 · 기보 · 단수/승강
   │  방 상태 저장(Firestore) · 기보 파일(GCS)
   ▼
[엔진 서버(GPU)]  KataGo 최강 · humanSL 급수 · 분석(형세·복잡도) · 리뷰
   지금 iMac → 테스터/라이브: RunPod 또는 재구축 4060 (주소만 교체, 매팅 체인과 같은 패턴)
```

- **엔진 서버는 계산만** 한다(무상태 API: 국면 + 설정 → 수·분석). 방 상태는 앱이 갖는다 → 엔진을 바꾸거나 늘려도 방이 안 깨진다.
- **로그인·크레딧·마이페이지는 포털 것을 쓴다**(idphoto-kr이 `PORTAL_API_URL`로 크레딧·OAuth를 소비하는 방식과 동일). 바둑 전용 회원 체계를 따로 만들지 않는다.
- 테스터 단계 임시 인증: Cloudflare Access가 넘기는 로그인 이메일(`Cf-Access-Authenticated-User-Email`)로 사용자 식별 → 라이브에서 포털 계정으로 이관.

## 3. 화면

### 3-1. 대기실
- **참여자 목록 — 단수별 묶음**(9단 → 1단 → 1급 → 18급), 상태 표시(대기·대국 중·관전 중).
- **대기실 채팅**(전체 1채널). 라이브 전: 신고·차단·금칙어.
- **대국 신청 3종**
  - **초청 대국**: 목록에서 상대 선택 → 치수·덤 자동 제안(§4 치수표), 조정 가능 → 수락 시 대국실 생성.
  - **강의 대국**: 강사 1 + 수강자 N. 강사가 판 위에 참고도(번호 수순)를 놓으면 전원에게 보임, 수강자는 채팅 질문. 대화형 참고도(review.py)·해설 기능 재사용.
  - **AI 대국**: 지금의 수준 선택(최강 / 사람형 급수).
- **내 진행 중 대국**(이어 두기) · **지난 대국**(결과·기보·리뷰 바로가기).

### 3-2. 대국실
- 지금 화면(모바일: 판·하단 착수 버튼·시간, 'AI분석' 시트) + **방 고유 주소 `/room/{id}`** — 새로고침·앱 재실행·서버 재시작에도 같은 판.
- 관전자 입장(읽기 전용), 대국자 채팅, 종국 후 리뷰 버튼.

### 3-3. 마이페이지 바둑 칸(포털 마이페이지 안)
- 현재 단수·임시 여부, 최근 20국 전적과 승강까지 남은 조건, 전체 전적, AI 대국 전적(별도), 기보 목록(내려받기·공유), 리뷰 모음.

## 4. 단수·승강 규정(초안 — 타이젬 준용, 실제 타이젬 규정과 대조 후 확정)

| 항목 | 규정 | 상태 |
|---|---|---|
| 가입 시 신고 | 18급 ~ **최대 5단**(작가님 확정). 그 위는 대국 결과로만 | 확정 |
| 임시 단수 | 첫 10국: 승패에 따라 한 번에 두 단계까지 조정 | 초안 |
| 승급 | 최근 20국 중 14승 이상(70%) → +1 · **10연승 → 즉시 +1** | 10연승은 작가님 제시, 20국 기준 확정 · 70%는 타이젬 대조 |
| 강급 | 최근 20국 중 6승 이하(30%) → −1 · 10연패 → 즉시 −1 | 초안 |
| 승강 후 | 카운트 초기화, 새 단수에서 다시 20국 | 초안 |
| 반영 대국 | **회원끼리 둔 정식 대국 반영**(작가님 확정). 친선·강의 제외 | 확정 |
| AI 대국 | 단수에 반영하지 않고 'AI 전적'으로 별도 표시(권장 — AI 약점 공략으로 단수 올리기 방지) | 작가님 결정 대기 |
| 중도 이탈 | 이탈·시간 초과 = 패 | 초안 |
| 치수 | 단수 1차 = 1점 · 같은 단수 호선(흑 6집반 공제) · 1차 정선 · 2차부터 접바둑(덤 반집) | 초안 |

> 타이젬 실제 승강 규정은 공개 도움말로 열람·대조(브리지 계정의 일반 열람 범위) — 대조표를 이 절에 붙인 뒤 확정.

## 5. 대국 포인트와 내기(칸만 마련 — 법률 확인 대기)

- **유료 크레딧(돈으로 구매)** 과 **대국 포인트(무상 지급·구매 불가·현금화 불가)** 를 처음부터 분리한다.
- 내기는 대국 포인트로만 가능한 구조로 설계해 두고, 유료 크레딧과의 연결(내기·환전·구매)은 **법률 검토 후** 결정한다.

### 5-2. 설계 결론(법률 자문 전 잠정)
- **현금으로 바뀌는 순간 사행성**: 환전·재매입·알선은 금액과 무관하게 금지 → 대국 포인트는 **환전·재매입·회원 간 현금 거래 경로를 원천 차단**(포인트 → 크레딧 역교환도 없음).
- **무상 포인트 내기 + 초청(상대 선택)**: 웹보드 규제가 적용되더라도 라-1) 예외에 해당하도록 **무료 지급 별도 포인트만** 내기에 쓴다 → 대기실 초청 내기 대국과 양립.
- **유료 크레딧으로 내기**(구매 가능 게임머니): 바둑이 웹보드에 포함되면 월 100만원·1회 1/10·상대 선택 금지(초청 불가 — 1/200 이하 소액 예외)·본인확인 적용. 포함 여부 불명 → **출시 전 법률 자문 + 게임물관리위원회 질의** 후 결정. 기본값은 미도입.
- 등급: 내기 기능이 있으면 게임물 등급분류(청소년이용불가 가능성 — 타이젬 앱 19+) 대상 — 출시 전 확인.

## 6. 실시간 해설과 분석 깊이

- 전수 분석하되 깊이는 복잡도로 배분: 평이 국면은 얕게(~100v), 복잡도 상위(승부처)는 깊게(1000v+). 관전 분석판의 복잡도 v0(rawStWrError·소유 불확실성·후보 분산)이 입력. 같은 지표로 AI 상대의 '사람다운 생각 시간'(쉬운 수 3~8초, 승부처 30~60초)도 배분.
- 해설 문장은 해설 LLM 3층 구조(사건 판정 → 언어 사전 → LLM, 관련 설계서) — 표기는 실전도·참고도·A/B(10-23 작가님 피드백).
