# DESIGN — 스토어 제출 자동화 (store_kit)

**[2026-11-06 06:00 KST]** iMac/쌍아 → 작가님

출처: 작가님 2026-11-06 05:59 iMac/쌍아 세션 사람 턴 — "idpass 때 해보니 거기서 언어 넣어주고 스크린 캡처 넣어주고 하는 일들이 무지 번잡하더군. idpass 경험이 있으니 패턴화해서 최대한 자동으로 심사까지 가능하도록 도구를 짤 필요가 있겠어". IDPASS 이력은 record-explorer(서브에이전트, 06:00)가 조사했다. 근거 경로는 §1.

## 0. 결론

`AI_Factory/store_kit/` 한 도구로 **원본 1장(store.yaml) → 검사 → 생성 → 업로드 → 심사 제출 직전**까지 자동화한다. 공식 API를 쓴다(App Store Connect API·Google Play Developer API — fastlane `deliver`·`supply`·`snapshot`·`frameit` 기반). 사람 손은 **API 키 1회 발급**과 **심사 제출 버튼**(외부 발송 = 승인 게이트) 둘만 남긴다. 리젝이 나면 사유를 장부에 넣고, 다음 제출부터 사전 점검이 그 사유를 막는다.

## 2. 구성

```
store_kit/
  store.yaml            # 앱별 원본: 이름·부제·설명·키워드·카테고리·URL·연령·개인정보 답·심사 메모(한국어 1벌 + 고정 번역 덮어쓰기)
  check.py              # 사전 점검: 글자 수·금칙어·리젝 장부·필수 규격·알파·라벨↔코드·빌드 번호·암호화 답
  gen_text.py           # 번역 생성(LLM) + 사람 검수용 표(한 눈 대조) — 확정본은 store.yaml에 고정
  gen_shots.py          # 촬영 모드 실행(시뮬레이터·FTL) → 규격 리사이즈·문구 띠·언어별
  push.sh               # fastlane deliver/supply — 메타·스크린샷·빌드 업로드(심사 제출 제외)
  submit.sh             # 심사 제출 — 작가님 '배포 승인' 토큰 있을 때만(E10 훅과 연동)
  rejections.md         # 리젝 장부(사유·가이드라인 번호·언어·대응 규칙) — check.py가 읽는다
```

- 앱별 폴더: `store_kit/apps/{monkos-go,idpass}/store.yaml`. IDPASS 현행 메타는 API로 끌어와 원본화한다(역수입).
- 시크릿: ASC API 키(.p8)·Play 서비스 계정 JSON·업로드 키스토어는 SM 등록 → `secret.sh` 경유. 값은 출력·커밋하지 않는다.

## 3. 단계 (작은 단위)

1. **v0 점검기**: `check.py` + `rejections.md`(2.3.7 1행). IDPASS 현행 메타를 수동 내보내기로 넣어 시험한다. 키는 필요 없다.
2. **v1 API 연결**: 작가님 ASC API 키 발급 → 읽기(앱·버전·빌드 번호 조회) → IDPASS 메타 역수입.
3. **v2 스크린샷**: MONKOS Go 촬영 모드 + 규격 생성(오늘 FTL Game Loop 캡처 장치 재사용).
4. **v3 업로드**: 메타·스크린샷 업로드 → 심사 제출은 submit.sh(승인 게이트).
5. **v4 Play**: 서비스 계정·업로드 키 → 내부 테스트 트랙.

## 4. 작가님 손이 필요한 곳

- App Store Connect API 키 발급 1회(사용자·액세스 → 통합 → App Store Connect API, 역할 'App Manager' 권장). Play Console 서비스 계정 연결 1회.
- 번역 최종 검수(원하실 때만 — 기본은 자동 + 금칙어 검사).
- 심사 제출 '배포 승인'.

## 5. 출시 전 확인 칸

- 가이드라인 원문(App Review Guidelines·Play 정책) 1차 출처를 장부 규칙마다 링크한다. 기억으로 쓰지 않는다.
- 번역 품질: 언어별 원어민 표현은 LLM 초안 + 금칙어 검사까지가 자동 범위다.
