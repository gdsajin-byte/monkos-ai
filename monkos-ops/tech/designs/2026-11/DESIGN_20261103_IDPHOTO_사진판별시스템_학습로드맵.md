# DESIGN — 사진 판별 시스템 학습 로드맵

**[2026-11-03 19:00 KST]** iMac/쌍아 → 작가님

## 0. 결론

사진사가 실제로 출고한 결과를 정답으로 삼아 판정 모델 네 개를 만든다. 순서는 **정답이 기계로 나오는 것부터**다(규격 → 동일인·보정 → 컷 선택). 각 모델은 작게(0.005~0.1B), 공개 비전 모델 위에 덧입혀 학습하고, 최종 결정은 코드 게이트가 한다. 첫 모델은 **규격 판정**이며 클라이언트(브라우저)에서 돈다.

## 1. 완성 그림

```
업로드 ─▶ [클라이언트] 규격 판정 모델 (≤0.02B, ONNX)  ── 즉시: 머리끝·눈·턱·화각·잘림
              │  (노출돼도 되는 판정만)
              ▼
         [서버] 코드 게이트(규정 수치) ── 결제·생성 허용
              ▼
AI 생성 ─▶ [서버] 동일인·과보정 모델 (0.02~0.1B) ── 출고 전 자동 검수 (헌법 1조 3항의 기계 기준)
              ▼
         [서버] 품질(컷 선택) 모델 ── 여러 컷 중 추천 · 사진관 셀렉 보조
              ▼
         경계 사례만 사람(작가님·꾸) 감수 → 다음 학습의 정답지로 환류
```

## 2. 정답지 — 어디서 오는가

| 판정 | 정답지 | 얻는 방법 | 사람 손 |
|---|---|---|---|
| 규격(크롭·머리끝·눈 높이·얼굴 크기) | 출고본의 크롭 위치 | 원본↔출고본 이미지 정합으로 크롭 상자·회전·배율 자동 추출 + 얼굴 랜드마크 | 없음 |
| 규격 종류 | 폴더명 `(여권)` `(증명)` `(베트남비자)` … | 폴더명 파싱 → 규격 코드 사전 | 사전 1회 |
| 동일인 | "출고됨 = 본인으로 인정" | 공개 얼굴 임베딩(ArcFace 계열) 유사도 분포 → 합격선 | 경계 사례 감수 |
| 과보정 | 원본↔출고본 차이 분포(피부 매끄러움·윤곽 이동·눈 크기) | 분포 범위 = 몽크 적정 보정, 밖 = 과보정 | 경계 사례 감수 |
| 좋은 사진(컷 선택) | 사진사가 고른 컷 vs 안 고른 컷 | 같은 고객 폴더 안의 선택/비선택 짝 | 없음 (단, 비선택 컷이 남아 있어야 함) |

## 3. 단계 (작은 단위 — 단계마다 게이트 통과 후 다음)

### P0. 재고·정합 가능성 (1~2일)
- 시놀로지(`gdsajin` 172.30.1.50) 마운트(작가님) → 읽기 전용 집계: 규격별·연도별 고객 폴더 수, 파일 형식(CR3·JPG·PSD 등), 원본·출고본 짝 비율, **비선택 컷 보존 여부**.
- 표본 50쌍으로 정합 시험: 원본(CR3 현상) ↔ 출고본 크롭 상자 추출 성공률·오차(px).
- 게이트: 짝 확보 ≥ 5,000쌍 + 정합 성공률 ≥ 90% → P1. 미달이면 원인 보고(출고본 위치·명명 규칙).

### P1. 데이터 파이프라인 (3~5일)
- RAW 현상(CR3 → 표준 JPEG, 고정 설정), 정합 → 라벨(JSON: 규격 코드·크롭 상자·랜드마크·회전), 품질 검사(정합 실패·얼굴 미검출 제외).
- **가명화**: 폴더명의 고객 이름은 해시 ID로 바꾸고, 라벨·로그·보고서에 이름을 남기지 않는다. 원본 픽셀은 학습 기기 밖으로 나가지 않는다.
- **분할**: 기간 기준(예: 최근 3개월 = 시험 세트). 같은 고객이 학습·시험에 동시에 들어가지 않게.
- 산출: 학습 세트 매니페스트 + 데이터 카드(규격별 분포·기간·제외 사유 표).

### P2. 모델 1 — 규격 판정 (1주)
- 구조: 공개 소형 비전 모델(MobileNetV3·EfficientNet-B0·DINOv2-S 중 라이선스 Apache/MIT·크기 기준 택1) + 출력 머리(머리끝·눈·턱 좌표 + 크롭 상자 + 잘림/화각 판정). **0.005~0.02B**.
- 학습: 4060(RTX 4060 8GB) 파인튜닝. 바둑 파일럿과 GPU 시간 분할.
- 평가: 시험 세트에서 (a) 출고 크롭 대비 오차 mm (b) 규정 수치 통과율 (c) 현행 규칙 엔진(precheck·hair-measure)과 판정 일치율·불일치 사례 표 (d) 기본 테스트 이미지·공개 표본·히잡·아기·대머리 등 취약군.
- 게이트: 현행 엔진보다 오차 작음 + **잘린 사진 통과 0** + 취약군 실패 목록 공개.
- 배치 준비: ONNX 8비트, 브라우저 실행 시간·용량 실측(목표 ≤20MB·≤0.3초 중급 폰).

### P3. 그림자 운영 (1~2주, P2 통과 후)
- 클라이언트 모델을 **켜되 결정에는 쓰지 않는다**. 현행 서버 판정과 나란히 로그만(판정·좌표·시간). 불일치 사례 주간 표.
- 게이트: 불일치 중 모델이 틀린 비율 기준 충족 → 클라이언트 판정을 1차로, 서버는 결제·생성 직전 재확인.

### P4. 모델 2 — 동일인·과보정 (2주)
- 동일인: 공개 얼굴 임베딩(라이선스 확인) 그대로 + 우리 출고 분포로 합격선 보정. 과보정: 차이 지표 → 소형 분류기(0.02~0.1B 또는 지표+규칙).
- 감수: 분포 끝단 300건을 작가님·꾸가 판정(약 1~2시간 분량) → 합격선 조정.
- 적용: AI 생성(₩2,000) 결과 출고 전 자동 검수 — 불합격은 출고하지 않고 재생성·환불 동선(무음 강등 금지).
- 서버 전용(가중치 비공개).

### P5. 모델 3 — 컷 선택 (P0에서 비선택 컷이 확인될 때만)
- 같은 고객의 선택/비선택 짝으로 선호 학습. 사진관 셀렉 보조·앱 다중 컷 추천.

## 4. 공통 골격 (바둑 파일럿과 공유)

데이터 매니페스트 → 학습 설정(파일 1개) → 체크포인트 → 고정 시험 세트 평가 → 결과 표·곡선 → 모델 등록(버전·데이터 버전·지표). 바둑 `AI_Factory/go_train/`에서 만든 측정·기록 틀을 `AI_Factory/photo_judge/`로 복제한다.

## 6. 위험·모르는 것

- 출고본의 위치·명명 규칙 미확인(드라이브 표본은 CR3 원본만). → P0에서 확정.
- 출고본이 보정·리사이즈·인화용 배치(여러 장 한 판)일 경우 정합이 어려움 → 정합 방식 분기.
- 시기별 촬영 장비·조명 변화 → 기간 분할 평가로 드러냄.
- 공개 기반 모델·얼굴 임베딩의 상업 라이선스 → 채택 전 1차 출처 확인(출시 전 확인 칸).
- 클라이언트 모델은 복제될 수 있다 → 노출돼도 되는 규격 판정만 내보낸다.

## 8. 학습 자료 형태 — 파일 분류·고객 레코드·정답지 (P0 실측 반영)

**[2026-11-03 20:16 KST]** iMac/쌍아 → 작가님 — 출처: 작가님 20:16 "학습 자료형태를 설계해, 파일명에 sv는 서비스 컷으로 나가는 거야, 모두 파악이 수월한지 소팅부터 해봐".

### 8-1. 저장소 두 곳 (11-03 실측, 경로·크기만)

| 공유 | 역할 | 규모 |
|---|---|---|
| `촬영접수` | 촬영 원본(셀렉 RAW) — 건대 시대는 PSD·JPG까지 | 고객 폴더 7,118 |
| `작업백업` | 하남 시대 완성본(월 단위 이관, 꾸) | 2024~26 고객 폴더 4,962 · 파일 ≈2.8만 |

두 곳은 고객 폴더 앞머리 **`YYYYMMDD_NNN`**(날짜_순번)으로 짝지어진다 — 이게 고객 레코드의 키다.

### 8-2. 파일 분류 규칙 (파일명·확장자만으로)

| 분류 | 규칙 | 의미 |
|---|---|---|
| `raw` | `.CR2` `.CR3` | 촬영 원본(셀렉 컷). 하남은 `YYYYMMDDhhmmss.CR3` 카메라 타임스탬프명 |
| `sidecar` | `.xmp` `.acr` `.cos` `.cop` `.cof` | 보정 조정값(크롭·회전·노출). `.xmp`는 같은 타임스탬프명 RAW와 1:1 |
| `master_tif` | `.tif` `이름님.tif` 등 | 보정 완료 전체 프레임(규격 크롭 전) |
| `spec_final` | `이름님_{용도}.jpg` (여권·증명·민증운전·운전·민증·미국비자·중국비자·사원증·이력서 …) | **규격 완성본 = 규격 정답** |
| `service_sv` | `이름님_sv[n].jpg` | **서비스 컷**(규격 외 추가 제공) — 보정 강도·표정 기준의 정답 |
| `print_layout` | `4R(3.5x4.5).psd`, `인화만4x6` 등 | 인화 배치판(여러 장 한 판) — 학습 제외, 수량·규격 확인용 |
| `psd_work` | 그 밖의 `.psd` | 작업 파일(건대 시대 주력) |
| `before_retouch` / `*re` | `보정전` · `여권re` | 보정 전 / 재보정 — 보정 차이·재작업 사례 |

### 8-3. 고객 레코드 완성도 (11-03 실측, 고객 수)

| 연도 | 고객 | RAW | 사이드카 | 마스터 TIF | 규격 완성 | sv | **RAW+규격** | **RAW+규격+sv** | RAW+사이드카 |
|---|---|---|---|---|---|---|---|---|---|
| 2023 | 1,020 | 943 | 22 | 2 | 160 | 0 | 150 | 0 | 22 |
| 2024 | 2,545 | 2,541 | 877 | 1,661 | 1,757 | 1,581 | 1,753 | 1,567 | 875 |
| 2025 | 2,563 | 2,557 | 2,522 | 2,554 | 2,513 | 2,436 | 2,509 | 2,422 | 2,518 |
| 2026 | 1,002 | 999 | 738 | 671 | 716 | 653 | 715 | 644 | 738 |
| **합계** | **7,130** | 7,040 | 4,159 | 4,888 | 5,146 | 4,670 | **5,127** | **4,633** | 4,153 |

- 하남 시대(2024 하반기~)는 거의 모든 고객이 **RAW + 사이드카 + 마스터 TIF + 규격 완성 + sv** 다섯 층을 갖는다 — 판별 학습에 이상적.
- 2023(건대)은 규격 완성 파일명이 다른 규칙(PSD 작업 + 무용도 JPG) — 별도 분류 규칙 필요(P1).
- 2026 최근분은 월 단위 이관 전이라 일부 빈칸(정상).

### 8-4. 학습 레코드 형식 (고객 1명 = JSONL 1행, 가명화)

```json
{
  "id": "c_9f3a…",                 // YYYYMMDD_NNN의 해시 — 이름·폴더명 미기록
  "era": "hanam",                    // gundae(~2024-05) | hanam
  "date": "2025-03",                 // 월 단위까지만
  "purpose": ["여권", "민증운전"],     // 폴더명 (용도) + 규격 완성 파일명
  "raw":   [{"path_ref": "r1", "w": 6000, "h": 4000}],
  "sidecar": [{"path_ref": "x1", "for": "r1", "crop": [l, t, r, b], "angle": 0.4}],
  "master": {"path_ref": "m1"},
  "spec_final": [{"path_ref": "f1", "purpose": "여권", "wh": [413, 531],
                  "crop_in_raw": [l, t, r, b]}],     // 정합 또는 사이드카에서
  "service": [{"path_ref": "s1"}],
  "flags": {"re": false, "before_retouch": false}
}
```

- `path_ref`는 별도 비공개 매핑 파일(학습 기기 안에만)로 실제 경로를 가리킨다 — 매니페스트만 돌아다녀도 고객이 드러나지 않게.
- 파생 정답: 규격 판정 = `crop_in_raw`·`purpose` / 보정 판정 = `master`↔`raw` 차이, `service`↔`spec_final` 차이 / 동일인 = `raw`↔`spec_final` 얼굴 임베딩 / (P5) 컷 선택 = 맥북 셀렉 기록기 이후.
