## 0. 요약 (Executive Summary)

포털 홈을 **iCloud 스타일 타일(박스) 그리드**로 전면 개편한다.
기존 3컬럼 사이드바 구조를 걷어내고, 모든 콘텐츠를 독립적인 타일 단위로 배치하여
**"블로그 사이트"에서 "서비스 플랫폼"으로** 인식을 전환한다.

| 항목 | v4 (현재 preview) | v5 (제안) |
|------|------------------|-----------|
| 레이아웃 | 3컬럼 (좌 사이드바 / 중앙 / 우 사이드바) | **타일 그리드** (12컬럼 CSS Grid, 사이드바 없음) |
| 첫 인상 | 블로그/매거진 사이트 | **서비스 플랫폼 대시보드** |
| 서비스 진입 | 텍스트 카드 2개 (증명사진/크롭앱) | **Apps 타일** — 아이콘 그리드 6+ 서비스 |
| 확장성 | 사이드바 내 콘텐츠 추가 시 지저분 | 타일 추가만으로 확장 (어드민 레이아웃 매니저와 연동) |
| 모바일 | 좌우 사이드바 비노출 (콘텐츠 유실) | 타일 세로 스택 (모든 콘텐츠 유지) |

## 1. 개편 배경

### 1-1. 문제 진단

**꾸님 피드백**: "사이드바가 지저분해 보인다"
— 좌측 매거진 + 태그클라우드, 우측 영상목업 + 크레딧이 중앙 콘텐츠와 시각적으로 경쟁하면서 시선이 분산됨.

**구조적 문제**:
- 좌우 사이드바는 모바일에서 완전 비노출 → 데스크톱 전용 콘텐츠가 됨
- 사이드바 콘텐츠(매거진, 영상, 크레딧)는 중요도가 높은데 부속물 취급
- 중앙에 텍스트 소개문 + 블로그 카드가 먼저 보여서 "블로그 사이트" 인식 형성
- v4의 3컬럼은 note.com 프로필 차용이었으나, MONKOS는 서비스 플랫폼이므로 포털 패턴이 더 적합

**작가님 방향 지시**: "iCloud처럼 전체를 박스들의 형태로. Apps 박스 안에 서비스 아이콘, 블로그/영상도 별도 박스."

### 1-2. 참고 모델: iCloud.com

iCloud.com은 2022년 리디자인 이후 타일 기반 대시보드를 채택:
- 배경 위에 독립적인 타일(박스)들이 그리드 배치
- 각 타일 = 하나의 서비스 또는 기능 그룹
- "Apps" 타일 안에 여러 앱 아이콘이 그리드로 배치
- Photos, Mail, Notes 등은 미리보기 콘텐츠를 포함한 타일
- 사용자가 타일 구성을 커스터마이즈 가능

## 2. 타일 구조 설계

### 2-1. 그리드 시스템

```
12컬럼 CSS Grid | max-width: 960px | gap: 16px
```

각 타일은 `grid-column: span N` 으로 크기 지정.
모바일에서는 4컬럼으로 전환, 모든 타일이 `span 4` (풀폭 스택).

### 2-3. 타일 상세 스펙

| 타일 | span | 내부 구조 | 데이터 소스 | 비고 |
|------|------|----------|-----------|------|
| **Apps** | 8 | 아이콘 그리드 (4×2 또는 유동) | 정적 config (어드민 토글 가능) | 서비스 증감 시 아이콘 추가/제거만 |

| **블로그** | 8 | 4칸 카드 그리드 (thumb + title + lang) | Firestore `blog_posts` | SSR + 다국어 필터 |
| **영상 가이드** | 4 | 세로 리스트 (thumb 9:16 + title) | 정적 또는 YouTube API | 숏폼 썸네일 실 배치 |
| **Before/After** | 6 | 가로 스크롤 pair strip | 정적 에셋 (실 사진) | note.com 기존 에셋 활용 |
| **고객센터** | 6 | FAQ 3문항 (Q + 1줄 A) | Firestore `faq` | 전체보기 → /faq 라우트 |
| **활용법** | 12 | 3단계 스텝 카드 | 정적 | SEO 텍스트 콘텐츠 |
| **매거진** | 8 | 가로 스크롤 카드 (cover + title) | Firestore `blog_posts` (pinned/featured) | 태그 기반 필터 |
| **게시판** | 4 | 최근 글 3건 리스트 | Firestore `board` | 전체보기 → /board |

## 5. 기술 구현 방향

### 5-1. CSS Grid 기반

```css
.tile-grid {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: 16px;
  max-width: 960px;
  margin: 0 auto;
}

.tile { grid-column: span N; }  /* N = 4, 6, 8, 12 */
```

반응형 브레이크포인트:
- **Desktop** (>768px): 12컬럼, 타일 원본 span
- **Mobile** (≤768px): 4컬럼, 모든 타일 span 4 (풀폭 스택)
- 태블릿 중간 단계는 선택적

### 5-2. 어드민 레이아웃 매니저 연동

기존 합의된 Level 2 레이아웃 매니저와 직결:

```json
{
  "tiles": [
    { "id": "apps",    "span": 8, "order": 1, "visible": true },
    { "id": "credits", "span": 4, "order": 2, "visible": true },
    { "id": "blog",    "span": 8, "order": 3, "visible": true },
    { "id": "video",   "span": 4, "order": 4, "visible": true },
    { "id": "gallery", "span": 6, "order": 5, "visible": true },
    { "id": "faq",     "span": 6, "order": 6, "visible": true },
    { "id": "howto",   "span": 12,"order": 7, "visible": true },
    { "id": "magazine","span": 8, "order": 8, "visible": true },
    { "id": "board",   "span": 4, "order": 9, "visible": true }
  ]
}
```

어드민에서:
- 타일 표시/숨김 토글
- 순서 변경 (order)
- span 크기 조정 (4/6/8/12)

### 5-3. 파일 구조 제안

```
public/
├── index.html          ← v5 진입점 (타일 그리드 셸)
├── css/
│   └── portal.css      ← 타일 시스템 + 반응형
├── js/
│   ├── tiles.js        ← 타일 렌더링 엔진 (config → DOM)
│   ├── i18n.js         ← 기존 유지
│   ├── auth.js         ← 기존 유지
│   ├── credits.js      ← 기존 유지
│   └── chat.js         ← 기존 유지
```

**핵심**: `tiles.js`가 어드민 config를 읽어 타일을 동적 렌더링.
각 타일은 독립적인 렌더 함수 (`renderAppsTile()`, `renderBlogTile()` 등).

### 5-4. SSR 고려

홈 타일 콘텐츠 중 SEO 크리티컬 항목:
- 블로그 (제목/발췌 텍스트) → SSR 필수
- FAQ (질문/답변 텍스트) → SSR 필수
- 활용법 (정적 텍스트) → 정적 HTML로 충분
- Apps, 크레딧, 영상 → 클라이언트 렌더 가능

기존 `render.js` fragment 구조를 타일 단위로 확장:
```javascript
// lib/cms/render.js
function renderHomeTiles(config, blogData, faqData) {
  return config.tiles
    .filter(t => t.visible)
    .sort((a, b) => a.order - b.order)
    .map(tile => {
      switch(tile.id) {
        case 'apps':    return renderAppsTile(tile);
        case 'blog':    return renderBlogTile(tile, blogData);
        case 'faq':     return renderFaqTile(tile, faqData);
        // ...
      }
    }).join('');
}
```

## 10. v4 차단 이슈와의 관계

v4 롤백 원인이었던 "컨텐츠 카드 인터랙션 미동작"은 v4의 3컬럼 + 외부분리 JS 구조에서 발생한 문제.

v5는 타일 렌더링 엔진을 새로 설계하므로, v4 카드 버그를 우회하는 것이 아니라 **구조 자체를 재설계**하여 해소한다. 다만 v4에서 구현된 아래 자산은 v5에 계승:

- ✅ CSS/JS 외부 분리 구조
- ✅ render.js fragment 시스템 (타일 단위로 확장)
- ✅ 블루/그린 배포 파이프라인
- ✅ CMS 플랫폼 (블로그/FAQ/갤러리/게시판 + 자동번역)
