## 1. 개요

### 1.1 프로젝트 정의

MONKOS CMS 블로그 에디터(이하 "본 시스템")는 다국어 콘텐츠 제작·번역·배포를 단일 인터페이스에서 수행하는 웹 기반 콘텐츠 관리 에디터이다. WYSIWYG 편집, AI 자동 번역, 이미지 자산 관리, 시드 기반 콘텐츠 기획, 실시간 리서치를 통합한 올인원 에디터 워크스테이션으로 설계되었다.

### 1.2 기술적 차별성

| 항목 | 기존 CMS (WordPress, Ghost 등) | 본 시스템 |
|------|-------------------------------|----------|
| 다국어 처리 | 플러그인 의존, 수동 번역 | AI 자동 번역 내장 (Gemini 2.0 Flash) |
| 이미지 관리 | 별도 미디어 라이브러리 | 에디터 내 통합 이미지 뱅크 + 실시간 WebP 변환 |
| 콘텐츠 기획 | 별도 도구 | 시드 카탈로그 내장 (에피소드 기반 콘텐츠 발굴) |
| 리서치 | 별도 브라우저 탭 | 에디터 내 뉴스/블로그/이미지 검색 통합 |
| 배포 | 단일 채널 | 발행 즉시 3개 언어 + OG 공유 (X, LINE, KakaoStory) |
| 아키텍처 | 프레임워크 의존 | 제로 프레임워크 바닐라 ESM 모듈 구조 |

### 1.3 적용 서비스

- **monkos.ai** (MONKOS AI 포털) — Cloud Run 배포
- 대상 사용자: 콘텐츠 운영자 (비개발자 포함)
- 지원 언어: 한국어(KO), 일본어(JA), 영어(EN)

## 3. 기능 명세

### 3.1 에디터 코어 (blog-editor.js)

#### 3.1.1 WYSIWYG 편집

- **엔진**: Toast UI Editor (ProseMirror 기반)
- **모드**: WYSIWYG (기본) / Markdown (전환 가능)
- **저장 형식**: Markdown (Firestore `content` 필드)
- **편집 영역**: 3컬럼 레이아웃
  - 좌측 (220px): 메타 정보 (카테고리, 언어, 썸네일, URL, 요약, 태그)
  - 중앙 (가변, 최대 820px): 에디터 본문
  - 우측 (300px): 도구 탭 (이미지/시드/리서치)

#### 3.1.2 메타데이터 관리

| 필드 | 타입 | 자동/수동 | 설명 |
|------|------|----------|------|
| title | string | 수동 | 제목 (필수) |
| slug | string | 자동생성 (수동 편집 가능) | URL 경로. 특수문자 세니타이징 |
| category | enum | 수동 | 7종: 사진, 패션, 헤어, 메이크업, AI, News, 기타 |
| lang | enum | 수동 | ko / ja / en |
| summary | string(160) | 수동 | SEO 메타 요약 |
| tags | string[] | 수동 | 콤마 구분 |
| thumbnail | URL | 자동추출 (수동 지정 가능) | 첫 이미지 자동 / 뱅크에서 지정 / 직접 업로드 |
| pinned | boolean | 수동 | 매거진 영역 고정 |
| published | boolean | 수동 | 발행 상태 |

#### 3.1.3 저장 및 발행 플로우

```
[임시저장] ──POST/PUT──→ blog.js ──→ Firestore (published: false)

[발행] ──POST/PUT──→ blog.js ──→ Firestore (published: true)
                        │
                        ▼ (비동기, 백그라운드)
                   translate.js
                   ├── Gemini 2.0 Flash (KO→JA)
                   └── Gemini 2.0 Flash (KO→EN)
                        │
                        ▼
                   Firestore
                   ├── {slug}-ja (자동 생성 또는 갱신)
                   └── {slug}-en (자동 생성 또는 갱신)
```

#### 3.1.4 Slug 세니타이징

```
클라이언트: 입력 시 실시간 제거 → /  $  #  [  ]  .
서버: generateSlug() + sanitizeSlug() 이중 방어
      → 소문자 변환 → 특수문자 제거 → 공백→하이픈 → 100자 제한
```

### 3.2 AI 자동 번역 시스템 (translate.js)

#### 3.2.1 번역 엔진

- **모델**: Vertex AI Gemini 2.0 Flash
- **방식**: 구조화 출력 (JSON 응답, `responseMimeType: 'application/json'`)
- **파라미터**: temperature 0.3, maxOutputTokens 4096
- **프롬프트**: 언어별 전문 번역자 역할 + SEO 최적화 지시

#### 3.2.2 번역 전략

| 원본 언어 | 번역 대상 | slug 패턴 |
|----------|----------|----------|
| KO | JA, EN | `{slug}-ja`, `{slug}-en` |
| JA | KO, EN | `{slug}-ko`, `{slug}-en` |
| EN | KO, JA | `{slug}-ko`, `{slug}-ja` |

#### 3.2.3 번역본 관리

```
신규 번역본: set() — 전체 필드 생성 (createdAt = 현재 시각)
기존 번역본: update() — 내용만 갱신 (viewCount, createdAt 보존)

추가 필드:
  originalSlug: 원본 slug 참조
  autoTranslated: true
  translatedAt: 마지막 번역 시각
```

#### 3.2.4 번역 검증

- 번역 결과의 title이 원본과 동일하면 번역 실패로 판정 → 스킵

### 3.3 이미지 자산 관리 시스템 (blog-image.js + upload.js)

#### 3.3.1 업로드 파이프라인

```
브라우저 파일 선택
    ↓
multipart/form-data POST
    ↓
upload.js 서버 처리
    ├── MIME 검증 (jpg/png/webp/gif만 허용)
    ├── 용량 제한 (5MB)
    ├── sharp WebP 변환 (quality: 85, GIF 제외)
    ├── 파일명 세니타이징 ({timestamp}_{safe-name}.webp)
    └── GCS 업로드 (public read)
    ↓
URL 반환 → 에디터 삽입 또는 썸네일 지정
```

#### 3.3.2 이미지 뱅크 (우측 탭)

- **표시**: GCS `blog/` 프리픽스 최근 50건, 날짜별 그룹핑
- **삽입**: 클릭 → 플로팅 툴바 → "본문 삽입" 또는 "썸네일 지정"
- **드래그**: 라이브러리에서 에디터로 드래그&드롭 삽입
- **삭제**: 역링크 보호 (사용 중인 글 경고 → 확인 후 삭제)

#### 3.3.3 이미지 삽입 중복 방지

```
문제: 클릭과 드래그 이벤트가 동시 발동 → 2장 삽입
해결:
  1. drop 핸들러를 capture phase로 전환 (ProseMirror보다 선점)
  2. stopImmediatePropagation()으로 후속 핸들러 차단
  3. insertImage() 함수에 debounce 플래그 (_isInsertingImage)
```

#### 3.3.4 이미지 삭제 정합성

```
문제: DOM 직접 조작 (img.remove()) → ProseMirror 내부 상태 불일치
해결: 에디터 API 경유
  1. editor.getMarkdown()으로 현재 마크다운 취득
  2. 정규식으로 해당 이미지 마크다운 구문 제거
  3. editor.setMarkdown()으로 전체 갱신
  → ProseMirror 상태와 DOM이 항상 정합
```

### 3.4 시드 카탈로그 (blog-seed.js)

- **데이터**: `/admin/data/episode_catalog.json` (정적 JSON)
- **구성**: 에피소드 ID, 제목, 요약, 인사이트, 카테고리(6종), 블로그 적합도(5점), 기간
- **기능**: 키워드 검색, 카테고리 필터, 적합도 정렬, 상세 팝업, "글감으로 사용" (제목 자동 채우기)

### 3.5 실시간 리서치 (blog-research.js)

- **소스**: Naver 검색 API (뉴스/블로그/이미지)
- **기능**: 키워드 검색, 소스 전환, 페이지네이션, 검색 기록(localStorage, 최근 5건)
- **자동 제안**: 제목 입력 시 1.5초 후 리서치 키워드 자동 제안 토스트
- **이미지 검색**: 그리드 표시, 클릭 시 원본 팝업, 저작권 경고 표시
- **참조 복사**: 제목+URL 클립보드 복사

### 3.6 소셜 배포 (blog-share.js)

- **지원 채널**: X (Twitter), LINE, KakaoStory, 링크 복사, 제목+URL 복사
- **활성화 조건**: published === true
- **URL 생성**: 언어별 경로 자동 분기 (`/blog/`, `/ja/blog/`, `/en/blog/`)

### 7.2 교훈 및 재발 방지

| 교훈 | 대응 |
|------|------|
| WYSIWYG 에디터 DOM은 외부에서 직접 조작 금지 | 에디터 API(getMarkdown/setMarkdown) 경유 원칙 확립 |
| 이벤트 리스너 등록 시 capture/bubble phase 명시 | 외부 라이브러리와 공존 시 capture phase + stopImmediatePropagation |
| 크롤러 중복 방지는 다중 기준 필요 | sourceUrl + title + slug 3중 체크. timestamp suffix 생성 금지 |
| Firestore set() vs update() 구분 | 기존 문서 존재 시 update()로 메타데이터 보존 |
| 단일 파일 1,500줄 이상은 버그 연쇄 위험 | ESM 모듈 분리로 기능 단위 격리 |
