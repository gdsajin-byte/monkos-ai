### 1.3 본 문서의 목적

1. 이미지 시스템의 현재 아키텍처를 정확히 기술

### 3.3 이미지 본문 삽입 (insertImage)

**현재 구현** (2026-03-22 15:02 확정):
```javascript
function insertImage(url, name) {
  const ed = getEditor();
  if (!ed) { showToast('에디터 초기화 대기 중', true); return; }
  try {
    ed.focus();
    ed.exec('addImage', { imageUrl: url, altText: name || 'image' });
    showToast('이미지 삽입 완료');
    setTimeout(() => updatePreview(), 300);
  } catch (err) {
    // 폴백: 마크다운 직접 삽입
    try {
      const md = ed.getMarkdown();
      ed.setMarkdown(md + `\n![${name || 'image'}](${url})\n`);
      showToast('이미지 삽입 완료');
      setTimeout(() => updatePreview(), 300);
    } catch (err2) {
      showToast('이미지 삽입 실패', true);
    }
  }
}
```

**삽입 경로 3가지**:
1. **확대뷰 "본문 삽입" 버튼** → `insertImage(url, name)`
2. **뱅크→에디터 드래그&드롭** → drop 이벤트 → `insertImage(match[2], match[1])`
3. **에디터 내장 이미지 업로드** (툴바 버튼/붙여넣기) → Toast UI `addImageBlobHook` → GCS 업로드 → `callback(url)`

### 4.2 발견된 근본 원인 4건

#### 근본원인 #1: GFE 정적 파일 캐시 (배포 미반영)

**현상**: CSS/JS 수정 후 prod 배포해도 `monkos.ai`에서 구버전이 서빙됨
**원인**: server.js에 `Cache-Control` 헤더 미설정 → Google Frontend가 자체 캐시 정책 적용 → 정적 파일 캐싱
**해소**: server.js:269에 `Cache-Control: no-cache` 추가
**교훈**: 서버사이드 코드 변경은 GFE 캐시에 영향 없어 즉시 반영되지만, 정적 파일(CSS/JS/HTML)은 Cache-Control 헤더 필수

#### 근본원인 #2: ESM `?v=` 캐시 버스팅이 모듈 인스턴스를 이중화

**현상**: `initEditor()`에서 `editor` 할당 성공, 그러나 `getEditor()`가 null 반환
**원인**:
```
blog-edit.html:  import from './js/blog-editor.js?v=20260322q'  → 모듈 인스턴스 A
blog-image.js:   import from './blog-editor.js'                  → 모듈 인스턴스 B
```
ESM 스펙에서 **URL이 다르면 별개 모듈**. `?v=` 쿼리가 있는 것과 없는 것은 다른 URL → 다른 인스턴스 → 다른 `editor` 변수
**해소**: ESM import에서 `?v=` 제거. CSS `<link>`의 `?v=`는 유지 (CSS는 ESM이 아님)
**교훈**: **ESM 모듈 간 import에는 절대로 캐시 버스팅 쿼리를 붙이면 안 된다.** 진입점 HTML에서만 캐시 버스팅 적용 가능한데, ESM import 체인에서는 URL 일관성이 필수.

#### 근본원인 #3: 이중/3중 스크롤 컨테이너

**현상**: 이미지 뱅크가 다른 UI 요소와 겹침
**원인**: `.editor-right`(overflow-y:auto) > `.tab-content`(높이 제약 없음) > `#imageLibrary`(max-height:60vh, overflow-y:auto) 3중 스크롤 구조
**해소**:
```css
.editor-right { overflow-y: hidden; display: flex; flex-direction: column; }
.tab-content { flex: 1; min-height: 0; overflow-y: auto; }
#imageLibrary { max-height: 360px; overflow-y: auto; }
```
**교훈**: flex 컨테이너에서 자식의 스크롤을 제어하려면 `min-height: 0` 필수 (flex 아이템의 기본 min-height는 content 크기)

#### 근본원인 #4: editor.on('change') 콜백 내 DOM 직접 수정 → ProseMirror change 루프

**현상**: 이미지 삽입 후 에디터 렉
**원인**: change 콜백에서 `img.style.cursor = 'pointer'`와 `markThumbnailInEditor()` → `img.style.outline = '3px solid ...'`를 ProseMirror DOM에 직접 주입 → ProseMirror가 DOM 변경 감지 → change 재발생 → 무한 루프
**해소**: change 콜백에서 DOM 스타일 주입 제거. cursor는 CSS로, markThumbnailInEditor()는 명시적 액션(썸네일 지정) 시에만 호출
**교훈**: **ProseMirror/Toast UI 에디터의 WYSIWYG 영역 DOM을 외부에서 직접 수정하면 안 된다.** change 이벤트가 재발생하여 루프. 스타일 변경은 CSS 클래스로, 콘텐츠 변경은 에디터 API로.

### 4.3 부차적 버그 3건

#### 부차 #1: setupImageHandlers() 에러로 죽어있었던 문제

`export let editor`가 모듈 로드 시 `undefined` → `editor.on('change')` 에서 TypeError → 이후 코드(드래그&드롭, 플로팅 툴바 외부 클릭) 미등록. **GFE 캐시로 구 JS가 서빙되면서 이 에러가 숨겨져 있었음.**

#### 부차 #2: 확대뷰 모달이 에디터 포커스를 소실시키는 문제

`showImagePreview()`가 풀스크린 오버레이를 띄우면서 에디터 포커스+커서 위치 소실 → `editor.exec('addImage')` 실패. `ed.focus()` + try-catch 폴백으로 해소.

#### 부차 #3: `_isInsertingImage` 가드가 잠기는 문제

이전 삽입 시도가 에러로 실패하면 `_isInsertingImage = true`에서 해제 안 됨 → 이후 모든 삽입 차단. try-catch-finally 또는 가드 제거로 해소.

### 5.1 배포 경로


### 5.2 캐시 계층

```
[브라우저 캐시] → [Google Frontend 캐시] → [Cloud Run 컨테이너]

Cache-Control 헤더 (server.js:269):
  CSS/JS: 'no-cache'     ← 매번 재검증 (2026-03-22 추가)
  기타:   'public, max-age=3600'  ← 1시간 캐시

ETag/Last-Modified: 미설정 → 브라우저 조건부 요청(304) 불가
```

### 5.3 난독화 영향

`obfuscate.mjs`는 `public/` 루트의 HTML 인라인 `<script>` 블록만 처리. `public/admin/` 하위 파일(CSS/JS)은 **난독화 대상 아님**. 이미지 겹침 버그와 무관.

### 5.4 캐시 버스팅 정책 (확정)

| 대상 | 캐시 버스팅 | 방식 |
|------|-----------|------|
| CSS `<link>` | ✅ 적용 | `?v=YYYYMMDD` (HTML에서 수동 갱신) |
| ESM `import` | ❌ **금지** | URL 일관성 필수 (모듈 인스턴스 이중화 방지) |
| HTML 자체 | ❌ 불가 | server.js Cache-Control 헤더로 대응 |

## 7. 교훈 및 재발 방지

### 7.0 최상위 교훈: 배포 검증 우선 원칙

**패턴**: 배포가 꼬여서 코드 수정이 반영 안 됨 → "코드가 잘못됐나?" → 불필요한 코드 수정 → 원래 잘 되던 코드까지 망가짐 → 진짜 버그 발생

**오늘의 실제**: 원래 버그 1건(이중 스크롤) → eafde7c에서 이미 해소 → GFE 캐시로 배포 6회 미반영 → "안 고쳐졌네" → 코드 수정 8회 → 2차 버그 4건 발생. **배포 검증을 먼저 했으면 코드 수정 0건이었을 가능성.**

**규칙**: "안 고쳐졌다" 보고가 오면 코드를 다시 수정하기 전에:
1. `curl -s https://monkos.ai/admin/파일경로 | grep "변경된_문자열"` — 실제 서빙 코드 확인
2. `curl -I https://monkos.ai/admin/파일경로 | grep -i cache` — Cache-Control 헤더 확인
3. 반영 안 됐으면 **코드 수정 금지** → 배포/캐시 파이프라인 점검
4. 반영 확인 후에만 코드 레벨 디버깅 진행

### 7.1 ESM 모듈 캐시 버스팅 금지

**규칙**: ESM `import` 구문에 `?v=` 쿼리 파라미터를 붙이지 않는다.
**이유**: 진입점과 모듈 간 import의 URL이 달라지면 브라우저가 별개 인스턴스로 로딩. 모듈 스코프 변수가 공유되지 않아 전역 상태 파편화.
**대안**: CSS는 `<link>` 태그에 `?v=` 사용. JS 캐시는 서버 `Cache-Control: no-cache` 헤더로 대응.

### 7.2 ProseMirror DOM 직접 수정 금지

**규칙**: `editor.on('change')` 콜백 내에서 에디터의 WYSIWYG DOM(`.ProseMirror` 하위)에 인라인 스타일을 주입하지 않는다.
**이유**: ProseMirror가 DOM 변경을 content change로 감지 → change 이벤트 재발생 → 무한 루프.
**대안**: 스타일은 CSS 클래스로, 콘텐츠 변경은 에디터 API (`getMarkdown`/`setMarkdown`, `exec`)로.

### 7.3 배포 후 검증 프로토콜

**규칙**: 정적 파일(CSS/JS/HTML) 변경 시 배포 후 반드시:
```bash
curl -I https://monkos.ai/admin/css/blog-editor.css | grep -i cache
curl -s https://monkos.ai/admin/js/blog-image.js | head -3
```
**이유**: GFE 캐시가 구버전을 서빙할 수 있음. `Cache-Control: no-cache` 헤더가 응답에 포함되는지 확인.

### 7.4 setupImageHandlers 재시도 상한

**규칙**: `setTimeout(setupImageHandlers, 200)` 재시도에 상한(예: 50회)을 두고, 초과 시 에러 로그.
**이유**: editor가 영원히 undefined일 때 200ms마다 무한 재시도 → 콘솔 오염 + 미세한 성능 저하.
**현재 상태**: 상한 미적용 (향후 개선 대상).
