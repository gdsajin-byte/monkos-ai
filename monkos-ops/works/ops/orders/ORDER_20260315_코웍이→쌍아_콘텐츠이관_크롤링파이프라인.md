## Firestore 데이터 구조

기존 CMS 스키마 (`lib/cms/blog.js`) 준수:

```js
{
  slug: String,          // URL-safe, 영문 소문자+하이픈 자동 생성
  title: String,         // 원문 제목
  content: String,       // HTML or Markdown (기존 CMS 형식에 맞출 것)
  summary: String,       // 첫 문단 또는 앞 200자 자동 추출
  author: String,        // 작성자 (네이버: 카테고리 기반 추정, note: 작성자 필드)
  lang: String,          // 'ko' | 'ja' | 'en' — 자동 감지
  source: String,        // 'naver' | 'note'
  sourceUrl: String,     // 원본 URL
  publishedAt: Timestamp, // 원본 게시일
  tags: Array,           // 본문 키워드 자동 추출 or 카테고리명
  category: String,      // 원본 카테고리
  thumbnail: String,     // 대표 이미지 URL (없으면 null)
  createdAt: Timestamp,  // 이관 시각
}
```

## 구현 지침

### 크롤러 위치
`lib/cms/importer/` 신규 디렉토리 생성:
```
lib/cms/importer/
├── naver.js    ← 네이버 블로그 크롤러
├── note.js     ← note.com 크롤러
└── index.js    ← 실행 진입점 (node lib/cms/importer/index.js)
```

### 네이버 블로그 크롤링 유의사항
- 네이버 블로그는 모바일 URL(`m.blog.naver.com`) 또는 RSS 활용 시 파싱 쉬움
- RSS: `https://rss.blog.naver.com/monkos_ai.xml` 시도 먼저
- RSS 카테고리 필터링 가능 여부 확인
- 카테고리 필터: MONKOS AI / SHIN's AI story / HAN's BEAUTY / KKU's DESIGN 만

### note.com 크롤링 유의사항
- note.com 공식 API 없음 → HTML 파싱
- `https://note.com/monkos_ai` 목록 페이지에서 포스트 URL 수집
- 각 포스트 본문 추출 (`.note-common-styles__textnote-body` 등 클래스 확인)
- 이미지: note.com CDN URL 그대로 사용 (직접 다운로드 불필요)

### 중복 방지
- `sourceUrl` 기준으로 Firestore 중복 체크
- 이미 존재하면 skip (재실행 안전)

### 실행 방법
```bash
node lib/cms/importer/index.js --source=note
node lib/cms/importer/index.js --source=naver
node lib/cms/importer/index.js --source=all  # 전체
```
