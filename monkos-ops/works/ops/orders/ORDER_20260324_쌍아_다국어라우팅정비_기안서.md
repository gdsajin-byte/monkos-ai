## 1. 현행 구조 진단

### 다국어 라우팅 — 3가지 방식이 혼재

| 페이지 | KO | JA | EN | 방식 |
|--------|-----|-----|-----|------|
| 홈 | `/` | `/?lang=ja` | `/?lang=en` | 파라미터 |
| 블로그 목록 | `/blog` | `/ja/blog` | `/en/blog` | 경로 |
| 블로그 글 | `/blog/{slug}` | `/ja/blog/{slug}` | `/en/blog/{slug}` | 경로 |
| FAQ | `/faq` | `/ja/faq` | `/en/faq` | 경로 |
| Pricing | `/pricing` | `/ja/pricing` | `/en/pricing` | 경로 |
| Gallery | `/gallery` | 없음 | 없음 | KO only |
| Board | `/board` | 없음 | 없음 | KO only |
| Guide | `/guide` | 없음 | 없음 | KO only |
| Crop | `/crop` | 없음 | 없음 | KO only |

**문제**: 홈만 파라미터 방식, 나머지는 경로 방식 — 일관성 없음.

### 홈페이지 hreflang — 잘못됨

현재 `index.html:36-39`:
```html
<link rel="alternate" hreflang="ko" href="https://monkos.ai/">
<link rel="alternate" hreflang="en" href="https://monkos.ai/">        ← KO와 동일 URL
<link rel="alternate" hreflang="ja" href="https://idphoto-jp.monkos.ai/">  ← 포털이 아닌 증명사진 앱
<link rel="alternate" hreflang="x-default" href="https://monkos.ai/">
```

- `en` → `monkos.ai/` = KO와 같은 URL을 가리킴 → 구글이 EN 대체 페이지를 인식 못함
- `ja` → `idphoto-jp.monkos.ai/` = 포털 홈이 아닌 증명사진 앱을 가리킴 → 완전히 다른 서비스

### `/ja/` 경로 404

- `server.js:221` — 홈은 `/ || /index.html`만 매칭
- `/ja/` 접속 시 정적 파일 서빙으로 넘어가서 404
- 구글 크롤러가 `/ja/`를 시도하면 실패 (코웍이 서치콘솔 실시간 테스트 확인)

### 사이트맵 누락

현재 `renderSitemap()`에 포함된 다국어 URL:
- `/ja/blog`, `/en/blog` — 2건만

누락:
- `/ja/faq`, `/en/faq`
- `/ja/pricing`, `/en/pricing`
- 홈 JA/EN 버전

### 자동 리디렉트 없음

- 일본 사용자가 구글에서 `/faq` 검색 결과 클릭 → 한국어 FAQ 랜딩
- 서버 측 Accept-Language 기반 리디렉트 없음
- 클라이언트 `i18n.js`가 언어 감지하지만 페이지 경로는 안 바꿈

## 2. 수정 방안 — 2개 안

### 안 A: 최소 수정 (리디렉트 + 사이트맵 보완)

현행 구조 유지하면서 구멍만 막는 방식.

#### A-1. `/ja/`, `/en/` 리디렉트 추가
**파일**: `server.js`

```javascript
// 다국어 홈 리디렉트 — /?lang= 방식으로 통일
if (urlPath === '/ja' || urlPath === '/ja/') return redirect(res, '/?lang=ja');
if (urlPath === '/en' || urlPath === '/en/') return redirect(res, '/?lang=en');
```

301 리디렉트 헬퍼:
```javascript
function redirect(res, location, code = 301) {
  res.writeHead(code, { Location: location });
  res.end();
}
```

#### A-2. 홈 hreflang 수정
**파일**: `index.html:36-39` 또는 `home.js`에서 SSR 시 동적 주입

```html
<link rel="alternate" hreflang="ko" href="https://monkos.ai/">
<link rel="alternate" hreflang="en" href="https://monkos.ai/?lang=en">
<link rel="alternate" hreflang="ja" href="https://monkos.ai/?lang=ja">
<link rel="alternate" hreflang="x-default" href="https://monkos.ai/">
```

또는 리디렉트를 넣었으니:
```html
<link rel="alternate" hreflang="ja" href="https://monkos.ai/ja/">
<link rel="alternate" hreflang="en" href="https://monkos.ai/en/">
```
→ 구글은 301을 따라가서 `/?lang=ja`를 색인

#### A-3. 사이트맵 다국어 URL 추가
**파일**: `render.js` — `renderSitemap()` staticUrls 배열

추가:
```javascript
{ loc: 'https://monkos.ai/ja/faq', lastmod: today, changefreq: 'weekly', priority: '0.6' },
{ loc: 'https://monkos.ai/en/faq', lastmod: today, changefreq: 'weekly', priority: '0.6' },
{ loc: 'https://monkos.ai/ja/pricing', lastmod: today, changefreq: 'monthly', priority: '0.5' },
{ loc: 'https://monkos.ai/en/pricing', lastmod: today, changefreq: 'monthly', priority: '0.5' },
```

홈 JA/EN은 리디렉트 URL이므로 사이트맵에 넣지 않음 (구글 가이드라인: 리디렉트 URL은 사이트맵 제외).

#### A-4. 사이트맵 재제출
코웍이가 서치콘솔에서 `monkos.ai/sitemap.xml` 재제출.

**안 A 작업량**: server.js 5줄 + index.html/home.js hreflang 수정 + render.js 4줄 + 코웍이 재제출
**안 A 소요**: 막내 30분 이내

### 안 B: 경로 통일 (`/ja/` 정식 라우트화)

홈도 `/ja/`, `/en/`으로 경로 방식 통일.

#### B-1. 홈 다국어 경로 라우트 추가
**파일**: `server.js`

```javascript
if ((urlPath === '/ja' || urlPath === '/ja/') && req.method === 'GET') return renderHome(req, res, 'ja');
if ((urlPath === '/en' || urlPath === '/en/') && req.method === 'GET') return renderHome(req, res, 'en');
```

**파일**: `home.js` — `renderHome(req, res)` 시그니처에 `forceLang` 파라미터 추가
- 현재: `req.query.lang`에서 언어 추출
- 변경: `forceLang || req.query.lang || 'ko'`

#### B-2. 홈 hreflang 수정
```html
<link rel="alternate" hreflang="ko" href="https://monkos.ai/">
<link rel="alternate" hreflang="en" href="https://monkos.ai/en/">
<link rel="alternate" hreflang="ja" href="https://monkos.ai/ja/">
<link rel="alternate" hreflang="x-default" href="https://monkos.ai/">
```

#### B-3. `/?lang=ja` 하위 호환
기존 `/?lang=ja` 접속도 유지 (하위 호환). 단 canonical은 `/ja/`로 설정하여 구글이 `/ja/`를 정본으로 인식.

#### B-4. 사이트맵 — 홈 JA/EN 포함
```javascript
{ loc: 'https://monkos.ai/ja/', lastmod: today, changefreq: 'weekly', priority: '0.9' },
{ loc: 'https://monkos.ai/en/', lastmod: today, changefreq: 'weekly', priority: '0.9' },
{ loc: 'https://monkos.ai/ja/faq', lastmod: today, changefreq: 'weekly', priority: '0.6' },
{ loc: 'https://monkos.ai/en/faq', lastmod: today, changefreq: 'weekly', priority: '0.6' },
{ loc: 'https://monkos.ai/ja/pricing', lastmod: today, changefreq: 'monthly', priority: '0.5' },
{ loc: 'https://monkos.ai/en/pricing', lastmod: today, changefreq: 'monthly', priority: '0.5' },
```

#### B-5. i18n.js 언어 전환 경로 보정
**파일**: `i18n.js:122-124`

현재:
```javascript
window.location.href = '/?lang=' + newLang;
```

변경:
```javascript
if (newLang === 'ko') window.location.href = '/';
else window.location.href = '/' + newLang + '/';
```

#### B-6. 사이트맵 재제출

**안 B 작업량**: server.js + home.js + index.html + render.js + i18n.js — 5개 파일
**안 B 소요**: 막내 1~2시간

## 4. 쌍아 의견

**안 B 추천.**

이유:
- 일본 시장이 핵심 타깃이고 취활 피크까지 6주 — SEO 효과 차이가 실질적
- `/ja/blog`, `/ja/faq`, `/ja/pricing`은 이미 경로 방식 — 홈만 파라미터인 게 오히려 이상
- `home.js`의 `renderHome`은 이미 `req.query.lang`으로 분기하고 있어서 `forceLang` 추가는 경미한 수정
- 안 A로 가면 나중에 결국 안 B로 전환하게 될 가능성 높음

단, **안 A를 먼저 빠르게 치고 → 안 B를 다음 스프린트에서** 하는 점진적 접근도 유효합니다.
