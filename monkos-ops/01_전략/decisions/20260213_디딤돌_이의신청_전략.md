## 1. 기술성 반론 (3건)

### 지적 ①: "오픈소스 모델의 화장품 실제 발색 수치 구현 정확성/신뢰성 미흡"

**반론:**

제안서 작성 시점(2026-01-17) 이후, 사업 방향을 **K-뷰티 룩북 → AI 증명사진 토털 솔루션**으로 피봇하였습니다. 이는 시장 검증 결과에 기반한 전략적 판단입니다.

| 항목 | 제안서 시점 | 현재 (2026-02-13) |
|------|-----------|-------------------|
| 핵심 서비스 | K-뷰티 룩북 이미지 생성 | **AI 증명사진 촬영 + 실시간 코칭** |
| 발색 문제 | SD/FLUX로 정밀 색재현 난제 | **증명사진은 발색 아닌 정체성 보존이 핵심** |
| 정체성 유지율 | 미검증 | **90:10 비율 최적화 완료** (IDENTITY_PRESERVATION) |
| 검증 수단 | 계획 단계 | **Gemini QC 자동 판정 파이프라인 가동 중** |

**증거:**
- 정체성 보존 90:10 프롬프트: 134줄 정밀 지시문 (2026-01-16 확립, Git 커밋 `a6c6417`)
- QC 파이프라인: Gemini 2.0 Flash → 원본/생성 이미지 비교 → JSON 자동 채점
- Cloud Run 3개 서비스 배포 완료 (2026-02-12, 3개국 동시 서비스)

**핵심 논점:**
> 발색 재현이 아닌 **인물 정체성 보존**이 핵심 기술 과제이며, 이는 이미 90% 이상의 정확도로 구현 완료되었습니다. 파인튜닝 대상도 "발색"이 아닌 "포즈/조명/의상 변환 시 동일인물 유지"로 명확합니다.

### 지적 ②: "로컬 GPU(RTX 5090)로 다수 사용자 처리 속도(10초 이하) 유지 구체적 방안 부족"

**반론:**

제안서에서 "로컬 50% 이하"로 제시한 하이브리드 아키텍처가 이미 구현되어 있으며, 현재는 **클라우드 100% + 향후 로컬 확장** 구조입니다.

**현재 운영 중인 스케일링 아키텍처:**

```
[현재 — 클라우드 퍼스트]
유저 → Cloud Run (서버리스, 자동 스케일) → Vertex AI / Gemini API
                ↑ 제로 스케일 (0~10 인스턴스)
                ↑ 동시성 80, 타임아웃 300초

[R&D 목표 — 하이브리드]
유저 → Cloud Run (라우터) → ┬─ 로컬 5090 (파인튜닝 모델, 고정비)
                             └─ Vertex AI (피크 트래픽, 종량제)
```

**구체적 수치 제시:**

| 항목 | 현재 실측 | 로컬 GPU 도입 후 (계획) |
|------|----------|----------------------|
| 이미지 생성 시간 | 3~5초 (Vertex AI) | 2~4초 (5090 로컬) |
| 코칭 지연 | 500~800ms (Gemini Live WS) | 동일 (클라우드 유지) |
| 동시 사용자 | 80명/인스턴스 × 10인스턴스 | 추론: 로컬 10명 + 클라우드 무제한 |
| 월 비용 | 종량제 ~$50 (현재 트래픽) | 로컬 고정 $0 + 클라우드 종량제 |

**RTX 5090 x2 (64GB VRAM) 검증 완료 사항:**
- 5090 듀얼 스케일링 팩터: 0.91~0.97 (PCIe 5.0)
- 70B 모델 4x 5090: 4,622 tokens/s (CloudRift vLLM 벤치)
- 분리 세트 구조 설계 완료 (장애 격리 + 독립 냉각)
- LoRA 패션모델 학습 완료 (2026-01-28, 1에포크, RTX 4060)

**핵심 논점:**
> "로컬만으로 처리"가 아닌 **"로컬+클라우드 하이브리드로 비용 최적화"**가 목표입니다. 현재 클라우드 100% 운영으로 서비스 안정성이 검증되었으며, 로컬 GPU 도입은 **비용 절감 + 데이터 주권 확보**를 위한 단계적 전환입니다.

### 지적 ③: "범용 GenAI 서비스와의 차별성 및 기술자립 방안 미흡"

**반론:**

**MONKOS만의 기술 해자 3가지:**

#### 해자 1: 실시간 AI 음성 코칭 (세계 최초)

```
[기존 서비스] 셀카 업로드 → AI 후처리 → 결과
[MONKOS]     카메라 ON → AI 실시간 음성 교정 → 완벽한 원본 → AI 재생성
```

| 기존 경쟁사 (PhotoAiD, 픽미 등) | MONKOS |
|-------------------------------|--------|
| 촬영 후 AI 보정 | **촬영 중 AI 코칭** (Gemini Live WebSocket) |
| 나쁜 원본 → 한계 있는 보정 | **좋은 원본 → 최소 보정** |
| 음성 가이드 없음 | **한국어/일본어 실시간 음성** |
| 정체성 왜곡 빈번 | **90:10 정체성 보존** |

- 기술 스택: Gemini 2.0 Flash Live API (WebSocket) → 카메라 프레임 30fps 분석 → TTS 음성 피드백
- RTT: 500~800ms (실측, 2026-02-08 E2E 성공)
- 프롬프트: 체계적 체크 순서 (정면향시 → 조명 → 표정 → 눈썹 → 얼굴라인)

#### 해자 2: 오프라인 사진관 노하우의 AI 전이

- 대표 신정규: **10년 사진관 운영 경력** → 촬영 노하우가 AI 프롬프트에 직접 반영
- 증명사진 규격 지식 (여권/비자/이력서/면허 — 4개국 대응)
- "사진관 아저씨의 한 마디"를 AI가 실시간으로 전달하는 구조

#### 해자 3: 멀티에이전트 오케스트레이션 (기술자립의 본질)

```
[API 감싸기 ≠ MONKOS]

MONKOS 기술 스택:
├── Gemini Live (실시간 코칭) — WebSocket 바이너리 스트리밍
├── Imagen 3.0 (I2I 생성) — 정체성 보존 프롬프트 엔지니어링
├── Gemini Vision (QC 자동 판정) — JSON 채점 파이프라인
├── Firestore (크레딧 원자적 트랜잭션) — 생성/다운로드/공유 경제
├── 4중 OAuth (Google/LINE/카카오/Telegram) — 3개국 인증
├── 이중 결제 (Lemon Squeezy/토스페이먼츠) — 글로벌+국내
└── Human-AI 협업 (Claude 5체제 + Gemini 전략) — 개발 자체가 AI 네이티브
```

**"API를 쓴다"와 "API로 시스템을 만든다"는 완전히 다릅니다.**
Adobe Firefly는 이미지 생성 도구이고, MONKOS는 **촬영 코칭 → 생성 → 품질검증 → 규격크롭 → 결제 → 배송까지 일관된 파이프라인**입니다.
