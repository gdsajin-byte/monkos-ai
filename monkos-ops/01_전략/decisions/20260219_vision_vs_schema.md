# MONKOS 비전 vs 심사 스키마 — 번역 전략

**일자:** 2026-02-19
**맥락:** 디딤돌 대출 심사 피드백 분석

---

## 문제: 낡은 스키마

정부/금융 심사 양식은 **업종-제품-타겟시장** 3칸 구조.
이 프레임은 "뭘 만들어서 누구에게 파는가"만 묻는다.

MONKOS의 본질인 **"특화 지능 플랫폼"**은 이 칸에 들어가지 않는다.
결과: 심사관이 칸 안에서만 보고 "레드오션", "경쟁력 불명확" 판정.

**자신들이 낡은 스키마를 설계해놓고, 그 스키마에 안 맞는다며 지원자를 탈락시키는 구조.**

---

## 실제 비전 (칸 밖)

MONKOS = **특화 지능 플랫폼**

- 고객 도메인 데이터로 베이스 모델을 파인튜닝
- 쓸수록 날카로워지는 피드백 루프
- 고객 환경에 종속된 지능 → 이탈 불가
- 증명사진은 이 구조의 첫 번째 수직 검증

확장 경로: 사진관 → 프랜차이즈 → 병원 → 중소기업 → 관공서
파는 것: 사진이 아니라 "내 업무를 나보다 잘 아는 지능"

---

## 번역 테이블 (심사용 ↔ 실제)

| 심사 양식 칸 | 번역 (심사용) | 실제 |
|-------------|-------------|------|
| 업종 | K-뷰티 | 특화 지능 플랫폼 (업종 무관) |
| 제품 | AI 증명사진 앱 | 자가 진화형 도메인 AI |
| 타겟 | 소상공인/개인 | 데이터를 가진 모든 조직 |
| 기술 | 온디바이스 AI | 임계점 도달 시 자체 모델 풀FT |
| 경쟁력 | 가격/편의성 | 축적된 파이프라인 + 데이터 해자 |
| 수익모델 | 건당 과금 | 특화 지능 SaaS (고객당 MRR) |

---

## 전략: 두 언어로 말하기

1. **서류/양식** → 그들의 칸에 맞춰 번역. K-뷰티, 증명사진, 소상공인.
2. **구두 면접** → 칸 밖의 그림을 30초로 설명. "증명사진은 첫 번째 검증이고, 본질은..."
3. **숫자** → 현재 가동 중인 앱 매출/사용자로 칸 안의 점수를 먼저 확보
4. **비전** → 점수 확보 후 "그런데 이게 전부가 아닙니다"로 확장

칸 안에서 먼저 이기고, 칸 밖을 보여주는 순서.

---

## GPU 투자 논리 (심사관 질문 대비)

**Q: 왜 GPU를 사야 합니까?**

심사용 답: "AI 추론 비용 절감, 월 API 비용 XX만원 → 자체 추론 시 0원"

실제 답: 범용 모델 성능이 수렴하는 임계점에서, 우리 데이터로 벼린 자체 모델이 서 있게 하기 위한 대기 병력. 클라우드 50(범용 두뇌) : 내부 50(특화 칼) 구조.
