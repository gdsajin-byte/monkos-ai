# MONKOS GPU 인프라 전략 — 통합 보고서

**작성일**: 2026-02-07 KST  
**범위**: 이전 세션(Tailscale 인프라, MONKOS 아키텍처) + 현재 세션(RTX 5090, Mac Studio M5, 하드웨어 로드맵)  
**결론**: 2025년 12월 설계한 **(5090 스테이션 + 서버박스) ↔ Mac Studio M5** 구조가 2026년 2월 시점에서도 최적 시나리오임이 검증됨

## 1. 최종 인프라 설계

### 1-1. 목표 아키텍처 (풀세트)

```
[세트 A] 5090 스테이션 + 서버박스 5090 (64GB VRAM)
[세트 B] 5090 스테이션 + 서버박스 5090 (64GB VRAM)
              ↕ Tailscale tailnet ↕
[Mac Studio M5 Ultra] (통합 메모리 128~192GB 예상)
```

- **평시**: 세트 A, B 모두 글로벌 서비스 추론 서버
- **개발 시**: 한 세트를 ML 실험/개발 환경으로 전환, 나머지가 서비스 유지
- **맥**: 대형 모델(70B) 추론 + 개발 환경 + 양쪽 서버박스 원격 접근

### 1-2. 1차 단계 (디딤돌/창사도약 자금)

```
[1차] 5090 x2 한 세트 + Mac Studio M5
├── 5090 세트: GPU 집약 연산 (튜닝, 이미지 생성, 고속 추론)
├── Mac Studio: 통합 메모리 기반 대형 모델 추론 + 개발 환경
├── Tailscale 연결로 양방향 접근
└── 서비스와 개발 동시 운용 가능
```

### 1-3. 5090 x2 (64GB VRAM)로 커버 가능한 범위

| 작업 | 가능 여부 | 비고 |
|------|-----------|------|
| 7B 풀 파인튜닝 | ✅ 넉넉 | 단일 GPU로 가능 |
| 7B~30B QLoRA 튜닝 | ✅ | Llama 3 8B, Mistral 7B, Qwen 14B 등 |
| 70B 4bit 추론 | ✅ | ~35GB VRAM 사용 |
| 70B QLoRA 튜닝 | ✅ | 64GB 범위 내 |
| Flux 커스터마이징 | ✅ | ~23GB VRAM, LoRA 트레이닝 한 장으로 가능 |
| 멀티 에이전트 동시 구동 | ✅ | 코딩 7B + 범용 7B + Flux + 라우터 3B 동시 |

## 2. RTX 5090 멀티GPU 기술 검증

### 2-1. NVLink 미지원 — PCIe 소프트웨어 프레임워크 의존

- RTX 5090은 NVLink 미지원 (NVIDIA가 프로/데이터센터 GPU 전용으로 제한)
- PCIe 기반 소프트웨어 프레임워크(DeepSpeed, PyTorch DDP, Ray) 사용 필수

### 2-2. PCIe 멀티GPU 스케일링 실측 데이터

| GPU | 스케일링 팩터 | 비고 |
|-----|-------------|------|
| **RTX 5090** | **0.91~0.97** | PCIe 5.0, P2P 비활성화지만 양호 |
| RTX PRO 6000 | 0.94~0.95 | P2P 활성화, 안정적 |
| RTX 4090 | 0.76 | NVIDIA 의도적 제한 추정 |

- RTX 5090이 4090 대비 멀티GPU 제한이 크게 완화됨
- CloudRift vLLM 벤치: 70B 모델 4x 5090에서 4,622 tokens/s 달성

### 2-3. 대안 구성 검토 및 기각 사유

#### Thunderbolt 5 외장 연결 — 비권장

- Gigabyte AORUS RTX 5090 AI Box: TB5 연결 시 PCIe 5.0 x16 대비 **14% 하락**
- 실제 게이밍 벤치: 데스크탑 5090 대비 **27% 느림**
- TB5 대역폭: 80Gbps 양방향이나 GPU는 실질 64Gbps PCIe Gen4 x4 사용
- **TB5는 PCIe Gen4 x4 수준, PCIe 5.0 x16(128Gbps)의 절반**
- 멀티GPU 트레이닝 시 gradient sync 병목 극심

#### 원보드 2GPU — 운영 리스크

- Puget Systems 사례: 듀얼 5090은 사실상 고출력 난방기 수준
- GPU 자체가 열을 외부로 배출하지 않는 설계 → 서버급 고RPM 팬 필수, 소음 심각
- 서버룸 전용 랙마운트로만 판매, 원격 접속 권장
- 2800W PSU에 200~240V 전용 회로 필요
- GPU 하나 장애 시 전체 다운 → 서비스 연속성 위험

#### 순수 외장 GPU 박스 (CPU 없이 GPU만) — 제품 부재

- HighPoint RocketStor 8631CW: 유일한 PCIe Gen5 x16 외장 GPU 인클로저
  - GPU 1장, $1,999 (인클로저만)
  - 호스트 PC에 PCIe 슬롯 필요 (맥 연결 불가)
- **CPU 없이 GPU 박스만 여러 장 묶는 상용 제품은 현재 존재하지 않음**
- 모든 멀티 GPU 솔루션(4장+)은 자체 CPU/메인보드 포함 독립 시스템

### 2-4. 분리 세트 구조가 최적인 이유

| 항목 | 원보드 2GPU | 분리 세트 (작가님 설계) |
|------|------------|----------------------|
| 장애 격리 | 한 GPU 문제 → 전체 다운 | 한 세트 장애 → 다른 세트 서비스 유지 |
| 냉각 | 3슬롯 GPU 2장 밀착, 폐열 간섭 | 각 세트 독립 냉각, 부담 분산 |
| 전력 | 1,500W+ 전용 회선 필수 | 각 세트 750W급, 일반 콘센트 가능 |
| 유연성 | 서비스/개발 동시 전환 어려움 | 세트 단위 역할 전환 자유 |
| 맥 연결 | 물리적 제약 | Tailscale로 어디서든 접근 |
| 확장성 | 보드 교체 필요 | 세트 추가만으로 확장 |

## 3. RTX 5090 vs RTX PRO 6000 Blackwell

| 항목 | RTX 5090 | RTX PRO 6000 Blackwell |
|------|---------|----------------------|
| CUDA 코어 | 21,760 | 24,064 |
| VRAM | 32GB GDDR7 | 96GB GDDR7 |
| 대역폭 | 1,792 GB/s | 1,600 GB/s |
| TDP | 575W | ~350W |
| PCIe P2P | 비활성화 | 활성화 |
| 멀티GPU 스케일링 | 0.91~0.97 | 0.94~0.95 |
| ECC 메모리 | 없음 | 있음 |
| 가격 | ~$2,000 | ~$6,800+ |

### 비용 시나리오

```
5090 x4:          $8,000 / 128GB VRAM / QLoRA 가능
PRO 6000 x2:     $13,600 / 192GB VRAM / FP16 여유
5090 x2 (1차):   $4,000 / 64GB VRAM / 7B~30B 최적
```

### 판단

- **현 단계**: 5090 x2 → 5090 x4로 확장 ($4,000 → $8,000)
- **서비스 확장 시**: PRO 6000을 안정적 추론 서버로 도입, 5090은 튜닝 전용 재배치

## 4. NVIDIA ↔ Mac 연결 — 새로운 가능성

### 4-1. TinyCorp 드라이버 성공 (2025년 10월)

- USB4/Thunderbolt 4를 통해 NVIDIA RTX 30/40/50 시리즈를 Apple Silicon MacBook에서 구동 성공
- 디스플레이 출력 불가, **AI 연산 가속기로만 기능**
- LLM과 신경망 연산을 Mac에서 NVIDIA GPU로 오프로드 가능

### 4-2. Apple MLX CUDA 백엔드 (2025년 7월)

- Apple의 MLX 프레임워크에 CUDA 백엔드 공식 지원 시작
- Mac에서 MLX로 프로토타이핑 → NVIDIA GPU 클러스터에 직접 배포 가능
- 핵심 연산(행렬 곱셈, softmax, reduction 등) 이미 지원

### 4-3. M5 세대 전망

- **Mac Studio M5**: 2026년 3~6월 출시 예상
- M5 Max + M5 Ultra 동시 탑재 (M4 세대의 Ultra 부재 해소)
- CPU/GPU 블록 분리 설계 → 커스터마이징 가능
- Thunderbolt 5 유지 (80/120Gbps)
- M5 Max 성능 47~54% 향상 예측, 모바일 RTX 5070 Ti 수준 도달
- 통합 메모리 대역폭 ~30% 향상 (153GB/s vs M4 120GB/s)

### 4-4. MONKOS 파이프라인에 대한 의미

```
[Mac Studio M5 Ultra]
  MLX로 프로토타이핑
       ↓ MLX-CUDA 백엔드
[5090 세트]
  QLoRA 튜닝 / 고속 추론
       ↓ Tailscale
[Mac Studio]
  결과 수신 → 개발 반복

+ TinyCorp 드라이버로 Mac → 5090 직접 AI 연산 오프로드 가능성
```

## 5. 오픈소스 경량 특화 모델 전망과 MONKOS 포지션

### 5-1. 시장 흐름 예측

- 파라미터 크기 경쟁 → **특화 경량화 경쟁**으로 전환
- 코딩 특화 (Codestral 등), 범용 다국어 (Qwen 등), 이미지 특화 (Flux 등) 포지션별 분화
- "7B인데 특정 영역에서 70B급 성능" 모델 시대 도래
- 개인/소규모 시장에 바람이 불 것이 확실

### 5-2. MONKOS의 전략적 위치

- 빅테크: 거대 모델 API 판매 구조 → 경량 특화 모델 로컬 오케스트레이션과 비즈니스 모델 충돌
- **MONKOS: 경량 특화 모델을 로컬에서 조합하여 통합 경험을 만드는 레이어**
- 오픈소스 경량 특화 모델이 많아질수록 MONKOS가 조합할 수 있는 무기가 늘어남

### 5-3. 5090 x2의 멀티 에이전트 동시 구동 시나리오

```
[5090 스테이션 + 서버박스 5090] 64GB VRAM
├── 코딩 특화 7B (6GB)      ← 막내/쌍아 역할
├── 범용 대화 7B (6GB)      ← 고객 대면
├── 이미지 특화 Flux (23GB)  ← 비주얼 생성
├── 라우터/오케스트레이터 3B (3GB)
└── 여유 26GB               ← QLoRA 튜닝 동시 가능
```

## 6. Tailscale 인프라 — 내부 신경계

### 6-1. 레이어 구분

```
[일반 서비스] 고객 폰 → Cloudflare 엣지 (300개 도시) → MONKOS 서버
  - 증명사진, 챗봇, 웹 접점
  - 빠르고 안정적

[디바이스 직결] 폰 ←→ 노트북 (WireGuard P2P)
  - 실시간 전송, 크로스 디바이스
  - 프리미엄 경험

[MONKOS 내부] Tailscale tailnet
  - 서버 간 통신, 에이전트 오케스트레이션
  - 개발 환경 동기화
  - 맥 → 5090 서버 원격 접근
```

### 6-2. WireGuard 임베드 가능성

- tsnet (Go): MONKOS 앱에 Tailscale 직접 내장 가능
- libtailscale (C): Swift FFI 연결
- WireGuardKit (iOS/macOS), wireguard-android: 네이티브 임베드
- Cloudflare BoringTun (Rust): 수백만 기기 배포 실적
- **고객은 MONKOS 앱만 설치, 내부에서 투명하게 작동**

### 6-3. 고객 경험

```
"MONKOS 가입 → 폰 앱 설치 → 노트북 앱 설치 → 끝"
- Tailscale 설치/설정 노출 안 됨
- 에어드롭보다 강력: 거리 무제한, 크로스 플랫폼, AI 통합
```

## 7. 빅테크 병목 vs MONKOS 강점

| 빅테크 | MONKOS |
|--------|--------|
| 음성/시각 각 팀 → 각 API → 각 서버 → 병목/레이턴시 | 단일 설계자 → 로컬 3B 타이밍 동기화 |

| 서버 전송 시 데이터 정렬 필요 | 서버 전송 시 이미 정렬된 멀티모달 패킷 |

## 11. 검증 결론

> **2025년 12월 설계한 (5090 멀티 + Mac Studio M5) 구조가 2026년 2월 시점 웹서치 및 벤치마크 데이터 검증을 통해 현시점 최적 시나리오임이 확인됨.**

검증 근거:
1. RTX 5090 PCIe 5.0 멀티GPU 스케일링 0.91~0.97 실측 확인
2. Thunderbolt 5 외장 연결의 14~27% 성능 로스 확인 → 분리 세트 구조 정당화
3. 원보드 2GPU의 냉각/전력/안정성 문제 확인 → 독립 세트 정당화
4. 순수 외장 GPU 박스 상용 제품 부재 확인 → 현 설계가 유일한 실용적 옵션
5. TinyCorp NVIDIA-Mac 연결 성공 + MLX CUDA 백엔드 → Mac Studio 투자 정당화
6. M5 Ultra CPU/GPU 블록 분리 설계 + TB5 → 향후 확장성 확보
7. 오픈소스 경량 특화 모델 흐름 → MONKOS 멀티 에이전트 오케스트레이션 시장 적합성 확인
8. 디딤돌/창사도약 두 과제 모두에 해당 예산 집중 배치 완료
