## 실행

```bash
# launch.json "gwansang-poc" 항목 또는:
python3 -m http.server 8807 --directory apps/gwansang-poc
# → http://localhost:8807  (?debug=1 : 앵커 인덱스 라벨 오버레이)
```

정적 서빙 필수 (ES 모듈 + fetch). 런타임 CDN 의존: Tailwind, MediaPipe Tasks Vision 0.10.14(wasm+모델 ~11MB, 최초 1회) — 오프라인 불가.

## 구조

| 파일 | 역할 |
|------|------|
| `data/gwansang_db.json` | **관상 지식 DB (정본)** — 모든 판정·해석 텍스트. 코드 수정 없이 콘텐츠 증보 가능 |
| `js/metrics.js` | 478 랜드마크 → 20개 측정치 (순수 함수, 롤 보정 포함) |
| `js/engine.js` | 측정치 + DB → 판정(bin)·오행형·리포트 조립 |
| `js/saju.js` | 60갑자 년주·일주 + 관상오행×일간오행 관계 |
| `js/app.js` | 입력·FaceLandmarker·캔버스 오버레이·렌더 |
| `schema.sql` | D1 이관용 DDL (서비스 전환 시) — 현재는 JSON이 정본 |

## DB 스키마 원칙

1. **측정 가능성 우선** — 모든 feature는 `metrics[]`의 랜드마크 번호 + 공식에 명시적으로 바인딩. "그럴듯한" 해석에 측정 근거 없는 항목 금지.
2. **판정 = bin 테이블** — `bins[].min` 내림차순 첫 매칭. 경계값은 `calibration: heuristic_v0` (초기 가설) — 실사진 표본 분포로 보정 필요.
3. **해석 3층** — `traditional`(통설) / `modern`(인상) / `career`(취업사진 전략). 부정 단정 금지, 성장 프레임.
4. **메시가 못 보는 것은 안 다룸** — 헤어라인(상정은 근사 명시), 귀, 기색(찰색), 점·흉터, 살집. 기색·퍼스널컬러는 조명 표준화 전제로 차기.
