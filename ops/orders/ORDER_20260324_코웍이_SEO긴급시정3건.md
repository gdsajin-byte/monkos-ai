## 건 1. FAQ 구조화 데이터 — mainEntity 누락 (P0)

### 현상
- 서치콘솔 → 개선사항 → 잦은 문의 사항: **"'mainEntity' 입력란이 누락되었습니다"**
- 유효 2건 / 오류 항목 존재
- 리치 결과(검색에서 FAQ 펼침 노출) 차단 상태

### 원인 — 쌍아 코드 레벨 검증 결과 (2026-03-24 03:43 KST)

> **코웍이 원래 추정(render.js 로직 문제)은 오진.** 쌍아 검증으로 원인 확정됨.

- `render.js:569-580` — `/faq` 전용 페이지의 `faqFragment()` JSON-LD는 **정상 구현**
  - `FAQPage > mainEntity > Question > acceptedAnswer` 스펙 정확
  - 유효 2건 = `/faq`, `/ja/faq` (크롤링된 페이지)
- Firestore `faq_items`: 39건 (KO 13 / JA 13 / EN 13) — 전 언어 `published: true`, **빈 배열 아님**

**진짜 원인: 홈페이지(`/`) FAQ 프리뷰**
- `home.js:139-156` — 홈에 FAQ 상위 3건을 HTML로 렌더링
- FAQ처럼 보이는 마크업 있음 (`<div class="faq-item"><h4>질문</h4><p>답변</p>`)
- 그러나 **JSON-LD 구조화 데이터 없음**
- 구글이 `/`, `/?lang=ja`, `/?lang=en` 크롤링 시 "FAQ 감지했는데 mainEntity 없다"로 오류 리포트

### 수정 방향

- **`home.js`에 JSON-LD 삽입**: faqSnap 데이터로 `FAQPage` 스키마를 홈 HTML `<head>`에 주입
- 올바른 구조:

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "질문 텍스트",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "답변 텍스트"
      }
    }
  ]
}
```

- 홈 프리뷰에 노출되는 3건만 JSON-LD에 포함 (전체 13건 아님)
- KO/JA/EN 각각 해당 lang의 faqSnap 데이터 사용
- 수정 파일: `monkos_AI/portal/lib/cms/home.js` **1곳만**

### 완료 조건
- [ ] `/` 홈에 FAQPage JSON-LD 포함 확인
- [ ] `/?lang=ja`, `/?lang=en` 동일 확인
- [ ] 서치콘솔 리치 결과 테스트 도구에서 전 URL 유효 판정
- [ ] 기존 `/faq` 페이지 JSON-LD 영향 없음 확인

## 건 2. 미색인 페이지 대응 (P1)

### 현상
- 색인됨: 26 / 미색인: 74
- 72건 "발견됨 — 현재 색인이 생성되지 않음" (구글 크롤링 우선순위 밀림)
- 404: 1건
- 리디렉션: 1건

### 수정 방향

#### (A) 404 URL 특정 + 처리
- 코웍이/민아가 서치콘솔 브라우저에서 404 해당 URL 확인 (쌍아는 코드만)
- 존재하지 않는 페이지면 사이트맵에서 제거
- 이동된 페이지면 301 리디렉션 설정

#### (B) 주요 JP 페이지 수동 색인 요청
- 코웍이 또는 민아가 서치콘솔 URL 검사에서 다음 페이지 색인 요청 가능:
  - `/ja/` (JP 메인)
  - `/ja/pricing` (JP 가격)
  - `/ja/blog/*` (JP 블로그 개별 글)
  - idphoto-jp 주요 페이지

#### (C) 내부 링크 강화
- 메인 → 블로그 개별 글 링크 추가 (크롤러 발견 경로 확대)
- 블로그 글 간 상호 링크 (관련 글 추천)
- JP/EN 메인에서 해당 언어 블로그로 직접 링크

### 완료 조건
- [ ] 404 URL 제거 또는 리디렉션 완료
- [ ] JP 핵심 5개 URL 수동 색인 요청 제출
- [ ] 내부 링크 보강 — 최소 메인→블로그 3건 이상
