**배경:**
- 코웍이가 블로그 목업 작업 중 IMAGE PRO 탐색 → 에디터 스코프가 "블로그 에디터"에서 "콘텐츠 통합 에디터"로 확장
- 작가님 비전: 애플 페이지스 + 캔바 수준의 통합 에디터 — IMAGE PRO 연동, 템플릿, 크롤러, 룩북/페이지스 동시 구현

**엔진 선택 논의 — 쌍아 vs 코웍이 견해 차이:**

| | 코웍이 권장 | 쌍아 권장 |
|--|-----------|---------|
| 엔진 | ProseMirror | Editor.js |
| 근거 | TipTap 베이스, 바닐라 순수, 확장성 | JSON 출력(Firestore 직저장+SSR 궁합), 블록 단위 지시서 분할 용이, Phase 1 도달 빠름 |

**쌍아 핵심 논점:**
- 작가님이 원하는 "페이지스/캔바" 수준은 ProseMirror로도 불가 → 어차피 캔버스 엔진(별도)이 필요
- 블로그 에디터(텍스트+블록)와 디자인 스튜디오(자유배치+레이어)는 **엔진이 두 개** — 같은 UI 안에서 탭으로 분리하는 구조 제안
- Editor.js는 블록 = 독립 클래스 = 막내 병렬 작업에 최적
- Phase 1에 빨리 도달하고, 캔버스 엔진은 Phase 3에서 별도 도입

**합의된 방향:**
- 독립 배포: `editor.monkos.ai` (IMAGE PRO 패턴 동일)
- 내부용 먼저 → 검증 → 오픈
- 엔진 최종 선택: **작가님 결정 대기** (ProseMirror vs Editor.js)

**제안한 Phase 구조:**
```
Phase 1: 블로그 에디터 코어 (코웍이 목업 기준 — 에디터 엔진 + 발행 + 자동배포)
Phase 2: IMAGE PRO 연동 블록 (에디터 안에서 이미지 생성·삽입)
Phase 3: 스튜디오 탭 — 캔버스 엔진 프로토 (템플릿 + 자유배치)
Phase 4: 에디터↔스튜디오 연결 (블로그 글에서 룩북 카드 임베드)
```
