## 0. v4 포털 작업의 맥락

v4는 단순 UI 개선이 아니라, MONKOS AI를 **SEO 최적화된 데스크톱 포털**로 전환하는 작업.

**출발 배경:**
- 구글봇이 긁어갈 콘텐츠가 없었음 — 기존은 모바일 앱 중심이라 검색 노출 불가
- 데스크톱에서 모바일 폭만 사용하는 공간 낭비

**v4 설계 원칙:**
- 중앙 영역은 기존 모바일 콘텐츠 폭 유지
- 양쪽 사이드바로 데스크톱 영역 확장 (매거진, 가이드, 크레딧 안내 등)
- note.com/monkos_ai 프로필 페이지에서 차용: 매거진 썸네일 자동 생성, SNS 공유 시스템, 전반적 디자인 톤

**핵심 목표**: 블로그/가이드/뉴스/FAQ 등 텍스트 콘텐츠를 대량 노출하여 구글 인덱싱 + 유저 체류시간 확보

## 2. 서브페이지 — SEO 관점 핵심 문제

### 공통 이슈

**🔴 디자인 단절**: 홈은 화이트 테마 + 3컬럼인데, 서브페이지(블로그/FAQ/갤러리/게시판)는 다크 테마 + 단일 컬럼 + 다른 네비게이션.
- UX: 같은 사이트인지 혼동
- SEO: 구글봇 입장에서 사이트 구조 일관성 부족 → 크롤 예산 낭비 가능

### 2-1. 블로그 — `/blog`

| 항목 | 현황 | 판정 |
|------|------|------|
| 콘텐츠 | **"No posts yet."** | ❌ SEO 치명적 |
| 언어 필터 | All / KO / JA / EN | ✅ 구조 OK |
| 홈과의 불일치 | **홈에는 블로그 글 4개 노출, /blog는 empty** | ❌ 데이터 연결 끊김 |

**SEO 영향**: /blog는 포털의 SEO 허브가 되어야 하는 페이지. 현재 empty 상태로는 구글이 인덱싱할 콘텐츠가 0. 홈에서 보이는 블로그 글 4개가 /blog에서도 동일하게 나와야 함.

### 2-2. FAQ — `/faq`

| 항목 | 현황 | 판정 |
|------|------|------|
| 콘텐츠 | "No FAQs yet." | ❌ SEO 기회 손실 |

**SEO 영향**: FAQ는 구조화 데이터(FAQ Schema)를 적용하면 구글 검색 결과에 직접 노출 가능. 현재 빈 상태로는 기회 손실.

### 2-3. 갤러리 — `/gallery`

### 2-4. 게시판 — `/board`

| 항목 | 현황 | 판정 |

## 7. note.com/monkos_ai 참고 사항

v4 포털은 note.com 자체를 복제하는 것이 아니라, 아래 요소를 차용:
- **매거진 썸네일 자동 생성**: 블로그/매거진 콘텐츠에 시각적 카드 자동 생성
- **SNS 공유 시스템**: X 등 소셜 인아웃 공유 구조
- **전반적 디자인 톤**: 히어로 + 콘텐츠 피드 + 깔끔한 카드형 레이아웃
- **프로필 페이지 구조**: 헤더 히어로 → 탭 네비 → 고정 기사 → 일반 기사 피드

note.com/monkos_ai에서 이미 실 사진 기반 콘텐츠 6건 이상 발행 중. 해당 에셋과 콘텐츠를 v4 포털과 동기화하면 SEO 콘텐츠 확보 + 디자인 품질 동시 달성 가능.
