## 왜 블로그 에디터 설계로 들어갔나

시작은 포털 UI/UX 디자인 작업이었다. 블로그 목업(DESIGN_blog_mockup.html)을 만들면서 자연스럽게 에디터 영역 설계로 진입했고, 그 과정에서 핵심 명제 하나가 도출됐다.

> **"에디터가 아름다워야 콘텐츠 품질이 올라가고, 양질의 유저가 유입된다."**

이것이 단순 UI 개선 요청이 아닌 이유다. 에디터의 품질은 작성자 경험에 직접 영향을 미치고, 작성자 경험이 좋을수록 콘텐츠의 밀도와 완성도가 올라간다. 콘텐츠 품질이 올라가면 독자층의 수준이 달라진다. 이것이 MONKOS가 에디터에 투자해야 하는 근본 이유다.

---

## IMAGE PRO 탐색에서 얻은 인사이트

같은 날 IMAGE PRO(image.monkos.ai)를 내부 탐색했다. 이 경험이 에디터 설계 방향을 결정적으로 바꿨다.

**IMAGE PRO 파이프라인 구조:**
- T2i (새로운 생성) / i2i (변화) 이원화 탭
- 소스 데이터 노드 → 빠른 변형 6카테고리 (포즈/차림새/배경/머리카락/빛/목)
- 신경 보고서: 생성 이미지 역분석 → img2prompt + 스타일 특징 + 자동 태그
- `→` 버튼: T2i 결과를 i2i 소스로 자동 장착하는 파이프라인 루프
- 엔진 스택: T2i = Imagen 4 Fast Ultra / i2i = Imagen 3 Pro (Nano Banana 3)
- 모델 추상화: API 명만 교체하면 엔진 스왑 가능한 구조

IMAGE PRO가 **이미지 생성 파이프라인**이라면, 에디터는 **콘텐츠 생성 파이프라인**이다. 에디터 안에서 IMAGE PRO를 직접 호출하고 생성된 에셋을 콘텐츠에 박아넣는 구조가 된다면, 에디터는 단순 글쓰기 도구가 아니라 **MONKOS의 모든 생성 기능을 통합하는 허브**가 된다.

## 스코프 확장: 블로그 에디터 → 콘텐츠 통합 에디터

대화 과정에서 스코프가 자연스럽게 확장됐다.

```
처음: 블로그 에디터 (글 쓰는 도구)
     ↓ IMAGE PRO 파이프라인 이해
     ↓ 포털 전체 구조 인식
현재: 콘텐츠 통합 에디터
     - 블로그/아티클
     - IMAGE PRO 직접 연동 (인라인 이미지 생성)
     - SNS 포스팅
     - 마케팅 콘텐츠
     - 한송이님 운영 콘텐츠
```

말이 블로그지, MONKOS 포털 안에서 생산되는 모든 텍스트+이미지 콘텐츠를 다루는 통합 플랫폼이다.

## 기술 스택 방향 결정

### 에디터 엔진

**직접 구현 → 불가** (브라우저 contentEditable 파편화, IME 처리, 히스토리 관리만 수개월)

**TipTap → 제외** (React 종속. 쌍아가 바닐라를 권장해온 배경과 충돌. 포털이 포털 사이즈로 확장되는 상황에서 프레임워크 종속은 배포 부담)

**ProseMirror → 채택 권장**
- TipTap의 베이스 엔진, 완전 바닐라, 프레임워크 독립
- 증명앱 노드 열몇 개 수준의 포털 확장성 대응 가능
- 커스텀 노드 시스템으로 IMAGE PRO 연동 블록 구현 가능
- 배포 독립성 유지

**Editor.js → 대안** (바닐라, 블록 기반, 구현 난이도 낮음. 단 기능 깊이가 ProseMirror 대비 얕음)

### 배포 구조

**독립 도메인 채택 권장: `editor.monkos.ai`**

IMAGE PRO가 `image.monkos.ai`로 독립된 것과 동일한 논리:
- 에디터 노드가 IMAGE PRO를 API로 호출 (종속이 아닌 대등 연결)
- 포털 전체에 영향 없이 독립 배포/업데이트
- 향후 외부 오픈 시 에디터만 선택적 퍼블릭 전환 가능
- 바닐라 포털 구조에서 ProseMirror를 해당 노드 안에서만 운용

## MONKOS 포털 전체 구도 (현재 인식 기준)

```
MONKOS 포털 (monk.kr / monkos.ai)
├── 증명사진 앱 — monkos.ai          ← 서비스 중
│   └── 노드 10개+
├── IMAGE PRO — image.monkos.ai      ← 내부 운용 중 (2달 전 프로토 완성)
│   ├── T2i: Imagen 4 Fast Ultra
│   └── i2i: Imagen 3 Pro (Nano Banana 3)
└── 콘텐츠 통합 에디터 — editor.monkos.ai  ← 설계 진입
    ├── 엔진: ProseMirror (바닐라)
    ├── IMAGE PRO API 연동 블록
    ├── 내부용 먼저 → 검증 → 오픈
    └── 한송이님 마케팅 콘텐츠 운용
```

## 설계 원칙 (IMAGE PRO로부터 계승)

1. **모델/엔진 추상화** — 에디터 엔진도 언제든 교체 가능한 구조로
2. **내부용 먼저** — 내부에서 실제 사용하며 검증 후 외부 오픈
3. **독립 노드** — 포털 전체에 종속되지 않는 독립 배포 단위
4. **파이프라인 사고** — 에디터는 도구가 아니라 콘텐츠 생성 파이프라인
