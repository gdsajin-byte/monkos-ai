# 디딤돌 창업과제 제1차 서면평가 결과 및 분석

**과제명**: 4 MUSE AI 플랫폼: 자체 GPU 인프라 기반 K-뷰티 지능형 콘텐츠 생산 시스템 개발
**사업**: 2026년도 창업성장기술개발사업(디딤돌)
**제출일**: 2026-01-23 (IRIS 시스템)
**결과 통보**: 2026-02-13
**결과**: **지원 제외**

## 1. 서면평가 결과 원문

### 기술성 평가

#### 지적 ① 오픈소스 모델 발색 정확성
> 오픈소스 모델의 화장품 실제 발색 수치 구현 정확성/신뢰성에 대한 구체적 검증 방안이 다소 미흡함

**평가 등급**: 다소 미흡함

**분석**:
- 제안서가 K-뷰티 룩북 기반이었으므로 발색 정확성 지적은 타당
- 그러나 제출 이후 AI 증명사진으로 피봇 → 발색이 아닌 정체성 보존이 핵심으로 전환
- **교훈**: 제안서에 기술 검증 방안을 정량적으로 명시해야 함 (예: "CIE Lab 색차 ΔE < 3.0 목표")

#### 지적 ② GPU 처리 속도 구체성
> 로컬 GPU(RTX 5090)로 다수 사용자에 대한 처리 속도(10초 이하) 유지에 대한 구체적 방안이 부족함

**평가 등급**: 다소 미흡함

**분석**:
- 제안서에서 "자체 GPU 인프라"를 강조했으나 구체적 벤치마크/스케일링 계획 부족
- 실제로는 클라우드 퍼스트로 운영 중이며 GPU는 비용 최적화 수단
- **교훈**: GPU 계획 시 반드시 구체적 수치 제시 필요
  - 모델별 추론 시간 (실측 or 공개 벤치마크)
  - 동시 사용자 수 × 추론 시간 = 필요 GPU 메모리/코어
  - 클라우드 폴백 시나리오

#### 지적 ③ 범용 GenAI 대비 차별성
> 범용 GenAI 서비스 대비 제안 기술의 차별성 및 기술자립 방안에 대한 구체성이 다소 미흡함

**평가 등급**: 다소 미흡함

**분석**:
- "API를 사용한다"는 것 자체가 약점으로 인식됨
- 평가자는 "왜 직접 만들지 않는가?"라는 관점
- **교훈**: 기술자립 로드맵을 단계별로 명시해야 함
  - 현재: 클라우드 API 활용 (MVP 검증)
  - 6개월: 로컬 추론 도입 (API 의존도 70% → 50%)
  - 12개월: 자체 파인튜닝 모델 (API 의존도 30%)
  - "시스템 통합"이 핵심 가치임을 강조 (API ≠ 제품)

---

### 사업성 평가

#### 지적 ④ 학습 데이터 저작권 리스크
> 학습 데이터 크롤링 과정에서 발생할 수 있는 저작권 침해, 원저작권자 수익 배분 등의 법적 리스크에 대한 구체적 해결 방안이 다소 미흡함

**평가 등급**: 다소 미흡함

**분석**:
- 크롤링 데이터 사용을 명시한 것이 역효과
- 정부과제에서 저작권 리스크는 매우 민감한 영역
- **교훈**:
  - "크롤링" 대신 "공개 데이터셋 활용" 또는 "자체 촬영 데이터" 강조
  - 데이터 거버넌스 계획 반드시 명시
  - 법적 자문 결과 또는 계획 첨부

#### 지적 ⑤ 경쟁사 비교 부적절
> Adobe Firefly, Runway, Stitch Fix 등 글로벌 경쟁 서비스 대비 K-뷰티 특화만으로는 차별화된 경쟁력 확보가 다소 미흡함

**평가 등급**: 다소 미흡함

**분석**:
- **평가자의 오해 가능성**: 범용 이미지 생성 도구와 비교했으나 실제 경쟁 영역이 다름
- 그러나 제안서 본문에서 경쟁사 분석이 부족했거나 잘못된 비교군을 제시했을 가능성
- **교훈**:
  - 경쟁사 분석 시 **정확한 비교군** 선정 필수
  - "Adobe vs 우리"가 아닌 "오프라인 사진관 vs 우리" 또는 "PhotoAiD vs 우리"
  - TAM/SAM/SOM 시장 크기를 명확히 구분

#### 지적 ⑥ 고해상도 비용 모순
> 고해상도(4K/300dpi) 이미지 처리를 위한 AI 서비스 운영 비용과 소상공인 대상 저비용 서비스 제공 목표 간의 모순이 해소되지 않음

**평가 등급**: 미흡함 (7건 중 유일하게 "다소" 없음 → **가장 부정적**)

**분석**:
- **가장 심한 지적**. "다소 미흡함"이 아닌 "미흡함"
- 비용 구조를 제안서에서 구체적으로 제시하지 않은 것이 원인
- **교훈**:
  - 원가 구조를 숫자로 제시 (1회 서비스 원가 $X, 판매가 $Y, 마진율 Z%)
  - "저비용"의 정의를 명확히 (누구 대비 저비용인지)
  - 단계별 해상도 제공 계획 (웹용 → 인쇄용 → 프리미엄)

#### 지적 ⑦ 사업화 전략 구체성
> 사업화 및 시장 확산 전략의 구체성이 다소 미흡함

**평가 등급**: 다소 미흡함

**분석**:
- "할 것이다"만 있고 "어떻게 할 것이다"가 부족
- **교훈**:
  - Phase별 구체적 수치 (MAU 목표, CAC, LTV)
  - 채널별 마케팅 전략 + 예산
  - 이미 달성한 것과 앞으로의 계획 분리
  - "이미 서비스 중"이라는 사실을 강력하게 어필

## 2. 종합 분석

### 평가 등급 분포
| 등급 | 횟수 | 비고 |
|------|------|------|
| 다소 미흡함 | 6건 | ①②③④⑤⑦ |
| 미흡함 | 1건 | ⑥ (비용 모순) — 가장 치명적 |

### 결과 해석
- 7건 모두 "부정적" → 서면 탈락은 불가피했음
- 그러나 "매우 미흡함"이나 "아이디어 자체가 부적합" 같은 극단적 평가는 없음
- **제안서 보강으로 2차에서 통과 가능성 있음**

### 근본 원인
1. **피봇 미반영**: 제안서 작성(1/17) 시점과 평가(2/13) 시점 사이에 사업 방향이 크게 변함
2. **구체성 부족**: "할 것이다"가 많고 "이렇게 한다/이미 했다"가 부족
3. **비용 구조 미제시**: 마진율 99.6%라는 강력한 수치를 제안서에 넣지 않음
4. **경쟁사 분석 오류**: 비교군 선정이 부적절 (Adobe/Runway ≠ 증명사진 시장)

## 3. 향후 정부과제/자금심사 체크리스트

### 제안서 작성 시 필수 포함 사항

**기술성:**
- [ ] 핵심 기술의 정량적 목표 (정확도 %, 처리시간 초, 해상도 dpi)
- [ ] 기술 검증 방법 및 수단 (벤치마크, A/B 테스트, 전문가 평가)
- [ ] 기존 경쟁 기술 대비 차별점 (동일 카테고리 내 비교)
- [ ] 기술자립 로드맵 (API 의존도 % 감소 단계)
- [ ] GPU/인프라 스케일링 계획 (구체적 수치 + 폴백 시나리오)

**사업성:**
- [ ] 원가 구조 (1회 서비스 비용 상세 분해)
- [ ] 매출 시나리오 (보수적/기본/낙관적)
- [ ] 경쟁사 분석 (정확한 비교군 + 차별점 매트릭스)
- [ ] 마케팅 채널별 전략 + 예산 + KPI
- [ ] 법적 리스크 대응 (저작권, 개인정보, 초상권)
- [ ] "이미 달성한 것" vs "앞으로 할 것" 명확 분리

**공통:**
- [ ] "계획"보다 "실적" 강조 (이미 서비스 중이면 반드시 명시)
- [ ] 데모 URL 또는 스크린샷 첨부
- [ ] 팀 역량 = 생산성 증거 (커밋 수, 배포 횟수, 개발 속도)

## 4. 와신상담 — 이 문서의 용도

이 문서는 단순 기록이 아닌 **향후 모든 심사 대비 기준서**로 활용한다:

- **디딤돌 2차 공고** → 이 7건 지적사항을 모두 해소한 제안서 작성
- **TIPS** → 동일 구조로 기술성/사업성 사전 점검

- **투자유치 IR** → 사업성 질문 사전 대비
- **정부 R&D 전반** → 체크리스트로 제안서 품질 보증
