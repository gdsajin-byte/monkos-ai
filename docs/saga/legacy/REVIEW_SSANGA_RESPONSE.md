## ⚠️ 실행 관점에서의 보완 의견

### 1. 구현 순서 조정 필요

**용아 제안**: 바로 Dockerizing 시작  
**쌍아 의견**: 단계적 접근 권장

```
[용아 순서]
Dockerizing → 배포 → 연동

[쌍아 제안 순서]
1. 기존 코드 검증 (이미 작동 중)
2. GCS 버킷 생성 (위험 낮음)
3. 최소 수정 후 Docker화
4. Cloud Run 배포 + IAM 확인
5. 프론트엔드 연결
6. 도메인/CDN은 안정화 후
```

**이유**: 
- 새 코드 작성 시 새로운 버그 발생 위험
- 어제 "유령 ID 사태"도 불필요한 수정에서 발생
- 검증된 코드 기반 최소 변경이 안전

---

### 2. 인증 방식 - 2단계 접근

**용아 제안**: Custom API Key로 빠르게  
**쌍아 의견**: 동의, 단 주의사항 추가

```
[Phase 1 - 23일 마감 전]
- Custom API Key (Header 방식)
- 빠른 구현, 데모 가능
- API Key는 Cloud Run 환경변수로만 관리
  ⚠️ 코드 하드코딩 절대 금지 (어제 교훈)

[Phase 2 - 마감 후]
- Firebase Auth 도입
- 사용자별 사용량 추적
- 결제 연동 준비
```

---

### 3. 저장소 아키텍처 상세화

**용아 제안**: GCS + Cloudflare CDN  
**쌍아 의견**: 훌륭한 조합, 구현 방법 명확화 필요

```
[권장 구조]
Cloud Run → GCS (비공개) → Cloudflare CDN → 사용자

[구현 방법]
1. GCS 버킷: 비공개 설정
2. Cloud Run에서 Signed URL 생성
   또는
3. Cloudflare에 GCS 오리진 연결
4. 캐싱으로 바우처 절약
```

**바우처 절약 효과**:
- GCS 직접 전송: $0.12/GB
- Cloudflare 캐싱 후: 거의 무료
- 이미지 1만 장 기준 약 $100+ 절약 가능
