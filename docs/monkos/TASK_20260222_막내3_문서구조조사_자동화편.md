# 막내3: 문서 전수조사 — 자동 분류 규격 + 지시서/보고서 템플릿 설계

## 배경
- 문서 폴더 구조가 정비되면 "파일 생성 → 자동 분류"가 가능해야 함
- 데몬(철창이/소넷이)이 파일명만 보고 올바른 폴더에 배치할 수 있는 규격 필요
- 지시서/보고서 템플릿이 표준화되면 파싱 → 검증 → 라우팅 자동화 가능
- 막내1 = 파일 인벤토리, 막내2 = 기술명세 로직, **막내3 = 자동화 규격** (병렬)

## TASK

### T1: 파일명 자동 분류 규격 설계
- 파일명 패턴 → 대상 폴더 매핑 규칙 설계
- 예시:
  ```
  TASK_YYYYMMDD_*.md        → tasks/YYYY-MM/
  SPEC_*.md                 → specs/{서비스명}/
  REPORT_YYYYMMDD_*.md      → reports/YYYY-MM/
  INCIDENT_YYYYMMDD_*.md    → incidents/YYYY-MM/
  YYYYMMDD_session*.md      → sessions/YYYY-MM/
  ```
- 분류 불가능한 패턴(기타)의 처리 규칙
- 파일명에서 추출해야 하는 메타데이터: 날짜, 에이전트, 서비스명, 타입

### T2: YAML frontmatter 표준 규격
- 모든 문서 타입별 필수/선택 YAML 필드 정의
- 지시서, 보고서, 기술명세, 세션로그, 장애기록 각각
- 자동 파싱 시 사용할 필드명 통일 (snake_case)
- 예:
  ```yaml
  ---
  type: task | spec | report | incident | session
  id: 고유 ID (파일명과 동일)
  service: idphoto-kr | portal | infra | common
  date: YYYY-MM-DD HH:MM KST
  status: pending | in_progress | completed | archived
  ---
  ```

### T3: 지시서 표준 템플릿 최종안
- 현재 10개+ 지시서 분석 (막내1 보고서의 REPORT_20260222_에이전트오케스트레이션.md 4.2절 참조)
- 대형 지시서 vs 소형 보정 지시서 구분
- 필수 섹션: 배경, TASK, 대상파일, 건드리지않는파일, 완료조건, 주의, **핵심요약**
- parent 참조 규칙 (보정 지시서 → 원본 지시서 ID)

### T4: 보고서 표준 템플릿 최종안
- 완료 보고 형식: YAML frontmatter + 결과표 + 완료조건 체크 + 변경파일 + 핵심요약
- **핵심요약은 보고 말미 필수** (작가님 한눈 검수용)
- diff 대조 자동화를 위한 "변경 예상 파일 + 라인" 명시 규격
- 쌍아 검증용 체크리스트 자동 생성 가능 구조

### T5: 데몬 자동 분류 시나리오 설계
- 시나리오 1: 쌍아가 `TASK_*.md` 생성 → 데몬이 감지 → `tasks/YYYY-MM/`으로 이동
- 시나리오 2: 막내가 `REPORT_*.md` 생성 → 데몬이 감지 → `reports/YYYY-MM/`으로 이동
- 시나리오 3: 텔레그램 팀챗에서 md 수신 → 디바이스 데몬이 파싱 → 올바른 경로에 배치
- 각 시나리오의 트리거, 파싱 로직, 배치 규칙, 에러 처리

### T6: 보고서 작성
- 파일: `docs/monkos/REPORT_20260222_자동분류규격.md`
- 구조:
  1. 파일명 → 폴더 매핑 규칙 (전체 테이블)
  2. YAML frontmatter 표준 규격 (타입별)
  3. 지시서 표준 템플릿 최종안
  4. 보고서 표준 템플릿 최종안
  5. 데몬 자동 분류 시나리오 3건
  6. 헌법/법률 반영 제안 (어떤 조항에 어떤 내용을 추가할지)
