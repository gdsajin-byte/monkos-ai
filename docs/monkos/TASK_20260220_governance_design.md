## 작업 내용

### Step 1: 참조 문서 읽기

### Step 2: CLAUDE.md 재구성 골격 설계

현행 372줄을 **위계 체계로 재배치**한 골격을 설계.

```markdown
# MONK.KR 프로젝트 헌법 및 법률

## 전문 (Preamble)
- 프로젝트 정체성 (이름, 비전, 도메인)
- 이 문서의 위계 설명
- 에이전트 대응 프로토콜 (★ 핵심 신규)

---

## 헌법 (Constitution) — 제1조~제N조
> 불변 원칙. 어떤 에이전트든 반드시 준수.
> 위반 시: 하위 법률 연쇄 영향 경고 + 재조정 범위 명시.

제1조: ...
제2조: ...
...

---

## 법률 (Laws) — 제1장~제N장
> 운용 규칙. 현재 유효하나 작가님 승인 시 예외/변경 가능.
> 위반 시: 해당 조항 인용 + 예외 확인.

### 제1장: ...
1조: ...
2조: ...

### 제2장: ...
...

---

## 규정 참조 (Regulations Reference)
> 기술 상세. 별도 파일 참조.
> 경로: docs/infrastructure/TECHNICAL_REGULATIONS.md
```

설계 원칙:
1. **줄 수 예측**: 헌법+법률을 합쳐 **200줄 이내** 목표 (현재 372줄에서 기술 상세를 빼면 가능)
2. **현행 규칙 누락 없이 재배치** — 삭제하는 것이 아니라 재분류
3. **각 섹션에 에이전트 행동 지침을 인라인으로** — "이 섹션 위반 시 ~하라"
4. MEMORY.md와의 역할 분담 명시

### Step 3: 에이전트 대응 프로토콜 설계

CLAUDE.md 전문(Preamble)에 들어갈 **에이전트 행동 분기 로직**.

```markdown
## 에이전트 대응 프로토콜

작가님의 지시가 본 문서의 규칙과 충돌할 때, 아래에 따라 행동한다.

### 헌법 위반 감지 시
1. 해당 헌법 조항 번호와 내용을 인용
2. 이 조항이 깨질 경우 영향받는 하위 법률 조항 목록을 제시
3. 재조정이 필요한 범위를 명시
4. 작가님께 진행 여부를 확인
5. 작가님이 명시적으로 승인한 경우에만 진행

### 법률 위반 감지 시
1. 해당 법률 조항 번호와 내용을 인용
2. "예외로 진행하시겠습니까?" 확인
3. 작가님 승인 시 진행, 세션 로그에 예외 기록

### 규정 변경 필요 시
1. 현재 값과 변경 값을 보고
2. 에이전트 자율 판단으로 진행 가능 (사후 보고)
```

### Step 4: MEMORY.md 역할 재정의

현행 MEMORY.md(192줄)와 재구성된 CLAUDE.md의 **역할 분담**을 명확히.

| | CLAUDE.md | MEMORY.md |
|---|---|---|
| 성격 | 헌법+법률 (행동 규칙) | 프로젝트 지식 (사실 기록) |
| 내용 | "~하라", "~금지" | "X는 Y이다", "A의 단가는 B" |
| 변경 | 작가님 결정 시에만 | 사실 변경 시 수시 |
| 중복 | 없어야 함 | 없어야 함 |

### Step 5: 마이그레이션 로드맵

현행 CLAUDE.md 372줄 → 재구성된 CLAUDE.md로의 전환 계획.

```markdown
## 마이그레이션 로드맵

### Phase 1: 골격 확정 (작가님 승인)
- 헌법 조항 목록 확정
- 법률 장/조 구조 확정
- 대응 프로토콜 확정

### Phase 2: 성문화 (막내 실행)
- 막내1 조항 코드표 + 본 설계 골격 = 합본
- CLAUDE.md 재작성
- 기술 규정 별도 파일 분리

### Phase 3: 검증 (에이전트 테스트)
- 새 CLAUDE.md로 막내 투입 → 실제로 조항 인용하는지 확인
- 헌법/법률 위반 시나리오 테스트
- 조정 후 프로덕션 적용
```
