## 1. 3가지 구현 경로 심층 비교

### 경로 A: Desktop Remote Session (Anthropic 클라우드)

**기술 사양:**
- Claude Desktop Code 탭에서 "Remote" 환경 선택, 또는 CLI에서 `claude --remote "task"` / `& task` 프리픽스
- Anthropic 서버의 격리 VM에서 실행. GitHub 레포를 자동 클론하여 샌드박스 내 작업
- 모니터링: Claude Desktop 앱, claude.ai/code, iOS/Android 앱
- 세션 핸드오프: Web→Terminal은 `/teleport` 명령, Terminal→Web은 `&` 프리픽스(새 세션 생성)

**비용 모델:**

| 시나리오 | 월 비용 | 근거 |
|----------|---------|------|
| 최소 (간헐 사용) | $0 추가 | Max 구독($100) 내 소모 |
| 표준 (일 5-10 태스크) | $0 추가 | 구독 레이트 리밋 내 |
| 최대 (고빈도) | $0 추가, 레이트 리밋 도달 | 구독 레이트 리밋이 병목 |

**보안 모델:**
- Anthropic 관리 VM 샌드박스 — Ask permissions 없음(이미 격리), Bypass도 없음
- 네트워크 접근: 기본 허용 도메인 화이트리스트 (커스텀 설정 가능)
- GitHub OAuth 인증 기반
- 코드는 Anthropic 서버에 일시 보관 → 세션 종료 후 삭제

**가용성:**
- 앱을 꺼도 작업 지속 (서버 독립 실행) — 24/7 유사
- 단, **태스크 스코프 세션**이지 영구 상주 데몬이 아님. 작업 완료 시 세션 종료
- 네트워크 장애 시 자동 재연결

**확장성:**
- 멀티 레포 동시 추가 지원
- 여러 Remote 세션 병렬 실행 가능
- 에이전트 추가 = 새 세션 생성 (독립)

**MONK OS 통합:**
- CLAUDE.md가 GitHub 레포에 있으므로 자동 로딩 → 헌법 체계 적용됨
- Git 기반 작업이므로 커밋/PR 자동 생성 가능
- 세션 간 컨텍스트 공유 불가 (각 세션 독립)
- 세션 로그/보고서 생성은 Git 커밋으로 남김

**제약 사항:**
- **GitHub 레포 전용** — GitLab/Bitbucket/로컬 전용 레포 불가
- **프로그래밍적 제어 제한** — `&`/`--remote`로 태스크 전송만 가능, 콜백/훅/조건부 로직 불가
- **영구 상주 불가** — 태스크 완료 시 세션 종료. "항시 깨어 있는 라우터" 불가능
- **로컬 파일시스템 접근 불가** — Anthropic VM 내에서만 동작
- **구독 레이트 리밋 공유** — 다른 Claude 사용(쌍아/막내 대화 등)과 쿼터 경쟁
- 현재 **Research Preview** 단계

### 경로 B: Agent SDK (`@anthropic-ai/claude-agent-sdk`)

**기술 사양:**
- npm 패키지 `@anthropic-ai/claude-agent-sdk` (TypeScript) / `pip install claude-agent-sdk` (Python)
- `query()` 함수: async generator로 메시지 스트리밍
- Claude Code와 동일한 도구 세트 (Read, Edit, Bash, Glob, Grep 등) 사용 가능
- 멀티턴 세션: `session_id`로 resume 가능
- 서브에이전트 정의, 훅 콜백, 구조화된 출력(JSON Schema) 지원
- 로컬 실행 또는 Cloud Run/EC2 등 클라우드 배포 가능

**비용 모델:**

| 시나리오 | 월 비용 | 근거 |
|----------|---------|------|
| 최소 (경량 라우팅) | ~$15-30 | Haiku 4.5 기준, 일 50회 × ~3K 토큰 |
| 표준 (분석+라우팅) | ~$55-100 | Sonnet 4.5 기준, 일 100회 × ~5K 토큰 |
| 최대 (복합 판단) | ~$150-300 | Opus 4.6 기준, 일 100회 × ~5K 토큰 |

> Opus: 입력 $5/M, 출력 $25/M · Sonnet: 입력 $3/M, 출력 $15/M · Haiku: 입력 $1/M, 출력 $5/M
> 프롬프트 캐시 적중 시 0.1배, Batch API 사용 시 50% 할인

**보안 모델:**
- `ANTHROPIC_API_KEY` 기반 인증 — 키 관리가 핵심
- `permissionMode` 설정: `default`(승인 필요), `acceptEdits`(편집 자동 승인), `bypassPermissions`(전체 자동)
- `allowedTools` 화이트리스트로 사용 가능 도구 제한
- `sandbox` 설정으로 격리 환경 구성 가능
- `maxBudgetUsd`로 비용 상한 설정

**가용성:**
- Node.js 프로세스로 실행 → **pm2/systemd로 24/7 상주 가능**
- 프로세스 크래시 시 자동 재시작 설정 가능
- 세션 ID로 중단된 대화 이어가기 가능

**확장성:**
- 서브에이전트를 코드로 정의 → 에이전트 추가 = 설정 추가
- MCP 서버 연동 (외부 도구 통합)
- 모델 동적 전환 (`setModel()`)
- 멀티 프로젝트: cwd 파라미터로 작업 디렉토리 전환

**MONK OS 통합:**
- `settingSources`로 CLAUDE.md 로딩 가능 → 헌법 체계 적용
- `systemPrompt`로 라우터 전용 규칙 추가 주입 가능
- 훅(PreToolUse, PostToolUse)으로 파괴적 명령 차단 로직 구현 가능
- 구조화 출력으로 보고서/지시서 형식 강제 가능
- Firestore/SQLite 연동으로 명령 큐/로그 저장

**제약 사항:**
- **API 키 필수** — claude.ai 구독 토큰 사용 불가. 별도 API 비용 발생
- **Anthropic 정책**: 서드파티가 claude.ai 로그인/레이트 리밋을 제품에 사용하는 것 금지
- **서버 필요** — 로컬 머신 또는 클라우드 인스턴스에서 상시 실행
- **복잡도** — 코드 작성/유지보수/디버깅 필요
- 현재 V2 프리뷰 단계 (인터페이스 변경 가능성)

### 경로 C: command_bridge.js 진화 (`claude -p` 기반)

**기술 사양:**
- 현행: Firestore `commands/ssanga/queue` 실시간 리스너 → `claude -p "<command>" --print` 실행 → 결과 Firestore 기록
- CLI `--print` 모드: 비대화형 단일 요청/응답. `--output-format json`으로 구조화 출력
- `--resume <session_id>`로 멀티턴 대화 가능
- `--continue`로 직전 세션 이어가기
- `--allowedTools`로 도구 제한 가능
- `--append-system-prompt`로 추가 시스템 프롬프트 주입

**비용 모델:**

| 시나리오 | 월 비용 | 근거 |
|----------|---------|------|
| 최소 | $0 추가 | Max 구독($100) 내 소모 (`claude -p`는 구독 토큰 사용 가능) |
| 표준 | $0 추가 | 구독 레이트 리밋 내 |
| 최대 | $0 추가, 리밋 도달 | 쿼터 경쟁 발생 시 대기 |

> **핵심**: `claude -p`는 API 키 또는 claude.ai 계정 모두 사용 가능. 구독 기반이면 추가 비용 0.

**보안 모델 (현행 문제점):**

| 취약점 | 심각도 | 현재 상태 |
|--------|--------|----------|
| Firestore 인증 부재 | **치명** | 누구든 명령 큐에 쓸 수 있음 |
| `shell: true` | **치명** | 커맨드 인젝션 가능 |
| serviceAccountKey.json 참조 | **높음** | 시크릿 파일 코드에 하드코딩 |
| Windows 경로 하드코딩 | 중간 | 크로스 플랫폼 불가 |
| 입력 검증 부재 | **높음** | 임의 명령 실행 가능 |

**가용성:**
- pm2로 백그라운드 실행 + 30분 하트비트 — 24/7 상주 가능
- 10분 타임아웃 설정 존재
- Firestore 리스너 에러 시 알림

**확장성:**
- 에이전트 추가: Firestore 컬렉션 추가 (`commands/{agentName}/queue`)
- 프로젝트 추가: `PROJECT_DIR` 분기 로직 추가
- 단, 구조가 단순하여 복잡한 라우팅 로직 추가 시 코드 복잡도 급증

**MONK OS 통합:**
- `PROJECT_DIR`을 monk_project로 설정하면 CLAUDE.md 자동 로딩
- `--append-system-prompt`로 라우터 규칙 추가 가능
- `--resume`으로 멀티턴 컨텍스트 유지 가능
- 알림 API(`notifyWriter`)로 작가님 텔레그램 알림 연동 가능

**제약 사항:**
- **단일 요청/응답** — 대화형 세션 관리에 한계 (`--resume`으로 부분 보완)
- **슬래시 커맨드 미지원** — `/commit`, `/review-pr` 등 불가
- **도구 승인 대기** — `--allowedTools` 또는 `--dangerously-skip-permissions` 필요
- **보안 취약점 다수** — 프로덕션 투입 전 전면 보수 필수
- **Firestore 의존** — 외부 서비스 의존성

## 3. 라우터 클로드 구현 아키텍처

### 전체 시스템 아키텍처

```
[인입 채널]                    [라우터 클로드]                    [실행 에이전트]
                               (command_bridge v2)
                               iMac pm2 상주
                                    │
~/Desktop/철창이/ ──┐               │
~/Desktop/용아/   ──┤  launchd      │
꾸 우체통 (SSH)   ──┼─ 파일감시 ──→ ┤
텔레그램 봇       ──┤               │
n8n 산출물        ──┤               │                     ┌─ iMac/쌍아 (VSCode)
작가님 직접       ──┘               │                     │   └─ 전략 해석, 지시서
                                    │                     │
           Firestore               ├── 분류 엔진 ───────→├─ iMac/막내N (iTerm)
           commands/               │   (규칙 기반)        │   └─ 코딩, 빌드, 배포
           router/                 │                     │
           queue                   ├── 컨텍스트 저장소 ──→├─ 4060/소넷이 (tmux)
             │                     │   (session_id DB)    │   └─ 모니터링, 경량 자동화
             ▼                     │                     │
     [인증+검증 레이어]            ├── 안전장치 ─────────→└─ Remote Session
       Firebase Auth               │   (헌법 8조)             └─ 중량 비동기 태스크
       + 명령 화이트리스트          │
       + 시크릿 패턴 차단           ├── 알림 ──→ 텔레그램/Notify API
                                    │
                                    └── 로그 ──→ Firestore + Git
                                         (인입 레지스트리)
```

### 명령 수신 방식

1. **Firestore 큐** (기존): `commands/router/queue` 실시간 리스너
2. **파일시스템 감시** (신규): launchd/fswatch로 `~/Desktop/철창이/`, `~/Desktop/용아/` 등 감시
3. **텔레그램 봇 웹훅** (Phase 5): Firestore에 명령 기록 → 라우터 처리
4. **작가님 CLI** (직접): `claude -p "라우터에게: ..."` 또는 전용 스크립트

### 맥락 보존 방식

```
[세션 컨텍스트 DB] (SQLite 또는 Firestore)
  │
  ├── router_sessions
  │     ├── session_id (claude -p 반환값)
  │     ├── source_channel (철창/용아/텔레그램/...)
  │     ├── topic_hash
  │     ├── created_at / last_active
  │     └── turn_count
  │
  └── routing_log
        ├── command_id
        ├── source → target (라우팅 경로)
        ├── action_type (direct/delegate/remote)
        ├── result_summary
        └── timestamp
```

- **같은 토픽의 명령** → `--resume <session_id>`로 맥락 이어가기
- **새 토픽** → 새 세션 생성, session_id 저장
- **세션 만료** → 24시간 미활동 시 세션 아카이브

### 에러 처리

| 에러 유형 | 처리 방식 | 알림 |
|-----------|----------|------|
| 인증 실패 | 명령 거부, 로그 기록 | ❌ (보안상 무응답) |
| 금지 명령 감지 | 명령 거부, `status: blocked`, 차단 사유 기록 | ⚠️ 작가님 알림 |
| claude -p 실행 실패 | 3회 재시도 (30초 간격) → 실패 시 `status: failed` | ⚠️ 작가님 알림 |
| 타임아웃 (10분) | 프로세스 kill, `status: timeout` | ⚠️ 작가님 알림 |
| Firestore 연결 끊김 | 자동 재연결 (firebase-admin 내장). 5분 연속 실패 시 프로세스 재시작 | 🔴 긴급 알림 |
| 분류 불확실 | staging/ 배치, 쌍아 판단 위임 | 💡 쌍아 알림 |

### 타임아웃 정책

| 유형 | 타임아웃 | 근거 |
|------|---------|------|
| 경량 명령 (분류/분석) | 3분 | 단순 파싱, 빠른 응답 기대 |
| 표준 명령 (코드 작업) | 10분 | 현행 유지 |
| 중량 명령 (Remote 위임) | 60분 | Remote Session은 장시간 |
| 하트비트 | 30분 | 현행 유지 |

### 우선순위 큐

| 우선순위 | 코드 | 처리 순서 | 사용 경우 |
|----------|------|----------|----------|
| **긴급** | P0 | 즉시 (현재 작업 완료 후 최우선) | INCIDENT, 작가님 직접 명령 |
| **높음** | P1 | 큐 선두 삽입 | 지시서 실행, 배포 관련 |
| **표준** | P2 | FIFO 순서 | 일반 분석/보고 |
| **낮음** | P3 | 유휴 시 처리 | 자동 분류, 정리 작업 |

```
Firestore Queue 구조:
  commands/router/queue/
    ├── {commandId}
    │     ├── priority: "P0" | "P1" | "P2" | "P3"
    │     ├── status: "pending" | "processing" | "completed" | "failed" | "blocked"
    │     ├── command: string
    │     ├── source: string
    │     ├── createdAt: timestamp
    │     └── ...
    │
    └── 정렬: priority ASC → createdAt ASC
```
