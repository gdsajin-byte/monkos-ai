## 1. 발견된 문제

### 1.1 ch4 1조의 docs/ 트리가 "완성형"으로 읽힌다

현행 ch4 1조는 docs/ 하위에 11개 폴더(infrastructure 6개 + monkos 5개 + specs 4개)를 트리로 정의하고 있다.

그러나 현실:
- `docs/specs/` — 존재하지 않음
- `docs/infrastructure/architecture/` 등 5개 — 존재하지 않음
- `docs/monkos/reports/`, `incidents/`, `designs/`, `sprints/` — 존재하지 않음
- `docs/monkos/` 루트에 105개 파일 플랫 배치
- `docs/infrastructure/` 루트에 62개 파일 플랫 배치

이것은 **법률 위반이 아니라, 법률이 "목표 상태"를 정의한 것인데 "현재 의무"로 읽히는 표현 문제**다.

### 1.2 docs의 본질이 불명확

ch4 4조에 "docs/ = 참고문헌 체계, monkos-ops/ = 운영체제"가 명시되어 있다.
그러나 ch4 1조의 트리가 완성된 폴더 구조처럼 정의되어 있어, 다음 혼란이 발생:

- 에이전트가 ch4 1조를 읽으면 "이 폴더들이 있어야 한다" → 즉시 위반 검출
- 작가님 의도: "docs는 원천(raw), ops로 정제(curate)하는 과정" → 과도기에 있는 것이 정상

**docs가 원천 아카이브인지, 즉시 정돈되어야 하는 참고문헌 서가인지 — 현행 ch4에서 명확하지 않다.**

### 1.3 ch4 2조 5항·7항이 즉시 적용 불가능

| 조항 | 내용 | 현실 |
|------|------|------|
| 2조 5항 | TASK_* docs/monkos/ 루트 배치 금지 → tasks/YYYY-MM/ 하위 | 목적지 폴더 미생성. 105개 파일 이동 미실행 |
| 2조 7항 | README.md 미보유 폴더 방치 금지 | 법률 1조 트리 폴더 자체가 미생성이므로 README 의무도 적용 불가 |

법률이 "즉시 준수해야 하는 규범"으로 발효됐는데, 물리적 전제 조건(폴더 생성 + 파일 이동)이 갖춰지지 않은 상태다.

## 2. 개정 제안

### 2.1 ch4 1조: "목표 구조"와 "현재 유효 구조"를 분리

**현행 문제**: 트리 하나로 목표와 현재를 겸하고 있어 혼란.

**제안**: 1조를 두 파트로 분리.

```
### 1조: docs/ 구조

#### 현재 유효 구조 (2026-02-22 기준)
{실제 존재하는 폴더만 나열}

#### 목표 구조 (Phase 2 이행 완료 시)
{현행 트리 유지}

#### 이행 규칙
- 목표 구조의 폴더는 해당 파일이 최초 생성되는 시점에 생성한다 (선제 생성 금지).
- 폴더 생성 시 README.md 동시 생성 (2조 7항).
- docs/monkos/ 루트의 기존 파일은 Phase 2 이행 지시서로 일괄 이동한다.
```

**핵심**: "docs/specs/portal/이 없다"가 위반이 아니라, "portal SPEC이 처음 생성될 때 폴더와 함께 만든다"가 되도록.

### 2.2 ch4 4조: docs의 본질 명시 — "원천 → 정제" 파이프라인

**현행 문제**: docs = 참고문헌이라고만 되어 있고, 원천 데이터가 쌓이는 과정에 대한 언급이 없다.

**제안**: 4조에 다음 원칙 추가.

```
#### docs ↔ ops 파이프라인

docs/는 **원천 아카이브**다. 에이전트의 작업 산출물(지시서, 보고서, 명세)이 최초 생성되는 곳이다.
monkos-ops/는 **정제된 운영체제**다. docs/에서 검증·승인된 문서가 정본으로 승격되는 곳이다.

원칙:
1. 신규 문서는 docs/에 먼저 생성한다 (ch4 3조 네이밍 규칙 준수).
2. 승인·검증이 완료되면 ops/ 해당 위치로 정본 승격한다.
3. 승격된 문서의 docs/ 원본은 참조용으로 유지하되, 수정은 정본(ops/)에서만 한다.
4. 세션 로그는 예외 — ops/06_로그/sessions/에 직접 생성한다 (현행 유지).
```

**효과**: "docs에 파일이 쌓여 있는 것"이 위반이 아니라, 파이프라인의 정상적인 원천 단계가 됨.

### 2.3 ch4 2조 5항: 이행 유예 조건 추가

**현행**: "지시서(TASK_*) docs/monkos/ 루트 직접 배치 금지"
**문제**: 105개 기존 파일의 이동이 완료되기 전까지 매 순간 위반 상태.

**제안**:
```
5. 지시서(TASK_*) docs/monkos/ 루트 직접 배치 금지. 반드시 `tasks/YYYY-MM/` 하위에 배치.
   — 이행 유예: 2026-02-22 이전 생성 파일은 Phase 2 이행 지시서로 일괄 이동 시까지 현 위치 유지.
   — 신규 생성분부터 즉시 적용.
```

### 2.4 ch4 2조 7항: 적용 시점 명확화

**현행**: "README.md 미보유 폴더 방치 금지. 폴더 생성 시 README.md 동시 생성 의무."
**문제**: "방치 금지"가 소급 적용으로 읽히면 기존 모든 폴더가 즉시 위반.

**제안**:
```
7. 폴더 생성 시 README.md 동시 생성 의무. 본 조항 발효(2026-02-22) 이후 신규 폴더에 적용.
   — 기존 폴더는 Phase 2 README 생성 로드맵에 따라 순차 보충.
```
