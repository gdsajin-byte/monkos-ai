## 1. 현황 — 현재 수동 운용 구조 + 병목

### 1.1 현재 워크플로우

```
쌍아(지시서 작성) → 작가님(수동 복붙 하달) → 막내(실행) → 막내(보고) → 작가님(수동 전달) → 쌍아(검증)
```

**작가님 = 수동 허브(라우터)**. 모든 정보가 작가님을 경유한다.

### 1.2 4대 병목

| # | 병목 | 현상 | 영향 |
|---|------|------|------|
| **B1** | 지시서 전달 | 쌍아 → (작가님 복붙) → 막내 | 작가님 부담, 전달 지연 |
| **B2** | 보고서 전달 | 막내 → (작가님 복붙) → 쌍아 | 검증 지연, 컨텍스트 유실 |
| **B3** | 커밋/푸시 조율 | 쌍아 망라 vs 막내 각자 (현재 쌍아 망라) | 충돌 리스크, 순서 대기 |
| **B4** | 세션로그 통합 | 쌍아가 수동 취합 | 누락 리스크, 쌍아 병목 |

### 1.3 현재 운영 규모

- 동시 에이전트: 최대 4개 (쌍아 + 막내1~3)
- 지시서 발행: 일 3~8건
- 보고서 수신: 지시서 당 1건
- 커밋: 일 5~15건

## 2. Anthropic Agent SDK 최신 동향 요약

### 2.1 3계층 멀티에이전트 아키텍처

Anthropic은 2026년 2월 기준 **3개 계층**의 멀티에이전트 시스템을 제공한다.

| 계층 | 이름 | 상태 | 통신 | 토큰 비용 |
|------|------|------|------|----------|
| **L1** | Subagents | **프로덕션** | 보고형 (→ 부모만) | 낮음 |
| **L2** | Agent Teams | **실험적** | P2P (↔ 직접) | 높음 |
| **L3** | Hooks | **프로덕션** | 이벤트 기반 | 최소 |

보조 인프라: **MCP** (Model Context Protocol) — 외부 도구/서비스 연결 표준.

### 2.2 L1: Subagents (프로덕션)

- **구조**: 별(star) 토폴로지. 부모 에이전트가 자식을 생성, 결과만 수신
- **동시성**: 최대 7개 병렬 실행
- **격리**: 각 서브에이전트는 독립 컨텍스트 윈도우
- **설정**: `.claude/agents/` YAML로 커스텀 에이전트 정의 가능
- **메모리**: user/project/local 3 스코프 영속 메모리
- **배경 실행**: 포어그라운드(블로킹) / 백그라운드(비블로킹) 선택
- **Git 워크트리 격리**: `isolation: worktree`로 브랜치 충돌 방지

**한계**:
- 서브에이전트끼리 직접 통신 **불가능** (부모만 경유)
- 중첩 불가 (서브에이전트가 또 서브에이전트 생성 불가)
- 동일 파일 동시 편집 시 덮어쓰기 발생

### 2.3 L2: Agent Teams (실험적, 2026년 2월 출시)

**활성화**: `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` 환경변수

- **구조**: 메시(mesh) 토폴로지. 리드(lead) + 팀원(teammate) N명
- **P2P 메시징**: 팀원 간 직접 메시지 전달 (리드 경유 불필요)
- **공유 태스크 리스트**: 모든 에이전트가 태스크 상태 확인, 자율 클레임
- **태스크 의존성**: blocked → unblocked 자동 전이
- **플랜 승인 게이트**: 팀원이 읽기 전용으로 계획 → 리드 승인 → 실행
- **디스플레이**: in-process(기본) / tmux/iTerm2 분할 패널

**한계**:
- 세션 재개 시 in-process 팀원 복원 **불가능**
- 중첩 팀 **불가능** (팀원이 자체 팀 구성 불가)
- 태스크 상태 지연 (완료 마킹 누락 가능)
- VS Code 통합 터미널에서 분할 패널 **불가능**

### 2.4 L3: Hooks (프로덕션)

15개 라이프사이클 이벤트에 훅 연결 가능:

| 이벤트 | 차단 가능 | 용도 |
|--------|----------|------|
| `PreToolUse` | Yes (exit 2) | 위험한 명령 차단, 검증 |
| `PostToolUse` | No | 자동 포맷, 린트, 알림 |
| `TaskCompleted` | Yes (exit 2) | 품질 게이트 (불완전 방지) |
| `SubagentStart/Stop` | No | 리소스 설정/정리 |
| `Stop` | Yes (exit 2) | 완료 검증 |

훅 타입 3종:
1. **command** — 셸 명령 (결정적, 빠름)
2. **prompt** — 단일 LLM 판단
3. **agent** — 다중 턴 에이전트 (도구 사용 가능)

### 2.5 MCP (Model Context Protocol)

- **역할**: LLM ↔ 외부 시스템 연결 표준 (LSP의 AI 버전)
- **구조**: 클라이언트-서버 (에이전트 = 클라이언트, 외부 = 서버)
- **공유**: 여러 에이전트가 동일 MCP 서버에 접속 가능
- **한계**: 서버-서버 통신 **불가능**, 에이전트 간 데이터 공유 용도 **아님**

## 3. 대조 분석 — 우리 병목 ↔ SDK 해법

### 3.1 대조표

| 병목 | 현재 | Agent Teams 해법 | Subagent 해법 | Hooks 해법 | 가능 여부 |
|------|------|-----------------|--------------|-----------|----------|
| **B1 지시서 전달** | 작가님 수동 복붙 | 리드 → 팀원 직접 태스크 할당 | 부모 → Task tool로 프롬프트 전달 | `UserPromptSubmit` 훅으로 자동 디스패치 | **가능** (Teams) |
| **B2 보고서 전달** | 작가님 수동 복붙 | 팀원 → 리드/다른 팀원 직접 메시지 | 서브에이전트 결과 → 부모에 자동 보고 | `Stop` 훅으로 보고서 자동 저장 | **가능** (Teams) |
| **B3 커밋 조율** | 쌍아 망라 커밋 | 각 팀원 독립 워크트리 → 각자 커밋 | `isolation: worktree` 격리 | `PostToolUse` 훅으로 커밋 검증 | **가능** (worktree) |
| **B4 세션로그 통합** | 쌍아 수동 취합 | 공유 태스크 리스트에 상태 기록 | 각 서브에이전트 결과가 부모에 수렴 | `SubagentStop` 훅으로 로그 자동 수집 | **부분 가능** |

### 3.2 상세 분석

#### B1: 지시서 전달 → Agent Teams의 태스크 할당

**현재**: 쌍아가 `.md` 작성 → 작가님이 VSCode에서 복사 → 막내 세션에 붙여넣기
**Agent Teams 해법**:
- 리드(쌍아)가 태스크를 직접 생성하면 팀원(막내)이 자동으로 수신
- `~/.claude/tasks/{team-name}/` 파일에 태스크 목록 자동 저장
- 팀원이 자율 클레임 또는 리드가 명시 할당

**판정**: **해결 가능**. 단, Agent Teams는 실험적 기능이고 세션 재개 불가 이슈 있음.

#### B2: 보고서 전달 → P2P 메시징

**현재**: 막내 완료 보고 → 작가님이 읽고 쌍아에게 전달
**Agent Teams 해법**:
- 막내(팀원)가 쌍아(리드 또는 다른 팀원)에게 직접 메시지
- `idle` 알림으로 작업 완료를 리드에 자동 통보

**판정**: **해결 가능**. 그러나 현재 MONK OS에서 쌍아와 막내는 별도 Claude Code 세션이므로, Agent Teams의 "단일 리드 → 팀원" 구조로 전환해야 함.

#### B3: 커밋 조율 → 워크트리 격리

**현재**: 막내들이 같은 develop 브랜치에서 작업, 쌍아가 망라 커밋
**Subagent/Teams 해법**:
- `isolation: worktree` → 각 에이전트가 독립 Git 워크트리에서 작업
- 파일 충돌 원천 차단
- 각자 커밋 후 리드가 머지

**판정**: **해결 가능**. 이미 프로덕션 기능.

#### B4: 세션로그 통합 → 부분 자동화

**현재**: 쌍아가 각 막내의 보고서를 종합하여 세션로그 작성
**해법 조합**:
- `SubagentStop` 훅 → 서브에이전트 종료 시 결과를 파일에 자동 append
- `TaskCompleted` 훅 → 태스크 완료 시 로그 자동 기록
- 최종 통합은 여전히 쌍아(리드) 역할

**판정**: **부분 해결**. 수집은 자동화 가능하나 통합/편집은 수동.

## 4. 즉시 적용 가능한 개선 — 지시서/보고서 템플릿 표준화

| 항목 | 일관성 | 비고 |
|------|--------|------|
| YAML `type/from/to/date` | 100% | 완벽 |

| YAML `priority` | 64% | 4파일 누락 |
| 섹션 `배경` | 100% | 완벽 |

## 배경
- [상황]
- [문제]
- [목표]

### 4.4 자동 파싱 파이프라인 (구상)

```
지시서(.md) → YAML 파싱 → status/priority/to 추출
                             ↓
                      라우팅 규칙 적용
                             ↓
                      해당 에이전트에 전달
                             ↓
보고서(.md) → YAML 파싱 → result/task_id 추출
                             ↓
                      지시서 status 갱신 (pending → completed)
                             ↓
                      세션로그 자동 append
```

이 파이프라인은 **Hooks** (`PostToolUse` + `Stop`)로 구현 가능하다.

## 5. 중기 적용 가능한 개선 — Hooks/MCP 활용

### 5.1 Hooks 기반 자동 디스패치

```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [{
          "type": "command",
          "command": "python scripts/check_task_file.py"
        }]
      }
    ],
    "Stop": [
      {
        "hooks": [{
          "type": "command",
          "command": "python scripts/auto_report.py"
        }]
      }
    ]
  }
}
```

**시나리오**:
1. 쌍아가 `TASK_*.md` 파일을 Write → `PostToolUse` 훅 발동
2. 스크립트가 YAML frontmatter의 `to` 필드 파싱
3. 해당 막내의 작업 큐에 자동 등록
4. 막내 세션 시작 시 `SessionStart` 훅에서 큐 확인 → 자동 로딩

### 5.2 커스텀 서브에이전트 정의

```yaml
# .claude/agents/makne-worker.yml
---
name: makne-worker
description: "MONK OS 막내 에이전트 — 지시서 기반 코딩 실행"
model: sonnet
tools: [Read, Write, Edit, Glob, Grep, Bash]
isolation: worktree
permissionMode: acceptEdits
maxTurns: 50
memory: project
hooks:
  Stop:
    - hooks:
        - type: command
          command: "python scripts/generate_report.py"
---
지시서를 읽고 코딩 작업을 수행하는 막내 에이전트입니다.
작업 완료 후 표준 보고서 형식으로 결과를 보고합니다.
```

### 5.3 MCP 서버 활용 (외부 도구 연결)

| MCP 서버 | 용도 | 연결 에이전트 |
|----------|------|-------------|
| GitHub MCP | PR 생성, 이슈 관리 | 쌍아, 막내 전원 |
| GCS MCP | 이미지 업로드/조회 | 막내(이미지 담당) |
| Slack/Telegram MCP | 알림 전송 | 리드(쌍아) |
| Firestore MCP | 크레딧 조회 | 막내(포탈 담당) |

## 6. 장기 비전 — P2P 에이전트 오케스트레이션

### 6.1 Agent Teams 기반 MONK OS 재설계

```
[쌍아 = Lead]
    ├── [막내1 = Teammate] ← worktree 격리
    ├── [막내2 = Teammate] ← worktree 격리
    ├── [막내3 = Teammate] ← worktree 격리
    └── [소넷이 = Teammate] ← 읽기 전용 (모니터링)

통신: P2P 메시징 (작가님 경유 불필요)
태스크: 공유 리스트에서 자율 클레임
승인: 플랜 승인 게이트 (쌍아 → 막내)
품질: TaskCompleted 훅 (완료 전 검증)
```

### 6.2 작가님 역할 변화

| 현재 | Agent Teams 전환 후 |
|------|---------------------|
| 수동 라우터 (복붙) | 전략적 의사결정자 |
| 지시서 전달 | 쌍아(리드)에게 방향 제시 |
| 보고서 중계 | 최종 승인/리뷰만 |
| 커밋 조율 | 머지 승인만 |

### 6.3 전환 로드맵

```
Phase 0 (즉시): 템플릿 표준화 → 파싱 가능한 지시서/보고서
Phase 1 (1~2주): Hooks 기반 자동 디스패치 + 보고서 자동 수집
Phase 2 (1개월): 커스텀 서브에이전트 정의 + worktree 격리
Phase 3 (2~3개월): Agent Teams 실험 (안정화 대기 후)
Phase 4 (3~6개월): 완전 자동화 오케스트레이션
```

### 6.4 전제 조건

1. Agent Teams 세션 재개 문제 해결 (현재 불가)
2. VS Code 통합 터미널 분할 패널 지원 (현재 불가)
3. 토큰 비용 관리 (팀원 수 × 풀 컨텍스트)

---

## 7. 결론 + 권고사항

### 7.1 핵심 발견

1. **Anthropic은 이미 우리 문제에 대한 해법을 만들었다.** Agent Teams의 P2P 메시징 + 공유 태스크 리스트는 MONK OS의 B1~B2 병목을 정확히 해결한다.

2. **그러나 Agent Teams는 아직 실험적이다.** 세션 재개 불가, 태스크 상태 지연, VS Code 분할 패널 미지원 등 프로덕션 운용에는 리스크가 있다.

3. **Hooks + 템플릿 표준화는 지금 바로 할 수 있다.** 이것만으로도 수동 부담의 30~40%를 줄일 수 있다.

4. **MCP는 에이전트 간 통신 수단이 아니다.** 외부 도구 연결용. 에이전트 간 데이터 공유는 파일 또는 태스크 리스트로 해결해야 한다.

### 7.2 권고사항

| 우선순위 | 항목 | 기대 효과 | 리스크 |
|---------|------|----------|--------|
| **P0 (즉시)** | 지시서/보고서 YAML 표준화 | 자동 파싱 기반 마련 | 없음 |
| **P0 (즉시)** | `task_rules.md` 성문화 | 새 에이전트 온보딩 가속 | 없음 |
| **P1 (1~2주)** | Hooks 기반 지시서 감지 + 보고서 자동 수집 | 수동 복붙 30% 감소 | 스크립트 유지보수 |
| **P1 (1~2주)** | 커스텀 서브에이전트 YAML 정의 | 역할 표준화 + 워크트리 격리 | 설정 복잡도 |
| **P2 (1개월)** | Agent Teams 실험 (비프로덕션) | P2P 통신 검증 | 실험적 기능, 토큰 비용 |
| **P3 (3개월)** | 완전 자동화 오케스트레이션 | 작가님 부담 80% 감소 | Teams 안정화 의존 |

### 7.3 "안 되는 것" 명확 정리

| 항목 | 상태 | 근거 |
|------|------|------|

| 서브에이전트 중첩 (서브가 서브 생성) | **불가능** | 1레벨만. 설계 의도. |
