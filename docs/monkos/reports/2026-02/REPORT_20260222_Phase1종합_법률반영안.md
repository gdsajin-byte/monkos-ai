#### [신설 4조] YAML Frontmatter 필수 규격

`docs/monkos/` 및 `docs/specs/`의 모든 .md 파일에 YAML frontmatter를 필수 기재한다.

**공통 필수 필드** (모든 타입):

```yaml
---
type: task | report | spec | incident | design | session
id: "{파일명과 동일}"
date: "YYYY-MM-DD HH:MM KST"
status: pending | in_progress | completed | archived | blocked
---
```

**타입별 추가 필수 필드**:

| 타입 | 추가 필수 필드 | 규칙 |
|------|---------------|------|
| task | `from`, `to`, `priority` | from: 발행자명 통일 (예: `쌍아`). priority: `P0`/`P1`/`P2`/`P3` |
| report | `task_id`, `from`, `to`, `result` | result: `success`/`partial`/`fail` |
| spec | `service`, `from` | service: `portal`/`idphoto-kr`/`infra`/`common` |
| incident | `service`, `severity` | severity: `critical`/`major`/`minor` |
| session | (공통만) | agents 필드는 선택 |

**표기 통일 규칙**:
- `from` 필드: 에이전트명만 (`쌍아`, `막내3` 등). `M1/쌍아`, `쌍아 (전략실)` 금지.
- `priority` 필드: `P0`~`P3`만. `HIGH`, `CRITICAL`, `중` 금지.
- `id` 필드: 파일명과 동일해야 한다. 불일치 시 데몬이 경고.

> **근거**: 막내3 §2(YAML 규격) + 막내3 §2.3(불일치 현황 분석)
> **위반 시**: 데몬 자동 분류/상태 갱신 불가, 에이전트 간 문서 추적 단절

### 4.2 제3장: 세션 로그 (현행 3조 → 4조)

#### [신설 4조] 보고서 연동 규칙

보고서(`REPORT_*.md`) 생성 시, 해당 날짜의 세션로그에 요약 1줄을 자동 append한다.

**형식**:
```markdown
### [HH:MM] 보고서 수신
- {agent}: {task_id} — {result} ({핵심요약 1줄})
```

**규칙**:
- 자동 append 주체: 데몬(소넷이) 또는 보고서 작성 에이전트
- 세션로그가 해당 날짜에 존재하지 않으면 append 건너뜀 (세션로그 신규 생성은 금지)
- YAML `task_id` 필드가 없는 보고서는 append 불가 → `task_id` 기재 강제 효과

> **근거**: 막내3 §6.2 + 헌법 제2조(보고 의무)
> **위반 시**: 세션로그에 보고 이력 누락 → 시계열 추적 단절
> **상위 헌법**: 제1조(시계열 정합성), 제2조(보고 의무)

### 4.3 제7장: 막내 행동 강령 (현행 5조 → 7조)

#### [신설 6조] 보고서 작성 규격

막내는 작업 완료 시 보고서를 아래 규격으로 작성한다.

**필수 요소**:

| 요소 | 내용 | 누락 시 |
|------|------|---------|
| YAML frontmatter | `task_id`, `from`, `to`, `date`, `result` | 데몬 연동 불가 |
| 결과 테이블 | 태스크별 상태 (✅/❌/⏳) | 쌍아 검증 불가 |
| 완료 조건 체크 | 지시서 완료 조건 대비 체크리스트 | 누락 확인 불가 |
| 변경 파일 테이블 | 파일명 + 변경 라인 + 변경 유형 (코딩 작업만) | diff 검증 불가 |
| 핵심요약 | 보고서 말미 1~3줄 요약 | 쌍아/작가님 빠른 파악 불가 |

**핵심요약 형식**:
```markdown
## 핵심요약
> TN개 완료, 파일 M개 수정. {주요 변경 1줄}. {대기 사항 or 이슈}.
```

**보고서 파일명**: `REPORT_YYYYMMDD_주제.md` (제4장 3조 준용)

> **근거**: 막내3 §4(보고서 템플릿) + 막내3 §6.3(강령화 제안)
> **위반 시**: 쌍아 검증 체크리스트 자동 생성 불가, 보고 품질 편차
> **상위 헌법**: 제2조(완료 보고 의무), 제5조(에이전트 역할 체계)

#### [신설 7조] 지시서 수신 프로토콜

막내는 지시서 수신 시 아래 순서를 따른다:

1. **MEMORY.md 확인** (기존 5조와 연계)
2. **지시서 YAML 검증**: `from`, `to`, `priority`, `status` 존재 확인
3. **역할 확인**: 지시서 `to` 필드가 자신의 역할(`막내N`)과 일치하는지 확인
4. **의존성 확인**: `depends_on` 필드의 선행 지시서가 모두 `completed` 상태인지 확인
5. **작업 착수**: 지시서 범위 내에서만 실행
6. **보고서 작성**: 6조 규격 준수
7. **완료 보고**: 헌법 제2조 형식 (`✅❌💡⏳📁🔀`)

> **근거**: 막내3 §3(지시서 템플릿) + 기존 1조(작업 흐름) 구체화
> **위반 시**: 의존성 미확인 → 작업 충돌, 역할 오인 → 보고 체계 와해
> **상위 헌법**: 제5조(에이전트 역할 체계)

#### [신설 5조] 데몬 역할 정의

소넷이, 철창이는 "데몬"으로서 아래 자동화 업무를 수행한다.

**데몬 권한**:
- 허용: 파일 이동(분류), YAML 필드 갱신(status), 세션로그 append, 자동 커밋(`[daemon]` 접두)
- 금지: 파일 삭제, 파일 내용 수정(YAML status 외), 코드 수정, 배포

**에러 처리**:
- YAML 파싱 실패: `_unsorted/` 이동 + 경고 로그

- 7일 미분류: 세션로그에 경고 기록

> **근거**: 막내3 §5(데몬 시나리오 3건) + 기존 1조(에이전트 정의 — 소넷이/철창이 이미 존재하나 자동화 역할 미규정)
> **위반 시**: 데몬 권한 초과 → 의도하지 않은 파일/코드 변경
> **상위 헌법**: 제5조(에이전트 역할 체계), 제8조(파괴적 명령 금지)
