```
세션 종료 → 완료 보고 (헌법 2조) → MEMORY 갱신 필요 여부 체크 (트리거표) → 갱신 시 세션 로그에 기록
```

**핵심 접점**: 세션 로그의 "완료 사항"에 MEMORY 갱신 여부를 포함하면, 소넷이 데몬이 자동으로 갱신 이력을 추적할 수 있음.

### 6.3 어젠다 #2(데몬 자동화)로 MEMORY 갱신 자동화 가능 영역

| 영역 | 자동화 가능성 | 방법 |
|------|------------|------|
| **prod rev 갱신** | ✅ 높음 | 배포 스크립트 후속 작업으로 MEMORY prod rev 자동 갱신 |
| **법률 경로 갱신** | ⚠️ 중간 | governance/ 파일 이동 감지 → MEMORY 참조 경로 자동 보정 |
| **기술 명세 추가** | ❌ 낮음 | 자연어 판단 필요 — 에이전트 재량 영역 |
| **금언/철학** | ❌ 없음 | 완전 수동 — 작가님 발언 맥락 판단 필수 |

## 7. 종합 권고안

### 7.1 갱신 체계 제안 (D+C 혼합 모델)

```
트리거 발생 → 주체 자동 지정 → MEMORY 해당 섹션 갱신 → 세션 로그에 [MEMORY] 기록
```

- **P0 트리거 (즉시)**: 법률/헌법 개정, 프로젝트 구조 변경 → 실행 에이전트 의무
- **P1 트리거 (같은 세션)**: 인프라/배포 변경 → 실행 막내 의무
- **P2 트리거 (다음 세션)**: 기술 명세, 금언 → 해당 에이전트/쌍아 권장
- **정기 검증**: 주 1회 쌍아가 MEMORY 정합성 대조

| 항목 | 현행 | 제안 |
