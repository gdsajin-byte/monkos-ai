## 1. 배경

photolab MPA 전환 완료 후, 준비실(index.html) UI 리뷰에서 기존 칩 방식(용도2+성별2+연령3)의 한계가 확인됨.
증명사진은 용도에 따라 규정·의상·헤어·배경·표정이 전혀 다른 서비스 수준의 차이가 있으며,
이를 정밀하게 세팅해야 **1회 정밀 생성** 원칙에 부합함.

### 핵심 원칙
- **"준비한 만큼 결과가 좋아진다"** — 사진관 20년 철학
- 클라이언트에게 I2I 재보정 미제공 → 촬영 전 완벽 세팅 필수
- 생성 후 수정 없음 = 준비실의 정밀도가 최종 품질 결정

## 4. UI 구조 — 키오스크 퍼널 + 사이드 챗봇

### 4-1. 키오스크 퍼널

- **스크롤 ✕, 페이지 전환 ○** (실제 키오스크 UX)
- 한 화면에 하나의 선택 → 슬라이드로 다음 스텝
- 뒤로가기로 수정 가능
- 카드 아래 기본 설명 텍스트

```
STEP 1: 용도 선택 (카드 4~5개)
STEP 2: 연령 선택 (용도별 필터링된 선택지)
STEP 3: 성별 선택
STEP 4: 의상 타입 (디폴트 세팅됨)
STEP 5: 의상 컬러 (조건부)
STEP 6: 넥타이 (조건부: 남성+정장/셔츠)
STEP 7: 헤어 (디폴트 "그대로")
STEP 8: 배경색 (조건부)
STEP 9: 표정 (조건부)
FINAL: 카드 확인 → [촬영 시작하기]
```

- 조건부 스텝은 해당 안 되면 자동 스킵
- 디폴트가 세팅된 스텝은 [다음] 누르면 그대로 진행

### 4-2. 사이드 챗봇 (MONKOS 챗봇)

- 💬 버튼으로 우측에서 슬라이드 인/아웃 (70% 높이)
- **기존 MONKOS.AI 챗봇에 "촬영준비 모드" 시스템 프롬프트 추가**
- 새 챗봇이 아님 — 기존 CS 챗봇의 모드 추가
- 현재 키오스크 스텝에 맞는 맥락으로 응답
- 법률/초상권/개인정보 등 기존 지식 그대로 활용
- 대화 로그 → 기존 자동 코퍼스화 로직 활용

### 4-3. 두 경로 공존

- 빠른 사용자: 키오스크만으로 진행 (디폴트 활용)
- 궁금한 사용자: 챗봇 열어서 Q&A
- 결과는 동일한 카드 완성 → 촬영실 이동

## 5. 고객 시나리오 코퍼스 (역할극 기반)

### 5-1. 성인 여성 — 여권

**퍼널:** 용도(여권) → 규격 설명 → 의상 체크(흰색 NG) → 의상+컬러 선택 → 헤어 규정 → 촬영실

**핵심 멘트:**
- "여권 외에도 운전면허, 주민등록증도 같은 규격"
- "주민등록증은 여권보다 규정 적용이 덜 타이트"
- "흰색 의상은 실무적으로 거의 금지. AI가 컬러 변환 처리"
- "눈썹·이마·얼굴라인을 헤어가 가리면 안 됨. AI가 추론하면 발급 문제 소지"
- "한국 기준 귀 노출 명시적 규정 삭제됨. 얼굴라인만 주의"

### 5-2. 엄마 + 아기(18개월) — 여권

**퍼널:** 용도(여권) → 공감 → 모바일 장점(자유 촬영) → 배경/조명 → AI 코칭 안내 → 보정 수준 → 카메라 방향 → 촬영실

**핵심 멘트:**
- "실무적으로 가장 어렵습니다"
- "눕혀서든 품에 앉혀서든 셀카로든 괜찮습니다" (모바일 서비스의 킬링 포인트)
- "동그라미 안에 아가 얼굴, 시선/방향 유도만 잘 해주세요"
- "배경은 흰벽이 최선, 처리 가능하지만 밝은 곳+그림자 주의"
- "AI가 실시간 도우미, 음성 온/오프 가능"
- "준비한 만큼 결과가 좋아진다. 과하면 과보정"
- "아가는 보정 최소. 밝기·피부톤 정도만"
- "딥페이크 원천차단 원칙이나 아가는 양방향 카메라 허용"

### 5-3. 대학생 남성 — 이력서

**퍼널:** 용도(이력서) → 의상 합성 안내 → 의상+컬러+넥타이 → 헤어 → 배경색 → 표정 가이드 → 촬영실

**핵심 멘트:**
- "의상은 자연스럽게 합성. 합성 티 안 남"
- "넥타이 유무 선택 가능 (노타이도 선택지)"
- "헤어는 준비하신 스타일에서 정돈이 원칙. 많이 바뀌면 어색"
- "이력서 배경: 흰색, 블루, 그레이, 베이지, 핑크"
- "잔잔한 미소 + 자신감 = 신뢰감 전달"

### 5-4. 중학생 여학생 — 학생증

**퍼널:** 용도(학생증) → 학교 지침 확인 → 교복 착용 권장 → 넥타이/리본 → 헤어 → 배경 → 촬영실

**핵심 멘트:**
- "학교 지침서에 조건이 제시되어 있지 않나요?" (규정 확인 유도)
- "대다수 학생증은 교복 착용"
- "AI가 모든 학교 교복 패턴을 보유하지 않음. 교복 입으시고 '그대로' 선택이 최선"
- "리본/넥타이 상관없음, 입은 그대로"
- "학생증은 헤어 특별 규정 없음, 깔끔하게 정돈"

### 5-5. 20대 여성 — 컬러증명(SNS/소장)

**퍼널:** "프로필 사진" 요청 → 증명 vs 프로필 정의 → 컬러증명 안내 → 자유도=AI관여 축소 → 의상/헤어 → 배경 → 촬영실

**핵심 멘트:**
- "증명=규정+규격, 프로필=규정 없는 스튜디오 인물사진. 범위가 너무 넓은 영역"
- "프로필은 모기업 몽크사진관이 전문"
- "증명 포맷 안에서 자유로운 표정/포즈면 가능"
- "자유도가 높으면 AI 관여 포인트가 줄어듦. 촬영 모습을 자연스럽게 보정하여 출력"
- 배경: "흰색, 그레이, 블루, 핑크, 베이지, 옐로우"

## 7. 기술 구현 요약

### 챗봇
- 기존 MONKOS.AI Gemini 2.0 챗봇에 "촬영준비 모드" 시스템 프롬프트 섹션 추가

- 대화 로그 → 기존 자동 코퍼스화 로직 그대로

### 키오스크 UI
- 준비실(index.html) 리디자인
- 스텝별 div + CSS slide transition
- 캐스케이드 필터링: store 기반 반응형
- 사이드 챗봇: translateX 슬라이드 인/아웃 패널

### 촬영 모드 분기
- 7세 이하 → `facingMode: 'environment'` (후면 카메라)
- 코칭 프롬프트: 보호자 모드 (3인칭) / 셀카 모드 (2인칭)

### 프롬프트 조립
- 카드 9값 → 각 필드별 프롬프트 fragment 테이블 lookup → 조립
- `DEFAULTS[locale][purpose][gender]` 디폴트 테이블
- `RULES[locale][purpose]` 규칙 테이블 (필터링, 금지 항목)
