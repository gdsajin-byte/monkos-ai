### 추가 조사: 흩어짐 원인 분석

각 "제 위치가 아닌" 파일에 대해 **왜 거기에 있는지** 원인을 1줄로 기록:

| 원인 유형 | 설명 |
|-----------|------|
| **규칙 부재** | 해당 분류의 폴더가 없어서 임의 배치 |
| **레거시** | 과거 구조에서 생성, 이후 방치 |
| **긴급 작업** | 급한 작업 중 루트에 생성 후 미정리 |
| **중복 생성** | 같은 내용이 다른 위치에 별도 생성 |
| **에이전트 혼선** | 막내/쌍아가 위치 몰라서 잘못 배치 |

## Phase 3: 전체 docs/ 재설계안

6분류 기반으로 **docs/ 폴더 전체 재설계안**을 제시.

```
docs/
├── philosophy/         ← 철학 (비전, 페르소나, 브랜드)
├── knowledge/          ← 지식 (인프라, API, 모델 스택)
├── law/                ← 법 (코딩표준, 디자인시스템, 배포가이드)
├── tech/               ← 테크 (기술별 폴더, 위 Phase 2)
├── history/            ← 히스토리 (세션 로그, 인시던트, 변천사)
│   ├── sessions/       ← 기존 corpus/sessions/ 승계
│   ├── incidents/      ← 장애 기록
│   └── gemini/         ← 용아 대화
├── business/           ← 비즈니스 (마케팅, R&D, 전략)
├── ops/                ← 운용 (지시서, 작업큐, 자동화)
│   ├── tasks/          ← 지시서 아카이브
│   └── automation/     ← 자동화 규칙
└── _legacy/            ← 정리 대기 (이관 전 임시)
```

**위 구조는 제안이다.** 조사 결과에 따라 조정하라. 핵심은:
- 현재 `infrastructure/`에 92개가 뒤섞인 상태를 해소
- 현재 `corpus/`, `monkos/` 등 경계가 모호한 폴더를 명확히
- 모든 문서가 6분류 중 하나에 귀속

## Phase 4: 흩어짐 방지 규정 초안

조사에서 발견된 **흩어짐 원인**을 바탕으로, 헌법/법률에 추가할 **문서 위치 규정 초안**을 작성.

```markdown
## 문서 위치 규정 (법률 제N장 — 초안)

### 1조: 문서 생성 시 분류 의무
- 모든 .md 파일 생성 시 6분류(철학/지식/법/테크/히스토리/비즈니스) 중 하나에 귀속
- 분류 불명 시 `_legacy/`에 임시 배치 후 다음 세션에서 정리

### 2조: 루트 방치 금지
- 프로젝트 루트에 임시 .md 파일 방치 금지 (기존 규칙 승계)
- 루트 허용: CLAUDE.md, README.md, package.json 등 프로젝트 설정 파일만

### 3조: 지시서 아카이브
- 완료된 지시서는 docs/ops/tasks/에 이관
- 미완 지시서는 docs/monkos/ 잔류 (현행 유지)

### 4조: 세션 로그 불변
- docs/history/sessions/ 원본은 수정/이동 금지
- 기술 내용 필요 시 추출하여 해당 tech/ 폴더에 기록

### 5조: 중복 문서 금지
- 같은 내용의 문서가 2개 이상 존재하면 1개로 통합
- 통합 시 근거가 더 풍부한 쪽을 유지
```

위는 예시다. 실제 조사 결과에서 발견된 원인에 맞게 조정하라.
