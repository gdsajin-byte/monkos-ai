## 2. 제출 범위

**ch4 2조(금지사항)와 YAML 규격 신설, 그리고 monkos-ops/ 재편의 ch4 반영에 대한 개정안을 작성하라.**

### 2-A. ch4 2조: 금지사항 현실 갱신

현행 2조의 경로 참조가 변경된 현실과 불일치:

| 현행 | 현실 | 갱신 필요 |
|------|------|----------|
| 2조 4항: 세션로그 정본 `monkos-ops/06_로그/sessions/` | ops/sessions/로도 이동됨 | 경로 갱신 |
| 2조 5항: `tasks/YYYY-MM/` 하위 배치 | 막내2가 122건 이미 이동 완료 | 이행 유예 필요 여부 재판단 |

추가 검토:
- 번호 폴더(01~06)와 부서 폴더(ops/tech/contents/marketing)가 공존하는 과도기에 금지사항이 어느 쪽에 적용되는가?
- "문서 정본 이중화 금지" (2조 3항) — 번호 폴더와 부서 폴더에 동일 파일이 잔존하지 않는가?

### 2-B. YAML Frontmatter 규격 (너의 청구 1 발전)

너의 기존 청구(YAML 필수 규격)를 ch4 개정안으로 구체화하라:

- 공통 필수 필드 (type, id, date, status) — 유지/수정?
- 타입별 추가 필드 — 어젯밤 실무에서 발견한 보완점?
- **헌법 제13조와의 정합**: 제13조는 "법률 제4장이 정한 파일 네이밍 규칙과 YAML frontmatter를 준수한다"고 명시. ch4에 YAML 규격이 **없으면** 제13조가 참조할 상세가 없는 상태.
- 적용 범위: governance/ 문서에도 적용? monkos-ops/ 문서에도 적용? 범위 결정.

### 2-C. monkos-ops/ 부서 재편의 ch4 반영

어젯밤 4부서 골격을 생성했으나, ch4에는 아직 번호 체계만 존재:

- ch4 1조의 monkos-ops/ 트리: 번호 → 부서명으로 갱신? 병기?
- ch4 4조의 정본 테이블: `monkos-ops/06_로그/sessions/` → `monkos-ops/ops/sessions/`?
- 번호 폴더 정리 시점: 즉시 삭제? 단계적? 법률 개정 발효와 동시?
