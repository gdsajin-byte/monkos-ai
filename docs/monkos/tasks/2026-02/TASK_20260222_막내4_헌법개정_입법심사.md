## 개정안 전문

### 개정 1: governance/ 신설 (프로젝트 구조 변경)

```
monk_project/
├── CLAUDE.md                        ← 헌법 (커널, 자동 인식)
├── governance/                      ← 거버넌스 (신설)
│   ├── laws/                          법률 ch1~ch8
│   ├── constitution/                  개정 절차 + 청구서 보관
│   │   └── petitions/
│   ├── history/                       역사 (세션로그 정본, 결정기록)
│   │   └── sessions/
│   └── philosophy/                    철학 (비전, 가치관, 어록)
├── docs/                            ← 원천 아카이브 (보존, 보물창고)
└── monkos-ops/                      ← 운영 (4부서 재편)
    ├── ops/                           운영 관리
    ├── tech/                          기술
    ├── contents/                      콘텐츠
    └── marketing/                     마케팅
```

**4계층 위계:**
```
헌법 (CLAUDE.md) — 자동 인식, 개요·강제
    │
법률 + 역사 + 철학 (governance/) — 절차·상세·근거
    │
부서 세칙 (monkos-ops/ 각 README) — 운영 규정
    │
데이터·에셋 (부서 하위) — 실행 산출물
```

### 개정 2: CLAUDE.md에 개정 청구권 개요 신설

현재 amendment.md에만 있는 개정 청구권의 **개요**를 헌법 본문에 삽입:

```
### 제12조: 개정 청구권 (신설)
- 모든 구성원(작가님·에이전트·팀원)은 법률·헌법의 개정을 청구할 수 있다
- 법률 개정: 쌍아+작가님 합의
- 헌법 개정: 삼권 심사 + 전원 만장일치
- 절차 상세: governance/constitution/amendment.md
```

### 개정 3: CLAUDE.md에 문서 규격 개요 신설

서류양식·파일링 규칙의 **개요·강제**를 헌법에, **디테일**을 법률에:

```
### 제13조: 문서 규격 준수 (신설)
- 모든 공식 문서는 정해진 파일 네이밍 규칙과 YAML frontmatter를 준수한다
- 네이밍 패턴, YAML 필수 필드, 배치 경로의 상세: 법률 제4장
```

### 개정 4: CLAUDE.md 법률 인덱스 경로 변경

```
현행: docs/infrastructure/laws/ch1_agent_system.md
변경: governance/laws/ch1_agent_system.md
(전 8장 동일 패턴)
```

### 작가님 확정 원칙

1. "경로 변경은 개헌이지만 최적화 방향"
2. "현행 docs/는 보물창고 — 보존. 제거 대상 아님"
3. "세션로그 → governance/history/. 기존은 백업"
4. "개정 청구권: 헌법에 개요, 법률에 절차·상세"
5. "서류양식·파일링: 헌법에 개요·강제, 법률에 디테일"
6. "법률은 OS 그 자체. 생성·추출·아카이브 대상이 아님"
