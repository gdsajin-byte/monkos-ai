# 막내1: Anthropic Agent SDK 정밀 조사 — 멀티에이전트 지시서/보고서 자동화 가능성

## 배경

현재 MONK OS의 멀티에이전트 운용 구조:
```
쌍아(지시서 작성) → 작가님(수동 복붙 하달) → 막내(실행) → 막내(보고) → 작가님(수동 전달) → 쌍아(검증)
```
작가님이 수동 허브 역할을 하고 있음. 지시서/보고서가 에이전트 간 직접 전달(P2P)되면 수동 부담이 해소됨.

Anthropic이 최근 발표한 Agent SDK / Claude Code 관련 업데이트 중 이 문제와 직접 관련된 내용이 있음. 작가님이 이미 메일로 수신하여 1회 검토하셨으나, 현재 운용 경험 기반의 정밀 분석이 필요.

## TASK

### T1: Anthropic Agent SDK 최신 동향 조사

- Anthropic 공식 블로그/문서에서 Agent SDK, multi-agent orchestration 관련 최신 발표 수집
- 조사 대상 키워드:
  - `Agent SDK` / `agent-to-agent` / `multi-agent`
  - `Task tool` / `subagent` / `orchestration`
  - `Claude Code hooks` / `custom slash commands`
  - `MCP (Model Context Protocol)` 서버 간 통신

### T2: 현재 MONK OS 구조와 대조 분석
- 현재 우리 구조의 병목 정리:
  1. 지시서 전달: 쌍아 → (작가님 수동) → 막내
  2. 보고서 전달: 막내 → (작가님 수동) → 쌍아
  3. 커밋/푸시: 쌍아가 망라 vs 막내 각자 (현재 쌍아 망라 방식 채택)
  4. 세션로그: 쌍아가 통합 작성 (개별 막내 로그는 완료보고서로 대체)

- 각 병목에 대해 Agent SDK가 제공하는 해법이 있는지 대조:
  - Task tool의 subagent 간 메시지 전달 가능 여부
  - 파일 기반 지시서/보고서를 자동 라우팅하는 방법
  - hooks를 활용한 자동 dispatch 가능성
  - MCP 서버를 허브로 쓰는 구조의 가능성
