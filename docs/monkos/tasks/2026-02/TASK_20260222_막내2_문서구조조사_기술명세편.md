# 막내2: 문서 전수조사 — 기술명세 로직 분석 + 기능별 카탈로그 설계

## 배경
- 현재 기술명세가 SPEC_*.md 몇 개로 흩어져 있고 기능별 체계가 없음
- 증명사진 앱 하나만 해도 크레딧/코칭/생성/QC/퍼널/결제 등 다수 기능
- "이 기능의 상세 스펙은 어디에?" 에 즉답 가능한 구조가 필요
- 막내1 = 파일 인벤토리, **막내2 = 기술명세 로직**, 막내3 = 템플릿/자동화 (병렬)

## TASK

### T1: 현재 기술명세 전수 파악
- docs/ 내 SPEC_*.md 파일 전체 읽기
- 각 파일이 다루는 기능/범위 요약 (1줄)
- **빠진 기술명세** 식별: 코드에는 있지만 문서화 안 된 기능

### T2: 서비스별 기능 카탈로그 작성
- 소스 코드 기반으로 현재 존재하는 모든 기능을 서비스별로 분류:

```
monkos.ai (portal)
├── 인증 (카카오, LINE, Google)
├── 크레딧 (조회, 차감, 환불, 충전)
├── 결제 (토스, 레몬스퀴지)
├── 공유 보너스
└── ...

idphoto-kr
├── 코칭 엔진 (Gemini Live → REST)
├── 프리체크
├── 이미지 생성 (Imagen)
├── QC
├── 퍼널 (prep → camera → result → thankyou)
├── 크레딧 연동
└── ...
```

- 각 기능에 대해: 현재 문서 있음/없음 표시

### T3: 기술명세 폴더 구조 제안
- 서비스 > 기능 2레벨 구조 설계
- 각 기능별 명세 파일명 규칙 제안
- 기존 SPEC 파일의 재배치 매핑 (현재 경로 → 제안 경로)

### T4: 기술명세 간 참조 관계
- 기능 간 의존 관계 맵 (예: 생성 → 크레딧 차감 → 포탈 API)
- 이 의존 관계가 폴더 구조에 어떻게 반영되어야 하는지

### T5: 보고서 작성
- 파일: `docs/monkos/REPORT_20260222_기술명세카탈로그.md`
- 구조:
  1. 현재 기술명세 현황 (있는 것 / 없는 것)
  2. 서비스별 기능 카탈로그 (전체 기능 목록)
  3. 폴더 구조 제안 (서비스 > 기능)
  4. 파일명 규칙 제안
  5. 기존 파일 재배치 매핑
  6. 기능 간 의존 관계
