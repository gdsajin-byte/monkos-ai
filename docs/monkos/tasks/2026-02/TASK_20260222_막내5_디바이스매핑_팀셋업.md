# 막내5: 디바이스 관계 매핑 + 팀원 셋업 체계 설계

## 배경
- MONK OS는 다중 디바이스에서 운용: iMac(자택), M1 MacBook(모바일), 팀원 디바이스
- 각 디바이스에 에이전트(쌍아/철창이/소넷 데몬)가 상주하며 역할 분담
- Tailscale 메시 VPN으로 P2P 연결, 텔레그램으로 지시서/보고서 전달
- 한송이, 꾸 등 팀원에게 헌법/법률을 심어주고 데몬을 깔아줘야 하는 미래 시나리오 존재
- 이 체계를 문서화하여 "새 디바이스 합류 = 체계 즉시 이식" 가능하게 만들어야 함

## TASK

### T1: 현재 디바이스 인벤토리
- 프로젝트에서 확인 가능한 디바이스 정보 수집:
  - 호스트명, OS, 역할, 상주 에이전트, Tailscale 상태
  - `.claude/` 설정, MEMORY.md 경로 등으로 추론 가능한 것들
- 현재 확인 가능한 디바이스 목록 작성

### T2: 디바이스 간 관계도 설계
```
[작가님]
    ├── iMac (자택 메인)
    │   ├── VSCode + Claude Code (쌍아)
    │   ├── 소넷 SSH 데몬
    │   ├── Tailscale node
    │   └── 역할: 설계/지시/관제
    │
    ├── M1 MacBook (모바일)
    │   ├── VSCode + Claude Code (쌍아/막내)
    │   ├── Tailscale node
    │   └── 역할: 실행/코딩/배포
    │
    └── [미래] 팀원 디바이스
        ├── 한송이 PC
        ├── 꾸 PC
        └── ...
```
- 각 디바이스 간 통신 경로 (Tailscale P2P, 텔레그램, Git)
- 데이터 동기화 방식 (Git push/pull, GCS, 텔레그램 파일 전송)

### T3: 에이전트 배치 맵
- 어떤 디바이스에 어떤 에이전트가 상주하는지
- 에이전트 간 지시/보고 경로:
  ```
  쌍아(M1) → 작가님 승인 → 막내(M1/iMac) → 완료보고 → 작가님
  쌍아(M1) → 텔레그램 → 팀원 디바이스 철창이 → 실행 → 보고
  소넷 데몬(iMac) → 자동화 태스크 → 텔레그램 알림
  ```
- 현재 운용 중인 자동화: 텔레그램 봇, 메일링, SSH 데몬

### T4: 팀원 디바이스 온보딩 시나리오
- **시나리오 1: 한송이 PC에 MONK OS 심기**
  1. Tailscale 설치 + 네트워크 합류
  2. Git clone (또는 텔레그램으로 핵심 파일 전송)
  3. CLAUDE.md (헌법) 배치
  4. 법률 파일 배치 (laws/ 전체)
  5. MEMORY.md 초기화 (팀원용 최소 버전)
  6. 에이전트 설치 (Claude Code 또는 철창이)
  7. 동작 확인: 헌법 준수 테스트, 지시서 수신 테스트

- **시나리오 2: 텔레그램 기반 경량 셋업**
  1. 텔레그램 팀챗 합류
  2. CLAUDE.md + 핵심 법률 .md 파일 전송
  3. 팀원 디바이스의 Claude Code에 붙여넣기
  4. 데몬 없이 수동 운용 (지시서 수신 → 실행 → 보고)

- **시나리오 3: 완전 자동 온보딩**
  1. 스크립트 1개 실행으로 전체 셋업
  2. Tailscale + Git + Claude Code + 헌법/법률 자동 배치
  3. 초기 MEMORY.md 자동 생성
  4. 셋업 완료 보고 자동 발송

### T5: 헌법/법률 이식 패키지 설계
- 새 디바이스에 심어줘야 하는 최소 파일 세트:
  - CLAUDE.md (헌법 전문)
  - laws/ (8장 전체)
  - MEMORY.md (팀원용 초기 버전 — 프로젝트 지식 최소 세트)
  - .claude/ 설정 (프로젝트 경로 매핑)
- "이식 패키지" 구성 규격 + 버전 관리 방법

### T6: 보고서 작성
- 파일: `docs/monkos/REPORT_20260222_디바이스매핑_팀셋업.md`
- 구조:

  2. 디바이스 간 관계도 (통신 경로 포함)
  3. 에이전트 배치 맵
  4. 팀원 온보딩 시나리오 3건
  5. 헌법/법률 이식 패키지 규격
  6. 보안 고려사항 (API 키 격리, 권한 범위)
