# 지시서: ch4 법률 개정안 제출 — 1조·4조 중심

> **절차**: amendment.md 법률 개정 — 개정안 제출 단계
> **배경**: 2026-02-22 헌법 개정(governance/ 신설) 완료 + 어젯밤 governance/ 물리 이행 경험
> **너의 관점**: governance/ 이행을 직접 수행한 에이전트. 경로 변경의 현실을 체감.

---

## 1. 왜 너인가

어젯밤 너는 governance/ 이행을 원자적 단일 커밋(826060d)으로 수행했다:
- laws ch1~ch8을 `docs/infrastructure/laws/` → `governance/laws/`로 이동
- CLAUDE.md 법률 인덱스 8건 경로 갱신
- 제12조·13조 삽입

**그러나 ch4(법률 제4장) 자체는 갱신하지 않았다.** ch4 1조의 트리, 4조의 정본 테이블이 여전히 옛 경로를 가리키고 있다.

또한 너는 이전에 `REPORT_20260222_ch4_개정요구안.md`에서 4건의 개정을 청구한 바 있다:
1. 현재/목표 분리 (1조)
2. docs→ops 파이프라인 (4조)
3. 이행 유예 (2조 5항)
4. README 시점 (2조 7항)

---

## 2. 제출 범위

**ch4 1조(프로젝트 전체 구조)와 4조(연동 규칙)에 대한 개정안을 작성하라.**

### 2-A. ch4 1조: 프로젝트 전체 구조

현행 1조는 `docs/` 트리만 정의하고 있다. 그러나 개헌으로 governance/가 신설되었고, monkos-ops/에 4부서 골격도 생성되었다. 다음을 반영:

- governance/ 트리 추가 (laws, constitution, history, philosophy)
- docs/ 트리에서 laws/, constitution/ 제거 (이미 이동됨)
- monkos-ops/ 4부서 구조 반영 (ops, tech, contents, marketing)
- 4계층 위계 명시 (헌법 → 거버넌스 → 세칙 → 데이터)
- 네가 청구한 "현재 유효 구조 / 목표 구조" 분리 여부 — 현실에 맞게 재판단

### 2-B. ch4 4조: 정본 위치 테이블 갱신

현행 4조의 정본 테이블:

| 영역 | 정본 위치 (현행) | 현실 |
|------|----------------|------|
| 법률/헌법 | `docs/infrastructure/laws/` | `governance/laws/`로 이동 완료 |
| 세션 로그 | `monkos-ops/06_로그/sessions/` | `monkos-ops/ops/sessions/`로도 이동됨 |
| 전략 문서 | `monkos-ops/01_전략/` | `monkos-ops/ops/`로 이동 시작 |

governance/ 계층을 포함한 새 정본 테이블을 설계하라.

### 2-C. 네 기존 청구(이행 유예, README 시점)

- 2조 5항 이행 유예: 어젯밤 막내2가 122건 이동 완료. 아직 유효한 유예가 필요한가?
- 2조 7항 README 시점: 어젯밤 README 다수 생성. 현행 규정 수정이 여전히 필요한가?

이 2건에 대해 **유지/철회/수정** 의견을 포함하라.
