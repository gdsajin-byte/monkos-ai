## 임무 정의

MONK OS의 **라우터 클로드** — 리모트 세션에 24/7 상주하며 조직 전체의 맥락을 라우팅하는 허브 — 의 **구현 설계서**를 작성하라. 기존 프로토타입(`command_bridge.js`)과 신기술(Claude Desktop Remote Session, Agent SDK)을 비교하여 최적 구현 경로를 제시한다.

---

## 배경

### 철창 설계: 라우터 클로드 구상

```
[라우터 클로드 - 리모트 상주]
  └─ CLAUDE.md: 조직 전체의 라우팅 규칙
      ├─ [프로젝트 A] — monk.kr
      ├─ [프로젝트 B] — monkos.ai
      └─ [프로젝트 N]
```

- 리모트 세션 = Anthropic 서버에서 실행, 앱 꺼도 작업 지속
- **별도 컴퓨트 요금 없음** (구독 플랜 내 소모)
- 모니터링: 데스크탑 앱, claude.ai/code, iOS 앱
- 역할: 세션 간 맥락 라우터, 기존 도구들 위의 자연어 오케스트레이션 레이어

### 기존 프로토타입: command_bridge.js

파일 위치: `monkos-ops/scripts/command_bridge.js`

**반드시 이 파일을 직접 읽어라.**

핵심 구조:
- Firestore `commands/ssanga/queue` 실시간 리스너
- pending 명령 감지 → `claude -p "<command>" --print` 실행 → 결과를 Firestore에 기록
- 10분 타임아웃, 30분 하트비트
- notify() 함수로 알림 API 호출

발견된 문제:
- 인증 없음 (Firestore에 쓸 수 있는 누구나 명령 실행 가능)
- `shell: true` (커맨드 인젝션 취약)
- Windows 경로 하드코딩 (`c:\Users\smuse73\`)
- serviceAccountKey.json 참조 (보안 위험)

### Agent SDK 경로 (심층 분석 결과)

- `@anthropic-ai/claude-agent-sdk`의 `query()` 함수
- Node.js 서버에서 직접 Claude Code 세션 생성
- 로컬 실행 or Cloud Run 배포 가능
- 월 비용 추정: $55-155 (모델 API 호출 기준)

### 3가지 구현 경로 비교 필요

| 경로 | 기술 | 비용 | 장점 | 단점 |
|------|------|------|------|------|
| A: Desktop Remote | Claude Desktop Code → Remote | 구독 내 | 비용 0, GUI 모니터링 | 프로그래밍 불가? |
| B: Agent SDK | Node.js + @anthropic-ai/claude-agent-sdk | API 비용 | 완전 자동화, 코드 제어 | 비용 발생 |
| C: command_bridge 진화 | Firestore + `claude -p` | 구독 내 | 이미 프로토타입 존재 | 보안 취약, 기능 제한 |
