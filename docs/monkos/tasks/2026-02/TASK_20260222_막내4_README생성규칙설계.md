# 막내4: 기능별 README 생성 규칙 설계

## 배경
- Phase 1 막내2 보고서(REPORT_20260222_기술명세카탈로그.md)에서 37개 기능, 문서화율 14% 확인
- 각 서비스/기능 폴더마다 README가 있어야 새 에이전트나 팀원이 즉시 맥락 파악 가능
- README = "이 폴더는 무엇인가"의 즉답 → 에이전트 온보딩의 핵심
- 작가님 구상: 한송이, 꾸 등 팀원 디바이스에 심어줄 때 README가 네비게이션 역할

## TASK

### T1: README 필요 디렉토리 전수 파악
- 프로젝트 전체 디렉토리 트리 탐색
- 각 디렉토리에 README.md 존재 여부 체크
- README 필요도 판단:
  - **필수**: 서비스 루트, 기능 폴더, 인프라 폴더
  - **선택**: 에셋 폴더, 빌드 산출물
  - **불필요**: node_modules, .git, dist 등

### T2: README 표준 템플릿 설계 (레벨별)

#### Level 1: 서비스 루트 README
```markdown
# {서비스명}
> {한줄 설명}

## 개요
- 역할: ...
- 배포: {플랫폼} / {리전} / {도메인}
- 기술 스택: ...

## 디렉토리 구조
{폴더 트리}

## 주요 기능
| 기능 | 설명 | 상세 명세 |
|------|------|----------|
| ... | ... | [SPEC_xxx.md](링크) |

## 실행 방법
{로컬 개발 환경 실행법}

## 배포
{배포 명령어}

## 관련 문서
- [기술명세](링크)
- [세션로그](링크)
```

#### Level 2: 기능 폴더 README
```markdown
# {기능명}
> {한줄 설명}

## 파일 목록
| 파일 | 역할 |
|------|------|

## 의존 관계
- 상위: ...
- 호출: ...

## 관련 명세
- [SPEC_xxx.md](링크)
```

#### Level 3: 문서 폴더 README (docs/ 하위)
```markdown
# {폴더명}
> {이 폴더에 들어가는 문서 유형}

## 파일명 규칙
{패턴 설명}

## 최근 문서
| 파일 | 날짜 | 요약 |
|------|------|------|
```

### T3: README 자동 생성 규칙
- 어떤 조건에서 README가 자동 생성/갱신되어야 하는지:
  - 새 폴더 생성 시 → README 스켈레톤 자동 생성
  - 폴더 내 파일 변경 시 → "최근 문서" 섹션 갱신
  - 배포 성공 시 → 서비스 README의 버전/배포일 갱신
- 데몬(철창이/소넷이)이 실행할 규칙 명세

### T4: 현재 README 현황 vs 필요 목록
- 이미 존재하는 README 목록 + 내용 품질 평가 (1줄 vs 상세)
- 신규 생성 필요한 README 목록 (우선순위 포함)
  - P0: 서비스 루트 (idphoto-kr, portal, idphoto-jp)
  - P1: 주요 기능 폴더
  - P2: 문서 폴더
