## TASK

### T1: 전체 트리 .md 파일 전수조사
- 프로젝트 루트(`/Users/developer/monk_project/`)부터 재귀 탐색
- **대상**: `*.md`, `*.txt`, `README*`, `CHANGELOG*`, `LICENSE*` 등 문서성 파일 전체
- **제외**: `node_modules/`, `.git/`, `dist/`, `build/` 등 빌드 산출물
- docs/ 내부는 Phase 1에서 완료 → 이번에는 **docs/ 외부만** 조사
- 각 파일: 경로, 파일명, 크기, 최종 수정일, 내용 1줄 요약

### T2: 트리별 문서 분포 매핑
```
프로젝트 루트
├── CLAUDE.md (헌법)
├── MONK_kr/          ← 여기 내 문서들
│   ├── ai_lab/photolab/  ← PAGE_SPLIT_ANALYSIS.md, flowchart 등
│   └── ...
├── monkos_AI/        ← 여기 내 문서들
│   ├── idphoto-kr/   ← README?, package.json 등
│   ├── idphoto-jp/
│   └── portal/
├── apps/             ← 레거시 문서
├── .claude/          ← MEMORY.md 등
└── docs/             ← (Phase 1 완료, 스킵)
```
- 각 트리의 문서 수, 분류(설정/README/기술문서/레거시), 상태(현행/구버전/사망)

### T3: docs/ 귀속 판단
- 각 파일에 대해 판단:
  - A) docs/로 이동해야 함 → 목적지 폴더 제안
  - B) 현재 위치가 맞음 (코드 옆 README 등) → 그대로 유지
  - C) 삭제 가능 (레거시/중복) → 삭제 후보 마킹
- Phase 1 막내3의 자동 분류 규격(파일명 패턴 7종)에 매칭 시도

### T4: 코드 디렉토리 내 인라인 문서 현황
- 각 서비스 디렉토리(monkos_AI/idphoto-kr, portal, idphoto-jp)에:
  - README.md 존재 여부
  - package.json description 필드 유무
  - 코드 내 JSDoc/주석 밀도 (샘플링)
  - .env.example 유무

  2. 트리별 문서 분포 시각화
