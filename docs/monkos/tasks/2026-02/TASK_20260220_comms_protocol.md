## Phase 2: 통신 채널 현황 분석

현재 프로젝트에서 사용 중 / 계획 중인 **모든 통신 채널**을 정리:

| 채널 | 방향 | 용도 | 현재 상태 | 관련 파일 |
|------|------|------|----------|----------|
| CLAUDE.md 수발신 헤더 | 에이전트↔에이전트 | 세션 내 통신 추적 | 활성 | CLAUDE.md |
| 완료 보고 (2규칙) | 에이전트→작가님 | 작업 결과 보고 | 활성 | CLAUDE.md |
| 지시서 | 쌍아→막내 | 작업 지시 | 활성 | docs/monkos/TASK_* |
| 세션 로그 | 에이전트→아카이브 | 이력 기록 | 활성 | docs/corpus/sessions/ |
| 텔레그램 | 에이전트→작가님 | 긴급 알림 / 이슈 보고 | ? | ? |
| git commit 메시지 | 에이전트→전원 | 변경 추적 | 활성 | CLAUDE.md |
| (기타 발견 시 추가) | | | | |

각 채널에 대해:
1. **현재 상태**: 활성 / 구현중 / 계획만 / 미착수
2. **구현 수준**: 규칙만 / 코드 있음 / 완전 자동화
3. **관련 파일**: 규칙 정의 파일 + 구현 코드 파일

## Phase 3: 통신 흐름도 작성

에이전트 간 전체 통신 흐름을 **매트릭스**로 정리:

```
         발신 →
수신 ↓    작가님    쌍아      막내N     소넷이    철창이    용아
작가님     -      완료보고   완료보고   알림      브레인   자문
쌍아     지시     -         지시서     모니터링   -       분석
막내N    지시     지시서     -         -         -       -
소넷이    -      지시서     -         -         -       -
철창이   대화     -         -         -         -       -
용아     대화     -         -         -         -       -
```

각 셀에 대해:
- **채널**: 뭘로 통신하나 (CLAUDE.md 헤더 / 지시서 / 텔레그램 / git / 구두)
- **형식**: 어떤 포맷인가 (2규칙 / 지시서 템플릿 / 자유)
- **의무/선택**: 반드시 해야 하는가 / 상황 판단인가

## Phase 4: 통신 규칙 기안

Phase 1~3 결과를 종합하여, 헌법/법률에 편입할 **통신 규칙 초안**을 작성.

### 구조 (제안)

```markdown
## 통신 규칙 (법률 제N장 — 초안)

### 1조: 통신 기록 의무
- 모든 에이전트 간 통신은 추적 가능해야 한다
- 타임스탬프(헌법 제1조) + 수발신 헤더 필수

### 2조: 보고 체계
- 완료 보고: 2규칙 형식 (✅❌💡⏳📁🔀)
- 에스컬레이션: [조건별 분기]
- 긴급 보고: [채널 + 형식]

### 3조: 지시서 체계
- 발행: 쌍아 전용 (작가님 지시 기반)
- 형식: 헤더(type/from/to/date/status) + 역할 선언 + 본문 + 완료 기준
- 아카이브: 완료 시 docs/ops/tasks/ 이관

### 4조: 세션 로그
- 1일 1파일, append only
- 형식: [기존 세션 로그 규칙 승계]
- 불변 원칙: 원본 수정/삭제 금지

### 5조: 외부 통신 채널
- 텔레그램: [용도, 트리거 조건, 형식]
- git push: [코드 저장만, 배포 아님 (CF 자동빌드 OFF)]

### 6조: 크로스 디바이스 통신
- M1↔iMac↔4060↔M2 간 통신 규칙
- 디바이스 약칭 표준 (M1/iMac/4060/M2/iPhone)

### 7조: 통신 장애 대응
- 텔레그램 불통 시 대체 채널
- 에이전트 무응답 시 에스컬레이션
```

위는 골격이다. 실제 조사 결과에 맞게 조항을 조정/추가하라.
