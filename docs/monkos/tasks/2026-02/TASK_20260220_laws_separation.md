### 각 파일 작성 규칙

**헤더 형식** (모든 파일 공통):
```markdown
# 법률 제N장: 장 제목

> 상위 헌법: 제X조, 제Y조
> 변경 권한: 작가님 승인 시 개정 가능

---
```

**조항 형식**:
```markdown
### N조: 조항명

- 핵심 내용

> 근거: YYYY-MM-DD — 세션 또는 CLAUDE.md 출처
> 상위 헌법: 제X조
```

### 각 장 내용 소스

| 장 | 조항 코드표 위치 | 거버넌스 설계 위치 | 조 수 |
|----|-----------------|-------------------|------|
| 제1장 에이전트 체계 | §II 제5장 1~5조 | §1-5 제1장 | 4조 (정의/흐름/지시서/수발신) |
| 제2장 코딩 규칙 | §II 제1장 1~5조 | §1-5 제2장 | 5조 (스택/네이밍/언어/CSS/백엔드) |
| 제3장 세션 로그 | §II 제3장 1~3조 | §1-5 제3장 | 3조 (위치/형식/타임스탬프) |
| 제4장 문서/폴더 | §II 제4장 1~2조 | §1-5 제4장 | 2조 (구조/금지) |
| 제5장 배포 규칙 | §II 제2장 1~4조 | §1-5 제5장 | 4조 (CF Pages/Cloud Run/prod권한/동결) |
| 제6장 브랜치/커밋 | §II 제6장 1~4조 | §1-5 제6장+제8장 | 4조 (브랜치/main보호/커밋메시지/완료보고) |
| 제7장 막내 행동 강령 | §II 제5장 3~5조 + 자유/금지 | §1-5 제7장 | 5조 (흐름/자유범위/금지/에스컬레이션/MEMORY확인) |
| 제8장 브랜딩/마케팅 | §II 제7장 1~3조 | — (조항 코드표에만) | 3조 (MONKOS통일/사업자정보/메신저전략) |

### 합본 원칙

- **조항 코드표** = 조항 번호 + 내용 + 근거 + 작가님 원문 + 위반 시 (근거 데이터)
- **거버넌스 설계** = 실제 삽입 텍스트 (압축된 실행 가능 문구)
- **합본**: 거버넌스 설계의 **압축 텍스트**를 기반으로 하되, 조항 코드표의 **근거·작가님 원문·위반 시**를 추가

### 장 번호 통일 주의

조항 코드표(막내1)와 거버넌스 설계(막내2)의 장 번호가 불일치한다:

| 내용 | 조항 코드표 | 거버넌스 설계 | **신규 통일** |
|------|-----------|-------------|-------------|
| 에이전트 체계 | 제5장 | 제1장 | **제1장** |
| 코딩 규칙 | 제1장 | 제2장 | **제2장** |
| 세션 로그 | 제3장 | 제3장 | **제3장** |
| 문서/폴더 | 제4장 | 제4장 | **제4장** |
| 배포 규칙 | 제2장 | 제5장 | **제5장** |
| 브랜치/커밋 | 제6장 | 제6장+제8장 | **제6장** (합본) |
| 막내 행동 강령 | 제5장 일부 | 제7장 | **제7장** |
| 브랜딩/마케팅 | 제7장 | — | **제8장** |

**신규 통일 번호**를 사용할 것. 거버넌스 설계의 장 번호를 기준으로 하되, 제8장(브랜딩)은 조항 코드표에서 가져온다.
