## 공유: 오늘 밤 설계 결론

### 1. 4계층 위계

```
헌법 (CLAUDE.md)                    ← 자동 인식 (커널)
    │
법률 + 역사 + 철학 (governance/)    ← 본질 · 설계 · 근거
    │
부서 세칙 (monkos-ops/ 각 README)   ← 운영 규정
    │
데이터 · 에셋 (부서 하위)            ← 실행 산출물
```

### 2. 이분 구조: governance + operations

```
monk_project/
├── CLAUDE.md                    ← 헌법 (커널)
├── governance/                  ← 거버넌스: 본질 · 설계 · 근거
│   ├── laws/                      법률 ch1~ch8
│   ├── constitution/              개정 절차 (amendment.md)
│   ├── history/                   역사 (세션로그, 결정기록)
│   └── philosophy/                철학 (비전, 가치관, 어록)
└── monkos-ops/                  ← 운영: 실행
    ├── ops/                       운영 관리 (tasks, releases, scripts, team)
    ├── tech/                      기술 (specs, architecture)
    ├── contents/                  콘텐츠 (publishing, academy)
    └── marketing/                 마케팅 (ads, channels)
```

### 3. 핵심 원칙

- **법률은 어떤 부서의 소관이 아니다** — 각 부서를 규정하는 상위 체제
- **docs/ → governance/ 리네이밍** — 문서가 아니라 거버넌스
- **역사·철학은 운영이 아닌 본질** — ops가 아니라 governance에 속함
- **부서 README = 세칙** — 법률이 부서를 규정하고, README가 세부 운영 규칙
- **삼권은 구조가 아니라 프로세스** — amendment.md에 입법·행정·사법 절차 내장

### 4. 작가님 핵심 발언

> "법률은 너희가 생성추출 아카이브하는 대상이 아니라 최우선 각인하고 모든것을 운영하는 체계 그 자체이다"

> "헌법(자동인식) 법률(규정사항) 세부 각부서별 목록및 세칙 그 제하에 생성되는 모든 데이터,에셋들은 하부조직이다"
