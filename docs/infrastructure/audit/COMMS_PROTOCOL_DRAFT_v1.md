## 4. 통신 규칙 기안

> 거버넌스 설계(MONK_GOVERNANCE_DESIGN_v1.md)에서 에이전트 운용이 법률 제1장에 배치됨.
> 통신 규칙은 **법률 제1장의 확장** 또는 **별도 제N장 신설**로 편입.
> 아래는 막내1 조항 코드표(MONK_ARTICLES_DRAFT_v1.md) 제5장(에이전트 운용 규칙)과 정합.

### 통신 규칙 초안 — 법률 제5장 확장안

```markdown
## 제5장: 에이전트 통신 규칙

> 상위 헌법: 제1조(타임스탬프), 제2조(보고 의무), 제5조(에이전트 역할)

### 1조: 통신 기록 원칙
모든 에이전트 간 통신은 **추적 가능**해야 한다.
- 타임스탬프(헌법 제1조) + 수발신 헤더 필수
- 형식: `[YYYY-MM-DD HH:MM KST] {디바이스}/{에이전트} → {수신자}`
- 디바이스 약칭: M1(집) / iMac(사무실) / M2(몽크사진관) / 4060(GPU서버) / iPhone(모바일)
- 작가님이 수신자일 때 디바이스 생략

### 2조: 완료 보고 (헌법 제2조 시행)
모든 에이전트는 작업 완료 시 아래 형식으로 보고한다.
```
---
## 완료 보고
[YYYY-MM-DD HH:MM KST] {디바이스}/{에이전트} → {수신자}

✅ 완료: {1줄}
❌ 실패: {원인 1줄}
💡 제안: {1줄}
⏳ 대기: {승인 필요 사항}
📁 변경 파일: {파일명 (수정 내용 1줄)}
🔀 커밋: {해시} {메시지}
---
```
- 해당 없는 항목 생략. 각 항목 1줄 이내.
- 이 보고가 **세션의 마지막 출력**이어야 함 (보고 후 잡담 금지).
- 코드 작업 시 📁, 🔀 반드시 포함.

### 3조: 지시서 체계
지시서는 **쌍아 전용** 발행물이다 (작가님 지시 기반).

#### 3-1. 형식
```yaml
---
type: task
from: 쌍아
to: 막내 N호
date: YYYY-MM-DD HH:MM KST
status: open
priority: high/medium/low
tags: [태그1, 태그2]
---
```

#### 3-2. 필수 구성
1. **역할 선언**: "너는 막내 N호다. 쌍아가 아니다." (정체성 혼동 방지)
2. **작업 내용**: 단계별 지시
3. **완료 기준**: 레벨 명시 (조사+보고 / 실행+커밋 / 배포+검증)
4. **규칙**: 브랜치, 커밋 메시지, 금지사항

#### 3-3. 경로
- 발행: `docs/monkos/TASK_YYYYMMDD_{주제}.md`
- 레거시(기존): `commands/YYYYMMDD_HHMM_{발신}_{수신}_{주제}.md`

### 4조: 세션 로그 (헌법 제1조 시행)
- 위치: `docs/corpus/sessions/YYYY-MM/YYYYMMDD_session.md`
- 1일 1파일, append only, Q&A 번호 연속 증가
- **원본 수정/삭제 절대 금지** (01-14 결정: "대화록 누락 절대 금지")
- 헤더: `# 세션 로그: YYYY-MM-DD (요일)` + 환경 + 시작시간
- 본문: `### [HH:MM] 작업 주제` + 작가님 발언 인용 + 실행/결과
- 종료: 완료 체크리스트 + TODO + 종료 시간

### 5조: 에스컬레이션 규칙
| 조건 | 행동 | 보고 형식 |
|------|------|----------|
| 에러 5회 반복 | 즉시 중단 + 원인 분석 | ❌ 에러 내용 + 💡 분석 결과 |

## 7. 통신 규칙 체계 — 합본 제안

막내2 거버넌스 설계 + 막내1 조항 코드표 + 본 통신 프로토콜의 **합본 구조 제안**:

### 7-1. 통신 관련 조항 배치 제안

```
헌법
  제1조: 시계열 정합성 (타임스탬프)        ← 통신 기록의 기초
  제2조: 보고 의무 (완료 보고)             ← 통신 형식의 핵심

법률
  제N장: 에이전트 통신 규칙              ← 본 문서 기안 (신규 장)
    1조: 통신 기록 원칙 (수발신 헤더)
    2조: 완료 보고 시행 (2규칙 상세)
    3조: 지시서 체계
    4조: 세션 로그
    5조: 에스컬레이션
    6조: 외부 통신 채널 (텔레그램/디스코드)
    7조: 크로스 디바이스 통신
    8조: 통신 장애 대응

규정 (별도 파일)
  R-xx: 텔레그램 봇 토큰/웹훅 URL
  R-xx: 디바이스 약칭 표
  R-xx: CLI alias 표
  R-xx: 디스코드 웹훅 URL
```

### 7-2. 기존 법률 장과의 관계

| 기존 (거버넌스 v1) | 합본 후 | 비고 |
|-------------------|---------|------|
| 제1장: 에이전트 체계 | 제1장: 에이전트 체계 (정의+역할) | 통신 규칙 분리 → 별도 장 |
| — | **제N장: 에이전트 통신 규칙** (신규) | 수발신, 보고, 지시서, 세션로그, 텔레그램 통합 |
| 제3장: 세션 로그 | 통신 규칙 장으로 흡수 | 세션 로그는 통신 채널의 일종 |
| 제7장: 막내 행동 강령 | 에스컬레이션은 통신 규칙으로 이동 | 막내 장에는 작업 범위/금지만 |
