# 법률 제6장: 브랜치/커밋 규칙

> 상위 헌법: 제3조(프로젝트 정체성), 제5조(응답 윤리)
> 변경 권한: 작가님 승인 시 개정 가능

---

### 1조: 브랜치 전략

- **기본 작업 브랜치: `develop`.**
- 지시서에 별도 브랜치 명시 시 해당 브랜치 사용.

> 근거: CLAUDE.md L311-316
> 상위 헌법: 제5조(에이전트 역할 체계 — 작업 범위)
> 예외: 지시서에 별도 명시 시

---

### 2조: main 보호

- `main` 브랜치 직접 커밋/push **금지**.
- `main`으로 머지 **금지** (쌍아 또는 작가님이 판단).

> 근거: CLAUDE.md L311-316
> 위반 시: 미검증 코드 프로덕션 유입. 법률 제5장(배포 규칙) 전체 무력화.
> 상위 헌법: 제5조(에이전트 역할 체계)

---

### 3조: 커밋 메시지

- **한국어**, 1줄 요약.
- 접두사 필수: `[feature]`, `[fix]`, `[design]`, `[refactor]`, `[docs]`
- 작업 단위로 분할 커밋 (**거대한 1커밋 금지**, 의미 단위로 분할).
- 예: `[design] index.html 파일 분리: CSS/JS 7파일 구조화`

> 근거: CLAUDE.md L348-353
> 상위 헌법: 제3조(한국어 우선)

---

### 4조: 완료 보고 (커밋 시)

- 헌법 제2조 형식 준수.
- 코드 작업 시 **📁 변경 파일, 🔀 커밋 반드시 포함**.
- 이 보고가 세션의 마지막 출력이어야 함 (보고 후 잡담 금지).

> 근거: 2026-02-15 확립
> 상위 헌법: 제2조(보고 의무)
