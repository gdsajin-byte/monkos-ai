## 1. 전략적 위치 재정의

### 기존 인식
```
monkos.ai (포털)
├── 쌍아 — 챗봇
├── 소소 — 이미지 (idphoto는 소소의 카드 1장)
├── 민아 — 모델
└── 용아 — 전략
```

### 수정된 인식
```
monkos.ai (포털) ──── 몽크사진관 (독립 버티컬)
├── 쌍아 — 챗봇       ├── AI 촬영+생성
├── 소소 — 이미지      ├── 규격 크롭
├── 민아 — 모델        ├── AI 리터칭
└── 용아 — 전략        ├── 인화 주문
                      └── (확장: 비자/운전면허/취활패키지...)
```

**몽크사진관은 포털의 카드가 아니라, 포털과 대등한 하나의 버티컬이다.**

## 2. 증명사진 비즈니스의 실제 깊이

### 2-1. 공정 (파이프라인)

```
[촬영] → [코칭] → [생성] → [QC] → [규격크롭] → [리터칭] → [인화] → [배송]
  │        │        │       │        │           │         │        │
  카메라    Gemini   Imagen  Gemini   Canvas      Imagen    외부     외부
  WebRTC   Live     I2I     3Flash   순수JS      I2I(2nd)  프린트   배송사
```

현재 idphoto가 커버하는 범위: **촬영~규격크롭** (5/8 공정)
빠져있는 공정: **리터칭, 인화, 배송** (3/8)

### 2-2. 분기 변수

| 변수 | 경우의 수 | 예시 |
|------|----------|------|
| **국가** | 한/일 (→ 글로벌 확장) | 규격, 결제, 언어 |
| **용도** | 여권, 이력서, 비자, 운전면허, 학생증... | 규격, 배경색, 복장 규칙 |
| **연령** | 유아, 청소년, 성인 | 보정 허용 범위 (아동=보정 금지) |
| **성별** | 남/여 | 복장 프롬프트 |
| **규격** | 3.5×4.5(한), 3×4(일), 2×2inch(미)... | 크롭 비율, DPI |

### 2-3. 수익 구조

| 카드 | 과금 | 단가 | 비고 |
|------|------|------|------|
| AI 촬영+생성 | 크레딧 (생성 1c) | ₩192/장 원가 | 코어 — AI 비용 발생 |
| 규격 크롭 | **무료** | ₩0 | 집객 무기 — SEO 유입 |
| AI 리터칭 | 크레딧 | ₩192/장 원가 | Imagen I2I 재호출 |
| 인화 주문 | 실비 + 마진 | 장당 ₩500~2,000 | 외부 연동 |
| 다운로드 | 크레딧 (10c) | - | 현재 구현됨 |

**무료 크롭 → 가입 → AI 촬영 → 리터칭 → 인화**: 자연스러운 퍼널

## 3. 4개 서비스 카드 설계

### Card 1: AI 촬영+생성 (현재 idphoto 코어)

**역할:** 카메라 코칭 → AI 증명사진 생성 → QC 검증
**기술:** Gemini Live (코칭) + Imagen I2I (생성) + Gemini Flash (QC)
**입력:** 실시간 카메라 스트림 (1024px, JPEG 85%)
**출력:** AI 생성 증명사진 (PNG, 3:4)
**과금:** 생성 1크레딧

```
┌─────────────────────────────────┐
│         Card 1: AI 촬영+생성      │
│                                 │
│  [카메라] → [AI 코칭] → [촬영]   │
│      ↓                          │
│  [Imagen I2I 생성] → [QC 검증]   │
│      ↓                          │
│  생성된 증명사진 (원본 해상도)      │
│      ↓                          │
│  → Card 2 (크롭) 으로 전달       │
│  → Card 3 (리터칭) 으로 전달      │
└─────────────────────────────────┘
```

### Card 2: 규격 크롭/리사이징 (독립 무료 툴)

**역할:** 사진을 국가/용도별 규격에 맞게 자동 크롭
**기술:** 순수 Canvas (AI 불필요) + Gemini Flash (얼굴 검출 — 선택)
**입력:** 아무 사진 (Card 1 결과물 OR 사용자 업로드)
**출력:** 규격 맞춤 사진 (여권 3.5×4.5, 비자 5×5 등)
**과금:** 무료 (SEO 집객)

```
┌─────────────────────────────────┐
│      Card 2: 규격 크롭 (무료)     │
│                                 │
│  [사진 업로드 / Card 1 결과]      │
│      ↓                          │
│  [얼굴 검출] → [자동 크롭]       │
│      ↓                          │
│  국가 선택: 🇰🇷 🇯🇵 🇺🇸 🇨🇳...     │
│  용도 선택: 여권 / 비자 / 이력서   │
│      ↓                          │
│  규격 사진 (300dpi 출력)          │
│      ↓                          │
│  → 무료 다운로드                  │
│  → Card 4 (인화) 으로 전달       │
└─────────────────────────────────┘
```

**SEO 가치:** "여권사진 규격", "パスポート写真サイズ", "passport photo size" 등
고의도 검색어로 유입 → 가입 → AI 촬영 유도

### Card 3: AI 리터칭 (프리미엄)

**역할:** 기존 사진의 AI 보정 (피부톤, 조명, 배경 교체)
**기술:** Imagen I2I (보정 전용 프롬프트)
**입력:** Card 1 결과물 OR 사용자 업로드
**출력:** 리터칭된 사진
**과금:** 크레딧

```
┌─────────────────────────────────┐
│      Card 3: AI 리터칭            │
│                                 │
│  [사진 업로드 / Card 1 결과]      │
│      ↓                          │
│  보정 옵션:                      │
│  ├── 피부 보정 (잡티, 피부톤)     │
│  ├── 조명 보정 (균일 스튜디오)    │
│  ├── 배경 교체 (흰색/파랑/회색)   │
│  └── 복장 보정 (정장 착용)        │
│      ↓                          │
│  [Imagen I2I] → [미리보기]       │
│      ↓                          │
│  → 다운로드 (크레딧)             │
│  → Card 2 (크롭) 으로 전달       │
└─────────────────────────────────┘
```

**주의:** 리터칭 = Imagen I2I 2회차 호출. 회차별 품질 열화 이슈 있음.
→ 1회 정밀 생성 전략 유지: Card 1에서 최대한 완성도 높이고, Card 3은 미세 보정만.

### Card 4: 인화 주문 (향후)

**역할:** 디지털 사진 → 실물 인화 + 배송
**기술:** 외부 프린트 API 연동
**입력:** Card 2 규격 사진
**출력:** 실물 인화 사진 (우편 배송)
**과금:** 실비 + 마진

```
┌─────────────────────────────────┐
│      Card 4: 인화 주문 (향후)     │
│                                 │
│  [Card 2 규격 사진]              │
│      ↓                          │
│  매수 선택: 4매 / 8매 / 16매     │
│  용지 선택: 일반 / 고급 광택      │
│  배송지 입력                     │
│      ↓                          │
│  [외부 프린트 업체 API]           │
│      ↓                          │
│  결제 → 인화 → 배송             │
└─────────────────────────────────┘
```

## 4. 카드 간 데이터 흐름

```
사용자 진입
    │
    ├─── [Card 2: 무료 크롭] ←── 자체 사진 업로드 (SEO 유입)
    │        │
    │        ├── 무료 다운로드 (규격 사진)
    │        ├── → Card 4 (인화)
    │        └── → "AI로 더 좋은 사진 찍어보세요" → Card 1 유도
    │
    ├─── [Card 1: AI 촬영+생성] ←── 포털/직접 진입
    │        │
    │        ├── → Card 2 (규격 크롭) — 자동 연결
    │        ├── → Card 3 (리터칭) — 선택
    │        └── 다운로드 (크레딧)
    │
    ├─── [Card 3: AI 리터칭] ←── Card 1 결과 또는 자체 업로드
    │        │
    │        ├── → Card 2 (규격 크롭)
    │        └── 다운로드 (크레딧)
    │
    └─── [Card 4: 인화] ←── Card 2 결과
             │
             └── 결제 → 배송
```

**핵심 퍼널:**
1. **무료 진입**: Card 2 (크롭) — SEO로 유입, 가입 유도
2. **AI 체험**: Card 1 (촬영+생성) — 무료 크레딧으로 첫 생성
3. **가치 인식**: 결과물 보고 "이거 좋다" → 다운로드/리터칭/인화
4. **과금 전환**: 다운로드 크레딧 + 리터칭 크레딧 + 인화 실비

## 5. 기술 아키텍처

### 5-1. 서비스 배포 구조

```
Cloud Run (us-central1)
├── monkos-portal          ← monkos.ai (인증/결제/크레딧)
├── monkos-idphoto-kr      ← idphoto-kr.monkos.ai (Card 1+2+3 KR)
├── monkos-idphoto-jp      ← idphoto-jp.monkos.ai (Card 1+2+3 JP)
└── (향후) monkos-print    ← print.monkos.ai (Card 4)
```

Card 1~3은 동일 서비스 내에서 라우팅으로 분리 (별도 Cloud Run 불필요):
- `/app` → Card 1 (AI 촬영+생성)
- `/crop` → Card 2 (규격 크롭) — 비로그인 허용
- `/retouch` → Card 3 (AI 리터칭)

### 5-2. KR/JP 공유 코어

```
monkos_AI/idphoto/                    ← 단일 코드베이스
├── server.js                         ← 공유 서버 (REGION 환경변수)
├── config/{kr,jp}.js                 ← 리전 설정
├── core/                             ← 공유 AI 모듈
│
├── public/shared/                    ← 공유 CSS + JS
│   ├── styles.css
│   ├── camera.js                     ← Card 1: 카메라/WS
│   ├── crop.js                       ← Card 2: 규격 크롭 엔진
│   ├── retouch.js                    ← Card 3: 리터칭 UI
│   ├── auth.js                       ← 인증/크레딧
│   └── utils.js                      ← 공유 유틸
│
├── public/kr/                        ← KR 엔트리 + i18n + 결제
│   ├── index.html                    ← /app (Card 1)
│   ├── crop.html                     ← /crop (Card 2)
│   ├── retouch.html                  ← /retouch (Card 3)
│   ├── i18n.js
│   └── payment.js                    ← 토스
│
└── public/jp/                        ← JP 엔트리 + i18n + 결제
    ├── index.html
    ├── crop.html
    ├── retouch.html
    ├── i18n.js
    └── payment.js                    ← Lemon Squeezy
```

### 5-3. 이미지 파이프라인 (확정)

| 스테이지 | 처리 위치 | 스펙 |
|---------|----------|------|
| 카메라 스트림 | 클라이언트 | getUserMedia max: 1280px |
| 코칭 프레임 | 클라이언트→서버 | 512px, JPEG 60%, 1fps |
| 최종 캡처 | 클라이언트 | 1024px, JPEG 85% |
| Imagen 입력 | 서버 (패스스루) | 그대로 전달, 2MB 검증만 |
| QC 입력 | 서버 (패스스루) | 그대로 전달 |
| 규격 크롭 | 클라이언트 (Canvas) | 300dpi 출력 |
| 리터칭 입력 | 서버 (패스스루) | Card 1 결과물 or 업로드 |

**sharp 의존성: 없음** (클라이언트 출력 제한으로 대체)

→ 상세 기술 스펙: [SHARED_CORE_SEPARATION_PLAN.md](./SHARED_CORE_SEPARATION_PLAN.md) §2-4
