## 2. Claude 플랜 비교 분석

### 2-1. Max 5x ($100) vs Max 20x ($200)
| 항목 | Max 5x ($100) | Max 20x ($200) |
|---|---|---|
| 기능 | **완전 동일** | **완전 동일** |
| 세션당 사용량 | Pro 5배 | Pro 20배 |
| 5시간당 메시지 | ~225+ | ~900+ |
| Claude Code/5h | ~50-200 프롬프트 | ~200-800 프롬프트 |
| Opus 사용 | 전략적 절약 필요 | 자유롭게 사용 |

- **핵심:** 기능 차이 제로, 순수 사용량 차이만 존재
- 작가님 현재 주간 전체모델 50% 사용, Sonnet 0% → Opus 헤비유저 패턴

### 2-2. Team 플랜
| 시트 유형 | 가격 | 사용량 | Claude Code |
|---|---|---|---|
| Standard | $25~30/인/월 | Pro 1.25배 | ❌ |
| Premium | $150/인/월 | Pro 6.25배 | ✅ |

- 최소 5인 필수
- Standard ↔ Premium 시트 간 재배정 가능
- Extra Usage 활성화 시 한도 초과분 API 요금으로 계속 사용 가능
- 개인별 월간 지출 한도 설정 가능

### 2-3. 플랜 간 핵심 비교
| 방식 | 월비용 | 프로젝트 공유 | 비고 |
|---|---|---|---|
| Max 20x (현재) | $200 | ❌ | 작가님 혼자 풀파워 |
| Max 5x + 팀원 Pro | $120~ | ❌ | 각자 따로 |
| Team Std 4 + Prem 1 | $270 | ✅ | 빈 시트 낭비 |
| Team Premium 5인 | $750 | ✅ | 과잉 투자 |
| API 종량제 | 변동 | N/A | 예측 불가, Opus 고비용 |

### 2-4. API 종량제 비용 참고
| 모델 | 입력 (1M 토큰) | 출력 (1M 토큰) |
|---|---|---|
| Opus 4.5 | $15 | $75 |
| Sonnet 4.5 | $3 | $15 |
| Haiku 4.5 | $0.80 | $4 |

### 2-5. Anthropic 플랜 설계의 구조적 문제
- 정액 + 팀 공유 + 유연한 인원 → 세 가지를 동시에 만족하는 옵션 없음
- Max: 정액 O, 공유 X, 유연 O
- Team: 정액 O, 공유 O, 유연 X (5인 최소)
- API: 정액 X, 공유 가능, 유연 O
- **의도적으로 한 가지씩 단점을 끼워넣은 구조**

## 3. MONKOS 최적 운용 전략 (현 시점)

### 3-1. 구독 구성
- **작가님:** Max 20x 유지 ($200) — Opus 5체제 풀파워
- **팀원(한송이 등):** 개별 Pro ($20) 또는 API 종량제
- **자동화(n8n 등):** API 종량제 + 월간 한도 설정
- **예상 총비용:** ~$240~270/월

### 3-2. 멀티에이전트 오케스트레이션 구조
```
전략실(용아/작가님) → 전략 수립, 파트별 임무 시트 작성
        ↓ 시트 배포
오케스트레이터(쌍아) → 각 에이전트에 임무 부여, 진행 관리, 결과 취합
        ↓ 임무 할당
수행자(막내/철창/기타) → Opus 또는 Sonnet으로 실제 작업 수행
        ↓ 결과 리턴
쌍아 검수 · 통합 → 전략실 보고
```

- $200으로 5~6명분 인건비에 해당하는 아웃풋 목표
- 오케스트레이션 로그 자체가 IR 실증 자료
- 비용이 아닌 투자 증빙으로 전환

## 4. 팀원 협업 체계: 이중 레이어 구조

### 4-1. 설계 원칙
- **Git은 AI 오케스트레이션의 신경계** (작가님 + AI 전용)
- **Google Drive는 인간 팀원과의 인터페이스**
- Claude 프로젝트 공유 없이도 플랫폼 종속 없는 체계

### 4-2. 코어 레이어 (Git + GCS)
```
monkos-ops/
├── 01_전략(strategy)/
│   ├── orders/          ← 지시서
│   ├── weekly-plans/    ← 주간 전략 시트
│   └── decisions/       ← 의사결정 로그
├── 02_리서치(research)/
│   ├── market/ / tech/ / funding/
├── 03_개발(dev)/
│   ├── tasks/ / reviews/ / releases/
├── 04_문서(docs)/
│   ├── reports/ / ir-materials/ / templates/
├── 05_공유(shared)/
│   ├── hansong/ (inbox/outbox/reference)
│   └── [팀원추가]/
└── 06_로그(logs)/
    ├── sessions/ / orchestration/ / metrics/
```

### 4-3. 팀원 레이어 (Google Drive)
```
MONKOS 공유드라이브/
├── 📋 지시서/
├── 📤 제출함/ (팀원별 하위폴더)
├── 📊 보고서/ (읽기전용)
├── 📚 참고자료/ (읽기전용)
└── 📌 템플릿/
```

### 4-4. 동기화 흐름
- **Git → Drive:** 철창 보고서 완성 → n8n 트리거 → Drive 자동 업로드 → 팀원 알림
- **Drive → Git:** 팀원 제출 → n8n 감지 → 쌍아 알림 → 검토 후 Git 반영

### 4-5. 장점
- 팀원 온보딩: "이 구글 드라이브 즐겨찾기 하세요" 한 마디
- 추가 비용 $0 (Google Workspace 기존 사용)
- Git 접근 없이 보안 유지 + 감사 추적 가능

## 5. 개발 팀원 도입 시 보안 전략

### 5-1. AI 시대의 IP 리스크
- 전통 개발: 소스코드 10만 줄 → 파악에 수개월
- AI 네이티브: 시스템 프롬프트 + 오케스트레이션 설계문서 몇 장 → **즉시 복제 가능**
- MONKOS 핵심 자산 = 코드가 아닌 **오케스트레이션 설계 자체**

### 5-2. 레이어별 접근 분리
```
Layer 0: 오케스트레이션 설계/전략  ← 작가님 ONLY
Layer 1: 시스템 프롬프트/코퍼스    ← 작가님 ONLY
Layer 2: API/인프라 구현          ← 개발팀원 접근 가능
Layer 3: 프론트엔드/UI            ← 개발팀원 접근 가능
```

### 5-3. 보호 장치
- **모듈화:** 팀원별 담당 파트만 보이게 레포 분리, 전체 아키텍처 조망은 대표만
- **법적 장치:** NDA + 경업금지 + 직무발명 (AI 운용 체계를 영업비밀로 명시 정의)
- **구조적 보안:** 핵심 설계는 대표 + AI 직접 운용, 인간 팀원은 실행 레이어만 담당

### 5-4. IR 어필 포인트
- "핵심 인력 이탈 리스크가 구조적으로 없습니다"
- AI 에이전트는 퇴사·이직·경쟁사 유출 리스크 제로

## 6. 시대적 인사이트

### 가치 축의 이동
- **"무엇을 만들 수 있는가" → "무엇을 만들어야 하는지 아는가"**
- 구현 능력은 AI가 평준화 → 방향 설정, 고객 이해, 시장 감각이 핵심 역량

- 나이, 전공, 코딩 경력 무관 — 에이전트를 다룰 줄 알면 기업을 일으킬 수 있는 시대
