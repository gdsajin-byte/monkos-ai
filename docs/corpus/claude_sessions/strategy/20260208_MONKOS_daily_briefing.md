## 2. 테일스케일 인프라 현황

### 연결 완료

| 디바이스 | 상태 | 비고 |
|---------|------|------|
| 사무실 맥 (작업 메인) | ✅ 연결 완료 | 핑 테스트 통과 |
| 아이폰 | ✅ 연결 완료 | 핑 테스트 통과 |
| 4060 PC (GPU) | ✅ 연결 완료 | 핑 테스트 통과 |
| 집 맥미니 | ⬜ 오늘 연결 | 아래 설치 가이드 참조 |

### 집 맥미니 테일스케일 설치 가이드 (막내용)

앱스토어 로그인 불필요. 터미널에서 설치.

**방법 1: Homebrew (권장)**

```bash
# Homebrew 미설치 시 먼저 설치
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 테일스케일 설치
brew install --cask tailscale
```

**방법 2: 직접 다운로드 (Homebrew 안 될 경우)**

```bash
curl -O https://pkgs.tailscale.com/stable/Tailscale-latest-macos.pkg
sudo installer -pkg Tailscale-latest-macos.pkg -target /
```

**설치 후:**

1. 앱 실행 → 메뉴바에 테일스케일 아이콘 표시됨
2. 작가님 구글 계정으로 로그인 (기존 tailnet에 합류)
3. 연결 확인: `tailscale status` 로 다른 디바이스 목록 확인
4. 핑 테스트: `tailscale ping <사무실맥 IP>` 로 지연 확인

## 3. 영상 파이프라인 아키텍처

### 전체 구조 (3개 레이어 = 하나의 파이프)

```
L1: 테일스케일 (터널) ─── "길을 뚫는다"
L2: WebRTC (스트리밍) ── "그 길 위에 영상을 흘린다"
L3: 몽코스 앱 (UI) ──── "사용자가 보는 화면"
```

포함 관계이지 별개의 객체가 아님. 수도관(테일스케일) 안에 물(WebRTC)이 흐르고, 수도꼭지(UI)를 틀면 나오는 구조.

### 캠 연동 시나리오

```
아이폰(카메라) ──Continuity Camera──→ 아이맥(영상소스)
                                        │
                                   테일스케일 P2P
                                        │
                                     4060(수신/처리)
```

또는

```
아이폰(카메라) ──테일스케일 직결──→ 맥/4060(수신)
```

### 레이턴시 벤치마크 (WebRTC P2P 기준)

| 구간 | 지연 |
|------|------|
| 카메라 캡처 | ~15ms |
| 인코딩 | 5~15ms |
| 네트워크 전송 (P2P, 같은 도시) | 5~30ms |
| 디코딩 + 버퍼 | 10~50ms |
| 화면 렌더링 | 8~16ms |
| **총 glass-to-glass** | **약 100~250ms** |

테일스케일 추가 지연: 1~3ms (P2P 직결 시). 영상통화 수준으로 시연/대화에 문제 없음.

## 4. 리스크 점검 결과

### 구조적 리스크 없음

| 항목 | 심각도 | 결론 |
|------|--------|------|
| 네트워크 순단 (5G↔WiFi) | - | 모든 영상 서비스 공통. 고정 환경에서는 문제 없음 |
| 배터리 소모 | - | 줌/카톡 영상통화와 동일 수준 |
| 앱스토어 심사 | 낮음 | 테일스케일 분리, 몽코스는 일반 앱으로 심사 통과 |
| 통신사업 규제 | 낮음 | 부가통신사업 신고제 (법인 설립 시 처리) |
| 개인정보보호 | 낮음 | P2P 직결 = 서버에 데이터 안 지남. AI 분석 시에만 동의 |
| 보안 | 없음 | SRTP(WebRTC 강제) + WireGuard(테일스케일) 이중 암호화 |
| 통신사 차단 | 낮음 | 암호화 터널이라 식별 어려움. DERP 폴백 존재 |

## 5. 비용 구조

### 영상 통신 비용 ≈ 0원

```
WebRTC: 무료 (오픈소스)
테일스케일 P2P: 무료 (Personal 플랜 100대)
서버 트래픽: 없음 (P2P 직결)
시그널링 서버: 극소량 (연결 초기 핸드셰이크만, GCP 프리티어 가능)
```

카카오/줌은 중앙 서버 경유 → 사용자 증가 시 비용 폭증.  
몽코스는 P2P → 사용자 10만이어도 영상 통화 비용 ≈ 0원.

## 6. 온디바이스 AI 아키텍처

### 3B(클라이언트) + 70B(서버) 하이브리드

```
[클라이언트 — 3B]              [본사 — 70B, 5090 x2]
폰/노트북에 상주                사무실 상시 가동
즉각 반응, 1차 분류/판단        복잡 추론, 이미지 생성
오프라인 기본 기능 유지          클라우드 API 비용 제로
             ←── 테일스케일 P2P ──→
```

### 3B가 현재 온디바이스 최적인 근거

- Apple Intelligence 온디바이스 = 3B
- Meta Llama 3.2 모바일 = 1B/3B
- Mistral Ministral 3B = 폰에서 500ms 이내 응답
- 4bit 양자화 시 메모리 ~1.5GB (아이폰 구동 적정)
- 2026년 기준 3B 성능이 작년 7B 수준 도달

### 비용 구조

- 3B 추론 = 사용자 디바이스 부담 (몽코스 비용 0)
- 70B 추론 = 5090 전기세만 (클라우드 API 0)
- Opus급 판단 필요 시에만 클라우드 선별 사용

## 7. 몽코스 제품 정체성

### 앱이 아니라 에이전트

- 버튼 10개 나열 = 앱
- 맥락 보고 알아서 꺼내줌 = **에이전트**

### 핵심 UX

> "이 친구 너무 편해. 왜 딱 맞는 걸 척척 해주지?"

영상 연동, 사진 동기화, AI 분석이 별개 기능이 아니라 **같은 파이프에서 AI 판단으로 나오는 것**. 사용자는 기능 목록을 탐색하지 않는다.

### 채팅방에 눈 다는 것

```
[현재 AI 챗]
대화 → 멈춤 → 촬영 → 파일탐색 → 업로드 → 대화 재개

[몽코스 목표]
대화하면서 "이거 봐" → 캠 토글 ON → AI가 보고 있음 → 대화 계속
```

### 무전기 모델 (카카오 모델 아님)

```
카카오: 내 폰 → 카카오 서버 → 상대 폰 (중앙 통제)
몽코스: 내 폰 ↔ 상대 폰 (P2P 직결, 중앙 없음)
```

인프라를 제공하지 않는다. 사용자의 디바이스가 곧 인프라.

## 8. 광고 전략 — 심사관용 핵심 논리

### K-pop 로드맵 = MONKOS 로드맵

1. **빅테크가 안 보는 시장에서 먼저 깐다** — 테헤란, 자카르타, 호치민, 울란바토르 (CPM 서울의 1/10)
2. **시그널이 뜨면 집중타격** — 초기 ROI는 매출 회수가 아니라 시장 검증
3. **기술이 이걸 가능하게 한다** — Imagen 4로 이미지 생성 비용 ≈ 0, 10개 도시 현지화 콘텐츠 무한 생산

### 예상 질문

- "왜 미국/유럽이 없나?" → 의도적. 변방에서 볼륨 만들면 메인스트림이 끌려옴.
- "AI 모델이 수익 내나?" → Phase 1은 시장 검증. 성장 곡선이 투자 근거.
- "경쟁사 차별점?" → Rozy는 이미지 1장에 수백만 원, 우리는 수 원.

## 9. 큰 그림 (내부 참조용, 심사관 비공개)

리니지 같은 가상세계. 게임이 아니라 실사.
