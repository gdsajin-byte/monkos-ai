- "고개를 조금 왼쪽으로", "턱을 살짝 당기세요" 등 실시간 가이드
- 정해진 규격(여권/이력서 등)을 systemInstruction에 넣으면 맥락 완성
- 실시간 카메라 피드 → AI 가이드 → 촬영자가 바로 조정
- monk.kr 포토랩(소소)과 직접 연결되는 기능
- 응답 지연 ~5초도 촬영 가이드엔 적합

**결론:**
- 오늘 핵심 성과 = **파이프가 뚫렸다** (카메라 → AI → 실시간 피드백)
- 1차 활용처: **증명사진 촬영 도우미** (소소 포토랩 연계)
- 2차 활용처: 프레젠테이션 보조 (맥락 주입 설계 후)

**잔여 과제:**
- 연결 안정성 (P2P 끊김 빈번 → 재연결 로직 보강)
- Gemini 세션 타임아웃 (Live API 제한 확인)
- systemInstruction 동적 교체 (용도별 프리셋)

### [14:18] P2P 안정성 분석

**결론: P2P 끊김 대부분 개발 환경 아티팩트**
- 서버 재시작, 브라우저 2중 접속 등이 원인 → 실제 WebRTC 문제 아님
- 벤치마크 원본: RTT 7ms, 패킷 손실 0% → P2P 자체는 안정적
- Tailscale이 NAT/방화벽 처리 → TURN 서버 불필요

**보강 필요 항목:**
- 시그널링 안정성 (재연결, 중복 등록 방지)
- ICE restart (네트워크 전환 대응)
- heartbeat (연결 상태 모니터링)

### [14:40] Photo Coach 앱 구현 (A/B 비교 테스트)

**핵심 개념 정리:**
- **Imagen 3.0 (i2i)이 증명사진 생성 엔진** — 변하지 않음
- **Gemini Live = 보조 역할**: 촬영 코칭(입구) + QC 검증(출구)
- **A/B 질문**: Gemini Live가 입출구를 잡으면 최종 품질이 얼마나 올라가는가?

**A/B 설계:**
- 앱 A: Imagen 3.0 단독 (기존 `MONK_kr/ai_lab/photolab/`)
- 앱 B: Gemini Live + Imagen 3.0 (`apps/photo-coach/`)

**구현:**
```
apps/photo-coach/
├── server.js    ← Gemini Live 코칭 + Imagen 3.0 프록시 + Gemini QC
├── index.html   ← 3단계 UI (코칭 → 촬영 → 생성+QC)
├── package.json
├── cert.pem → 심링크 (monk-cam)
└── key.pem  → 심링크 (monk-cam)
```

**server.js 3가지 역할:**
- a) Gemini Live 중계 (Vertex AI, `gemini-2.0-flash-live-preview-04-09`)
- b) Imagen 3.0 프록시 (`@google/genai` SDK, `gemini-3-pro-image-preview`)
- c) Gemini QC (`gemini-2.0-flash`, 원본 vs 생성물 비교)

**API Key 구조:**
- Gemini Live: Vertex AI ADC 인증 (프로젝트 monkos)
- Imagen + QC: `apps/imagen3/backend/.env`의 GEMINI_API_KEY 공유 (Google AI Studio)

**디버깅:**
- Gemini Live 토큰 쪼개짐 → 응답 버퍼링 (turnComplete 또는 600ms 무입력 시 플러시)
