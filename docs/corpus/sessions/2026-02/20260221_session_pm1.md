### 조사 과정 — 가설 수립과 반증의 연속

**가설 1: getUserMedia max constraint 부재로 4K 입력**
- 2/17에 `ideal: 1024, max: 1280` 구현 → 카메라 오류 발생 → 720×960 원복 (커밋 `b1e1664`)
- 원복 후 재적용 안 됨, MPA 분리 시에도 누락
- **반증**: Safari iOS는 getUserMedia를 720p로 하드캡 (Apple Developer Forums 확인). max constraint 유무와 무관

**가설 2: Gemini API 리전 차단 (CF Function 엣지 IP)**
- 에러 메시지: `API 400: User location is not supported for the API use.`
- CF Function이 아시아 엣지에서 Gemini API 직접 호출 → 리전 차단?
- **반증**: 작가님 iPhone(같은 CF Function 경로)에서는 성공

**가설 3: 이미지 크기 차이 (센서별 JPEG 압축률)**
- Pro Max의 더 좋은 센서가 같은 720p에서도 더 큰 JPEG?
- MAX_CAPTURE_SIZE 720→512, captureQuality 0.8→0.6으로 축소 → 배포
- **반증**: 작가님 "지금 맥스와 내가 동일하게 720~960으로 입력되는데 차단된거다"

**가설 4: 네트워크(통신사) 차이**
- 작가님: "한송이가 아까 성공한건 monkos.ai(Cloud Run)로 들어가서 79버전이었던 것"

- monk.kr(CF Pages/Function) → 셀룰러에서 실패, Wi-Fi에서 성공

### 확정 원인

**LG U+ 셀룰러 → CF Function → Gemini API 경로에서만 400 에러 발생.**

- CF Workers/Pages의 fetch는 엣지에서 실행됨
- 셀룰러 통신사(LG U+)의 네트워크를 타면 CF 엣지 라우팅이 달라짐
- 특정 CF PoP(또는 CF PoP의 outbound IP 대역)에서 Google이 `User location not supported` 반환
- Cloud Run(us-central1)은 항상 미국 IP로 나가므로 통신사 무관하게 통과
