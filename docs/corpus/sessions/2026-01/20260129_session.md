## 3. GCS 버킷 생성

### 문제

기존 `gs://monk-ai-images` 버킷이 존재하지 않음.

### 해결

```bash
# 버킷 생성
gsutil mb -p monkos -c STANDARD -l us-central1 gs://monk-ai-images

# 디렉토리 구조 생성
echo "MONKOS Image Storage" | gsutil cp - gs://monk-ai-images/generated/.keep
```

**생성 완료:**
- 버킷: `gs://monk-ai-images/`
- 리전: us-central1
- 클래스: STANDARD
- 디렉토리: `generated/` 준비

## 4. Cloud Run 배포

### 서비스 계정 생성

```bash
gcloud iam service-accounts create monk-image-engine \
  --display-name="MONK Image Engine Service Account" \
  --project=monkos
```

**생성된 계정:**
- `monk-image-engine@monkos.iam.gserviceaccount.com`

### 권한 부여

1. **Vertex AI 사용 권한**
   ```bash
   gcloud projects add-iam-policy-binding monkos \
     --member="serviceAccount:monk-image-engine@monkos.iam.gserviceaccount.com" \
     --role="roles/aiplatform.user"
   ```

2. **Cloud Storage 권한**
   ```bash
   gcloud projects add-iam-policy-binding monkos \
     --member="serviceAccount:monk-image-engine@monkos.iam.gserviceaccount.com" \
     --role="roles/storage.objectAdmin"
   ```

3. **Cloud Build 권한** (배포 중 추가 필요 발견)
   ```bash
   # 사용자 계정
   gcloud projects add-iam-policy-binding monkos \
     --member="user:gdsajin@gmail.com" \
     --role="roles/cloudbuild.builds.editor"

   # Cloud Build 서비스 계정
   gcloud projects add-iam-policy-binding monkos \
     --member="serviceAccount:933456016842@cloudbuild.gserviceaccount.com" \
     --role="roles/storage.admin"
   ```

## 학습 포인트

### 1. ADC (Application Default Credentials)
- Cloud Run에서는 서비스 계정이 자동으로 인증됨
- JSON 키 파일 불필요 (보안 강화)
- 환경 변수로 프로젝트 ID만 전달

### 2. Cloud Build 권한
- 사용자 계정 + 서비스 계정 모두 권한 필요
- Storage Admin 권한 필수 (빌드 컨텍스트 저장)

### 3. Docker 최적화
- package-lock.json 없으면 `npm install` 사용
- 프로덕션 의존성만 설치로 이미지 경량화
- 헬스 체크로 안정성 향상

### 4. 배포 자동화
- deploy.sh로 5단계 자동화
  1. 프로젝트 설정
  2. API 활성화
  3. Docker 빌드
  4. Cloud Run 배포
  5. URL 출력
