# MONKOS 퍼널 UI 기획안 v5 — 쌍아 전달

> **작성**: 철창이 (웹UI 전략/디자인)
> **승인**: 신작가님
> **일시**: 2026-03-02
> **첨부**: `MONKOS_퍼널_프로토타입.jsx` (1,266줄, React 프로토타입)

---

## 1. 이 문서의 목적

이 기획안은 **프로토타입 JSX 파일과 함께** 읽어야 한다.
프로토타입은 "어떻게 생겼는지"를 보여주고, 이 문서는 **"왜 이렇게 만들었는지"**를 설명한다.

쌍아는 이 문서를 기반으로 막내들에게 페이지별 지시서를 발행한다.
각 페이지는 실제 앱에서 별도 라우트 + 별도 엔진으로 동작하며,
프로토타입은 하나의 JSX에 전체 흐름을 시뮬레이션한 것이다.

---

## 2. 전체 퍼널 구조 (컨베이어 벨트)

```
[1p] 규격 선택
  ↓
[2p] 성별 + 연령
  ↓
[3p] 스타일 선택 (의상/헤어/배경)
  ↓
[4p] CONFIRM (요약 + 코칭멘트)
  ↓
[촬영/업로드] ← 프로토에 없음. 실제 앱 카메라/갤러리
  ↓
[AI 생성] ← 프로토에서는 10c 차감만 시뮬. 실제는 AI 엔진 가동 + 대기 화면
  ↓
[프리뷰] 전후비교(워터마크) + 규격 완성본
  ↓ (잔고 부족 시)
[충전 화면]
  ↓
[다운로드] 70c 차감
  ↓
[엔딩] 셀레브레이션 + 업셀 + 발급보장
```

**절대 원칙**: 이 벨트에 분기 없음. 중간에 끊기는 경로 없음. 유저는 직선으로만 흐른다.

## 3. 페이지별 설계 의도 + 구현 명세

---

### 3-1. [1p] 규격 선택

**프로토 위치**: 약 L502~L558

**설계 취지**:
- 유저가 처음 마주하는 화면. 선택지를 2개로 극한 축소.
- "여권/신분증"과 "증명사진" 두 카드만 존재. 이 선택이 이후 전체 트리(배경 고정 여부, 코칭 멘트, 발급 보장 표시)를 결정한다.
- SOON 카드(비자, SNS)는 삭제 확정. 1단계에서 유저를 혼란시키지 않는다.
- 비자·SNS·기타 규격은 "몽크사진관에서 상담해 드려요 → Telegram" 안내로 대체.

**카드 정보**:

| 카드 | spec 표시 | desc | warn |
|------|-----------|------|------|
| 🛡️ 여권/신분증 | 3.5×4.5cm · 흰색 배경 | 여권발급·운전면허·주민등록증·외국인등록증 등 | ⚠️ 눈썹·이마 노출 필수 · 무표정 정면 |
| 📋 증명사진 | 3×4cm 반명함 · 배경 컬러 선택 가능 | 이력서·학생증·사원증·원서접수 등 | 💡 용도에 맞는 의상 착용 · 깔끔한 헤어 정돈 |

**badge**: 여권 카드에 "발급 보장" 뱃지 표시 — 이게 경쟁사 대비 몽크의 핵심 차별점이므로 1p부터 인지시킨다.

**전환**: format 선택 후 [다음 →] → 2p

**상태 저장**: `format` = `"passport"` | `"id"`

---

### 3-2. [2p] 성별 + 연령

**프로토 위치**: 약 L560~L612

**설계 취지**:
- 성별(2택) + 연령(4택)을 한 화면에서 처리.
- **연령 선택이 이후 스타일 옵션 분기의 핵심 키**. 영유아/어린이는 의상변경(색상만), 중고생/성인은 캐주얼/정장 풀옵션.
- 연령 카드의 warn 멘트가 **규격(format)에 따라 분기**한다:

| 연령 | 여권/신분증 warn | 증명사진 warn |
|------|-----------------|--------------|
| 👶 영유아 | 부모님이 안고 셀카 촬영 | 부모님이 안고 셀카 촬영 |
| 🧒 어린이 | 깔끔한 의상 · 정면 응시 유도 | 깔끔한 의상 · 정면 응시 유도 |
| 🎒 중고생 | 눈썹·이마 노출 · 무표정 정면 | 헤어·의상 정돈 · 교복 직접 착용 |
| 🙂 성인 | 눈썹·이마 노출 · 무표정 정면 | 헤어·의상 정돈 · 좋은 인상의 표정 |

**왜 이렇게?**: 여권은 규정이 엄격해서 "무표정 정면"이 필수. 증명사진은 자유도가 있어서 "좋은 인상"을 권할 수 있다. 이걸 2p에서 미리 알려주면 3p 스타일 선택과 촬영 시 실수를 줄인다.

**전환**: gender + age 선택 후 [다음 →] → 3p

**상태 저장**: `gender` = `"f"` | `"m"`, `age` = `"baby"` | `"child"` | `"teen"` | `"adult"`

---

### 3-3. [3p] 스타일 선택 ⭐ 핵심 페이지

**프로토 위치**: 약 L614~L913

**설계 취지**:
- **한 화면에서 의상/헤어/배경을 모두 처리**. 페이지를 분리하지 않는다.
- 각 항목은 기본값 "그대로"로 설정. 유저가 건드리지 않으면 디폴트로 통과.
- [변경 >] 누르면 같은 화면 안에서 옵션이 펼쳐지는 구조 (아코디언).
- **이 구조가 곧 AI 프롬프트 빌딩 순서**. 퍼널 한 단계 = 프롬프트 한 줄.

**조건부 표시 로직**:

```
영유아/어린이 + 여권:   의상만 표시
영유아/어린이 + 증명:   의상 + 배경
중고생/성인 + 여권:     의상 + 헤어
중고생/성인 + 증명:     의상 + 헤어 + 배경 (풀코스)
```

**의상 옵션 (연령별 완전 분기)**:

#### 영유아/어린이

| 선택 | 세부 |
|------|------|
| 그대로 | — |
| 의상변경 | 컬러: 하늘색, 핑크, 레몬, 그린 |

- 프롬프트: 색상만 지정하면 AI가 아이다운 옷으로 처리
- ⚠️ 여권/신분증은 흰색 의상 불가 경고 표시

#### 중고생/성인

| 선택 | 세부 |
|------|------|
| 그대로 | — |
| 캐주얼 | 컬러: 베이지, 블루, 와인, 그린 |
| 정장 | 수트(네이비✓/브라운/그레이/블랙) + 셔츠(화이트✓/연블루/연핑크/연베이지) + 타이(노타이/네이비✓/와인/블랙) + 무늬(민✓/스트라이프) |

- 정장 디폴트: 네이비 수트 + 화이트 셔츠 + 네이비 민타이 (가장 무난한 조합)
- ⚠️ 여권/신분증은 화이트 셔츠 불가 경고
- 노타이 선택 시 무늬 선택 자동 숨김

**헤어 옵션** (중고생/성인만):

| 선택 |
|------|
| 그대로 ✓ |
| 깔끔 정리 |
| 올림머리 |

**배경 옵션** (증명사진만):

| 선택 |
|------|
| 흰색 ✓ |
| 회색 |
| 파랑 |
| 베이지 |

여권/신분증은 배경 흰색 고정. "🎨 여권/신분증 배경은 흰색으로 고정됩니다" 안내 표시.

**프롬프트 스택 예시 (이 순서가 핵심)**:

```
[1p] 여권             → "증명사진, 3.5×4.5"
[2p] 여성 · 성인      → + "한국 여성 성인"
[3p] 정장             → + "네이비 수트, 화이트 셔츠, 네이비 민타이"
[3p] 깔끔정리         → + "깔끔한 헤어"
[3p] 흰색 배경        → + "흰색 배경"
+ [고정 프롬프트]      → 카메라 세팅, 조명 세팅, 공간 세팅 (유저 안 보임)
```

이 고정 프롬프트가 10년 사진관 노하우. 유저에게 보이지 않지만 품질의 핵심이며, 발급 보장이 가능한 이유이다.

**상태 변수**:

```javascript
clothing:      "default" | "change" | "casual" | "suit"
clothingColor: null | "skyblue" | "pink" | "lemon" | "green" | "beige" | "blue" | "wine"
suitColor:     "navy" | "brown" | "gray" | "black"
shirtColor:    "white" | "lightblue" | "lightpink" | "lightbeige"
tieColor:      "notie" | "navy" | "wine" | "black"
tiePattern:    "solid" | "stripe"
hair:          "default" | "tidy" | "updo"
bgColor:       "white" | "gray" | "blue" | "beige"
styleEdit:     null | "clothing" | "hair" | "bg"  // 현재 펼쳐진 아코디언
```

**전환**: [다음 →] → 4p CONFIRM

### 3-4. [4p] CONFIRM

**프로토 위치**: 약 L915~L955

**설계 취지**:
- 유저가 선택한 모든 옵션을 한눈에 요약.
- 각 행에 [수정] 버튼 → 해당 페이지로 돌아가기 가능.
- 촬영 직전 마지막 코칭 멘트 표시 (연령×규격별 분기).

**코칭 멘트 분기**:

| 조건 | 멘트 |
|------|------|
| 영유아 | "아이를 안고 촬영해도 됩니다" |
| 어린이 | "정면을 바라보도록 유도해 주세요" |
| 여권 (중고생/성인) | "눈썹 · 이마가 보이도록 준비해 주세요" |
| 증명 (중고생/성인) | "좋은 인상의 표정으로 촬영해 주세요" |

**CTA 버튼 분기**:
- 잔고 10c 이상: `촬영 시작하기 → (10c)` → 10c 차감 후 프리뷰로 이동
- 잔고 부족: `크레딧 부족 · 충전하기` → 충전 화면으로 이동

---

### 3-5. [촬영/업로드] + [AI 생성] — 프로토 미포함

**프로토에 없는 구간**. 실제 앱에서:
1. 카메라 촬영 또는 갤러리 업로드
2. AI 코칭 (얼굴 위치, 조명 가이드)
3. 생성 버튼 → 10c 차감 → AI 엔진 가동
4. 대기 화면 (로딩 애니메이션)
5. 생성 완료 → 프리뷰로 전환

이 구간의 UI는 기존 구현을 유지하되, 10c 차감 시점과 에러 핸들링(생성 실패 시 크레딧 환불)을 명확히 해야 한다.

---

### 3-6. [프리뷰]

**프로토 위치**: 약 L900~L1020 (정리 후 기준)

**설계 취지**:
- **과금 전환의 핵심 페이지**. "보여주되 못 가져가게" 구조.
- 전후 비교(BEFORE/AFTER)에 워터마크 오버레이.
- 규격 완성본 디스플레이: 선택한 규격/의상/헤어 정보 요약.
- 다운로드 버튼 문구: **"📥 워터마크 없는 증명사진 다운로드 — 70c"** — "고화질"이 아니라 "워터마크 없는"이 과금 포인트를 명확히 전달.

**셀레브레이션**: 상단에 ✨ 펄스 애니메이션 + "고객님의 증명사진이 완성되었습니다" 그라디언트 텍스트.

**잔고별 분기 (분기이지만 경로는 하나)**:

```
잔고 ≥ 70c:
  [📥 워터마크 없는 증명사진 다운로드 — 70c]  ← 활성 버튼, 클릭 시 -70c → 엔딩

잔고 < 70c:
  [📥 워터마크 없는 증명사진 다운로드 — 70c]  ← 비활성(회색)
  ┌──────────────────────────────┐
  │  크레딧이 부족합니다           │
  │  현재 0c / 필요 70c          │
  └──────────────────────────────┘
  [충전하러 가기 →]  ← 유저가 직접 누름
```

**왜 바로 충전으로 안 보내나?**: 기존에는 잔고 부족 시 자동으로 충전 화면 이동이었는데, 유저가 맥락을 잃는다. "크레딧이 부족합니다" 메시지를 먼저 보여주고, 유저가 스스로 [충전하러 가기]를 누르면 위화감이 줄어든다.

### 3-7. [충전 화면]

**프로토 위치**: 약 L760~L900 (인라인 구현)

**설계 취지**:
- 오버레이 모달이 아닌 **풀 페이지**. 모달로 띄우면 Phone 안에서 콘텐츠가 안 보이는 문제가 있었고, 충전은 중요한 전환점이므로 페이지 급으로 대우.
- 상단에 잔고 + 부족 크레딧 한눈에 표시.
- 기축 안내: "💡 10c = $1 (≈₩1,450) · 생성 10c · 다운로드 70c · **1회 = 80c**"

**상품 카드 구조 (v2.1 과금체계 반영)**:

| 상품 | 크레딧 | 보너스 | 총 지급 | 정가(취소선) | 할인가 | 실질 할인율 | 태그 |
|------|--------|--------|---------|-------------|--------|-----------|------|
| 단품 | 70c | +10c | 80c | ~~₩10,150~~ | ₩9,900 | 실질 14% | [추천] |
| 패키지2 | 140c | +20c | 160c | ~~₩20,300~~ | ₩18,900 | 실질 19% | — |
| 패키지4 | 280c | +60c | 340c | ~~₩40,600~~ | ₩34,900 | 실질 29% | ★BEST |

각 카드에 **장당 단가** 표시 → 패키지의 가성비를 직관적으로 비교 가능.

**소액 충전**: 10c = ₩1,450 (앵커 가격, 할인 없음, 보너스 없음). 부족분만 채울 때 사용. 앵커 역할이므로 할인하지 않는다.

**가격 표시 원칙**:
- 취소선 = 10c=$1 기준 정가 (달러 환산 역산)
- 할인가 = 각국 심리가격대 (실결제 금액)
- 보너스 = 상품과 별도 지급되는 혜택

**결제 수단**: 토스페이먼츠 · 카카오페이 · 네이버페이 (하단 안내)

**크레딧 표기**: UI에서는 `c` 사용 (10c, 70c). 동전 로고에만 `Cr` 각인. 읽기는 "크레딧".

### 3-8. [엔딩 페이지]

**프로토 위치**: 약 L1020~L1180

**설계 취지**:
- 유저 여정의 마지막. 만족감 극대화 + 자연스러운 업셀 + 재방문 엔진.
- 셀레브레이션 → 다운로드 → 업셀 → 발급보장 순서가 중요하다.

**구조 (위에서 아래 순서)**:

```
🎉 (펄스 애니메이션)
"증명사진이 완성되었습니다!"
"아래에서 다운로드해 주세요"

[완성본 이미지] — 규격에 따라 "여권 규격 35×45mm" 또는 "증명사진 3×4cm 반명함" 표시
[📥 다운로드] — 그라디언트 버튼

[📸 전후 비교 저장 · 무료] — 갤러리 저장, SNS 이벤트 소재로도 활용

──────────── 구분선 ────────────

[내 크레딧: Xc]

📸 풀샷 원본 받기 — 20c
  "크롭되지 않은 풀 원본 사진"
```

**발급 보장이 최하단인 이유**: 대부분의 유저는 발급이 통과된다. 반려는 소수 케이스. 상단에 놓으면 불안감을 줄 수 있고, 최하단에 놓으면 "혹시 반려되면 여기서" 안전망 느낌.

## 6. 크레딧 플로우 시뮬레이션

### 시나리오 A: 첫 방문 유저 (보너스 10c 보유)

```
가입 보너스         +10c  → 잔고 10c
CONFIRM 촬영 시작   -10c  → 잔고 0c
프리뷰 도착         잔고 0c < 70c → "크레딧이 부족합니다"
충전 (단품 70c)     +80c  → 잔고 80c  (70c + 10c 보너스)
다운로드            -70c  → 잔고 10c
엔딩                잔고 10c → 풀샷(20c) 부족, 소액 충전 유도 가능
```

### 시나리오 B: 패키지4 구매 유저

```
가입 보너스         +10c  → 잔고 10c
충전 (패키지4)      +340c → 잔고 350c  (280c + 60c 보너스)
1회차 촬영+DL       -80c  → 잔고 270c
2회차               -80c  → 잔고 190c
3회차               -80c  → 잔고 110c
4회차               -80c  → 잔고 30c
잔여 30c → 풀샷(20c) 1회 + 10c 남음 → 재방문 엔진
```

## 7. 프로토 → 실제 앱 변환 시 주의사항

### 프로토에 있지만 실제 동작이 다른 것

| 프로토 동작 | 실제 앱 동작 |
|------------|-------------|
| CONFIRM → 10c 차감 → 바로 프리뷰 | CONFIRM → 촬영/업로드 → AI 생성(10c) → 대기 → 프리뷰 |
| 충전 상품 클릭 → 즉시 크레딧 추가 | 충전 상품 클릭 → PG 결제 → 성공 시 크레딧 추가 |
| 네비 탭으로 자유 이동 | 실제는 순방향만 가능 (뒤로가기 제한) |

### 프로토에 없지만 실제 필요한 것

| 항목 | 설명 |
|------|------|
| 로그인 게이트 | 1p 이전, 촬영실 진입 시 소셜 원탭 로그인 + 10c 셀레브레이션 |
| 카메라 촬영 UI | 촬영 가이드 오버레이, AI 코칭 |
| AI 생성 대기 화면 | 로딩 애니메이션, 예상 시간 |
| 생성 실패 핸들링 | 크레딧 환불 + 재시도 |
| PG 결제 연동 | 토스/레몬스퀴지/코모주 |
| 다국어 전환 | KR/JP/EN 텍스트 분기 |
| UTM 태깅 | 랜딩 유입 경로 추적 |

## 9. 쌍아 지시서 발행 가이드

프로토타입 JSX를 기준으로 막내들에게 지시할 때:

```
[막내 A] 1p 규격 선택 페이지
  → 프로토 L502~L558 참조
  → format 상태 관리 + 텔레그램 딥링크(start=custom)

[막내 B] 2p 성별+연령 페이지
  → 프로토 L560~L612 참조
  → warn 멘트 format 분기 주의

[막내 C] 3p 스타일 선택 페이지
  → 프로토 L614~L913 참조 (가장 큰 페이지)
  → 연령×규격 조건부 렌더링 로직이 핵심
  → 상태 변수 8개 관리

[막내 D] 4p CONFIRM + 충전 화면
  → 프로토 L915~L1097 참조
  → 충전 상품 데이터 + PG 연동

[막내 E] 프리뷰 + 엔딩
  → 프로토 L1099~L1180 참조
  → 워터마크 처리 + 크레딧 차감 로직
  → 텔레그램 딥링크 5개 매핑
```

각 막내에게 해당 프로토 구간 + 이 기획안의 해당 섹션을 함께 전달할 것.
프로토는 "이렇게 생겨야 한다", 기획안은 "이렇게 해야 하는 이유"를 담고 있다.
