# MONKOS 에러 핸들링 시나리오 설계서

> **2026-03-02 | 철창이 → 쌍아 전달용**
> **선행 근거**: 교차검증 리포트 §7-4 #3 "에러 핸들링 시나리오 설계 → 🚨 설계 필요"
> **적용 범위**: 컨베이어 벨트 전체 (STAGE 1~6)

---

## 0. 설계 원칙

1. **컨베이어 벨트를 멈추지 않는다** → 에러가 나도 유저를 벨트 위에 유지
2. **크레딧은 서비스 완료 시에만 확정 차감** → 실패하면 무조건 환불
3. **유저 탓하지 않는다** → "다시 시도해 주세요"가 아니라 "처리 중 문제가 발생했습니다"
4. **자동 복구 우선, 수동 CS 최후** → 재시도 → 자동환불 → 텔레그램 CS 순서
5. **톤**: 전문 사진관 톤 유지. 친근/캐주얼 금지. 간결하고 사무적.

## 1. 에러 분류 체계

### 1-1. 과금 지점별 에러 맵

```
[STAGE 1] 로그인 게이트
  ├─ E1: 소셜 로그인 실패
  └─ E2: 가입 보너스 10c 지급 실패

[STAGE 3] AI 생성 (10c 차감 지점)
  ├─ E3: 생성 요청 전 잔고 부족 → 에러가 아닌 유저 분기
  ├─ E4: 10c 차감 성공 → AI 생성 실패 → 환불 필수
  ├─ E5: 10c 차감 성공 → AI 생성 타임아웃 → 환불 필수
  └─ E6: 10c 차감 자체 실패 (서버 통신 오류)

[STAGE 4] 프리뷰 → 충전
  ├─ E7: PG 결제 연동 실패 (PG 연결 오류)
  ├─ E8: PG 결제 중 유저 이탈/취소
  ├─ E9: PG 결제 성공 → 크레딧 미반영 → 가장 위험
  └─ E10: PG 결제 실패 (카드 한도, 잔액 부족 등)

[STAGE 5] 다운로드 (70c 차감 지점)
  ├─ E11: 70c 차감 성공 → 다운로드 실패 → 환불 필수
  └─ E12: 70c 차감 자체 실패

[STAGE 6] 엔딩 (부가)
  ├─ E13: 풀샷 원본 20c 차감 → 다운로드 실패
  └─ E14: 규격 추가 10c 차감 → 변환 실패
```

### 1-2. 심각도 분류

| 등급 | 정의 | 해당 에러 | 자동 복구 |
|------|------|----------|----------|
| **🔴 Critical** | 돈이 나갔는데 서비스 미제공 | E9 | 자동환불 + CS 알림 |
| **🟡 Major** | 크레딧 차감 후 서비스 실패 | E4, E5, E11, E13, E14 | 즉시 자동환불 + 재시도 |
| **🟢 Minor** | 기능 실패, 금전 영향 없음 | E1, E2, E6, E7, E8, E10, E12 | 재시도 안내 |

## 2. 에러별 상세 시나리오

---

### E1: 소셜 로그인 실패

**발생 지점**: STAGE 1 로그인 게이트
**원인**: Google/Kakao/LINE OAuth 서버 오류, 네트워크 끊김
**크레딧 영향**: 없음 (로그인 전)
**심각도**: 🟢 Minor

**유저 화면**:
```
┌──────────────────────────┐
│  로그인에 실패했습니다     │
│                          │
│  네트워크 연결을 확인하고   │
│  다시 시도해 주세요       │
│                          │
│  [다시 로그인하기]        │
│  [다른 방법으로 로그인]    │
└──────────────────────────┘
```

**처리 로직**:
1. OAuth 콜백 에러 감지
2. 에러 메시지 표시 (로그인 게이트 화면 유지)
3. [다시 로그인하기] → 같은 소셜 재시도
4. [다른 방법으로 로그인] → 소셜 선택 화면으로 복귀

**다국어**:
| KR | JP | EN |
|----|----|----|
| 로그인에 실패했습니다 | ログインに失敗しました | Login failed |
| 다시 로그인하기 | 再度ログイン | Try again |

---

### E2: 가입 보너스 10c 지급 실패

**발생 지점**: STAGE 1 로그인 성공 직후
**원인**: 크레딧 서버 통신 오류
**크레딧 영향**: 10c 미지급 (유저는 0c 상태)
**심각도**: 🟢 Minor

**처리 로직**:
1. 로그인 자체는 성공 → 유저를 벨트 위에 유지
2. 보너스 지급 실패 시 백그라운드 재시도 (최대 3회, 간격 2초)
3. 3회 실패 시: 서버에 `pending_bonus` 플래그 저장
4. 다음 API 호출 시 자동 재지급 시도
5. **유저에게 에러 메시지를 보여주지 않음** → 셀레브레이션만 스킵하고 퍼널 진행
6. 보너스 미지급 상태로 생성 시도 시 잔고 부족 → 충전 화면에서 자연스럽게 처리됨

**왜 에러를 안 보여주나?**: 10c는 가입 선물. 이걸 위해 유저 사정을 멈추면 안 됨. 백그라운드에서 해결하고, 최악의 경우 유저는 충전 화면에서 처리.

---

### E4: AI 생성 실패 → 환불 필수

**발생 지점**: STAGE 3 → 10c 차감 성공 후 AI 엔진 에러
**원인**: Vertex AI API 에러, 이미지 처리 파이프라인 실패, 얼굴 미인식
**크레딧 영향**: 10c 차감됨 → **즉시 환불 필수**
**심각도**: 🟡 Major

**유저 화면**:
```
┌──────────────────────────┐
│  ⚠️                      │
│  사진 생성에 실패했습니다   │
│                          │
│  10c가 자동으로 환불됩니다 │
│  현재 크레딧: Xc          │
│                          │
│  [다시 촬영하기]          │
│  [💬 문의하기 →]          │
└──────────────────────────┘
```

**처리 로직**:
1. AI 엔진 에러 응답 수신
2. **서버에서 즉시 10c 환불** (클라이언트 요청이 아닌 서버 자동)
3. 클라이언트에 환불 완료 + 현재 잔고 전달
4. 에러 화면 표시
5. [다시 촬영하기] → 촬영/업로드 화면(STAGE 2)으로 복귀
6. [문의하기] → `t.me/monkos_bot?start=help`

**서버 로직 핵심**:
```
트랜잭션:
  1. credit -= 10  (차감)
  2. AI 생성 요청
  3-a. 성공 → 프리뷰 이미지 반환
  3-b. 실패 → credit += 10 (환불) + 에러 코드 반환
```

**환불이 실패하면?**: 서버에 `pending_refund` 기록. 5분 간격 cron으로 재시도. 24시간 미해결 시 텔레그램 CS 팀에 자동 알림.

**다국어**:
| KR | JP | EN |
|----|----|----|
| 사진 생성에 실패했습니다 | 写真の生成に失敗しました | Photo generation failed |
| 10c가 자동으로 환불됩니다 | 10cは自動的に返還されます | 10c automatically refunded |
| 다시 촬영하기 | 再撮影する | Retake photo |

### E5: AI 생성 타임아웃 → 환불 필수

**발생 지점**: STAGE 3 → 10c 차감 성공 후 AI 응답 시간 초과
**원인**: Vertex AI 과부하, 네트워크 지연, 이미지 크기 과대
**크레딧 영향**: 10c 차감됨 → **환불 필수 (단, 실제 성공했을 수 있음)**
**심각도**: 🟡 Major

**유저 화면 (대기 중)**:
```
┌──────────────────────────┐
│                          │
│  [프로그레스 바 80%...]   │
│                          │
│  증명사진을 생성 중입니다  │
│  잠시만 기다려 주세요      │
│                          │
│  예상 시간: 약 30초       │
│                          │
└──────────────────────────┘
```

**유저 화면 (타임아웃 후)**:
```
┌──────────────────────────┐
│  ⚠️                      │
│  처리 시간이 초과되었습니다 │
│                          │
│  [다시 시도] → 무료       │
│  (크레딧이 차감되지 않습니다)│
│                          │
│  [💬 문의하기 →]          │
└──────────────────────────┘
```

**처리 로직**:
1. 클라이언트 타임아웃: **60초** (유저 체감 한계)
2. 타임아웃 시 서버에 상태 확인 요청 (`GET /api/idgen/status/{job_id}`)
3. 서버 응답이 "아직 처리 중" → 추가 30초 대기 후 재확인
4. 서버 응답이 "실패" 또는 2차 타임아웃 → 10c 환불 + 에러 화면
5. 서버 응답이 "성공" → 프리뷰로 정상 이동 (환불 없음)
6. [다시 시도] → 새 job 생성, **환불된 10c로 재차감** (유저에게 무료 느낌)

**핵심**: 타임아웃 ≠ 실패. 서버에서 실제로 성공했을 수 있으므로 job 상태를 반드시 확인한 후 환불 여부를 결정.

### E6: 크레딧 차감 자체 실패

**발생 지점**: STAGE 3 → 생성 버튼 클릭 시
**원인**: 크레딧 서버 통신 오류, 동시 요청 충돌
**크레딧 영향**: 차감 안 됨 (없음)
**심각도**: 🟢 Minor

**유저 화면**:
```
┌──────────────────────────┐
│  처리 중 문제가 발생했습니다│
│  잠시 후 다시 시도해 주세요│
│                          │
│  [다시 시도]              │
└──────────────────────────┘
```

**처리 로직**:
1. 차감 API 실패 감지
2. 자동 재시도 1회 (2초 후)
3. 2차 실패 시 에러 화면 표시
4. [다시 시도] → 같은 생성 요청 재시도
5. 유저는 같은 화면(CONFIRM or 촬영)에 머무름 → 벨트 이탈 없음

**원인**: 토스/레몬스퀴즈/코모주 서버 오류, SDK 로딩 실패
**크레딧 영향**: 없음 (결제 전)
**심각도**: 🟢 Minor

**유저 화면**:
```
┌──────────────────────────┐
│  결제 서비스 연결에        │
│  실패했습니다              │
│                          │
│  [다시 시도]              │
│  [다른 결제 수단]         │
└──────────────────────────┘
```

**처리 로직**:
1. PG SDK 초기화 실패 감지
2. [다시 시도] → 같은 PG 재연결
3. [다른 결제 수단] → 결제 수단 선택으로 복귀

### E8: PG 결제 중 유저 이탈/취소

**발생 지점**: STAGE 4 PG 결제 창 내
**원인**: 유저가 뒤로가기, PG 창 닫기, 취소 버튼
**크레딧 영향**: 없음 (결제 미완료)
**심각도**: 🟢 Minor (에러가 아닌 유저 행동)

**처리 로직**:
1. PG 콜백으로 취소/이탈 감지
2. 충전 화면으로 조용히 복귀 (에러 메시지 없음)
3. 유저가 원하면 다시 결제, 원하지 않으면 프리뷰로 돌아가기 가능
4. **"결제를 취소하셨습니까?" 같은 확인 팝업 절대 금지** → 유저 의사를 존중

---

### E9: PG 결제 성공 → 크레딧 미반영 → 가장 위험

**발생 지점**: STAGE 4 → PG에서 "결제 성공" 응답 후 크레딧 서버 반영 실패
**원인**: 웹훅 전달 실패, 크레딧 서버 다운, 네트워크 단절
**크레딧 영향**: **돈은 빠졌는데 크레딧이 안 들어옴** → 유저 관점 최악의 시나리오
**심각도**: 🔴 Critical

**유저 화면**:
```
┌──────────────────────────┐
│  ⚠️                      │
│  결제는 완료되었으나       │
│  크레딧 반영에 시간이      │
│  걸리고 있습니다           │
│                          │
│  최대 5분 내 자동 반영됩니다│
│                          │
│  반영되지 않으면:          │
│  [💬 CS 문의 →]           │
│                          │
│  결제번호: TXN-XXXXXX    │
└──────────────────────────┘
```

**처리 로직 (다중 안전장치)**:
1. PG "결제 성공" 콜백 수신
2. 크레딧 서버에 반영 요청
3. 실패 시 → 즉시 재시도 (최대 3회, 간격 5초)
4. 3회 실패 → `pending_payment` DB 기록 (PG 거래번호, 금액, 유저 ID, 상태)
5. 유저에게 안내 화면 표시 + 결제번호 제공
6. **서버 cron (1분 간격)**: `pending_payment` 테이블 스캔 → 미반영 건 재처리
7. **PG 웹훅 수신**: PG 측에서도 웹훅으로 결제 확인 → 이중 안전장치
8. **5분 초과 미해결**: 텔레그램 CS 팀에 자동 알림 (유저 ID + 거래번호 + 금액)
9. **CS 수동 처리**: 거래번호로 PG 대시보드 확인 → 수동 크레딧 지급

**절대 원칙**: 이 에러에서 유저에게 "다시 결제해 주세요"라고 절대 말하지 않는다. 돈은 이미 나간 상태.

**다국어**:
| KR | JP | EN |
|----|----|----|
| 결제는 완료되었으나 크레딧 반영에 시간이 걸리고 있습니다 | お支払いは完了しましたが、クレジットの反映に時間がかかっています | Payment completed, credits are being processed |
| 최대 5분 내 자동 반영됩니다 | 最大5分以内に自動反映されます | Auto-applied within 5 minutes |

---

### E10: PG 결제 실패 (카드 한도, 잔액 부족 등)

**발생 지점**: STAGE 4 PG 결제 과정
**원인**: 카드 한도 초과, 잔액 부족, 카드 정지, 3DS 인증 실패
**크레딧 영향**: 없음 (결제 미완료)
**심각도**: 🟢 Minor

**유저 화면**:
```
┌──────────────────────────┐
│  결제에 실패했습니다       │
│                          │
│  카드 정보를 확인하시거나  │
│  다른 결제 수단을          │
│  이용해 주세요            │
│                          │
│  [다시 시도]              │
│  [다른 결제 수단]         │
└──────────────────────────┘
```

**처리 로직**:
1. PG 에러 코드 수신
2. **구체적 사유를 절대 표시하지 않음** → "카드 한도 초과" 같은 건 개인정보
3. 일반적 안내만 제공
4. 충전 화면 유지 → 벨트 이탈 없음

---

### E11: 다운로드 실패 → 환불 필수

**발생 지점**: STAGE 5 → 70c 차감 성공 후 파일 다운로드 실패
**원인**: CDN 오류, 이미지 스토리지 접근 실패, 네트워크 끊김
**크레딧 영향**: 70c 차감됨 → **환불 또는 재다운로드 필수**
**심각도**: 🟡 Major

**유저 화면**:
```
┌──────────────────────────┐
│  ⚠️                      │
│  다운로드에 실패했습니다    │
│                          │
│  [다시 다운로드] → 무료   │
│  (추가 크레딧이 필요하지    │
│   않습니다)               │
│                          │
│  [💬 문의하기 →]          │
└──────────────────────────┘
```

**처리 로직**:
1. 다운로드 실패 감지 (HTTP 에러, 타임아웃)
2. **환불하지 않음** → 대신 다운로드 권한을 유지
3. `download_entitled: true` 상태를 서버에 저장
4. [다시 다운로드] → 같은 이미지 재다운로드 시도 (크레딧 미차감)
5. 3회 연속 실패 시 → 자동 환불(70c) + CS 안내
6. **세션 만료 후에도** 다운로드 권한은 유효 (24시간 이내)

**왜 즉시 환불이 아닌가?**: 이미지는 이미 생성되어 서버에 있음. 환불하면 유저가 처음부터 다시 해야 함. 다운로드만 재시도하는 게 유저 경험에 훨씬 좋음.

---

### E13: 풀샷 원본 다운로드 실패

**발생 지점**: STAGE 6 엔딩 페이지 → 20c 차감 후
**원인**: E11과 동일
**크레딧 영향**: 20c → E11과 같은 로직 (권한 유지 + 재다운로드)
**심각도**: 🟡 Major

**처리**: E11과 동일 구조. 금액만 20c.

---

### E14: 규격 추가 변환 실패

**발생 지점**: STAGE 6 엔딩 페이지 → 10c 차감 후
**원인**: 크롭 엔진 에러, 규격 DB 미스매치
**크레딧 영향**: 10c → 즉시 자동환불
**심각도**: 🟡 Major

**처리 로직**:
1. 변환 실패 시 10c 즉시 환불
2. 에러 메시지 + [다시 시도] + [문의하기]
3. 규격 추가는 보류 항목(1단계 미구현)이므로 현재는 설계만 준비

## 3. 네트워크 공통 처리

모든 API 호출에 적용되는 공통 네트워크 에러 처리.

### 3-1. 오프라인 감지

```
네트워크 끊김 감지 (navigator.onLine === false)
  →
하단 토스트: "네트워크 연결이 끊어졌습니다"
  →
자동 재연결 대기 (navigator.onLine === true)
  →
토스트 해제 + 마지막 작업 자동 재시도
```

**원칙**: 오프라인이 되어도 현재 화면 유지. 페이지 이동 없음.

### 3-2. API 공통 재시도 정책

| API 유형 | 자동 재시도 | 간격 | 최대 횟수 | 실패 시 |
|----------|-----------|------|----------|--------|
| 크레딧 조회 | ✅ | 2초 | 3회 | 마지막 캐시값 표시 |
| 크레딧 차감 | ✅ | 2초 | 2회 | 에러 화면 (E6/E12) |
| AI 생성 | ❌ (단발) | — | 1회 | E4/E5 처리 |
| PG 결제 | ❌ (PG 관할) | — | — | E7/E8/E9/E10 처리 |
| 파일 다운로드 | ✅ | 3초 | 3회 | E11/E13 처리 |
| 보너스 지급 | ✅ (백그라운드) | 2초 | 3회 | pending_bonus 저장 |

### 3-3. Idempotency (멱등성)

**크레딧 차감/환불 API는 반드시 멱등 키를 사용**:
- 클라이언트가 `idempotency_key` (UUID) 생성
- 같은 키로 중복 요청 시 서버는 최초 결과를 반환
- 이중 차감 / 이중 환불 방지

## 4. 환불 정책 요약

| 에러 | 차감 크레딧 | 환불 방식 | 환불 시점 |
|------|-----------|----------|----------|
| E4 AI 생성 실패 | 10c | 서버 자동 | 실패 즉시 |

| E11 다운로드 실패 | 70c | 권한 유지 (3회 실패 후 환불) | 3회 실패 후 |
| E13 풀샷 다운로드 실패 | 20c | E11과 동일 | E11과 동일 |
| E14 규격 변환 실패 | 10c | 서버 자동 | 실패 즉시 |

## 6. 유저 화면 디자인 가이드

### 에러 화면 공통 레이아웃

```
┌──────────────────────────┐
│                          │
│  [아이콘] ⚠️ 또는 ℹ️     │
│                          │
│  [제목]                  │ ← 16px, bold, #F1F5F9
│  한 줄로. 간결하게.       │
│                          │
│  [설명]                  │ ← 13px, #94A3B8
│  환불/처리 상태 안내      │
│  크레딧 잔고 표시 (해당 시)│
│                          │
│  [주요 CTA]              │ ← 그라디언트 버튼
│  [보조 CTA]              │ ← 텍스트 링크
│                          │
└──────────────────────────┘
```

### 컬러 사용

| 상황 | 아이콘 배경 | 텍스트 |
|------|-----------|--------|
| 환불 완료 | `#10B981` (green) | "자동으로 환불됩니다" |
| 처리 중 | `#F59E0B` (gold) | "반영에 시간이 걸리고 있습니다" |
| 실패 | `#EF4444` (red) | ❌ (사용하지 않음. 유저 불안감 유발) |
| 일반 안내 | `#8B5CF6` (accent) | "다시 시도해 주세요" |

**빨간색은 에러 화면에서 사용하지 않는다.** 유저가 "내가 뭔가 잘못했나" 느끼게 만든다. 금색(처리 중)과 초록(환불 완료)을 주로 사용.

### 톤 원칙

| ✅ 사용 | ❌ 금지 |
|---------|--------|
| 처리 중 문제가 발생했습니다 | 오류가 발생했습니다 |
| 자동으로 환불됩니다 | 환불을 신청해 주세요 |
| 잠시 후 다시 시도해 주세요 | 인터넷 연결을 확인해 주세요 |
| 추가 크레딧이 필요하지 않습니다 | 무료로 다시 시도할 수 있습니다 |
